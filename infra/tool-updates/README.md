# Eolssu Updates

[S15P31E102-508](https://ssafy.atlassian.net/browse/S15P31E102-508)의 Windows·Mac 개발 도구 알림 앱이다. Graphify 중앙 발행은 선행 Task 504가 담당하며 이 앱은 새 버전을 확인하고 사용자 프로젝트로 받는다.

## 사용

1. Windows는 NSIS 설치 파일로 설치한다. Mac Apple Silicon은 ZIP의 `.app`을 고정된 응용 프로그램 폴더로 옮긴 뒤 실행한다. 개발 산출물은 Windows 미서명, Mac 로컬 ad-hoc 서명이며 공인 서명·공증 배포는 별도다.
2. 각 PC에 Git, OpenSSH 클라이언트, Python 3.9 이상, COCO용 Node.js 22 이상과 npm이 필요하다. 기존 SSH 설정에 `edo1`을 구성하고 직접 접속해 서버 호스트키를 확인한다. 비밀번호 입력 없는 키 인증을 사용한다. `edo2` 바로가기도 각자 SSH 별칭이 필요하다. 앱은 키·비밀번호를 저장하거나 접속 권한을 새로 만들지 않는다.
3. 실제 `S15P31E102` Git 루트를 선택한다. 기본은 알림 후 **다운로드**다. **모든 업데이트 자동 반영**을 선택하면 최신 Graphify와 저장한 설치 범위의 최신 COCO를 받는다. 현재 코드보다 새 그래프도 받을 수 있으며, 파일·줄 위치는 실제 코드에서 확인한다. 필요할 때 프로젝트의 로컬 Git 제외에 `graphify-out/`을 등록한다. COCO는 프리릴리스도 비교하고 APK·IPA는 다운로드 버튼으로 받는다.
4. 화면 맨 아래 **로그인 시 실행**을 선택하면 OS 로그인 항목을 등록한다. 창을 닫으면 트레이·메뉴 막대에서 계속 실행하며 **종료**로 끝낸다. 앱을 이동했다면 새 위치에서 로그인 시 실행을 다시 선택한다. OS에서 로그인 실행을 차단했다면 해당 OS 설정도 확인한다.
5. **알림 테스트**로 권한을 확인한다. 차단 시 **알림 설정**에서 이 앱을 허용한다. 집중 모드나 화면 공유 중 OS가 알림을 숨길 수 있다. 설치/빌드만으로 모든 PC의 알림 권한이 자동 허용되지는 않는다.
6. COCO는 정식·프리릴리스를 포함한 모든 npm 신규 배포를 알린다. 제목 오른쪽에서 배포 버전, 설치 대상(기본 Codex/Claude), 적용 위치(현재 프로젝트 또는 전역)를 고른 뒤 **설치·업데이트**를 누른다. 정확한 npm 버전의 공식 CLI를 사용한다. 기존 개인 수정이나 전역 충돌을 임의 삭제하지 않는다. Codex/Claude 선택 시 일부 런타임만 성공할 수 있으며 실패 메시지에 완료 대상을 표시한다. 적용 후 새 AI 세션을 연다.
7. **폰 APK / 태블릿 APK**는 서버의 같은 최신 공용 QA APK, **아이폰 IPA**는 최신 게시 IPA를 저장 대화상자로 받는다. 서버 인덱스의 `builtAt`을 정렬하며 SHA-256·크기 검증 후에만 목적 파일을 교체한다. IPA 다운로드는 기기 설치·서명·프로비저닝을 수행하지 않는다.
8. **연결** 카드와 운영 탭의 **edo1** 버튼은 같은 대화형 SSH 연결을 사용한다. Grafana·Prometheus·Jenkins·DB·n8n 포트는 로컬 루프백에 연결한다. `edo2`는 해당 별칭의 터미널 연결을 연다. Windows `.cmd`, Mac `.command`는 앱 사용자 데이터의 `ssh/`에 생성된다.
9. **QA** 탭에서 [QA 페이지](https://15.165.144.7/qa), **블로그** 탭에서 [팀 블로그](https://team-edo.github.io/)를 앱 안에 연다. QA 접속 키는 QA 화면에서 직접 입력한다. 웹 탭은 최대 1100×760으로 넓어지고 최초 배율은 80%다. 웹 페이지는 별도 세션을 사용하고 로컬 파일·프로세스 실행용 IPC나 Node.js 권한을 받지 않는다. TLS 검증 실패를 우회하지 않는다. 실패 시 재연결 또는 브라우저로 열 수 있다.
10. **Grafana / Prometheus / Jenkins / DB / n8n**은 각각 localhost:13000 / :13001 / :18080 / :18081 / :15688을 연다. DB는 edo1의 루프백 8081에 연결한다. 화면이 비어 있거나 연결에 실패하면 중앙의 **SSH edo1 연결**을 누른다. 앱이 해당 로컬 포트가 열렸는지 확인하고 페이지를 다시 시도한다. 연결이 늦으면 터미널 연결이 끝난 뒤 **다시 연결**을 누른다. n8n을 일반 SSH 세션에서도 쓰려면 `~/.ssh/config`의 `Host edo1`에 `LocalForward 127.0.0.1:15688 127.0.0.1:5688`을 추가한다. 앱 연결 버튼은 기존 SSH 세션이 다른 로컬 포트를 쓰고 있어도 새 포워딩 시도를 계속한다.
11. **PlayStore출시**는 팀 전용 빌드의 Doply 출시 링크를 OS 기본 브라우저에서 연다. 키를 포함한 설치 파일은 팀 안에서 공유한다. 링크가 없는 빌드는 같은 탭에서 비공개 출시 링크를 등록할 수 있다. 등록한 기기별 링크는 OS 암호화 저장소로 보호한다.

Graphify·npm·앱 파일 목록은 약 60초마다 확인하며 절전 해제 시 다시 조회한다. Graphify·APK·IPA는 SSH, npm은 공식 HTTPS 레지스트리를 사용한다. SSH 장애와 npm 장애를 독립 표시한다. 설정과 알림 이력은 OS 사용자 데이터의 `settings.json`에 저장하며 앱 실행은 한 인스턴스로 제한한다. 설정 초기화는 앱을 완전히 종료하고 해당 파일을 백업·이동한 뒤 재실행한다. 다운로드 실패 시 기존 그래프·파일을 보존하고 해당 전송의 임시 파일만 정리한다.

## 개발·패키징

이 폴더에서 실행한다. 의존성은 lockfile과 Electron 45.2.3, electron-builder 26.18.0에 고정한다.

```sh
npm ci
npm test
npm run prepare-client
npm start
npm run dist:mac
npm run dist:win
```

기본 패키징은 인접한 `../graphify/context.py`를 자원으로 복사한다. 504가 아직 같은 checkout에 없을 때만 `GRAPHIFY_CONTEXT_SOURCE`에 해당 피처 브랜치의 실제 파일을 지정한다. 팀 전용 빌드에는 승인된 링크를 `resources/playstore-link.txt`에 준비한다. 빌더는 해당 파일이 있으면 앱 자원으로 복사한다. 생성된 `resources/`·`dist/`·`node_modules/`는 Git 제외하며 Python 클라이언트를 별도 구현하거나 그래프를 앱에 내장하지 않는다. 두 MR의 병합 순서는 504→508이다. Mac 배포는 Apple Silicon, Windows는 x64 NSIS 대상이다.

## 검증 범위

- `npm test`: 신규/프리릴리스·재시작/304·중복 억제, 수동/자동 다운로드·호환성·실패 재시도, 명시적 COCO 설치 argv·결과 처리, 최신 모바일 빌드 선택·실패 보존, SSH 별칭 제한.
- 실제 edo1 메타데이터·그래프 확인, npm 전체 메타데이터, 격리 경로의 공식 COCO 1.5.0→1.5.1 설치/업데이트, APK 33,578,729 bytes와 IPA 30,521,912 bytes의 SHA-256 일치 확인.
- Mac 620×440 실행·QA 탭 연결·사용자의 실제 알림 표시 확인. 버전별 재검증은 작업 계획에 구분해 기록한다. 로그인 항목 켜짐 확인, 로그인 재시작은 미검증. Windows는 설치 파일 빌드 외 실제 OS 동작 검증이 필요하다.
