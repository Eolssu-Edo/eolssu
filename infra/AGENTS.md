# Infra 작업 지침

- Docker·Jenkins·Nginx 설정은 실제 앱·서버·분석 구성과 실행 명령에 맞춰 작성한다. 미정 기술·포트·DB·서비스 분리를 확정값으로 만들지 않는다.
- `develop`을 통합·CI/CD 기준으로 사용하고 실제 배포 트리거는 팀 설정을 따른다. 파이프라인 수정과 배포 실행의 권한을 구분한다.
- 변경 영역에 맞춰 검사하되 공통 설정·의존성·계약 변경 시 관련 영역을 함께 검증한다. 경로 필터가 공유 변경이나 문서 검사를 누락하지 않게 확인한다.
- 빠른 기본 검사와 실제 모델·기기·대용량 검증을 구분한다. 무거운 검증의 실행 조건·담당자·결과 위치를 명시하고 해당 변경의 필수 검사는 병합 전에 완료한다.
- CI가 느리면 설치·빌드·테스트·Runner 대기 시간을 나눠 측정한다. 테스트별 실행 시간과 반복 초기화를 확인하고 필요한 검증을 없애거나 timeout만 늘리지 않는다.
- 캐시 사용 시 의존성·도구 버전 변경에 따른 갱신을 확인한다. 재사용한 결과의 입력·코드·환경이 현재 검증 대상과 같은지 확인한다.
- 비밀값은 저장소·이미지·로그에 넣지 않는다. 설정 예시에는 이름과 용도만 남기고 실행에 필요한 값은 환경에서 주입한다.
- 배포·DB·볼륨 변경 전에 실제 공유 환경과 보존할 데이터를 확인한다. 확인된 요구보다 큰 클러스터·데이터 플랫폼·운영 절차를 선제적으로 추가하지 않는다.
- 구성 선택·CI 병목 측정·배포 제약은 `docs/knowledge/infra/`에 남기고, 재현 가능한 실행·점검·복구 명령은 이 폴더의 README에 기록한다.
