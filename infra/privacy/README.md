# 개인정보 보유기간과 관리자 처리 기록

Task: S15P31E102-300. 승인된 정책: 일반 로그 최대 14일, 개인정보 관리자 접근기록 1년, 처리 완료 문의·삭제 요청 90일, DB 백업 최대 30일.

## 일반 로그

`30-eolssu-logs.conf`는 기존 rsyslog에 loopback TCP 1514 입력을 추가한다. 고정된 얼쑤 컨테이너 태그만 `/var/log/eolssu/ordinary`에 날짜별로 기록하고 다른 기본 로그 규칙으로 전달하지 않는다. 디렉터리 0700·파일 0600이며 syslog/adm 소유다. 새로운 외부 로그 업체로 전송하지 않는다.

runtime Compose의 syslog 드라이버는 Docker의 로컬 중복 캐시를 끈다. frontend·backend·AI·MySQL을 해당 구성으로 각각 재생성해야 적용된다. 수집기 준비 전에 새 Compose를 적용하지 않는다. 기존 컨테이너는 재생성 전까지 기존 드라이버를 유지하므로 이 단계만으로 전체 적용 완료로 보고하지 않는다.

Nginx 접근 로그는 IP·시각·메서드·경로·상태·응답 크기를 기록하고 쿼리·쿠키·본문·Referer를 제외한다. 서명 읽기 경로는 접근·오류 로그를 남기지 않는다. 원본 로그를 날짜별로 정리하며 시간별 실행 지연을 고려해 13일 경과 날짜 묶음을 정리하여 14일 상한을 넘지 않도록 한다. 수집기·타이머 장애는 운영 점검 대상이다.

```sh
sudo python3 infra/privacy/install.py           # 소스 준비 확인만
sudo python3 infra/privacy/install.py --apply   # 검토·검사 후 운영 호스트에서 실행
sudo systemctl status eolssu-privacy-retention.timer --no-pager
```

설치기는 rsyslog 전체 구성 문법을 검사한 뒤 재시작하며 실패하면 이전 전용 설정을 복구한다. loopback 바인딩과 합성 Docker 로그 수신·중복 캐시 비활성 옵션을 검사하고 정리 타이머를 켠다. 앱·DB 컨테이너를 재생성하지 않는다. 새 컨테이너의 `docker logs`는 사용할 수 없으므로 승인된 운영자는 위 root 전용 로그 경로로 확인한다.

## 개인정보 관리자 접근기록

SSH 로그인 기록만으로 개인정보 처리 대상·업무까지 기록됐다고 보지 않는다. 운영자가 개인정보를 조회·변경·삭제·내보내기 전에 식별 가능한 담당자, 접속지, 대상 회원 ID 또는 요청 ID, 업무와 사유를 별도 기록한다. 비밀번호·인증번호·녹음 내용·전체 SQL·문의 본문을 기록하지 않는다.

```sh
sudo /opt/eolssu-privacy/retention.py audit --actor operator-id --source source-ip --subject user:123 --operation DELETE --reason request-id
```

이 명령은 데이터 자체를 삭제하거나 관리자 권한을 부여하지 않는다. 본인 확인·업무 승인과 실제 처리 결과 확인은 별도 운영 절차다. 원본 접근기록은 `/var/lib/eolssu-privacy/audit/access.YYYY-MM-DD.jsonl`에 0600으로 보관하고 최소 1년이 지나고 날짜 묶음의 기간이 끝난 뒤 정리한다. 운영자는 매월 접근기록을 점검하고 직접 DB 작업을 포함하여 누락·권한 오용을 확인한다.

## 문의·삭제 요청

문의 메일은 개인정보 담당자가 처리한다. 접수·본인 확인·요청 범위·회신·처리 완료 시각을 구분한다. 서버에 별도 보관이 필요한 처리 기록은 `/var/lib/eolssu-privacy/requests/<UUID>/request.json` 및 같은 디렉터리의 필요한 첨부로 관리한다. `completedAt`은 시간대가 있는 ISO 시각이다. 미처리 건을 임의로 완료 처리하지 않는다.

불필요한 첨부는 처리 완료 시 제거하고 처리 완료 후 90일에 서버 보관 건을 정리한다. 타이머는 Naver 메일함을 읽거나 삭제하지 않는다. 담당자는 매일 같은 기준으로 보낸메일·받은메일·휴지통·다운로드 사본을 확인해 기한이 지난 문의를 정리해야 한다. 메일함 삭제를 서버 정리 성공으로 대신 보고하지 않는다.

## DB 백업과 복원

[백업 정리 코드](../backup/backup.py)는 최신 사본 예외를 없앤다. 일 1회 정리 지연을 고려해 DB는 29일에서 정리하여 30일 상한을 넘지 않도록 한다. 적용 전 사본·복원 가능성과 정리 타이머 상태를 확인한다.

삭제 처리 기록을 확인하기 전 백업을 운영에 복원해 공개하지 않는다. 복원본을 외부 접근 차단 상태로 올리고 백업 스냅샷 이후의 계정·개별 자료 삭제 요청을 재적용한 뒤 개인정보 담당자가 대조하고 서비스에 연결한다. 이는 자동 재적용이 구현됐다는 뜻이 아니다. 관련 기록의 백업 및 담당자를 운영 준비 확인 항목에 포함한다.

## 검증

Linux에서 `python3 -m unittest discover -s infra/privacy -p 'test_*.py' -v`를 실행한다. 합성 파일로 보유 경계·미완료 요청 보존·다른 프로젝트 보존·심볼릭 링크 이탈 거절·감사 기록 권한을 검사한다. 운영 rsyslog 8.2312.0의 비활성 설정 문법 검사도 통과했다. 실제 설치·컨테이너별 드라이버 전환·메일함 파기는 별도 확인한다.
