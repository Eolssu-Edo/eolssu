745 → 453 → 454 → 707. 745가 보관 테이블을 제공하며 DB 통합 검증도 이 선행 작업과 함께 실행한다. 원래 기대한 녹음 판본 보호에 더해 구 앱의 판본 생략 요청을 보관 이력 기준으로 제한한다. 신규 요청의 판본을 알 수 없는 경우의 오채점을 막기 위한 보완이며 보관 이력 없는 기존 곡의 구 앱 호환성은 유지한다.

## 검증 기록

구현 완료, 통합 DB 검사 대기. 분리 작업자 707의 읽기 전용 교차 검토에서 추가 확정 결함은 없었다. 외부 Jira·Push·MR·Notion API 문서 작업은 통합 담당자가 처리한다.

- JDK: 로컬 Zulu 21.0.11. 모든 Gradle 실행은 `--max-workers=2 --console=plain`을 사용했다.
- Red: backend `test --tests '*CreatePracticeSessionTests'`에서 보관 곡의 판본 없는 요청이 저장되는 실패를 확인했다(11건 중 1건 실패). 보호 구현 후 같은 검사 11건 통과.
- Green: backend `clean build` 성공. JUnit XML 기준 709건, 실패 0, 기존 제외 1.
- Green: frontend `:shared:testAndroidHostTest` 성공. JUnit XML 기준 1,350건, 실패 0, 기존 제외 4. 최신 733의 OS 마이크 권한 직접 요청 흐름도 유지한다.
- 감도 검사: `PracticeViewModel`·`AnalysisSession`만 기준 구현으로 임시 되돌리고 새 테스트 12건 실행 시 구판 시작·권한 대기 중 게시·녹음 판본 전달 등 5건이 실패했다. 두 파일은 검사 직후 원본 바이트로 복원했으며 같은 12건이 다시 통과했다.
- 최종 SQL 보관 판본 조건은 `<`가 아닌 `<>`다. 현재 v1로 롤백하고 v2가 보관돼 있어도 판본 없는 신규 녹음을 거절해야 하기 때문이다. 해당 롤백 DB fixture를 추가한 뒤 backend 생성 서비스·Controller 19건과 테스트 컴파일이 성공했다.
- DB 검사 준비: `PracticeSessionApiDatabaseTests`에 생략/null/명시 불일치·기존 키 재전송·구판 부모·읽기 이후 교체·낮은 판본 롤백 사례를 추가했다. 745의 V38이 필요한 통합 검사는 통합 담당자가 실행한다.
- 기준 브랜치의 `PracticeRoute`에 남아 있던 존재하지 않는 `leaveToSongInfo()` 호출은 실제 콜백 `leaveEvaluation()`로 1줄 수정했다. 이는 FE 컴파일을 위한 선행 회귀 수정이다.
- 실제 Android/iOS 기기 녹음과 iOS 컴파일은 이 worktree에서 검증하지 않았다. 707 v2 게시 전에 담당자가 앱 전환을 확인해야 한다.
- Notion API 문서는 통합 담당자의 연결 조회에서 `object_not_found`로 접근되지 않았다. PRA-01 추가 계약을 로컬 명세에 기록했고 외부 갱신은 미완료다.
