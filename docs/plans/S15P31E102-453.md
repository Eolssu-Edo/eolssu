## 실행 계획

1. PRA-01 명시 판본·부모 판본 검증 및 과거 판본 보관 곡의 미지정 신규 요청 차단을 실패→성공 검사한다.
2. 현재 판본을 SQL 삽입 조건에 포함해 조회 이후 교체 경합을 차단한다.
3. 녹음 판본을 보존·전달하고 구판의 새 연습 진입을 막는 클라이언트를 이식한다.
4. backend 빌드, frontend Android host, 745 마이그레이션 포함 DB 검사로 검증하고 구현 커밋을 남긴다.

## 범위와 배포 순서

745 → 453 → 454 → 707. 745가 보관 테이블을 제공하며 DB 통합 검증도 이 선행 작업과 함께 실행한다. 원래 기대한 녹음 판본 보호에 더해 구 앱의 판본 생략 요청을 보관 이력 기준으로 제한한다. 신규 요청의 판본을 알 수 없는 경우의 오채점을 막기 위한 보완이며 보관 이력 없는 기존 곡의 구 앱 호환성은 유지한다.
