- 기준: develop `6ebd0b8f`에서 작업하고 Push 전 `924e9b68`(946·244·951·943·952 병합 포함) 위로 다시 맞췄다. 브랜치 `chore(infra)/S15P31E102-945-infra·ai·data·catalog-Python-테스트를-Jenkins-변경-경로-기준으로-실행`.

- 일정: 저장소 변경까지만 한다. 운영 Jenkins 등록은 발표(11-18) 동결이 끝난 뒤 사용자 확인을 받고 진행한다.

## 문제

운영 Jenkins는 infra 테스트 파일 6개만 실행한다. ai(pytest), data, catalog와 나머지 infra 폴더의 Python 테스트는 CI에서 돌지 않아, 깨진 변경이 develop에 들어가도 바로 드러나지 않는다.

## 변경

- [python-tests.py](../../infra/jenkins/python-tests.py): 변경 경로로 실행 묶음을 고르는 `plan`, 묶음의 가상환경을 준비하고 실행하는 `run`. 영역 간 파일 의존을 선택 규칙에 넣었고, 목록에 없는 경로·신뢰할 수 없는 기준 SHA는 전체 실행으로 처리한다. 테스트 폴더는 실행할 때 찾으므로 새 infra 폴더도 따로 등록하지 않는다.
- [python-tests.Jenkinsfile](../../infra/jenkins/python-tests.Jenkinsfile): `eolssu-backend` 완료 뒤 실행되는 새 잡 `eolssu-python-tests`. 묶음별 단계, pytest JUnit 보관, 격리 테스트는 빌드를 실패시키지 않는 별도 단계.
- [python-tests-requirements.txt](../../infra/jenkins/python-tests-requirements.txt): data·catalog 고정 의존성. ai는 `ai/uv.lock`을 그대로 쓴다.
- [register-python-tests.groovy](../../infra/jenkins/register-python-tests.groovy): 잡 생성 전용, 기존 잡은 덮어쓰지 않는다.
- 단위 테스트 [test_python_tests.py](../../infra/jenkins/tests/test_python_tests.py) 15건, [운영 적용 절차](../../infra/runtime/README.md#python-테스트-잡-s15p31e102-945), [선택 규칙·실측·격리 근거](../knowledge/infra/python-tests-ci.md).
- 다른 잡·`configure-jenkins.groovy`·알림 서비스는 바꾸지 않았다. 알림 서비스가 `eolssu-*` 잡을 모두 읽으므로 새 잡의 실패도 알린다.

## 검증 (2026-11-15, 로컬 macOS)

- `test_python_tests.py` 15건: 시스템 Python 3.9.6과 uv Python 3.12.13에서 통과.
- 실제 도구로 네 묶음을 새 작업 폴더에서 실행한 결과는 [지식 문서](../knowledge/infra/python-tests-ci.md#영역별-로컬-실측)에 있다. 격리하지 않은 테스트의 실패는 0건이다.
- 운영 Jenkins에서는 실행하지 않았다. Pipeline linter도 아직 통과시키지 않았다.
- 독립 리뷰로 선택 규칙의 누락 2건을 고쳤다: data 재생 테스트가 읽는 frontend `Sigimsae.kt`, 실행되지 않던 `backend/tools/tests`. executor 대기 설명을 실제 동작에 맞추고, 의존성 변화 확인용 주간 전체 실행을 더했다.

## 남은 일

- 발표 뒤 적용: edo1 Jenkins 사용자의 `python3`·`uv` 확인 → Jenkinsfile 설치·linter → 잡 생성 → 첫 실행(Build Now, 전체 묶음) 시간 기록 → 다음 develop 병합에서 자동 예약 확인.
