# S15P31E102-212 백엔드 분석 요청을 받는 POST /v1/analyses API 구현

- Jira: [S15P31E102-212](https://ssafy.atlassian.net/browse/S15P31E102-212), 담당 우동균, Story [S15P31E102-35](https://ssafy.atlassian.net/browse/S15P31E102-35) 관련됨, Epic S15P31E102-20. 활성 스프린트 `S15P31E1 1 스프린트 3`(59139)의 진행 중.
- 브랜치: `feat(ai)/S15P31E102-212-백엔드-분석-요청을-받는-POST-/v1/analyses-API-구현`, 기준 `origin/develop` `7f9eee9`.
- 스펙: [연주 분석 실패 사유와 화면 안내](../specs/practice-analysis-failure.md)의 '분석 요청과 상태 조회 계약'. 호출자는 백엔드 `HttpAnalysisClient`(S15P31E102-186).

## 범위와 완료 조건

- `ai/`에 FastAPI 앱을 두고 `POST /v1/analyses`를 연다. 요청의 `audioUrl`에서 원본을 내려받아 `decode_recording()`(S15P31E102-183)으로 16kHz 모노로 바꾸고, pYIN 음높이 추정 뒤 `score()`로 채점해 같은 응답으로 돌려준다.
- 응답은 `DONE`(modelVersion·점수 4개·tuningOffsetCent·tuningOutOfRange·음표별 결과) 또는 `FAILED`(`NO_SOUND`·`TOO_SHORT`·`DECODE_ERROR`).
- 완료 조건: 작은 고정 오디오와 가짜 다운로드로 DONE·FAILED 3종과 idx 대응을 `uv run pytest`로 검증하고, `HttpAnalysisClient`가 읽는 필드 이름·타입과 대조한다.
- 제외: 실행 이미지와 ffmpeg 버전 고정, 기준음·공통 악보 데이터 반영(S15P31E102-157), 실제 녹음 채점 품질 검증.

## 결정

| 항목 | 선택 | 근거·영향 |
| --- | --- | --- |
| 웹 프레임워크 | FastAPI + uvicorn | 요청 검증을 모델로 적고 테스트 클라이언트로 외부 호출 없이 검사한다. 채점은 CPU 작업이라 동기 함수로 두어 스레드 풀에서 돈다 |
| 기준음 | 상수 E♭4(311.13Hz) | 요청에 기준음이 없다. `semitone`은 받은 그대로 쓰고 조율 보정(±100센트)이 기기 차이를 흡수한다. 기본음 녹음·공통 악보 반영은 S15P31E102-157 |
| 박 길이 | `60 / bpm`초 × `beats` | `beats`는 백엔드가 `bpmUnit` 단위로 센 값이라고 본다. `bpmUnit`은 DB의 4종만 받고 채점에는 쓰지 않는다 |
| `modelVersion` | `pyin-1` | 계약 예시와 같다. 음높이 추정·채점 방식을 바꾸면 올린다 |
| 다운로드 실패·디코딩 밖 오류 | HTTP 502·500(본문에 요청 내용 없음) | 녹음 탓이 아니므로 실패 코드가 아니다. 백엔드는 오류 응답을 `SERVER_ERROR`로 저장하고 다시 시도할 수 있다 |
| 다운로드 한도 | 25MiB, 30초 | PRA-02 원본 상한 20MiB보다 크면 거절한다(Nginx·multipart 한도와 같은 값) |
| 입력 검증 오류 | 422, 오류 위치만 담고 입력값은 빼기 | FastAPI 기본 422는 입력값을 되돌려 서명 URL이 응답에 실린다 |
| 로그 | 시도마다 `sessionId`·`attempt`·결과·처리 시간(ms) 한 줄 | `audioUrl`과 예외 메시지(경로·URL이 들 수 있음)는 남기지 않는다 |

## 검증

- `cd ai && uv sync && uv run pytest`
- API 테스트는 `evaluation.synthetic`의 합성음을 ffmpeg로 m4a로 만들어 가짜 다운로드로 넘긴다. 실제 대금 녹음·모델 품질 검증이 아니다.

## 결과 (2026-10-28)

- `uv run pytest`: 54 passed(그중 `tests/unit/test_api.py` 17). DONE과 요청 idx(7부터) 유지, 틀린 음 → `PITCH`, 빠진 음 → `MISSED`와 null 오차, 무음 → `NO_SOUND`, 0.5초 녹음 → `TOO_SHORT`, 오디오 아닌 파일 → `DECODE_ERROR`, 다운로드 실패 502·예외 500·검증 오류 422에서 서명 URL이 응답·로그에 없음.
- 변이 검사: 위치 순번 idx 반환, 422 처리기 제거, 예외 밖으로 던지기, httpx 예외 연결, 크기 한도 제거, httpx 로그 허용, 결과 기록 누락을 각각 넣었을 때 해당 테스트가 실패했다.
- 실행 검증: `uvicorn ai_service.api:app`과 로컬 HTTP 서버(저장소 대역)로 -20센트 합성음 m4a를 분석해 200 DONE(조율 보정 -15.0센트, 요청 idx 3~6), 없는 파일 502, `bpm` 누락 422(입력값 없음)를 받았다. DEBUG 로그에 서명 토큰이 0회 나왔다.
- 발견: 테스트용 m4a를 조각 mp4로 만들면 AAC 앞부분 지연이 잘리지 않아 음이 늦게 시작한 것처럼 판정된다. 앱 녹음과 같이 `+faststart` 일반 mp4로 만들었다. httpx는 INFO 로그에 요청 URL 전체를 남겨 WARNING 미만을 막았다.

## 백엔드 `HttpAnalysisClient` 대조

| 클라이언트가 읽는 것 | AI 응답 |
| --- | --- |
| `status` `DONE`·`FAILED` | 같음 |
| `modelVersion` 1~30자 | `pyin-1` |
| `total`·`pitch`·`timing`·`duration` Int 0~100 | Python int, 0~100 |
| `notes[].idx` 요청 순서와 같은 목록 | 요청 `idx`를 순서대로 돌려줌 |
| `notes[].verdict` `CORRECT`·`PITCH`·`TIMING`·`MISSED` | 같음 |
| `pitchErrorCent` Double? / `onsetErrorMs`·`durationErrorMs` Int? | float / int, `MISSED`는 모두 null |
| `failReason` `AnalysisFailReason` 이름 | `NO_SOUND`·`TOO_SHORT`·`DECODE_ERROR`만 |
| 오류 상태 코드는 본문을 읽지 않음 | 422·502·500 본문에 요청값 없음 |
| `tuningOffsetCent`·`tuningOutOfRange`는 무시 | 보냄(계약대로) |

요청은 클라이언트의 `RequestBody`(`sessionId` Long, `attempt`·`bpm` Int, `audioUrl`·`bpmUnit` String, `notes[{idx, semitone, beats(Double), sigimsae}]`)를 그대로 받는다.
