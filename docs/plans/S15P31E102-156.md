## 목적

사람이 확정한 정답 `.jgb.json`(S15P31E102-154)을 FE 표시·AI 채점·BE 저장이 함께 쓰는 공통 악보 데이터로 바꾼다. 원본 jgb는 고치지 않는다.

## 기준

- 노션 1차 MVP 논의사항 B2(2026-10-27 결정): 화면 배치용 `columns → cells`와 재생·채점용 `events`를 함께 주고 `cellId`·`eventId`로 잇는다. 음높이·시작·길이는 이벤트에 한 번만 저장한다. 필드 이름·타입은 아리랑 한 곡을 FE·AI·BE가 검증한 뒤 확정한다.
- 노션 5-1(담을 정보와 표현 원칙): 악보 식별, 화면 위치, 음표, 표현(쉼·붙임·연장·숨표·시김새), 음악 해석(조율 기준·시간 단위·박/소박 구조·빠르기 단위), 근거. 붙임·연장은 앞 음에 더하고, 빈칸은 원본 규칙대로, 숨표와 쉼을 구분하고, 시김새는 본음과 구분해 보존하며, 화면 배치와 채점 시간을 나눈다.
- 읽는 쪽(이번 Task에서는 바꾸지 않음): FE `frontend/shared/.../core/model/Score.kt`(`Score`·`ScoreEvent`), BE `backend/.../analysis/domain/PracticeAnalysis.kt`(`ScoreNote`·`PracticeScoreNotes`), AI `ai/src/ai_service/pipelines/scoring.py`(`Note`).
- 기준 데이터: `data/reference/`(율명·장단·곡, S15P31E102-155). 정답: `data/annotations/scores/<원본 ID>/`.

## 데이터 정의 (기본기 1: 단위)

- **이벤트 하나 = 소리 하나 또는 쉼 하나.** 이음표 `-`와 빈 정간은 앞 이벤트의 길이에 더한다.
- **정간(cell) 하나 = 화면 칸 하나.** 정간 안 글자 하나하나(unit)는 자기가 속한 이벤트를 가리킨다.
- **각(column) 하나 = jgb 선율의 한 줄.** 곡마다 각 길이가 다르다(도라지타령·밀양아리랑 3정간, 아리랑·늴리리야 12정간).

## 결정 (2026-10-28 coco-design 추천안, 사용자 승인)

| 번호 | 내용 | 결정 |
| --- | --- | --- |
| D1 | 시작·길이 단위 | 박(곡 장단의 `bpm_unit`)을 정수 틱으로 저장. `ticksPerBeat` = 모든 시작·길이 분모의 최소공배수(변환 중에는 `fractions.Fraction`). 초는 저장하지 않는다(사용자가 BPM을 바꾼다) |
| D2 | 정간 하나의 박 | jgb에 없으므로 사람이 정한다. 정답 검토 기록의 `sourceValues.beatsPerJeonggan`에 근거(원본 장구 기호 칸)와 함께 적는다: 아리랑·도라지타령·밀양아리랑 1, 늴리리야 1/3. 결과의 시간 정보에도 남긴다 |
| D3 | 정간 안 리듬 | 띄어 쓴 줄은 정간을 똑같이 나눈다. 붙여 쓴 반칸(한 줄의 여러 음)은 그 줄을 똑같이 나눈다. 4곡에는 반칸이 없다 |
| D4 | 정간과 이벤트 연결 | `cells[].units[]`가 `eventId`를 가리키고, 이벤트는 시작 정간 `cellId` 하나를 가리킨다. ID는 위치로 만든다: `c{각}-j{정간}`, 이벤트는 시작 글자 위치 `c{각}-j{정간}-r{줄}` |
| D5 | 표현 | 쉼은 `kind: "REST"` 이벤트(율명 없음). 숨표는 `breathAfter`. 시김새는 이벤트의 `sigimsae` 목록(4곡에는 없음). 율명은 `yul`·`octave`로 저장하고 반음 번호는 율명 표에서 찾는다 |
| D6 | 결과 위치 | 정답 4곡의 변환 결과를 Git에 커밋하고(BE가 DB에 넣고 FE·AI가 시험에 쓴다), 테스트가 다시 변환한 결과와 바이트까지 같은지 검사한다. 위치는 U5에서 사용자 확인 |

### U0 v1 형식

- 정답 4곡은 모두 `"v": 2`다. Jira 범위가 v1·v2 모두 읽기를 요구하므로 v1 문서의 실제 모양을 우물사이 코드(`C:/Users/SSAFY/omr114/jeongganbo-generator`)에서 확인한다.
- 완료: v1과 v2의 선율 필드 차이를 한 줄로 정리하고, 고정 테스트 파일로 쓸 v1 예시를 만든다. v1 근거를 찾지 못하면 알리고 v2만 지원한다.
- **결과(2026-10-28):** 우물사이 `js/app.js` `applyState`(저장소 9d4a24e)가 기준이다. v2는 `parts[]`의 각 파트에 `melody`·`lyrics`·`cellStyles`·`instrument`가 있고, v1은 같은 값이 루트에 하나(`melody`·`lyrics`·`cellStyles`·`ornInstrument`)다. 우물사이는 `parts`가 비어 있지 않은 배열이면 그것을, 아니면 루트 값을 파트 1개로 읽는다. 선율 문법은 같다.
- **받은 파일:** 노션 jgb 모음 99개 중 단소 46개는 모두 v2, v1은 대금 13개·소금 13개, 우물사이 예시 5개도 v1. 여러 파트(v2 `parts` 2개)는 소금 북천이맑다커늘 1개뿐이고 1차 4곡은 모두 파트 1개다.
- **고정 파일:** `data/tests/fixtures/jgb/v1-minimal.jgb.json`, `v2-minimal.jgb.json`. 원본 악보를 옮기지 않고 같은 선율(이음·쉼·숨표·빈 정간 포함)을 두 형식으로 직접 만들었다.
- **U1에 넘길 것:** 파트가 2개 이상이면 변환할 파트를 정해야 한다. 1차는 파트 1개만 받고, 여러 개면 파트 번호를 받지 않는 한 멈춘다.

### U4 불변식·계보 (기본기 2·4·5)

| 검사 | 식 또는 조건 |
| --- | --- |
| 길이 합 | Σ `durationTick` = 정간 수 × `beatsPerJeonggan` × `ticksPerBeat` |
| 빈틈·겹침 없음 | 이벤트 k의 `startTick` + `durationTick` = 이벤트 k+1의 `startTick` |
| 참조 유효 | 모든 `units[].eventId`가 `events`에 있고, 모든 이벤트의 `cellId`가 `cells`에 있다 |
| 율명 | 모든 NOTE 이벤트의 (`yul`, `octave`)가 `data/reference/pitches.json`에 있다 |
| 개수 | NOTE 이벤트 수 = 정답 jgb 율명 수(154 집계: 61·91·85·68), REST 수 = `쉼` 수 |
| 결정적 변환 | 같은 입력을 두 번 변환하면 바이트까지 같다 |

- 완료: 4곡 모두 통과. 검사마다 값을 일부러 틀려 실패하는지 확인한다.
