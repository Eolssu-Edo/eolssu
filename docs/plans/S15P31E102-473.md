## 계획

1. 남은 높이에 맞춘 짧은 각 묶음·3소박 정간 높이를 작은 함수와 자동 검사로 구현한다.
2. 연습 화면에서만 배치를 적용하고 음 선택·진행 강조·따라가기를 원본 좌표에 연결한다.
3. Android 단위 검사·APK 빌드 후 에뮬레이터에서 확인하고 결과를 기록한다.

## 설계

요청한 오른쪽 위→아래, 다음 묶음은 왼쪽 순서를 유지한다.
고정 3각이 화면을 넘치는 경우 글자를 과도하게 줄이지 않고 들어가는 묶음 수를 선택한다.
공통 렌더러에는 기본값이 기존 동작인 배치·정간 높이 옵션을 추가하며 연습 화면만 사용한다.

## 검증

- `frontend/`에서 `./gradlew.bat :shared:testAndroidHostTest :androidApp:assembleDebug --console=plain` 성공.
- 이번 실행의 `testAndroidHostTest` XML만 집계: 751개 중 747개 통과, 4개 건너뜀, 실패·오류 0개.
  기존 `wasmJsBrowserTest` 결과는 이번 Android 검증 수에 포함하지 않는다.
- `PracticeScorePackingTest` 7개와 `ScoreLayoutTest` 10개 통과.
  묶음 순서·세로 높이 경계·가로/세로 소박 구분·큰 글꼴·긴 각·진행 위치를 검사했다.
  기존 도라지타령 카탈로그 fixture 28각이 500dp에 3각씩 들어가며 확장 칸이 44dp보다 길어지는 것도 확인했다.
- 초기 검사에서는 아직 없는 배치 함수 참조로 컴파일 실패를 확인한 뒤 구현했다.
- Android API 37 에뮬레이터 `Medium_Phone_API_37.0`에 APK를 설치하고 운영 카탈로그의 도라지타령으로 진입했다.
  준비 화면 2각, 연주 중 3각씩 오른쪽 위→아래 / 다음 묶음은 왼쪽으로 표시된다.
  1·2·3각 / 4·5·6각과 하단 연주 컨트롤이 세로 스크롤 없이 보이고, 연주 중 현재 표시 칸과 가로 따라가기가 묶음 단위로 이동하는 것을 관찰했다.
  음 선택 콜백은 기존 원본 이벤트를 그대로 전달하며 정적 대조했다. 변경 후 기기에서의 음 선택·운지 패널 재검증은 별도로 남긴다.
- 초기 실화면에서는 3소박이 많은 각 때문에 2각만 들어갔다.
  일반 칸 최소 높이를 기존 밀집 악보의 32dp까지 허용해 3각을 확보했고, 3소박 칸은 최소 48dp로 기존 44dp보다 길게 유지했다.
  소수점 픽셀 반올림용 여유 2dp를 두었다.
- 로컬 화면 증거: `frontend/build/practice-stacks-473/recording-three-stacks.png` (Git 제외).
- `git diff --check` 통과. 공통 렌더러의 새 옵션을 지정하는 곳은 휴대폰 연습 화면뿐이다.
- Windows에서 iOS 컴파일·실기기 검증은 하지 않았다. 변경 후 Web 실행·태블릿·작은 창·확대 글꼴의 실화면 검증도 미실시이며 자동 경계 검사와 구분한다.
- 독립 코드 리뷰·Push·MR은 미실시. Jira는 진행 중을 유지한다.

## 기대와 실제

요청한 3각 세로 묶음과 3소박 칸 확대를 연주 화면에 적용했다.
높이가 부족한 준비 화면에서는 글자를 과도하게 줄이지 않고 2각, 더 낮은 공간에서는 1각으로 줄인다.
다른 악보 페이지와 원본 악보·시간·음표 식별자는 변경하지 않았다.
