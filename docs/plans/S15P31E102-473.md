## 계획

1. 남은 높이에 맞춘 짧은 각 묶음·3소박 정간 높이를 작은 함수와 자동 검사로 구현한다.
2. 연습 화면에서만 배치를 적용하고 음 선택·진행 강조·따라가기를 원본 좌표에 연결한다.
3. Android 단위 검사·APK 빌드 후 에뮬레이터에서 확인하고 결과를 기록한다.

## 설계

요청한 오른쪽 위→아래, 다음 묶음은 왼쪽 순서를 유지한다.
고정 3각이 화면을 넘치는 경우 글자를 과도하게 줄이지 않고 들어가는 묶음 수를 선택한다.
공통 렌더러에는 기본값이 기존 동작인 배치·정간 높이 옵션을 추가하며 연습 화면만 사용한다.

## 기대와 실제

요청한 3각 세로 묶음과 3소박 칸 확대를 연주 화면에 적용했다.
높이가 부족한 준비 화면에서는 글자를 과도하게 줄이지 않고 2각, 더 낮은 공간에서는 1각으로 줄인다.
다른 악보 페이지와 원본 악보·시간·음표 식별자는 변경하지 않았다.

## 후속 수정: 가로줄 시작 높이 정렬

사용자 확인에서 묶음별 자연 높이 누적으로 2·5·8각, 3·6·9각의 윗부분이 어긋난 점을 지적했다.
기존 묶음별 쌓기를 가로줄별 최대 높이 공유로 대체한다.
1·4·7·10…각 / 2·5·8·11…각 / 3·6·9·12…각의 시작 높이를 맞추고, 공유 높이를 포함해 화면에 들어가는지 계산한다.
일부 각만 남은 마지막 묶음과 도라지타령의 3각 배치를 자동 검사하고 실제 화면을 다시 확인한다.

- 새 회귀 검사 2개가 기존 구현에서 assertion 실패하는 것을 확인한 뒤 수정했다.
- 전체 각을 가로줄 위치별로 나눠 최대 높이를 공유하고, 렌더러가 같은 높이의 공간을 예약한다.
  줄 사이 간격은 6dp로 맞추고 줄마다 픽셀 반올림 여유 2dp를 포함해 3각 배치를 유지한다.
- `./gradlew.bat :shared:testAndroidHostTest :androidApp:assembleDebug --console=plain` 성공.
  최신 Android 검사만 집계: 753개 중 749개 통과, 4개 건너뜀, 실패·오류 0개.
  `PracticeScorePackingTest` 9개 통과. 도라지타령 28각의 공유 높이까지 포함한 500dp 배치 검사도 통과했다.
- API 37 에뮬레이터에 수정 APK를 설치했다.
  준비 화면의 2줄과 연주 화면의 3줄에서 각 머리글 시작점이 같은 수평선에 놓이는 것을 확인했다.
  연주 화면의 1·4·7·10각, 2·5·8·11각, 3·6·9·12각 시작점과 세로 스크롤 없는 표시를 관찰했다.
- 최신 로컬 화면 증거: `frontend/build/practice-stacks-473/recording-aligned-rows.png` (Git 제외).
- 요청한 가로줄 정렬을 그대로 적용했으며 추가적인 동작 변경은 없다.
  독립 코드 리뷰·iOS·Web 재검증은 미실시. 기존 검증 한계를 유지한다.

## 후속 확장: 다른 악보의 높이에 따른 자동 왼쪽 줄바꿈

사용자가 도라지타령 외의 악보에도 각 길이를 보고 세로로 들어가는 만큼 배치하도록 요청했다.
기존 4정간 이하·최대 3각 제한을 실제 각 높이에 따른 계산으로 대체한다.
첫 두 각만이 아닌 전체 각과 3소박 높이·공유 가로줄 높이를 반영하며, 한 각만 들어갈 때도 최소 글자 크기 안에서 높이를 맞춘다.
원본 표시상 한 각을 여러 줄로 나누는 악보는 기존 동작을 보존한다.
1정간 7각·5정간 2각·8정간 1각·길이가 섞인 악보의 높이 경계를 먼저 검사하고 다른 곡의 실제 화면을 확인한다.

- 확장 회귀 검사 4개가 기존 구현에서 assertion 실패하는 것을 확인한 뒤 구현했다.
- 각의 정간 수가 아니라 기존 렌더러에서 한 표시 줄인지 확인한다.
  원본 장단에 의해 11+1줄처럼 이미 나눈 각과 12정간을 넘어 나뉜 각은 보존한다.
- 남은 높이와 가장 짧은 각으로 가능한 개수의 상한을 잡고, 악보 전체의 공유 가로줄 높이로 들어가는 개수를 찾는다.
  한 각만 들어갈 때에도 32dp 이상의 읽을 수 있는 정간 높이 안에서 맞춘다.
- 빌드: `./gradlew.bat :shared:testAndroidHostTest :androidApp:assembleDebug --console=plain` 성공.
  마지막 추가 장단 경계 검사 후 `./gradlew.bat :shared:testAndroidHostTest --console=plain`도 성공했다.
  Android 최신 검사만 집계: 758개 중 754개 통과, 4개 건너뜀, 실패·오류 0개.
  `PracticeScorePackingTest` 14개 통과. 1정간 7각·5정간 2각·8정간 1각·가변 각 길이·원본 장단 분할 보존을 포함한다.
- 공개 운영 API를 인증정보 없이 읽어 원본 각 길이를 대조했다.
  `/api/songs/8/score`: 고사리 끊자 8각, 각당 4정간.
  `/api/songs/9/score`: 구아리랑 16각, 각당 3정간.
  `/api/songs/19/score`: 몽금포타령 6각, 각당 12정간.
  `/api/songs/33/score`: 오나라 6각, 각당 12정간.
  `/api/songs/6/score`: 개구리소리 5각, 각당 12정간.
- API 37 에뮬레이터에 수정 APK 설치 성공. 개구리소리의 상세·연습 준비 화면 진입을 확인했다.
  이후 연주 중 화면 확인 시 컴퓨터 사용 도구가 사용자 입력 감지로 조작을 중단했다.
  사용자 조작과 겹치는 추가 UI 검증은 수행하지 않았다.
  다른 곡의 연주 중 표시·세로 스크롤 없는 전체 표시는 자동 경계 검사와 구분해 실화면 검증 대기로 남긴다.
- 기존의 가로줄 시작 높이 정렬과 3소박 높이 확대를 유지한다.
  사용자 요청에 따라 적용 곡과 한 세로줄의 각 수를 확장했으며 다른 페이지의 적용 범위는 늘리지 않았다.
- 독립 리뷰·iOS·Web 실화면 재검증·Push·MR은 미실시. Jira의 기존 Story·스프린트·진행 중 상태를 유지한다.
