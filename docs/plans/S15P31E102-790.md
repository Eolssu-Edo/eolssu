## 계약과 완료 조건

SHT-04/08/11의 선택적 expressions 및 V43 expressions_json을 통해 기존 수행 companion을 보존한다. 새 요청이 없거나 null이면 현재 초안의 non-null 계획을 우선 사용하고 없으면 확정본을 사용한다. 숫자 계획의 기본100/구간80을 기본120으로 바꾸면120/96으로 한 번 비례 변경한다. 악보와 계획 SHA를 다시 연결하며 원본 authoring 계약은 유지한다.

위치를 바꾸는 숫자 계획 구조 편집은 PLAN_POSITIONS_CHANGED로 거절한다. 음고·악기·기본BPM 변경은 허용 범위에서 다시 검증한다. 확정 저장은 실제 생성기의 사전검사를 통과해야 DB를 변경한다. 빠른 음의 PCM/MIDI 해상도와 600초 경계, 생성기 불가503을 원인·위치·조정 범위와 함께 전달한다. 숫자 cue가 MIDI0tick이 된 경우 기본 BPM 조정으로 해결할 수 있는 잘못된 maxBpm을 주지 않는다.

가져오기·저장·음원 요청 BPM은 양의 정수이고 임의30~160 상한은 제거한다. QUARTER/DOTTED_QUARTER 단위와 구간 비율은 생성기 계약에 따른다. V41·42는 유지하고 V43에서 필요한 INT/양수 검사와 companion 컬럼만 추가한다. 초안과 기존 게시 악보를 일괄 수정하지 않는다.

## 검증

- 분할 snapshot `test`의 SheetExpressionsTests/EditUserSheetTests/UserSheetControllerTests/SheetImportsTests/OpenApiRequestExampleTests 집중 34건과 bootJar 성공. `clean build --max-workers=2`: 748건, 실패 0, 조건부1건 건너뜀.
- 새 폐기 MySQL8.4 `authoring_split790`에서 V1~V43와 실제 인증HTTP 저장/초안/음원, 실제 DATA773 CAT/FFmpeg 생성: 95건, 실패/건너뜀0. databaseTest 대상은 UserSheetApi/SheetImportApi/SheetAudio/SheetTempoApi/SheetAuthoringCat/OpenApi/BuiltinFingeringApi/CatalogReferenceApi 및 Flyway 최초·재실행이다. TEST_PLAYBACK_URL·PLAYBACK_TEST_BASE_URL에 분할773 소스의 loopback 생성기를 지정했다. 객체 저장소만 메모리 대역이며 운영DB/R2는 사용하지 않았다.
- 실제 저장 판본2·음원/악보 SHA·12초 수행표와12.55초 M4A, 첫쉼1.5박·장단ID12·60→30구간 계획을 대조했다. 기본100/구간80→120/96→144/115.2, 초안계획 생략/null 보존, 구조변경 거절과2,000,000BPM의 PCM_NOTE_TOO_SHORT 오류도 확인했다. MIDI0tick 사유 전달은 OpenAPI/생성기 계약 및 선행773 실제HTTP 검증을 함께 따른다.
- 독립 분할본의 검증 결과를 기록하며 과거 통합본 통과를 그대로 주장하지 않는다. 실물 연주 검수/기기 청취/배포는 범위 밖이다.

## 설계 비교

사용자가 확정한 구간 비율 보존과 기술적 제한 정책을 그대로 분리한다. 의미 변경은 없다. 지원음·원본·장단·생성기의 선행 결과가 실제 컴파일/실행 계약이므로 MR 본문에 의존 관계를 밝힌다. [내 악보](../specs/user-sheets.md), [음원](../specs/sheet-audio.md).

최종 동기화: 최신 origin/develop `5321f7c4`, BE788 `d51f52f2`, BE787 `392a16bf`, DATA789 `2858ada5`, DATA773 `ac615a3c`를 모두 ancestor로 포함했다. 동기화 후 backend main/test 및 DATA 제품은 검사한 통합 기준 `9b7cda3b`와 차이가 없고 FE는 최신 develop과 같다. 따라서 무관한 FE 동기화로 서버 검사를 반복하지 않았다.
