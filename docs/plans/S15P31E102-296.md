## 구현 결과

1. `POST /api/webhooks/kakao/events`는 쿠키 없이 최대16KiB SET를 검증하고 빈202, 검증 실패400 err/description, 일시 장애503을 반환한다. 설정 미주입 상태에서도 기동하며 수신은503이다.
2. RS256·typ·kid·issuer·aud·app_id·주체·이벤트 구조·iat/toe·선택 exp/nbf를 검사한다. 고정 JWKS만 사용하고 리다이렉트 금지, 연결500ms·읽기750ms·32KiB,5분 캐시·10초 조회 제한을 둔다. 신규 Nimbus JWKSetUnavailableException도503으로 매핑했다.
3. 회원→subject 잠금 뒤 영수증과 연결 삭제를 같은 트랜잭션으로 처리한다. 동시 중복에서 먼저 영수증을 확인해 불필요한 소유자 변경503을 피한다. 실제 소유자가 달라졌으면 롤백·503으로 재전송받는다.
4. state의 시작 시각을 MERGE·연결 행에 전파하고, 해제 이전 흐름의 로그인/연결/병합을 워터마크로 막는다. V9에서 발급된 티켓도 STATE+MERGE 최대20분 경계로 보수적으로 처리한다. 이미 연결된 V9 행의 시작 시각은 복원할 수 없으므로 created_at으로 대체하는 제한을 명시했다.
5. 수신 최대24시간·미래 오차60초, 해시 영수증/워터마크48시간 보관·매분500행 정리를 구현했다. 카카오 재전송은 최초 포함6회(약130분)다. 토큰 원문·키·subject를 새 테이블·로그에 남기지 않는다.
6. 본문 수신 후2.5초 상한, 대기열 없는 최대4작업, DB 트랜잭션1초 제한을 둔다. 취소와 커밋이 겹치면503이어도 처리됐을 수 있으나 재전송 영수증이 중복 효과를 막는다.
7. 회원·연습 기록·비밀번호·다른 제공자·탈퇴 대기 상태·기존 refresh 세션 보존을 확인했다. 정확한 POST만 공개하며 다른 API의 Origin·JSON·인증 보호는 유지한다.
8. Swagger38개(기존 업무37+웹훅1), backend README·DB 계약·환경 예시·Compose 전달을 갱신했다. Notion [웹훅 API 행](https://app.notion.com/409a0252aa4581c782a6cfe9d03ae1ab)에 요청·SET 필드·응답·오류·동일 초 정책·보관·연동 상태를 작성했다. 상태는 In progress, 비고는 로컬 검증 완료·배포/콘솔 활성화 대기로 두었다. 기존 소셜 해제 명세에는 짧은 참조만 남겼다.
