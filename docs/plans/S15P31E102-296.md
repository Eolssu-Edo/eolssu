## 구현 결과

1. `POST /api/webhooks/kakao/events`는 쿠키 없이 최대16KiB SET를 검증하고 빈202, 검증 실패400 err/description, 일시 장애503을 반환한다. 설정 미주입 상태에서도 기동하며 수신은503이다.
2. RS256·typ·kid·issuer·aud·app_id·주체·이벤트 구조·iat/toe·선택 exp/nbf를 검사한다. 고정 JWKS만 사용하고 리다이렉트 금지, 연결500ms·읽기750ms·32KiB,5분 캐시·10초 조회 제한을 둔다. 신규 Nimbus JWKSetUnavailableException도503으로 매핑했다.
3. 회원→subject 잠금 뒤 영수증과 연결 삭제를 같은 트랜잭션으로 처리한다. 동시 중복에서 먼저 영수증을 확인해 불필요한 소유자 변경503을 피한다. 실제 소유자가 달라졌으면 롤백·503으로 재전송받는다.
4. state의 시작 시각을 MERGE·연결 행에 전파하고, 해제 이전 흐름의 로그인/연결/병합을 워터마크로 막는다. V9에서 발급된 티켓도 STATE+MERGE 최대20분 경계로 보수적으로 처리한다. 이미 연결된 V9 행의 시작 시각은 복원할 수 없으므로 created_at으로 대체하는 제한을 명시했다.
5. 수신 최대24시간·미래 오차60초, 해시 영수증/워터마크48시간 보관·매분500행 정리를 구현했다. 카카오 재전송은 최초 포함6회(약130분)다. 토큰 원문·키·subject를 새 테이블·로그에 남기지 않는다.
6. 본문 수신 후2.5초 상한, 대기열 없는 최대4작업, DB 트랜잭션1초 제한을 둔다. 취소와 커밋이 겹치면503이어도 처리됐을 수 있으나 재전송 영수증이 중복 효과를 막는다.
7. 회원·연습 기록·비밀번호·다른 제공자·탈퇴 대기 상태·기존 refresh 세션 보존을 확인했다. 정확한 POST만 공개하며 다른 API의 Origin·JSON·인증 보호는 유지한다.
8. Swagger38개(기존 업무37+웹훅1), backend README·DB 계약·환경 예시·Compose 전달을 갱신했다. Notion 기존 소셜 해제 명세에는 외부 웹훅 규칙을 최소 변경으로 반영했다. 새 API 행 생성은 MCP INVALID_ARGUMENT으로 실패해 재생성하지 않았으며 상세 계약은 저장소 스펙과 Swagger에 있다.

## 검증 기록

- Red→green: 정상 RS256 SET가 구현 전 거절됨 → 통과, 유효기간이 지난 선택 exp가 허용됨 → 거절, 수신 경로/SET 미지원 →202, 해제 전 mergeTicket 재연결 허용 →410·소비 롤백, 배포 전 티켓이 늦은 통지를 우회 →시작 경계 전파, JWKS 조회 장애가400 →503. 각 실패를 실제로 관찰한 후 수정했다.
- Java21.0.11·MySQL8.4, 전용 `eolssu-task296-mysql`/eolssu_test에서 `clean build databaseTest` 성공(단위367·DB132). 이후 V9 티켓·JWKS 장애 매핑 수정과 추가 검사까지 마친 최종 `build databaseTest`도 성공: **단위370·DB135, 실패/건너뜀0**. 최종 JAR 생성도 성공했다. 토큰 서명은 자체 RSA 키, OAuth 제공자 응답은 대역이며 실제 카카오 송신 검증은 아니다.
- `docker compose -f infra/runtime/compose.yml config --quiet` 성공. 실제 비밀값 대신 검증용 임시 환경값만 사용했다.
- 테스트 민감도: Git 작업 파일 대신 `backend/build/task296-sensitivity` 복사본과 별도 eolssu_mutation DB에서 서명 검증 우회·시간 제한/작업 상한 제거·독립 커밋으로 롤백 훼손·정리 누락 결함을 주입했다. 새 단위8개 전부·DB12개 중11개가 실패했고, 남은 동시 중복 검사도 별도로 중복 거절 결함을 넣어 실패를 확인했다. 이 기대된 실패를 본 구현의 회귀 실패로 혼동하지 않는다. 테스트/코드 복사본은 Git에 포함하지 않는다.
- 자기 검토 범위는 기준0052082 이후 코드·기존 인증 호출자·변경/신규 테스트·V10·보안 필터·Swagger·Compose·문서 전부다. 공백 검사도 통과했다. 전용 테스트 컨테이너는 생성 ID를 대조한 뒤 익명 볼륨과 함께 삭제했고, 다른 기존 컨테이너는 보존했다.
- [인증 저장·잠금 지식](../knowledge/backend/auth-token-storage.md)에 회원→subject→이메일→티켓→연결→refresh 순서와 해제/재연결·취소/커밋 경합을 추가했다.
- [스펙](../specs/kakao-webhook.md)에 위협·입력 경계·시간/보관·배포/되돌리기를 기록했다. 원래 기대한 카카오 연결만 정리하는 범위는 유지했고, 실제 선택은 어드민 키 대신 사용자 승인 SET다. DB 워터마크와 시작 시각은 늦은 이벤트·기존 티켓 경쟁을 막기 위한 보완이다.
