## 범위와 완료 조건

운영 도메인의 HTTP 접속을 경로·쿼리·메서드를 보존해 HTTPS로 전환한다. HTTP-01 인증서 갱신, 내부 HTTP 상태 검사와 기존 HTTPS·백엔드·MySQL을 보존한다. 실제 Nginx 요청의 실패 재현과 수정 후 검증, 서버 설정 백업·적용·복구 가능 여부, 작업 단위 커밋을 확인한다.

## 확인과 결정

- 기존 Task 65와 MR !18은 완료·병합 상태다. 별도 수정 Task를 생성하고 Story·에픽·활성 스프린트·진행 중을 MCP로 재조회했다.
- 공개 HTTP 루트는 200을 반환했다. TLS 템플릿에는 443 server만 있어 도메인의 80 요청을 전환하지 않았다.
- TLS 템플릿에 도메인 전용 80 server를 추가한다. 일반 요청에는 고정된 인증서 도메인으로 308을 반환하고 ACME webroot는 HTTP로 제공한다. 기본 HTTP server는 localhost 검사와 초기 인증서 발급에 계속 사용한다.
- 다른 작업의 브랜치·미추적 문서를 보존하고 전용 worktree에서 수정한다. 프론트 자동 배포 Task 73의 ACME 고정 경로 변경은 이 작업에 포함하지 않는다.

## 검증과 결과

- 수정 전 공개 HTTP에서 200을 재현했다. 실제 Nginx 회귀 검사도 GET·HEAD의 200 및 누락 ACME 토큰의 SPA 200으로 실패했다.
- `RUN_NGINX_TESTS=1 python3 -B -m unittest discover -s infra/scripts/tests -v`: TLS 초기화 7개·실제 Nginx 7개, 총 14개 통과. GET·HEAD·POST 308, 경로·쿼리 보존, ACME 200/404, loopback 200, 인증서를 검증한 HTTPS 200, `nginx -t`를 확인했다.
- `python3 -B -m unittest discover -s infra/jenkins/tests -v`: 기존 백엔드 배포·복구 회귀 검사 5개 통과.
- macOS Docker VM에서 기본 임시 폴더를 mount할 수 없어 fixture를 체크아웃 아래 임시 폴더로 격리했다. HTTP와 HTTPS 양쪽 준비 완료 후 검사하며 종료 시 컨테이너·fixture를 정리한다.
- 검사 환경: macOS Python 3.9.6·Docker 29.5.2(Colima), 운영과 같은 `nginx:1.30.6-alpine`. 입력은 임시 webroot·테스트 인증서·GET/HEAD/POST 요청이며 운영 자격 증명은 사용하지 않았다.

## 운영 반영 — 2026-10-22 17:52 KST

- 기존 TLS 설정이 기준 템플릿과 같은 SHA-256인지 확인하고 공용 배포 lock을 획득했다. `/opt/eolssu/tls-redirect-xm1ej3nn/`에 기존 설정과 영수증을 root 전용으로 보관했다.
- 실제 이미지·운영 인증서를 사용하는 네트워크 없는 일회성 Nginx 검사 후, bind mount의 inode를 유지해 TLS 설정만 교체하고 `nginx -t`·reload를 수행했다. 실패 시 이전 바이트를 복구하고 검사·reload하는 절차를 준비했다. 이번 적용에서 복구 분기는 실행되지 않았다.
- 서버 영수증: `/opt/eolssu/tls-redirect-xm1ej3nn/receipt.json`, 적용 설정 SHA-256 `347e833e878b84eadfa435537ed1ecb4fec04ede5b708793acb99ca3920ac538`.
- 서버 검사: GET·HEAD·POST 308, 실제 임시 ACME 파일 200·누락 파일 404, loopback 루트 200·API JSON 404, HTTPS 루트 200·인증서 검증, Certbot timer 활성화를 확인했다. 생성한 ACME 검사 파일은 삭제했다.
- 프론트·백엔드·MySQL의 컨테이너 ID·기동 시간·재시작 횟수가 동일했다. Compose·환경변수·인증서·DB 볼륨은 변경하지 않았다.
- 17:53 KST 외부 요청: HTTP `/`와 `/nested?x=1&y=two%20words`의 308·정확한 Location을 확인했다. `curl -L`은 HTTPS 200·전환 1회·인증서 검증 0(성공), HTTPS API는 기존 Spring JSON 404였다. 서버 설정 해시와 Nginx 검사도 재확인했다.

이 변경만 되돌려야 하면 위 백업의 `nginx.tls.conf`를 원래 파일에 `cp`로 복사하고 `docker exec eolssu-runtime-frontend-1 nginx -t` 통과 후 `nginx -s reload`를 실행한다. 공용 배포 lock을 사용하고 후속 설정 변경이 없는지 먼저 대조한다. 파일 교체용 rename은 기존 bind mount가 새 inode를 참조하지 않으므로 사용하지 않는다.
