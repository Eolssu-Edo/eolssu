# S15P31E102-701 Mattermost 점검 명령 통합과 보고서 표 구분

- Mattermost CI/CD 채널의 점검을 호스트별 `/edo1`, `/edo2`로 통합한다. 기존 상태·서버·컨테이너 검사의 판정과 측정값을 유지하고, 짧은 제목과 주제별 표로 표시한다. [Jira 작업](https://ssafy.atlassian.net/browse/S15P31E102-701) · [운영 모니터링 Story](https://ssafy.atlassian.net/browse/S15P31E102-41) · [메시지 스펙](../specs/mattermost-inspection-messages.md)
- 중계에서 기존 세 SSH 수집을 순차 실행한다. 한 모드의 실패를 해당 표의 미측정으로 표시하고 성공한 모드의 결과를 보존한다. 보고서가 여러 게시물로 나뉘면 같은 요청 ID를 사용한다.
- 실제 Mattermost 11.7.2에서 기존 상태 점검 명령의 트리거를 변경해 토큰을 유지한다. 새 트리거는 edo2의 비공개 설정에서 기존 토큰 키를 옮겨 연결한다. 두 명령이 동작하면 나머지 네 명령을 되돌릴 수 있게 비활성화한다. `/applog`의 접수와 조회는 기존 규칙을 따른다. [전환·복구 절차](../../infra/edo-check/README.md#통합-명령-전환과-복구) · [Mattermost 명령 수정 구현](https://github.com/mattermost/mattermost/blob/v11.7.2/server/channels/app/command.go#L703-L733)

## 검증과 반영

- 점검기 자동 테스트 102건이 통과했다. 부분 수집 실패, 다른 채널 차단·중복 요청, 긴 표의 분할·머리글·길이 제한, `/applog` 회귀를 확인했다.
- 실제 두 호스트의 전용 SSH로 각 세 모드를 수집하고 같은 입력의 기존 표와 통합 표를 대조했다. 행·측정값·판정 건수를 확인했고 edo1은 9,731자와 8,610자, edo2는 7,336자로 생략 없이 표시했다.
- 2026-11-10 16:48 KST에 운영 중계에 반영했다. 16:49~16:50에 CI/CD 채널에서 두 명령을 실행해 제목·주제별 표·요청 ID와 journal의 게시 성공 세 건을 확인했다. edo2는 네 판정 건수가 모두 0이었다. edo1은 장애·주의·미검증 0건, 서버 미측정 3건과 컨테이너 미측정 1건이었다. Docker 저장공간 수집 시간 초과가 기존 입력 비교에서도 관측됐다. - 이전 네 명령의 트리거를 보관용 이름으로 변경하고 자동 완성을 해제했다. 중계에서 기존 토큰 키를 제거해 두 통합 명령만 허용되는 것을 확인했다. `/applog`와 다른 설정은 동일하다. 최종 `/healthz`가 정상 응답했다. 복구용 원본과 전환 중간 설정은 edo2의 root 전용 `/var/backups/edo-check/S15P31E102-701-20261110T074840Z`에 있다.
