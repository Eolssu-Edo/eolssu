## 작업별 완료 조건과 검증

### FE-1 측정기

- 완료 조건:
  - 화면 보임·가려짐, 활동(입력, 재생·녹음·메트로놈 시작·정지), 시간 경과를 입력으로 받아 구간을 열고 닫는다. 플랫폼 코드 없이 `commonMain`에 둔다.
  - 가려지면 구간을 닫고, 다시 보이면 새 구간 키로 연다.
  - 재생·녹음·메트로놈 중에는 입력 없이도 인정 시간을 센다.
  - 마지막 활동 뒤 9분 30초에 알림 이벤트를 한 번 내고, 10분 뒤에는 인정 시간을 멈춘다. 다음 활동에서 다시 센다.
  - 인정 시간 10초 미만 구간은 닫을 때 버린다. 상한은 없다.
  - 30초마다 저장할 상태(스냅샷)를 내놓고, 스냅샷으로 닫힌 구간을 복원할 수 있다.
- 검증: 가짜 시계로 `commonTest`에 스펙 '완료 확인'의 FE 측정 항목을 테스트한다. 고정 sleep은 쓰지 않는다. `frontend/`에서 `./gradlew :shared:testAndroidHostTest`, `./gradlew :shared:wasmJsTest`.

### FE-2 기기 저장과 전송

- 완료 조건:
  - 열린 구간 스냅샷을 30초마다 덮어쓰고, 닫힌 구간을 대기열에 넣어 바로 보낸다.
  - 앱 시작·복귀 때 대기열을 보내고, 닫히지 않은 구간은 마지막 저장 시각으로 닫아 넣는다.
  - 같은 구간은 같은 키와 본문으로 다시 보낸다. 응답별 처리(201·200·409·400·404 삭제, 401 갱신 후 재시도, 5xx·네트워크 오류 유지)는 스펙 표를 따른다.
  - 측정한 회원으로 로그인한 상태에서만 보낸다. 로그아웃 때 한 번 보내 보고 남은 기록은 지운다.
- 검증: 저장소·HTTP 대역으로 같은 FE 명령. 실제 서버 연동은 BE-1 이후 CP-1에서 확인한다.
- 위험: 기기 저장소·HTTP 클라이언트를 고르는 일은 앱 전체 기반이다. 이 Task에서 고르지 말고 기반 작업과 [FE 결정 기록](../decisions/frontend-navigation-di.md) 방식으로 따로 정한다.

### FE-3 화면 연결

- 완료 조건: Android·iOS 앱 생명주기와 웹 탭 숨김을 측정기 입력으로 연결하고, 화면의 터치·스크롤과 재생·녹음·메트로놈 상태를 활동으로 넘긴다. 9분 30초 알림을 띄우고, 누르면 활동으로 보낸다. 측정 범위는 스펙 미결 사항(곡 상세 미리보기 포함 여부)이 정해진 대로 따른다.
- 검증: 화면 상태 단위 테스트는 같은 FE 명령. 백그라운드·화면 잠금·탭 숨김은 CP-1 실행 검증으로 확인한다.

### BE-1 체류 기록 저장 API

- 완료 조건:
  - `Idempotency-Key`와 본문(곡, 시작·끝, 보인 시간, 인정 시간)을 받아 `score_views`에 저장한다. 새 키 201, 같은 키·같은 본문 200, 같은 키·다른 본문 409.
  - 400: 끝 < 시작, 인정 > 보인, 음수, 보인 시간 > 구간 길이 + 1초, 보인 시간 > 서버 수신 시각 − 시작. 없는 곡 404. 인증 없음 401.
  - 같은 키를 동시에 두 번 보내도 한 행만 남는다(`uq_score_views_user_idempotency` 위반은 기존 행 비교로 처리).
  - 경로와 오류 형식은 Notion GRO-04에 맞추고, 다르면 API 명세 담당(S15P31E102-139)에게 전달한다.
- 검증: 고정 시계로 `backend/`에서 `./gradlew test`. 저장·중복·동시 요청은 `./gradlew databaseTest`(TEST_DB_* 필요). 마무리 때 `./gradlew clean build`.

### BE-2 합산 조회

- 완료 조건: 회원의 기간별 `counted_seconds` 합을 `started_at`의 KST 날짜 기준으로 돌려준다. 23:50 KST 시작·00:20 끝 구간은 시작한 날에 30분으로 센다. 여러 기기 구간은 그대로 더한다.
- 검증: KST 경계 고정 데이터로 `./gradlew databaseTest`. 조회가 `idx_score_views_user_started`를 쓰는지 `EXPLAIN`으로 확인한다.
- 선행 결정: GRO-01·02가 보여 주는 기간(일·주·누적)과 '연습한 날' 판정. 정해지기 전에는 시작하지 않는다.

### DATA-1 마트 총 연습 시간

- 완료 조건: `mart_daily_practice`에 `total_practice_seconds`를 더한다(새 마트는 `schema.sql`, 이미 만든 마트는 `ALTER` 안내). 일 배치는 `(KST 날짜, 악기)`별로 그날 시작한 구간의 `counted_seconds`를 곡의 악기로 묶어 더한다.
- 검증: 작은 고정 데이터로 집계 결과를 비교한다. 마트 배치 코드와 검사 명령이 아직 없어서, 채우기 검증 방법은 배치 작업에서 정한다.
- 위험: 집계 DB 계약 변경이다. Grafana·Metabase에서 이 테이블을 읽는 화면이 있으면 함께 확인한다.

### CP-1 실행 검증

- 완료 조건: Android·iOS·웹에서 악보 화면을 보다가 백그라운드·화면 잠금·탭 숨김을 하면 구간이 닫혀 서버에 저장된다. 오프라인에서 연습하고 다시 연결하면 한 번만 반영된다. 강제 종료 뒤 다시 실행하면 마지막 저장값으로 보낸다. 성장 화면 합산이 서버 값과 같다.
- 검증: 실행 기록(기기·버전·입력·화면·서버 행)을 남긴다. 무거운 검증이므로 담당자와 실행 시점은 Task를 만들 때 정한다.
