- omr 테스트 실패 1건: `test_staff_musicxml.py::test_many_notes_are_laid_out_in_linear_time`은 4000음 변환이 벽시계로 1초 안에 끝나야 한다(원래 실측 0.13초). 에뮬레이션에서 1.45~2.3초가 걸려 실패했다. 게이트는 이 실패에서 종료 코드 1로 멈췄다. edo1(네이티브 amd64) 첫 실행에서 통과하는지 본다. AI 파트 테스트라 이 작업에서 고치지 않는다.
- 첫 시도에서 고친 것: omr 테스트 환경을 `uv sync --inexact`로 만들면 스캔 확장이 올린 `pypdfium2 5.15.2`·`pycparser 3.12`가 lock 버전으로 내려가 운영과 다른 환경이 됐다. 설치된 버전을 제약으로 걸고 dev 그룹만 `--no-deps`로 더하게 바꿨다. playback은 `unittest discover -t .`가 네임스페이스 패키지라 시작 폴더를 못 읽어, `data/README.md`와 같은 명령으로 바꿨다.
- 로컬 Compose 통합: `infra/runtime/compose.yml`을 대역 `.env`로 렌더링하고 omr·playback의 syslog 로그 설정만 뺀 파일로 프로젝트 `eolssu-runtime`을 띄웠다. backend는 같은 내부망의 curl 컨테이너로 대신했다. 대역으로 바꾼 것은 DB 대기열 값, 보호 서비스 비교, 다른 배포 확인, Git 순서 검사다. 태그·재생성(`--wait`, playback `--profile playback`)·health·backend 쪽 빈 요청·도구 확인·journal·되돌리기는 실제 도구 코드다.
  - omr: 대기열 2건 → 0건이 된 뒤 교체(10.1초). `eolssu-omr:rollback`=이전 이미지, journal `deployed`·`failed_during_switch: 0`. 이어서 `plan`이 `skip`.
  - playback: 대기 단계에서는 0건, lock 안 재확인에서 1건 → 바꾸지 않고 lock을 놓은 뒤 다시 시도해 교체(13.9초). 이 시도에 `phase_failed`가 없어 Jenkins 단계가 실패로 표시되지 않는다. 같은 후보 재실행은 `already_deployed`로 재생성하지 않음.
  - 바로 종료하는 고장 이미지(`CMD false`, 라벨은 정상): `Recreate playback service` 단계 실패 → 이전 이미지로 복구, healthy, journal `rolled_back`(8.5초).
- 확인하지 못한 것: edo1에서의 빌드·테스트 시간과 위 속도 테스트, 실제 CAT 자산으로 띄운 smoke와 실제 음원 생성, 운영 DB·backend 컨테이너를 통한 도구의 대기열 조회, sudo 설치, Jenkins sandbox에서 `String.replaceFirst` 승인 여부(linter는 sandbox를 보지 않는다). 운영 설치 4단계의 Build Now에서 확인한다.
