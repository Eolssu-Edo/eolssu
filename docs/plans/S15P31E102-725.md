# 내 악보 편집 진입과 저장 오류 처리

- Jira: S15P31E102-725 · Story S15P31E102-319 · Epic S15P31E102-16.
- 시작 상태: 스프린트 5(59321), 진행 중. 기준 develop `93dcb1a5`.
- 범위: 검토 대기 악보를 바로 편집기로 연결하고 정간보 단일 화면을 제공한다. 왼쪽에는 빠르기와 편집 버튼을 둔다. 상단 ‘저장하기’는 제목·빠르기·예상 음원 길이를 표시하는 창을 열고 바로 저장한다.
- 저장 조건: 확인하지 않은 정간과 현재 잘못된 음·장단 불일치는 확정 저장을 막고 해결 동작을 제공한다. 자동·임시 저장은 유지한다. 변환 당시 안내와 현재 오류를 구분한다.
- 장단 불일치는 음표·tick을 임의로 늘리거나 줄여 해결하지 않는다. 사용자가 호환 장단을 선택하거나 장단 사용을 해제하도록 한다. 장단 해제는 실행 취소할 수 있다.

## 검증 계획

- 미확인·잘못된 음의 저장 차단, 수정·확인 후 저장, 실행 취소 후 재차단을 작은 고정 데이터로 검사한다.
- 장단 불일치의 확정 저장 차단과 임시 저장 허용, 장단 해제 시 음표·시간·배치 보존, 재진입 및 실행 취소를 검사한다.
- 정상 악보와 전조 등 정보성 안내만 있는 악보의 저장을 유지한다.
- Android 호스트 테스트와 APK 빌드를 실행한다. 별도 앱 ID와 메모리 저장소로 편집 화면의 저장 창, 제목·빠르기 변경, 예상 길이 갱신, 오류 차단을 확인한다.
- iOS 기기 검증과 운영 서버 배포는 이 작업에서 수행한 것으로 보고하지 않는다.

## 진행

- 검토 대기 항목은 직접 편집으로 이동한다. 기존 열람 URL은 편집 경로로 넘기며 완료 악보의 연습 진입은 유지한다.
- 편집 화면의 표기 전환과 오선보 UI를 제거했다. 정간보 단일 편집과 왼쪽 빠르기·편집 버튼을 적용했다.
- ‘편집 내용 확인’을 ‘저장하기’로 바꿨다. 후속 사용자 요청에 따라 다음 페이지 이동을 없애고 대화상자에서 제목·빠르기와 예상 음원 길이를 확인한 뒤 직접 저장한다. 미리듣기는 별도 버튼으로 유지한다.
- 빠르기 저장 때 삼성 패스가 로그인 정보 저장을 제안한다는 후속 제보를 반영했다. 공통 숫자 입력이 `KeyboardType.NumberPassword`로 전달되던 것을 `Number`로 수정했다. 실제 비밀번호 입력 유형은 유지한다. 일반 숫자 입력 전체에 같은 원인이 반복되지 않도록 공통 입력 컴포넌트에서 처리한다.
- 완료 검증을 요청 전·저장 잠금 안에서 수행한다. 확정 요청 중 편집을 막고, 음역 정보 조회 실패에는 다시 받기 동작을 제공한다.

## 자동 검증

- JDK 21, Android SDK 37 환경에서 `:shared:testAndroidHostTest`와 `:androidApp:assembleDebug`를 통과했다(`frontend/gradlew.bat`, `--max-workers=2 --console=plain`). 화면용 별도 앱 ID 검증 빌드는 로컬 init script를 추가했고, 이후 init script 없이 일반 앱 빌드도 다시 통과했다.
- 194개 테스트 묶음, 총 1,314개 중 1,310개 통과·4개 건너뜀·실패 0·오류 0. 새 직접 저장 순서/재시도 2개와 예상 길이 6개를 포함한다.
- 현재 오류 수정·확인, 실행 취소, 장단 해제와 시간 보존, 저장 경합, 음역 카탈로그 로딩·실패·재시도 회귀를 확인했다. 독립 코드 검토에서 나온 저장 응답 경합과 음역 조회 문제를 수정하고 재검토했다.
- `git diff --check` 통과. 구현 검증 종료 시점에는 커밋·Push·배포를 수행하지 않았다. 이후 사용자의 MR 요청에 따라 아래 발행 준비를 진행한다.

## 화면 검증과 남은 범위

- Android 17/API 37 `Medium_Phone` 에뮬레이터, `com.ssafy.eolssu.preview725`의 메모리 저장소와 고정 악보를 사용했다. 네트워크·녹음 권한이 없는 별도 검증 앱이다.
- ‘저장하기’가 편집 화면 위의 저장 창을 직접 여는 것을 확인했다. 제목 `Changed725`, 120 BPM으로 확정 저장한 뒤 112 BPM으로 다시 저장했다. 두 번 모두 `draft=false` 요청값, 성공 후 창 닫힘과 편집 화면의 제목·빠르기 갱신을 확인했다.
- 16정간 고정 악보의 예상 길이는 96 BPM `0:10`, 120 BPM `0:08`, 112 BPM `0:09`였다. BPM 29는 입력 오류를 표시하고 예상 길이를 숨기며 저장을 막았다.
- 장단 불일치에서 저장 버튼이 비활성이고 해결 설명이 표시됐다. ‘장단 사용 안 함’ 이후 저장이 활성화되며 확정 저장에 성공했다. 실제 캡처에서 제목·입력란·설명·버튼 잘림은 없었다.
- 두 차례 빠르기 입력의 Android EditorInfo는 `inputType=0x2`, UI 계층은 `password=false`였다. 일반 숫자 입력 전달을 확인한 결과이며 삼성 패스 자체 검증을 뜻하지 않는다.
- 검증 산출물: `C:/Users/SSAFY/AppData/Local/EolssuDownloads/verification-725-20261111/ui725/emulator/verification-summary.json`. 같은 디렉터리에 EditorInfo, 저장 요청 기록, 화면 캡처를 보존했다. `normal-save-screen.png`는 후속 요청 이전의 화면으로 최종 검증에서 제외했다. 일시적인 알림과 반올림 값에 관한 검증 스크립트의 잘못된 기대를 수정한 뒤 남은 시나리오를 재개해 완료했다.
- 검증용 APK·init script·하네스는 위 산출물 디렉터리에 보관하고 저장소 변경에서 제외했다. 테스트용 에뮬레이터를 종료했다.
- 삼성 SM-S926N의 ADB 연결이 끊겨 실제 삼성 패스 팝업 재발 검증은 미완료다. 처음 요청한 배포 QA 버전 설치와 이번 소스 수정의 설치는 구분한다. 이번 변경은 사용자 기기에 설치하지 않았다.

## MR 준비

- 사용자 요청: 현재 변경의 MR 생성. 대상은 `develop`이며 병합·배포는 포함하지 않는다.
- 최신 `origin/develop` `af659a8f`를 fast-forward로 반영했다. upstream 변경 10개 파일과 이 작업 변경은 겹치지 않는다. 기존 화면 검증 대상 코드는 유지됐다. 통합 후 `:shared:testAndroidHostTest :androidApp:assembleDebug` 성공(1분 7초): 1,316개 중 1,312개 통과·4개 건너뜀·실패 및 오류 0개. 로그는 검증 산출물의 `mr-build.log`다.

- GitLab CLI API 인증과 브라우저 조작이 불가능해 Git push option의 MR 생성 기능을 사용한다. 라벨 목록 조회와 저장된 담당자·리뷰어·본문의 API 재조회는 미완료이며, 재확인할 수 없으면 완료로 보고하지 않는다.
