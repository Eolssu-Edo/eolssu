## 결정·제약

- Jenkins 빌드는 컨테이너 컨트롤러가 아니라 edo1 호스트 에이전트(`edo1-host`, Ubuntu 24.04)에서 돈다. 호스트 apt의 `ffmpeg=7:6.1.1-3ubuntu5`를 설치했다. 운영 이미지(8.0.1)와 메이저가 다르지만 호스트 배포판 버전을 쓰기로 했다(사용자 결정). 운영 버전 판정은 실행 컨테이너의 ffprobe로 따로 확인한다.
- 백엔드 잡은 파이프라인을 SCM이 아니라 잡 설정(`CpsFlowDefinition`)에 직접 둔다. 변경 전 잡 스크립트는 저장소 `infra/jenkins/backend.Jenkinsfile`과 같았고(끝 줄바꿈 차이만), 같은 내용을 기존 관리자 CLI `update-job`으로 반영했다. 스크립트 외 잡 설정은 백업과 같다.
- 서버 `backend.Dockerfile`로 만드는 `eolssu-backend:ci-<SHA>`는 후보 검증과 JAR 추출에만 쓰인다. 운영 compose는 `eclipse-temurin:21-jre`에 JAR만 붙여 실행하므로 Dockerfile 변경만으로는 운영에 ffprobe가 없었다(빌드 #53 뒤 컨테이너에서 `ffprobe` not found 확인). 운영 compose의 backend 이미지를 `eolssu-backend-runtime:21-jre-ffmpeg8.0.1`(베이스 + ffmpeg 8.0.1)로 바꿨다(사용자 결정, 1안). JAR mount·환경변수·healthcheck·배포 스크립트는 유지한다. 이미지는 약 410MB 커지고, 베이스 보안 업데이트는 이 이미지를 다시 빌드해 반영해야 한다.
