# S15P31E102-798 로그인·회원가입·비밀번호 찾기 화면을 마이페이지 스타일로 변경

- Jira: [S15P31E102-798](https://ssafy.atlassian.net/browse/S15P31E102-798) (Story S15P31E102-109 UI/UX, 에픽 S15P31E102-1)
- 브랜치: `feat(fe)/S15P31E102-798-로그인·회원가입·비밀번호-찾기-화면을-마이페이지-스타일로-변경` (develop `0f6000aa`에서 시작)

## 범위와 완료 조건

- 첫 로그인 화면과 거기서 이어지는 화면(비밀번호 찾기 1·2단계, 회원가입 약관 동의·약관 보기·이메일 인증·비밀번호 설정·프로필 설정, 간편 로그인 연결·진행 화면)을 S15P31E102-768 마이페이지 방향으로 맞춘다.
- 완료 조건: 회색 바탕 위 테두리 없는 흰 입력칸·카드, 하단 버튼 위 구분선 없음, 공유 테스트·JS 컴파일·Android 설치 빌드 통과, 에뮬레이터 화면 확인.

## 결정

- 화면마다 고치지 않고 공통 틀(`AuthScaffold`)에서 바탕을 `groupedBackground`로, 하단 구분선을 끄도록 바꿔 인증 화면 전체에 같이 적용했다. 태블릿 가로의 브랜드 칸 옆 바탕도 같은 회색이다.
- 입력칸은 모두 `bordered = false`(평소 흰 채움, 오류일 때만 빨간 테두리)로 비밀번호 변경 화면과 맞췄다.
- 간편 로그인 버튼은 테두리를 뺐다. Google 흰 버튼도 회색 바탕 위에서 구분된다. 제공사별 바탕·글자색은 그대로 둔다.
- 체크 상자는 테두리 없이 고르면 연두, 안 고르면 채움색만 둔다. 회색 바탕(로그인)은 흰 채움, 흰 카드 안(약관 동의)은 `cardLine` 회색 채움이다. 쓰지 않게 된 `AuthFaint`를 지웠다.
- 체크 상자는 옆 글자·줄 전체가 아니라 상자만 눌린다(추가 요청). 누르는 영역은 Compose가 작은 누름 대상을 최소 48dp로 넓혀 주는 기본 동작에 맡기고, 화면 읽기는 상자에서 이름('[필수] 서비스 이용약관' 등)을 읽고 글자는 읽지 않는다. 로그인의 '아이디 기억하기'·'자동 로그인'과 약관 동의 전체에 적용했다.
- 약관 동의는 '모두 동의해요'만 감싸던 테두리 상자 대신 동의 목록 전체를 테두리 없는 흰 카드 하나(모서리 20dp)에 담았다.
- 인증번호 '다시 받기'는 테두리 없는 흰 알약(막히면 회색 채움), 간편 로그인 연결의 계정 카드는 테두리 없는 흰 카드로 바꿨다. 단계 막대의 빈 점 안은 흰색으로 했다.
- 프로필 설정의 악기 고르기는 고르지 않은 칸이 회색 채움이라 회색 바탕에서 사라져, `InstrumentPicker`에 `unselectedColor`를 두고 이 화면만 흰 채움을 넘긴다. 다른 화면은 기존 회색 그대로다.
- 로그인 화면은 사용자가 보낸 참고 화면처럼 단순하게 다시 배치했다(추가 요청): 로고 → 이메일·비밀번호 → 아이디 기억하기·자동 로그인 → 로그인 → '비밀번호 찾기 | 회원가입'(두 링크 같은 회색 글자) → '간편 로그인' 구분 줄 → 카카오·네이버·Google 동그라미(56dp) 버튼. 쓰지 않게 된 '이메일로 회원가입' 문구를 '회원가입'으로 바꿨다.
  - 간편 로그인은 제공사 심볼만 둔 동그라미로, 화면 읽기는 'OO로 로그인'을 읽는다.
- 로그인·가입·비밀번호 찾기 입력칸은 칸 위 이름표 대신 이름을 자리 글자로만 둔다(`EolssuTextField`의 `labelInside`). 입력하면 이름은 사라지고 입력한 값만 보인다. 처음엔 이름표를 칸 안 위로 올리는 두 줄 칸(60dp)이었으나 칸이 뚱뚱해 보여 바꿨다. 로그인 칸 높이는 48dp, 가입 칸은 기본 52dp다. 화면 읽기는 칸 이름을 그대로 읽는다.
- 테두리 없는 입력칸은 오류일 때도 빨간 테두리를 두르지 않고 같은 흰 칸 그대로 두며, 오류는 아래 문장으로만 알린다(추가 요청). 마이페이지 비밀번호 변경 등 다른 테두리 없는 칸에도 같이 적용된다. 테두리 있는 칸은 그대로 빨간 테두리다.
- 로그인 화면 아래 산 그림은 회색 바탕에서도 자연스러워 그대로 두었다.
