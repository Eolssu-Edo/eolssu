## 확인한 사실 (2026-11-04)

- 채점 `score()`(`ai/src/ai_service/pipelines/scoring.py`)는 놓치지 않은 음마다 두 값을 이미 계산한다.
  - `raw`(220행): 음정 측정 프레임의 중앙값. 단위는 황(E♭4) 기준 센트다. `err = raw - applied - 100·semitone`이다. `applied`는 채점에 적용한 조율 보정이고, 상한을 넘으면(`tuning_out_of_range`) 0이다(213~214행).
  - `onset_frame`(224~239행): 녹음에서 그 음이 시작된 프레임. f0는 업로드 원본 전체를 자르지 않고 처음부터 계산하므로(`api.py` `_score_recording`), `onset_frame × HOP_S`가 업로드 녹음 0초 기준이다.
- 응답은 `api.py` `_response()`의 dict이고, `NoteOut`은 OpenAPI 문서용 모델이다. `tests/unit/test_api.py`가 두 모양(`NOTE_KEYS`, `aliases(NoteOut)`)을 맞춘다.
- 응답 계약 문서는 [PRA-03 분석 요청과 상태 조회 계약](../specs/practice-analysis-failure.md#분석-요청과-상태-조회-계약-s15p31e102-186)이고, `ai/README.md`가 이를 가리킨다.
- 서버 AI는 develop에 병합해도 자동으로 바뀌지 않는다. edo1에서 `eolssu-ai:runtime`을 다시 빌드해야 한다(`infra/runtime/README.md` "ai 분석 서비스").

## 결정 (BE와 합의, 2026-11-04)

| 번호 | 내용 |
| --- | --- |
| D-1 | `detectedSemitone`은 `pitches.semitone`과 같은 눈금(황 0 = E♭4, 정수)이다. 값은 `round((raw - applied) / 100)`, 곧 채점에 적용한 조율 보정을 뺀 뒤 가장 가까운 반음이다. `tuningOutOfRange`이면 `applied`가 0이므로 `tuningOffsetCent`를 빼면 안 된다 |
| D-2 | `recordingOffsetMs`는 업로드한 녹음 파일 0ms 기준으로 그 음의 소리가 실제로 시작된 시각이다. 값은 `round(onset_frame × HOP_S × 1000)`이고 10ms 단위의 정수다. 녹음 앞 여백을 포함한 그대로다. 구간 연습도 그 연습 녹음의 0ms 기준이다 |
| D-3 | MISSED(놓친 음)는 두 값 모두 `null`이다. 그 밖의 판정(CORRECT·PITCH·TIMING)은 두 값이 항상 있다 |
| D-4 | 점수·판정·기존 필드는 바꾸지 않는다. 채점 결과가 같으므로 `modelVersion`(`pyin-5`)도 유지한다 |
| D-5 | `pitches`에 없는 반음은 AI가 걸러 내지 않고 그대로 준다. BE가 `detected_pitch_id`를 `null`로 저장한다(480) |

### U1 채점 결과에 두 값 담기

- 내용: `NoteResult`에 `detected_semitone: int | None`과 `recording_offset_ms: int | None`을 더한다. `score()`에서 D-1·D-2대로 채운다. MISSED는 기본값 `None`이다.
- 수락:
  - 합성 f0(`f0_of`처럼 정확한 높이)로 만든 음은 `detected_semitone`이 정답 semitone과 같다.
  - 반음 높게 분 음은 +1이 나온다.
  - 조율이 상한을 넘은 경우는 보정 없이 반올림한 값이 나온다.
  - 앞에 0.5초 무음을 붙이면 `recording_offset_ms`가 그만큼 커진다.
  - 놓친 음은 두 값 모두 `None`이다.
  - 기존 판정·점수가 그대로다.
- 검증: 위 경우를 먼저 테스트로 쓰고 실패를 확인한 뒤 구현한다. `ai/tests` 전체를 돌린다.

### U2 응답과 문서 모델

- 내용: `_response()`의 음표 dict와 `NoteOut`에 `detectedSemitone`·`recordingOffsetMs`를 더한다. 설명 문구에 D-1·D-2 정의를 적는다.
- 수락: `test_api.py`의 `NOTE_KEYS`가 새 키를 포함한다. 응답과 문서 모델의 키가 같다. 두 값의 타입이 `int`다(BE는 Int로 읽음). MISSED 음은 두 값이 `null`이다.
- 검증: `ai/tests` 전체.

### U3 계약 문서

- 내용: PRA-03 계약(`docs/specs/practice-analysis-failure.md`)의 응답 표에 두 필드를 넣는다. 정의, `null` 조건, 한계를 적는다. 한계는 두 가지다. 같은 높이로 이어 분 음은 시작을 구분하지 못한다. 시김새 음은 꾸밈이 섞인 중앙값이다. `ai/README.md`의 응답 설명도 맞춘다.
- 수락: 문서의 필드 이름·타입·정의가 코드와 같다. Notion API 명세서에 AI 응답이 있으면 BE 담당(480)과 누가 고칠지 확인한다.
