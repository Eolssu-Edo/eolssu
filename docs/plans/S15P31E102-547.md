- 사용자 요청(2026-11-06): '완료한 단계'·'곡별 최고 점수' 카드 삭제, '점수 변화 · 최근 5회'에 악기·곡 선택 추가, 기본 평가만 최근 5회로 표시. 정간보 크기·한자 잘림은 다른 세션.

## 기본 평가 기준 (사용자 결정 2026-11-06)

- 앱은 취약 구간 재평가만 구간 범위와 `parentSessionId`를 붙여 세션을 만들고, 곡 전체 연주('같은 곡 다시 연습'·'다시 연주하기' 포함)는 기준 세션 없이 만든다.
- 그래서 GRO-03 `scope=FULL`(곡 전체 범위 연주)을 기본 평가로 쓰고 '구간' 범위 칩을 없앴다. 서버가 FULL만 골라 최근 5개를 오래된 순으로 주므로 '기본 평가만 거른 뒤 최근 5개'가 서버에서 보장된다.
- 곡 전체 다시 연주는 기본 평가에 넣는다.
- 남은 경계: 취약 구간이 곡 전체를 덮으면 그 재평가가 FULL에 섞인다(서버는 `parent_session_id`를 보지 않음). 사용자 결정으로 서버·API 계약은 바꾸지 않았다.

## 변경

- 악기는 GRO-03 응답에 없어 앱이 곡 목록(CAT-01 `/api/instruments`, CAT-02 `/api/songs`)의 `instrumentId`로 곡을 묶는다. 목록을 받지 못하면 악기 줄 없이 곡만 고른다.
- 곡 목록은 게시·미삭제 곡만 주지만 GRO-03은 지우거나 비공개로 바꾼 곡의 연주도 준다. 처음엔 이런 곡을 '기타'로 묶었으나 실기기(test1 계정)에서 대금 곡이 '기타'로 보여, 사용자 결정(2026-11-06)으로 곡 목록에 없는 곡은 점수 변화에서 뺀다(A안). 기록이 없는 악기는 칩에 없다.
- 후속: 백엔드에 GRO-03 `songs[].instrumentId` 추가와 해당 계정의 빠진 곡 확인을 요청했다. 응답이 오면 서버 값을 먼저 쓰도록 바꾼다.
- 기본 평가가 없는 곡(재평가만 있음)은 곡 고르기에서 빼고, 서버가 그런 곡을 기본으로 고르면 가장 최근 기본 평가 곡을 다시 받는다. 기본 평가 곡이 하나도 없으면 빈 상태 문구.
- `GrowthViewModel`은 `LearnProgressRepository`·`InstrumentRepository` 대신 `SongRepository`를 받는다. `GrowthRoute`의 `onOpenSteps`·`onOpenRecords`는 두 카드와 함께 없앴다. GRO-01 `bestBySong` 파싱·`GrowthStats.bestBySong`은 그대로 둔다.
