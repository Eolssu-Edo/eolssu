## 초기 구현과 검증 (e7e83458, 후속 지시로 대체)

- 원인: `SheetReviewIssue`가 `detail.reason`을 버리고, `SheetEditRoute`의 정간 클릭은 NOTE 음고 교정 후보만 조회하므로 REST의 미확인 검수가 있어도 안내를 열지 않는다.

- 실제 초안 재생: 로컬 보관한 35번·revision3 입력과 공개 단소 지원음을 같은 ViewModel에 로드했다. `selectedReviewIssue.reason=GAP_IN_VOICE`, 음역 오류 0·구조 정상·미확인 1·쓰기 0이며 기존 REST 이벤트·길이·시간을 보존했다. 하네스는 실행 후 제품 테스트 폴더에서 제거하고 원본·결과·로그는 `output/review-hint-890/`에 보존했다. 운영 서버에는 쓰지 않았다.
- 구현: 미확인 검수 칸을 누르면 기존 검수 대화상자를 연다. 음고 교정 후보가 있으면 기존 팝업을 우선하고, 소박 클릭은 실제 붉은 소박에서만 검수 대화상자를 연다. GAP 문구는 LOW_CONFIDENCE/GAP_IN_VOICE에만 사용한다.

## 클릭한 위치의 정보로 분리

- 사용자 후속 지시: “클릭한 거에 대한 정보를 보여줘야지. 전체적인 정보를 보여주면 어떻게 해.” 기존 전체 검수 창 재사용 선택을 철회하고, 해당 위치·기호·사유와 닫기만 있는 클릭 전용 창으로 바꾼다. 전체 저장 검수와 `확인했어요`는 저장 버튼 경로에 남긴다.
- 범위 회귀: 같은 정간의 다른 소박에 연결된 이벤트 검수가 함께 나오는 실패를 먼저 확인했다. 셀 전체 검수와 이벤트별 검수를 나눠 클릭한 현재 이벤트에만 연결하고, 이음도 가리키는 이벤트를 기준으로 조회한다. 다른 정간·이벤트의 사유를 추정하거나 합치지 않는다.
- 후속 구현·실행 UI·전체 검사: 진행 중. 위 초기 검사 결과를 이 후속 변경의 통과로 재사용하지 않는다.
