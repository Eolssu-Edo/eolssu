# S15P31E102-998 악보 변환 대기 화면과 목록 진행 상태·실패 사유 표시 개선

- 계기: 악보 접수 뒤 "접수했어요 → 내 악보 목록으로"로 끝나 언제 끝나는지 모르고, 목록의 진행 표시가 서버와 달라 보이며, 실패 문구가 막연하다(사용자 지적, 2026-11-16).
- 병렬 작업: 997(올리기 화면 `SheetImportScreen`·`EditNewScreen`·파일 선택기), 1000(편집 화면), 1002(AI 서버)의 파일은 고치지 않는다. 999(악기 필터)가 이 Task 뒤에 같은 목록 화면을 고친다.

## 서버 계약 대조 (develop `747a559d`)

- SHT-10 `GET /api/users/me/sheets/{id}/conversion`: `notation`(`JEONGGANBO`·`STAFF`), `status`, `stage`(RUNNING에서 `OMR`·`BUILDING_SCORE`), `processedPageCount`, `pageCount`, `pollAfterMs`(진행 중 2000), `failureCode`, `retryable`.
- 읽은 쪽 수: 백엔드는 OMR을 HTTP 한 번으로 부르고, `processed_page_count`는 인식이 끝나 `BUILDING_SCORE`로 바뀔 때 한 번에 `page_count`로 채운다(`ConversionQueue.building`). 인식 중에는 항상 0이다.
- 공개 실패 코드는 4종이다. OMR의 `NO_GRID_FOUND`·`NO_STAFF_FOUND`는 `NO_SCORE_FOUND`로, `ENGINE_ERROR`는 `SERVER_ERROR`로 바뀌고(`ConversionWorker`·`ConversionQueue.fail`), 만료된 원본의 `UNSUPPORTED_FILE`은 `TIMEOUT`이다. 정간·오선 구분은 `notation`으로 한다.
- `retryable`은 지금 항상 false(`ConversionRetryPolicy`)이고 SHT-14는 409라, 모든 실패의 다음 행동은 새 파일로 다시 불러오기다.

## 원인: 목록 진행 상태가 서버와 다르게 보임

- 앱은 `pageCount > 0`이면 `악보 읽는 중 0/3쪽`을 띄우고 막대를 읽은 쪽 비율로 채웠다. 서버가 인식 중에 쪽 수를 올리지 않아, 실제로는 읽는 중인데 0쪽에 멈춘 것처럼 보이다가 끝날 때 한 번에 바뀌었다(오선보 1쪽 25~30초, 여러 쪽이면 수 분).
- 수정: 읽은 쪽 수는 서버가 실제로 중간값(1~m-1)을 줄 때만 `n/m쪽`으로 보이고, 그 밖에는 `악보 m쪽 읽는 중`으로 쓴다. 대기 화면의 막대는 쪽 수·표기법별 예상 시간으로 상한(읽기 구간 끝) 아래에서 천천히 다가간다.

## 범위와 완료 조건

1. 접수 뒤 대기 화면(`sheet-edit/conversion/{id}`): 붓 일원상(AI 연주 평가 대기 화면의 `BrushEnso`를 `core/ui/component`로 옮겨 재사용)과 단계(대기 → 읽기 → 만들기), 쪽 수, 안내를 보인다. 완료(DONE)되면 같은 화면 대신 편집 화면으로 바로 이동하고 앱 전체 완료 배너는 띄우지 않는다. '내 악보 목록에서 기다리기'로 나가도 변환은 계속되고, 내 악보 목록의 변환 중·실패 줄을 누르면 이 화면으로 다시 들어온다.
2. 목록 진행 표시: 위 원인 수정. SHT-01 목록만 받은 상태에서도 기존처럼 대기로 보인다.
3. 실패 사유: 정간보 격자 못 찾음·오선 못 찾음·표기법 모름·파일 오류·시간 초과·서버 오류마다 원인과 다음 행동을 안내한다. 목록 줄에는 짧은 원인과 행동 한 줄, 대기 화면에는 원인과 할 일 목록, '다시 불러오기'(악보 문제·파일 문제)·'잠시 후 다시 불러오기'(서버 문제) 버튼을 둔다.

API·저장 형식은 바꾸지 않는다.

## 설계 결정과 원래 기대와의 차이

- 원래 기대: 대기 화면에 쪽 진행 `n/m쪽`. 실제: 서버가 인식 중 쪽 진행을 주지 않아 `m쪽 읽는 중`과 예상 시간 기반 진행 막대로 대체하고, 서버가 중간값을 주면 `n/m쪽`을 그대로 쓴다. 쪽 단위 진행이 필요하면 백엔드·OMR 변경이 필요하다(후속).
- 원래 기대: `ENGINE_ERROR` 등 OMR 코드별 안내. 실제: 공개 코드 4종과 `notation`으로 6가지 안내를 만든다. `ENGINE_ERROR`는 서버 오류 안내에 포함된다.
- 올리기 화면은 997 소관이라 `SheetImportScreen`은 고치지 않고, `SheetImportRoute`에 접수 시 이동 콜백만 더했다.
