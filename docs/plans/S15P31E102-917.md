# S15P31E102-917 웹 정적 자산 gzip 압축과 캐시 헤더 적용

- Jira: [S15P31E102-917](https://ssafy.atlassian.net/browse/S15P31E102-917). Story 40 배포 환경·CI, Epic 21 인프라·운영. 담당 우동균. 활성 스프린트 5.
- 기준: develop `8725918f`. 브랜치 `feat(infra)/S15P31E102-917-웹-정적-자산-gzip-압축과-캐시-헤더-적용`.
- 관련: API JSON 압축은 [419·486](../../infra/runtime/README.md)에서 적용했다. 이 작업은 `location /`의 웹 정적 파일만 다룬다.

## 문제

- 운영 Nginx(`infra/runtime/nginx.conf`, `nginx.tls.conf.template`)는 `/api/` JSON에만 gzip을 켰다. 웹 앱의 Wasm·JS·글꼴은 압축 없이 내려갔다.
- 정적 파일에 `Cache-Control`이 없어 브라우저가 휴리스틱으로 캐시했다. 이름이 고정된 `index.html`·`webApp.js`·글꼴은 배포 뒤 오래된 사본이 남을 수 있었다.
- 기본 `mime.types`에 `ttf`·`otf`가 없어 글꼴이 `application/octet-stream`으로 나가 압축 대상으로 고를 수 없었다.

## 변경

- 두 설정의 `location /`에 gzip(`gzip_comp_level 5`, 1KiB 이상, `Vary: Accept-Encoding`)을 켠다. 대상은 Wasm·JS·CSS·SVG·글꼴·문자열 XML·JSON·텍스트다. webp·mp3·wav 같은 이미 압축된 미디어는 뺀다.
- `font/ttf`·`font/otf`를 기본 `mime.types`에 더해 등록한다(`include` 뒤 `types` 추가, Nginx가 두 표를 합친다).
- `map $uri`로 캐시 정책을 고른다. webpack이 내용 해시를 붙인 `/<16~64자리 16진수>.wasm`만 `public, max-age=31536000, immutable`이다. 나머지와 SPA 대체 `index.html`은 `no-cache`라 매번 ETag로 확인하고 바뀌지 않았으면 304를 받는다. 없는 해시 Wasm이 `index.html`로 대체되면 `$uri`가 바뀌므로 오래 보관되지 않는다.
- 두 파일은 운영에서 한 http 블록에 함께 실리므로 map 변수 이름을 `$eolssu_static_cache_control`·`$eolssu_tls_static_cache_control`로 나눴다.
- 사전 압축(`gzip_static`)은 넣지 않았다. 운영 웹은 릴리스 폴더를 볼륨으로 마운트하므로 Jenkins 산출물 단계에서 `.gz`를 만들어야 하고, 배포 manifest 검사도 함께 바꿔야 한다.
- `deploy-frontend`의 `healthy()`에는 헤더 검사를 넣지 않았다. 롤백 때도 같은 검사를 하므로 서버 Nginx 설정이 늦게 반영되면 롤백까지 실패한다. 헤더 계약은 Jenkins backend 잡이 이미 실행하는 `RUN_NGINX_TESTS` 테스트에 넣었다.

## 검증 (2026-11-15)

- `RUN_NGINX_TESTS=1`로 `test_nginx_redirect.py` 11개, `test_nginx_actuator.py` 6개, `test_init_letsencrypt.py` 8개 통과. `test_nginx_redirect`는 운영처럼 두 설정을 한 컨테이너에 함께 싣고 `nginx -t`도 확인한다. 추가한 검사:
  - HTTP(기본 서버)·HTTPS(도메인 서버)에서 Wasm·JS·ttf는 `Accept-Encoding: gzip`일 때만 gzip이고 풀면 원본과 같다. webp는 압축하지 않는다.
  - MIME: `application/wasm`, `application/javascript`, `font/ttf`, `image/webp`.
  - 해시 Wasm만 `immutable`, `webApp.js`·글꼴·`/`·SPA 경로·없는 해시 Wasm은 `no-cache`.
  - `If-None-Match`로 304 재검증.
- `test_nginx_blue_green.py`는 로컬에 `python:3.11.16-slim-trixie` 이미지가 없어(`--pull never`) 실행하지 못했다. Jenkins에서도 실행하지 않는 테스트다.
- `infra/jenkins/tests/test_deploy_frontend.py` 12개 통과(변경 없음 확인).
- 실제 번들 전송량: 510 작업공간의 production 번들(2026-11-05 빌드, `.map` 제외 167개 파일)을 변경한 `nginx.conf`로 띄워 `curl --compressed` 없이 `Accept-Encoding: gzip` 다운로드 크기를 쟀다.

## 운영 반영 절차 (사용자 확인 후)

운영 Compose는 두 설정을 파일 단위로 마운트한다(`compose.yml`의 `./nginx.conf`, `compose.tls.yml`의 `./nginx.tls.conf`). 파일을 새로 만들어 바꾸면 컨테이너가 이전 inode를 계속 보므로, 같은 파일에 덮어쓴 뒤 reload한다.

1. 서버 파일이 저장소의 변경 전 원본과 같은지 확인한다. 다르면 중단하고 차이부터 정리한다.

   ```sh
   git show 8725918f:infra/runtime/nginx.conf | sudo diff - /opt/eolssu/config/nginx.conf
   git show 8725918f:infra/runtime/nginx.tls.conf.template | sed 's/__TLS_DOMAIN__/k15e102.p.ssafy.io/g' | sudo diff - /opt/eolssu/config/nginx.tls.conf
   ```

2. 백업 후 같은 파일에 덮어쓴다.

   ```sh
   sudo cp -p /opt/eolssu/config/nginx.conf /opt/eolssu/config/nginx.conf.bak-917
   sudo cp -p /opt/eolssu/config/nginx.tls.conf /opt/eolssu/config/nginx.tls.conf.bak-917
   sudo cp infra/runtime/nginx.conf /opt/eolssu/config/nginx.conf
   sed 's/__TLS_DOMAIN__/k15e102.p.ssafy.io/g' infra/runtime/nginx.tls.conf.template | sudo tee /opt/eolssu/config/nginx.tls.conf >/dev/null
   ```

3. 실행 중인 컨테이너에서 검사하고 reload한다. 검사가 실패하면 reload하지 말고 백업을 같은 방식으로 되돌린다.

   ```sh
   sudo docker exec eolssu-runtime-frontend-1 nginx -t
   sudo docker exec eolssu-runtime-frontend-1 nginx -s reload
   ```

4. 외부에서 확인한다. `<해시>`는 운영 릴리스 폴더(`WEB_DIST_DIR`)에 있는 `*.wasm` 파일 이름이다.

   ```sh
   curl -sI -H 'Accept-Encoding: gzip' https://k15e102.p.ssafy.io/webApp.js | grep -iE 'content-encoding|cache-control'
   curl -sI -H 'Accept-Encoding: gzip' https://k15e102.p.ssafy.io/<해시>.wasm | grep -iE 'content-type|content-encoding|cache-control'
   curl -fsS https://k15e102.p.ssafy.io/api/actuator/health/readiness
   ```

5. 복구: 백업 두 개를 `sudo cp`로 같은 파일에 되돌리고 3번을 반복한다.
