# 무음 판정과 오답·미검출 채점 분리 (S15P31E102-291)

- Jira: [S15P31E102-291](https://ssafy.atlassian.net/browse/S15P31E102-291), Story S15P31E102-38(예외 처리), Epic S15P31E102-20
- 선행: S15P31E102-170(모든 음표 `MISSED`면 `NO_SOUND`, 완료). 재개하지 않고 이 Task에서 기준을 바꾼다.
- 기준 스펙: [분석 실패 사유](../specs/practice-analysis-failure.md)

## 문제

`score()`가 모든 음표가 `MISSED`이면 `FAILED`/`NO_SOUND`를 돌려줬다. 그래서 소리가 있는데 음표를 맞히지 못한 연주도 무음 실패로 처리됐다. 실기기 세션 22는 22.29초 내내 수음됐고 음높이가 1027프레임 잡혔는데도 `NO_SOUND`였다(S15P31E102-283에서 발견). 앱은 이 경우 "소리가 들리지 않았어요"라고 사실과 다르게 안내한다.

## 결정

- 무음은 음표 결과가 아니라 녹음 자체로 판정한다(`scoring.has_sound`). 10ms마다 20ms 창으로 잰 음량(`frame_rms`)이 -50dBFS 이상인 프레임 수와, 음높이가 잡힌 프레임 수를 센다. 둘 중 큰 쪽이 0.3초 미만이면 `NO_SOUND`다. 악보 길이의 10%가 0.3초보다 짧으면 그 길이를 기준으로 쓴다(1~4프레임 DTW 고정 입력용).
- 소리가 있으면 음높이를 하나도 못 잡았거나 모든 음표가 `MISSED`·`PITCH`여도 `DONE`이다. 이때 점수는 낮다(대개 0점).
- -50dBFS는 앱이 마이크 입력이 없다고 보는 크기(S15P31E102-206)와 같다. 0.3초는 딸깍 소리나 잡음 몇 프레임을 소리로 세지 않으려는 값이다. 두 값 모두 실제 녹음의 잡음 크기로 검증하기 전의 제안 값이다.
- 음량이 -50dBFS보다 작아도 음높이가 잡히면 소리로 본다. 마이크에서 멀리 떨어져 분 연주를 무음으로 처리하지 않기 위해서다.
- `TOO_SHORT`, `DECODE_ERROR`, 실패 코드, API 응답 구조는 바꾸지 않는다. 판정 방식이 바뀌어 `modelVersion`은 `pyin-9`가 된다. 합산 규칙은 같아 `scoringVersion`은 `note-mean-2` 그대로다.

## 영향

- 백엔드는 변경이 없다. `AnalysisFailReason`과 V4 CHECK는 그대로다. 모든 음표가 `MISSED`인 `DONE`도 기존 음표 저장 규칙대로 받는다(`MISSED`는 인식 음·녹음 위치를 null로 저장). `modelVersion`이 바뀌므로 `pyin-8` 평가와 구간을 비교하면 `MODEL_CHANGED`로 비교하지 않는다.
- 앱도 변경이 없다. `NO_SOUND` 안내는 그대로이고 실제 무음에만 나온다. 소리가 있는 오답·미검출은 0점 결과 화면에서 음표가 미검출로 표시된다.
- 배포 순서와 무관하다. 운영 배포는 이 Task 범위가 아니다.

## 검증

`cd ai && uv run pytest`(2026-11-15, 이 브랜치 기준)

- 새 회귀 테스트: 무음과 짧은 무음(`NO_SOUND`), 잡음 몇 프레임(`NO_SOUND`), -60dBFS 방 잡음(`NO_SOUND`), 소리는 있는데 f0를 못 잡음(`DONE` 0점, 전부 `MISSED`), f0가 다섯 프레임에 하나만 잡혀 전부 `MISSED`(`DONE` 0점), 큰 잡음(`DONE`, 10점 이하, API 포함), 전부 틀린 음(`PITCH`, 기존), 일부 무음(`DONE`, 해당 음만 `MISSED`), 음량 기준 아래의 작은 연주(`DONE` 100점), 짧은 입력(`TOO_SHORT`)
- 고치기 전 `origin/develop`의 `scoring.py`로 같은 입력을 돌리면 f0 미검출, 전부 `MISSED`, 큰 잡음이 모두 `NO_SOUND`였다.
- 전체 결과: 이 변경과 관련된 실패는 없다. 남은 16개 실패는 채점과 무관한 환경 조건 때문이다. `test_staff_rhythm_preservation` 15개는 `JGB_GENERATOR_DIR`이 없어 실패했다. `test_onset_spread_experiment` 1개는 메모리 제한이 Windows에서만 구현돼 실패했다.

## 남은 일

- 실기기 세션 22 원본을 읽기 전용으로 재분석해 `NO_SOUND` 대신 `DONE`이 나오는지 확인한다. 원본 접근은 사용자 승인 뒤에 한다.
- 운영 배포와 실제 앱 결과 재확인은 하지 않았다. 운영 AI는 이 변경 전 버전이다.
- 두 문턱 값(-50dBFS, 0.3초)은 실제 무음·방 잡음 녹음의 크기로 다시 확인해야 한다.
