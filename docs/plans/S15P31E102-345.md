- 상태: 보류 결정(2026-11-02, 사용자 선택). Story 24, Epic 15. 앱 연결 S15P31E102-371은 백로그로 되돌린다.
- 기준 `origin/develop` 1dec028b. 수동 coco-clarify이며 코드·API 변경은 없다.
- 대상: CAT-01 `GET /api/songs`([곡·평가 조회 계약](../specs/practice-read-apis.md)).

## 결정

`GET /api/songs`에 검색어·난이도·악기 조건과 페이지를 지금 추가하지 않는다. 앱이 목록을 한 번 받아 제목·난이도·채점 가능 여부로 거르는 현재 방식을 유지하고, 아래 재개 조건 중 하나가 생기면 다시 설계한다.

## 재개 조건

하나라도 생기면 이 결정을 다시 연다.

1. 단소 외 악기의 곡이 앱 DB에 PUBLISHED로 들어온다. 사용자가 고른 악기의 곡만 보일지부터 정한다.
2. 목록 응답이 500KB를 넘는다. 곡당 약 20KB라 약 25곡이다.
3. 디자인에 더보기·정렬·악기 필터가 생긴다.

다시 열 때 먼저 볼 것:

- 응답 크기가 문제라면 검색보다 목록에서 원본 `score`를 빼는 것이 먼저다. 앱은 목록 응답의 `score.instrument`로 'n곡 · 악기'를 표시하므로 S15P31E102-371에서 표시 출처를 함께 바꾼다.
- 조건 없는 요청은 지금 응답과 같게 유지한다. 페이지는 현재 ID 오름차순을 그대로 쓰는 커서(마지막 songId 다음)가 page·size보다 중복·누락에 강하다.
- 이전 Notion 초안(q 1~100자, page 기본 0, size 1~100·기본 20)은 제안일 뿐 계약이 아니다.

## 하지 않는 것

- 서버 검색·필터·페이지 파라미터와 목록 응답 경량화
- 난이도 DB 값과 앱 3단계(입문·초급·중급)의 대응. 계약 문서는 1~3, V1 CHECK는 1~5라 별도 합의가 필요하다.
