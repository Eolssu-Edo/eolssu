# S15P31E102-684 내 악보 음원의 임시 다운로드와 기기 재생 연결

- 상태는 진행 중. Story 319, 스프린트 5.
- 초기 기준은 `3af7b31f`이며 현재 기준은 `f3497671`이다. [음원 스펙](../specs/sheet-audio.md)에 다운로드와 기기 재생 계약을 기록했다.
- 서버는 사용자의 SHT-12 요청으로 생성하고 완료 후 10분에 M4A만 만료·삭제한다. SHT-13은 시간을 연장하지 않는다. MIDI와 만료되지 않는 링크를 제공하지 않는다.
- 앱은 명시적인 저장에서 유효한 M4A를 기기에 내려받고 재생한다. 계정·악보 버전과 설정을 구분하고 부분 파일은 재생하지 않는다.
- 편집기, 서버, 플랫폼 파일을 별도 작업공간에서 구현했다. 673·674의 병합 후 개인 연습의 기기 재생과 장단 저장을 함께 반영했다.
- 격리 MySQL·렌더러 테스트로 만료·재요청·소유권·객체 정리를 확인했다. Android 에뮬레이터에서는 서버 파일이 만료된 뒤 기기 저장본을 재생했다.

## 검증 결과

- 작업 커밋 `b6f96e17`. 673·674의 열린 MR을 함께 반영한 로컬 통합 커밋 `314ed06f`. 통합 환경에서 684의 서버 코드는 작업 커밋과 동일하다.
- 격리 MySQL 43개와 백엔드 단위 테스트 692개 통과. MySQL 검사에는 실제 CAT·FFmpeg 생성 두 건을 포함한다. 만료 전 URL 재조회, 만료 후 삭제·재요청, 삭제 재시도, 레거시 객체를 확인했다.
- 통합 Android 호스트 검사 1,224개 중 1,220개 통과, 4개 건너뜀. 디버그 APK 및 Wasm 컴파일 통과. iOS 빌드 및 실기기 재생은 미검증이다.
- Android 17 API 37 에뮬레이터에서 실제 단소 M4A를 요청 1회·다운로드 1회로 기기에 저장했다. 서버 음원 만료 응답 뒤 같은 파일로 편집 미리듣기와 개인 연습을 재생했다. 파일 크기와 SHA-256을 원본과 비교했고 추가 음원 다운로드는 없었다.
- 673·674 병합 후 !529의 충돌을 해결했다. 계획 문서를 제외한 트리가 통합 검증 커밋 `314ed06f`와 동일함을 확인했다.
- 운영의 기존 음원 일괄 삭제와 배포는 별도다.
