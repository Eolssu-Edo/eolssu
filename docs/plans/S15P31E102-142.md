## 합의가 필요한 변경

공유 계약(DB 정본)의 의미를 바꾸므로 구현 전에 확인한다.

1. **`users_chk_2` 삭제:** 기존 "활성 회원은 이메일·비밀번호·닉네임 필수"가 없어진다. 대신 비밀번호가 있으면 이메일이 있어야 한다. 닉네임은 응답 명세가 `STRING | NULL`이라 필수로 두지 않았다. 계정 통합은 회의 A2 결정안(통합함)을 따랐다. 회의 하위 페이지(BE)에는 "통합하지 않고 409"라고 남아 있어 정리가 필요하다.
2. **`deleted_at`의 의미:** USR-05 명세는 탈퇴 요청 시각을 `deleted_at`에 넣으라고 하지만, AUTH-01은 `deleted_at`이 있으면 로그인을 거절해 "30일 안에 로그인하면 취소"가 불가능하다. 그래서 요청 시각은 `withdrawal_requested_at`, 대기 상태는 `status`에 두고, `deleted_at`은 30일 뒤 일괄 삭제(익명화)를 마친 시각으로 쓴다. AUTH-01은 `status = 'DELETED'`만 거절하고 대기 회원은 로그인 시 탈퇴를 취소한다. 데이터 파이프라인(사지한)·통계 배치(우동균)에 영향이 있다.
3. **`notation_mode` 기본값 HANJA:** 명세 기준으로 바꿨다. FE 기본 표기와 맞는지 확인한다.
4. **`bpm_unit` 기본값 없음(`jangdans`·`practice_sessions`):** 새 행은 단위를 반드시 넣는다. 기준 데이터(사지한)를 넣을 때 단위를 함께 넣는다. 세션 BPM 범위는 V1 CHECK 30~400이고 PRA-01 초안은 20~240이라 맞춰야 한다.
   - 원래 안(`32b47ac`): 행이 있는 DB에서는 V2가 실패하고, MySQL DDL은 되돌려지지 않아 앞부분만 남으므로 DB를 폐기 후 다시 만든다.
   - 바뀐 안(리뷰 고려 사항): 기존 장단은 이름(세마치·굿거리·중모리·타령, 회의 1-2 확정값)으로, 기존 세션은 곡의 장단으로 단위를 채운다. 그 밖의 장단이나 개인정보가 남은 탈퇴 회원이 있으면 DDL 전에 멈춰 아무것도 바꾸지 않는다. 데이터 파트의 로컬 DB도 다시 만들지 않고 적용할 수 있다.
5. **`practice_sessions` 수정 허용:** V1 주석은 "추가만 하고 status만 바뀐다"였다. `saved_at`·`memo`·`viewed_at`·`record_deleted_at`은 사용자가 나중에 바꾼다. 파이프라인은 이 칸을 읽지 않는다고 가정했다.
   - **기록 삭제(REC-04)는 소프트 삭제:** 명세는 평가 결과까지 지우면서 성장 통계·미션 판정은 유지하라고 한다. 평가 행을 지우면 점수 집계가 사라지므로 `record_deleted_at`을 채워 목록·재생·상세에서 빼고, 녹음 파일과 `recording_url`·`memo`만 지운다. 평가 행을 남기는 것이 "평가 결과 삭제"와 맞는지 확인한다.
6. **악보 스냅샷 방식:** 세션에는 `score_version`만 남긴다. `songs.score_json`을 덮어쓰면 예전 버전 악보는 사라지므로, 지난 연습의 오류 위치(cellId)를 정확히 보여 주려면 곡 악보 버전 보관 테이블이 필요하다. 1차는 악보를 고치지 않는다고 보고 넣지 않았다.
7. **`mission_id` 외래키 없음:** missions 테이블은 MIS 작업(우동균)에서 만든다. 그때 외래키를 건다.
8. **연습 설정 저장 위치:** 회의 B1 결정안(토글은 기기, 곡별 BPM만 서버)을 따라 `user_song_settings`만 추가했다. 한글·계이름 동시 표시용 boolean 칸은 넣지 않았다.
9. **이메일 인증 목적 `ACCOUNT_MERGE`:** 명세 목적값은 SIGN_UP(·PASSWORD_RESET)뿐이다. 통합 본인 확인(AUTH-09)은 가입된 이메일을 인증해야 하므로 목적값을 하나 더 두는 안이다.

넣지 않은 것: `jangdan_sound_on`(PRA-01 논의 필요), 장단 근거 칸(`jangdans.source`가 이미 있음), CAT-04 `notationCapabilities`(B1에 따르면 FE 대응표), missions·mission_progress, 모범 연주·장단 음원 메타데이터(CAT-05·08 soundUrl).

## 인프라 전달 사항(우동균)

V2 병합 후 서버 DB에 적용할 때 함께 처리한다. 이 Task에서는 서버·권한을 바꾸지 않았다.

1. **모니터링 계정 권한 축소:** `infra/monitoring/README.md`의 `grafana`·`metabase` 계정은 `GRANT SELECT ON eolssu.*`라 V2의 `email_verifications`·`refresh_tokens`(해시)와 `user_social_accounts`가 대시보드 쪽에 보인다. 대시보드가 쓰는 테이블만 테이블 단위로 주는 안이다.

   ```sql
   REVOKE SELECT ON eolssu.* FROM 'grafana'@'%', 'metabase'@'%';
   -- Grafana 대시보드와 Metabase 곡별 통계가 읽는 테이블만 허용. Metabase 테이블 보기도 이 테이블만 보인다
   GRANT SELECT ON eolssu.users             TO 'grafana'@'%', 'metabase'@'%';
   GRANT SELECT ON eolssu.practice_sessions TO 'grafana'@'%', 'metabase'@'%';
   GRANT SELECT ON eolssu.evaluations       TO 'grafana'@'%', 'metabase'@'%';
   GRANT SELECT ON eolssu.note_results      TO 'grafana'@'%', 'metabase'@'%';
   GRANT SELECT ON eolssu.songs             TO 'grafana'@'%', 'metabase'@'%';
   GRANT SELECT ON eolssu.instruments       TO 'grafana'@'%', 'metabase'@'%';
   ```

   `users`의 이메일·닉네임까지 막으려면 열 단위 GRANT(`GRANT SELECT (id, instrument_id, notation_mode, status, last_login_at, withdrawal_requested_at, purge_scheduled_at, created_at, deleted_at) ON eolssu.users ...`)를 쓴다. 수정한 대시보드 쿼리는 이 열만 읽는다. 다른 기준 테이블을 Metabase에서 둘러봐야 하면 그 테이블을 더한다.
2. **대시보드 다시 가져오기:** `eolssu-overview.json`의 회원 쿼리 2개가 V2의 `status` 칸을 쓴다. 서버 DB에 V2를 적용한 뒤 Grafana에서 다시 가져온다. 먼저 가져오면 두 패널이 오류를 낸다.
3. **인증번호 HMAC 비밀키:** S15P31E102-143에서 `AUTH_CODE_HMAC_SECRET` 같은 비밀값이 필요하다. 배포 환경 주입 방식을 함께 정한다.
