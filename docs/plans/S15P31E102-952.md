# S15P31E102-952 Jenkins 실패 알림의 한글 잡 이름 처리

- Jira: S15P31E102-952 (Story 41 운영 모니터링). 943 일치 점검에서 발견했습니다.
- 대상: [notify.py](../../infra/jenkins/notifications/notify.py), [운영 안내](../../infra/jenkins/notifications/README.md)

## 원인

- 잡 이름 검사 `JOB = eolssu-[a-z0-9-]+`가 한글을 허용하지 않았습니다. 그래서 2026-11-06(527)부터 쓰는 웹 수동 배포 잡 `eolssu-frontend-web-수동배포용`이 감시 목록에서 빠졌고, 실패해도 Mattermost 알림이 가지 않았습니다.
- 검사만 풀면 두 가지 문제가 남습니다.
  - Jenkins API 경로에 한글이 그대로 들어가 HTTP 요청을 만들 수 없습니다.
  - 기존 상태 파일이 있으면 처음 보는 잡을 새 잡으로 보고 기준점을 0으로 둡니다. 그러면 최근 100개 빌드 중 실패한 빌드를 모두 다시 알립니다.

## 수정

1. `JOB`에 한글(`가-힣`)을 허용합니다.
2. Jenkins API·로그 링크의 잡 경로를 `job_path()`로 퍼센트 인코딩합니다.
3. 잡 목록 조회에 `timestamp`·`duration`을 추가합니다. 운영 중 처음 보이는 잡은 직전 감지(상태 파일 수정 시각) 전에 이미 끝난 빌드를 기준점으로 삼아 건너뜁니다. 그 뒤에 끝나거나 진행 중인 빌드는 알립니다. 정말 새로 만든 잡의 첫 실패도 그대로 알립니다.

## 검증

- `python3 -B -m unittest infra/jenkins/notifications/test_notify.py`: 14건 통과. 새로 추가한 3건은 다음을 확인합니다.
  - 한글 잡 이름이 대상에 들어가고, 로그 링크와 API 요청 경로가 ASCII로 인코딩되는지
  - 대상 조건에 새로 들어온 잡의 과거 실패 3건은 알리지 않고, 직전 감지 뒤에 끝난 빌드와 진행 중이던 빌드만 알리는지
  - 새로 만든 잡의 첫 실패를 알리는지
- `python3 -B -m unittest discover -s infra/jenkins/tests`: 86건 통과

## 운영 반영 (사용자 승인 후)

edo1에서 진행하며 webhook URL과 인증 파일 내용은 출력하지 않습니다.

1. `/opt/eolssu/jenkins-notify/notify.py`와 `/var/lib/eolssu-jenkins-notify/state.json`을 root 전용 백업 디렉터리에 복사합니다.
2. 새 `notify.py`를 root 소유 644로 같은 경로에 설치합니다. 타이머는 각 실행이 끝난 뒤 30초마다 돌기 때문에 다음 실행부터 새 코드가 쓰입니다.
3. 다음 실행 뒤 `journalctl -u eolssu-jenkins-notify.service`에 오류가 없는지, 상태 파일 `jobs`에 웹 수동 배포 잡이 생겼는지, 과거 빌드에 대한 알림이 가지 않았는지 확인합니다.
4. 되돌릴 때는 백업한 두 파일을 같은 소유·권한으로 복원합니다.
