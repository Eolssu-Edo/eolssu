# S15P31E102-687 Android 카카오·네이버 간편 로그인 콜백 실패 수정

- [Jira](https://ssafy.atlassian.net/browse/S15P31E102-687)
- 기준 `origin/develop 1a6e28b4`. 별도 worktree에서 진행한다.
- 목표: Android 일반·QA 앱에서 카카오·네이버 로그인·연결 뒤 브라우저가 앱으로 돌아오게 한다. 웹 간편 로그인과 Android Google은 범위 밖이다(Google은 S15P31E102-683).

## 원인

- 서버 start는 세 제공자 모두 200이고, 카카오·네이버 인증 화면은 Android redirectUri를 받아들였다. `assetlinks.json`과 CSRF 필터도 정상이다.
- QA Galaxy S10(2026-11-10): 얼쑤 QA의 지원되는 웹 주소에 `k15e102.p.ssafy.io`가 등록돼 있고 지원되는 링크 열기가 켜져 있다.
- 같은 기기에서 네이버 세션이 있는 상태로 마이페이지 네이버 연결을 누르자, 네이버가 사용자 조작 없이 콜백으로 보냈다. Chrome은 그 주소를 웹으로 열었고, 웹 앱은 무한 스피너를 보였다. 앱은 '네이버 화면에서 계속해 주세요'에 머물렀다.
- 같은 Chrome에서 사용자가 직접 누른 `intent://k15e102.p.ssafy.io/auth/android/oauth/naver/callback#Intent;scheme=https;end` 링크는 얼쑤 QA 앱을 열었다.
- 결론: Chrome은 사용자 조작 없는 리다이렉트를 App Links로 넘기지 않는다. 계정을 직접 고르는 Google(2026-11-07 성공)과 달리, 세션이 남은 카카오·네이버는 곧바로 리다이렉트돼 막혔다.

## 변경

- `frontend/webApp/src/webMain/resources/index.html`: Android 콜백 경로에서는 웹 앱을 불러오지 않고 '얼쑤 앱 열기' 버튼을 보여 준다.
  - 버튼은 같은 쿼리를 담은 `intent://` 링크다.
  - 다른 경로는 기존처럼 `webApp.js`를 불러온다.
  - `Referrer-Policy: no-referrer` 메타를 추가했다.
- `docs/specs/social-auth.md`에 Android 복귀 안내 페이지 절을 추가했다.
- 서버·앱·redirectUri·제공자 콘솔은 바꾸지 않는다.

## 검증 기록

- 로컬 SPA 대체 서버(없는 경로는 `index.html`)와 브라우저로 확인했다.
  - `/auth/android/oauth/naver/callback?code=abc%2B1&state=st.ate`: 버튼이 표시되고, href가 `intent://<host>/auth/android/oauth/naver/callback?code=abc%2B1&state=st.ate#Intent;scheme=https;…;end`로 쿼리 인코딩을 유지한다. `webApp.js`는 불러오지 않는다.
  - `/auth/android/oauth/apple/callback`과 `/`: 버튼 없이 `webApp.js`를 불러온다.
- `frontend`에서 `./gradlew :webApp:wasmJsBrowserDistribution` 통과. 배포 산출물 `index.html`이 원본과 같다.
- 미확인: 운영 배포 뒤 실기기의 카카오·네이버 로그인·연결 왕복. 웹 배포 Job은 develop의 wasmJs 테스트 실패(S15P31E102-586 `MySheetConversionTest`)가 해결돼야 통과한다.
