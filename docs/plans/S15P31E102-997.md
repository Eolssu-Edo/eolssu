# S15P31E102-997 악보 올리기 흐름의 화면 이동·파일 선택·사전 안내 개선

- Jira: S15P31E102-997 · 진행 중 · 스프린트 5 · Story S15P31E102-317. 브랜치 `feat(fe)/S15P31E102-997-악보-올리기-흐름의-화면-이동·파일-선택·사전-안내-개선`, 기준 `origin/develop` `747a559d`.
- 계기: 사용자(오은서)가 악보 추가·올리기 화면에서 불필요한 확인 단계, 드라이브로만 열리는 파일 선택, 올리기 전 안내 부족, 이해하기 어려운 접수 실패 문구를 지적했다.
- 제외: S15P31E102-867(접수 화면 안내 문구 줄바꿈)은 `sheet_import.xml`의 `sheet_upload_accepted_help`만 고치므로 그 주변 줄(13~16행)은 건드리지 않는다. 998·1000·1002 파일은 수정하지 않는다.

## 범위와 완료 조건

1. 악보 추가(EDIT-01)는 `내 악보 가져오기`·`얼쑤에서 가져오기` 두 카드를 위아래로 둔다. `내 악보 가져오기`는 주 행동이라 연두 바탕·먹색 글자로 강조하고, 누르면 확인 버튼 없이 바로 `악보 올리기` 화면으로 간다. `얼쑤에서 가져오기`는 기존 `내 악보·제공 곡 불러오기`(EditPick)로 간다. 하단 `악보 정보 입력하기` 버튼은 없앤다.
   - 사용자 결정(2026-11-16): 정간보·오선보 카드 두 장 + 불러오기 줄 대신 위 두 카드로 바꾼다. 처음에는 카드 아래 드롭다운에서 종류를 골랐으나 어색하다는 의견에 따라 종류 선택을 올리기 화면 안으로 옮겼다.
   - 올리기 화면 맨 위 `악보 종류` 칸에서 `정간보`(처음 선택)·`오선보`를 고른다. 종류는 `SheetImportUiState.kind`로 들고, 접수 때 정간보면 장단을, 오선보면 황 음높이를 싣는다. 장단 목록은 종류와 상관없이 받아 두되, 오선보로 시작해 못 받았으면 정간보로 바꿀 때 다시 받는다.
   - `악보의 장단` 칸은 정간보일 때만 보인다. 장단 12개 칩 대신 고른 장단 한 줄과 아래 화살표를 두고, 누르면 악기 선택과 같은 공통 메뉴(높이 320dp까지, 안에서 스크롤)로 고른다. 오선보로 바꿔도 고른 장단은 남겨 두고 접수에는 싣지 않는다.
2. `PDF·이미지 선택`을 누르면 악기 선택 드롭다운과 같은 공통 메뉴가 버튼 아래로 펼쳐지고 `파일`·`갤러리` 중 하나를 누른다. `파일`은 문서 선택기(드라이브), `갤러리`는 휴대폰 사진첩을 바로 연다. Android는 문서 선택기와 사진 선택기(`PickMultipleVisualMedia`), iOS는 `UIDocumentPickerViewController`와 `PHPickerViewController`를 쓴다. 웹은 파일 선택 하나뿐이라 메뉴 없이 바로 연다. 선택지는 `SheetFileSource` 목록으로 두어 2차의 사진 촬영(S15P31E102-1003)이 항목만 더하면 되게 한다.
   - 사용자 결정(2026-11-16): 처음 만든 `어디에서 가져올까요?` 아래 패널, 그다음 `내 파일`·`갤러리` 칩 토글을 거쳐 악기 선택과 같은 드롭다운 메뉴로 정했다. 사진 촬영은 2차에서 같은 메뉴에 더한다.
   - 갤러리에서 한 번에 고르는 사진 10장 제한은 서버의 한 번 업로드 파일 수 제한(`SHEET_IMPORT_MAX_FILES = 10`)이라 유지한다. 내 악보 10개 제한과는 다른 규칙이다.
3. 올리기 화면 맨 위에 `잘 읽히는 악보` 안내: 표준악보집 같은 PDF가 가장 정확, 사진은 정면에서 악보 전체가 밝게, 오선보만 `오선보 사진은 잘 못 읽을 수 있어요`를 더한다.
4. 같은 안내에 제한: 내 악보 최대 10개(backend `SHEET_LIMIT_PER_MEMBER = 10`), 변환은 한 번에 1개(backend `countActiveConversions > 0`이면 `CONVERSION_IN_PROGRESS`).
5. 접수 실패 계열 문구(`sheet_upload_failed`·`unavailable`·`conflict`·`in_progress`·`limit`)를 무엇이 일어났고 무엇을 하면 되는지 쉬운 말로 고친다.

저장 형식·API 계약은 바꾸지 않는다.

## 검증

- 자동: `:shared:testAndroidHostTest :androidApp:assembleDebug :shared:compileKotlinWasmJs`.
- 에뮬레이터 `emulator-5554`: 카드 탭 → 바로 올리기 화면, 안내 표시, 선택지 창 → 앨범(사진 선택기)·파일(문서 선택기) 각각 열림.
- iOS는 Windows에서 컴파일할 수 없어 미검증으로 남긴다.

## 기록

- 자동(2026-11-16, 커밋 전 작업 트리): `./gradlew :shared:testAndroidHostTest :androidApp:assembleDebug :shared:compileKotlinWasmJs --max-workers=2` 성공. 공유 host 테스트 1,867개 중 실패·오류 0(외부 서버 검사 5개 skip), 신규 `SheetUploadGuideTest` 3개 포함. 신규 테스트는 구현과 함께 작성해 실패를 먼저 보지 않았다.
- 에뮬레이터(emulator-5554, 디버그 APK, 2026-11-16): 악보 추가에서 하단 버튼이 사라지고 `오선보 가져오기`를 누르자 바로 `악보 올리기`로 이동했다. 맨 위 안내 카드에 PDF·사진 팁, 오선보 경고, 10개·한 번에 하나 제한이 보였다. `PDF·이미지 선택` → `어디에서 가져올까요?` 패널 → `앨범에서 사진 고르기`는 시스템 사진 선택기가 열려 사진 2장을 고른 순서대로 받았고, `파일에서 고르기 (PDF·사진)`는 문서 선택기가 열려 `serbia_march.pdf`로 바뀌었다. 실제 업로드는 서버 상태를 만들므로 누르지 않았고, 바뀐 실패 문구는 화면에서 띄워 보지 않았다.
- 미검증: iOS(PHPicker·문서 선택기, Windows에서 컴파일 불가), 실기기, 웹 실행 화면(컴파일만 확인).

- 드롭다운·위아래 카드 변경 뒤(2026-11-16): 같은 Gradle 명령 성공, 공유 host 테스트 1,867개 실패·오류 0(5개 skip). 997 전용 에뮬레이터 emulator-5558(새 AVD `Pixel_7_API_35_997`, 다른 세션과 겹치지 않게 켬)에서 악보 추가에 연두 `내 악보 가져오기`·흰 `얼쑤에서 가져오기`가 위아래로 보였고, `내 악보 가져오기`를 누르면 `정간보`·`오선보` 메뉴가 카드 아래로 펼쳐졌다. 올리기 화면 `파일`·`갤러리` 메뉴는 사용자가 직접 확인 중이다.
