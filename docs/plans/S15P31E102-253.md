## 구현·집중 검사

- 등록된20개 메서드/경로와 실제 생성 문서를 비교한다. ResponseEntity<*>의 결과 타입은 실제 응답 DTO를 ModelConverters로 읽고 공통 envelope를 덧붙여 보완한다. 요청은 실제 컨트롤러를 읽되 커스텀 역직렬화 songId의 문자열 wire 타입을 명시한다.
- API별 요약/규칙·성공 상태·공통/업무 오류와 예시·access/refresh 쿠키 보안·Set-Cookie 범위를 제공한다. 실제4종 details DTO를 oneOf로 문서화하며 details는 선택이다. 204에는 content를 넣지 않는다.
- db·ops 실제 HTTP 검사로 UI·정적 자산·설정 JSON 인증, 무인증/탈퇴 대기401, 전체 매핑, 스키마 참조 무결성, nullable/비밀번호 규칙/204/업로드/문자열ID를 확인한다. 개발 무DB 기본 프로필에서는 비활성이다.
- 초기 문서404 실패→구성 후 통과, 자동 생성의 summary/계약 누락 실패→전체 계약 보완 통과, details 타입 누락 실패→4종 DTO 추가를 수행했다.
- 보완 발견: 본문 없는 POST도 기존 보안 필터상 application/json 헤더가 필수다. Swagger 선택 JSON{} 본문 예시로 UI가 헤더를 설정하게 하며 서버 동작은 바꾸지 않는다. 해당 문서 계약을 테스트 먼저 확인했다.
- 외부 온라인 validator는 끈다. 브라우저 Cookie 인증 제약은 [Swagger 공식 안내](https://swagger.io/docs/specification/v3_0/authentication/cookie-authentication/)에 따라 설명했고, 같은 출처에서 먼저 로그인한 브라우저 쿠키를 사용한다.

## 의존성 증가에 따른 기존 검사 보완

- 첫 전체 build에서 기존 FfprobeAudioProbeTests5개가 실패했다. 실제 원인은 새 의존성이 늘린 전체 테스트 classpath를 가짜 ffprobe 자식 JVM 명령행에 넣어 Windows CreateProcess error206 한도를 넘은 것이다. timeout/미생성 PID는 그 후속 증상이다.
- 가짜 프로세스에 필요한 테스트 클래스와 Kotlin stdlib의 codeSource만 classpath로 넘기도록 fixture를 보완했다. 기존5개 집중 검사 통과. 운영 ffprobe 명령/타임아웃·검사 기준은 변경하지 않는다. Swagger 의존성 포함 전체 원래 시나리오를 다시 검사한다.
