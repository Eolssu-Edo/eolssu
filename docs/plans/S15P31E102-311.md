# S15P31E102-311 Google 간편 로그인 콘솔·서버 연동 준비

## 진행

- Story S15P31E102-22 관련됨·Epic14·담당 오은서·활성 스프린트59139·진행 중을 Jira MCP로 확인했다. 기존 구현 Task211은 완료 상태로 유지한다.
- 시작 기반은 origin/develop `884c74fc12dde19c8824ca2ade5190927f939315`, 브랜치는 `chore(be)/S15P31E102-311-Google-간편-로그인-콘솔·서버-연동-준비`다. 별도 google-auth-311 worktree를 사용한다. 기존 체크아웃의 사용자 미추적6개와296의 FE 전달 기록 수정은 그대로 보존한다.
- Google Cloud 진입 시 기존 학교 계정에 재로그인/본인 인증을 요구했다. 사용자에게 얼쑤에 사용할 Google 계정으로 직접 로그인하도록 요청했으며, 프로젝트·OAuth 클라이언트 존재 여부는 아직 확인하지 않았다.

## 범위와 준비안

- 기존 서버의 시작 → 외부 브라우저 → HTTPS App Link → 같은 앱 클라이언트의 완료 API 흐름을 유지한다. Android SDK나 FE 코드는 이 Task에서 바꾸지 않는다.
- 현재 서버는 Google authorization code를 서버에서 교환하고 secret을 보관한다. 이에 맞춰 Google OAuth의 Web application 클라이언트를 준비한다. 실제 콘솔 등록 전 앱/계정·콜백과 생성 내용을 확인한다.
- 콜백 후보는 `https://k15e102.p.ssafy.io/auth/android/oauth/google/callback`이다. 최신 Android Manifest에는 이 경로가 있지만 제공자 콘솔·서버 등록 합의는 아직 확정으로 간주하지 않는다. 기존 카카오 URL을 덮어쓰지 않는다.
- 현재 Google 요청 scope는 `openid email`, PKCE는S256이다. state는10분·1회용이며 앱의 HttpOnly 결속 쿠키에 묶인다. 제공자 secret과 access token은 앱 응답·Git·로그에 넣지 않는다.
- Google Cloud 프로젝트·OAuth 동의 화면의 External/Testing 여부, 표시 이름·지원/연락 이메일·도메인·공개 정책 URL을 실제 콘솔에서 확인한다. 이름은 기존 서비스명 얼쑤를 준비하되 계정·연락처·프로젝트를 임의 지정하지 않는다. 운영 게시와 브랜드 검증은 기본 인증 scope의 테스트 예외와 구분한다.

## 작업 순서

1. 사용자 본인 인증 후 Google Cloud의 기존 프로젝트·클라이언트를 확인한다. 기존 자격증명은 무단 재발급/교체하지 않는다.
2. 콜백·지원 이메일·동의 화면·최소 권한을 구체적으로 준비한다. 실제 키 생성·새 권한·약관 동의가 필요한 단계는 실행 직전 확인한다.
3. 승인된 키와 콜백은 기존 설정을 보존하며 서버 root 전용 환경에 주입하고, 누락된 관리 Compose 전달을 추가한다. 변경 전후 백업·해석된 설정 차이를 확인한다. 배포/재시작은 실제 승인 범위에서만 한다.
4. 시작200·정확한 authorize URL·미허용 콜백401·잘못된/만료/다른 브라우저 state401을 확인한다. 실제 제공자 성공·거절·취소와 Android App Links 왕복은 별도로 검증한다.
5. API 명세·FE 전달사항에 확인한 결과와 미검증 범위를 반영하고 작업 단위로 커밋한다. Push·MR은 요청 전 실행하지 않는다.

## 확인 근거와 한계

| 확인 | 결과 |
| --- | --- |
| 기존 Google 코드 | RestOAuthGateway에서 Google authorize/token/userinfo 고정 주소·서버 코드 교환·S256·openid email 확인. 실제 Google 통신 성공 증거는 아님 |
| 기존 테스트 | RestOAuthGatewayTests에 Google PKCE URL·코드 교환·주소 거절 검사가 존재함을 읽었다. 코드 변경이 없어 새 전체 테스트를 실행하지 않았으며 이번 확인을 테스트 통과로 기록하지 않음 |
| 운영 환경·컨테이너 | Google client ID·secret·redirect URI가 모두 미설정. 키 원문은 출력하지 않음 |
| 관리 Compose | Google client ID·secret 전달은 있으나 AUTH_OAUTH_GOOGLE_REDIRECT_URIS 전달은 누락됨. 아직 수정하지 않음 |
| 외부 HTTPS 시작 API | 후보 콜백으로 POST /api/auth/oauth/google/start →503 SERVICE_UNAVAILABLE, 공통5필드 응답 확인. 현재 사용 가능으로 보고하지 않음 |
| 콘솔·키 발급 | 본인 인증 대기. 프로젝트·클라이언트·동의 화면 조회/생성 미수행 |
| 실연동 | 키 주입·배포·실제 Google 인증·Android 왕복 미수행 |

## 공식 근거

- [Google 웹 서버 OAuth](https://developers.google.com/identity/protocols/oauth2/web-server): 서버에서 secret을 보관하는 코드 교환, Web application 클라이언트·정확한 redirect URI 등록.
- [OAuth 앱 상태와 기본 인증 범위의 예외](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview): External/Internal·Testing/Published·브랜드/권한 검증을 구분한다. 기본 openid/email/profile 범위 예외를 일반 사용자 데이터 권한으로 확대 해석하지 않는다.
- [Google Auth Platform](https://support.google.com/cloud/answer/15544987): 브랜딩·Audience·클라이언트 설정 위치.
- 위 문서는2026-10-30에 확인했다. 실제 콘솔 표시·조직 정책과 다르면 해당 차이를 먼저 확인한다.

## 이어받을 전달사항

- 사용자가 나중에 전달사항을 요청하면 카카오의 Android 로그인 → 카카오 설정에서 외부 연결 해제 → 앱 재연결 공동 검증을 함께 안내한다. FE는 앱 흐름, 테스트 사용자는 휴대폰 조작, BE는 웹훅·DB·재연결을 확인한다. 해당 기록은 기존 메인 체크아웃의296 계획 문서에 저장돼 있으며 자동 메시지·예약은 만들지 않았다.
