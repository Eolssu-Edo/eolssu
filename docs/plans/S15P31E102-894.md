# S15P31E102-894 제공 곡 사본에 검수된 장단 연결 유지

- Jira: [S15P31E102-894](https://ssafy.atlassian.net/browse/S15P31E102-894), Story 319(Relates), 에픽 16, 담당 오은서, 스프린트 59321, 진행 중.
- 브랜치: `fix(be)/S15P31E102-894-제공-곡-사본에-검수된-장단-연결-유지` (develop `021b1be1`에서 시작)

## 원인

- 편집 화면은 악보에 적힌 장단 이름(`music.jangdan`)을 보여 주고, 장단 선택 창은 서버 장단 연결(`jangdanId`)로 선택을 정한다.
- 운영 `/api/songs`에서 제공 곡 대부분은 `jangdan`(곡 행 연결)이 null이고 `jangdanName`만 있다. 연습 반주는 `ScoreGridJangdanPlayback`이 악보 장단명과 격자로 정한다(강원도아리랑 5번 → 엇모리 6).
- 복사(`CopyPublishedSheet`)는 곡 행 연결만 옮겨서 사본은 장단 없음이 됐다. 그래서 사본 편집 장단 창은 '반주 없음'을 고르고, 사본 연습에서는 장단 반주가 나지 않았다.

## 결정

- 사용자 선택(2026-11-14): 앱 표시만 고치지 않고 서버가 사본에 장단을 넣는다.
- 곡 행 연결이 있으면 그대로 쓴다. 없으면 원곡 연습 반주와 같은 판정(`SongJangdanPlaybackResolver`, 빈으로 분리해 곡 조회와 공유)으로 장단을 찾는다.
- 찾은 장단은 사본 저장(SHT-04)과 같은 이름·박 단위·격자 검사(`SheetJangdanValidation`)를 통과할 때만 넣는다. 저장할 수 없는 사본을 만들지 않기 위해서다.
- 이미 만든 사본은 바꾸지 않는다. 다시 복사하거나 장단 창에서 고르면 된다.

## 검증

- `CopyPublishedSheetTests` 3개: 반주 장단 연결, 이름·단위·격자가 맞지 않거나 반주가 없을 때 null, 곡 행 연결 우선. 검사 조건을 빼거나 연결을 막으면 각각 해당 테스트가 실패함을 확인한 뒤 원복했다.
- 운영 5번 악보(`/api/songs/5/score`, 반주 `jangdanId` 6)를 임시 테스트로 넣어 엇모리 6 패턴이 저장 검사를 통과함을 확인했다(임시 테스트는 지움).
- 백엔드 `clean build` 통과: 767개(실패 0, 건너뜀 1).
- 미실행: `UserSheetApiDatabaseTests`에 곡 행 연결 없는 곡 복사 검사를 추가했으나, 이 PC에 MySQL·Docker가 없어 `databaseTest`를 돌리지 못했다. 병합 전에 실행해야 한다.
- 앱·운영 반영 후 사본 편집·연습 반주 확인은 하지 않았다.
