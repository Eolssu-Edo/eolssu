# S15P31E102-310 구간 재평가 비교

- Story 37, Epic 20. 기준 origin/develop 03253c1. 사용자 요청(2026-10-30): 와이어프레임·노션에서 2차 보류였던 EVA-04도 맡은 API라 함께 구현.
- 계약: 노션 EVA-04 계약 초안. [스펙](../specs/evaluation-detail-apis.md)의 EVA-04 절.
- 범위 밖: 구간 반복 연습·재평가 화면(FE 2차), AI 구간 재집계 공식, 판정 정책 버전 저장.

## 결정

- 이전 세션은 baselineSessionId, 생략 시 PRA-01 parentSessionId를 쓴다. 타인·없음 404, 다른 곡 400, 미완료 409는 PRA-01의 parentSessionId 규칙과 같다.
- 점수는 AI가 음표별 오차·허용 범위로 계산해 저장 판정만으로는 다시 만들 수 없다(`ai/src/ai_service/pipelines/scoring.py`). 구간이 다른 이전 결과는 점수를 null로 두고 오류 수·고친 음표만 비교한다.
- comparable은 악보 버전·구간·모델 버전·BPM이 모두 같을 때만 true다. 판정 정책 버전은 저장하지 않아 조건에 넣지 못했다.
- 악보 버전이 다르면 noteIdx가 같은 음이라는 보장이 없어 고친 음표를 비운다. 이번 세션 악보가 현재 곡 악보와 다르면 각 위치를 낼 수 없어 409다(EVA-03과 같음).

## 검증
- 단위 `SectionComparisonTests` 4개(같은 구간 재평가, 곡 전체 이전 결과, 모델·속도 차이, 악보 버전 차이)와 MockMvc `SectionComparisonControllerTests` 4개(parentSessionId 기본값, 이전 세션 400·404·409, 이번 세션 404·409)를 추가했다.
- 실제 HTTP/MySQL `SectionComparisonApiDatabaseTests`: V6 시드 1번 곡 음표 16~19의 구간 재평가에서 parent_session_id·model_version 조회, delta·고친 음표·남은 오류·각 위치, 모델 차이 comparable=false, 이전 세션 미완료 409·삭제 404를 확인했다.
- 첫 DB 실행에서 테스트 준비가 실패 사유 없이 FAILED로 바꿔 `chk_practice_sessions_fail_reason`에 걸렸다. 미완료 상태를 PENDING으로 바꿨다(구현 문제 아님).
- `./gradlew clean build`: 일반 테스트 397개 통과. `databaseTest`(임시 MySQL 8.4, `--max-connections=400`): 145개 모두 통과. 임시 컨테이너·인증 파일은 제거했다.
- 최신 develop(S15P31E102-304 조율 정보) 병합: 평가 조회 스냅샷·쿼리에서 조율 2필드와 parent_session_id·model_version을 함께 유지했다. 병합본 `clean build databaseTest` 일반 404개·MySQL 147개 통과.
- 남은 일: FE 2차 화면 연동, AI 구간 재집계 공식.
