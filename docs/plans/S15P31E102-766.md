- [Jira](https://ssafy.atlassian.net/browse/S15P31E102-766) · Story S15P31E102-319 · 에픽 S15P31E102-16 · 스프린트 5 진행 중
- 기준 `origin/develop` `866d9064`. 전용 worktree `sheet-save-766`.
- 범위는 QA706 보고서의 `sheet-save-feedback`과 개선 작업 계획의 개인 악보 항목을 따른다.

## 요구사항과 검증 계획

- 편집기에서 저장 중, 자동저장 완료, 확정 저장 완료와 실패를 구분한다. 확인된 최신 편집본만 완료로 표시한다. 실패한 초안은 편집 화면에서 재시도하고 확정 저장은 기존 저장 창에서 다시 요청한다.
- 저장을 연타하거나 자동저장 중 편집기를 닫아도 같은 편집본의 요청을 중복 전송하지 않는다. 초안과 확정본의 저장 및 재열기 경로를 확인한다.
- 개인 악보 연습 화면은 음원 준비와 다운로드 진행, 실패와 재시도, 재생 준비 완료를 표시한다. 화면의 계정·악보·확정 판본에 맞는 파일만 재생한다.
- 공유 테스트에서 지연·오류·재열기·판본 변경을 재현한다. 실제 기기에서 검증할 수 있는 항목과 미관측 항목을 기록한다.

## 기기 확인 절차

1. 테스트 계정의 개인 악보에서 제목 또는 빠르기와 정간 내용을 바꾼다. 자동저장 완료를 확인하고 다시 열어 편집값을 비교한다.
2. 저장 창에서 제목을 바꾸고 저장을 연속 입력한다. 확정 저장 완료, 단일 저장 요청, 목록 제목과 재열기 값을 확인한다. 격리 서버에서 한 번 실패시킨 뒤 같은 내용으로 재시도한다.
3. 아직 음원이 없는 확정 판본으로 연습을 연다. 준비 중, 다운로드 중, 미리듣기 준비 완료와 실제 스피커 출력을 확인한다. 생성 또는 다운로드 실패를 한 번 주입하고 재시도한다.
4. 기존 음원이 있는 악보를 편집해 새 판본을 만든다. 새 판본의 연습에서 이전 파일이 재생되지 않는지 확인한다. 준비 중 악보가 바뀐 응답은 다시 열기 안내와 파일 미저장을 확인한다.

## 회귀 검증

- 2026-11-11 Windows, JDK 21. 중간 구현을 Chrome Headless에서 `.\gradlew.bat :shared:jsTest --offline --no-build-cache --console=plain --max-workers=2`로 실행했다. 1,384개 중 `SheetCompletionValidationTest`의 3개가 실패했다. 최초 명시적 임시저장과 쓰기 대기 중 편집을 복원했다.
- 변경 전 테스트 실행은 JS 출력 폴더에서 빌드가 겹쳐 중단됐다. 기준 빌드의 저장·재생 관측값은 위 QA 기록을 사용한다.

- 최종 구현은 Chrome Headless에서 1,384개 통과, 실패·건너뜀 0개였다. 저장·판본별 음원 관련 네 클래스의 33개를 포함한다. 앞서 실패한 세 검사도 통과했다.
- 자동저장과 확정 저장은 각각 성공 응답 뒤 표시했다. 실패 뒤 같은 편집 내용을 재시도했고 재열기 시 제목·빠르기·빈 정간이 유지됐다. 연속 확정 입력과 자동저장 중 닫기에서 각각 한 번만 저장했다. 음원 준비·다운로드·실패·재시도·판본 불일치와 재생 차단을 격리 응답과 기기 저장 대역에서 확인했다.

```powershell
# frontend/에서 실행
$env:CHROME_BIN = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
.\gradlew.bat :shared:jsTest --offline --no-build-cache --no-daemon --no-watch-fs --no-configuration-cache --console=plain --max-workers=1 '-Dorg.gradle.jvmargs=-Xmx5g -XX:ActiveProcessorCount=4 -Dfile.encoding=UTF-8' '-Pkotlin.compiler.execution.strategy=in-process'
```

기본 Kotlin JVM은 힙이 가득 차 메모리 정리를 반복했고, 별도 JVM의 첫 실행은 Gradle 파일 감시 스레드에서 충돌했다. 위 명령은 파일 감시를 끈 별도 JVM에서 통과했다.
