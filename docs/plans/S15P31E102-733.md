# S15P31E102-733 연주 평가 시작 시 서비스 마이크 안내 창 없이 기기 권한 요청만 표시

- Jira: S15P31E102-733, Story S15P31E102-32(연습 화면 흐름), Epic S15P31E102-20. 담당 송가연.
- 브랜치: `fix(fe)/S15P31E102-733-연주-평가-시작-시-서비스-마이크-안내-창-없이-기기-권한-요청만-표시`, `origin/develop`(ec9a8238) 기준.

## 범위와 완료 조건

- '연주 평가 시작'에서 서비스 마이크 안내 창(`PracticePopup.Permission`, '계속'·'나중에')을 띄우지 않고 기기(OS) 권한 창만 띄운다.
- 이미 허용: 바로 3·2·1 카운트다운. 아직 묻지 않음·다시 물을 수 있음: 기기 권한 창 → 허용하면 시작, 거부하면 시작하지 않음. 기기가 더 묻지 않는 차단: 설정 안내(`PermBlocked`)만.
- 권한 창 응답을 기다리는 동안 다시 눌러도 요청·평가 시작이 겹치지 않는다.
- 유지: 공통 안내 창 컴포넌트와 혼자 연습 '한 음씩'의 안내 창, 구간 반복·배우기 화면(이미 기기 권한만 요청), 녹음·타이머·채점·결과 저장.

## 원인과 결정

- 두 창이 함께 보인 원인: `requestEvaluation()`이 권한이 없으면 서비스 안내 창을 띄우고, 그 창의 '계속'이 안내 창을 연 채로 `MicPermission.request()`를 불러 기기 권한 창이 그 위에 떴다.
- 앱 안의 '허용' 값(`PracticeSettingsStore.micGranted`)이 없으면 기기 권한이 이미 있어도 안내 창이 떴다. 연주 평가는 기기 권한만 본다. 허용되면 앱 값도 함께 남겨 혼자 연습의 기존 판정은 그대로 둔다.
- 다시 물을 수 있는 거부는 서비스 창을 띄우지 않고 준비 상태에 머문다(다시 누르면 기기 창이 다시 뜬다). 곡 정보에서 바로 시작한 평가는 보일 플레이어가 없으므로 곡 정보로 돌아간다(`leaveDirect`).
- 차단 판정은 기존 `MicPermission.isPermanentlyDenied()`를 쓴다. 누르기 전부터 차단이면 기기 창을 부르지 않고 설정 안내를 띄우고, 이번 응답으로 차단된 경우(Android '다시 묻지 않음', iOS 첫 거부)는 기기 창이 닫힌 뒤 설정 안내를 띄운다.
- 권한 요청이 예외로 끝나면 거부와 같이 평가를 시작하지 않는다.
- S15P31E102-165의 '허용하지 않았으면 연습 화면 안내 창을 띄운다'는 연주 평가에서는 이 결정으로 대체한다.
