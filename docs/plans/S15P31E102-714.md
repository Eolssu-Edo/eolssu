# S15P31E102-714 iOS 연습 장단 소리 재생 연결

- [Jira](https://ssafy.atlassian.net/browse/S15P31E102-714) · [장단 재생 스펙](../specs/jangdan-practice-playback.md#ios-연습-장단-재생-s15p31e102-714)
- 기준 `origin/develop f16679d2`.
- 목표: Android에만 있던 연습 장단 소리를 iOS에서도 낸다. 지금 iOS는 재생기가 없어 '이 환경 또는 속도에서는 장단 소리를 지원하지 않아요.'를 보인다.

## 변경

- `core/audio/JangdanSampleFiles.kt`(공통): 검수 장단 M4A를 받아 manifest의 크기·SHA-256으로 검증하고 다 받은 파일만 캐시에 남긴다.
- `platform/audio/IosJangdanSamplePlayer.kt`(iOS): `AVAudioEngine` 재생 노드 8개로 타격을 겹쳐 내고, 굴림은 `AVAudioUnitTimePitch` 오프라인 렌더링으로 길이를 맞춘다.
- iOS `PlatformModule`에 캐시(Caches/`jangdan-practice-v1`)와 재생기를 등록한다.
- 공통 연습 화면·타격 시간표와 Android 코드는 바꾸지 않는다.

## 결정

- 캐시는 플랫폼 의존이 없어 공통 코드로 새로 만들었다. Android의 `JangdanSampleCache`는 그대로 둔다. 이 Mac에 Android SDK가 없어 Android 쪽을 옮기면 컴파일·테스트로 확인할 수 없기 때문이다. Android 이전은 Android 빌드를 확인할 수 있을 때 따로 한다.

## 검증 기록

- `:shared:iosSimulatorArm64Test`의 새 테스트 4개 통과.
  - `JangdanSampleFilesTest` 2개: Android 캐시 테스트와 같은 시나리오(한 번 받아 오프라인 재사용, 손상 파일 삭제 후 재다운로드, 큰 파일·해시 불일치 미저장).
  - `IosJangdanRollTest` 2개: 굴림을 0.5배·1.5배 길이로 맞출 때 목표 프레임 수와 앞부분 소리 유지, 빈·스테레오 입력 거부.
- iOS 시뮬레이터 테스트 바이너리 전체 1258개 통과(`MyPageInstrumentTest` 제외, 기존 멈춤).
- `:shared:compileKotlinJs`·`:shared:compileKotlinWasmJs` 통과.
- 미확인: 시뮬레이터·실기기에서 연습 화면의 실제 장단 소리(로그인 필요), Android 빌드(이 Mac에 SDK 없음, 코드 변경 없음).
