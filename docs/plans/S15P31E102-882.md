## 검증 기록

### 수정과 독립 리뷰

- 명시 계획이 없을 때만 기존 placements의 반복표·도돌이표가 있는 각을 2회 반복으로 명시한다. DATA의 기존 교육용 자동 반복과 같으며 기존 명시 repeats는 그대로 둔다. 추가 후 삭제에도 반복을 보존한다.
- 160/160.0, 80/80.0의 JSON 표현 비교를 숫자·시작/목표·끝 위치·한배 미생성 검증으로 바꿨다. 의미나 숫자를 바꿔 테스트를 통과시키지 않았다.
- 독립 리뷰가 찾은 지속 이벤트의 기호 순서 불일치를 해결했다. 이벤트 sigimsae와 companion placements가 같은 기보 위치 순서로 만들어져 DATA의 일치 검사를 통과한다.
- 숫자 계획이 없는 본래속도로는 화면에서 해결 상태로 보이던 기존 동작에 맞춰, export에 알려진 기본 BPM을 실제 숫자 계획으로 넣는다. 기존 명시 항목은 우선 보존한다.
- 삭제 후 남는 느리게/빠르게의 방향도 검증한다. 잘못된 방향을 만들 삭제는 유지하고 창에 오류를 표시한다.
- 전체 회귀에서 발견한 기기 미리듣기 차단도 수정했다. 편집 스냅샷과 확정 스냅샷에 확정 문서의 authoring·expressions·기준 BPM을 똑같이 설정한다. 미확정 초안과의 차이 비교는 유지한다.

독립 리뷰는 위 세 기호/방향 결함과 스냅샷 회귀의 수정본을 재검토해 수용했고 추가 중대 결함을 찾지 못했다. 최초 반복 회귀·기호 순서·본래속도로 누락은 수정 전 실패를 확인했다. 기존 오디오 ViewModel 3검사도 실제 실패 후 수정해 전체 실행에서 통과했다. 기대한 설계와 실제 구현 사이의 의미 변경은 없다.

### 실제 Android UI

다른 MR의 잠금 해제 뒤 FileMode.CreateNew로 공용 잠금을 획득했다. 전용 새 AVD `MR736_S10`은 Galaxy S10 화면 규격1440×3040·560dpi, Android17/API37·x86_64 이미지다. 고정 악보를 프로덕션 `SheetEditSettingsDialog`, `SheetEditUiState`, `JeongganboView`에 연결한 임시 Activity에서 adb 입력으로 다음을 확인했다. 저장 버튼은 로컬 파일을 쓰는 fixture이며 실제 API의 저장·재진입은 위 별도 통합 검증에서 확인했다.

- 다섯 한배 선택지·목표 미지정 안내 표시. 숫자 없이 좀 느리게를 추가하면 전체60을 유지하고 악보의 해당 위치에 세로 `ㅈㄴ`이 나타났다.
- 적용 후 실행 취소0구간→다시 실행1구간과 기호 복원을 확인했다.
- 수정으로 목표40 지정, 전체60→90 변경 시 화면 목표60 표시. 로컬 초안 저장/재진입 뒤에도90·목표60을 유지했다. 기기 파일 read-back은 저장 BPM90, 원래 기준 목표40, 반복2회, 음표4개였다.
- 삭제 후0구간·기호 제거, 실행 취소1구간·기호 복원, 다시 실행0구간을 확인했다.
- 점점 느리게 목표40·끝 위치 공란은 반영이 차단되고 오류를 표시했다. 긴 폼에서도 오류가 반영 버튼 위에 바로 보이도록 편집 중/목록 상태의 오류 위치를 나눴고, 수정 APK에서 추가 스크롤 없이 오류가 보이는 것을 재확인했다. 이 보완 뒤 FE 전체1680/제외5와 정상 APK를 다시 통과했다.

핵심 PNG/XML: `.scratch/mr736-ui/13-valid-unresolved-applied.*`, `14-valid-undo.*`, `15-valid-redo.*`, `21-global-90.*`, `24-local-reopened.*`, `27-delete-applied.*`, `28-delete-undo.*`, `29-delete-redo.*`, `41-error-fix-visible.*`. 최종 AndroidRuntime 오류 로그는 비어 있다. 초기 임시 Activity 소스 배치 오류와 비숫자 fixture ID는 harness에서만 수정했고 제품 결함으로 세지 않았다. 기기 세션 종료 시 소유 에뮬레이터를 종료하고 finally에서 잠금을 해제했으며 잠금 부재를 확인했다. 일반 빌드 출력도 정상 앱 ID로 복구했다.
