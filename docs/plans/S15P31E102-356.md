## 계약과 순서

1. 소셜 완료는 기존 연결200·기존 이메일409 ACCOUNT_MERGE_AVAILABLE 유지, 신규는409 SOCIAL_SIGN_UP_REQUIRED 및 result.details.signupTicket·expiresAt 반환. 티켓은43자·10분·1회용·제공자 쿠키 결속, DB 해시 저장. 제공자 ID·이메일은 클라이언트 입력을 신뢰하지 않는다.
2. POST /api/auth/oauth/sign-up: signupTicket·nickname·agreements(기존 termId/version/agreed)·선택 instrumentId/notationMode. 가입·약관·소셜 연결·토큰·티켓 소비를 한 트랜잭션으로 처리해201·기존 회원가입 응답/쿠키 발급. 오류410 SIGNUP_TICKET_EXPIRED,409 충돌/마지막 수단,422 현재 필수 약관. 클라이언트 자동401 재전송 금지.
3. 소셜 회원 password_hash nullable, 확인되지 않은 email은NULL. MyInfo email nullable. 이메일 로그인·비밀번호 재설정은 password가 있는 회원만 처리해 기존 계정 탈취 경로를 열지 않는다. 연결 제공자에 EMAIL을 허위 표기하지 않는다.
4. V12에 기존 users/check·oauth_proofs 제약을 호환 확장한다. 운영 DDL은 실행하지 않는다. 회원→카카오subject→티켓→링크/토큰 잠금 순서와 웹훅 시각 차단을 유지한다. 동시가입·다른티켓·약관변경·토큰발급 실패의 원자성·회귀를 검사한다.
5. 테스트 먼저 작은 API/서비스 slice 후 clean build·폐기 MySQL databaseTest. Swagger·스펙·Notion(관련 범위)·FE 인계 갱신. 실제 제공자·실기기/운영 마이그레이션은 별도이며 mock 성공으로 완료 처리하지 않는다.

## 소셜 전용 탈퇴 확정

- 사용자 추가 확정: 비밀번호 없는 소셜 회원도 탈퇴할 수 있도록 연결 계정 재인증을 지원한다. 기존 비밀번호 탈퇴는 유지한다.
- POST /api/users/me/withdrawal/oauth/{provider}/start와 POST 같은 경로(완료)를 추가한다. access_token·정확한 회원·연결 provider subject·WITHDRAW 목적·쿠키를 확인한10분·1회 withdrawalTicket으로 DELETE /api/users/me를 호출한다. currentPassword와 withdrawalTicket은 정확히 하나만 받는다. 모든 refresh 폐기·쿠키삭제·30일 유예 정책은 동일하다. kind/purpose를 구분해 가입·로그인·연결 토큰으로 탈퇴할 수 없다.
- 신규 가입부터 재인증 탈퇴까지 실제 HTTP·폐기 DB 테스트를 먼저 추가하고 미구현404 실패를 확인했다. 미배포 V12 초안을 보완한 뒤 체크섬을 강제로 수리하지 않고 새 폐기 DB로 검증한다.

## 구현·검증 기록

- 소셜 신규409→가입201·email null·로그인·마지막 해제409·재인증 탈퇴200을 HTTP/실제 MySQL로 검사했다. 가입 구현 전401, 탈퇴 추가 전404를 먼저 확인했다. 회원/쿠키/목적/만료 불일치·재사용 거절, 서로 다른 가입 티켓의 동일 소셜 계정 경쟁(201/409), refresh 저장 실패 시 회원·동의·연결·티켓 소비 전체 롤백을 확인했다.
- 3종 제공자 대역으로 가입을 검사했다. 카카오·Google의 확인 이메일은 저장하고 Naver 미확인 이메일은 NULL이다. 모든 소셜 전용 회원은 password_hash=NULL이며 이메일 로그인401, 유효한 PASSWORD_RESET 증명이 있어도401 EMAIL_NOT_VERIFIED여서 비밀번호 생성 경로를 열지 않는다. 제공자 파서의 신뢰 조건은 기존 코드를 유지한다.
- 소셜 탈퇴 증명은 다른 회원/브라우저/목적·만료·중복 사용을 거절한다. DB 오류 시 상태와 티켓 소비가 롤백되어 같은 증명으로 재시도할 수 있다. 완료 응답에서 결속 쿠키를600초 갱신해 증명 유효기간과 맞췄다.
- 자체 점검에서 이메일 NULL을 행 부재로 간주하던 기존 탈퇴 일괄 삭제를 찾았다. 소셜 전용 회원의 보관 기간 후 삭제 실패를 먼저 재현하고 id+nullable email 행 매핑으로 수정했다. 이메일 없는 회원도 파일 준비·개인정보/연결 삭제·DELETED 전환을 거친다.
- clean build의 일반 검사424개 통과. 초기 전체 DB 검사는 컨텍스트별 기본 풀의 연결 누적으로 MySQL 한도에 도달해, 이 폐기 검증 실행에만 maximum-pool-size=2·minimum-idle=0을 적용했다(운영 설정 변경 없음). Swagger 검사는 develop에 추가된 HTML 약관/서명 녹음 경로를 포함해 경로 집합을 비교하고, 이 비JSON 경로에는 업무 envelope 검사를 적용하지 않는다. 문서 경로의 Spring 정규식 표기를 OpenAPI 템플릿 표기로 정규화한다.
- 신규 가입·탈퇴·Swagger 대상24개 통과. 최종 전체 DB 회귀 156개 통과(실패/오류/건너뜀 0). clean build 일반424개와 합계 580개 통과. git diff --check도 통과했다.
