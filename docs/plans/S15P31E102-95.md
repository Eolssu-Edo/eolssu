## HTTPS·방화벽 검증

- Let’s Encrypt IP 인증서를 발급했다. SAN은 IPv4 `54.180.251.87`, issuer YE2, 인증서 경로 `/etc/letsencrypt/live/edo2-ip/`다. 이번 인증서 만료는 **2026-10-30 06:37:12 KST**다.
- `shortlived` 프로필의 160시간 인증서다. `snap.certbot.renew.timer` 활성화와 다음 실행 예약을 확인했다. `certbot renew --cert-name edo2-ip --dry-run --run-deploy-hooks`가 staging 갱신·Nginx 검사·reload까지 성공했다. 실제 미래 갱신 성공을 미리 보장하는 뜻은 아니다.
- HTTP 80은 ACME challenge만 제공하고 다른 경로는 404다. HTTPS는 명령 endpoint와 liveness만 제공하며 인증서 검증을 우회하지 않는다.
- UFW는 active/enabled, 기본 incoming deny·outgoing allow, IPv6 활성화다. TCP 22·80·443만 IPv4·IPv6에서 허용한다. 기존 설정은 `/var/backups/edo2-ufw/`에 보관했고 새 SSH 연결 성공 후 임시 복구 타이머를 제거했다.
- 외부 443 시간 초과는 Lightsail 방화벽의 HTTPS 규칙 누락 때문이었다. 사용자 요청에 따라 AWS 로그인 후 **HTTPS TCP 443, Any IPv4 or IPv6 address**만 추가했다. 저장 성공·규칙 재조회로 확인했고 기존 22·80을 보존했다.
- 외부 Mac에서 `curl --fail https://54.180.251.87/healthz`가 인증서 검증을 포함해 HTTP 200, `{"status":"ok"}`를 반환했다. 외부 IPv6 통신은 별도 실측하지 않았으며 IPv6 규칙 저장과 서버 수신 설정을 확인했다.

## 관측된 제약과 후속 범위

- 5개 컨테이너의 RAM·CPU·쓰기 영역 개별 제한이 미설정이다. RAM 제한과 Docker가 인식하는 호스트 RAM, 쓰기 영역과 공유 파일시스템 용량을 구분한다. 자원 제한은 이 Task에서 바꾸지 않았다.
- frontend·mysql Docker health는 healthy다. backend·Grafana·Metabase Docker healthcheck는 미설정이며, 별도로 Grafana·Metabase HTTP 200·본문 상태는 정상이다. 외부 웹 200, API `/api/actuator/health`는 404이므로 미설정으로 보고한다.
- Lightsail 정적 IP가 아직 연결되지 않았다. 중지·시작하면 현재 공인 IPv4가 바뀔 수 있다. 정적 IP 전환은 주소 변경 범위를 합의한 뒤 인증서·Mattermost URL·edo1 키 출발지 제한을 함께 변경해야 한다.
- callback 전달도 실패하면 채널에 실패 메시지를 남길 수 없다. journal에 기록하고 자동 재전송하지 않는다. 중계 서버 자체 장애·미래 갱신 실패에 대한 외부 알림은 이번 수동 점검 범위에 없다.
- 리뷰는 기준 커밋 이후 해당 Task의 추적·미추적 파일 전체에 대한 작성자 자체 검토다. 독립 리뷰 완료로 보고하지 않는다. 인증·고정 명령·시간 제한·공개 범위·저장공간 중복 집계와 실제 경로를 확인했다.
