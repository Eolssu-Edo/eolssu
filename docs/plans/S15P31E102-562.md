# S15P31E102-562 iOS 녹음 입력과 실시간 음높이 분석 구현

- [Jira](https://ssafy.atlassian.net/browse/S15P31E102-562)
- 기준 `origin/develop ef912bf8`.
- 목표: Android에만 있던 녹음 중 음높이 관측(`pitchReadings`·`captureBoundary`·`pitchGate`·`diagnostics`)을 iOS에서도 내보낸다. 지금 iOS는 `AVAudioRecorder`라 입력 샘플이 없어서, 기초부터 배우기 4~6단계의 음높이 판정과 연습 화면의 한 음씩 음높이 안내가 iOS에서 동작하지 않는다.

## 변경

- `platform/audio/IosAudioRecorder.kt`(iOS): `AVAudioEngine` 입력 tap → `AVAudioConverter`로 44.1kHz 모노 Float32 → `AVAudioFile`(AAC 128kbps m4a)로 저장. 같은 샘플을 Android와 같은 창 2048·간격 882로 잘라 공통 `YinPitchEstimator`·`PitchConfirmation`에 넘긴다.
- 시각 기준은 tap 입력 묶음의 host time을 `AVAudioTime.secondsForHostTime`으로 바꾼 값이며, `captureBoundary.observedNanos`도 같은 시계(`mach_absolute_time`)로 읽는다.
- 일시정지·재개는 Android처럼 새 구간(segment)으로 나누고, 엔진이 일시정지 없이 멈추면(전화·Siri·입력 장치 변경) `interrupted`로 알린다.
- `platform/audio/PitchWindows.kt`(iOS): 입력 묶음 크기와 상관없이 창을 자르는 작은 도우미와 테스트.
- 공통 화면·ViewModel·채점 규칙, Android 코드는 바꾸지 않는다.

## 결정

- 2026-11-08 첫 출시(빌드 4)에는 넣지 않기로 한 결정(S15P31E102-564)은 유지한다. 이 변경은 이후 develop QA 빌드부터 들어간다.
- 2026-11-11 사용자 지시: develop 기준으로 iOS에 빠진 기능을 채우고 새로 설치할 수 있게 한다. 조사 결과 플랫폼 구현 중 iOS에만 빠진 것은 이 음높이 관측뿐이었다.

## 검증 기록

- `:shared:compileKotlinIosSimulatorArm64` 통과(경고 없음).
- `:shared:iosSimulatorArm64Test`의 `platform.*`·`core.audio.*`·`feature.practice.*`·`feature.guide.*` 509개 통과. 새 `PitchWindowsTest` 2개(입력 묶음 크기와 무관한 창 위치, 일시정지 뒤 남은 창 버림) 포함.
- 미확인: 실제 마이크 입력의 음높이·녹음 파일 재생·서버 평가는 iPhone 실기기에서 확인해야 한다(develop 병합 뒤 QA 빌드로 설치). 운영 서버 로그인이 필요해 시뮬레이터에서 연습 화면 녹음은 확인하지 않았다.
