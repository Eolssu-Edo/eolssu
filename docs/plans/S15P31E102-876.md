## 중청 이미지 인식 후속 수정

- 사용자 요청: PNG·JPEG에서 중청 5칸을 청으로 읽는 오류를 수정하고 같은 자료로 재검증한다. 기존 Task·Story·스프린트·진행 중을 유지한다. `coco-debug` → `coco-build`로 구현·작업 단위 커밋·실제 API 재검증까지 수행한다.
- 실패 재현: 같은 SHA-256 입력으로 실제 OMR API를 다시 실행했다. PNG·JPEG는 각각 19/24, PDF는 24/24다. reader의 원시 토큰부터 청태·청중·청임·청무로 나와 후단 공통 악보 변환에서 옥타브를 지운 문제가 아니다.
- 원인: 고정 모델 어휘에는 중청황만 있고 다른 중청 토큰이 없다. 실제 이미지의 두 겹 물수변 획은 남아 있다. 기존 평균 글자 템플릿 보정은 특정 교재의 청태·청황만 다루며 서비스 기본 경로에서 사용하지 않으므로 그대로 확장·적용하지 않는다.
- 선택: 기존 모델의 율명·위치 판정 뒤, 각 음의 실제 그림에서 두 물수변의 점 배치와 아래 획이 모두 구분되는 경우에만 청을 중청으로 복원한다. 애매한 그림·없는 글자·음역·주변 선율로 옥타브를 추정하지 않는다. 두 reader 경로(모델 격자·엄격한 기하 격자)에 동일하게 적용하며 원시 위치·시김새·confidence·원본 bbox·ID·시간축을 보존한다.
- 완료 조건: 같은 PNG·JPEG 24/24, PDF 24/24와 AuClair 청성 입력 유지. 작은 글자·JPEG 손실·음악 기호·복합 음 토큰의 부작용을 회귀 검사하고, 실제 스캔 입력을 전후 대조한다. 모델 가중치·API/DB 형식·기존 저장 악보는 변경하지 않는다.

### 후속 구현·검증 결과

- 픽셀에서 두 물수변이 구분될 때만 중청으로 복원하도록 기존 DATA reader에 연결했다. 두 격자 경로 모두 `text`·`jg`에 반영하며 confidence·시김새·위치·bbox를 유지한다. 실제 모델 어휘에서 중청황만 존재함을 다시 조회했다. 스캔 엔진 버전은 r4로 올렸다.
- 같은 원본 PNG·JPEG 각각 19/24 → 24/24, PDF 24/24 유지. 실제 이벤트에서 바뀐 곳은 7·11·15·19·22번째 음의 옥타브뿐이며 정확히 +1이다. 나머지 ID·음 종류·칸·시작·길이·시김새는 모두 동일하다.
- AuClair PNG 44음과 실제 스캔 동동 95·수제천 334·여민락 388·보허자 464·해령 116음은 수정 전후 이벤트·정간이 모두 동일하다. 회귀 보존을 확인했으며 전곡 인식 정확도 승인으로 확대하지 않는다.
