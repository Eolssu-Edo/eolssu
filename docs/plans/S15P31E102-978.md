# S15P31E102-978 악보 추가·가져오기 화면 태블릿 가로 폭 확장

- Jira: S15P31E102-978 · Story S15P31E102-109 · 조사 근거 [S15P31E102-960](S15P31E102-960.md) 3번 항목.
- 문제: 악보 추가 흐름이 모든 창 너비에서 휴대폰 열(560dp)을 써서 1280×800 태블릿 가로에서 좌우가 약 360dp씩 비었다.
- 기존 결정 확인: `EditNewScreen.kt`의 "넓은 창에서는 휴대폰 너비로 가운데에 둔다" 주석은 S15P31E102-455·725 때 기본 동작을 설명한 것이다. 608·881·906 기록과 `frontend/docs/architecture.md` 9장에 560을 유지하자는 결정은 없다.

## 변경

- `feature/song/edit/component/SheetAddWidth.kt`: Expanded(840dp 이상)에서만 본문 최대 폭 720dp(좌우 여백 포함, 본문 680dp). 하단 버튼 묶음은 560dp로 가운데에 둔다. Compact·Medium은 기존 560dp 그대로다.
- 적용 화면: 악보 추가(`EditNewScreen`), 내 악보·제공 곡 불러오기(`EditPickScreen`), 악보 정보 입력(`SheetImportScreen`), 인식 중(`ImportScreen`), 인식 결과(`ImportResultScreen`). 상단 바도 같은 폭을 받아 뒤로 가기 꺽쇠가 본문 왼쪽 끝과 맞는다.
- 그대로 둔 것: `SheetDocumentNotice`는 가운데 정렬 안내 문구와 버튼 하나뿐이라 넓혀도 버튼만 늘어나므로 바꾸지 않았다. `ImportScreen` 마스코트 자리 높이 300dp는 폭 680dp에서도 비율이 어색하지 않아 유지했다. `SheetEditScreen`·`EditInputPanel`(965)과 업로드·변환 로직은 건드리지 않았다.
- 폭 720은 마이페이지(`ProfileFrame`, 680)보다 조금 넓다. 두 가져오기 카드를 나란히 두고 인식 결과 정간보를 보이는 화면이라 넓힌 쪽을 골랐다.
