# S15P31E102-941 운영·품질 실측 근거 표와 시스템 아키텍처 문서

- Jira: [S15P31E102-941](https://ssafy.atlassian.net/browse/S15P31E102-941) (에픽 21, Story 40 관련됨, 스프린트 5)
- 기준: origin/develop `25f7d263` (2026-11-15)

## 목표

최종 발표(11-18)에서 운영·품질 개선을 수치로 보여 줄 근거 표, 실제 시스템 구성 문서, 검증 이야기를 저장소에 남긴다.

## 범위

- 결과물: [운영·품질 실측 근거 표](../knowledge/infra/ops-quality-evidence.md), [시스템 아키텍처](../knowledge/infra/system-architecture.md), [설계 근거 표](../knowledge/domain/design-evidence-map.md)에서 두 문서로 연결
- 제외: 슬라이드(865 완료), 논문 근거 표 본문(205 완료), 새 측정, 서버 접속

## 진행과 결정

- 205·865는 모두 완료이고 결과물이 다르다(논문 근거·슬라이드). 그래서 저장소 문서용 Task를 새로 만들었다.
- 수치는 develop 문서에서 다섯 분야(CI·배포, 장애 대비, 웹·API, 분석·채점, QA·릴리스)로 모았다. 모은 96개 행을 다른 검토자가 출처 행을 다시 열어 대조했다. 88개는 일치했고 8개는 출처 행이나 조건을 고쳤다. 발표에 쓸 행만 골라 표에 넣었다.
- 격리·합성·추정 값은 구분 열로 표시했다. 문서가 단축률 계산을 피한 값(서로 다른 커밋 표본, 측정 대상이 다른 메모리)은 비율로 쓰지 않았다.
- 구성도에서 Metabase는 202에서 제거됐으므로 넣지 않고 '운영에 없는 것'에 적었다.

## 검증

- 주요 수치(917, 579, 919, 921, 823, 659, 292, 604, 158)를 출처 행과 직접 다시 대조했다.
- 문서 안의 상대 링크가 모두 실제 파일을 가리키는지 스크립트로 확인했다.
- Mermaid 그림은 저장소 렌더러에서 직접 보지 않았다.

## 남은 일

- 근거 표의 '미확인 항목'(RPO·RTO 합의, 운영 DNS 전환 시간, 개선 후 실기기 재측정 등)은 각 Task에서 측정되면 표에 추가한다.
- 문서 정리 중 찾은 불일치: `infra/runtime/README.md`의 OMR 운영 반영 상태(87행과 99행), 블로그 주소 표기(`team-ido`·`team-edo`). 이번 Task에서는 고치지 않았다.
