## 발견 내용과 남은 범위

### 생성 음원의 독립 검사

원본 PDF를 시각 확인한 별도 검토자가 기존 Python 환경의 PyAV로 `audio49.m4a`를 끝까지 디코드했다. 새 패키지 설치·폰 접근은 하지 않았다. AAC 44,100Hz 모노이며 컨테이너와 스트림 재생 길이는38.950초다. PCM 전체 프레임38.963초는 마지막 패딩을 포함한 값이다.

메타데이터와 실제 파일 크기·SHA256이 일치하고, RMS -10.38dBFS·최대 진폭0.851로 비무음을 확인했다. 수행 시간표는600ms/박,64박,38.400초,고유 음표44개이며 꼬리550ms다. 실제 파형의 안정구간 스펙트럼을 원본 아랫단+6반음의 음이름과 대조한 결과44/44가 일치했다. 첫 F#-F#-F#-G#, 중간 G#×4 / D#-D# / G#-F#-F-D# / C#, 끝 F#-A#-G#-G# / F#가 대응한다. 강한 배음을 잡는 방법의 한계가 있으므로 정확한 옥타브와 전문가 음질 판정은 포함하지 않는다. 증거 `audio49-analysis.json`.

### 실패·미검증

- 원본100BPM이160BPM으로 인식된 문제를 이번 실제 앱에서 재현했다. 기존 [박자 가져오기 검증](../knowledge/data/common/rhythm-metronome/meter-import-validation.md)의 Au clair Q100→Q160 항목에도 같은 제한이 기록돼 있어 최초 발견이라고 주장하지 않는다. 별도 읽기 조사에서 PDFium 글자층 `Moderato U+ECA5 = 100`이 보완 정규식의 일반♩/ASCII q에 매칭되지 않음을 실제 원본으로 확인했다. 백엔드 인식값이 없으면4박 기본반주의160을 사용하는 경로가 있다. 최초 OMR MusicXML을 읽지 않았으므로 전체 최초 누락 원인을 확정하지 않으며, 변환 결과를 수동100으로 바로잡은 성공을 자동인식 통과로 보고하지 않는다.
- PDF 완료 알림927, 이조 복원929는 수정이 별도로 진행·병합된 결과와 배포372의 차이를 구분한다. 배포 버전을 임의로 중간 교체하지 않았다.
- 원본의 주선율은 피아노 아랫단이다. 단소 지원음으로 맞춘 이조·옥타브 결과와 원본 실음을 같은 음고로 오판하지 않는다.
- `BlueVal_261114_091621.pdf`는 원본 템포160, 26마디80/가속→30마디160, 58마디80/가속→62마디160을 독립 시각 확인했다. 이번 첫 전체 경로에는 업로드하지 않았으므로 이 자료의 구간 빠르기 보존·생성은 미검증이다.
- 알림의 열기 동작, 실제 스피커 청음, 오프라인 재생, 서버 파일 만료 후 재생, iOS/Web는 이 실행으로 통과 처리하지 않는다.
- 기존 사용자 악보·로그인·학습/기록 데이터는 변경하지 않았다. 추가한 테스트 악보49와 기기 파일을 보존했다.
