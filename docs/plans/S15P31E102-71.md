## 플랫폼·외부 등록 영향

Android applicationId와 iOS bundle identifier가 변경되어 기존 식별자의 앱과 다른 앱으로 취급될 수 있다. 기존 설치 앱의 데이터 자동 이전이나 스토어·서명·외부 인증 등록의 존재·갱신 상태를 확인하지 않았으며, 이 작업에서 외부 등록·인증 정책은 변경하지 않는다. 저장소의 iOS TEAM_ID는 비어 있으므로 Mac 담당자가 자신의 개발팀 설정을 적용해 새 bundle identifier로 빌드·서명을 확인해야 한다.

Windows에서는 iOS를 컴파일할 수 없다. Mac 사용 프론트 담당자에게 필요한 검증은 Xcode 설정·제품명·bundle identifier·Shared 프레임워크 연결 및 iOS 기동이다. 미실행 상태를 통과로 보고하지 않는다.

현재 PC에 Android SDK가 없음을 확인했다. 사용자가 Android 검증을 다른 PC에서 진행하도록 명시했으므로, 해당 PC에서 `:androidApp:assembleDebug :shared:testAndroidHostTest`를 실행하고 새 applicationId 및 앱 표시명을 확인해야 한다. 그 결과는 이 기록 또는 MR에 추가한다.

## 결과

구현·자체 변경 검토를 마쳤다. 별도 독립 리뷰는 수행하지 않았다. Kotlin 소스 17개는 기존 코드와 이름 치환 외 차이가 없고, 파일 이동 42개와 `.gitkeep` 보존을 확인했다. 활성 frontend·backend에서 남은 이전 이름은 README의 앱 식별자 이전 설명뿐이다.

- 백엔드: JDK 21에서 `./gradlew.bat clean build` 성공. 실행 JAR `eolssu-0.0.1-SNAPSHOT.jar`를 임의 로컬 포트로 기동해 `[eolssu]` 로그와 미등록 HTTP 경로의 404 응답을 확인하고 종료했다.
- 프론트: `./gradlew.bat :webApp:jsBrowserDistribution :webApp:wasmJsBrowserDistribution :shared:jsTest :shared:wasmJsTest --console=plain` 성공. JS·Wasm 각각 기존 브라우저 테스트 2개가 통과했다. 배포 결과는 `frontend/webApp/build/dist/`에서 확인한다.
- 첫 웹 실행에서 JS `node_modules` 누락으로 webpack·테스트 실행 모듈을 찾지 못했다. `./gradlew.bat kotlinNpmInstall --rerun-tasks --console=plain --info`를 단독 실행한 후 같은 검증 명령을 다시 실행해 성공했다. 의존성·설정 변경은 없으며 병렬 설치가 원인인지는 확정하지 않았다.
- webpack 번들 크기 권고 경고는 남아 있다. 성능 개선은 이름 변경 범위에 포함하지 않았다.
- Android·iOS는 위에 적은 환경에서 추가 검증이 필요하다. 이 결과를 통과로 간주하지 않는다.

Jira는 Story 연결 및 활성 스프린트의 `진행 중`을 유지한다. Push·MR 생성·Jira 완료 전환은 이번 요청에 포함하지 않는다.

## 이름 변경 후 전체 구조 재점검 (2026-10-22)

검토 대상은 이름 변경 커밋 `67df759`와 현재 작업 트리다. 사용자 요청으로 frontend·backend뿐 아니라 ai·data·infra·blog·루트 문서와 설정도 로컬에서 점검했다. 외부 Notion·배포 서버·스토어 상태는 조회하지 않았다. 이번 점검은 자체 검토이며 모든 기능의 동작을 보증하는 인수 테스트가 아니다.

### 확인한 문제와 조치

1. **이전 패키지의 빈 폴더 잔존 — 정리함.** 이전 작업에서 파일만 이동하면서 backend의 main/test와 frontend 11개 소스 경로에 `eolsu` 폴더가 남았다. 13개 이전 패키지 루트 아래 모든 파일·숨김 파일·링크 부재와 저장소 내부 경로를 확인하고, 빈 디렉터리만 아래에서 위로 47개 삭제했다. 현재 `eolssu` 코드와 `.gitkeep`은 보존했다. Git은 빈 폴더를 추적하지 않으므로 이 정리 자체에는 Git diff가 생기지 않는다. 이전 완료 보고는 Git 추적 파일만 확인해 로컬 빈 폴더를 놓쳤다.
2. **루트 README의 현재 구현 안내가 오래됨 — 후속 수정 필요.** `README.md`의 초기 상태·기술 스택·실행 안내는 앱·서버·분석 코드가 없고 백엔드 프레임워크가 미정이라고 설명한다. 실제로 frontend Compose 프로젝트, backend Spring Boot 프로젝트, ai 채점 코드 및 각 README의 실행 명령이 존재한다. 루트 구조표에는 실제 존재하는 `blog/`도 빠져 있다. 기획 범위와 현재 구현 현황을 구분해 안내해야 한다.
3. **블로그 브랜치 예시 불일치 — 후속 수정 필요.** `blog/README.md`의 `feature/docs/blog-<주제>`는 루트 지침의 `타입(파트)/전체JiraKey-Task제목`과 다르다. 블로그 업무에 대응하는 실제 Task·머리말을 확인한 후 팀 규칙을 참조하도록 고쳐야 한다.
4. **Hugo 생성 결과물 제외 규칙 없음 — 후속 수정 필요.** `blog/Jenkinsfile`이 생성하는 `blog/public/`과 Hugo 임시 `blog/resources/`, `blog/.hugo_build.lock`은 현재 `.gitignore`에서 제외되지 않는다. 로컬 미리보기·빌드 산출물이 변경 목록에 들어올 수 있다. 실제 생성물을 소스와 분리해 제외해야 한다. 이 점검에서는 Hugo를 설치하거나 배포하지 않았다.

안쪽 `backend`는 별도 Gradle 프로젝트가 아니라 기존 합의 패키지 `com.ssafy.eolssu.backend`의 마지막 요소다. 실제 프로젝트 루트는 저장소 바로 아래 `backend/` 하나이며, `src/main/kotlin/com/ssafy/eolssu/backend/BackendApplication.kt`와 test 경로가 대응한다. 패키지를 `com.ssafy.eolssu`로 줄이는 것은 이번에 임의 적용하지 않았다.

- 현재 Kotlin 소스 전체의 package 선언과 `kotlin/<package>/` 경로가 일치한다. 이전 이름의 추적 경로·활성 코드 참조는 없고, 이전 이름은 역사 기록과 이전 앱 설명에만 남아 있다.

- 앞서 같은 코드에서 통과한 backend 빌드·HTTP 기동, JS·Wasm 배포 빌드·브라우저 테스트 증거를 재사용한다. 이번에는 빈 경로만 정리했으므로 무거운 빌드를 반복하지 않았다. Android 다른 PC·iOS Mac 검증은 여전히 미실행이다.
