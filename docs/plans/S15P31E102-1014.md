# S15P31E102-1014 비밀번호 64자·이메일 100자로 서버 입력 상한을 앱과 맞추기

- Jira: S15P31E102-1014 · 진행 중 · 스프린트 5 · Story S15P31E102-22 · 담당 박찬형. 브랜치 `fix(be)/S15P31E102-1014-비밀번호-64자·이메일-100자로-서버-입력-상한을-앱과-맞추기`, 기준 `origin/develop` `09cfdc9a`. MR !872.
- 계기: 앱(S15P31E102-996)은 비밀번호를 64자, 이메일을 100자로 막는데 서버는 비밀번호 8~128자, 이메일 320자를 받았다. 처음에는 비밀번호만 등록했으나, 사용자가 이메일도 맞춰야 한다고 해서(2026-11-16) 제목과 범위를 넓혔다.

## 결정

- 이메일 100자: 표준상 실제로 쓸 수 있는 최대 길이는 254자이고, 320은 로컬부 64 + 도메인 255를 더한 이론값이다. 실제 주소는 회사·학교 주소를 포함해도 50자 안팎이라 100자로 정했다.
- 새로 정하는 값만 막는다. 새 비밀번호(가입·재설정·변경)와 새 이메일(가입·인증번호 발송)에 적용한다.
- 로그인·현재 비밀번호·탈퇴·소셜 계정 연결 비밀번호, 로그인 이메일, 간편 로그인 제공자 이메일은 그대로 둔다. 예전 규칙(128자·320자)으로 가입한 계정이 로그인·탈퇴하지 못하게 되는 일을 막기 위해서다. 이것으로 Jira 완료 조건의 "기존 계정 처리 방식"을 정했다.

## 범위와 완료 조건

1. `PasswordPolicy` 8~128 → 8~64자. 새 비밀번호 요청 `@Size` 256 → 128(UTF-16 기준 64자의 두 배). OpenAPI 8~64.
2. `EmailPolicy`·가입·인증번호 발송 요청 `@Size` 320 → 100.
3. 65자 이상 새 비밀번호, 101자 이상 새 이메일은 400. 관련 테스트 통과.
4. `backend/README.md` 설명 갱신.

## 기록

- 단위 테스트(2026-11-16): `./gradlew test` 779개 통과. 정책·이메일 정규화·OpenAPI 기대값을 새 기준으로 고쳤다. 첫 실행에서 `SignInRequestTests`가 "가입 정책이 받는 128자 비밀번호"를 고정하고 있어 실패했다. 그래서 64자 기준 테스트와, 예전 128자 비밀번호도 로그인 요청이 통과하는지 보는 테스트로 나눴다.
- DB 테스트: 로컬 MySQL 8.4 일회용 스키마 `eolssu_test`에서 OpenApi·EmailVerification·PasswordReset·SignUp·PasswordChange `databaseTest` 통과. 처음 2개가 트리거 생성·`performance_schema` 조회 권한 부족으로 실패해 테스트 계정 권한만 보강했다.
- 로컬 서버(`db` 프로필 :18080): 인증번호 발송 이메일 100자 202, 101자 400. 65자 비밀번호 로그인은 길이로 막히지 않고 401(비밀번호 불일치).
