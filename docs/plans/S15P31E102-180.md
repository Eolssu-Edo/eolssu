## 결정·제약

- ffprobe가 필요한 검사는 `media` 태그의 `./gradlew mediaTest`로 분리했다(사용자 결정). Jenkins는 edo1 호스트 에이전트에서 `clean build`를 실행하므로, 호스트에 ffmpeg를 설치하기 전에 `clean build`에 넣으면 develop 빌드·배포가 멈춘다. `mediaTest`는 ffmpeg·ffprobe가 없으면 건너뛰지 않고 실패한다. 기본 `test`는 셸 스크립트 대역으로 JSON 해석·종료 코드·시간 초과만 본다.
- 고정 버전: 실행 베이스 `eclipse-temurin:21-jre`는 Ubuntu 26.04(`resolute`)이며 `ffmpeg=7:8.0.1-3ubuntu2`를 설치한다. 베이스의 Ubuntu가 바뀌면 설치가 실패하므로 함께 갱신한다. ffmpeg 레이어는 약 410MB다.
- 오디오 스트림이 없는 m4a(ffmpeg로 0초를 지정해 만든 파일)는 스펙의 검사 순서대로 형식 검사에서 `UnsupportedFormat`(415)이 된다. 스펙 완료 판정의 "0초 파일은 422"는 AAC 트랙의 길이가 0인 경우에 해당한다. 단위 테스트는 길이 0.0을 `InvalidDuration`으로 확인한다.
- MP4 계열 판정은 ffprobe `format_name`에 `mp4` 또는 `m4a`가 있는지로 한다. ffprobe는 MP4·MOV·3GP를 같은 이름 목록(`mov,mp4,m4a,3gp,3g2,mj2`)으로 보고하므로 AAC가 든 MOV도 통과한다.
- ffprobe 실행 실패·10초 초과·출력 미완료는 규격 위반이 아닌 `AudioProbeException`이다. 경로는 `file:` 접두어로 넘겨 다른 프로토콜로 해석되지 않게 한다.
- multipart 한도는 파일 21MB·요청 22MB다. 20MiB 경계(413)는 `RecordingFileValidator`가 정한다. 413·415·422의 HTTP 응답 연결은 업로드 API(S15P31E102-181)에서 한다.

## 검증 결과

- `./gradlew --no-daemon clean build`: 성공. 기본 테스트 12개(검사 규칙 4, ffprobe 대역 4, 기동 3, readiness DB 실패 1), 실패 0.
- `./gradlew --no-daemon mediaTest`(로컬 ffmpeg 8.1.2): 5개 통과. 44.1kHz 스테레오·48kHz 모노 AAC 수용과 메타데이터, 이름 바꾼 MP3·ALAC·오디오 없는 m4a·잘린 파일·빈 파일 거부, 600.5초 통과·601초 거부, 20,971,521바이트 거부·20,971,520바이트 통과 후 형식 거부, ffprobe 없음은 `AudioProbeException`.
- `PATH=/usr/bin:/bin:/usr/sbin:/sbin`으로 ffmpeg를 뺀 `mediaTest`: 5개 모두 실패, 건너뜀 0.
- 대역 테스트 민감도: 종료 코드 검사와 시간 초과를 제거한 변형에서 해당 테스트 2개가 실패하는 것을 확인하고 원복했다.
- 이미지: `docker build`로 만든 이미지의 ffprobe는 `8.0.1-3ubuntu2`. 같은 픽스처 8종의 `format_name`·길이·코덱·샘플레이트·채널이 로컬 8.1.2와 같았다. 컨테이너를 UID 10001로 띄워 readiness HTTP 200, 같은 사용자로 ffmpeg 생성·ffprobe 판독을 확인했다.
- edo1 서버·Jenkins·운영 이미지에서는 실행하지 않았다.
