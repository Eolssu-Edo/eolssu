## 결정·제약

- ffprobe가 필요한 검사는 `media` 태그의 `./gradlew mediaTest`로 분리했다(사용자 결정). Jenkins는 edo1 호스트 에이전트에서 `clean build`를 실행하므로, 호스트에 ffmpeg를 설치하기 전에 `clean build`에 넣으면 develop 빌드·배포가 멈춘다. `mediaTest`는 ffmpeg·ffprobe가 없으면 건너뛰지 않고 실패한다. 기본 `test`는 테스트 JVM의 `java`로 띄우는 가짜 ffprobe(`FakeFfprobe`)로 JSON 해석·종료 코드·시간 초과·중단을 본다. 처음에는 `#!/bin/sh` 스크립트였으나 Windows에서 실행되지 않아 리뷰 후 바꿨다.
- 고정 버전: 실행 베이스 `eclipse-temurin:21-jre`는 Ubuntu 26.04(`resolute`)이며 `ffmpeg=7:8.0.1-3ubuntu2`를 설치한다. 베이스의 Ubuntu가 바뀌면 설치가 실패하므로 함께 갱신한다. ffmpeg 레이어는 약 410MB다.
- 오디오 스트림이 없는 m4a(ffmpeg로 0초를 지정해 만든 파일)는 스펙의 검사 순서대로 형식 검사에서 `UnsupportedFormat`(415)이 된다. 스펙 완료 판정의 "0초 파일은 422"는 AAC 트랙의 길이가 0인 경우에 해당한다. 길이 하한은 168 스펙(`2ec0830`)대로 1ms다. 단위 테스트가 0.0004초·0.000999초 거부, 0.001초 통과(1ms)를 확인한다.
- MP4 계열 판정은 ffprobe `format_name`에 `mp4` 또는 `m4a`가 있는지로 한다. ffprobe는 MP4·MOV·3GP를 같은 이름 목록(`mov,mp4,m4a,3gp,3g2,mj2`)으로 보고하므로 AAC가 든 MOV도 통과한다.
- ffprobe 실행 실패·10초 초과·출력 미완료·대기 중 중단·출력 읽기 실패는 규격 위반이 아닌 `AudioProbeException`이다. 중단되면 인터럽트 표시를 되살리고, 어느 경우든 남은 ffprobe 프로세스를 종료한다. 출력 읽기 실패 경로는 자동 테스트로 재현하지 못했다. 경로는 `file:` 접두어로 넘겨 다른 프로토콜로 해석되지 않게 한다.
- multipart 한도는 168 스펙(`b740548`)의 요청 크기 한도 표대로 파일·요청 25MiB다. 20MiB 경계(413)는 `RecordingFileValidator`가 정한다. Nginx `client_max_body_size 25m`과 413·415·422의 HTTP 응답 연결은 업로드 API(S15P31E102-181)에서 한다.

## 검증 결과

- `./gradlew --no-daemon clean build`: 성공. 기본 테스트 12개(검사 규칙 4, ffprobe 대역 4, 기동 3, readiness DB 실패 1), 실패 0.
- `./gradlew --no-daemon mediaTest`(로컬 ffmpeg 8.1.2): 5개 통과. 44.1kHz 스테레오·48kHz 모노 AAC 수용과 메타데이터, 이름 바꾼 MP3·ALAC·오디오 없는 m4a·잘린 파일·빈 파일 거부, 600.5초 통과·601초 거부, 20,971,521바이트 거부·20,971,520바이트 통과 후 형식 거부, ffprobe 없음은 `AudioProbeException`.
- `PATH=/usr/bin:/bin:/usr/sbin:/sbin`으로 ffmpeg를 뺀 `mediaTest`: 5개 모두 실패, 건너뜀 0.
- 대역 테스트 민감도: 종료 코드 검사와 시간 초과를 제거한 변형에서 해당 테스트 2개가 실패하는 것을 확인하고 원복했다.
- 이미지: `docker build`로 만든 이미지의 ffprobe는 `8.0.1-3ubuntu2`. 같은 픽스처 8종의 `format_name`·길이·코덱·샘플레이트·채널이 로컬 8.1.2와 같았다. 컨테이너를 UID 10001로 띄워 readiness HTTP 200, 같은 사용자로 ffmpeg 생성·ffprobe 판독을 확인했다.
- edo1 서버·Jenkins·운영 이미지에서는 실행하지 않았다.

## 독립 리뷰 반영 (`672ff12..69ecd06`)

사용자 지시로 독립 리뷰 지적 1·2·3·5를 168 브랜치 최신 스펙 기준으로 고쳤다. 구현 당시 스펙 스냅샷(`17672ef`) 이후 168 브랜치에서 길이 하한(`2ec0830`)과 요청 크기 한도(`b740548`)가 바뀌었다.

| 지적 | 처리 |
| --- | --- |
| 1 길이 하한 0초 초과 → 1ms | 수정. 0.0004초·0.000999초 거부, 0.001초 통과 단위 테스트 추가 |
| 2 multipart 21MB·22MB → 25MiB | 수정. 파일·요청 25MiB. Nginx는 S15P31E102-181 |
| 3 셸 스크립트 대역이 Windows에서 실행 불가 | 수정. 테스트 JVM의 `java`로 띄우는 `FakeFfprobe`로 교체. ffprobe 명령을 실행 파일+앞 인자 목록으로 받게 바꿨다. Windows에서 직접 실행해 보지는 않았다 |
| 5 대기 중 중단 시 프로세스 잔류, 출력 읽기 실패를 415로 오판 | 수정. 중단·읽기 실패도 `AudioProbeException`, `finally`에서 남은 프로세스 종료. 중단 테스트 추가 |
| 4 Jenkins ffmpeg·`mediaTest`, 서버 Dockerfile, 스펙 버전 기록 | 기록만. 위 진행 목록의 미완료 3개 그대로다. 운영 이미지는 서버 Dockerfile로 만들므로 맞추기 전에는 운영에 ffprobe가 없다. 이 Task를 완료로 보고하지 않는다 |
| 6 베이스 이미지 태그 미고정·ffmpeg 버전 고정의 보안 업데이트 차단 | 기록만. 베이스 Ubuntu가 바뀌면 설치가 실패하므로 함께 갱신한다. 베이스 digest 고정 여부는 별도로 정한다 |
| 7 첫 오디오 스트림만 판정 | 기록만. 첫 오디오가 AAC가 아니고 뒤 스트림이 AAC인 파일은 415가 된다. 앱 녹음은 오디오 스트림 하나라 영향이 작다 |
| 8 크기를 호출자 값으로 판정 | 기록만. S15P31E102-181에서 실제 수신 바이트 수를 넘겨야 한다 |

리뷰 반영 후 검증:

- 각 수정은 테스트를 먼저 바꿔 실패를 확인했다: 0.0004초가 통과하던 단위 테스트 실패, multipart 1MB 기본값과 21MB 대신 25MiB 기대 실패, 중단 시 `InterruptedException`이 그대로 나오던 테스트 실패.
- 프로세스 정리를 제거한 변형에서 시간 초과·중단 테스트 2개가 실패하는 것을 확인하고 원복했다.
- `./gradlew --no-daemon clean build`: 성공, 기본 테스트 13개(검사 규칙 4, ffprobe 대역 5, 기동 3, readiness DB 실패 1) 실패 0. 실행 후 남은 가짜 ffprobe 프로세스 없음.
- `./gradlew --no-daemon mediaTest`: 5개 통과.
- Windows에서는 실행하지 않았다.
