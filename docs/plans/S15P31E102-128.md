## 범위와 완료 조건

GitLab의 `blog/` 변경이 develop에 머지되면 Jenkins가 Hugo로 빌드해 GitHub Pages에 자동 배포되도록 완성한다.

| 단계 | 내용 | 수행 |
| --- | --- | --- |
| 1 | `blog/Jenkinsfile`: GitLab webhook 대신 develop SCM polling으로 `blog/` 변경 감지, `docker run`으로 Hugo 빌드 | 완료 (이 브랜치) |
| 2 | `blog/README.md`·`.gitignore`: 배포 설정 절차와 Hugo 생성물 제외 | 완료 (이 브랜치) |
| 3 | 1·2를 develop에 머지 (Jenkins 잡이 develop의 Jenkinsfile을 읽음) | 커밋·MR은 요청 시, 머지는 사람 |

완료 조건: develop에 블로그 글을 머지하면 블로그 주소에서 실제로 보인다. 잡 로그에서 polling 감지·빌드·배포 성공을 확인한다.

## 확인과 결정

- Jenkins 컨트롤러는 `127.0.0.1:8080`에서만 수신하고, 다른 develop 잡은 1분 SCM polling을 쓴다([서버 구성 기록](../knowledge/infra/server-configuration.md)). 기존 블로그 Jenkinsfile의 `gitlab(...)` 트리거는 webhook이 Jenkins에 닿지 않아 동작할 수 없다.
- 백엔드 develop 잡(`infra/jenkins/backend.Jenkinsfile`)과 같은 형태로 맞춘다: `pollSCM('* * * * *')`, `skipDefaultCheckout()`, `refs/heads/develop` 명시 체크아웃(`eolssu-gitlab`), 커밋 SHA 검사.
- 빌드는 `agent { docker }` 대신 호스트 에이전트에서 `docker run`으로 Hugo 이미지를 실행한다. 다른 잡도 호스트 Docker를 직접 쓰고, Docker Pipeline·GitLab 플러그인 설치 여부를 확인하지 않아도 된다. 소스는 읽기 전용, 네트워크 없음, 에이전트 UID로 실행하고 결과물은 workspace의 `blog-build/public`에 쓴다.
- 빌드·배포는 이번 빌드에 `blog/**` 변경이 있거나 사람이 직접 실행했을 때만 한다. 다른 develop 변경으로 polling이 돌아도 두 단계는 건너뛴다.
- 같이 정리: README의 블로그 브랜치 예시를 루트 규칙으로 고침, `.gitignore`에 `blog/public/`·`blog/resources/_gen/`·`.hugo_build.lock`·`blog-build/` 추가([Task 71 점검](S15P31E102-71.md)의 후속 지적 2·3·4 중 블로그 항목).

## 검증과 결과

- `bash -n blog/scripts/deploy.sh` 통과, `git diff --check` 통과. Jenkinsfile에 `gitlab(...)` 트리거·`agent { docker }`가 남지 않음을 확인했다.
- Build 단계의 `sh` 블록을 그대로 로컬에서 실행했다(Windows Docker Desktop 29.6.1, `ghcr.io/gohugoio/hugo:v0.145.0`, `WORKSPACE`=worktree).
  - 첫 실행은 `failed to acquire a build lock: open /project/.hugo_build.lock: read-only file system`로 실패했다. Hugo가 소스 폴더에 lock 파일을 만들기 때문이다. 소스를 읽기 전용으로 유지하려고 `--noBuildLock`을 추가했다.
  - 수정 후 성공: 16페이지, 정적 파일 2개, 약 0.2초. `blog-build/public/index.html` 존재, sitemap의 주소가 `https://team-ido.github.io/…`, 소스 폴더에 lock 파일 없음, `blog-build/`는 Git 변경 목록에 나타나지 않음.
- 확인하지 못한 것: Jenkins 선언형 문법 검사, 실제 polling 감지·`changeset` 조건, `deploy.sh`의 GitHub push(토큰·저장소 없음). 잡 생성 후 첫 직접 실행에서 확인한다.
