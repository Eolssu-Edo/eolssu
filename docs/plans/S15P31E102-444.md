## 개발 앱 분리와 Apple 로그인 (2026-11-09)

- 출시 앱과 번들 ID가 같아 OTA 설치가 막혔다(“동일한 번들 ID”). 개발본을 `com.ssafy.eolssu.dev`·표시 이름 '얼쑤 개발'로 분리했다. Jenkins #58 게시 확인(설치 페이지 목록). 게시기는 개발 번들만 받는다(서버 백업 `publish-ipa.py.backup-444-before-dev`).
- 결정(사용자 승인): 개발 앱 Apple 로그인을 붙인다. Apple Developer에서 `com.ssafy.eolssu.dev`의 Sign in with Apple을 `com.ssafy.eolssu`에 그룹화하고, 앱은 Apple redirectUri로 개발 앱 전용 주소를 보낸다. 서버는 그 주소일 때만 개발 번들 ID로 교환·검증한다. 앱 식별자 필드를 새로 두는 방식은 API 계약 변경이라 택하지 않았다. 계약은 [소셜 로그인 명세](../specs/social-auth.md)의 Sign in with Apple 절.
- 다른 제공자는 `ASWebAuthenticationSession`이 복귀 스킴을 세션 안에서 받으므로 두 앱이 같은 스킴이어도 겹치지 않는다.
- 검증
  - 백엔드 `AppleOAuthGatewayTests` 10개 통과(개발 번들 교환·client_secret sub·authorizationUrl, 출시/개발 토큰 교차 거절, 개발 설정 없으면 개발 주소 거절, 해지 재시도·미재시도).
  - 백엔드 전체 `test` 690개 중 6개 실패: `LocalRecordingStorageTests`·`LocalRecordingReadTests`·`LegalDocumentPageTests`·`AccountDeletionPageTests`. 변경을 빼고 같은 커밋에서 다시 돌려도 같은 실패라 이 Mac의 임시 폴더 심볼릭 링크 환경 문제로 본다(“Recording root must not contain symlinks”). 이 변경과 관계없음.
  - iOS 시뮬레이터 테스트 바이너리 1077개 통과(`MyPageInstrumentTest` 제외, 기존 멈춤). `IosOAuthRelayTest`에 개발 앱 경로 검사 추가. `compileKotlinIosArm64` 통과. 이 Mac에 Android SDK가 없어 Android 호스트 테스트는 미실행.
- 남은 일: Apple Developer 그룹화(사용자), MR 병합 후 운영 `.env`·서버 Compose에 `AUTH_OAUTH_APPLE_DEV_CLIENT_ID`·`AUTH_OAUTH_APPLE_DEV_REDIRECT_URIS` 추가와 backend 재생성, 새 개발 빌드에서 Apple 로그인 실기기 확인, Notion API 명세서 Apple 항목 갱신.
