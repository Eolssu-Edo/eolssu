# 웹 수동 배포 잡의 Jenkins 실행 슬롯 분리

[S15P31E102-755](https://ssafy.atlassian.net/browse/S15P31E102-755) · Story S15P31E102-40

- [x] 웹 잡 전용 노드 `edo1-web`의 등록 파일·systemd 서비스와 Pipeline 라벨을 저장소에 추가한다.
- [ ] edo1에 노드·서비스를 적용하고 웹 잡 Pipeline을 갱신한다.
- [ ] 백엔드 빌드 중에도 웹 잡이 `edo1-web`에서 바로 시작하는지 확인한다.

## 배경

edo1의 빌드 슬롯은 `edo1-host` executor 1개뿐이었다. 백엔드·웹 잡이 모두 `agent any`라 백엔드 빌드가 도는 동안 웹 수동 배포는 대기열에서 기다렸다.

## 결정

블로그 잡의 `edo1-blog`와 같은 방식으로 EXCLUSIVE 전용 노드를 추가했다. `edo1-host`의 executor를 2개로 늘리는 방법은 쓰지 않았다. 그 방법은 `agent any` 잡 두 개가 같은 노드에서 겹쳐 백엔드 잡끼리의 병행까지 열고, 잡별 슬롯을 보장하지 못하기 때문이다. 전용 노드는 웹 잡만 받고 작업 공간도 분리된다.

운영 배포의 직렬화는 기존 공유 lock(최대 120초 대기)과 백엔드 journal 상태 검사가 계속 맡는다. 같은 호스트의 CPU를 나눠 쓰므로 두 잡이 겹치면 각 빌드 시간이 늘 수 있다.

## 검증

적용 절차와 복구는 [컨트롤러 문서](../../infra/jenkins/controller/README.md#웹-수동-배포-전용-슬롯)를 따른다. 운영 적용·실행 결과는 적용 후 여기에 기록한다.
