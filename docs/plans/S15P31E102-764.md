# 모범 연주 메타데이터와 시간표의 방문 간 재사용

- [S15P31E102-764](https://ssafy.atlassian.net/browse/S15P31E102-764) · Story S15P31E102-30 · 에픽 S15P31E102-18
- 기준 커밋 `866d9064` · 스프린트 5 · 진행 중

## 범위와 계획

1. 제공 곡의 모범 연주를 다른 연습 방문에서 다시 열어도 같은 판본의 검증된 메타데이터와 시간표를 재사용한다. 개인 악보는 기존 경로를 사용한다.
2. 곡·악보 응답에 현재 음원 해시가 없어 메타데이터 GET으로 서버의 게시 상태와 판본을 매번 확인한다. 곡·악보·음원 해시·공통 악보 해시와 재생 조건이 일치하면 시간표 GET과 재파싱을 생략한다. 플레이어에는 서버의 고정 재생 경로를 전달한다.
3. 재진입 전후의 요청 수와 재생 시작 시간을 비교한다. 음원과 악보 판본 변경, 조회·재생 오류 뒤 재시도, 서명 URL 갱신, 탐색 위치와 악보 동기화를 확인한다. 비교 환경과 관측하지 못한 항목을 기록한다.

## 구현 결정

- 앱 수명의 `ApiModelAudioRepository`에 최근 검증 완료한 제공 곡 최대 4개의 메타데이터와 시간표를 보관한다. 게시 상태를 확인한 응답의 곡 ID·악보 판본·음원 SHA-256·공통 악보 SHA-256과 재생 조건, 화면의 악보 구조가 모두 일치할 때만 재사용한다.
- 첫 방문과 판본이 달라진 방문에서는 시간표를 받고 기존 검증을 통과한 뒤 저장한다. 404·서버 오류·시간표 검증 실패 시 기존 오류 흐름을 따른다. 시간표가 없는 음원과 절대 URL을 받는 구형 응답은 기존 조회 흐름을 사용한다.
- 플레이어에는 동일 서버의 `/play` URL을 전달한다. 서버는 로딩마다 게시 상태를 확인하고 `Cache-Control: no-store`인 302로 새 서명 URL을 발급한다. 시간표를 재사용하면 기존 성능 로그에 `model_audio_timeline`의 `retained` 데이터 로드를 남긴다.

## 변경 전후 격리 검증

2026-11-11 Windows, JDK 21, Kotlin 2.4.20에서 `866d9064`의 저장소 코드와 변경본을 같은 JVM 검증 코드로 각각 실행했다. 공통 코드의 `ApiModelAudioRepository`, `ModelAudioSession`, 악보 위치 계산을 그대로 실행했다. Ktor MockEngine은 메타데이터 35ms와 시간표 90ms, 모의 플레이어는 로딩 후 110ms에 재생 상태를 내도록 설정했다. `previewSong()`의 반복 구간이 있는 고정 악보를 사용했다. 버전마다 저장소 한 인스턴스로 첫 방문을 한 뒤, 세션·플레이어를 매번 새로 만들어 10회 재진입했다. 시간은 재생 요청부터 세션의 `Playing` 상태까지 쟀다.

- JVM에서 `ModelAudioRepositoryTest`, `ScorePerformanceTest`, `CommonScoreDataTest`, `ModelAudioSessionTest`를 JUnit으로 실행했다. 변경 전에는 신규 재사용 테스트 1개가 재조회로 인해 실패했고, 변경 후에는 35개 모두 통과했다.
- 같은 악보 판본에서 음원 SHA-256이 바뀌거나 악보 판본이 오르면 새 시간표를 조회했다. 게시 음원 404·503은 기존 오류 처리를 따랐고, 시간표 503 뒤 재시도에서 정상 시간표를 받았다. 서명 값이 달라진 모의 절대 URL 응답은 재조회한 URL을 사용했다.
- 마지막 재진입에서 75% 위치로 탐색하면 플레이어가 고정 재생 경로로 다시 로딩했고, 음원 위치 4,875ms에 맞춰 화면 상태의 악보 위치가 5.5 tick으로 갱신됐다. 탐색 중 메타데이터와 시간표의 추가 GET은 0건이었다.

- 변경본의 Web JS 코드와 테스트 소스는 `gradlew.bat --offline --max-workers=2 :shared:compileKotlinJs :shared:compileTestKotlinJs`로 컴파일을 통과했다.

## 검증 대기

- Android 호스트 테스트 `gradlew.bat --offline :shared:testAndroidHostTest --tests '*ModelAudioRepositoryTest'`는 SDK 경로가 없어 시작하지 못했다. 변경 APK의 실제 재생 시작 시간, 서명 만료 뒤 302 및 음원 출력, 탐색 시 화면의 악보 동기화는 실기기 검증 대기다.
- 변경 APK를 준비하면 !564와 동일한 정악대금 오나라(62)에서 첫 조회를 1회 하고 연습 화면에 새로 들어가 재생하는 흐름을 10회 반복한다. 기존 계측의 `model_audio_metadata`·`model_audio_timeline` HTTP 시도와 `player_started`를 수집하고, 이전 표본과 중앙값·P90을 비교한다. 서명 만료 뒤 화면 재진입과 탐색에서 새 302, 실제 음원 출력과 정간보 진행 위치를 확인한다.
- Web 브라우저 테스트 `gradlew.bat --offline :shared:jsTest`는 기준 코드 컴파일 후 `kotlin-web-helpers/dist/kotlin-test-karma-runner.js`를 찾지 못해 실행되지 않았다.
