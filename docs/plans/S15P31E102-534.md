- Story 318, Epic 15, 스프린트 59245, 오은서, 진행 중. 기준 origin/develop 288f3bb8. 별도 wt-534·피처 브랜치, 시작 시 깨끗함. 메인 체크아웃의 기존 변경은 보존한다.

## 순서

1. 임시 저장소의 실제 파일 수명·읽기 권한·30분 만료·재시작 삭제를 실패부터 검증한다.
2. 저장소를 접수/인식에 분리 주입하고 성공·실패·경합 시 정리한다. R2 음원은 기존 저장소를 유지한다.
3. 재시도 비활성·원본 페이지 미반환과 내부 경로 차단을 회귀 검사한다. FE에서 해당 기능의 실제 소비 여부를 대조한다.
4. Notion SHT-07·08·10·14·02·12 등 실제 영향 페이지를 코드와 대조해 수정·재조회한다. 이전 명세는 대체됨을 표시하고 임의 삭제하지 않는다.
5. backend clean build·DB 통합·내부 HTTP 동작을 검증하고 변경 영향 문서·자체 검토 후 작업 단위 커밋한다. 정식 재리뷰·Push·운영 배포는 단계와 권한을 구분한다.

## 리뷰 후속 수정 (2026-11-06, 로컬)

- multipart 위치를 `eolssu.sheet-import.multipart-directory`로 고정하고 임시 저장소가 처음 본 시각부터 30분에 삭제한다. 재시작 시에도 비운다.
- 대기열 사본이 30분을 새로 받아 최대 약 60분이 되던 문제를 복사본 만료 상속으로 고쳤다.
- 파일이 사라진 요청은 `files`·`metadata` 어느 쪽에서 실패해도 503 `CONVERSION_UNAVAILABLE`이다. 처음 구현에서는 `metadata` 쪽이 400이었고, DB·HTTP 테스트로 발견해 고쳤다.
- 남은 한계: 요청 복사본의 30분은 컨트롤러 진입부터 세므로 파싱과 진입 사이가 멈추면 합계가 30분을 넘을 수 있다. Nginx 본문 임시 파일은 이번 범위 밖이다. 같은 위치를 쓰는 녹음 업로드는 30분 넘게 정체하면 500으로 끝난다.

| 검사 | 실제 결과 |
| --- | --- |
| backend `gradlew.bat clean build databaseTest --max-workers=1` | 성공. 일반 678개 중 677 통과·기존 1개 미실행, DB 295개 중 294 통과·기존 1개 미실행. 실제 MySQL 8.4와 로컬 playback 사용. |
| 구현 전 실패 | 단위 3개와 DB·HTTP 1개가 의도한 지점에서 실패함을 확인. |
| 변이 | `files` 복사의 IOException 처리를 빼면 파일 파트 소실 테스트가 500으로 실패. 처음 쓴 테스트는 `metadata` 파일을 지워 변이를 잡지 못했고, 내용으로 파일 파트를 고르도록 고쳤다. |

이번 수정은 backend만 바꿨으므로 AI·OMR·frontend·Nginx 검사는 다시 실행하지 않았다.
