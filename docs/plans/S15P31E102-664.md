# S15P31E102-664 Mattermost 점검 수정

- [Jira 작업](https://ssafy.atlassian.net/browse/S15P31E102-664) · [판정 기준](../specs/mattermost-inspection-measurements.md) · [운영 모니터링 Story](https://ssafy.atlassian.net/browse/S15P31E102-41)
- 활성 스프린트 5 · 진행 중. 최신 develop `f2bf0a2b`에서 분리했다.
- 여섯 세션의 재현 결과를 입력으로 삼는다. 롤백 보관본 오탐은 별도 [662](https://ssafy.atlassian.net/browse/S15P31E102-662)에서 처리한다.

1. 서버 저장공간 단일 요청과 부분 실패 보존을 두 Engine API 응답으로 확인한다.
2. 컨테이너 로그, bind, NET·I/O의 표기와 근거를 회귀 테스트로 확인한다.
3. 대기 웹의 확인된 loopback TLS 경로와 HTTP 실패 응답을 테스트한다.
4. 점검기 회귀 테스트와 운영 입력으로 여섯 보고서를 검증한다.

## 구현 검증

- 저장공간 중복 조회와 형식 오류 회귀를 재현했다. Docker Engine 29.9.2(API 1.56), 29.1.3(API 1.52)에서 서버 점유량·회수 가능량을 표시했고, 수집은 각각 27.16초와 4.82초였다.
- 운영 데이터를 읽기 전용으로 수집해 edo1 syslog 태그 여섯 개, node-exporter 관측용 마운트, Jenkins 데이터 11.8GiB를 확인했다. edo2 AI·OMR의 네트워크와 블록 I/O 기록 없음을 별도로 표시했다.
- 대기 웹은 컨테이너 안에 Docker 검사를 추가하는 대신 현재 공개된 loopback 포트에서 검증한다. 후보 수집기가 인증서를 검증하고 HTML HTTP 200을 받은 것을 확인했다. 404·다른 본문 유형·TLS 실패는 장애, 신뢰 파일 읽기 실패는 미측정으로 확인했다.
- 점검기 회귀 테스트 68건과 양쪽 SSH dispatch 문법 검사를 통과했다.
