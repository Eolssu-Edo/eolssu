# S15P31E102-1229 JDK 자동 업데이트 뒤 Jenkins 에이전트 빌드 실패와 JDK 자동 업데이트 제외

- [Task](https://ssafy.atlassian.net/browse/S15P31E102-1229)는 우동균 담당, Epic S15P31E102-21 소속, 활성 스프린트 5 배정, S15P31E102-758과 relates로 연결했다(2026-11-22 생성).
- 시작 기준은 `origin/develop` `e09d056a9`다. 범위와 완료 조건은 Task 본문을 따른다. 운영 절차는 [needrestart 안내](../../infra/needrestart/README.md)에 있다.

## 장애 경과 (UTC)

- 11-20 01:53: backend #704, ai #174, omr #168, playback #169가 마지막으로 성공했다.
- 11-20 06:58: unattended-upgrades가 `openjdk-21-jre`·`-jre-headless`·`-jdk-headless`를 21.0.13.0.3에서 21.0.13.1로 올렸다. 758 설정대로 needrestart는 에이전트 4개를 `Service restarts being deferred:`에 남기고 재시작하지 않았다(`unattended-upgrades-dpkg.log`로 확인).
- 이후 수동 재시작이 없었다. 에이전트 JVM은 11-13(host·web·blog)·11-15(ai)에 시작한 예전 버전으로 남았고, 디스크의 `jspawnhelper`는 새 버전이었다. 에이전트가 외부 프로세스를 띄울 때마다 `Failed to exec spawn helper ... JDK version mismatch`로 실패해 checkout의 `git init`부터 진행되지 않았다.
- JDK가 바뀐 뒤에도 develop에 새 커밋이 없어 빌드는 돌지 않았다. 08:31에 S15P31E102-1227이 병합되자 첫 빌드가 checkout에서 실패했다.
- 네 잡의 SCM polling은 `* * * * *`(1분마다)다. Jenkins는 checkout에 성공해야 빌드한 커밋을 기록하므로, 실패한 빌드는 `e09d056a9`를 빌드했다는 기록을 남기지 못했다. 그래서 polling은 1분마다 아직 빌드하지 않은 새 커밋이 있다고 판단해 빌드를 다시 시작했다. 08:31부터 11-22 08:46까지 약 2,895분 동안 backend 빌드 번호가 #704에서 #3599로 2,895만큼 올라갔다(ai·omr·playback은 각각 #3068·#3062·#3063까지). 해당 시각의 빌드는 지워져 직접 확인하지 못했고, 두 수가 일치하는 것으로 판단했다.
- 잡마다 최근 빌드 10개만 보관하는 설정(`numToKeep=10`)이 있어 오래된 실패 빌드는 자동으로 지워졌다. 약 2,900은 쌓인 빌드 수가 아니라 빌드 번호가 올라간 횟수다.
- Jenkins 컨트롤러는 Docker 이미지 안의 자체 JDK를 써서 영향이 없었다. 디스크(69%)·메모리(가용 10Gi)도 원인이 아니었다.

## 복구 (11-22)

- 08:46:05 `eolssu-jenkins-agent`·`-web-agent`·`-ai-agent`, 08:49:30 `eolssu-jenkins-blog-agent`를 재시작했다. 모든 노드가 온라인으로 돌아왔다.
- 재시작 직후 ai #3069, omr #3063, playback #3064가 성공했다. backend #3599는 재시작 4초 전에 시작해 실패했고, #3600은 checkout부터 배포까지 통과해 약 10분 만에 성공했고, `e09d056a9`가 `deployed`로 운영에 반영됐다.
- 복구 뒤에는 polling이 변경 없음으로 판단해 1분 간격 빌드가 멈췄다.
- 09:00 무렵 Script Console에서 장애 기간(11-20 06:58~11-22 08:46)에 시작했고 로그에 `Failed to exec spawn helper`가 있는 FAILURE 빌드만 지웠다. 먼저 삭제 없이 대상을 센 뒤 지웠다. 남아 있던 33개(backend #3591~#3599, ai #3061~#3068, omr #3055~#3062, playback #3056~#3063)가 대상이었다. 다른 잡의 예전 실패 빌드는 남겼다.

## 선택

- `/etc/apt/apt.conf.d/51eolssu-jenkins-jdk`로 `openjdk-` 패키지를 unattended-upgrades의 `Package-Blacklist`에 넣었다. apt 설정의 목록 값은 여러 파일에서 합쳐지므로 기본 `50unattended-upgrades`는 고치지 않았다.
- 758의 needrestart 재시작 미루기는 유지한다. JDK 외 라이브러리 업데이트에도 빌드가 끊기지 않게 하는 역할은 여전히 필요하다.
- 대가: JDK 보안 업데이트가 자동으로 설치되지 않는다. 운영 안내에 JDK 업데이트와 에이전트 재시작을 한 번에 하는 절차를 적었다.
- 검토한 대안: JDK 업데이트 뒤 빌드가 없을 때 에이전트를 자동 재시작하는 타이머. 빌드 유휴 판정과 배포 lock을 다뤄야 해서 이번 범위에서 제외했다.
