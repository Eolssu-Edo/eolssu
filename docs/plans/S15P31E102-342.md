## 범위

- 포함: REC-01 `PUT /api/practice-sessions/{sessionId}/record`, REC-02 `GET /api/users/me/practice-records`, REC-03 `GET /api/practice-sessions/{sessionId}/recording`, REC-04 `DELETE /api/practice-sessions/{sessionId}/record`, PRA-03 변경(지운 기록 404, 저장 기록 첫 조회 때 `viewed_at`), 계약 문서·Swagger·테스트.
- 하지 않음: 앱 연결(369), 보관 정책·약관·R2·정리 작업(375), EVA-01~04 변경(이미 404), 구간 반복 횟수 필드(REC-02 규칙 8, 2차), 파일 존재 확인. V2 칸(`saved_at`·`memo`·`viewed_at`·`record_deleted_at`)을 쓰므로 Flyway 추가는 예정하지 않는다. 목록 조회 인덱스가 필요하면 spec·plan에서 판단한다.
- 유지: 성장 집계는 저장·삭제와 관계없이 DONE 평가를 센다. PRA-03의 분석 대기 조회와 시간 초과 처리, 업로드·분석 흐름, 탈퇴 일괄 삭제의 녹음 삭제는 그대로 둔다.

## 완료 조건

- 저장 멱등(`savedAt` 유지), DONE 아님 409, 없음·타인·지운 기록 404, 메모 규칙, 곡 묶음 정렬·페이지, `isNew`, 재생 주소, 삭제 순서와 파일 삭제 실패 503을 `./gradlew test`·`./gradlew databaseTest`로 확인한다.
- 서명 URL 재생은 테스트 버킷에서 확인한다. 확인하지 못하면 미검증으로 남긴다.
- 계약 문서와 Swagger를 갱신한다.

## 열린 항목

- Notion REC-01~04 정정: 30일 문구는 375가, `lastSavedAt` 설명·PRA-03 404·지운 기록 404는 이 Task의 spec 확정 뒤에 고친다. Notion 연결 계정이 은서님 것이라 쓰기 주체를 먼저 정해야 한다.
- 디자인 보드의 NEW 배지·삭제 화면 여부는 369에서 확인한다. NEW 배지가 없더라도 `isNew` 필드가 남는 것 외의 영향은 없다.
- 실제 R2 버킷으로 받은 서명 URL 재생은 확인하지 못했다(이 환경에 R2 연결값이 없다). 배포 뒤 운영 R2에서 한 번 확인한다.
- 로컬 녹음 저장소로 되돌리면 다시 듣기는 503이다. 그때 앱에서 다시 들으려면 외부 HTTPS 재생 흐름이 따로 필요하다(369·375가 알아야 할 제약).
