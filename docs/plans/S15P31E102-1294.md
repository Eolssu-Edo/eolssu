# Jenkins CI·빌드·배포의 GitHub Actions 이전

[Jira Task](https://ssafy.atlassian.net/browse/S15P31E102-1294) · [서버 반납 Story](https://ssafy.atlassian.net/browse/S15P31E102-1163) · [Mac mini 이전 계획](https://ssafy.atlassian.net/browse/S15P31E102-1291)

## 요구사항

- team-edo/eolssu의 develop에 대한 PR과 병합 후 자동 검사를 GitHub 표준 러너에서 실행한다. 주간 Python 검사와 DB·Python 격리 검사 결과를 구분한다.
- 운영자가 필요할 때 develop 이력의 검사된 커밋을 지정한다. GitHub Actions가 기존 이미지 검사와 기동 점검을 거쳐 GHCR에 게시하고, 운영 Mac의 Linux VM에서 기존 헬스 검사와 복구 도구로 digest를 적용한다.
- Android QA·출시와 iOS Ad Hoc·출시 빌드는 수동 실행한다. 보호된 GitHub 환경에서 QA·출시 서명 자격증명을 주입하고 스토어 업로드는 실행 입력으로 선택한다. QA APK는 기존 QA 서명으로 업데이트할 수 있어야 하고 Ad Hoc IPA는 등록 기기용이다.
- 기존 Jenkins 종료 조건은 새 경로의 자동 검사, 운영 환경과 격리된 Mac에서 배포·복구, 모바일 설치 및 내부 스토어 업로드 확인이다.

## 실행 순서

1. GitHub 자동 점검에서 기존 백엔드·브라우저·Python 명령과 리포트를 재사용한다.
2. 테스트 통과한 커밋으로 이미지와 모바일 산출물을 만든다. 스토어와 레지스트리 쓰기는 보호된 develop의 전용 잡에 둔다.
3. SHA와 이미지 digest를 대조해 기존 배포 저널로 한 서비스씩 적용한다. OMR x86_64의 M4 성능과 실제 playback 에셋은 격리 환경에서 대조한다.
4. 실제 실행 증거를 확인한 뒤 기존 Jenkins를 종료한다.
