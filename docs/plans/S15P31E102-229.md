- 시작 단계: 활성 스프린트 `S15P31E1 1 스프린트 3`(59139)의 진행 중
- 작업 상태의 기준은 Jira다.

## 문제

배포 도구는 등록 안 된 `/api/infra-smoke`가 Spring JSON 404를 주면 "백엔드가 떴다"고 봤다. 인증이 develop에 들어온 뒤 `/api/**`는 로그인이 필요해 같은 주소가 401이 됐고, 2026-10-28 11:39(KST) 이후 Jenkins backend 빌드 #86~#95가 `HTTP readiness failed`로 모두 실패했다. 운영은 `519410f` JAR에 머물러 그 뒤 병합된 업무 API가 반영되지 않았다(운영 `/api/terms` 404).

## 변경

| 위치 | 전 | 후 |
| --- | --- | --- |
| `deploy-backend.py` 후보 검사 | 후보 IP `/api/infra-smoke` 404 | 후보 IP `/api/actuator/health/liveness` 200 `UP`(후보는 DB 없이 뜸) |
| `deploy-backend.py` 운영 교체 뒤 | Nginx `/api/infra-smoke` 404 | Nginx `/api/actuator/health/readiness` 200 `UP` |
| `deploy-frontend.py` 교체 뒤 | 같은 404 검사 | 같은 readiness 검사 |
| `backup.py` 격리 복원 검증 | 같은 404 검사 | Nginx를 거친 readiness 200 `UP` |

`probe`는 기대 상태 코드와 JSON 본문의 키·값(예: `{"status": "UP"}`)으로 판단한다.

## 검증 (2026-10-28)

| 검사 | 결과 |
| --- | --- |
| `python3 -m unittest discover -s infra/jenkins/tests` | 20건 통과. 새 `ProbeTests` 3건은 고치기 전 실패 확인(UP만 통과·401·DOWN·비JSON 거절, 운영 검사 주소, 후보 주소) |
| 실제 JAR(프로필 없음) | `/api/infra-smoke` 401, `/api/actuator/health/liveness` 200 `{"status":"UP"}`, 새 `probe` 통과 |
| `infra/backup`·`infra/scripts` 테스트 | 통과 |
