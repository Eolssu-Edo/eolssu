# Android 평가 녹음의 스피커 장단 유입 완화

- 작업: S15P31E102-695. 연주 녹음·업로드 Story S15P31E102-33에 연결.
- 기준: origin/develop 7caf0b73, [평가 중 장단 동작](../specs/practice-controls.md).
- 완료 조건: 스피커 장단을 유지하면서 녹음 속 장단 성분을 줄이고, 장단과 겹친 연주 음의 시작점과 음높이를 보존한다.

## 검증과 결정

1. Galaxy S24+에서 기존 녹음 경로의 기기 AEC 켬·끔을 비교했다. 활성화는 성공했고 누음은 두 비교에서 각각 0.38dB와 0.29dB 줄었다. 이 설정은 앱에 반영하지 않았다.
2. 스피커 장단을 유지하고 재생 신호로 누음을 제거하는 검증을 선택했다. 캘리브레이션과 평가 타격을 분리해 추정한 누음 성분을 빼고, 시작점과 음높이 보존 여부를 별도로 관찰했다.
3. 고정된 스피커 응답을 가정한 모의 실험, Galaxy의 합성 타격음과 실제 ‘덩’ 음원 결과를 [측정 기록](../knowledge/frontend/android-jangdan-recording-echo.md)에 정리했다. 제품 녹음에 적용하기 전에는 실제 연주가 겹친 입력과 출력 경로·볼륨 변경에서 보정 실패를 감지하고 우회할 수 있어야 한다.
4. 같은 기기의 실제 덩 음원에서도 결과가 달랐고, 첫 시험에서 일부 타격의 누음이 증가했다. 제품 코드는 배포 후보에 포함하지 않고 재현용 도구와 실측만 남겼다.
5. 사용자 조건을 스피커 장단 + 휴대폰 내장 마이크로 확정했다. 연속 AudioTrack의 정확한 PCM과 하드웨어 시각을 사용해 AEC3·고정 파형·주파수 마스크·음악 분리 모델을 비교했다. 기본 AEC3는 장단을 크게 줄였지만 약한 대금도 일부 낮췄다. 고정 파형의 원본 보존이 가장 명확했으나 잔여 장단으로 인한 오류는 남았다.
6. 연주 구간의 가장 큰 250ms 장단 유입보다 대금이 12dB 크게 들어오는 디지털 혼합에서, 세 음 모두 실제 서버 pYIN의 음높이·시작점 비교 문턱을 통과했다. 이는 볼륨·입력 비율 조절의 실연 검증 출발점이며 휴대폰 볼륨 단계나 최종 채점 품질을 확정하지 않는다.
7. [실측 재현 도구](../../frontend/tools/probe_jangdan_aec3.py)는 원본 PCM·시각·참조 SHA-256을 읽고 AEC3 또는 보정 구간만 학습한 고정 파형의 출력과 타격별 지표를 남긴다. 실측 반복과 독립 읽기 검토, 보정 구간 이후 입력 변경에 대한 파형 불변성, 샘플 수·참조 이동 경계 검사를 수행했다. 제품 적용과 최종 채점 검증은 진행 중이다.
8. 사용자 소금 실연 2회를 확보했다. 첫 실연은 보정 구간의 연주음 때문에 없는 음높이를 만들었으므로 해당 보정을 기각했다. 조용한 보정 뒤 재시험에서는 소금 기본음 대역이 고정 파형에서 0.006dB, AEC3에서 0.48dB만 낮아지고 장단 저음이 포함된 대역은 각각 4.26dB, 6.69dB 낮아졌다. 순수 장단 제거량이나 곡 전체 채점 성공으로 일반화하지 않는다.
9. 제품 반영 전 조용한 보정의 자동 확인·실패 시 미적용, 출력/입력 시각 연결, 경로·볼륨 변경 처리, 처리 지연 보정과 실제 곡 채점 검증이 필요하다. Jira는 기존 Story S15P31E102-33, 스프린트 5(59321)의 진행 중을 유지한다. 실험 기록과 도구만 커밋하며 Push는 하지 않는다.
10. 사용자가 자동 차단·검증·앱 적용을 요청해 구현을 시작했다. origin/develop 74e5f41d를 122cb1bb에 병합했고 문서 목록 충돌은 양쪽 항목을 보존했다. [구현 스펙](../specs/android-recording-echo.md)에 실패 시 원본 유지, 준비 화면, 변경 시 무효화와 검증 기준을 기록했다.
