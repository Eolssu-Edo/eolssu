# Android 평가 녹음의 스피커 장단 유입 완화

- 작업: S15P31E102-695. 연주 녹음·업로드 Story S15P31E102-33에 연결.
- 기준: origin/develop 7caf0b73, [평가 중 장단 동작](../specs/practice-controls.md).
- 완료 조건: 스피커 장단을 유지하면서 녹음 속 장단 성분을 줄이고, 장단과 겹친 연주 음의 시작점과 음높이를 보존한다.

## 검증과 결정

1. Galaxy S24+에서 기존 녹음 경로의 기기 AEC 켬·끔을 비교했다. 활성화는 성공했고 누음은 두 비교에서 각각 0.38dB와 0.29dB 줄었다. 이 설정은 앱에 반영하지 않았다.
2. 스피커 장단을 유지하고 재생 신호로 누음을 제거하는 검증을 선택했다. 캘리브레이션과 평가 타격을 분리해 추정한 누음 성분을 빼고, 시작점과 음높이 보존 여부를 별도로 관찰했다.
3. 고정된 스피커 응답을 가정한 모의 실험, Galaxy의 합성 타격음과 실제 ‘덩’ 음원 결과를 [측정 기록](../knowledge/frontend/android-jangdan-recording-echo.md)에 정리했다. 제품 녹음에 적용하기 전에는 실제 연주가 겹친 입력과 출력 경로·볼륨 변경에서 보정 실패를 감지하고 우회할 수 있어야 한다.
4. 같은 기기의 실제 덩 음원에서도 결과가 달랐고, 첫 시험에서 일부 타격의 누음이 증가했다. 제품 코드는 배포 후보에 포함하지 않고 재현용 도구와 실측만 남겼다.
5. 사용자 조건을 스피커 장단 + 휴대폰 내장 마이크로 확정했다. 연속 AudioTrack의 정확한 PCM과 하드웨어 시각을 사용해 AEC3·고정 파형·주파수 마스크·음악 분리 모델을 비교했다. 기본 AEC3는 장단을 크게 줄였지만 약한 대금도 일부 낮췄다. 고정 파형의 원본 보존이 가장 명확했으나 잔여 장단으로 인한 오류는 남았다.
6. 연주 구간의 가장 큰 250ms 장단 유입보다 대금이 12dB 크게 들어오는 디지털 혼합에서, 세 음 모두 실제 서버 pYIN의 음높이·시작점 비교 문턱을 통과했다. 이는 볼륨·입력 비율 조절의 실연 검증 출발점이며 휴대폰 볼륨 단계나 최종 채점 품질을 확정하지 않는다.
7. [실측 재현 도구](../../frontend/tools/probe_jangdan_aec3.py)는 원본 PCM·시각·참조 SHA-256을 읽고 AEC3 또는 보정 구간만 학습한 고정 파형의 출력과 타격별 지표를 남긴다. 실측 반복과 독립 읽기 검토, 보정 구간 이후 입력 변경에 대한 파형 불변성, 샘플 수·참조 이동 경계 검사를 수행했다. 제품 적용과 최종 채점 검증은 진행 중이다.
8. 사용자 소금 실연 2회를 확보했다. 첫 실연은 보정 구간의 연주음 때문에 없는 음높이를 만들었으므로 해당 보정을 기각했다. 조용한 보정 뒤 재시험에서는 소금 기본음 대역이 고정 파형에서 0.006dB, AEC3에서 0.48dB만 낮아지고 장단 저음이 포함된 대역은 각각 4.26dB, 6.69dB 낮아졌다. 순수 장단 제거량이나 곡 전체 채점 성공으로 일반화하지 않는다.
9. 제품 반영 전 조용한 보정의 자동 확인·실패 시 미적용, 출력/입력 시각 연결, 경로·볼륨 변경 처리, 처리 지연 보정과 실제 곡 채점 검증이 필요하다. Jira는 기존 Story S15P31E102-33, 스프린트 5(59321)의 진행 중을 유지한다. 실험 기록과 도구만 커밋하며 Push는 하지 않는다.
10. 사용자가 자동 차단·검증·앱 적용을 요청해 구현을 시작했다. origin/develop 74e5f41d를 122cb1bb에 병합했고 문서 목록 충돌은 양쪽 항목을 보존했다. [구현 스펙](../specs/android-recording-echo.md)에 실패 시 원본 유지, 준비 화면, 변경 시 무효화와 검증 기준을 기록했다.
11. `2eb3250f` PCM 재생, `07031201` 보정 필터, `181362ba` 준비/실패 UI, `d7a86c93` 재사용·출력 수명, `f7ccc6d7` 녹음 연결을 통합했다. `cd439305`에서 타격 중 저역 악기 오염도 반복 잔차로 차단하고 `96797e25`에서 취소 경쟁과 출력 시각 손실을 닫았다. 정상 보정은 같은 물리 캡처를 유지하되 준비 PCM을 저장·분석에서 제외한다. 서버 채점 계약은 바꾸지 않는다.
12. 전체 host 1,310건 중 1,306건 통과·외부 설정 선택 검사 4건 건너뜀, 마지막 수정 관련 15건 통과. 실측 오염 거부/정상 42블록 적용과 추가 additive 오염 거부를 확인했다. 독립 검토의 P1 두 건·P2 한 건 및 취소 경쟁 후속 지적을 모두 수정·재검토했다. [측정 기록](../knowledge/frontend/android-jangdan-recording-echo.md)에 재현과 한계를 갱신했다.
13. QA APK `qa-local-695-96797e25`(1794300497)를 기존 인증서로 Galaxy에 데이터 삭제 없이 설치했다. Android APK 및 JS/Wasm 공유 코드 컴파일 통과. 기존 로그인·마이크 권한을 보존했다. 실제 꿩꿩장서방 평가 준비에서 볼륨 5/15 보정은 첫 시도 `NotQuiet`, 한 번의 재시도 `Unreliable`로 거부됐고 새 녹음/AAC를 시작하지 않았다. 실기기 정상 보정·AAC 반영·볼륨 변경 우회는 미검증이다.
14. **사용자 요청으로 2026-11-10 시험 중단, 다음 날 재개 예정.** 새 진단/시험은 진행하지 않는다. 다음 순서는 보정 거부 단계·클립·집계 진단(원본 음성 로그 제외) → 실제 정상 통과/적용 블록과 AAC 확인 → 볼륨 변경·취소/복귀 확인이다. 문턱을 임의로 낮추지 않는다. Jira는 S15P31E102-695, Story S15P31E102-33, 활성 스프린트 5(59321)의 진행 중을 유지하며 Push/MR은 하지 않았다.
15. **2026-11-11 사용자 재개 요청.** 동일 작업 브랜치 `8ff4bd9f`와 Jira 진행 중 상태를 확인했다. 먼저 판정 정책을 보존하면서 거부 분기·클립·구간·집계 수치를 구분하는 진단을 추가한다. 실기기 정상 거부인지 시각/입력 구성 오류인지 확인한 뒤 필요한 수정만 적용한다. 원본 음성은 진단 로그에 남기지 않는다.
16. `a98a36cb`·`ab4de8b9`에서 판정 정책을 보존한 거부 단계·집계와 입력/출력 시각 진단을 추가했다. 진단 회귀·두 실연 replay와 통합 focused 검사 통과, 깨끗한 실연의 처리 PCM SHA-256 불변, 독립 검토 finding 없음. 실제 볼륨 5에서 `Kung / RepeatMatchCount=1 < 3`이 확인됐다. 최소 quiet 여유 6,440프레임과 시각 차이 변동 10프레임으로, 의심한 50ms 구간 겹침은 이번 실패 원인이 아니었다.
17. 같은 앱·곡에서 볼륨만 8로 바꾼 비교는 보정 통과(최소 일치도 `.6654602`) 후 실제 녹음에서 384/673블록 감산·593,586샘플 저장·`Active` 종료를 확인했다. AAC 13.514초와 실제 저장 13.46초가 맞고 준비 구간 14.78초는 포함되지 않았다. 저음/전체대역 정합으로 바꾸면 기존 정상 실연도 실패하므로 문턱·정합 대역은 유지한다. 실패 안내에 장단이 작을 때 볼륨을 조금 올려 재확인하는 방법을 보완한다. 볼륨 변경 차단과 취소/복귀 검증은 이어서 수행한다.
18. 실제 보정 통과 후 녹음 중 볼륨 8→5 변경에서 ‘장단 보정 꺼짐’ 표시와 `Changed` 종료를 확인했다. 변경 전 67/158블록 적용, 총 591,822샘플 녹음·13.468초 AAC 정상 저장으로 녹음 지속을 확인했다. 완료 뒤 홈→같은 프로세스 복귀→새 보정 시작·취소도 통과했고, 마이크 스레드·활성 출력 트랙이 남지 않았다. 두 AAC는 기기/로컬 SHA-256을 대조했고 업로드하지 않았다.
