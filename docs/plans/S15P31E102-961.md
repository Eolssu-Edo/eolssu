## 1차 점검 방법과 한계 (2026-11-15)

- `feature/**`·`core/ui/**`의 화면 39개를 영역 4개(인증·프로필 / 곡·편집·홈 / 연습·결과 / 배우기·기록)로 나눠 코드를 읽어 점검했다. 사용자 예시 "토글을 누르면 눌림 배경이 직사각형으로 나타남"과 같은 상호작용 표시 문제를 우선했다.
- `clickable`·`toggleable`·`selectable`·`Surface(onClick)` 전부(약 110곳)를 앞뒤 modifier 순서와 함께 확인했다.
- 운영 웹(375×667)에서 로그인 화면만 직접 봤다. 로그인 후 화면과 실기기·iOS 화면은 아직 보지 않았다. 아래 항목은 모두 **코드 판독 결과**이며, `확인`은 코드상 반드시 생기는 것, `의심`은 기기에서 확인이 필요한 것이다.

## 공통 원인

- **R1. 눌림 효과가 모양대로 잘리지 않음.** Compose의 눌림 효과(ripple)와 웹 hover·키보드 focus 표시는 `clickable`이 걸린 영역의 사각형으로 그려진다. 둥근 모양을 `background(shape)`나 안쪽 박스로만 그리고 `clip(shape)`를 `clickable` 앞에 두지 않으면 사각형이 보인다. `Surface(modifier = Modifier.selectable(...), shape = …)`처럼 Surface 바깥 modifier에 클릭을 걸어도 같다. 테마에 ripple·indication 설정은 없다.
- **R2. 보이는 크기와 누르는 영역을 한 박스로 처리.** 48dp 터치 영역을 확보하려고 바깥 박스를 키우고 거기에 클릭을 걸어, 눌림 효과가 보이는 버튼보다 크게 퍼진다.
- **R3. Material 기본 컴포넌트가 테마를 거치지 않고 노출.** 앱 공통 컴포넌트(`EolssuButton`·`EolssuIconButton`·`EolssuMenuPanel`·`EolssuDialog`)와 모양·색·글꼴이 다르다.
- **R4. 맨 `clickable`의 터치 영역이 48dp 미만.** `Surface(onClick)`는 48dp로 자동 확장되지만, 맨 `clickable`은 그렇지 않다.

## 개선 방향 (구현 전 초안)

1. 공통 규칙 하나를 정한다: 보이는 모양에 `clip(shape)` → `clickable`, 터치 영역은 `minimumInteractiveComponentSize()`로 따로 확보한다. 둥근 버튼은 shape를 준 `Surface(onClick)`를 쓴다.

3. C는 앱 공통 컴포넌트로 교체한다. D는 1번 규칙으로 함께 해결한다.
4. E·F는 기기 확인이 필요한 `의심` 항목을 먼저 확인하고 고친다.
5. 결정 필요: A18 마이페이지 카드 줄 눌림 스타일, B1 홈 붓 버튼 눌림 표현, C7 드롭다운 방식 통일.
