| 계층 | 내용 |

## 결정과 스펙과의 차이

- Spring Bean으로 등록하지 않았다. 기본 실행은 DB 없이 뜨고(`BackendApplicationTests`), Mapper Bean은 `db` 프로필에만 있다. Mapper를 쓰는 Bean을 지금 등록하면 기본 기동이 깨진다. 어느 프로필에서 연결할지는 API를 붙일 때 정한다.
- 수신 시각 검사(스펙 R3)에도 구간 길이 검사와 같은 1초 반올림 여유를 뒀다. 앱이 구간을 닫자마자 보내면 반올림된 보인 시간이 수신 시각 − 시작보다 1초 미만으로 길 수 있어 정상 기록이 거절되기 때문이다. 스펙 반영이 필요하다.
- 곡 존재는 `songs` 행이 있는지만 본다. 숨김·삭제 표시된 곡의 기록도 받는다(오프라인에서 연습한 뒤 곡이 숨겨진 경우).
- 중복 키 뒤의 재조회는 잠금 읽기(`FOR SHARE`)로 한다. MySQL REPEATABLE READ에서 트랜잭션 안의 일반 조회는 처음 읽은 시점의 스냅샷을 봐서, 다른 요청이 커밋한 행을 찾지 못하고 500이 된다. 잠금 읽기는 커밋된 최신 행을 읽으므로 API 연결 때 서비스를 트랜잭션으로 묶어도 맞다(리뷰 발견 1).
- DATETIME 범위 밖 시각은 `TIME_OUT_OF_RANGE`(400)로 거절한다. 그대로 두면 저장 오류(5xx)가 되어 앱 대기열이 끝없이 다시 보낸다. 기간 계산 전에 검사해 아주 먼 시각의 `Duration.toMillis` 넘침도 막는다(리뷰 발견 2).
