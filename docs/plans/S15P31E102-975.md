# S15P31E102-975 연습 화면 태블릿 가로 악보 빈 공간과 설정 시트 높이 정리

- 브랜치: `fix(fe)/S15P31E102-975-연습-화면-태블릿-가로-악보-빈-공간과-설정-시트-높이-정리`, 기준 `origin/develop` `96122c9b`.

## 결정

- **설정 시트 유지**: `PracticeExpandedLayout` 주석은 보조 패널이 오른쪽 상태 패널 자리에 열린다고 적었지만, S15P31E102-518(`0445801f`)에서 배경을 눌러 닫기 위해 "모든 화면 크기에서 설정 시트"로 일부러 통일했다([518 계획](S15P31E102-518.md)). 도크로 되돌리지 않고 시트를 유지하며, 낡은 주석만 고쳤다.
- **시트 높이**: Expanded에서만 최대 높이를 창 높이의 45%(설정)·60%(하위 패널)에서 75%·80%로 올렸다. 1280×800에서 설정 시트가 약 330dp에서 약 550dp까지 커져 내용이 한 번에 보인다. 태블릿 세로는 45%·60% 그대로다.
- **악보 정렬**: 연습 악보(`JeongganboView`)는 이미 `Alignment.TopEnd`로 각을 오른쪽부터 그려 짧은 곡도 상태 패널 바로 옆(간격 24dp)에 붙는다. 운영 1440×765에서 본 왼쪽 빈 공간은 정렬 문제가 아니라 짧은 곡(5각 × 72dp)이 악보 칸(약 716dp)보다 좁아 생기는 남는 폭이다. 악보와 패널 묶음을 가운데로 옮겨도 빈 폭의 총량은 같고 패널이 상단 바 오른쪽 끝과 어긋나므로 코드를 바꾸지 않았다. 긴 곡의 가로 스크롤·자동 따라가기(S15P31E102-495)도 그대로다.

## 검증

- 자동(2026-11-16, develop `origin/develop` 병합 후): `:shared:testAndroidHostTest` 1,826개 중 실패 3·제외 5. 실패 3개는 `SheetAdaptationPersistenceTest`(hwangHz 소수 끝자리)로 깨끗한 develop에서도 같은 기존 실패이며 이번 변경과 무관하다. `:androidApp:assembleDebug`·`:webApp:wasmJsBrowserDistribution` 성공.
- 화면(웹 1280×800, 커밋하지 않은 임시 하네스로 `PracticeScreen`에 표본 곡 아리랑을 고정 상태로 그림):
    - 5각으로 줄인 짧은 곡: 악보가 상태 패널 바로 왼쪽에 붙고, 빈 폭은 악보 칸 왼쪽에 남는다.
    - 원래 길이 곡: 악보 칸을 채우고 가로 스크롤 시작 위치(오른쪽 끝)가 그대로다.
    - 설정 시트: 하네스 상태에는 연습 악기 카드가 없어 내용이 약 365dp로 시트 안 스크롤 없이 모두 보였다. 이 높이는 이전 상한(800 × 0.45 = 360dp)을 이미 넘어, 악기 카드가 붙는 실제 화면에서는 이전에 시트 안에서 스크롤됐을 내용이다. 실제 로그인 화면·태블릿 기기는 확인하지 않았다.
- 미확인: Android·iOS 태블릿 실기기, 로그인한 실제 연습 화면.
