## 범위와 완료 조건

서버에 비어 있던 개발·운영 Compose를 현재 Spring Boot 백엔드에 맞춰 작성한다. 사용자가 Nginx 프록시와 백엔드 Jenkins 파이프라인까지 포함하도록 선택했다. 환경변수 예시, Dockerfile, 빌드 컨텍스트 제외 규칙, 실행·검증 문서를 함께 제공한다.

Compose 해석, 이미지 빌드, 개발·운영 프록시 경유 HTTP, 백엔드 필수 검사와 전체 변경 검토를 수행하고 작업 단위로 커밋·Push한다. 운영 서버 배포·재시작, Jenkins 설치·잡 등록, DB·AI 서비스 추가는 이 작업에 포함하지 않는다.

2026-10-22 SSH 읽기 전용 점검에서 `/opt/app`의 `docker-compose.dev.yml`, `docker-compose.prod.yml`, `.env.dev`, `.env.prod`는 모두 0바이트였다. Docker Compose 프로젝트와 실행 중인 컨테이너가 없으며 Nginx·Jenkins 실행 파일도 확인되지 않았다. 서버 HEAD는 기준 커밋과 같았다. 기존 운영 설정을 복원한 것으로 취급하지 않는다.

개발·운영은 독립 Compose 프로젝트로 구분하고 예시 HTTP 포트는 8080/8081이다. 실제 공개 포트·도메인·TLS·DB는 미정으로 유지한다. 외부 접근은 기본 loopback으로 제한하고 백엔드 8080은 Compose 네트워크에서만 사용한다. Jenkins는 `develop`의 테스트·설정 검사·이미지 빌드·JAR 보관까지 수행하며 자동 배포는 구성하지 않는다. 블로그 파이프라인은 별도 잡으로 유지한다.
