## 후속 실행: develop 자동 빌드·테스트·배포

2026-10-22 사용자가 develop 병합 후 Jenkins의 자동 빌드·테스트와 서버 배포까지 연결하도록 승인했다. 같은 Task·Story·활성 스프린트·진행 중 상태와 MR !18을 재사용한다. 시작 시 원격 develop은 `9cae73dbbd155d71911d92b2e55356b4e9f93e55`, Jenkins 마지막 성공은 #2의 `23e1d26…`였다.

Jenkins의 loopback 접근을 유지하면서 SCM polling으로 develop을 1분마다 확인한다. 변경이 없으면 실행하지 않고, 변경 시 기존 검사와 이미지 빌드 후 격리된 후보 실행·HTTP 검증을 거쳐 백엔드 JAR만 배포한다. 같은 이미지에서 JAR을 추출해 기존 JRE+읽기 전용 bind mount 구성을 유지한다. 프론트와 MySQL 컨테이너·물리 볼륨·DB 값은 보존한다. 앱 소스·패키지·DB 이름은 수정하지 않는다.
