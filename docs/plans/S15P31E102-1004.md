# 악보 추가·편집 튜토리얼과 원본 대조 검수 방식 초안

- Jira S15P31E102-1004 · Story S15P31E102-319 · 팀 검토용
- 목표는 처음 쓰는 사람이 악보를 올리고 편집한 뒤, 확인이 필요한 칸을 찾아 인식 결과를 검수할 수 있게 하는 것이다.

## 튜토리얼 제안

| 화면 | 처음 열었을 때 안내할 순서 |
| --- | --- |
| 악보 올리기 | ① 정간보·오선보 중 올릴 악보의 종류를 고른다. ② 악기와 정간보 장단을 고른다. ③ 파일·갤러리에서 원본을 선택하고 업로드한다. |
| 편집 입력판 | ① 바꿀 정간이나 소박을 고른다. ② 율명·기호 입력판을 사용한다. ③ 실행 취소와 저장 위치를 확인한다. |
| 확인 카드 | ① 확인할 칸을 연다. ② 인식 결과를 확인하고 필요하면 수정한다. ③ 확인을 마치고 다음 칸으로 이동한다. |

각 안내는 해당 화면을 처음 쓰는 상황에서만 제안한다. 확인 항목이 없는 악보에서는 확인 카드 안내를 띄우지 않는다. 사용자는 중간에 건너뛰거나 화면의 다시 보기에서 같은 안내를 시작할 수 있다. 시김새와 구간 빠르기의 조작 설명은 1001의 화면별 안내를 사용한다.

팀에서 처음 봤다는 기록을 기기에서만 유지할지 계정에 동기화할지 정한다. 초안은 계정 저장을 추가하지 않고 기기별로 적용하는 방향을 제안한다. 다시 설치하거나 다른 기기에서 열면 안내가 다시 나올 수 있다.

## 원본 대조 후보

확인 카드에서 원본 쪽과 위치를 식별할 수 있을 때 해당 부분의 미리보기를 보여 주는 안을 검토한다. 원본 참조의 유무와 좌표 형식은 정간보·오선보 샘플에서 확인해야 한다. 편집으로 칸의 위치가 바뀌어도 참조는 인식 당시 위치를 가리킨다. 참조가 없거나 좌표의 일치를 검증할 수 없으면 미리보기 대신 기존 검수 흐름을 제공한다.

현행 업로드 원본은 변환 성공·실패 시 즉시 삭제하고 최대 30분만 보관한다. 근거는 [원본 수명 주기](../knowledge/backend/temporary-sheet-source-lifecycle.md)다.

| 후보 | 사용 경험 | 팀이 정할 사항 |
| --- | --- | --- |
| 사용자가 원본을 다시 선택 | 서버에 새 이미지 보관이 필요 없다. 사용자가 파일을 갖고 있을 때 대조할 수 있다. | 같은 판본임을 확인하는 방법과 플랫폼별 로컬 파일 접근 |
| 확인이 필요한 위치의 축소 이미지를 보관 | 변환 뒤에도 확인 카드에서 바로 대조할 수 있다. | 보관 목적·기간, 용량 상한, 소유자 전용 접근, 개별 삭제·탈퇴 처리와 고지 |

보관 합의 전에는 원본 재선택 방식으로 사용 흐름을 검토한다. 축소 이미지 보관안을 선택하면 악보당 용량 상한과 보관 기간을 정하고, 다쪽 악보 한 건으로 위치 정확도와 저장량을 측정한다.

## 합의 후 구현 작업 후보

1. 화면별 튜토리얼 · 최초 진입, 건너뛰기, 다시 보기, 확인 항목이 없는 경우를 검증한다.
2. 원본 좌표 검증 · 정간보·오선보의 다쪽 입력에서 확인 카드와 원본 쪽·영역의 대응을 확인한다.
3. 원본 대조 UI · 참조가 있는 칸과 없는 칸, 편집 후 위치 변경, 만료 또는 파일 재선택 흐름을 확인한다. 이미지 보관을 선택했을 때만 저장·권한·삭제 작업을 별도 계획한다.
