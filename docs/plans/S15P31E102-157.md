## 목적

AI 채점 함수 `score()`가 백엔드가 보내는 채점 요청(PRA-03 `notes`)을 그대로 받아, 쉼을 지키며 채점하고 결과를 요청의 음 번호(`idx`)로 돌려주게 한다. 기준음은 황 = E♭4(311.13Hz)로 고정한다.

## 기준과 범위 밖

- PRA-03 스펙 `docs/specs/practice-analysis-failure.md` 80~93행: 요청 `notes: [{idx, semitone, beats, sigimsae}]`, 결과 `idx`는 요청과 같아야 한다. 백엔드 `HttpAnalysisClient`가 이를 검사한다.
- 공통 악보 데이터(S15P31E102-156): 시간은 정수 틱, `beats = durationTick / ticksPerBeat`, 반음 번호는 `data/reference/pitches.json`(황 = 0).
- **범위 밖:** HTTP API `POST /v1/analyses`(S15P31E102-212, 우동균), 백엔드가 `score_json`을 음표로 푸는 일(`PracticeScoreNotes`), 박자 판정 방식 변경(팀 합의 뒤, 박자 실험 Task에서 근거 마련).

### U1 쉼과 음 번호

- 기대 음 곡선은 지금 `starts = cumsum(beats)`로 만든다(`scoring.py:117-118`). `start_beat`가 있으면 `starts = start_beat − 첫 음 start_beat`로 바꾸고, 음이 없는 프레임은 소리 없음으로 둔다. DTW에서 소리 없음 기대와 소리 남 측정은 지금 `_UNVOICED_COST`(300센트)를 쓴다.
- 완료: (1) `start_beat` 없는 기존 테스트가 그대로 통과, (2) 쉼이 낀 합성 연주를 정확히 불면 TIMING이 0개, (3) 같은 연주를 `start_beat` 없이 채점하면 쉼 뒤 음이 TIMING이 되는 차이를 테스트로 보인다, (4) 결과 `idx`가 요청 `idx`(예: 3, 7, 12)와 같다.

### U3 보정 상한

- 식: `min(tol.max_tuning_cent, 최소 간격 − tol.pitch_cent − 10)`. 최소 간격 = 곡에 나오는 서로 다른 반음 번호의 최소 차이 × 100. 음이 하나뿐이면 상한 그대로.
- 완료: 단소 다섯 음 곡은 100, 반음 이웃(예: 반음 0·1)이 있는 곡은 40. 이웃 음을 잘못 분 합성 연주가 보정 뒤에도 PITCH인지 확인.

### U5 아리랑 끝까지

- 입력: `data/tests/fixtures/scores/ngc-standard-2022-p173.score.json`(156 샘플). NOTE 이벤트마다 `idx`(음 순번), `semitone`(율명 표), `beats`·`startBeat`(틱 ÷ 박당 틱)를 만든다. 이 변환은 백엔드가 할 일을 테스트 안에서 흉내 내는 것이고 AI 코드에 넣지 않는다.
- 완료: 만점, 음 바꿈 → PITCH, 0.2박 지연 → 그 음만 TIMING, 한 음 빼기 → MISSED. 결과 `idx`가 요청과 같다.
