## 검증 계획

Windows에서는 iOS를 컴파일할 수 없다. 이 PC에서는 공통·Android 회귀(`:shared:testAndroidHostTest`, `:androidApp:assembleDebug`)만 확인하고, 아래는 Mac·iPhone에서 수행한다.

1. `./gradlew :shared:compileKotlinIosSimulatorArm64 :shared:iosSimulatorArm64Test`
2. Xcode에서 `iosApp` 빌드·시뮬레이터 실행(Team 선택 필요)
3. 실제 iPhone: 마이크 권한 허용·거부·설정에서 해제 후 재진입, 평가 연주 녹음→업로드→분석 결과, 받은 파일 `ffprobe`(AAC·모노·샘플레이트·비트레이트), 10분 자동 정지, 일시정지·이어 연주, 백그라운드 전환·전화 수신 중 녹음, 업로드 실패 후 앱 재시작·재전송
4. 모범 연주: 재생·일시정지·속도 변경·위치 이동·끝까지 재생·이어폰 분리·다른 앱 소리로 중단
5. Xcode Organizer의 Privacy Report로 매니페스트 경고 확인

## 결정

- 오디오 세션 공유(`IosAudioSession`): iOS는 앱 전체가 `AVAudioSession` 하나를 쓰고, 세션을 끄면 그 위의 녹음도 멈춘다. 재생기의 `stop()`은 비동기라 평가 녹음 시작 뒤에 처리될 수 있으므로, 녹음 중에는 재생기가 세션을 켜거나 끄지 못하게 했다. 녹음 중 재생 요청은 Interrupted가 된다.
- 녹음 세션은 PlayAndRecord·측정 모드·스피커 출력이다. 측정 모드로 음성용 자동 음량 조절을 줄이고, 녹음 중 메트로놈·안내음(`IosSoundPlayer`)도 나게 한다.
- 입력 크기는 `peakPowerForChannel`(dBFS)을 Android와 같은 -50dB~0dB 범위로 옮긴다. 실제 단소·대금 소리에서 '입력 없음' 판정이 맞는지는 실기기에서 확인한다.
- 개인정보 매니페스트: 추적 없음, 수집 항목은 코드에서 확인한 이메일(가입·로그인)·사용자 ID(닉네임 포함, Apple 분류상 화면 이름은 User ID)·녹음(평가 업로드)·기타 사용 데이터(연습 기록·연습 시간·평가 결과)이며 모두 앱 기능 목적·계정 연결이다. 팀이 App Store Connect 라벨을 정할 때 같은 항목인지 확인한다. 필수 사유 API는 UserDefaults(CA92.1, `IosKeyValueStore`), 파일 정보(C617.1, 녹음 파일 크기), 부팅 시간(35F9.1, 경과 시간 측정)이다. App Store Connect 라벨과 Xcode Privacy Report로 대조해야 한다.
