# S15P31E102-1252 문의 API 추가 뒤 실패하는 OpenAPI 엔드포인트 개수 검사 바로잡기

- [Task](https://ssafy.atlassian.net/browse/S15P31E102-1252)는 우동균 담당, Epic S15P31E102-14 소속, 활성 스프린트 5 배정, Story S15P31E102-1191과 relates로 연결했다(2026-11-22 생성).
- 시작 기준은 `origin/develop` `adb10112c`다. 범위와 완료 조건은 Task 본문을 따른다.

## 원인

- Jenkins `eolssu-backend`는 #3608까지 SUCCESS였고, #3609(11-22 10:49 UTC)부터 `Backend database tests` 단계의 `:databaseTest`가 실패해 UNSTABLE이 이어졌다. 이 단계는 `catchError`라 배포는 계속 진행됐다.
- #3616 테스트 리포트 기준으로 360개 중 2개가 실패했다. `OpenApiDatabaseTests`와 이를 `ops` 프로필로 상속한 `OpenApiOpsDatabaseTests`의 `definition covers every implemented method with schemas errors and cookie security()`이며, 둘 다 `expected: <81> but was: <82>`였다.
- 이 테스트는 `com.ssafy.eolssu.backend.feature.` 패키지의 핸들러 메서드 수를 숫자로 고정해, 엔드포인트를 추가하면 개수와 OpenAPI 계약을 함께 점검하게 한다.
- #3609에 처음 들어온 `e8a9f8015`(S15P31E102-1240)가 `POST /api/users/me/inquiries`를 추가해 82개가 되었다. 같은 커밋이 `OpenApiContracts.kt`에 계약을 넣었으므로 OpenAPI 정의는 맞고, 테스트의 고정값만 갱신되지 않았다.

## 수정

- 기대값을 82로 바꾸고, 문의 경로가 실제 핸들러 목록에 있는지 확인하는 단언을 추가했다. S15P31E102-823에서 최근 연주 API를 추가할 때와 같은 방식이다.
- API·OpenAPI 계약·운영 설정은 바꾸지 않았다.

## 검증 (11-22)

- 로컬 Windows에는 `infra/jenkins/run-database-tests.py`의 `signal.pthread_sigmask`가 없어 래퍼가 그대로는 실행되지 않는다. scratchpad 실행 스크립트로 그 호출만 무동작으로 바꾸고, 같은 `mysql:8.4.13` 일회용 컨테이너 설정으로 실행했다.
- 수정 전 테스트 파일로 `databaseTest --tests '*OpenApi*'`를 실행하면 12개 중 같은 2개가 `expected: <81> but was: <82>`로 실패해 Jenkins 결과를 재현했다.
- 수정 뒤 전체 `databaseTest`는 360개 중 실패 0개, 건너뜀 7개(Jenkins #3616과 같은 수)로 `BUILD SUCCESSFUL`이었다. 두 테스트는 모두 통과했다.
- 원인 기능의 `InquiryConfigTests` 3개와 `InquiryControllerTests` 6개도 `test`에서 통과했다. 운영 코드는 바꾸지 않았으므로 문의 기능 동작은 그대로다.
- 일회용 컨테이너는 실행 뒤 남지 않았다. 병합 뒤 Jenkins `eolssu-backend`가 SUCCESS로 돌아오는지는 아직 확인하지 않았다.
