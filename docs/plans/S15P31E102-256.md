- 기준 `origin/develop` fd8323d. 수동 coco-build; 구현·검증·커밋까지, 리뷰·Push 미선택.
- 계약: [곡·평가 조회](../specs/practice-read-apis.md). 숫자 곡 ID와 기존 schemaVersion 1 악보를 그대로 전달한다.

## 순서와 검증

1. 게시·미삭제 곡 목록·상세의 MockMvc 검사를 실패부터 확인한다.
2. 기존 MyBatis Mapper에 공개 조회만 추가한다. 기존 내부 findById 의미는 보존한다.
3. 실제 MySQL에서 게시·비공개·삭제 제외와 JSON·장단 연결을 확인한다.
4. `./gradlew clean build`, `./gradlew databaseTest` 뒤 자체 점검·작업 단위 커밋. 독립 리뷰와 운영 검증은 별도다.

## 진행

- 구현: 공개 곡 목록·상세, 원본 score_json 객체와 장단 제공. 기존 내부 findById·보안 정책·DB 스키마는 보존했다.
- 실패 확인: SongControllerTests 2개가 빈 목록·상세 404 때문에 실패한 뒤 구현 후 통과.
- `clean build`: 기본 테스트 311개 통과. `databaseTest`: MySQL 8.4.9의 폐기 전용 pra_api_test에서 94개 통과. 첫 전체 DB 실행은 여러 Spring 컨텍스트의 합산 연결이 기본 151개를 넘어 실패했고, 임시 서버만 max_connections=500으로 바꾼 뒤 통과했다.
- 실제 임의 포트 HTTP로 공개·비공개·삭제 필터, 원본 JSON 동일성·정렬·없는 곡 404, Swagger 계약을 확인했다. 운영 서버 검증은 수행하지 않았다.
- 자체 점검: 추적·미추적 소스·SQL·테스트·문서 범위 전체, 비밀값·무관한 파일 없음. 형식·외부 계약 의미 변경 없음. 독립 리뷰 대기.
- 메인 체크아웃의 -80 미커밋 문서는 이 worktree에 포함하지 않았다.
