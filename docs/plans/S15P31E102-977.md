# 성장 화면 태블릿 가로 두 칸 최소 높이 조정

[Jira S15P31E102-977](https://ssafy.atlassian.net/browse/S15P31E102-977) · 조사 근거 S15P31E102-960(표 3번)

## 문제

`GrowthExpandedLayout`의 두 칸 최소 높이 680dp가 1280×800 태블릿 가로에서 실제 남는 높이(상태·내비게이션·상단 바를 빼면 약 640dp)보다 컸다.
그래서 두 칸 보드 전체가 약 40dp 쓸데없이 스크롤됐다.
680은 S15P31E102-795에서 "오른쪽 연습량 달력 6줄 기준"으로 넣은 값이고, 따로 측정한 근거는 남아 있지 않다.

## 결정

- 최소 높이를 600dp로 낮춘다.
  달력 카드에서 가장 높은 경우(6주 달, 기록 있는 날 상세)를 코드의 고정 크기로 더하면 카드 약 578dp, 위아래 여백 28dp를 더해 약 606dp다.
- 내용이 칸보다 길면(6주 달 + 기록 상세, 큰 글꼴 배율) 오른쪽 달력 칸만 따로 세로 스크롤한다.
  예전처럼 680으로 모든 달에 여유를 주는 대신, 드문 경우에만 칸 안에서 스크롤하고 1280×800에서는 보드가 화면에 맞는다.
- 창이 600dp보다 낮으면(분할 화면 등) 지금처럼 보드 전체를 세로로 스크롤한다.
- Compact·Medium 배치, 상태, ViewModel, 성장 데이터 표시는 바꾸지 않았다.
  높이 계산은 `coerceAtLeast` 한 줄이라 따로 순수 함수로 빼 테스트하지 않았다.

## 검증

- `:shared:testAndroidHostTest`(최신 develop 병합 후): 1,826개 중 3개 실패, 5개 건너뜀.
  실패 3개는 모두 `SheetAdaptationPersistenceTest`(악보 편집)의 `hwangHz` 부동소수 끝자리 차이로, 이번 변경과 관계없다.
  깨끗한 develop에서도 같은 3개가 실패함을 다른 세션에서 확인해 develop에 이미 있던 실패로 본다.
- `:androidApp:assembleDebug`: 성공.
- 화면 확인: 미검증.
  성장 화면은 로그인과 기록 API가 필요하고, 이번 작업에서 고정 상태 하네스는 만들지 않았다.
  1280×800 기기·에뮬레이터에서 두 칸이 페이지 스크롤 없이 보이는지, 6주 달에 기록 있는 날을 골랐을 때 달력 칸만 스크롤되는지 확인이 남았다.
