# S15P31E102-967 구간 연습 구간 선택 화면 태블릿 가로 두 칸 배치

- Jira: S15P31E102-967 · Story S15P31E102-109 · 활성 스프린트 59321 · 진행 중.
- 근거: 태블릿 가로 화면 조사(960)의 1순위 항목. 1440×765 운영 화면의 `#weak/<recordId>/sections`가 560dp 휴대폰 폭 한 줄로 쌓여 정간보가 4각만, 낮은 높이로 보이고 양옆이 비었다.
- 범위: `feature/practice/SectionSelectScreen.kt`의 Expanded(840dp 이상) 배치만 바꾼다. Compact·Medium 배치, 상태·ViewModel, 구간 선택·추천 구간 동작은 그대로 둔다.

## 결과

- Expanded에서 상단 바와 본문을 `WindowBreakpoints.ContentMaxWidth`(1120dp)로 넓힌다.
- 왼쪽 380dp 칸에 틀린 종류 탭·안내 줄(‘취약 구간 보기’ 포함)을 두고, 같은 칸 아래에 ‘구간 연습 시작’·‘구간 재평가 시작’을 나란히 둔다. 버튼은 칸 너비를 넘지 않고 하단 고정 바는 쓰지 않는다.
- 오른쪽 칸은 정간보가 남은 너비와 전체 높이를 쓴다.
- 비교 화면(966)과 나눠 쓸 만큼 작은 공용 도우미가 없어 `core/ui`에 새 코드를 두지 않았다.

## 검증

- `:shared:testAndroidHostTest` 기존 실패 3개: 모두 `SheetAdaptationPersistenceTest`(악보 편집 저장)의 `hwangHz` 마지막 자리 부동소수점 차이다. 변경 없는 develop `96122c9b`에서도 같은 3개가 실패해(비교 화면 Task 966 확인) 이 Task에서 고치지 않는다.
- 최신 develop(`57233532`)을 병합한 뒤 한 번에 실행: 위 기존 실패 3개 외 전체 통과(1,826개 중 제외 5), `:androidApp:assembleDebug`·`:webApp:wasmJsBrowserDistribution` 성공.
- 화면 확인(웹 배포본, 커밋하지 않은 임시 하네스로 예시 곡·예시 오류·추천 구간 고정 상태의 `SectionSelectScreen`을 그림):
    - 1280×800: 왼쪽 칸에 탭·안내·두 버튼(칸 너비 안), 오른쪽에 정간보 8각이 보인다. 이전 560dp 폭은 4각이었다.
    - 같은 크기에서 정간 두 번 누르기로 시작·끝 선택, 선택 중 버튼 비활성·끝난 뒤 활성을 확인했다.
    - 375×812(Compact): 기존처럼 세로로 쌓이고 두 버튼은 아래 고정 바에 있다.
- 미확인: 실제 로그인 계정의 운영 데이터 화면, Android 태블릿 실기기·iOS.

## 남은 일

- 정간보는 기존 읽기 형식대로 한 줄에 각을 가로로 놓아, 1280×800에서 칸 아래쪽이 비어 있다. 짧은 각을 위아래로 쌓아 높이를 채우려면 악보 표시 형식을 바꿔야 해 이 Task 범위에 넣지 않았다.
