# S15P31E102-1039 내 악보 음원 생성 중 상태 표시

- 작업: `S15P31E102-1039` · Story `S15P31E102-319`
- 범위: 내 악보 연습(native) 화면의 음원 상태 표시. 서버 API·음원 생성 로직, 내 악보 목록 줄, Web 재생 UI는 제외.

## 원인

- 연습 화면은 열 때 기기 파일만 확인했다. 편집기 등에서 요청한 생성이 서버에서 QUEUED·RUNNING이어도 `음원 다운로드` 버튼을 띄워 준비되지 않은 것으로만 보였다. 화면을 떠났다 돌아와도 같았다.

## 변경

- `SheetPracticeRepository.generationStatus`: 기기 파일이 없을 때 SHT-13으로 이 확정 판본의 생성이 진행 중인지와 그 상태를 본다. 설정(악기·빠르기)은 보지 않는다.
- `download(resume = true)`: SHT-12를 다시 보내지 않고 진행 중인 생성만 기다린다. 끝난 음원이 연습 설정과 다르거나 기다릴 생성이 없으면 `NotStarted`로 다운로드 버튼에 돌아간다. 생성 실패는 기존처럼 `다시 시도`다. `onStatus`로 대기·생성 상태를 화면에 넘긴다.
- 표시(사용자 확정 문구): 버튼 자리(52dp)에 테두리 카드 + 회전 표시 + 한 줄 문구. 서버 QUEUED `음원 생성 대기 중`, RUNNING·요청 직후 `음원 생성 중`, 기기 저장 `음원 다운받는 중`. 막대 아래 설명 문장과 경과 시간은 넣지 않는다. 서버가 진행률·대기 순번을 주지 않아 %는 표시하지 않는다.

## 검증

- `PracticePersonalAudioTest`: 열 때 대기→생성→저장(요청 없음), 재진입 후 이어서 대기, 다른 설정으로 끝남 → 다운로드 버튼, 실패 → 다시 시도, 기기 파일 삭제 → 다운로드 버튼 후 복구, 편집(판본 1→2) 후 옛 판본 파일 무시·새 판본 생성·저장·재생, 편집 후 새 판본 생성 중이면 대기. 전체 Android host 1,926건 통과(기존 skip 5), APK·Wasm 컴파일 성공.
- 에뮬레이터(Eolssu_QA911_S10_API37, API37)와 저장소 밖 일회용 loopback fixture로 실제 앱을 확인했다. 운영 API·계정은 쓰지 않았다.
  - 생성 중 진입: `음원 생성 중` 회전 카드 → 완료 후 자동 저장 → 재생 버튼. SHT-12 요청 0건.
  - 기기 파일 삭제(`run-as`로 M4A 삭제) 후 재진입: `음원 다운로드` → 누르면 서버의 현재 판본 DONE을 다시 받아 재생 버튼. 새 생성 없음.
  - 편집(확정 판본 2→3) 후 진입: 기기의 판본 2 파일을 쓰지 않고 `음원 다운로드` → 누르면 `음원 생성 대기 중` → `음원 생성 중` → 재생 버튼. 저장 메타데이터 판본 3으로 교체.
  - `음원 다운받는 중`은 작은 파일이라 너무 짧아 화면으로 잡지 못했다(자동 테스트로 확인).
- 실기기·iOS·운영 API 확인은 하지 않았다.
