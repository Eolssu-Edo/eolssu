## 범위와 완료 조건

- SHT-08 내 악보 편집 진입 시 서버 문서와 저장 초안을 복원한다. 로딩·실패 상태에서는 예시 악보를 표시·저장하지 않는다.
- SHT-11 임시·자동 저장은 baseScoreVersion/draftRevision으로 순서를 지킨다. 확정 저장 SHT-04는 서버 성공 후에만 완료 표시한다. 충돌 시 현재 편집을 보존하고 자동 재요청하지 않는다.
- 원본의 가변 각 길이·정간 내부 row/col·가사·시김새·이벤트 연결·tick 단위를 보존한다. 수정하지 않은 표기를 평탄화하지 않는다. 편집으로 위치가 바뀌면 공통 스키마의 위치 ID를 함께 갱신한다.
- 서버 악보 ID로 기존 SHT-12·13을 재사용한다. 계정 변경 시 문서·초안·음원 작업과 화면 자료를 폐기한다.
- 파일 업로드의 장단 선택은 사용자 보류 결정 유지. 취소된 SHT-03 생성 API와 새 파일 선택 경로를 추가하지 않는다. PRA-06 실제 판정기 연결은 별도 다음 범위.
- 사용자 결정(2026-11-06): 서버 악보는 정간보 편집·저장을 먼저 연결하고 오선보 변환 확장은 후속으로 분리한다. 서버 문서를 로드한 편집기는 정간보로 열며 오선보 전환을 노출하지 않는다. 기존 예시 흐름의 오선보 보기와 원본 데이터는 보존한다.

## 순서와 검증

1. 조회·초안·확정 저장 HTTP 계약과 409/오류 응답 집중 테스트.
2. 공통 악보 ↔ 편집 상태 보존·수정·빈 정간·가변 각·분할·이음·가사 테스트.
3. ViewModel의 실제 조회·복원·저장·경합·계정 변경 및 화면 로딩/재시도 연결.
4. Android host suite / APK / Wasm 컴파일. 가능한 에뮬레이터 화면 검증. 실서버 자료 쓰기·iOS·실기기 미확인은 구분.
