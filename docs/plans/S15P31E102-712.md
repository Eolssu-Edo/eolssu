# edo1·edo2 운영 로그 중복과 증가량 줄이기

[작업 S15P31E102-712](https://ssafy.atlassian.net/browse/S15P31E102-712) · [운영 모니터링 Story](https://ssafy.atlassian.net/browse/S15P31E102-41) · 스프린트 5

## 독립 HTTPS 점검

- edo1에서 기존 타이머 주기와 TLS·HTTP·JSON 검증을 유지한다. 최근 검사 시각과 각 대상의 판정·고정 상세는 기존 `latest.json` 형식으로 매번 원자적으로 갱신한다.
- `relay`와 `terms`의 직전 판정을 각각 비교한다. 첫 성공과 같은 판정의 반복은 조용히 처리한다. 직전 판정이 없거나 정상이었고 실패하면 장애 시작을, 직전 실패 후 정상이면 복구를 한 줄씩 기록한다. 로그에는 시각, 대상, 이벤트, 고정 상세만 남긴다. 상태 갱신에 실패하면 서비스 실패가 드러나야 한다.
- 정상 반복, 한 대상만 실패, 실패 상세 변경, 복구와 재발에서 상태 파일과 로그 수를 검사한다. 기존 수집기가 새 파일을 읽어 정상과 장애를 표기하는지 검사한다.
- 원격 기본 브랜치 `develop`의 `06bec0ba`에 독립 점검이 없어서 709의 독립 타이머 원본 커밋만 선행 커밋으로 재사용한다. 709의 보고서 소비자와 호환을 별도 검증한다.

## 전체 운영 로그 검토

두 호스트의 journald, Nginx 접근·오류, 앱 syslog, Docker 컨테이너와 Jenkins 로그를 용량·증가율·회전·보존 기준으로 집계한다. 앱 일반 로그의 최대 14일 정책과 오류 진단 기록을 유지한다. 중복 확인과 검증이 끝난 변경만 구현하고, 실제 운영 적용은 배포 권한과 별개로 기록한다.
