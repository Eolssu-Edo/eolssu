## 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 구현이 없는 플랫폼 | `AudioRecorder`·`MicPermission`은 플랫폼 모듈에 구현이 있을 때만 등록하고, 연습 화면은 `getOrNull()`로 받는다. 없으면 지금처럼 녹음 없이 진행만 하고 입력 크기를 흉내 낸다 | iOS는 송가연이 구현하고 웹 녹음은 범위 밖이다. 배포 중인 웹의 연습 흐름을 깨지 않는다 |
| 10분 정지 | 플랫폼 기능(`setMaxDuration`)이 아니라 공통 코드의 `RecordingClock`으로 실제 녹음된 시간을 재고 10:00에 연주를 마친다. 일시정지한 동안은 세지 않는다 | iOS도 같은 규칙을 그대로 쓴다. 시계는 `TestTimeSource`로 단위 테스트한다 |
| 10분에 닿았을 때 | 곡 끝에 닿은 것과 같게 '연주를 마쳤어요' 창을 띄운다 | 지금 예시 곡은 가장 느린 속도에서도 10분보다 짧아 실제로는 거의 생기지 않는 안전장치다. 별도 안내 문구는 화면 설계가 생기면 정한다 |
| 일시정지 | '연주 중단' 확인 창과 '계속 연주' 카운트다운 동안 녹음을 일시정지하고, 이어 연주할 때 같은 파일에 이어 녹음한다 | 악보 위치도 멈춘 자리부터 이어 가므로 녹음과 악보 시간이 맞는다 |
| 버리는 녹음 | 끊긴 연주(앱 이탈), 처음부터 다시, 나가기, 연습 준비로 돌아가기에서 진행 중인 녹음을 지운다. 마친 녹음 하나는 캐시의 `recordings/`에 남기고 다음 녹음을 시작할 때 지운다 | 업로드가 아직 없다. 보관·다시 보내기는 업로드 작업에서 정한다 |
| 마이크 권한 | 앱 안의 '허용'과 OS 권한이 모두 있어야 녹음한다. 첫 실행 마이크 안내와 연습 화면 마이크 안내의 '허용'·'계속'에서 OS 권한 창을 띄우고, 거부하면 '허용 안 함'·'나중에'와 같게 처리한다 | S15P31E102-165의 '첫 실행에서 허용했으면 연습 화면에서 다시 묻지 않는다'를 지키려면 첫 실행에서 OS 권한까지 받아야 한다 |
| Android 입력 | `AudioSource.VOICE_RECOGNITION`, 모노·AAC·128kbps·44.1kHz | `MIC`는 기기에 따라 잡음 제거가 켜져 길게 부는 관악기 소리를 줄일 수 있다. Android 호환성 정의는 `VOICE_RECOGNITION`의 잡음 제거·자동 음량 조절을 끄도록 한다 |
| 입력 크기 표시 | `maxAmplitude`를 dBFS로 바꿔 -50dB 이하를 0(입력 없음)으로 보고 0.1초마다 갱신한다 | 기존 화면은 0일 때만 '입력 없음'을 보인다 |

## 검증

2026-10-28, Windows 11, `frontend/`에서 실행.

- `./gradlew :shared:testAndroidHostTest :shared:jsTest :shared:wasmJsTest :androidApp:assembleDebug :webApp:wasmJsBrowserDistribution --console=plain`: 성공. 세 타깃 합계 561개 테스트 통과(새 `RecordingClockTest` 4개, `PracticeStateTest` 추가 2개 포함). iOS는 Windows에서 컴파일할 수 없어 확인하지 않았고, 이번 변경에는 iOS 코드가 없다.
- Android 에뮬레이터 `Medium_Phone_API_37.0`(Android 17, 1080×2400), 호스트 마이크 입력 켬(`adb emu avd hostmicon`). 디버그 APK를 설치해 아리랑(60BPM, 0:48)으로 확인했다.

| 확인 | 결과 |
| --- | --- |
| 첫 실행 마이크 안내 '허용' | OS 권한 창이 뜨고, 허용하면 OS 권한 `granted=true`와 앱 `mic_granted=true`가 함께 남는다. 연습 화면에서 안내 창 없이 바로 카운트다운 |
| 첫 실행 '허용 안 함' → 연습 화면 '계속' | 연습 화면 마이크 안내 → OS 권한 창 → 허용하면 바로 녹음 시작 |
| OS 권한 회수(`pm revoke`) 뒤 연주 평가 | 연습 화면 마이크 안내가 다시 뜬다. OS 권한 창에서 거부하면 곡 정보로 돌아가 '마이크를 허용해야…' 안내 |
| 곡 끝까지 녹음 | ffprobe: `aac`, 44,100Hz, 1채널, 48.79초(곡 0:48) |
| 연주 중단 창 8초 + 이어 연주 카운트다운 | 멈춘 동안 파일 크기가 248,993바이트로 그대로. 마친 파일 49.02초로 멈춘 시간이 들어가지 않음 |
| '평가하기' | 녹음 파일이 남는다. 다음 연주를 시작하면 지워진다 |
| 연주 중 홈 버튼 | 진행 중이던 녹음 파일이 지워지고 '연주가 중단되었어요' 창 |
| 10분 자동 정지 | 곡 끝에서 처음으로 돌아가도록 임시로 고친 빌드(커밋하지 않고 되돌림)로 확인. 시작 10분 뒤 '연주를 마쳤어요' 창이 스스로 뜨고, 파일은 `aac`·44,100Hz·1채널·**600.07초**·7,308,157바이트. 서버 길이 상한(601.0초 미만) 안이다 |

- 에뮬레이터 녹음에는 소리가 거의 없었다(10분 파일과 49초 파일 모두 평균 -79dB 수준). 그래서 입력 크기 표시는 '입력 없음'으로만 보였다. 무음에 가까운 입력이라 실제 비트레이트는 약 96kbps였다.

### 실기기

2026-10-28, 갤럭시 S10(SM-G973N, Android 12, API 31), USB 디버깅으로 같은 디버그 APK 설치. 권영민이 직접 조작했다.

| 확인 | 결과 |
| --- | --- |
| 첫 실행 마이크 안내 '허용' | OS 권한 `granted=true`, 앱 `mic_granted=true` |
| 아리랑 연주 평가 녹음 | ffprobe: `aac`, 44,100Hz, 1채널, 48.13초, 780,632바이트, 약 130kbps(요청한 128kbps와 일치) |
| 소리 크기 | 평균 -39.2dB, 최대 -4.6dB로 소리가 실제로 녹음되었고 잘림(0dB) 없음. 2초 단위 RMS가 -31~-47dB로 움직였다 |

- 10분 자동 정지, 일시정지·이어 녹음은 실기기에서 다시 하지 않았다(에뮬레이터 결과만 있음).
- 녹음 파일로 서버 채점까지 이어 보지는 않았다. 업로드가 아직 없다.
- 같은 거부가 반복돼 Android가 '다시 묻지 않음'(`USER_FIXED`)으로 바꾼 뒤에는 '계속'을 눌러도 OS 권한 창 없이 바로 거부로 처리된다. 아래 남은 일의 설정 화면 안내가 필요한 경우다.

## 남은 일

- iOS: `AVAudioRecorder` 등으로 `AudioRecorder`·`MicPermission`을 구현해 `iosPlatformModule`에 등록하고, `Info.plist`에 `NSMicrophoneUsageDescription`을 넣는다(송가연).
- Android에서 권한을 '다시 묻지 않음'으로 거부한 경우 설정 화면으로 안내하는 흐름은 없다. 지금은 '마이크를 허용해야…' 안내만 뜬다.
- 실기기 녹음 품질(입력 방식별 차이)은 확인하지 않았다.
