- 범위: 이전 세션 선택, 비교 대상 없음 200, 응답 모양 교체, BPM이 달라도 비교, 악보 버전이 다르면 오류 수 비교 불가.
- 범위 밖: `/v1/analyses` 변경, 부분 점수 저장·Flyway, 구간 점수 합산, FE 연결. AI 합의와 Task가 없어 점수 비교는 하지 않고 `scoreComparable=false`, `NO_NOTE_SCORES`로 둔다.

## 결정

명세에 적히지 않은 경계를 다음처럼 정했다. 2026-11-05 노션 EVA-04에 반영했다.

- 첫 연주 응답: `scoreComparable`·`errorComparable`·`bpmChanged`는 false, `notComparableReasons`는 `[]`다. 사유 코드는 비교 대상이 있는데 비교하지 못하는 이유만 나타낸다.
- `parentSessionId`의 세션을 본인 소유로 찾지 못하면(기록 삭제 등) 직전 세션으로 넘어간다. 찾으면 `baselineSource=PREVIOUS`, 없으면 200과 null이다. 명세의 404는 지정한 이전 세션 기준이고 parent는 사용자가 지정한 값이 아니다. 원본 기록을 지웠다고 재평가 기록의 비교가 404가 되면 앱이 목록으로 이동한다. 리뷰 후 사용자 승인으로 처음의 404 유지를 바꿨다. 명시한 `baselineSessionId`의 404, 찾은 parent가 다른 곡·미완료일 때의 400·409는 그대로다.
- 악보 버전이 다른 세션은 ③에서도 구간 포함을 보지 않는다. 다른 판본의 구간 번호는 다른 음을 가리키므로 310의 QUERY·PARENT 처리와 같게 했다. 그 세션이 가장 최근이면 고르고 `SCORE_VERSION_CHANGED`로 알린다.
- 시작 시각이 같으면 id가 작은 쪽을 먼저 시작한 세션으로 본다. 정렬 기준(`startedAt`·`sessionId` 내림차순)과 맞춘 것으로, 두 세션이 서로를 직전 세션으로 고르지 않는다.
- 채점 모델이 달라도 `errorComparable=true`이고 `delta.errorCount`를 준다(명세: 악보 버전만 조건). 1차에서 null이던 값이 바뀐다.
- `before`·`delta`는 비교 대상이 있으면 객체를 유지하고 안의 값만 null이다. 1차의 `delta` 전체 null과 다르다.
- `scoreComparable`은 도메인 결과의 고정값 false다. 부분 점수를 저장하면 조건으로 바꾼다.

## 검증

- 2026-11-05, 임시 MySQL 8.4(`--max-connections=400`). 테스트를 새 계약으로 먼저 바꿔 컴파일 실패를 확인한 뒤 구현했다.
- `./gradlew clean build databaseTest --continue`: 일반 테스트 594개 통과, MySQL 테스트 231개 중 3개 실패·1개 건너뜀.
- 실패 3개는 모두 이번에 추가한 테스트 코드 문제였다. 시드 없는 악보 버전 0이 `chk_practice_sessions_score_version`에 걸려 2로 바꿨다. OpenAPI는 nullable 필드를 `required`에 넣지 않는 기존 방식이라 그 검사를 뺐다(`nullable`·`isFullSong` 이름 검사는 유지). 메인 코드는 고치지 않았다.
- 수정 후 `./gradlew databaseTest --tests '*SectionComparisonApiDatabaseTests*' --tests '*OpenApi*'` 통과. 전체 `databaseTest`는 다시 돌리지 않았다.
- 직전 세션 SQL의 구간 포함 조건과 같은 시각 조건을 지운 변형에서 `SectionComparisonApiDatabaseTests`가 실패하는 것을 확인하고 원복했다.
- 임시 컨테이너는 제거했다. AI·앱 실기기 검증은 하지 않았다.
