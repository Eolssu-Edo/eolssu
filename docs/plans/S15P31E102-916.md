- 완료 조건: 절차 문서, 테스트를 통과한 도구, 팀이 결정할 질문 목록.

## 조사에서 확정한 사실

- origin/main `400aaf13`은 origin/develop의 조상이다. fast-forward로 옮길 수 있다.
- backend·web 배포 도구(`check_release_order`)는 develop 이력 안의 SHA만 받고, 현재보다 오래된 SHA를 거부한다. 따라서 **main에 병합 커밋을 만들면 그 SHA는 배포할 수 없고**, 운영 롤백은 되돌림 커밋을 develop에 병합하는 앞으로 배포 방식이다.
- `eolssu-backend` 잡은 `pollSCM('* * * * *')`로 develop 변경을 자동 배포한다. 동결은 병합 중지나 잡 일시 중지로 구현해야 한다.
- ai·omr·playback은 Jenkins가 갱신하지 않는다. 운영 revision은 이미지 라벨로 확인한다.
- 앱 표시 버전이 Android `1.0.0`, iOS `1.0.1`로 다르다.

## 결정

- 릴리스 식별자는 develop RC SHA에 붙이는 `vX.Y.Z` 주석 태그로 제안한다(안 A). 서버 구성 요소는 SHA로 식별하고 앱 표시 버전만 맞춘다. 팀 결정 전이다.
- 도구는 서버·원격에 접속하지 않고 로컬 Git 객체만 읽는다. 배포 revision은 사람이 읽어 `--deployed`로 넣는다. 태그·Push는 명령을 출력만 한다.
- 발표 중 기본 대체 수단은 녹화 영상이다. edo2 전환은 579 병합과 DNS 리허설 뒤에만 선택지에 넣는다.
