# S15P31E102-163 — 1차 화면 태블릿 세로·가로 배치

## 범위와 기준

- Task: [S15P31E102-163](https://ssafy.atlassian.net/browse/S15P31E102-163) `[FE] 1차 화면 태블릿 세로·가로 배치 적용`. 담당 권영민.
- 브랜치: `feat(fe)/S15P31E102-163-1차-화면-태블릿-세로·가로-배치-적용`, S15P31E102-149 위에 쌓음.
- 범위: 휴대폰 배치로 만든 1차 화면(곡 목록·상세, 내 악보·PDF 올리기, 연습, 분석 대기·평가 결과, 연습 기록·기록지, 운지법·쉽게 읽기·기초부터 배우기, 첫 실행·로그인·회원가입)에 와이어프레임 태블릿 아트보드(세로 800×1280 · 가로 1280×800)의 배치를 적용한다. 홈은 S15P31E102-116에서 끝났다.
- 기준: 와이어프레임 '태블릿' 파트. 상태·데이터는 휴대폰과 같고 배치만 바꾼다. 600dp 미만은 휴대폰, 600~840dp는 태블릿 세로, 840dp 이상은 태블릿 가로·넓은 웹 창이며 넓은 창의 내용은 최대 1120dp로 가운데에 둔다.

## 결정

| 항목 | 결정 | 근거 |

| 화면 틀 너비 | `EolssuScaffold(contentMaxWidth)`·`EolssuTopBar(maxWidth)`·`EolssuBottomBar(maxWidth)`. 기본값은 휴대폰 너비 560dp | 휴대폰 배치는 그대로 두고 태블릿 배치만 넓힌다 |

| 가로 두 칸 | 곡 목록+곡 상세, 연습 기록+기록 상세, 단계 목록+단계 상세는 목록 경로 한 화면에서 오른쪽 칸만 바꾼다. 고른 항목은 각 UiState(`selectedSongId`·`selectedRecordId`·`selectedStage`)에 두고, 세로·휴대폰은 지금처럼 상세 화면으로 이동 | 와이어프레임 `tabCounterpart`: 세로 두 화면 ↔ 가로 한 화면 |
| 회전 | 단계 상세를 보다 가로가 되면 그 단계를 고른 목록 두 칸으로, 가로에서 고른 뒤 세로가 되면 그 단계 상세로 간다. 곡·기록은 가로에서 상세 경로로 바로 오면(배우기의 곡 열기, 주소 직접 입력) 상세를 세로 배치로 가운데에 둔다 | 와이어프레임 프로토타입 동작. 곡·기록의 목록 복귀는 NavHost 정리가 필요해 남긴다 |

| 평가 결과 | 태블릿은 점수·오류 위치 정간보 전체·필터·고른 칸 설명을 한 화면에 둔다(휴대폰은 RESULT-03로 넘어가는 내용). 처음 고른 칸은 틀린 칸이 몰린 두 각에서 연주 순서로 첫 오류. 오류 설명 문구는 예시 결과일 때만 붙임 | 아트보드 메모. 결과 모델에 오류별 설명이 없다 |
| 정간보 공통 | `scoreStrips(columnRange)`·`JeongganboView(columns, dimUnmarked, highlightColumns)` 추가, `JeongganboMetrics.practice(tablet = true)`를 와이어프레임 값(각 72/92dp, 정간 최소 44/60dp)으로 맞춤. 기본값이면 휴대폰 렌더링은 같다 | 기록 상세 세로(여러 줄 접기)와 결과·연습 두 단이 같은 기능을 쓴다 |
| 첫 실행·로그인 | 세로는 가운데 한 단(560dp), 가로의 약관 동의·로그인·가입·프로필은 왼쪽 브랜드 칸 + 오른쪽 입력 칸 560dp. 약관 보기·마이크·소셜 로그인은 가로에서도 한 단(640dp). 대표 문구는 붓글씨 대신 세리프 굵은 글꼴 | 와이어프레임 `tab-app.js` split 설정. 앱에 붓글씨 글꼴이 없다(홈 족자와 같음) |
