## 원인 확인

1. 운영 DB를 읽기 전용으로 조회해 같은 곡의 업로드 두 건을 대조했다. 경고가 난 건은 3·5·6·7·8·12마디가 짧았고, 가사 없는 입력용 PDF로 올린 건은 16마디가 원본과 일치했다.
2. 로컬 Audiveris로 두 PDF를 서비스 옵션 그대로 재현했다. 서버 저장 결과와 마디별 길이가 같았다. 기호 위치를 그림에 표시해 가사 글자가 6잇단·악센트·스타카토·p로 분류된 것을 확인했다.
3. 가사 줄만 지운 그림, 1.5배 확대 그림을 비교해 가사 원인(6잇단·가짜 음)과 해상도 원인(쉼표 누락)을 분리했다. 수치는 [기술 기록](../knowledge/ai/score-recognition-corrections.md#가사-줄의-기호-오인식-992)에 둔다.

## 구현과 검증

- `staff_engine.lyric_regions`가 첫 인식 `.omr`에서 가사 줄 띠를 찾고, `_retry_without_lyrics`가 띠를 가린 그림으로 한 번 다시 읽는다. `rhythm_mismatches`로 마디 수가 같고 불일치가 늘지 않을 때만 채택한다. 기존 빠르기 재인식 뒤, 1.25배 리듬 재인식 앞에 둔다.
- 작은 고정 데이터: `test_staff_lyrics.py` 7검사. 실제 Audiveris 출력의 `.omr`에서 띠 4개가 수동으로 지운 영역과 같은 높이로 나오는 것도 확인했다.
- 관련 회귀(`test_staff_lyrics`·`test_omr_staff_engine`·`test_staff_pdf_tuplets`·`test_staff_rhythm_preservation`·`test_staff_musicxml`·`test_staff_pdf_tempo`) 172 통과, 2 건너뜀(AuClair 로컬 PDF 없음). 가짜 Audiveris는 `.omr`을 내지 않아 기존 흐름은 바뀌지 않는다.
- `tests/unit` 전체는 578 통과·43 실패·2 건너뜀. 실패는 모두 OMR 이미지에 없는 `ffmpeg`·`ffprobe`와 Windows 전용 메모리 측정을 쓰는 채점·오디오 검사이며 이번 변경 파일과 무관하다. pytest는 실행 중인 임시 컨테이너에만 설치했고 이미지는 바꾸지 않았다.
- 실제 서비스 경로: 두 PDF를 `api._pdf_pages`→`staff_engine._read_pages`로 처리했다. 가사 PDF는 `LYRICS_REMOVED` 4건과 함께 채택, 가사 없는 PDF는 변화 없음.

## 남은 일과 한계

- 저화질 래스터의 쉼표 누락은 그대로다. 이번 재인식에서 12마디는 고쳐지고 15·16마디 앞 8분쉼표는 빠졌다.
- 가사 줄이 오선 구조와 1간격 안으로 붙은 악보, 오선 위쪽 가사, 피아노 단 사이 가사는 대상이 아니다.
- 커밋·Push·MR은 요청 시 진행한다. 운영 배포 전에는 운영 이미지에서 같은 PDF로 재확인이 필요하다.
