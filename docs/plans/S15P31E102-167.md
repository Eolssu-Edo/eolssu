## 작업별 완료 조건과 검증

### AI-1 NO_SOUND 판정 변경

- 완료 조건:
  - 모든 음표가 `MISSED`이면 `FAILED`/`NO_SOUND`를 반환한다. 잡음이 몇 프레임 있어도 같다.
  - 일부 정간만 무음이면 `DONE`이고 그 음표만 `MISSED`다.
  - 틀린 음만 분 녹음은 `DONE`이고 `PITCH`다.
  - 기존 `TOO_SHORT` 판정(정답 길이의 절반 미만)과 테스트는 그대로 통과한다.
  - `ai/README.md`의 실패 행에 바뀐 `NO_SOUND` 기준을 적는다.
- 검증: `ai/`에서 `uv run pytest`. 새 경우는 `tests/unit/test_scoring.py`에 작은 합성 배열로 추가하고, 고치기 전 실패를 먼저 확인한다. `uv run --group eval python -m evaluation.run_evaluation`으로 평가 표의 실패 행을 다시 만든다.
- 위험: S15P31E102-157(채점 입력 변경)이 같은 `score()`를 고친다. 먼저 병합되는 쪽에 맞춰 다른 쪽을 다시 맞춘다.

### AI-3 처리 시간 측정

- 완료 조건: 곡 길이(예: 15·30·60·300·600초)와 방법(pYIN·CREPE full·tiny)별 처리 시간, 메모리, 실행 환경을 `docs/knowledge/ai/`에 기록한다. 60초 제한 시간과 600초 녹음 상한 중 무엇을 바꿀지 제안한다.
- 검증: 기록에 재현 명령·입력·버전을 남긴다. 합성 입력 결과를 실제 서버 성능으로 일반화하지 않는다.
- 위험: 현재 DTW는 프레임 수의 제곱만큼 메모리를 쓰며 1분 넘는 녹음을 다루지 않는다([AI README](../../ai/README.md)). 긴 입력은 측정 자체가 실패할 수 있으니 실패도 결과로 기록한다.

### BE-U 분석 요청·결과 저장·상태 조회

- 완료 조건: `PENDING` 세션을 AI로 분석하고, `DONE`이면 `evaluations`·`note_results`를, `FAILED`이면 AI가 준 실패 코드를 저장한다. 앱이 세션 분석 상태를 조회할 수 있다.
- 검증: AI 대역으로 `./gradlew test`, 저장·조회는 `./gradlew databaseTest`.

### BE-1 시간 초과·SERVER_ERROR·늦은 결과

- 완료 조건:
  - 시도 시작 뒤 제한 시간(설정값, 기본 60초)이 지나면 `FAILED`/`TIMEOUT`이다.
  - 상태 조회 때 오래된 `PENDING`을 `TIMEOUT`으로 바꾼다(서버 재시작 대비).
  - AI 연결 실패·예외·형식 오류·저장 실패는 `SERVER_ERROR`이고 `fail_reason`에는 코드만 남긴다.
  - 다른 시도 번호의 결과와 `TIMEOUT` 뒤의 결과는 버린다.
  - 시도마다 처리 시간(ms)과 결과 코드를 로그에 남긴다.
- 검증: 조정 가능한 시계와 AI 대역으로 `./gradlew test`. 저장·조회는 `./gradlew databaseTest`. AI 대역 통과를 실제 AI 검증으로 보고하지 않는다.

### BE-2 분석 다시 시도

- 완료 조건: `FAILED`이고 `TIMEOUT`·`SERVER_ERROR`일 때만 새 시도를 만든다. `PENDING`이면 현재 상태를 돌려준다. `NO_SOUND`·`TOO_SHORT`·`DECODE_ERROR`·`UPLOAD_TIMEOUT`·`DONE`은 거절한다. 같은 요청을 여러 번 보내도 분석은 하나만 돈다.
- 검증: `./gradlew test`(동시 요청 경우 포함), `./gradlew databaseTest`.

### FE-U 녹음 다시 보내기

- 완료 조건: 업로드가 성공할 때까지 녹음 파일을 기기에 보관한다. 네트워크 오류·503이면 '녹음 다시 보내기'로 같은 세션에 다시 올리고, 앱을 다시 열어도 만료 전이면 보낼 수 있다. 성공하면 파일을 지운다. 410이면 파일을 지우고 사과 문구로 다시 연주를 안내한다. 413·415·422에는 다시 보내기를 보이지 않는다.
- 검증: 업로드 대역으로 `./gradlew :shared:testAndroidHostTest`. Android 에뮬레이터·iOS 시뮬레이터에서 네트워크를 끊었다 켜서 확인한다. 웹 녹음은 PRA-02 결정에 따라 범위가 아니다.

### FE-1 실패 화면

- 완료 조건: `NO_SOUND`·`TOO_SHORT`·`DECODE_ERROR`·`TIMEOUT`·`SERVER_ERROR`에 스펙의 안내 문구와 버튼이 대응하고, 모르는 코드·빈 값은 `SERVER_ERROR` 화면이다. `UPLOAD_TIMEOUT`은 화면에 보이지 않는다. '다시 연주하기'는 같은 곡·구간·BPM 연습 화면으로, '분석 다시 시도'는 재시도 요청으로 이어진다(연동 전에는 예시 데이터).
- 검증: `frontend/`에서 `./gradlew :shared:testAndroidHostTest`, `./gradlew :shared:wasmJsTest`.
- S15P31E102-147은 실패·다시 시도를 하나의 상태로 구현했다. 이 Task는 그 화면을 코드별로 나누며 S15P31E102-147 병합 뒤 진행한다.

### FE-2 상태 조회

- 완료 조건: 2초마다 조회하고 `DONE`·`FAILED`에서 멈춘다. 응답 없이 70초가 지나면 `TIMEOUT` 화면을 보여 준다. 백그라운드에서 돌아오면 한 번 조회하고 `PENDING`이면 조회를 다시 시작한다.
- 검증: 가짜 시계·가짜 저장소로 FE-1과 같은 명령. 고정 sleep을 쓰지 않는다.

### CP-1 실행 검증

- 완료 조건: 실제 앱·서버·AI로 다음을 확인한다.
  - 정상 녹음 → 결과 화면
  - 무음 녹음 → `NO_SOUND` 화면
  - 업로드 중 네트워크 단절 → 녹음 다시 보내기 성공

- 검증: 실행 기록(입력·버전·화면·로그 위치)을 남긴다. 무거운 검증이므로 담당자와 실행 시점은 착수 전에 정한다.
