# 실제 앱 조작과 격리 서버 처리의 실시간 시연

- Jira는 S15P31E102-283이며 연결 Story는 S15P31E102-38이다. 진행 중인 같은 작업의 후속 검증이다.
- 브랜치는 `feat(fe)/S15P31E102-283-앱-조작과-격리-서버-처리-실시간-시연`, 시작 커밋은 `57666c0389f067a4ba084a2fd88088491f2273ee`이다.
- 실제 QA 앱의 동작·HTTP 송신·응답·Compose 첫 그리기를 구분해 지휘통제 수집기가 관찰하도록 한다. API 주소는 격리 중계 `http://127.0.0.1:18180`이다.

## 완료 조건과 구현 순서

1. QA 빌드 속성이 켜진 Android debug, `.qa` 패키지, 루프백 API 조건에서만 `EolssuLive` 로그를 기록한다.
2. 공통 HTTP 진입점에서 실제 송신 시도마다 UUID `X-QA-Request-Id`를 보내고 같은 ID의 시작·완료 이벤트를 기록한다. 401 갱신 재전송은 각각 구분하고 실패·취소도 종료 이벤트로 남긴다.
3. 기존 ACTION·화면 방문·평가 진단 ID와 실제 그리기 이벤트를 재사용한다. 곡 상세의 성공한 콘텐츠에 첫 그리기 계측을 연결한다. HTTP 성공을 화면 표시로 판정하지 않는다.
4. 허용한 대상 이름·단계·상태·난수 상관 ID와 시간만 JSON에 기록한다. URL·쿼리·본문·쿠키·사용자 입력은 기록 필드로 받지 않는다.
5. MockEngine으로 시작 순서, 응답·오류·401 재전송 상관, QA 비활성 상태 및 민감한 값의 제외를 검사한다. 공유 Android 호스트 테스트와 QA APK 빌드를 수행한다.
6. 기기 설치·실제 버튼 클릭과 수집기 대조는 실행 담당자가 수행한다. 빌드 성공과 기기 검증 결과를 각각 기록한다.

## 검증

- 2026-11-15 JDK 21·Android API 37에서 `:shared:testAndroidHostTest` 1,754건, 실패·오류 0건, 건너뜀 5건을 확인했다.
- 새 HTTP 계측 검사 5건은 모두 통과했다. 최초 구현 전 검사는 Gradle 캐시와 SDK 누락 때문에 실행 준비에서 멈췄다. SDK 복구 후 기존 HttpClients 코드로만 되돌린 민감도 검사에서는 5건 중 4건이 계측 누락을 검출해 실패했고, 구현 복원 후 5건이 다시 통과했다.
- `:androidApp:assembleDebug -Peolssu.qaLive=true -Peolssu.debugApiBaseUrl=http://127.0.0.1:18180`가 성공했다. APK는 `frontend/androidApp/build/outputs/apk/debug/androidApp-debug.apk`이며 SHA-256은 `ba5965c6b9d4e9774b82bcfee3247c80ae3acb8b387c42dbdc6276e92003f02e`이다.
- APK 메타데이터에서 패키지 `com.ssafy.eolssu.qa`, 버전 `1.0.0-qa283-live`, API 주소 18180, `QA_LIVE=true`, `QA_SKIP_CONSENT=false`를 확인했다.
- SDK 일부 파일이 임시 폴더에서 없어져 공식 Google 배포 파일과 체크섬으로 복구했다. API 37.0의 `source.properties`만 기존 AGP가 읽을 수 있는 주 버전 37·부 버전 0으로 표현했다. 프로젝트의 SDK 대상과 플랫폼 바이너리는 동일하다.
- 별도 검토자가 opt-in 가드, 요청별 UUID, 기존 스냅샷 수집기의 호환성 및 실제 그리기 위치를 검토해 중대한 지적이 없었다.
- 기기 설치와 실제 앱·중계·AI·DB 대조는 실행 담당자가 진행한다. 이 문서의 호스트 테스트와 APK 빌드만으로 기기 검증 완료를 판정하지 않는다.
- iOS·Web 실행 검증은 이 Android QA APK 작업의 완료 범위 밖이다.

## 이벤트 계약

- Android 태그 `EolssuLive`는 JSON 한 줄을 출력한다. `kind=request_started|request_finished`에 같은 UUID `request_id`를 넣으며, 실제 HTTP 시도마다 새 UUID를 사용한다.
- 기존 `action`, `visit_started`, `milestone`, `http_attempt` 등의 허용한 필드도 같은 태그로 출력한다. 전용 수집기가 기존 스냅샷 프로토콜에 없는 필드를 처리하므로 스냅샷 수집기의 허용 목록은 유지한다.
- `song_detail_drawn`은 로드된 곡 상세 본문의 첫 그리기, `practice_drawn`은 연습 악보의 첫 그리기, `score_drawn`은 결과의 첫 점수 표시다. 점수 이외 모든 세부 콘텐츠의 로딩 완료를 의미하지 않는다.
- `analysis_ready`는 서버 DONE을 앱이 확인한 시점이다. 결과의 실제 `score_drawn`은 같은 흐름과 `evaluation_submission`으로 연결하며, `analysis_ready.evaluation_timing_id`를 통해 서버 시도와 연결한다.


## QA 합성 PCM 입력 후속 검증

- 에뮬레이터의 무음은 앱의 실제 입력 검사에서 중단되어 녹음 후 파일 교체로는 정상 제출 경로를 검증할 수 없었다.
- 명시적인 QA 입력 선택으로 `files/qa-live-input.pcm`을 녹음 시작 시점에 확인한다. 허용 조건은 디버그 앱, 정확한 `com.ssafy.eolssu.qa` 패키지 및 기존 QA_LIVE 활성화다.
- 파일은 16kHz 모노 signed16 little-endian, 최대 60초다. 기존 녹음 파이프라인은 44.1kHz이므로 고정 입력을 선형 리샘플링하고 실제 경과시간에 맞춰 전달한다. AAC 인코딩·레벨·YIN 추정·카운터·기존 입력 검사는 같은 경로로 수행한다.
- 마이크가 기본 입력이다. 합성 파일이 선택되면 `synthetic_input` 로그를 남기고, 끝난 뒤에는 무음 샘플을 보내며 중지·일시정지·재개 동작을 그대로 따른다.
- 순수 PCM 검사로 signed16 해석·리샘플링·종료 후 무음·실시간 간격·재개 위치·크기 제한을 검증한 뒤 APK를 다시 빌드한다.

- 2026-11-15 PCM 입력 검사 4건과 QA APK 빌드가 통과했다. 전체 공유 Android 호스트 회귀는 1,758건 중 실패·오류 0건, 건너뜀 5건이다.
- 후속 APK의 SHA-256은 `74129ec3b02a2e83a8d67089e99122ebd4bef58976e6b89906b80d3c700f174a`이다. 기존 API 주소와 opt-in 가드를 유지했다.
- 별도 검토자가 패키지·디버그 가드, 입력 리샘플링과 실시간 간격, 일시정지·재개와 끝난 뒤 무음을 확인해 중대한 지적이 없었다. 입력 선택 로그는 파일을 실제로 연 사실이며, 채점 완료와 화면 표시의 증거는 별도로 수집한다.
