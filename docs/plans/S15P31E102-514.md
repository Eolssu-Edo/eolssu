## 검증 기록

- 2026-11-05: Compose 검사와 공식 phpMyAdmin 5.2.3 이미지의 PHP 구문 검사 통과. 이미지 digest는 Compose에 고정했다.
- 격리 MySQL: 권한 부여 전 SELECT 거부. 부여 뒤 일반·인증 테이블의 행 조회 성공. INSERT·UPDATE·DELETE·CREATE, 다른 스키마 조회와 평문 연결 거부. 사용자 지정 temp-mysql로 종료와 정리를 확인했다.
- 격리 HTTP: 전용 계정이 일반·인증 테이블을 열었고, 유효한 앱 계정과 인증서 이름이 불일치하는 서버의 접속을 거부했다.
- edo1 읽기 전용 점검: MySQL 8.4.13 healthy, eolssu 테이블 30개, 3306 미공개, 새 UI 포트와 계정 이름 미사용. 실제 MySQL의 TLS 1.3 연결에서 CA와 서버 이름 검증을 통과했다.
- 최초 운영 적용 명령은 인증서 검증 예외와 운영 적용 범위가 승인되지 않았다는 자동 승인 심사로 실행되지 않았다. 검증 예외를 제거했다. 운영 UI 설치와 계정 생성, 운영 브라우저 확인은 별도 적용 뒤 수행한다.
- 2026-11-05: 인증서 검증을 사용하는 최종 구성의 운영 적용을 사용자가 승인했다. 첫 실행은 컨테이너 직후 HTTP 연결 초기화로 실패하여 새 UI·전용 계정만 롤백했다. 운영 MySQL과 백엔드 ID 및 MySQL 볼륨은 그대로였다. HTTP 준비 검사를 재시도하도록 바꿔 두 번째 적용을 완료했다.
- 운영 phpMyAdmin의 전용 계정으로 30개 테이블 표시와 MySQL 상태 수치 3종을 확인했다. MySQL 권한은 USAGE와 eolssu 전체 SELECT뿐이며 mysql.user 접근과 root 웹 로그인은 거부됐다. phpMyAdmin에서 MySQL TLS 연결을 확인했다. Mac의 SSH 터널로 로그인 화면까지 HTTP 200을 확인했다.
- 8081은 edo1의 127.0.0.1에만 열렸고, 3306은 호스트에 열리지 않았다. 운영 MySQL과 백엔드 컨테이너 ID·healthy 상태 및 MySQL 볼륨을 유지했다. 운영 Compose·PHP 설정 해시는 이 브랜치의 파일과 일치한다.
