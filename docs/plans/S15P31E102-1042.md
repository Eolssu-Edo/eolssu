## 범위와 완료 조건

1. 변환된 악보(서버 `conversionStatus`가 있는 문서)를 열면 아래 입력판을 접은 채로 시작하고, 펼침 버튼 옆에 "악보를 직접 편집할 수 있어요"를 둔다. 탭을 고르거나 높이 맞추기·고치기 버튼을 누르면 펼친다.
2. 음역·이조 탭: 이름을 쉬운 말로 바꾸고, 악기 표시 자리에 흰 상자로 지금 고른 이조 값(`+1반음`)을 둔다. '추천'이 무엇인지 한 줄로 설명하고, 높이를 바꿔도 남는 음이 있으면 그 수와 다음 할 일을 안내한다.
3. 확인 카드: 초록 상자에 `확인 필요: 단소로 낼 수 없는 음 N개` 한 줄과 흰 버튼 `N반음 올려서 모두 고치기`. 다시 볼 곳도 같은 모양.
4. 다시 볼 곳: '보러 가기'나 표시된 칸을 누르면 그 칸으로 가서 고칠 방법(율명 넣기·시김새 넣기·원본과 같아요)을 바로 보인다.
5. 운지 자료 미확인·꾸밈음 등 안내를 사용자가 할 일 중심 문장으로 바꾼다.
6. 저장 창: 제목과 예상 음원 길이만 둔다. 저장을 막는 문제와 오류만 있을 때 보인다.

API·저장 형식은 바꾸지 않는다.

## 설계 결정과 원래 기대와의 차이

- 입력판 접힘은 화면 안 기억값이던 것을 `SheetEditUiState.inputPanelExpanded`로 올렸다. 다시 볼 곳의 '율명 바꾸기'·확인 카드의 높이 맞추기처럼 화면 밖 동작이 입력판을 펼쳐야 하기 때문이다. "처음 들어오면"은 변환된 악보를 열 때마다로 구현했다(다시 열어도 접혀 시작). 손으로 만든 악보·제공 곡 복사본은 지금처럼 펼친 채 연다.
- 탭 이름은 `높이 맞추기`로 했다. 흰 상자는 슬라이더에서 고른 값(`원조 유지`·`+1반음`)을 보이고, 같은 값을 보이던 슬라이더 위 가운데 글자는 뺐다.
- 확인 카드의 다시 볼 곳도 같은 모양(`확인 필요: 다시 볼 곳 N곳` + 흰 버튼 `첫 곳으로 가서 고치기`)으로 맞췄다. 추천이 없을 때 버튼은 `높이 맞추기에서 고치기`.
- 다시 볼 곳 창: 칸 정보만 보이던 '선택한 위치 정보'를 '이 칸을 원본과 비교해 주세요'로 바꾸고 `율명 바꾸기`(꾸밈음이면 `시김새 넣기`)·`원본과 같아요`·`닫기`를 둔다. `원본과 같아요`를 누르면 다음 다시 볼 곳으로 바로 간다. 확인할 수 없는 항목(지원음 문제 등)에는 `원본과 같아요`를 보이지 않는다.
- 저장 창에서 변환 참고 알림(`SheetConversionNotes`)을 뺐다. 저장을 막는 문제·오류·빠르기 오류는 있을 때만 남긴다. 그 결과 '음높이 조정 ±N반음'·'성부 중 선율을 골랐어요' 같은 변환 참고는 앱에서 더 보이지 않는다. `SheetConversionNotes` 함수와 테스트는 다른 화면에서 다시 쓸지 정하기 전까지 남겨 두었다.
- 피치 확인 창의 버튼 '악기·음역 맞추기'는 탭을 여는 동작과 맞게 '곡 전체 높이 맞추기'로 바꿨다.

## '악기·음역 맞추기'를 눌러도 낼 수 없는 음이 남는 문제(강원도아리랑·단소 41개)

- FE 원인: 피치 확인 창의 버튼은 높이 탭을 열기만 하고 적용하지 않는다. 탭은 원조 유지 상태의 개수(41개)를 그대로 보여 '눌러도 안 고쳐진다'로 보였다. 이제 탭에 '추천'의 뜻을 적고, 어느 높이로도 다 못 고치면 `높이만 바꿔서는 N개가 남아요. 적용한 뒤 빨간 칸을 눌러 하나씩 바꿔 주세요.`를 보인다(`SheetAdaptationUi.unavoidableUnresolved`).
- 높이만으로 남는 이유: 높이 맞추기는 음마다 옥타브를 접어 악기 지원음 중 같은 율(12율 위치)을 찾는다. 단소 지원음(V18·V32 시드)은 황·태·협·고·중·임·남·무 8율이라 대·유·이·응만 없다. 5음 음계인 강원도아리랑이 바르게 인식됐다면 어느 한 높이에서 모두 맞는다.
- 따라서 가장 좋은 높이에서도 41개가 남는다면 인식된 음에 음계 밖 율이 많다는 뜻이고, 조표·임시표를 잘못 읽은 인식(OMR) 문제로 보인다. 같은 악보는 이 계정에 없어 에뮬레이터로 재현하지 못했다(미확인). 인식 쪽은 S15P31E102-1043에서 다룬다.
