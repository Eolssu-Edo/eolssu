# S15P31E102-889 악보 불러오기·올리기·편집 화면 배치 정리

- Jira: [S15P31E102-889](https://ssafy.atlassian.net/browse/S15P31E102-889), Story 319(Relates), Epic 16, 담당 오은서, 활성 스프린트 59321, 진행 중.
- 브랜치: `feat(fe)/S15P31E102-889-악보-불러오기·올리기·편집-화면의-목록·파일-선택·장단·빠르기-배치-정리`.
- 요청: 불러올 악보 목록을 연습하기와 같게, 올리기 화면은 버튼을 눌렀을 때만 파일 선택, 장단 선택은 네모 버튼, 편집 자동저장 중단, 빠르기 옆 연필과 오른쪽 예상 음원 길이, 음역 맞추기 개수 한 줄과 작은 적용 버튼.

## 결정

- 불러올 악보 고르기는 연습곡 고르기의 부품(`MySongsTabSwitch`·`SongSearchField`·`SongLevelChips`·`SongSortButton`·`ProvidedSongRow`)을 그대로 쓴다. 글자 타일과 고름 점을 없애고, 고른 줄은 연습 목록의 선택 줄처럼 연한 연두 바탕이다. 검색어는 두 탭에 함께 적용하고 단계 필터는 제공 곡 탭에만 둔다.
- 내 악보 줄은 같은 틀의 `MySheetPickRow`(제목·보조 문구·연습 가능/확인 필요 배지·화살표)다. 편집·삭제는 내 악보 목록에서만 한다.
- 악보 올리기는 진입할 때 파일 선택 창을 열지 않는다. 경로의 `pick` 인자를 지웠다.
- 편집은 자동저장하지 않는다. 바뀐 내용이 있으면 닫기에서 `임시저장하고 닫기`·`계속 편집하기`·`변경을 버리고 닫기`를 묻는다. 서버 악보가 없는 편집(제공 곡 복사 미저장)은 임시저장 없이 계속/버리기만 둔다. 누른 저장이 진행 중이면 결과를 기다린 뒤 판단한다. 저장 상태 문구는 `임시저장 완료/하지 못했어요/다시 시도`로 바꿨다.
- 음역 맞추기의 악기 드롭다운은 다시 고르는 칸이 아니라 악보를 다른 악기로 바꾸는 기능(적용 시 `score.instrument` 변경)이라 이번에는 유지했다. 처음 고른 악기가 기본 선택이다. 숨길지는 사용자 결정으로 남긴다.

## 검증

- shared Android host 1665개 통과(실패 0·기존 제외 5), JS 컴파일 통과.
- 새 테스트: `SheetDocumentViewModelTest › editsAreNotSavedUntilTheUserAsks`, `closingWithUnsavedEditAsksFirstAndSaveDraftAndCloseWaitsForAcknowledgement`, `failedSaveDraftAndCloseKeepsTheEditorOpenAndAsksAgain`, `SheetEditStateTest › editPickFiltersSongsByLevelAndSearchesSheetsLikePracticeList`. 편집 시 저장을 되살리고 단계·검색 필터를 지운 코드에서 10개가 실패하는 것을 확인했다.
- 자동저장을 전제로 한 기존 테스트는 명시적 `saveDraft`로 바꿨다. 닫기 저장 중 재조회·계속 편집 시 자동저장 재개를 검사하던 2개는 동작이 없어져 지웠다.
- Android 에뮬레이터(emulator-5554)에서 목록·단계 필터·선택·내 악보 탭, 올리기 화면 진입 시 파일 창 없음과 버튼으로 문서 선택기 열림, 연필·예상 길이 배치, 장단 네모 버튼, 개수 한 줄·작은 적용, 빠르기 변경 후 닫기 확인 창과 버리기 후 원래 빠르기 유지를 확인했다. 실제 기기·iOS는 미검증이다.
- 발견: 장단 이름이 `엇모리장단`인 사본에서 장단 창이 `장단 사용 안 함`을 선택으로 표시한다(`jangdanId` 없음). 이번 변경 전 동작이며 고치지 않았다.
