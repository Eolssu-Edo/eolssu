## 문제

운영 compose는 `SPRING_PROFILES_ACTIVE=ops`다. 업무 Bean 21곳이 `@Profile("db")`이고 Mapper XML 설정도 `application-db.yml`에만 있어, 운영에는 약관·인증·연습·성장 API가 없었다(모두 404). 운영 DB에는 V1~V4가 이미 적용돼 있다.

## 결정(2026-10-28 사용자 확정)

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 켜는 방식 | 업무 Bean을 `@Profile("db \| ops")`로, `application-ops.yml`에 Mapper 설정·UTC 세션 추가 | `db,ops`로 함께 켜면 프로필 순서에 따라 운영 DB에 Flyway가 돌 수 있다. ops는 Flyway를 계속 끈다 |
| 인증번호 키가 없을 때 | 기동하고 이메일 인증번호 발송·확인만 503 | 운영 `.env`에 아직 없을 수 있다. 로그인 토큰 키(`AUTH_JWT_SECRET`)와 같은 방식. 형식이 틀린 값·32바이트 미만은 계속 기동 실패 |
| 서버 적용 | 병합 뒤 SSH로 적용 | 백업 → `.env` 확인 → compose 설치 → backend 재생성 → 확인 |

함께 바뀐 것: 업로드 만료 작업이 운영에서도 5분마다 돈다(`eolssu.scheduling.enabled`로 끌 수 있음). Hikari 풀은 헬스체크 전용일 때의 3개에서 10개로 올렸다.
