# S15P31E102-685 닉네임 최대 10자 서버 검증

- [Jira](https://ssafy.atlassian.net/browse/S15P31E102-685)
- 기준 `origin/develop 1a6e28b4`. 별도 피처 worktree에서 구현한다.
- 목표: 닉네임 최대 길이를 60자에서 10자로 줄이고 서버에서 강제한다. 11자 이상은 기존 400 `INVALID_REQUEST` 검증 경로로 거절한다.

## 범위

- 서버: `POST /api/auth/sign-up`, `POST /api/auth/oauth/sign-up`(요청 검증과 `SocialAuthService` 재검사), `PATCH /api/users/me`.
- 서버 상수 `NicknamePolicy.MAX_LENGTH`(auth domain)를 세 요청의 `@Size`와 소셜 가입 서비스 검사가 함께 쓴다. Swagger의 `maxLength`는 `@Size`에서 생성되고, 닉네임 수정 설명 문구도 10자로 고쳤다.
- 앱: `core/model/NicknameRule`을 가입 화면 검사(`AuthValidation.nicknameError`)와 닉네임 수정(`NicknameEditViewModel`)이 함께 쓴다. 안내 문구는 `1~10자`로 바꿨다.
- 제외: DB 컬럼(`users.nickname VARCHAR(60)`)과 마이그레이션, 기존 저장 닉네임 변환, Notion API 명세 수정.

## 결정

- 길이는 Kotlin `String.length`(UTF-16 코드 단위)로 센다. 서버 `@Size`와 같은 기준이다. 보충 평면 문자(이모지 등)는 1자를 2로 센다.
- 앱은 전송값과 같게 앞뒤 공백을 뺀 값으로 센다. 서버는 받은 값 그대로 센다.
- 이미 저장된 11자 이상 닉네임은 그대로 둔다. 조회는 영향이 없고, 수정할 때만 새 규칙을 적용한다.

## 검증 기록

- 테스트를 먼저 바꿔 실패를 확인했다. 백엔드 대상 19개 중 4개 실패(가입·소셜 가입 요청 검증, 소셜 가입 서비스, 닉네임 수정), 앱 대상 15개 중 2개 실패.
- 구현 뒤 같은 대상 테스트 통과: 백엔드 19개, 앱 15개, 실패 0.
- `backend`에서 `./gradlew clean build` 통과. 695개, 실패 0, 건너뜀 1. 앱 빌드와 동시에 돌린 첫 실행에서는 관계없는 `BackendApplicationTests` prometheus 조회가 5초 시간 초과로 1번 실패했고, 단독 재실행에서는 통과했다.
- `frontend`에서 `ANDROID_HOME=<Android SDK> ./gradlew :shared:testAndroidHostTest` 통과. 1,207개, 실패 0, 건너뜀 4(실행 조건이 없는 선택 로컬 서버 검사).
- 미실행: `databaseTest`(쿼리·스키마 변경 없음), Web·iOS 테스트, 실제 HTTP 호출, 실기기 확인.
