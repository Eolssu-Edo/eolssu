# 기록 상세의 목록 캐시와 공개 악보 의존 해소

- Jira: S15P31E102-454 · Story 23 · 박찬형 · Sprint 5 · 진행 중.
- 기준: `192ee0014da8e777dfc8f04e8b91ebc0017938b9`에서 독립 분리한 뒤 최신 develop `d123c0ed`를 fast-forward 반영했다. 원본 707과 기존 454 작업 폴더는 보존했다.
- 목적: 상세 직접 진입과 숨김·삭제·조회 실패 악보에서도 점수, 메모, 녹음을 유지한다. 오류 위치는 기록 당시 판본에만 매핑한다.
- 계약: 745의 PRA-03 `songTitle`, `scoreVersion`과 CAT-01·04 `scoreVersion` 조회를 사용한다. 과거 보관을 하지 않던 이전 454 결정은 745의 판본 보관 계약으로 대체한다.
- 범위: 기록 상세 조립, 정확 판본 조회, 결과·취약 구간·비교 조회, 녹음 재생의 악보 의존 제거. 녹음 시점 판본 캡처와 세션 시작 보호는 453, 데이터 공개는 707이다.
- 완료 조건: 목록 요청 없이 상세를 표시한다. 악보 404·네트워크 오류에서 점수·메모·녹음이 유지되며 악보만 재시도한다. 같은 곡의 다른 판본을 재사용하지 않는다. 정간 및 소박 오류 표시와 기존 성능 계측·삭제·재생 위치 처리를 유지한다.
- 검증: 작은 가짜 HTTP·저장소 테스트로 직접 진입, 과거 판본, 악보 실패/재시도, 오류 매핑을 검증하고 Android host 전체 시험·웹 컴파일을 수행한다. 운영 데이터 변경과 실기기 시험은 이 작업에서 수행하지 않는다.
- 병합 순서: 745 → 453 → 454 → 707. 앱 전환 확인 후 707 데이터 공개 절차를 수행한다.

## 검증 기록

- 최초 직접 진입 회귀 시험 실행은 develop의 `PracticeRoute.kt:106` 기존 `leaveToSongInfo` 참조 오류로 컴파일 단계에서 중단됐다. 453 소유의 `leaveEvaluation()` 한 줄 수정을 검증할 때만 임시 적용했다. 이 수정은 454 커밋에 넣지 않는다.
- 직접 진입·판본 조회·악보 실패/재시도·기존 API 평가·녹음 재생 대상 시험은 통과했다.
- 첫 전체 시험 1,347개 중 요청 판본을 못 찾는 저장소의 결과를 `Failed`로 기대한 기존 시험 하나가 실패했다. 정확 판본 조회 계약에 맞게 `Missing` 기대를 명시했고, 다음 전체 시험 및 JS/Wasm 컴파일이 통과했다.
- 교차 리뷰에서 캐시 기록이 있는 상세 조회 실패 후 재시도가 막히는 경로를 발견했다. `cachedRecordRetriesFailedDetailBeforeLoadingItsScore` 실패(1 test, 1 failure)를 재현한 뒤 상세 우선 재시도로 수정했다. 같은 곡 다른 기록 전환에서 남아 있던 악보가 재시도 버튼을 가리는 경우도 함께 검증한다.
- 점수 선표시·성능 계측·계정 취소 처리를 유지했다. 원본 음 판정을 보존하고 `withScore`에서 정간 오류와 소박 오류를 함께 매핑한다. 미지원 판정도 점수 선표시를 막지 않고 악보 매핑 단계에서만 실패한다.
- 목록이 없는 상세의 전체/구간 표기는 처음에는 ‘구간 정보 없음’으로 보수적으로 표시한다. 당시 악보를 받으면 세션 음 인덱스로 복구한다. PRA-03의 `songTitle`·`scoreVersion` 및 기록 목록·저장 응답의 판본은 745에 의존한다.
- iOS 시뮬레이터는 Windows에서 실행할 수 없다. 실기기 녹음·운영 조회·데이터 공개는 미실행이다.

- 최종 검증: JDK 21·Android SDK를 지정하고 `:shared:testAndroidHostTest :shared:compileKotlinJs :shared:compileKotlinWasmJs --max-workers=2` 실행 성공. Android host 1350개 중 실패 0개·오류 0개·건너뜀 4개. JS/Wasm 컴파일 통과. 교차 리뷰의 재시도 결함은 수정 후 재확인했다.
