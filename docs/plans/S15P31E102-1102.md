# S15P31E102-1102 기초 배우기 단계 카드를 빠르게 넘길 때 호랑이가 늦게 따라오는 문제 수정

- Jira: S15P31E102-1102 · Story S15P31E102-316(기초부터 배우기) · 에픽 S15P31E102-17 · 활성 스프린트 5 · 진행 중.

## 요구

- 기초 배우기 단계 목록에서 카드 '다음' 화살표를 빠르게 여러 번 누르면, 징검돌 지도의 호랑이가 누르는 속도를 따라오지 못한다.
- 단계가 바뀔 때마다 지도를 새로 그리는 것처럼 보인다.

## 원인

- 호랑이는 카드 넘기기가 멈춘 뒤(`pager.settledPage`)에야 알림을 받는다. 빠르게 누르는 동안에는 카드가 계속 움직여 호랑이가 제자리에 있다가, 카드가 멈춘 뒤 여러 돌을 한꺼번에 건넌다.
- 호랑이 이동이 `animateFloatAsState` + `tween(FastOutSlowInEasing)`이라 목표가 바뀔 때마다 속도를 버리고 느린 출발부터 다시 한다.
- 호랑이 위치·높이·눌림 값을 컴포지션에서 읽어, 건너는 동안 프레임마다 지도 블록(돌 7개·물결·그림자)을 다시 구성한다.
- 화살표가 '지금 보이는 카드 + 1'을 목표로 잡아, 넘기는 도중에 누르면 같은 카드를 다시 목표로 잡아 누른 횟수가 사라진다.

## 결정

- 카드 넘기기가 화살표·키보드로 가고 있는 단계(`heading`)를 누르는 순간 정해 둔다. 다음 입력은 지금 보이는 카드가 아니라 이 단계에서 한 장 더 간다.
- 카드 넘기기에 `onAim`을 두어 `heading`을 바로 알린다. 단계 목록 본문은 이 값을 화면 안 상태(`aimedStage`)로만 들고 지도 호랑이에 넘긴다.
- 손으로 끌기 시작하거나 바깥에서 다른 단계를 고르면(돌 누르기·악기 바꿈·가로 배치) `heading`을 지워, 호랑이는 지금처럼 카드가 자리 잡은 단계를 따른다. 손으로 밀 때 호랑이 동작은 바뀌지 않는다.
- 단계 선택(`onShow`)은 지금처럼 카드가 자리 잡은 뒤 한 번만 알린다. 태블릿 가로의 상세 조회(`loadDetail`)와 QA 내용 선택 로그는 지나친 단계마다 생기지 않는다.
- 카드 넘기기가 스스로 알린 단계(`reported`)나 가고 있는 단계로 `current`가 바뀌면 카드를 다시 넘기지 않는다. 자리 잡은 직후 누른 화살표가 이전 카드로 되돌려지지 않는다. 바깥에서 다른 단계를 고르면 이 기억을 지워, 돌을 아무 순서로 눌러 예전 단계로 돌아와도 카드가 따라간다.
- 호랑이 이동은 `Animatable`로 남은 거리만큼 건넌다(돌 하나 280ms, 상한 1.4초). 건너는 도중 목표가 바뀌면 `LinearOutSlowInEasing`으로 지금 속도에서 이어 달리고, 내려앉아 눌리던 중에 다시 떠나면 눌림·물결을 바로 편다.
- 호랑이·그림자·물결의 위치와 모양은 `offset { }`·`graphicsLayer { }`·그리기 안에서만 읽어, 건너는 동안 배치·그리기만 다시 한다.

## 리뷰

- 독립 리뷰(coco-review)에서 다음 문제를 찾아 위 결정으로 반영했다.
    - 처음 방식(`pager.targetPage`를 그대로 호랑이에 전달)은 손으로 56dp만 끌어도 호랑이가 건너갔다.
    - 상세에서 돌아올 때 되살아난 옛 위치가 먼저 전달될 수 있었다.
    - 자리 잡은 직후 누른 화살표가 되돌려질 수 있었다.
    - 착지 눌림이 중간에 끊겨 남을 수 있었다.
- 남긴 점:
    - 화살표로 넘기는 중 손으로 잡아 끌면, 손을 뗄 때까지 화살표 기준이 옛 목표일 수 있다(라이브러리가 취소된 목표를 지우지 않음).
    - 아주 빠르게 여러 장 앞서 누르면 `animateScrollToPage`가 먼 거리를 건너뛰듯 넘길 수 있다.
    - 미리 그려 두지 않은 카드(`beyondViewportPageCount = 1` 밖)는 처음 지나갈 때 그림을 읽는다. 읽은 그림은 캐시되어 두 번째부터는 영향이 없다.
