- 범위 원칙(2026-11-08 사용자): 화면에 보이는 부분은 절대 수정하지 않는다. 내부 로직과 FE 인계 문서의 계약 설명만 바꾼다.

## 확인한 사실 (2026-11-08)

- 공개 악보 API(`/api/songs/{id}/score`의 `result.score.events`)로 채점 계획 곡을 셌다. 단소 35곡 중 33곡은 곡에서 가장 가까운 두 음이 2반음, 1곡은 3반음, 49번 곡만 청남·청무가 반음 이웃이다. 소금 18곡은 모두 2반음이다.
- 서버 채점(`ai/src/ai_service/pipelines/scoring.py`)은 연주 전체 중앙값으로 조율 차이를 빼고(상한 min(100, 가장 가까운 음 간격 − 60센트)) ±50센트를 넘으면 PITCH다. 실시간은 미래 음을 모르므로 같은 방식을 바로 쓸 수 없다.
- 실제 팀 녹음(세션 117·169·181)의 연주 전체 조율 차이는 −25·−25·+45센트였다(540 후보 도구, 2026-11-08).
- 지금 앱 판정(`comparePitch`)은 조율 보정 없이 ±50센트로 낮음·맞음·높음을 내고 `PitchFeedback.direction`에 담는다. 이 값을 그리는 화면은 아직 없다.

### U1 판정 로직과 결과 형식 (D-1~D-4, D-6)

- 내용: `feature/practice/PracticePitchFeedback.kt`.
  - `PracticePitchTracker`가 곡 이벤트에서 서로 다른 목표 음(Hz)을 한 번 모아 정렬해 둔다. 기존 최저음(`lowestHz`)도 여기서 나온다.
  - `comparePitch`는 목표 음과 곡의 음 목록을 받아 `Boolean?`(맞음 true, 틀림 false, 보류 null)을 돌려준다. 순서: 측정 오류 보류(D-4) → 맞음 범위(D-1·D-2) 안이면 true → 그 밖에는 false. 옥타브 띠(1,200±100센트)는 false다(D-3).
  - `PitchFeedback.direction: PitchDirection?`을 `correct: Boolean?`으로 바꾸고 `PitchDirection`을 지운다.
- 수락: 계획의 "완료 확인" 항목이 테스트로 고정된다. 기존 테스트의 낮음·맞음·높음 기대값을 새 의미로 바꾼다. 쉼표·시김새 보류는 그대로다.
- 검증: 테스트 먼저. 위·아래 경계 99·101센트, 49센트·51센트(반음 이웃), 최고음의 위쪽 100센트. 이웃 거리 대신 고정 ±50으로 바꾸면 테스트가 실패하는지 본다. `git diff --stat`에 화면 파일(`*Screen.kt`, `*Route.kt`, `component/`)이 없음을 확인한다.
- 범위: `PracticePitchFeedback.kt`, `PracticePitchFeedbackTest.kt`, `PracticePitchConnectionTest.kt`.
