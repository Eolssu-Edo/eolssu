# S15P31E102-777 연주 분석 대기 화면의 붓 일원상·퍼센트 진행률

- [Jira 작업](https://ssafy.atlassian.net/browse/S15P31E102-777) · Story S15P31E102-37 · 에픽 S15P31E102-20 · 스프린트 5, 진행 중
- 기준: 첫 구현 `eebeb787`(녹음 전송률 표시), `origin/develop` `e0bd8235` 병합 후 후속 수정
- 범위: 분석 대기 화면의 진행률 계산과 표시. 분석 요청·상태 조회 주기·채점 결과·결과 화면 전달 데이터는 바꾸지 않는다.
- 완료 조건: 분석이 끝나기 전에는 100%를 보이지 않고, 첫 `DONE` 확인과 같은 프레임에 100%가 되어 결과 화면으로 넘어간다.

## 원인과 결정

첫 구현은 녹음 파일을 읽은 바이트만으로 0~100%를 채우고, 전송 뒤 분석을 기다리는 동안 100%를 유지했다. 그래서 서버 분석과 상태 조회(처음 8초 1초 간격)로 완료를 확인할 때까지 100%에 멈춰 보였다. [S15P31E102-763](S15P31E102-763.md)의 QA 관측에서 첫 상태 조회부터 완료 확인까지 4,278ms(조회 5회)였다. 완료를 확인한 뒤의 화면 이동에는 고정 대기가 없다. `AnalysisRoute`가 `evaluationId`를 받는 즉시 이동하고 화면 전환 애니메이션은 `None`이다.

상태 조회 API(PRA-03)는 `PENDING`·`DONE`·`FAILED`만 알려 주므로 서버 분석의 실제 비율은 알 수 없다. 진행률을 단계로 나눈다.

| 단계 | 진행률 | 근거 |
| --- | --- | --- |
| 녹음 전송 | 0~30% | 읽어 보낸 바이트 비율 × 0.3 |
| 분석 대기(`PENDING`) | 30%에서 99% 미만으로 다가감 | 전송 완료 뒤 경과 시간, 시간 상수 4초(763 관측). 상한 0.99라 표시 숫자는 99를 넘지 않는다 |
| 분석 완료(`DONE`) | 100% | 평가 ID 수신. 따라가는 애니메이션 없이 즉시 1로 두고 같은 상태로 결과 화면에 간다 |

전송률을 모르는 경우(이전 녹음의 결과만 기다리거나 분석 재요청)는 기존처럼 붓을 되풀이해 그리고 퍼센트를 숨긴다. 분석 실패 뒤 다시 시도하면 대기 그림을 새로 그리며 분석 대기 경과도 처음부터 센다.
