### TLS 사본 경로 판단

사용자가 고른 "edo1 인증서 사본 동기화"는 기존 config 백업이 이미 하고 있다. 매일 03:20과 배포 전후에 edo1 `/etc/letsencrypt`가 암호화돼 edo2에 도착하고, 11-14 복원 검사에서 복호화가 확인됐다. 그래서 새 키 전송 경로나 deploy hook을 만들지 않고, 승격할 때 최신 config 사본에서 꺼낸다. 사본은 최대 하루 늦다. edo1이 만료 30일 전에 갱신하므로 꺼낸 인증서는 적어도 29일 유효하다.

## 로컬 승격 리허설

서버 리허설은 승인 범위 밖이어서, 런북 4단계의 SQL을 로컬 임시 MySQL 두 대에서 실행했다. Homebrew MySQL 8.4.9(운영 8.4.13), `temp-mysql`로 실행·정리했다. 복제본 기동 옵션은 `replica.compose.yml`과 같다. 원본에는 복제되지 않는 앱 계정을 만들어 edo2 상태(계정 없음)를 재현했다.

| 확인 | 결과 |
| --- | --- |
| 승격 SQL | 원본 종료 뒤 `WAIT_FOR_EXECUTED_GTID_SET` 0 → `STOP REPLICA; RESET REPLICA ALL` → 쓰기 허용 → 앱 계정 생성까지 **117ms**. 앱 계정의 첫 쓰기까지 **166ms**. 원본 50행 모두 보존, 복제 채널 0개 |
| 앱 계정 재생성 | `backup.py`와 같은 `--batch --raw` 출력의 `SHOW CREATE USER`·`SHOW GRANTS`로 계정과 비밀번호 해시가 복원됐다. `--raw` 없이 뽑으면 해시가 이스케이프돼 `ERROR 1827`이 난다. 무작위 비밀번호 계정 200개를 `--raw`로 뽑아 다시 넣으니 200개 모두 한 줄이었고 모두 성공했다. |
| 재시작 후 읽기 전용 | `SET PERSIST read_only=OFF`를 해도 기동 옵션 `--read-only=ON`으로 재시작하면 `read_only=1`로 돌아가고 앱 쓰기가 거부됐다. 옵션을 빼고 재시작하면 `0`이 유지되고 쓰기도 성공했다. → 런북 4-5단계와 [`replica.promote.compose.yml`](../../infra/standby/replica.promote.compose.yml)을 추가했다. |

같은 머신의 소량 데이터 측정이다. 두 호스트 간 지연, 운영 데이터 크기, edo2 컨테이너 재생성 시간은 포함하지 않는다. 8.4.13에서의 재확인은 서버 리허설에서 한다.

## 하지 않은 것과 보류

- **서버 전환·원복 리허설**: 이번 승인 범위가 읽기 전용이어서 실행하지 않았다. 완료 조건의 서버 측 전환·원복 시간은 아직 없다. 579의 32.82초·33.08초는 edo2 내부 스키마 기준이고 DNS·공인 TLS를 포함하지 않는다.
- **인증서·가상 호스트 사전 배치**: 승인받으면 edo2에 런북 6단계를 미리 적용해 둘 수 있다. 그러면 평소에도 `--resolve` 검사가 가능하고 장애 때 2–3분을 줄인다. 사본이 하루 단위로 바뀌므로 갱신 방법(매일 config 사본에서 다시 꺼내기)도 함께 정해야 한다.
- **프록시 로그 회전 교체**: 보류. 서버 변경이 승인 범위 밖이다. 또 현재 로그 파일이 6일 실행 동안 0바이트라 디스크 위험이 없다. stream 프록시는 접속 로그를 남기지 않는다. 교체가 필요한 이유는 `SIGQUIT` 종료 대기와 재생성 정의 일치 정도다. 다음 변경 창에서 [기존 절차](../../infra/docker/README.md#edo1-복제-프록시-전환과-복구)로 적용한다.
- **edo1 앱 장애 때 edo1 Nginx → edo2 중계**: DNS 없이 전환하는 방법이지만 준비·시험하지 않았다. 런북에서는 A 상황을 edo1 자체 복구로 둔다.

## 남은 일

1. 사용자가 [사전 문의](../../infra/standby/failover-runbook.md#사전-문의)를 SSAFY에 보낸다. 답(담당 경로, 처리 시간, 연습 가능 여부)을 이 문서와 런북 전제 표에 반영한다.
2. 연습이 가능하면 서버 리허설 승인을 받는다. 측정 항목은 다음과 같다.
   - 백업 추출, 승격(컨테이너 재생성 포함), 운영 모드 앱 기동, TLS 적용, `--resolve` 검증, DNS 반영의 단계별 시간
   - 원복 데이터 이동·`CHECKSUM TABLE` 대조
   - 리허설은 운영 복제본이 아니라 복제본을 복사한 별도 볼륨으로 한다. 운영 복제가 끊기지 않게 하기 위해서다.
3. 사전 준비(로컬 `edo1-ip` 별칭, edo2에 승격 파일 배치)와 프록시 교체의 변경 창을 정한다.
