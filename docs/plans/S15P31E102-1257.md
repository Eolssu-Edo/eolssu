## 결정 (2026-11-23 우동균)

- 푸시 방식: FCM 토픽 + Firebase 콘솔 발송. Jenkins 발송 잡(서비스 계정 키 필요)과 기기 로컬 알림, 백엔드 발송 API는 고르지 않았다.
- Android 업데이트 흐름: 즉시(immediate) 유지.
- Firebase 설정 파일: 저장소에 둔다.
- Firebase 프로젝트: `eolssu`(ID `eolssu-8f73a`), 크롬에 로그인된 오은서 Google 계정에 만들었다. Google Analytics, Firebase의 Gemini, Google 개발자 프로그램 가입은 껐다. Android `com.ssafy.eolssu`, iOS `com.ssafy.eolssu` 앱을 등록했다.
- Android 인앱 업데이트 실제 동작은 이번에 확인하지 않는다(Play 설치본에서만 동작).

## 검증 (11-23)

- `:shared:testAndroidHostTest` 통과. 업데이트 관련 `StoreUpdateCheckTest` 7개, `AppStoreLookupTest` 6개, `UpdateTopicsTest` 5개 모두 성공.
- `:androidApp:lintRelease` 통과. 새 코드에서 나온 지적은 없다.
- Android 에뮬레이터 `eolssu_capture_api35`(API 35), debug 빌드:
  - Firebase 설정 없이 실행해도 멈추지 않고 Firebase 초기화만 건너뛴다.
  - 첫 실행에 알림 권한 창이 뜨고, 다시 켜면 묻지 않는다. `app_update` 채널(중요도 높음)이 생긴다.
  - Firebase 설정을 넣은 `versionCode` 9 빌드가 `update-android-9`를 구독했다.
  - 앱이 백그라운드일 때 콘솔에서 `update-android-9`로 보낸 푸시가 종 아이콘·`app_update` 채널 배너로 표시되고, 누르면 앱이 열린다.
  - `versionCode` 10으로 덮어 설치한 뒤 처음 켤 때 `update-android-10`을 구독하고 `update-android-9`를 해제했다.
  - 앱을 켠 채로 `update-android-9`로 보낸 푸시는 오지 않았고, `update-android-10`으로 보낸 푸시는 `UpdateNotificationService`가 배너로 띄웠다. 콘솔 게시 뒤 표시까지 약 1분 반 걸렸다.
- 확인하지 않은 것
  - iOS: Windows에서 컴파일할 수 없다. `eolssu-ios-qa`·`eolssu-ios-release`는 develop에 속한 커밋만 빌드하므로 병합 전에는 Mac 빌드를 확인하지 못했다. 병합 뒤 `eolssu-ios-qa`로 빌드와 서명(`aps-environment`)을 확인해야 한다.
  - Android 인앱 업데이트(Play 즉시 업데이트, 진행 중 업데이트 이어 띄우기): Play 설치본이 필요해 확인하지 않았다.
  - 실기기: 연결된 R39M402VJ0H에는 Play 설치본이 있을 수 있어 쓰지 않았다.
