## 범위와 완료 조건

사용자가 edo1에서 Jenkins를 컨테이너로 전환하고 기존 설정·빌드·배포 보존 검증까지 승인했다. 실행 구성은 `/opt/eolssu/jenkins`, 홈은 `/var/lib/jenkins`, 접속은 `127.0.0.1:8080`, 배포 대상은 `/opt/eolssu`를 유지한다. 설정·Credentials·키·플러그인·잡 정의·빌드 이력을 보존하고 전환 전 root 전용 백업과 실패 시 복구 절차를 준비한다.

기존과 같은 Jenkins 2.580.1 공식 이미지의 digest를 고정한다. 컨트롤러는 기존 UID/GID 111:113으로 실행하며 홈 소유권을 바꾸지 않는다. 컨테이너에 Docker 소켓·운영 env·호스트 배포 디렉터리를 mount하지 않는다. 빌드·배포는 기존 `jenkins` 사용자·Docker 그룹·제한된 sudo 권한을 사용하는 같은 서버의 WebSocket 에이전트에서 수행한다. controller executor 1개를 agent 1개로 이동하며 Pipeline의 `agent any`와 기존 명령을 유지한다.

컨트롤러·에이전트 재기동 후 인증·잡·트리거 보존과 실제 빌드·테스트·아티팩트·배포 결과·서비스 응답을 검증해야 완료한다. 동일 SHA 배포가 기존 도구에서 무변경 처리되면 그 결과를 그대로 기록한다. 앱·DB·모니터링은 Jenkins 전환 때문에 재생성하지 않는다.

## 검증 결과

아직 운영 전환하지 않았다. 서버의 다운로드한 이미지 digest는 `sha256:a660310e39ade10631f774bacd5219de767dfd08947ea5c32a739b5e5bb382c1`이다.

| 검사 | 결과 |
| --- | --- |
| 실제 edo1 `docker compose -f - config --quiet` | 통과 |
| 실제 edo1 `systemd-analyze verify` | 통과 |
| 기존 Jenkins API의 등록 스크립트 파싱·DumbSlave 생성자·WebSocket 설정 | 통과. 노드는 등록하지 않음 |
| 일회용 공식 이미지 실제 기동 | network none·tmpfs 홈·UID 111에서 HTTP API와 Jenkins 2.580.1 확인. 운영 홈·포트·잡 미사용 |
| 기존 배포 도구 회귀 검사 | 기준 브랜치의 테스트 5개 통과. 후속 다른 Task의 신규 코드는 포함하지 않음 |
| 보존 대조·복원 검사 | 임시 데이터에서 Credentials·잡·보안 설정의 변경을 감지하고 executor만 바뀌는 경우를 구분. 실제 tar 복원 후 내용·UID 111·GID 113·0600 권한 확인 |
| 기존 설정 보존·실제 빌드·배포 | 선행 서버 작업 종료 후 실행 예정 |

격리 기동에서 공식 이미지의 `COPY_REFERENCE_FILE_LOG`가 기본 홈을 참조해 UID 111에서 쓰기 실패하는 것을 확인하고 기존 홈으로 명시해 기동을 통과시켰다. WebSocket은 `JNLPLauncher(true)`가 아닌 `setWebSocket(true)`로 명시해야 함을 기존 Jenkins API에서 검증했다. 컨트롤러 첫 기동 전에 중단된 `config.xml`의 executor만 0으로 바꿔 quiet-down이 재기동 때 유지되지 않아도 컨트롤러에서 빌드가 시작되지 않게 한다.

## 준비 구성 검토와 대기 조건

준비 구성 8개 파일의 전체 변경·미추적 파일을 자체 검토했다. 요구사항 축은 구성 준비에 한해 충족하며 실제 전환·빌드·배포 증거는 아직 미확보다. 지침 축은 전용 worktree·실제 Jira·Story·스프린트·같은 버전·비밀값 제외를 확인했다. 품질 축은 홈 자동 생성 차단·UID 보존·loopback 공개·agent TCP 포트 비활성·컨트롤러의 Docker 소켓 제외·원래 sudoers 보존·첫 기동 executor 0·전체 백업 복구를 검토했다. 독립 리뷰는 수행하지 않았다.

「nginx 설정 추가」는 MR !24 병합으로 완료됐다. 「Fix Let’s Encrypt 초기화 후 배포」의 프론트 CI 작업은 배포 도구의 sudo 권한 합의 단계에 있어 아직 종료되지 않았다. 사용자의 지시에 따라 해당 작업이 완료될 때까지 운영 Jenkins 중단·quiet-down·설정 변경은 하지 않는다. 전환 스크립트는 `/tmp/eolssu-jenkins76-prepared/eolssu-jenkins76-migrate.py`, 구성은 `/tmp/eolssu-jenkins76-source/infra/jenkins/controller`에만 준비했다. 실제 실행 시 원본 스크립트와 비밀값 없는 영수증을 root 전용 백업에 함께 보존한다.
