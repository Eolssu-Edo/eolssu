## 범위와 완료 조건

사용자가 edo1에서 Jenkins를 컨테이너로 전환하고 기존 설정·빌드·배포 보존 검증까지 승인했다. 실행 구성은 `/opt/eolssu/jenkins`, 홈은 `/var/lib/jenkins`, 접속은 `127.0.0.1:8080`, 배포 대상은 `/opt/eolssu`를 유지한다. 설정·Credentials·키·플러그인·잡 정의·빌드 이력을 보존하고 전환 전 root 전용 백업과 실패 시 복구 절차를 준비한다.

기존과 같은 Jenkins 2.580.1 공식 이미지의 digest를 고정한다. 컨트롤러는 기존 UID/GID 111:113으로 실행하며 홈 소유권을 바꾸지 않는다. 컨테이너에 Docker 소켓·운영 env·호스트 배포 디렉터리를 mount하지 않는다. 빌드·배포는 기존 `jenkins` 사용자·Docker 그룹·제한된 sudo 권한을 사용하는 같은 서버의 WebSocket 에이전트에서 수행한다. controller executor 1개를 agent 1개로 이동하며 Pipeline의 `agent any`와 기존 명령을 유지한다.

컨트롤러·에이전트 재기동 후 인증·잡·트리거 보존과 실제 빌드·테스트·아티팩트·배포 결과·서비스 응답을 검증해야 완료한다. 동일 SHA 배포가 기존 도구에서 무변경 처리되면 그 결과를 그대로 기록한다. 앱·DB·모니터링은 Jenkins 전환 때문에 재생성하지 않는다.
