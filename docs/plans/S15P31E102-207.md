## 작업 순서(세로 조각, 각 조각마다 테스트 포함)

1. **공통 오류 보완:** 공통 처리기 `else` 분기를 상태별 공통 형식으로 막는다(ProblemDetail·이유 문구 노출 방지). 가입·로그인 오류 코드(`EMAIL_NOT_VERIFIED` 401, `INVALID_CREDENTIALS` 401, `TERMS_AGREEMENT_REQUIRED` 422)와 503 일반 문구.
2. **비밀번호:** Argon2id 인코더, 규칙(영문·숫자·특수문자 모두 포함 8~128자) 검증.
3. **토큰 발급과 쿠키:** HS256 access(30분, `sub`=users.id), 임의 256비트 refresh(SHA-256만 저장, 14일), 쿠키 작성·삭제 도우미.
4. **AUTH-02 가입:** verificationToken 1회 소비(SIGN_UP·이메일 일치·30분), 시행 중 필수 약관 전부 현재 버전 동의, 악기·표기 기본값, 409 중복, 201과 로그인 쿠키.
5. **AUTH-01 로그인:** 이메일 없음·비밀번호 불일치·DELETED는 같은 401, 같은 이메일 15분 5회 실패 시 15분 429(서버 메모리), WITHDRAWAL_PENDING은 탈퇴 취소·`withdrawalCancelled`, `last_login_at` 갱신.
6. **AUTH-04 재발급:** 회전(ROTATED), 폐기된 토큰 재사용 시 그 회원 토큰 전부 폐기(REUSE_DETECTED), ACTIVE가 아니면 401.
7. **AUTH-03 로그아웃:** 현재 refresh 폐기(SIGN_OUT)와 두 쿠키 삭제.
8. **SMTP 연결:** 발송을 잠금·트랜잭션 밖(커밋 뒤)으로 옮기고, 발송 예외를 `VerificationMailUnavailable`로 바꾼다. 변수·문서.

### 계획과 다른 점

- **SMTP 발송 위치:** 계획은 발송을 잠금·트랜잭션 밖(커밋 뒤)으로 옮기는 것이었다. 가입 발송 실패 때 새 행·이전 번호 무효화를 롤백한다는 기존 합의를 지키려면 커밋 뒤 발송에 보상 처리가 필요해, 발송은 트랜잭션 안에 두고 SMTP 시간 제한(연결 3초·읽기/쓰기 5초)으로 잠금 시간을 묶었다. 하루 100통 안쪽 규모라 충분하다.
- **응답 시간 차이:** 재설정·계정 연결은 회원에게만 실제로 보내 응답 시간이 다를 수 있다. 가입 인증번호 409가 이미 가입 여부를 알리므로(명세) 추가 노출은 작다고 보고 그대로 둔다.
- **명세에 없던 세부:** 로그인 429에 `result.details.retryAvailableAt`, 재발급 401 때 쿠키 삭제, 로그아웃은 그 회원의 토큰만 폐기. Notion 명세에 반영했다.
- **`AUTH_MAIL_MODE`:** 기본값이 `unavailable`에서 `smtp`로 바뀌었다. 인프라 compose는 이 변수를 넘기지 않으므로 SMTP 값만 있으면 발송된다. `unavailable`을 명시하면 항상 거절한다.
- **테스트 시각:** access_token 만료는 실제 시각으로 검증하므로, 로그인 뒤 보호 경로를 부르는 DB 테스트는 고정 시계 대신 실제 시각으로 발급한다.
