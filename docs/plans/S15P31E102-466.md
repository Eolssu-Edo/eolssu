## 배경

access_token은 30분 동안 서명만으로 통과한다. `ActiveMemberFilter`는 회원 상태(ACTIVE)만 보므로 로그아웃·비밀번호 변경·재설정·refresh 재사용 탐지로 refresh를 폐기해도, 이미 발급된 access_token은 만료까지 보호 API를 부를 수 있다. 같은 필터가 요청마다 `users.status`를 DB에서 읽는다.

## 바뀌는 동작

| 상황 | 지금 | 바뀐 뒤 |
| --- | --- | --- |
| 로그아웃한 기기의 access_token | 만료까지 200 | 바로 401 `UNAUTHENTICATED`, 쿠키 삭제 |
| 비밀번호 변경 전 다른 기기의 access_token | 만료까지 200 | 바로 401. 변경한 기기는 새 토큰으로 유지 |
| 비밀번호 재설정·refresh 재사용 탐지 뒤 그 회원의 access_token | 만료까지 200 | 바로 401 |
| refresh 회전 | 새 토큰 쌍 | 같음. 같은 세션 ID를 이어받아 이전 access_token도 만료까지 유효 |
| 배포 전에 발급된 sid 없는 access_token | — | 만료(최대 30분)까지 지금처럼 허용 |

## 설계

1. **세션 ID:** `refresh_tokens.session_id`(V23)를 둔다. 로그인·가입·간편 로그인으로 새 세션을 만들 때 무작위 값을 정하고, refresh 회전은 이전 행의 값을 이어받는다. 기존 행은 행마다 다른 값으로 채운다.
2. **access_token `sid` 클레임:** 발급할 때 세션 ID를 넣는다.
3. **세션 확인:** 같은 회원·세션 ID에 폐기되지 않고 만료 전인 refresh 행이 있으면 활성이다. 인증 필터가 회원 상태와 함께 확인하고, 활성이 아니면 지금 탈퇴 대기 회원과 같은 401과 쿠키 삭제로 답한다.
4. **캐시:** 회원 상태와 세션 활성 여부를 Caffeine에 짧게(10초) 둔다. refresh를 폐기하거나 회원 상태를 바꾸면 트랜잭션 커밋 뒤에 그 회원의 캐시를 지운다. 커밋 전에 지우면 동시 요청이 옛 값을 다시 채울 수 있다. 10초는 서버가 여러 대일 때 다른 서버의 캐시가 늦게 바뀌는 최대 시간이다.

## 검증 기록

- 커밋 `1594a20e`(세션 ID·sid·필터 확인): `TokenRefreshApiDatabaseTests`의 로그아웃·재사용 탐지 검사가 구현 전 실패(컬럼 없음, 탐지 뒤 200) → 통과. sid 없는 토큰 허용 검사는 기존 동작 보호용이라 처음부터 통과한다.

- 캐시: `AuthSessionCacheTests` 3건이 구현 전 컴파일 실패 → 통과(만료 전 1회 조회, 회원 단위 삭제, 커밋 뒤에만 삭제).

- 일부러 깨 본 검사: 세션 확인을 끄면 로그아웃·재사용 탐지·비밀번호 변경 검사 3건, 로그아웃의 캐시 삭제를 빼면 로그아웃 검사 1건이 실패했다.
