# Jenkins·QA 도구의 저장소 연결을 SSAFY GitLab에서 GitHub로 전환 (S15P31E102-1290)

- 상태: develop 쪽 구현·검증 완료, 커밋 전
- 브랜치: `chore(infra)/S15P31E102-1290-Jenkins·QA-도구의-저장소-연결을-SSAFY-GitLab에서-GitHub로-전환` (base `ea1fc1e85`), blog 쪽은 같은 Key의 별도 브랜치

## 배경

2026-11-26 코드 저장소를 SSAFY GitLab에서 GitHub `team-edo/eolssu`(Public)로 옮겼다. 브랜치·커밋은 그대로이고 기본 브랜치는 `develop`, 병합은 PR(merge 커밋)로만 한다. SSAFY 서버·도메인·Mattermost는 과정 종료와 함께 없어지며 새 서버는 따로 구축한다.

## 범위

| 대상 | 바꾸는 내용 |
| --- | --- |
| Jenkinsfile·잡 등록 스크립트 | 클론 주소를 `https://github.com/team-edo/eolssu.git`, 인증 정보 ID를 `eolssu-github`로 |
| QA 폰 APK 게시 | merge 커밋의 `Merge pull request #N`에서 PR 번호를 읽는다 |
| QA 폰 MR 정보 동기화 | GitHub GraphQL로 PR 제목·작성자를 10개씩 읽는다. 인증은 `Authorization: Bearer` 헤더, 리디렉션 거부 유지 |
| tool-updates | 허용 저장소 주소를 GitHub로 |
| 릴리스 노트 | `release-candidate.py notes`가 GitHub PR 병합 커밋(`Merge pull request #N from team-edo/<브랜치>`)도 병합 작업으로 읽는다. 예전 GitLab 병합 기록도 계속 읽는다 |
| 릴리스 절차 | main은 PR이 아닌 관리자 fast-forward Push로 RC SHA에 맞춘다(PR은 merge 커밋만 만들도록 설정함) |
| 문서 | 루트 README의 제출 문서 링크, 운영 README의 클론·인증 정보 안내 |

범위 밖: 새 서버 구축, 도메인 교체, Mattermost 봇 폐기(`infra/edo-check`는 폐기 예정이라 손대지 않음), `docs/`의 지난 MR 링크(과거 기록), `.gitlab/` MR 템플릿의 GitHub 이전.

## 결정

- QA 보관함은 새 서버에서 비어 있는 상태로 시작한다(2026-11-26 사용자 결정). 그래서 `index.json`의 `mergeRequests`·`mergeRequestDetails` 필드 이름과 화면 코드는 그대로 두고 값만 GitHub PR 번호로 채운다. 예전 GitLab 번호가 남은 보관함을 그대로 옮기면 다른 PR 제목이 붙으므로 옮기지 않는다.
- 동기화 토큰은 GitHub fine-grained PAT(`team-edo/eolssu`, Pull requests 읽기)이다. GraphQL은 공개 저장소도 인증이 필요하다.

## 완료 조건

1. 운영 코드(`infra/`, 폐기 예정 `edo-check` 제외)에 `lab.ssafy.com`·`eolssu-gitlab`·GitLab API 참조가 없다.
2. QA 폰 Python 테스트와 tool-updates 테스트가 GitHub 기준으로 통과한다.
3. 서버 반영(인증 정보 등록·토큰 파일·서비스 재설치) 절차가 해당 README에 있다.
