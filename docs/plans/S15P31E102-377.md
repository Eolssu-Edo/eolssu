## Shared 프레임워크 연결 확인

`Config.xcconfig`에 구성·SDK별 framework 검색 경로와 `-framework Shared`를 추가했다. 공통 UI·API·녹음 기능 코드는 변경하지 않았다.

## 개발 인증서 발급과 키체인 서명 확인

2026-11-02 사용자가 Apple Development 인증서 발급과 이 Mac 키체인에 개인키 저장을 명시적으로 승인했다. 수동 메뉴가 비활성화된 상태여서 Xcode 자동 서명으로 진행했다.

```sh
xcodebuild -quiet -project frontend/iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug -destination 'generic/platform=iOS' -derivedDataPath /private/tmp/eolssu-ios-377-derived -allowProvisioningUpdates build
```

이 빌드는 `Your team has no devices from which to generate a provisioning profile` 및 해당 Bundle ID의 profile 부재로 종료 코드 65를 반환했다. 다만 인증서는 비동기로 생성됐으며 Xcode 인증서 목록에서 새 항목을 확인했다. 제한된 명령 실행 환경에서의 최초 `security find-identity`는 0개를 반환했으나, 시스템 키체인에 접근 가능한 실행 환경에서 재확인한 결과 유효한 Apple Development ID 1개였다. 이 차이를 인증서가 없다는 근거로 사용하지 않는다.

원본 빌드 산출물을 보존하고 `/private/tmp/eolssu377-codesign-q47ajytj/eolssu.app` 복사본에 해당 서명 ID로 `codesign --force --sign <발급된 서명 ID> --timestamp=none`을 수행했다. 이후 `codesign --verify --strict --verbose=2`는 종료 코드 0으로 통과했다. 서명 상세의 Authority는 Apple Development 및 Apple 인증서 체인, TeamIdentifier는 로컬 설정의 무료 팀과 일치했다. 이 결과는 인증서와 연결된 개인키가 실제 서명에 사용 가능함을 입증한다. 개인키는 내보내지 않았다.

`embedded.mobileprovision`은 없다. 따라서 이 복사본은 로컬 서명 검증용이며, iPhone 설치·실행 가능한 배포본으로 보고하지 않는다. 다음 단계는 이 Mac에 iPhone을 연결·신뢰·개발자 모드 설정하고 Xcode로 기기를 등록한 뒤 같은 자동 서명 빌드로 profile을 생성하는 것이다. 그 전에는 실제 iPhone API 검증을 완료할 수 없다.
