- 복구 후: 곡 93 PUBLISHED·음원 PUBLISHED(원래대로), 곡 139 HIDDEN·음원 DRAFT(지우지 않음, 연습 기록 보존).

- 실행(운영 서버 bash, 사용자): 네 행이 정확히 바뀔 때만 COMMIT한다.

```bash
C=$(sudo /opt/eolssu/bin/deploy-backend --active-container 2>/dev/null || echo eolssu-runtime-backend-1); DB=$(sudo docker inspect "$C" --format '{{range .Config.Env}}{{println .}}{{end}}' | sed -n 's#^DB_URL=jdbc:mysql://[^/]*/\([A-Za-z0-9_]*\).*#\1#p'); echo "START TRANSACTION; UPDATE songs s JOIN song_model_audios a ON a.song_id=s.id SET s.status='PUBLISHED', a.status='PUBLISHED' WHERE s.id=93 AND s.source='mr203-fixed-sogeum-005-p1' AND s.status='HIDDEN' AND a.status='DRAFT' AND s.deleted_at IS NULL; SELECT ROW_COUNT() INTO @a; UPDATE songs s JOIN song_model_audios a ON a.song_id=s.id SET s.status='HIDDEN', a.status='DRAFT' WHERE s.id=139 AND s.source='s15p31e102-1227-sogeum-doraji-8gak' AND s.status='PUBLISHED' AND a.status='PUBLISHED' AND s.deleted_at IS NULL; SELECT ROW_COUNT() INTO @b; SELECT IF(@a=2 AND @b=2,'restored','NOT EXPECTED, rolled back') AS result, @a, @b; SET @sql=IF(@a=2 AND @b=2,'COMMIT','ROLLBACK'); PREPARE s FROM @sql; EXECUTE s; SELECT s.id,s.title,s.status,a.status,s.is_scorable FROM songs s JOIN song_model_audios a ON a.song_id=s.id WHERE s.id IN (93,139) ORDER BY s.id;" | sudo flock -w 120 /run/lock/eolssu-backend-deploy.lock docker exec -i eolssu-runtime-mysql-1 sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql --no-defaults --skip-reconnect --default-character-set=utf8mb4 --user=root --batch --skip-column-names --database="$0"' "$DB"
```

- 정상 출력: `restored 2 2`, `93 도라지타령 PUBLISHED PUBLISHED 1`, `139 도라지타령 HIDDEN DRAFT 1`.
- 확인: 공개 API `GET /api/songs/93`이 200, `/api/songs/139`가 404이고, 앱 소금 목록에 원곡 도라지타령이 보이며 열린다.
