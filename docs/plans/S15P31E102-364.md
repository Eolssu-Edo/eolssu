## 범위와 순서

1. V14에서 nullable FK와 연결 근거를 추가한다. 기본음만 연결하고 기존 행은 null로 유지한다.
2. 실제 파일·명시적 매핑을 검증하는 별도 CLI로 `(yul, octave)`를 해석한다. 단소 기본음 30개 매핑을 기록한다.
3. 조회 API에 nullable 문자열 `pitchId`와 선택 필터를 추가한다. 재생·검수·채점 상태는 보존한다.
4. Python 단위/실제 MySQL, Kotlin clean build/databaseTest, 실제 430개 매핑을 검증하고 계약·운영 절차를 갱신한다.

## 완료 조건

- 고아 FK·시김새 연결·근거 없는 연결을 DB에서 거부한다.
- 여러 클립이 같은 기준 음에 연결되며 목록 필터와 상세의 `pitchId`가 일치한다.
- 매핑 충돌·없는 pitch·파일 불일치는 배치 전체를 거부한다. 재실행과 기존 import는 연결·게시·검수 상태를 유지한다.
- 실제 430개 중 30개만 연결, 400개 null, inferred/채점 제외를 유지한다.
- 운영 반영·R2 쓰기·Push는 하지 않는다. 외부 Jira/Notion/MR 정리는 부모 작업에서 담당한다.
