# S15P31E102-1003 카메라로 찍은 악보를 문서 스캔본으로 바꿔 올리기

- Story S15P31E102-317 · 활성 스프린트 5 · 진행 중
- 기준 develop 8a63cb426. 997의 가져올 곳 메뉴와 998의 변환 대기 화면을 사용한다.

## 범위와 완료 조건

1. Android와 iOS의 악보 가져올 곳에 카메라로 스캔을 추가한다. 웹 파일 선택기는 기존대로 연다.
2. Android ML Kit 문서 스캐너, iOS VisionKit의 자르기·원근 보정 화면에서 확정한 JPEG를 촬영 순서대로 받는다. 앱이 해상도를 따로 줄이지 않는다.
3. 기존 업로드 계약인 최대 10장과 합계 20MiB를 적용한다. 취소와 실패는 선택 결과를 통해 처리해 기존 첨부가 있으면 유지하고 다시 시도할 수 있게 한다.
4. Android APK·Wasm 빌드와 공유 테스트를 실행한다. 카메라 촬영, 보정, 업로드, 변환을 지원 Android 기기에서 확인한다. iOS는 Mac·기기 검증 전까지 미확인으로 기록한다.

## 플랫폼 근거

- [Android ML Kit 문서 스캐너](https://developers.google.com/ml-kit/vision/doc-scanner/android)
- [Apple VisionKit 문서 카메라](https://developer.apple.com/documentation/visionkit/vndocumentcameraviewcontroller)

## 구현과 검증

- Android는 ML Kit의 JPEG 결과를 촬영 순서대로 기존 제한 검사와 업로드 흐름에 넘긴다. iOS는 VisionKit의 보정된 쪽을 JPEG로 인코딩한다. 두 구현 모두 앱에서 픽셀 크기를 따로 줄이지 않는다.
- 공유 테스트 1,914개 중 1,909개 통과, 5개 건너뜀, 실패·오류 0건. Android 디버그 APK와 Wasm 컴파일 성공. iOS 카메라 권한 문구가 들어간 Info.plist XML 파싱 성공.
- Android 15 emulator-5558 새 APK에서 가져올 곳에 파일·갤러리·카메라로 스캔이 보였고 스캔 선택 시 Google Play 서비스 모듈 다운로드 화면으로 이동했다. 두 번 모두 “Something went wrong / Try again later”가 표시됐다. 첫 실패 후 앱의 기존 올리기 화면으로 돌아오는 것을 확인했다.
- Android의 실제 촬영→보정→업로드→변환은 모듈을 설치할 수 있는 기기에서 재확인해야 한다. iOS 빌드와 카메라 실행은 Mac·기기에서 미검증이다.
