## 순서와 완료 조건

① 원본 율명·옥타브로 운지 연결 및 미지원 음·쉼 구분: 회귀 red → green.
④ 대강 2개 고정 페이지와 다음 음 2개 미리보기: 사용자 확인 완료. 경계·탐색 검사와 UI 확인.
② 장음·빈 자리 운지 제거: 표시 자리별 높이·연결 보존 검사.
③ 한글 가사만 대응 위치에 표시: 토큰 위치·원본 불변 검사.

검증 명령은 frontend Gradle 설정과 README의 `:shared:testAndroidHostTest`, `:shared:jsTest`, `:shared:wasmJsTest`, `:androidApp:assembleDebug`를 따른다. 실행 결과·미확인 상태는 이 문서에 기록한다.

## 원인

`PracticeFingeringPage.fingerCells`가 SourcePitch를 17개 항목의 `Yul`로 변환한 뒤 운지를 조회한다. 청고 등 실제 내장표에 있는 음도 변환이 null이 되고, `FingerCell.rest`가 null을 쉼으로 취급한다. `NoteLine`도 같은 변환으로 음 여부를 판단한다. 내장표와 원본의 중청·배성 이체자도 문자열 완전 일치로는 연결되지 않는다.

## 검증 기록

- ① `finger-red.log`: Android host 회귀 3개 중 청고·전체 내장표 연결 2개 assertion 실패를 재현했다. 의미 기준 연결 후 `finger-green.log`의 3개가 통과했다. 내장표 4악기 92행을 모두 대조하며, 원본 구멍 상태 자체는 변경하지 않았다.
- ④ `paging-red.log`: 신규 페이지 함수 미구현을 컴파일 오류로 확인했다. `paging-green.log`에서 운지 3개·페이지 5개, 총 8개 통과. 3정간/9소박 환산, 곡별 검수 tick 연결과 못갖춘마디, 페이지 경계와 역방향 탐색, 쉼·장음 제외 다음 발음·같은 음 반복·마지막 페이지를 확인했다.
- ② `hold-red.log`: 같은 정간의 음·장음·빈 자리·쉼·새 음을 포함한 검사에서 장음 그림이 남는 assertion 실패를 재현했다. 표시 슬롯은 유지하고 장음·빈 자리 그림만 제거했으며 `hold-green.log`의 운지·페이지 9개가 통과했다.
- 자동 승인 검토의 사용량 제한으로 페이지 green 명령이 한 차례 실행되지 않았고, 사용자의 계속 진행 요청 후 재실행해 통과했다.

## 브라우저 실행 증거

- 실제 `school-textbook-sogeum-p16.score.json`에 원본 JGB의 가사를 좌표별로 붙인 임시 자료로, 제품의 `PracticeFingeringPage`·`JeongganboView`를 그대로 띄웠다. 검증 후 임시 자료·Composable·웹 진입점 변경을 제거하고 원래 App 진입점으로 복원했다.
- 390×844·320×720에서 청고가 실제 `100000` 운지로 표시되고 두 대강 페이지와 다음 음 두 개가 수평 넘침 없이 보였다. 도라지 3페이지의 장음 두 자리는 그림 없이 비어 있고, ‘라’가 청태의 세 번째 자리 옆에 정렬됐다. 일반 정간보 곁줄에서도 기호 없이 한글 음절이 해당 소박 줄에 표시됐다.
- 합성 공통 악보는 동일 정간 안의 1.0·1.5 onset과 1.5 페이지 경계를 사용했다. 다음 음 선택 시 1→2페이지, 이전 음 선택 시 2→1페이지 복귀를 실제 브라우저 상태로 확인했다. 원본 도라지의 모의 연주 상태에서 1→2페이지 자동 전환도 확인했다. 오디오·마이크·서버 API 호출 검증은 아니다.
- 화면 증거(Git 제외): `frontend/build/practice-fingering-500/practice-fingering-holds.jpg`, `practice-fingering-fractional.jpg`, `practice-lyric-lane.jpg`.
- 브라우저 개발 로그 조회에서는 개발 서버 WebSocket 재연결 메시지를 관찰했다. 키보드 자동 조작은 Compose 접근성 요소의 입력 준비 단계에서 실패해 키보드 검증으로 세지 않는다. Android·iOS 실기기 및 전체 앱 E2E는 미실행이다.

## 정리와 결과

요청한 1→4→2→3 순서의 운지 연결·고정 페이지·장음 그림 제거·가사 정렬을 구현했다. 초기 분수 대강 fallback을 정확한 두 대강 페이지로 보완해 원요청의 표시 결과를 유지했으며 제품 범위의 이탈은 없다. 원본 데이터·타이밍은 유지했다. 장단 정보 자체가 없는 악보는 스펙대로 각 경계를 보존 단위로 쓴다.

`cleanup-build.log`에서 임시 파일 제거 후 실제 App 진입점의 `:androidApp:assembleDebug :webApp:compileKotlinJs :webApp:compileKotlinWasmJs`가 성공했다. 임시 웹 진입점·검증 자료의 diff는 남기지 않았다. 문서 링크와 `git diff --check`도 확인했다.

이 Task의 12개 파일만 작업 단위 커밋한다. Push·MR·운영 반영은 수행하지 않으며 Jira는 진행 중으로 유지한다. 최종 미완료 범위는 기존 JS 497 실패 통합, Android·iOS 실기기·전체 앱 E2E 및 키보드 확인이다.
