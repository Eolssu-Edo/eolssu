## 검증·결정

`coco-debug`와 `coco-docs`를 적용했다. 원래 기대는 Wasm 지연과 backend 전체 시간의 설명이며, 실제로 기존 실행에서 대기와 실행 비용을 분리했다. 구현 최적화·재빌드·운영 변경은 이번 진단에 포함하지 않았다.

SSH 읽기 전용 조사와 기존 완료 빌드 재계산을 수행했다. 전체 앱·컨테이너·테스트를 새로 실행하지 않았다. 현재 설치 Pipeline 해시는 증거 JSON에 기록했다. 원본 저장소와 inline 잡을 혼동하지 않는다. Jira는 진행 중이며 Push·MR·완료 전환을 수행하지 않았다.

문서의 SSH 명령을 그대로 실행해 backend #259·frontend #186의 네 시간 필드가 보존 JSON과 정확히 같음을 확인했다. 7개 빌드의 시간 분해, 새 문서의 상대 링크 6개, Markdown 공백과 `git diff --check`를 통과했다. Gradle 버전 고정 문서 URL은 조회 도구로 확인되지 않아 같은 설명을 확인한 공식 current 문서로 연결했다. 독립 읽기 전용 문서 검토에서도 수치·대기 구간·중단 시간의 해석·소스 대조·재현 코드에 수정할 문제를 찾지 못했다. 검토자는 운영 원본을 재조회하지 않고 보존 증거를 검토했다.

### 구현 상태

구현 커밋 `87e46457`. 단계와 Gradle task를 합치지 않고 JVM을 재사용한다는 설계대로 구현했다. 운영 적용과 전체 앱 성능 확인은 아직 수행하지 않았다.

독립 검토의 P3는 Docker 검증 중 SIGTERM이 검사용 정지 컨테이너 정리를 끊는 문제였다. 복사 중단이 잔여 컨테이너 assertion으로 실패하고, 첫 보완 뒤 삭제 중 신호는 종료 유예 assertion으로 실패했다. 고유 이름·라벨·SIGTERM 종료 처리와 삭제 중 신호 유예를 적용해 두 검사 모두 통과했다. 실제 Docker 두 중단 지점에서도 종료 143·컨테이너 0개·임시 context 0개를 확인했다. 최종 Jenkins 도구 58개 통과, 배포 hook 및 Jenkinsfile linter는 이전 통과 증거를 재사용한다. 검증 전용 tag와 임시 디렉터리는 정리했다.

최종 독립 재검토에서 복사·삭제 중단 경로가 해결됐고 추가 수정 사항이 없음을 확인했다. 코드·격리 실행 검증은 완료했다. 실제 전체 CI 단축 시간과 운영 적용은 develop 병합 후 확인할 항목으로 남긴다.
