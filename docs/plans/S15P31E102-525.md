### 보류 및 미완료

- **사용자 보류 결정:** 정간보 업로드 장단 선택 시점. 화면은 인식 후 선택, API는 업로드 시 필수. 업로드 전 장단 UI 추가 또는 서버 계약 조정 중 결정 필요. 임의 기본값을 보내지 않는다.
- SHT-07·10·14 실제 파일 접수·변환·재시도 화면 경로 미연결.
- SHT-08·04·11 서버 악보·초안 복원과 편집 저장 미연결. 가변 각 길이·분할·원본 ID·버전 충돌 보존 작업 필요.
- PRA-06 기준 조회 미연결. develop의 ManualStepNoteJudge 대역을 실제 판정기로 바꾸고 기준을 적용해야 한다.
- SHT-12·13 기존 FE 연결은 유지. 최신 develop에 BE 481이 병합됐으나 실제 서버 악보부터 음원까지의 전체 경로는 미검증.
- 내부 인식 API는 BE 전용, SHT-03 생성 API는 취소됐으므로 FE 신규 연결에서 제외. 해당 예시 화면은 이번 MR에서 수정하지 않음.

## 계약과 완료 조건

열린 [Notion API 명세서](https://app.notion.com/p/API-3fea0252aa45804cb9f0f896ec0310ad)의 2차 항목 14개와 저장소의 최신 서버 구현을 대조했다. 구체 계약은 [내 악보](../specs/user-sheets.md), [평가 상세](../specs/evaluation-detail-apis.md), [한 음 연습 기준](../specs/note-practice-criteria.md)을 따른다.

| API | 시작 시 상태 / 처리 |
| --- | --- |
| SHT-01·02 | 예시 목록·로컬 삭제 → 인증 서버 목록·삭제 |
| SHT-04·08·11 | 예시 편집·저장 안내 → 서버 악보·초안 복원과 버전 충돌을 지키는 저장 |
| SHT-07·10·14 | 예시 파일·고정 진행률 → 실제 파일 접수·상태 조회·서버 허용 재시도 |
| SHT-12·13 | 기존 API 구현 재사용. 편집의 실제 서버 ID 연결, BE는 명세상 구현 중 |
| PRA-06 | 기준 조회 계약 확정. 실제 음높이 판정기는 develop에서 ManualStepNoteJudge 대역이므로 음 인식 완성으로 보고하지 않음 |
| EVA-04 | 이전 comparable 계약 → scoreComparable/errorComparable 분리 및 서버 점수 반영 |
| 내부 POST /v1/recognitions | BE 전용. FE 직접 호출하지 않음 |
| SHT-03 POST /users/me/sheets | 취소·서버 제거. 빈 악보·복사 생성 호출을 되살리지 않음 |

예시 성공·다른 곡 악보 대체를 금지하고, 로딩·실패·재시도를 실제 요청 상태로 표시한다. 계정 변경 시 이전 데이터와 요청을 폐기한다. 서버 ID·scoreVersion·draftRevision 및 악보의 음표 식별자와 원본 메타데이터를 보존한다. 서버 구현이 없는 동작을 연결 완료로 보지 않는다.
