# S15P31E102-1000 악보 편집 임시저장 닫기 지연과 빠르기 입력 창 흔들림 수정

- Jira: S15P31E102-1000 · 진행 중 · Story S15P31E102-319. 브랜치 `fix(fe)/S15P31E102-1000-악보-편집-임시저장-닫기-지연과-빠르기-입력-창-흔들림-수정`, 기준 `origin/develop` `747a559d`.
- 계기: 사용자가 악보 편집(가져온 악보 변환 포함)에서 `임시저장하고 닫기`를 누르면 나가기까지 매우 느리고, 정간보 편집의 빠르기 설정에서 목표 빠르기 숫자를 누르거나 입력하면 설정 창이 흔들린다고 지적했다.

## 범위와 완료 조건

1. `임시저장하고 닫기`를 누른 뒤 닫힐 때까지 걸리는 시간을 재고, 원인을 찾아 줄인다.
2. 저장하는 동안 확인 창에 `임시저장하는 중…`을 보이고, 모든 버튼과 창 닫기를 막아 중복 저장을 막는다.
3. 저장에 실패하면 화면을 떠나지 않고 확인 창을 유지해 다시 고를 수 있게 한다.
4. 빠르기 설정 창에서 목표 빠르기를 누르거나 입력해도 창이 흔들리지 않는다.

저장 형식·API 계약은 바꾸지 않는다. 다음 Task 1001이 같은 `SheetEditRoute.kt`·`EditInputPanel.kt`를 고치므로 저장·빠르기 입력에 필요한 부분만 바꾼다.

## 원인

- 임시저장 닫기: `SheetEditViewModel.persist`가 화면 코루틴(`viewModelScope`, Android 메인 스레드)에서 공통 악보 변환·원본 해시·JSON 직렬화와 Ktor 요청 본문 직렬화를 했다. 앱을 새로 띄운 뒤 첫 저장에서 직렬화 코드가 처음 실행되며 메인 스레드가 약 2.4초 멈췄다. 같은 프로세스의 두 번째 저장은 0.3초였다. 또 버튼을 누르자마자 확인 창을 닫아, 기다리는 동안 아무 표시 없이 편집 화면이 멈춘 것처럼 보였다.
- 빠르기 창 흔들림(코드 대조): `EolssuDialog`는 `usePlatformDefaultWidth = false`에 기본값 `decorFitsSystemWindows = true`를 쓰면서 `imePadding()`도 넣었다. 이 조합에서는 키보드가 올라올 때 시스템이 창 크기·위치를 바꾸고 Compose도 여백을 넣어 같은 키보드를 두 번 처리한다. Compose `DialogProperties` 문서도 이 경우 `decorFitsSystemWindows = false`를 권하며 키보드 애니메이션 중 화면 깨짐을 언급한다(`androidx.compose.ui:ui-android` 1.12.1 `AndroidDialog.android.kt`). 빠르기 창은 길어서 화면 높이를 다 쓰므로 창 크기가 바뀔 때마다 내용 재배치와 입력 칸 스크롤이 겹쳐 흔들림이 크게 보인다.

## 변경

- 저장 본문 만들기·직렬화·전송을 `saveDispatcher`(앱은 `Dispatchers.Default`)에서 한다. 작업 스레드에서 화면 상태를 바꾸지 않도록 버전·리비전·표현 정보는 전환 전에 읽는다. 테스트처럼 넘기지 않으면 전과 같이 화면 코루틴에서 한다.
- 닫기 확인 창은 저장 중에도 남아 `임시저장하는 중…`을 보이고 세 버튼과 창 닫기를 막는다(`closeSaving`). 성공하면 창을 닫고 화면을 떠나며, 실패하면 버튼이 다시 살아나고 기존 `임시저장하지 못했어요` 문구로 남는다.
- `EolssuDialog`: Android는 `decorFitsSystemWindows = false`(expect/actual `eolssuDialogProperties`)로 시스템이 창 크기를 바꾸지 않게 하고, 화면 크기 상자 안에서 `safeDrawing`(시스템 바·키보드) 여백과 가운데 정렬을 한다. 창이 화면을 덮으므로 바깥 누름 닫기는 상자에서, 창 안 누름은 카드에서 받는다. iOS·Web은 창 설정을 바꾸지 않았다.
