# S15P31E102-689 내 악보 편집에서 제목과 기본 빠르기 변경

- 관련 Story S15P31E102-319, Sprint 5 진행 중. 기준 `origin/develop` `8d958652`, 별도 작업공간에서 시작.
- 내 악보 편집에서 제목과 기본 BPM을 바꾼다. 제공 곡을 복사해서 열면 같은 개인 악보 편집기가 적용된다. 제목은 앞뒤 공백을 뺀 1~50자(유니코드 코드포인트), 빠르기는 30~160 BPM의 정수다. 악보의 기존 BPM 단위를 사용한다.
- 다이얼로그에서 적용하면 두 값이 한 번에 바뀌어 실행 취소와 다시 실행을 함께 지원한다. 취소하면 입력을 버린다. 기존 SHT-11 초안과 SHT-04 확정 저장을 재사용한다. 기본 BPM을 바꾼 뒤에는 새 음원을 요청하기 전에 악보를 확정 저장한다.

## 작업 계획

1. 편집 화면에 제목과 빠르기 입력을 연결하고, 기존 초안 및 확정 요청에 값이 들어가도록 한다.
2. 변경한 빠르기가 확정되기 전에는 음원 생성을 막고 저장 이후 요청에 새 빠르기를 보낸다.
3. Android 호스트 검사에서 입력 범위, 실행 취소, 초안·확정 저장, 음원 생성의 요청 조건을 확인하고 Android 디버그 앱을 빌드한다.

## 구현과 검증

- 편집 도구줄의 연필 버튼으로 제목·빠르기 창을 연다. 적용할 때 한 편집으로 저장하고, 창을 취소하면 입력을 버린다. 기존 저장 흐름을 사용한다는 계획대로 서버 계약 변경 없이 구현했다.
- 기본 BPM 변경을 초안에만 저장한 경우 음원 요청이 전송되는 회귀를 재현했다. 확정 저장으로 새 버전을 받은 뒤에는 새 BPM을 담아 요청하는 것을 검사했다. 제목 검사는 한글 49자와 보조 평면 문자 한 자를 50자로 처리하고, 변경 후에도 원본 BPM 단위와 이벤트 타이밍이 유지되는 것을 확인했다.
- `frontend`에서 `gradlew.bat :shared:testAndroidHostTest :androidApp:assembleDebug --max-workers=2 --console=plain` 통과. 호스트 테스트 1,226개 중 1,222개 통과, 기존 외부·자료 의존 검사 4개 건너뜀, 실패·오류 없음. 새 회귀 검사 2개 통과.
- `frontend/androidApp/build/outputs/apk/debug/androidApp-debug.apk`를 생성하고 `apksigner verify --verbose`로 v2 서명을 확인했다. 웹·iOS 실행은 확인 대기다.
- Android API 37 에뮬레이터에서 로컬 악보의 제목과 기본 BPM을 함께 바꿨다. 96 BPM과 변경한 제목이 표시되고, 실행 취소 한 번으로 원래 제목·60 BPM이 복원됐다. 확정 저장 요청과 초안 복원은 호스트 테스트로 확인했다.
