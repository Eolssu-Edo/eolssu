## 구현과 게시

- 새 결과별 브랜치는 최신 origin/develop에서 만들고 필요한 선행 결과를 통합한다. 모든 MR 대상은 develop이다. 선행 MR 및 해당 Task 자체의 비교 범위를 본문에 적는다.
- 기존 !622·!623·!624와 로컬 통합본은 변경 전 근거로 보존한다. 새 MR 확인 후 기존 MR에 대체 링크를 기록하고 중복 병합을 막도록 닫는다. 공유 브랜치를 강제로 다시 쓰지 않는다.
- MR 제목은 최신 사용자 요청에 따라 기존 형식인 `타입(파트): 결과 (전체 Jira Key)`를 사용하고, 본문은 실제 완료 Task의 `Closes`를 사용한다. 각 결과의 검증·제약을 기록하고 사람이 승인·병합하도록 둔다.
- MR 라벨은 프로젝트에 이미 있는 이모지 라벨만 사용한다. 분할을 위해 임의의 새 라벨을 만들지 않는다.
- 공유 파일은 기능별 변경 부분을 분리한다. 코드만 옮기고 테스트·배포 리소스·오류 계약을 누락하지 않는다. API/데이터 계약 소비자까지 필요한 최소 범위는 하나의 결과에 포함한다.
- 격리 worktree에서 결과별 빌드와 집중 회귀 후, 최종 통합본을 기존 구현과 대조한다. 실제 API→CAT, 가중 음가·반복·변속→기기 장구 회귀를 통합 관문으로 둔다.
- 선택적 수행표 필드를 엄격하게 읽는 구 FE가 있을 수 있으므로 새 DATA와 FE 소비자의 배포 순서를 검증한다. 기존 악보·음원·R2 객체·판본은 재작성하지 않는다. 실물 악기 연주 검수와 iOS 실기기는 별도 미검증으로 유지한다.

구현 참고: 통합 기준 `0802b1ff`에는 770~773의 기능과 최신 develop `e0bd8235`가 포함된다. weighted 로컬 반주 시계 보완은 `9b7cda3b`에 통합했고 실제 CAT 6종·FE 48건·DATA 86건과 독립 경계 검토가 통과했다. 기존 계획들의 과거 검증 결과를 새 분할본의 검증 완료로 자동 간주하지 않는다.
