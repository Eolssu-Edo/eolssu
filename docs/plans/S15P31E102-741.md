- 스펙: [내 악보 음역·수정 안내](../specs/sheet-pitch-correction.md). 구현·검증·로컬 커밋까지 수행한다. 발행·배포는 별도 요청 범위다.
- 기존 기본 checkout의 DATA 미커밋 작업을 보존하고 별도 worktree에서 작업한다. 병렬 조사와 구현은 소유 경로/별도 worktree로 나눈다.

## 순서와 완료 조건

1. 제공된 두 PDF의 음·6각 기호·박 구성을 시각 대조하고, 단소 지원 목록·지속 표시·장단 호환의 실제 원인을 재현한다.
2. 입력판 음역을 5개 직접 선택으로 바꾸고 한자·한글을 가운데 정렬한다. 최초는 기본이며 기본 한자는 비운다.
3. 지원하지 않는 음에 실제 지원 목록 기반 대체음을 제공한다. 명시적 선택만 적용하고 취소·실행 취소 및 원본 정보 연결을 보존한다.
4. 확인된 지속음/수정 안내 결함을 수정한다. 장단에는 실제 악보와 후보의 박 구성을 보여 해결 방법을 설명한다. 서버/음역 지원 계약 의미는 임의 변경하지 않는다.
5. 목표 회귀를 실패→통과로 검증하고 Android 호스트 회귀·APK·별도 고정 입력 화면을 검사한다. PDF/코드/런타임 근거와 미검증 범위를 기록한다.

## 진행

- Jira 생성·Story 연결·스프린트 배정·진행 중 전환을 각각 MCP 재조회했다.
- 사용자의 정렬 요청은 정간 렌더러가 아니라 율명·기호 입력판 버튼의 한자/한글 가운데 정렬로 확정했다.
- PDF·변환기와 클라이언트 검증 로직의 병렬 조사를 완료했다. 아래 확인된 원인만 구현에 반영했다.
- 실제 PDF 리더 재현에서 중청대의 점 두 개를 놓쳐 기본 대로 읽는 결함과 벡터 쉼표 누락을 확인했다. 각 경계 지속도 추적한다. 데이터/인식 변환기의 확인된 결함을 같은 사용자 결과에 필요한 범위로 포함한다. 원본·저장 문서의 자동 변경 없이 작은 합성 입력 회귀와 두 PDF 대조로 검증한다.

## 구현과 검증

- 5개 음역 직접 선택·기본 초기값·가운데 정렬·접근성 선택 상태를 구현했다. 320dp 폭을 위해 지우기는 지속·쉼 줄의 오른쪽으로 옮겼다. 기존 공식 Noto 원본/고정 fonttools로 `彳` 한 글자를 보강하고 기존 2,785글자의 cmap·수평 metrics 보존을 검사했다.
- 미지원 음/그 지속 칸을 누르면 실제 지원 목록의 가까운 후보와 동일 율명 옥타브 후보를 표시한다. 명시적 선택만 시작 음에 적용하고 ID·길이·이음·시김새 및 실행 취소를 유지한다. 키판도 같은 악기 지원 교집합을 쓴다.
- 현재 각의 정간당 박수/총 박수와 후보 장단의 박수를 표시한다. 원본과 다를 때 재변환해야 함을 안내하고 기존 호환 정책은 유지한다.
- 인식 엔진 3은 벡터 점·삼각 쉼표·PDF 명시적 각 경계 지속을 복구한다. 기존 검수 JGB·오선보 기본값은 유지한다. Python reader22+score51+인식/staff/API166=239개 통과했다.
- 실제 우물사이 PDF 4쪽의 production API 로컬 재현: 115각/460정간→118각/472정간, 2·6각의 중청대 복구, 4·8각 지속 연결, 9·49·85각 쉼 복구. 단모리의 4박 격자로 재변환했을 때 472박과 연속 시간축·참조를 확인했다. [세부 근거](../knowledge/frontend/sheet-pitch-conversion-corrections.md).
- 대체음 목표 검사에서 조회·후보 테스트 2개가 의도대로 실패한 뒤 5개 통과했다. 장단 목표4개 중3개 실패→4개 통과, 기존 영향 검사까지18개 통과. 음역 직접 선택·ViewModel 영향 검사11개 통과.
- 통합 후 Android 호스트 전체와 APK 빌드가 성공했다(1분34초). 독립 검토에서 일반 편집 후 각 경계 지속 끊김을 발견했고, 별도 회귀의 `ScoreDataException` 실패를 확인한 뒤 수정했다. 최종 전체 재검사와 화면 검증도 완료했다.
- 후속 검토에서 원본의 별도 REST를 명시적 지속과 구별해야 함을 확인하고, NOTE로 합쳐지는 회귀 실패를 재현한 뒤 수정했다. 두 검토 지적은 재검토에서 해결됐고 추가 지적은 없었다.
- 최종 Android 호스트 **1,342개 중 1,338개 통과, 기존 opt-in 4개 건너뜀, 실패·오류 0개**. 일반 APK 빌드 성공. 로그는 `verified-build.log`. 이후 수정 완료/장단 안내 문구를 조정한 최종 APK도 `release-candidate-build.log`에서 성공했다(57초).
- 장단 검토에서 총 박수는 같아도 정간당 3박 때문에 연결되지 않는 경우를 확인했다. 포괄적인 ‘각 길이와 박 단위가 모두 맞는 장단이 없다’ 대신 ‘현재 악보에 연결할 수 있는 장단이 없다’로 고쳐 구체적인 제한 설명과 모순되지 않게 했다.
- Android 17 에뮬레이터에서 실제 편집 Route와 고정 저장소를 연결해 일반/320dp 화면을 검사했다. 5개 음역 직접 선택·재클릭·최소 48dp 터치 영역·한자/한글 정렬·기본의 빈 한자 칸, 미등록/범위 밖 안내, 지속에서 대체음 적용·취소·undo/redo·시김새 편집·명시적 검수 확인·저장을 통과했다. 대체 후 4개 지속과 이벤트 ID·20tick 길이가 유지됐다.

- 화면 증거는 `verification-741-20261111/ui/verification-summary.json`(passed), `results/result.json`, `results/skewed-result.json`, 스크린샷 30개다. 최종 앱 생산 코드/리소스 21개가 통합 worktree와 SHA-256으로 일치했다. 검증 도구의 선택 상태 탐색·이전 fixture 파일·저장 버튼 이름·캡처 시간 초과 보정은 별도 기록했고 실제 동작 검증 조건을 완화하지 않았다.
- 검증용 에뮬레이터의 크기·밀도를 복원하고 종료했다. 실제 삼성 기기, iOS·웹 런타임, TalkBack 음성, 실물 단소 연주는 검증하지 않았다. Push·MR·배포·사용자 기기 설치는 수행하지 않았다. 기존 저장 악보의 복구에는 인식 서비스 배포 후 재변환이 필요하다.
