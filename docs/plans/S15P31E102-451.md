## 확인한 사실 (2026-11-04)

- 채점은 운영 악보의 음표로 한다. 지금의 `infra/catalog/enable_scoring.py`는 숨표와 검수 상태만 바꾼다.
- 악보 버전 규칙은 "score_json을 바꿀 때마다 1씩 올린다"이다(`V2__auth_user_practice_extensions.sql:160`).
- 모범 음원은 곡의 현재 `score_version`, 그리고 `score_json.score.scoreVersion`과 같은 버전의 음원만 나온다(`ModelAudioMapper.xml:9`, `:15`). 5곡 모두 지금 v1 모범 음원이 있다.
- 연습은 채점이 켜진 곡에서만 시작된다(`PracticeSessionMapper.xml:22`). 대상 곡은 채점이 켜진 적이 없어서 연습 기록이 없다.
- 정답 변환기(`score_data.convert_answer`) 출력은 운영 악보와 구조가 같다. 404 31곡을 대조한 결과, 출처·변환기 정보와 황 음높이 값을 빼면 다른 곳은 두 가지뿐이다. 하나는 빈 정간 기호(`-`/`''`)로 11곳이고, 다른 하나는 실제 음 차이다.
- 44의 `무{니나}`처럼 율명에 붙은 시김새를, 정답 변환기는 그 음의 시김새로만 둔다. 449의 B 결정과 같은 표현이라 새 변환 규칙이 필요 없다.

U1·U3·U4는 서로 기다리지 않는다. U3·U4는 코드, U1은 원본 대조다.

### U1 원본 확인 (AI 1차 + 사용자 모호 항목, 404 D-13 방식)

- 28 싸름: `싸름타령_정간보_단소_기존참고악보.pdf`에서 `농음표`가 미치는 범위와 이름을 확인한다. 운영이 시김새를 앞뒤 음에 붙인 것이 원본과 맞는지 본다.
- 43 청어엮기: `청어엮기_정간보_단소_국악원-18940.pdf`에서 c3-j0이 청협인지 청태인지 확인한다.
- 49 진도아리랑: 단소 원본 `진도아리랑_정간보_단소_기존참고악보.pdf`로 정답을 새로 옮긴다. 지금 JGB는 산조대금 자료라 쓰지 않는다. 옥타브, 자출, 숨표를 원본대로 둔다.
- 수락: 곡마다 "원본 = 운영" 또는 "원본 = 정답(운영 틀림)"과 근거 정간이 기록된다. 49는 새 JGB 초안이 있다.
- 사용자 시간: 모호 항목만 확인하면 30분, 49 전체를 사람이 검수하면 1시간.

### U2 정답 확정

- 내용: 5곡의 정답 폴더를 `data/annotations/scores/`에 둔다. 25는 이미 있다. 44·28·43은 404 원본 JGB에서 만든다. 49는 U1의 새 JGB를 쓴다. 검토 기록은 reviewed로 하고, 검수 방법과 운영과의 관계(같음/다름, 다른 정간)를 적는다.
- 수락: 5곡 모두 스키마·불변식 검사를 통과하고, 원본 확인 결과와 정간이 같다.
- 검증: data 테스트. 테스트의 단소 정답 목록에 새 폴더를 더한다.

### U3 목표 악보 만들기

- 내용: 순수 함수 `target_score(production, answer)`(위치는 `infra/catalog/` 도구 옆). D-4 규칙을 따른다.
- 수락과 검증(단위 테스트):
  - 운영 유지 값이 바뀌지 않는다.
  - `events`·`columns`가 정답과 같다.
  - `score.scoreVersion`이 +1이다.
  - 박 단위나 틱이 다르면 오류를 낸다.
  - 입력을 바꾸지 않는다.

### U4 enable_scoring 교체 경로

- 내용: 계획 항목의 `targetScore`, `targetScoreVersion`, `noteCount`를 검사한다. 교체 경로에서는 현재 해시·버전 조건이 맞을 때만 `score_json`, `score_version`, `note_count`, `is_scorable`을 한 UPDATE로 바꾼다. 완료 상태는 "버전 = 목표 버전, 해시 = 목표 해시, 채점 켜짐"이다. 목표 파일의 해시가 계획의 `targetSha256`과 다르면 쓰기 전에 멈춘다.
- 수락과 검증(가짜 DB 테스트):
  - 숨표 경로의 기존 테스트 14개가 그대로 통과한다.
  - 교체 경로에서 버전 증가, note_count 갱신, 재실행 0건을 확인한다.
  - 목표 파일이 바뀌었으면 멈춘다.
  - 한 곡이 바뀌면 전체를 되돌린다.

### U5 계획과 목표 파일

- 내용: U2 정답과 공개 곡 상세(GET)의 현재 악보로 목표 파일을 만들고, `danso.json`에 항목을 더한다. 원본과 운영이 같은 곡은 숨표 경로(D-8)로 넣는다.
- 수락: 계획 검사 테스트가 목표 파일 = `target_score(현재 운영, 정답)`을 확인한다. 이미 켜진 30곡의 항목은 그대로다.

### U6 격리 DB 확인

- 내용: 폐기용 MySQL 8.4에 공개 API로 읽은 운영 악보를 넣고 실행한다. 대상은 30곡(이미 완료 상태)과 이번 곡이다.
- 수락: 읽기 검사에서 이번 곡만 대기한다. 적용하면 버전·해시·note_count·채점이 맞는다. 재실행은 0건이다. 쓰기 직전 충돌이면 전체가 취소된다. 모범 음원 조회 조건(버전 일치)으로 v1 음원이 더는 붙지 않는 것도 확인한다.

### U7 독립 검토

결론 없이 결과물과 요구만 받은 검토자가 범위 전체를 본다.
