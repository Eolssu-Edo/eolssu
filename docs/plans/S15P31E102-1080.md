# S15P31E102-1080 악보 편집 실사용 점검과 저장·시김새·빠르기 잠금 오류 수정

- Jira: S15P31E102-1080 · Story S15P31E102-319 · 활성 스프린트 · 진행 중.
- 원인·실측: [악보 편집에서 음원을 만들 수 없는 입력과 잘못 남는 표시](../knowledge/frontend/sheet-editor-playback-guard.md).

## 점검 방법

- 배포 QA APK #474(`com.ssafy.eolssu.qa`, `qa-20261117.021154-6ec216ab`, SHA-256 `3cffc9a8…1370`)를 API 37 에뮬레이터(Medium_Phone)에 설치하고 운영 계정(사용자가 직접 로그인)의 내 악보 8개로 편집기를 조작했다.
- 저장 거절 이유를 보려고 develop `97aa1cdda` 디버그 빌드에 응답 본문 로그를 임시로 넣어 같은 운영 API로 확인했다. 로그는 커밋하지 않았다. 디버그 빌드는 서명이 달라 Google 로그인 복귀 링크가 검증되지 않으므로 에뮬레이터에서만 `pm set-app-links-user-selection`으로 열었다.
- 시김새 조합은 `data/src/playback`의 `preflight`를 로컬에서 직접 호출해 52개 단일·1,275쌍을 네 악기로 확인했다.

## 발견과 처리

| 증상 | 원인 | 처리 |
| --- | --- | --- |
| 시김새를 붙이면 저장이 안 되고 음원도 없음 | 생성기가 전성과 382개 조합을 거절. 서버는 `INVALID_REQUEST`만 주고 앱은 일반 실패 문구 | 충돌 시김새는 새로 고른 것으로 교체하고 안내. 전성·거절 위치는 1084·1086·1087에서 처리돼 충돌 표만 최신 생성기로 다시 만듦(400쌍) |
| 구간 빠르기가 없는데 정간·장단이 막힘 | 빈 `performancePlan`도 계획으로 판정 | `tempos`·`repeats` 항목이 있을 때만 잠금 |
| 고쳐도 표시가 남음(산조대금 파파2, 52칸) | 기준음 불일치 시 입력 가능 음이 빈 집합, 안내는 0개로 사라짐 | 상단 안내에 "기준음 맞추기" 추가 |
| 눌러도 반응 없는 율명 키 | 지원 밖 음은 비활성 버튼 | 누를 수 있게 하고 이유 안내 |
| 구간 빠르기 삭제 버튼 모양 | 테두리 없는 글자 버튼 | 수정과 같은 테두리, 빨간 글자 |
| 장단 선택 창 제목·안내가 비어 보임 | 대화상자 바깥에 세로 스크롤 중복 | 중복 스크롤 제거 |

## 검증

- 단위 테스트 추가: `SheetTempoPlanLockTest`, `SigimsaePlaybackRulesTest`. 생성기가 거절하는 조합을 기대하던 기존 테스트(`SheetDraftTest`·`SheetDocumentEditingTest`)와 비활성 율명 결과를 비교하던 `SheetPitchCorrectionTest` 2건은 바뀐 동작에 맞게 고쳤다.
- develop `f79bc1317` 위에 다시 적용한 뒤 `:shared:testAndroidHostTest` 전체 1,996건 통과(실패 0, 기존 제외 5), `:androidApp:assembleDebug`, `:webApp:compileKotlinWasmJs` 성공(2026-11-17, Windows).
- 수정 APK(SHA-256 `465e96ae…6e56`)로 에뮬레이터 확인: 기준음 맞추기 한 번에 52칸 표시 해제 후 저장 200, 구간 빠르기 추가 시 잠금·삭제 후 정간 나누기 동작, 장단 창 제목·안내 표시, 퇴성→추성 교체 안내, 추성+요성 저장 200과 연습 화면 음원 생성(미리듣기 준비 완료), 흐린 율명 안내.
- 실행하지 못한 것: 실기기, iOS, 웹 화면, 세 개 이상 시김새 조합, 악보 인식(PDF·사진) 경로.

## 따로 다룰 일

- 조금 빠르게·느리게의 끝 구간 지정과 본래 속도로 제거(FE, 빠르기 명세 변경).
- 악보 인식 때 전체 빠르기가 구간 빠르기로 잡히는 문제(AI). 이번 점검에는 재현할 인식 자료가 없었다.
- 전성의 재생 해석·기호 그림, 사전 검사 오류에 음 위치·기호 담기: 1084·1086·1087로 병합됨.
- 작업 중 커밋 전 변경을 develop 동기화 과정에서 잃어(stash 실패 후 reset) 대화 기록과 세션 파일 사본으로 최신 develop 위에 다시 적용했다. 에뮬레이터 확인은 잃기 전 코드로 한 것이다.
