## 작업 순서(세로 조각, 각 조각마다 테스트 포함)

2. **USR-03 닉네임 수정:** 검증과 수정 뒤 내 정보 반환.
3. **USR-02 악기·표기 저장:** 한 필드 이상, 활성 악기 확인(422).
4. **USR-04 비밀번호 변경:** 현재 비밀번호 확인(403·429), 새 비밀번호 규칙, 해시 저장, refresh 전부 폐기 후 현재 기기 재발급.

### 계획과 다른 점

- **재발급 재사용 탐지:** 계획에 없던 AUTH-04 수정이다. USR-04 DB 검사에서 다른 기기의 예전 토큰 재발급이 비밀번호를 바꾼 기기의 새 토큰까지 폐기하는 것을 발견해, 회전된 토큰만 탐지하기로 정했다(오은서 확인).
- **비밀번호 변경 저장 순서:** 트랜잭션 안에서 해시 저장 → refresh 전부 폐기 → 새 토큰 발급 순이다. 발급을 먼저 하면 새 토큰도 함께 폐기된다. 서명 키가 없으면 503이고 변경은 되돌린다.
