# S15P31E102-307 오류 음표·취약 구간 조회

- Story 37, Epic 20. 기준 origin/develop 5c38033. 사용자 요청(2026-10-30): 노션 API 명세서의 EVA 미구현 항목 중 EVA-02·03을 구현. EVA-04는 2차 보류로 제외.
- 계약: 노션 EVA-02·03 계약 초안을 따른다. 현재 저장 데이터에 없는 errorTypes 복수값·DURATION·recordingOffsetMs는 고정값으로 두고 [스펙](../specs/evaluation-detail-apis.md)에 표시했다.
- 범위 밖: AI 응답·`note_results` 스키마 변경, 노션 명세서 상태 갱신(사용자가 별도로 진행), FE 연동.

## 결정

- 취약 구간은 새 테이블 없이 매 요청 계산한다(노션 규칙 1). 이어진 2각 창의 틀린 칸 수가 많은 순, 같으면 앞 구간, 겹치지 않게 limit개. 디자인 문구 '3–4각'의 예를 기준으로 창 길이를 2각으로 둔 초안이다.
- 세션 이후 곡 악보 버전이 바뀌면 음표 순번과 정간이 어긋나므로 EVA-03은 409로 거절한다. EVA-02는 악보를 읽지 않아 영향이 없다.
- 판정은 AI 저장값만 사용하고 오차로 판정을 다시 만들지 않는다(backend 지침: 판정 로직 복제 금지).

## 검증
- 단위 `WeakSectionsTests` 5개(전부 정답, 최다 2각 창, 겹침 없는 복수 구간·빈 각 제거, 동률 처리, 세션 구간 제한)와 MockMvc `EvaluationDetailControllerTests` 7개(구간·필터·400·409·404)를 추가했다.
- 실제 HTTP/MySQL `EvaluationDetailApiDatabaseTests`: V6 시드 1번 곡 음표 16~19의 정간 묶음, 판정별 개수, 범위 400, 악보 버전 변경 409, 기록 삭제 404를 확인했다.
- 첫 DB 실행에서 OpenAPI 전수 검사 2건이 새 경로 미문서화로 실패해 Swagger 계약 2건을 추가했다.
- `./gradlew clean build databaseTest`(임시 MySQL 8.4, `--max-connections=400`): 일반 테스트 382개·MySQL 테스트 136개 모두 통과. 임시 컨테이너·인증 파일은 제거했다.
- 남은 일: 독립 리뷰, FE 연동, 노션 명세서 갱신(사용자 진행), 커밋·Push·MR(요청 시).
