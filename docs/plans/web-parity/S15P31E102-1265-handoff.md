## 1. 목표와 완료 조건

Web은 화면 이동 그래프를 브라우저 기록에 잇는다(`bindToBrowserNavigation`). 그래서 브라우저 뒤로 가기는 화면 안의 `BackHandler`를 거치지 않고 화면을 바로 뺐다. 편집 중이면 고친 내용이 확인 없이 사라졌고, 패널·대화상자가 열린 채 뒤 화면으로 넘어갔다. 기존 가로채기(`BrowserBackGuard.onBack`)는 한 칸뿐이라 연습·결과 화면만 썼다.

Jira 완료 조건:
1. 웹에서 편집 중 브라우저 뒤로 가기를 누르면 앱과 같은 미저장 확인 창이 뜬다.
2. 미저장 상태에서 새로고침·탭 닫기를 하면 브라우저 확인이 뜬다.
3. 패널이 열린 채 뒤로 가기를 누르면 패널만 닫힌다(연습 설정 패널, 읽기 목차, 음역 맞추기 패널, 악보 가져오기 진행 중, 변환 화면).
4. `:shared:compileKotlinWasmJs` 통과, 관련 commonTest 통과.

## 5. 남은 일·주의

- macOS Safari와 실제 브라우저의 떠나기 확인 창(새로고침·탭 닫기)은 확인하지 않았다. 운영 배포(S15P31E102-1269) 뒤 편집기에서 한 칸을 바꾸고 새로고침해 보면 된다.
- 1262(웹 녹음) 병합으로 웹에서도 연주 중 브라우저 뒤로 가기 확인(시나리오 8 뒷부분)과 결과 화면 미저장 확인(9)이 쓰이게 됐다. 이 Task는 두 화면의 기존 가로채기를 바꾸지 않았지만(D5) 브라우저로는 확인하지 않았다.
- 브라우저 **앞으로 가기**도 `popstate`라 등록된 동작(패널 닫기·미저장 확인)이 불린다(기존 한계). 앞 기록이 두 칸 이상이면 주소가 화면보다 한 칸 앞설 수 있다.
- 주소창에서 다른 `#경로`를 입력하면 화면 동작만 불리고 주소는 다음 이동 전까지 화면과 다를 수 있다.
- 메뉴 팝업은 브라우저 뒤로 가기로 닫히지 않는다(D3).
- `beforeunload` 문구는 브라우저가 정한다. 1264는 '다른 탭 계정 변경으로 새로고침할 때는 확인을 건너뛴다'로 정했다. 1264는 그 `location.reload()` 바로 앞에서 `skipNextUnsavedChangesWarning()`을 불러야 한다(부르지 않으면 미저장 편집 중에 확인 창이 뜬다).
- 편집기 Esc·기기 뒤로 가기가 접힌 입력판에서 바로 닫기 판단으로 가는 것은 Android·iOS에도 적용된다(기기 확인 안 함).
