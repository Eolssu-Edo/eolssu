# S15P31E102-1267 웹 셸 정비 (favicon·manifest·viewport·Safari 글꼴 미리 해석·글꼴 크기 줄이기)

- [Task](https://ssafy.atlassian.net/browse/S15P31E102-1267)는 우동균 담당, Epic S15P31E102-1148(홈·공통 화면 구성) 소속이고 상태는 `진행 중`이다. 스프린트 6에 배정돼 있지만 2026-11-24 기준 스프린트 6은 시작 전이고 활성 스프린트가 없다.
- 기준은 `origin/develop` `b72d56156`이다. 2026-11-23 Windows에서 초안(글꼴 변환 스크립트·Regular 시험 결과)을 만들고, 2026-11-24 Mac에서 패치로 옮겨 마무리했다.
- 범위와 완료 조건은 Task 본문을 따른다. 서버 압축·캐시(brotli, Wasm 미리 받기, 글꼴 장기 캐시)는 S15P31E102-1123의 범위다.

## 검증

모두 2026-11-24 macOS(Apple Silicon)에서 했다.

- 글꼴 변환(fonttools 4.60.1·Pillow 13.0.0, uv 임시 환경)
  - 원본 세 파일의 SHA-256이 Google Fonts `ofl/ibmplexsanskr` 원본(`raw.githubusercontent.com`에서 다시 받음), 기존 앱 파일과 같다.
  - 같은 명령을 두 번 실행해 세 출력 해시가 같았다. 아이콘 생성 스크립트도 두 번 실행해 다섯 파일 해시가 같았다.
  - 글리프 수·cmap·글자 폭·세로 지표·굵기 값이 원본과 같고, 한글 11,172자가 모두 있으며, 이름에 `Plex`가 없다. 윤곽 차이는 경계 최대 1/1000em, 면적 최대 1.2%다([기록](../../knowledge/frontend/web-korean-fonts.md#본문-글꼴-cff-변환-s15p31e102-1267)).
- 빌드: `./gradlew :webApp:wasmJsBrowserDistribution :shared:compileKotlinIosArm64 --max-workers=2`가 통과했다(JDK 21, 1분 54초). 이 Mac에는 Xcode가 없어 iOS는 `iosArm64` klib 컴파일까지만 확인했고 앱 링크·실행은 하지 않았다.
- 배포 폴더: 전체 38,638,268바이트(Wasm 두 개 20,052,193, gzip 5단계 6,539,998). 바꾸기 전 develop은 바뀐 파일 크기로 계산해 약 47.6MB다(Wasm 크기 차이는 빼고 계산). 본문 글꼴 전송 크기(gzip 5단계)는 3,118,430 → 2,396,528바이트다.
- 정적 서버(배포 폴더, Python `http.server`)
  - `manifest.webmanifest`·`favicon.ico`·아이콘 4개가 200과 맞는 MIME으로 오고, manifest JSON이 파싱된다.
  - Chrome 156(앱 내장 브라우저)과 macOS Safari 26.2 모두 icon·apple-touch-icon·manifest 링크를 읽고 manifest·아이콘을 요청했다. 둘 다 `100dvh`를 지원하고 `body` 높이가 창 높이와 같았다. 로딩 안내 없이 앱이 화면을 붙였다.
  - Chrome의 로그인·홈 화면에서 한글이 빈 상자 없이 그려졌다. Safari 화면은 캡처하지 않았고 요청·실행 기록으로만 확인했다.
- `PrepareHomeFonts` 대체 경로: `localStorage`에 로그인 상태(`first_run_completed`, `auth.member_id`)를 심고 `/api/users/me`·`/api/instruments`에 고정 응답을 줘서 홈을 열었다. 검사 스크립트가 `setTimeout(…, 100)`·`requestIdleCallback` 호출의 스택을 기록했다.
  - macOS Safari 26.2: `requestIdleCallback`이 없다. 홈에서 `wasm-function[31881]`이 100ms 대기를 618·761·862ms에 세 번 불렀다(Bold → SemiBold → Normal). Safari 스택에는 JS 연결 함수 줄이 빠져 있어서, 헤드리스 Chrome 158에서 `requestIdleCallback`을 지운 같은 배포본으로 `com.ssafy.eolssu.feature.home.requestTimeout`을 부르는 함수가 같은 `wasm-function[31881]`임을 확인했다(Chrome도 100ms 간격 세 번).
  - `requestIdleCallback`이 있는 헤드리스 Chrome 158은 기존처럼 `requestIdle`을 부르고 대체 경로를 타지 않았다.
- Android: `./gradlew :shared:testAndroidHostTest :androidApp:assembleDebug --max-workers=2`가 통과했다(1분 33초). 호스트 테스트 2,069개 중 실패 0, 기존 건너뜀 5개다. 새 `BodyFontCoverageTest`도 통과했다. 같은 `Font.canDisplay` 검사로 세리프 서브셋은 한글 2,350자, 새 본문 글꼴은 11,172자로 세어져 검사가 실제로 구분함을 jshell로 확인했다. 기기·에뮬레이터 화면은 보지 않았다.

## 남은 일

- 화면 확인: Android·iOS 앱과 Safari에서 새 본문 글꼴이 원본과 같은 모양·행간으로 보이는지 눈으로 비교하지 않았다. iOS는 Xcode가 있는 Mac에서 앱을 빌드해 한 번 본다.
- 홈 화면 추가: Android Chrome·iOS Safari 실기기에서 아이콘과 단독 창 실행을 확인해야 완료 조건을 모두 채운다.
- `standalone`의 영향: iOS 단독 창은 Safari와 쿠키가 분리되어 홈 화면에서 열면 다시 로그인해야 한다. 브라우저 뒤로 가기 버튼이 없어 앱 안 뒤로 가기에만 의존한다. S15P31E102-1263(웹 간편 로그인)·1264(웹 세션)·1265(뒤로 가기 보호)는 단독 창에서도 한 번 확인한다. Android 간편 로그인 복귀 주소(`/auth/android/oauth/.../callback`)는 manifest `scope` 안에 있으니, 웹 앱을 홈 화면에 설치한 Android 기기에서 복귀가 설치 앱으로 열리지 않는지 확인한다.
- S15P31E102-1123: 글꼴 파일 이름이 `eolssu_sans_kr_*.otf`로 바뀌었으니 캐시 규칙·사전 압축 목록에 새 이름을 넣는다. `.webmanifest`·`.ico`는 nginx 기본 MIME 표를 따른다.
- `index.html`은 1263·1269와 함께 고친다. 1263의 복귀 처리 스크립트는 `styles.css`·icon·manifest 같은 상대 경로 자원보다 앞에 있어야 한다. 이 MR은 링크를 `styles.css` 뒤에 둬서 그 순서를 지킨다.
