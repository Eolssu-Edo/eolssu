# S15P31E102-1259 웹 오디오 재생기 연결로 모범 연주 듣기·기록 녹음 재생 살리고 기록 상세 무한 로딩 막기

- [Task](https://ssafy.atlassian.net/browse/S15P31E102-1259)는 우동균 담당, Epic S15P31E102-18(모범 연주) 소속, 상태 `진행 중`이다. 스프린트 6(시작 전)에 들어 있고 2026-11-24 기준 활성 스프린트가 없어 그대로 두었다.
- 초안은 2026-11-23 Windows PC에서 만들었다(커밋 없음). 2026-11-24 이 Mac에서 패치(`b72d56156` 기준)를 이어 받아 검증하고 MR을 열었다.
- 후속: S15P31E102-1261(웹 내 악보 음원 재생)이 이 브랜치 위에서 시작한다. `WebAudioPlayer`가 `LocalAudioFile` 요청을 바로 실패로 알리고 주소(https·http·blob)만 재생한다는 규칙을 전제로 한다.

## 1. 목표와 완료 조건

웹(webMain)이 `AudioPlayer`를 `UnavailableAudioPlayer`로 등록해서 곡 연습의 '모범 연주 듣기'와 기록 상세의 '내 녹음' 재생이 소리 없이 끝났다. 재생기를 쓸 수 없을 때 기록 상세에 로딩 막이 남았다.

Jira 완료 조건:
1. 웹에서 곡 연습의 모범 연주가 재생·일시정지·탐색·속도 변경된다.
2. 웹에서 앱으로 녹음한 기록의 내 녹음이 재생된다.
3. 재생기를 쓸 수 없는 상황에서도 기록 상세에 무한 로딩이 남지 않는다.
4. `:shared:compileKotlinWasmJs` 통과, 관련 commonTest 통과.

범위 밖: 웹 장단 재생(1260), 웹 녹음(1262), 내 악보 음원(1261).

## 2. 원인(develop `b72d56156`)

경로는 `frontend/shared/src/` 아래다.

- webMain `platform/PlatformModule.kt`가 `factory<AudioPlayer> { UnavailableAudioPlayer() }`를 등록했다. 연습(`audioPlayer = get()`)과 기록 상세(`player = get()`)가 이것을 받는다(`commonMain/.../app/di/AppModule.kt`).
- 연습: `ModelAudioSession`은 `player.available`이 false면 `Unsupported`로 끝낸다. 무한 로딩은 없지만 소리가 나지 않는다.
- 기록 상세: `RecordDetailViewModel.playFrom`이 `playing=true, playbackLoading=true`로 바꾸고 녹음 주소를 받은 뒤 `player.load()`를 부른다. `UnavailableAudioPlayer.load()`는 상태를 보내지 않으므로 `onPlayer`가 sourceId 불일치로 무시하고 로딩 막이 남았다.
- 안내 화면의 웹 전용 `WebReferenceAudioPlayer`는 따로 있었다. load마다 새 `<audio>`를 만들고 `positionSampledAt`·`positionClockRate`를 보내지 않았다.

`WebAudioPlayer`의 동작:
- 상태 전이는 `AndroidAudioPlayer`와 같다. `load` → Loading → `playing` 이벤트에서 Playing(`positionClockRate=0`) → 위치가 실제로 움직이면 `positionClockRate=playbackRate`.
- 재생 중 위치를 50ms마다 읽는다(`timeupdate`의 약 250ms 간격은 쓰지 않는다). `waiting`(버퍼링)이 오면 다음 표본을 기다리지 않고 바로 시계 배율을 0으로 보내 진행 선이 소리보다 앞서지 않게 한다. 위치가 다시 움직일 때까지 10ms마다 읽는다.
- `loadedmetadata`에서 길이를 확인하고 시작 위치로 옮긴다. 시작 위치가 길이 이상이면 실패.
- `pause()`는 준비 전이면 자원을 놓고 Paused, 재생 중이면 멈추고 Paused. `resume()`은 준비된 Paused에서만 동작한다.
- `ended`: `retainCompletedMedia`(안내 음원)면 요소를 남겨 `seekTo`로 다시 옮길 수 있게 하고, 아니면 자원을 놓는다. 둘 다 Completed(위치=길이).
- 페이지가 가려지면(`document.hidden`) Interrupted로 바꾸고 자원을 놓는다. 다시 재생은 사용자가 누른다.
- `play()` 거절·`error` 이벤트·준비 30초 초과는 Failed. `LocalAudioFile` 요청과 https·http·blob이 아닌 주소도 바로 Failed.
- iOS Safari 대비: `<audio>` 요소 하나를 계속 재사용하고, 재생 중이 아닐 때 들어온 첫 `touchend`·`pointerup`·`click`·`keydown`(document, capture)에서 10ms 무음 WAV(data URI)를 한 번 `play()`한다. 모범 연주·녹음은 주소를 받는 네트워크 대기 뒤에 `load()`가 불려 클릭 제스처를 벗어나기 때문이다.
- Kotlin/Wasm은 같은 Kotlin 람다를 JS로 넘길 때 WeakMap으로 같은 JS 함수를 돌려준다(빌드 산출물의 `convertKotlinClosureToJsClosure` 확인). 그래서 `removeEventListener`로 등록한 리스너를 해제할 수 있다.

## 6. 남은 일과 위험

- iPhone 실기기 Safari: 무음 unlock이 통하는지 실기기에서 확인하지 않았다. 통하지 않으면 모범 연주가 Failed로 보인다.
- 운영 배포 뒤 확인: 모범 음원 주소 `/api/songs/{id}/model-audio/play`는 서명 URL로 302 이동한다. 운영 웹이 이 브랜치를 포함해 배포(1269)된 뒤 실제 도메인에서 한 번 더 재생한다.
- 1260 병합 뒤: 웹 장단이 켜지면 모범 연주+장단 동기화가 `positionSampledAt`·`positionClockRate` 정확도에 기댄다. 두 MR 병합 뒤 함께 확인한다.
- 1270 병합 순서: 웹 DI 바인딩 검사가 `AudioPlayer`=`WebAudioPlayer`를 기대값으로 삼아야 한다. `WebAudioPlayer`는 만들 때 document 리스너를 단다.
- `PlatformModule.kt`는 1260·1262·1263·1270도 고친다. 뒤에 병합하는 쪽이 줄 단위 충돌을 푼다.
