- 권한: 사용자의 독립 수정·리뷰·MR 요청 및 `정간보에 ㅈㅈㅅ와 시작·목표 속도 표시` 선택. 구현·검증·독립 리뷰·커밋·Push·Draft MR까지 진행한다. 물리 폰·공유 서버·병합·배포 금지. 원 checkout의 사용자 변경은 보존한다.

## 구현과 완료 조건

1. 숫자 가속을 UI 표시 모델로 투영한다. 편집·연습은 같은 투영을 사용하고 저장 계약·음표·재생은 보존한다. `placements=[]`, 명시 한배 우선, 명시 시작/기본/앞 속도, BPM 단위·배율, 끝 경계·겹침을 확인한다.
2. 시작 정간에는 한배 하나, 악보 위에는 속도·위치 안내를 표시한다. 좁은 기호 칸과 음표를 겹치지 않게 하고 두 단 높이 계산에 반영한다. 공유 변경은 core/model의 UI 모델, core/ui/score의 표시 컴포넌트이며 편집·연습에 필요하다. 단일 작성자가 수정한다.
3. 실패 확인→구현→초점 회귀, 전체 Android host test와 debug 빌드, 현재 소스의 실제 편집·연습 렌더링, 독립 리뷰 후 첫 Push 완료 기록과 Draft MR을 게시한다. iOS는 Windows에서 미검증이다.

## 상태와 근거

- 표시 구현·독립 리뷰·전체 회귀·Android 제품 컴포넌트 렌더링 검증 완료. 첫 Push 기록과 Draft MR 게시를 준비한다. 코드 변경 전에 명세와 이 계획을 작성했다.
- 원 기대: 저장된 가속이 정간보에서 보이고 수치로 읽힌다. 실제 선택: 기존 세로 기호와 별도 가로 속도/위치 안내. 수치는 14dp 기호 칸 밖에 배치하며 저장·재생 의미의 변경은 없다.
- 초기 디스크·메모리 제약은 아래 환경 회복 뒤 해소됐다. 사용자 자료 삭제, 물리 폰·공유 ADB·공유 서버 조작 없이 검증했다.

## 구현·검증 기록

- `CommonScoreData.toScore`가 숫자 계획을 `Score.tempoRanges`와 표시용 한배로 투영한다. 명시 기호를 우선하고 원본·편집용 `tempoAnnotations`는 바꾸지 않는다. 미완성 초안은 변환 성공 여부를 기준으로 원본의 표시 정보를 사용한다.
- 편집 `EditScoreBoard`, 휴대폰 `PracticeBoardScore`, 태블릿 `PracticeScoreArea`가 같은 안내를 사용한다. 안내를 뺀 높이로 기존 정간 배치를 계산한다.
- 변경 전 `ImportedTempoDisplayTest`의 기호 보존 검사 1개가 예상한 빈 기호 목록으로 실패했다(종료 1). 변경 후 해당 파일 6개와 기존 `SheetTempoEditingTest` 14개, 총 20개가 실패·오류·제외 0으로 통과했다. JDK 21, Gradle 9.5.1, Windows Android host test이다.
- 초점 검사 첫 구현 실행은 테스트 JVM의 532MB mmap 실패(Windows 1455)로 시작하지 못했다. 외부 init에서 테스트 heap 256MB·SerialGC·worker 1로 제한한 실행은 통과했다. 전체 검사 시도는 Gradle wrapper의 metaspace 64KB commit 실패로 중단됐다. 테스트 assertion 실패로 분류하지 않는다.
- 빌드 출력에만 NTFS 무손실 압축을 적용했다(약 220MB 논리 데이터→159MB 실제 저장). 마지막 실행이 956이고 이후 유휴인 Gradle PID 29400을 재확인해 종료한 뒤 1GB Gradle로 전체 검사를 재개했다. 공유 Kotlin·ADB·WSL을 종료하지 않았다.
- 독립 `coco-review`: 첫 snapshot `8ba01c0e…cb367d`에서 휴대폰 전용 경로의 숫자 안내 누락 P2를 발견했다. `PracticeBoardScore` 연결 후 snapshot `7f3f5bf3…6bfa78b` 재검토에서 해결·추가 finding 없음. 필수 실행 증거가 없으므로 병합 준비 완료를 승인한 결과는 아니다.
- 실제 BlueVal 재검증 입력은 외부 `C:/higher/qa-evidence/S15P31E102-953/final/response.json`(SHA-256 `5877364772d75106ac4e972628c57e0024a904956cf0085748e899e49dc55cfb`). 118각·472정간, 516 이벤트(492 NOTE·24 REST)이며 두 구간은 26/1→30/1·58/1→62/1, 80→160이다. 44음은 AuClair의 값으로 혼동하지 않는다.
- 외부 Android 화면 하네스는 `C:/higher/qa-evidence/S15P31E102-956/ui`, 실제 입력 host 검사는 같은 작업 폴더의 `actual`에 있다. 아래 최종 결과는 이번 소스로 만든 APK와 새 캡처를 사용한다.
- 디스크 고갈 당시 전체 재검사는 `compileAndroidMain`의 디스크 부족으로 실패했다. 생성 class 하나가 0바이트였으며 사용자 코드 오류와 구분했다. 직접 빌드 출력 삭제는 자동 승인 검토에서 차단되어 실행하지 않았다. 공간 회복(약 19GB 이상) 뒤 삭제 없이 비증분·프로세스 내 컴파일로 파일을 재생성했다.
- 회복 후 전체 host 검사: **254클래스·1,818개 중 1,813 통과·실패/오류 0·환경 검사 5개 제외**. 제외는 캡처 CAT-04·로컬 catalog·107곡 corpus·로컬 V21 장단·production QA 미설정이며 이 변경의 신규 검사는 모두 실행됐다. `:androidApp:assembleDebug`도 성공했다. 로그: 외부 `ui/recovered-final-checks.log`.

정상 APK는 하네스 빌드 전에 외부 `product-debug.apk`로 보존했다(SHA-256 `08e6ed7d60b02c0b10503551b194d23edfa095b92a598f9b1546f42fd5237739`). 하네스 APK는 별도 앱 ID `com.ssafy.eolssu.tempo956qa`, SHA-256 `8b2b18e752f8acbe9a8434b313feca5a82e74993673aa73fc3bbfc91b1edab4c`이다. 각각 `ui/integrated-android-receipt.json`, `ui/build-receipt.json`으로 구분한다. 현재 Gradle debug 출력은 하네스이므로 배포용으로 사용하지 않는다.

화면 검증은 API 37·1440×3040·560dpi의 소유 에뮬레이터에서 실제 `EditScoreBoard`, `PracticeBoardScore`, `PracticeScoreArea`를 실행했다. 휴대폰 컴포넌트 최대 높이는 480dp이며 행 수는 제품 packing 결과를 따른다. **실제 BlueVal은 1행**, 짧은 자작 입력은 2행으로 관찰됐다. 인증 앱 전체 흐름이나 실기기 검증으로 확대하지 않는다. 캡처는 `ui/captures/`에 PNG와 UI XML을 함께 보존했다.

- `editor-actual-26-font1`, `editor-actual-58-font1`, `phone-actual-26-font1`, `phone-actual-58-font1`: 80→160·범위와 첫 정간의 `ㅈㅈㅅ`, 율명 분리.
- 위 4개의 `font2`: 확대 글꼴에서도 기호와 음표가 분리된다. 두 번째 안내가 뷰포트 밖이면 가로 스크롤로 읽는다.
- `phone-actual-58-font2-scrolled-range`: 안내 영역에서 실제 가로 swipe 후 `80 → 160 BPM`과 `58각 1정간 → 62각 1정간 시작` 전체 판독. XML의 속도/범위 경계는 각각 `[300,707][885,833]`·`[300,833][1349,949]`로 뷰포트 안이다.
- `phone-imported-26-font1`, `phone-imported-58-font1`: 실제 휴대폰 컴포넌트의 2행 배치와 안내 높이 반영. `practice-imported-26-font1`은 별도 태블릿 경로다.
- `phone-dedup-26-font1`, `phone-manual-26-font1`: 명시 기호 하나와 기존 5종 한배 회귀. 화면 검사 뒤 crash buffer는 비어 있었다.

전용 ADB 포트 5046·serial `emulator-5596`·AVD `TEMPO956_READONLY_S10`만 조작했다. 종료 전에 AVD 신원을 재확인했으며 `ui/cleanup-receipt.json`은 소유 QEMU·리스너 모두 0과 캡처 PNG 30개를 기록한다. 공유 ADB·물리 폰·공유 서버는 조작하지 않았다.
