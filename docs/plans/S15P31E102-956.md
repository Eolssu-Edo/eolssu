## 구현과 완료 조건

1. 숫자 가속을 UI 표시 모델로 투영한다. 편집·연습은 같은 투영을 사용하고 저장 계약·음표·재생은 보존한다. `placements=[]`, 명시 한배 우선, 명시 시작/기본/앞 속도, BPM 단위·배율, 끝 경계·겹침을 확인한다.
2. 시작 정간에는 한배 하나, 악보 위에는 속도·위치 안내를 표시한다. 좁은 기호 칸과 음표를 겹치지 않게 하고 두 단 높이 계산에 반영한다. 공유 변경은 core/model의 UI 모델, core/ui/score의 표시 컴포넌트이며 편집·연습에 필요하다. 단일 작성자가 수정한다.
3. 실패 확인→구현→초점 회귀, 전체 Android host test와 debug 빌드, 현재 소스의 실제 편집·연습 렌더링, 독립 리뷰 후 첫 Push 완료 기록과 Draft MR을 게시한다. iOS는 Windows에서 미검증이다.

## 상태와 근거

- 표시 구현과 독립 정적 리뷰 완료, 전체 회귀·빌드·실제 렌더링 검증 진행 중. 코드 변경 전에 명세와 이 계획을 작성했다.
- 원 기대: 저장된 가속이 정간보에서 보이고 수치로 읽힌다. 실제 선택: 기존 세로 기호와 별도 가로 속도/위치 안내. 수치는 14dp 기호 칸 밖에 배치하며 저장·재생 의미의 변경은 없다.
- 로컬 C 드라이브 여유가 약 1GB로 빌드·격리 에뮬레이터 증거 확보에 제약이 있다. 기존 사용자 자료를 지우거나 다른 기기/공유 ADB를 조작하지 않는다.

## 구현·검증 기록

- `CommonScoreData.toScore`가 숫자 계획을 `Score.tempoRanges`와 표시용 한배로 투영한다. 명시 기호를 우선하고 원본·편집용 `tempoAnnotations`는 바꾸지 않는다. 미완성 초안은 변환 성공 여부를 기준으로 원본의 표시 정보를 사용한다.
- 편집 `EditScoreBoard`, 휴대폰 `PracticeBoardScore`, 태블릿 `PracticeScoreArea`가 같은 안내를 사용한다. 안내를 뺀 높이로 기존 정간 배치를 계산한다.
