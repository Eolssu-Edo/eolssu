# S15P31E102-915 iOS 연습 화면 모범 연주가 재생되지 않는 문제 수정

- [Jira](https://ssafy.atlassian.net/browse/S15P31E102-915) · 담당 오은서
- 기준 `origin/develop bac2acf1`.
- 2026-11-15 사용자 보고: iPhone 연습 화면에서 '모범 연주 듣기'를 눌러도 소리가 나지 않는다.

## 원인

- 서버는 정상이다. 운영 `/api/songs/{id}/model-audio`가 곡 108개 모두 200이고, 재생 리다이렉트로 받은 음원의 sha256과 타임라인(`/performance`)도 맞다.
- 모범 연주 음원 캐시(`ModelAudioFileCache`, 859에서 추가)가 받은 파일을 `<sha256>.audio`로 저장한다. 재생기는 원격 주소 대신 이 로컬 파일을 연다.
- iOS `AVPlayer`/`AVURLAsset`은 로컬 파일 형식을 확장자로 정한다. 운영 음원을 그대로 두고 이름만 바꿔 macOS AVFoundation으로 열어 보면 `.m4a`는 16.5초로 열리고 `.audio`는 "Cannot Open"으로 실패한다.
- 캐시는 처음 재생할 때부터 쓰이므로 iOS에서는 항상 실패했다. Android(ExoPlayer)는 내용을 보고 형식을 판단해 영향이 없었다.

## 변경

- `ModelAudioFileCache.fileFor`가 서버가 준 `contentType`을 받아 파일 이름에 확장자를 붙인다(`audio/mp4`→`.m4a`, `audio/mpeg`→`.mp3`, `audio/ogg`→`.ogg`, `audio/wav`→`.wav`). 모르는 형식이면 캐시하지 않고 기존 원격 재생으로 둔다.
- 같은 해시의 예전 `.audio` 파일은 지우고 다시 받는다. 정리 대상 이름에 예전 확장자도 남겨 다른 해시의 `.audio`도 개수 제한에 따라 지워진다.
- `ApiModelAudioRepository`가 `contentType`을 넘긴다.
- 악보 음원 저장(`SheetAudioDeviceStore`)은 이미 `.m4a`라 바꾸지 않는다.

## 검증 기록

- `ModelAudioFileCacheIosTest`(iOS 시뮬레이터): AAC m4a를 만들어 캐시에 받은 뒤 `AVURLAsset.playable`이 참인지, 같은 바이트를 `.audio`로 두면 거짓인지 확인한다.
- `ModelAudioFileCacheTest`(Android 호스트)는 새 인자와 확장자에 맞게 고치고 확장자·예전 파일 교체 테스트를 더했다. 이 Mac에는 Android SDK가 없어 MR 파이프라인에서 확인한다.
