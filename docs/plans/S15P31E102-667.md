## 검증과 통합 조건

- 기존 중계는 edo1 컨테이너에서 공통 준비 검사 배열을 읽지 않아 회귀 테스트가 실패했다. 수정 뒤 점검기 테스트 73건이 통과했다. 성공은 `검증 완료`와 근거로 표시하고 실패, 수집 지연, 확인 불가, 미검증 및 Docker 우선순위를 각각 확인했다.
- 12:06 KST에 665 수집기 후보를 edo1에서 읽기 전용으로 실행하고 667 중계로 렌더링했다. 운영 파일이나 콜백을 사용하지 않았다. 11.45초에 23개 행을 수집했고 12,895자 메시지에서 모두 표시했다.
- 쓰기·로그인 편집기 `/config` HTTP 200과 OAuth/CORS, phpMyAdmin 로그인 양식 HTTP 200, 터널 `/ready` HTTP 200 및 엣지 연결 4개가 각각 `검증 완료`와 검사 근거로 표시됐다.
- 복제 프록시는 수신 소켓까지 확인해 전달·복제 미검증을 표시했다. 추가로 분석 AI는 HTTP 422 입력 검증까지 확인해 실제 음원 처리·추론 미검증을 표시했다.
- Grafana·n8n HTTP 200과 node-exporter 수집 `up`은 상태 수집기에서 확인했다. 이번 후보의 컨테이너 사실에는 세 결과가 없어 미검증을 유지했다. 두 명령이 같은 준비 근거를 표시하려면 수집기가 이 세 결과도 전달하고 node 지연의 `주의`를 보존해야 한다.
