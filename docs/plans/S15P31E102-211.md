# S15P31E102-211 간편 로그인·계정 연결과 마이페이지 연결·해제 API 구현

**전체 기능은 미완료다.** 서버 코드·대역 테스트와 실제 제공자 연동 완료를 구분한다. 사용자는2026-10-29에 제공자 키를 아직 발급하지 않았다고 확인했다. 앱 등록·키 발급·FE 콜백 합의·환경 주입·실제 로그인 검증 전에는 운영 사용 가능 또는 Task 완료로 보고하지 않는다. 키/허용 콜백이 없으면 서버는 기동하되 해당 제공자 인증을503으로 거절한다.

- 담당 오은서, Epic14·Story22 관련됨. 활성 스프린트59139 배정·진행 중을 Jira MCP로 재조회했다(2026-10-29).

## 확정 사항

- 사용자 답변: 미가입 소셜 계정은 401 SOCIAL_ACCOUNT_NOT_REGISTERED, mergeTicket 유효기간10분. 앱 등록·콜백 URI·state FE 합의는 아직 없으며 서버 시작 API 방향으로 설계한다.
- 소셜 신규 가입 없음. 연결된 제공자 ID로만 즉시 로그인, 탈퇴 대기는 로그인 성공 시 취소. 같은 이메일 기존 계정은 자동 연결하지 않고 동의를 받는다.
- 제공자가 확인한 이메일은 동의만, 나머지는 비밀번호 또는 ACCOUNT_MERGE 완료 토큰으로 확인한다. 회원 ID·기록·설정 보존, users를 refresh_tokens보다 먼저 잠근다.
- 제공자 토큰·인가 코드·state·mergeTicket·verificationToken을 로그나 toString에 담지 않는다. 키 누락 시 해당 제공자 거절. 실제 제공자 호출은 로컬 대역으로 검증하며 운영 앱 등록 완료로 보고하지 않는다.

## 미정·의존 사항

- 사용자 확정: state와 mergeTicket의 소비 기록은 MySQL에 해시로 저장한다. 유일키만으로 재사용을 막던143의 안을 대체한다. 임의256비트 토큰+DB 해시 조회이므로 서명 토큰 대신 불투명한 임의 토큰을 쓰며 제공자 ID·이메일을 클라이언트 토큰에 담지 않는다.
- 사용자 확정: POST /api/auth/oauth/{provider}/start(로그인), POST /api/users/me/social-accounts/{provider}/start(연결). state10분·1회 사용·브라우저 쿠키 결속. FE는 authorizationUrl을 열고 기존 완료 API를 호출한다.
- 사용자 확정: 계정 연결 비밀번호 확인은 회원별 독립15분 내5회 실패·15분 잠금. 잠겨도 이메일 인증 경로 허용. 기존 로그인/현재 비밀번호 카운터는 변경하지 않는다.
- 실제 앱 등록·redirect URI는 FE/제공자 설정 회신이 필요하다. 주소가 없는 제공자는 기능 거절로 처리하고 가상 URL을 운영 허용 목록에 넣지 않는다.

## 구현 결과·검증

다음은 최초 구현27acb9e 시점의 기록이다. 이후 정식 리뷰와 지적 수정은 아래 '리뷰 수정'에서 관리한다. 최초 통과 결과로 실제 제공자 연동이나 수정 후 재검토를 완료 처리하지 않는다.

- API6개(시작2·로그인·병합·연결·해제)를 추가했고 기존 내 정보 linkedProviders 저장 조회를 재사용했다. 전체29개 업무 API를 실제 매핑과 OpenAPI로 대조했다. 공통 오류 envelope·쿠키·ACTIVE 확인·테스트 회원 무기한 세션 정책은 유지한다.
- state·mergeTicket: 원문/서명 payload 대신 임의256비트 값과 MySQL SHA-256을 사용한다. START와 MERGE를 구분하고 브라우저·제공자·목적·회원·정확한 콜백에 결속한다. state는 코드 교환 전에 한 번 소비하며 제공자 장애 뒤에도 재시작이 필요하다. merge는 회원 PK 잠금 뒤 소비·연결·로그인 발급을 한 트랜잭션으로 묶는다. 실패 시 증명 소비와 모든 쓰기를 되돌린다.

- Android 조사 결과: 패키지 com.ssafy.eolssu, manifest/Activity에 복귀 처리 없음, 현재 CI는 웹만 빌드하고 배포 APK/인증서 근거 없음. 기존 SecureCookiesStorage는 결속 쿠키를 보관할 수 있으나401 자동 재전송 정책에는 OAuth 예외가 없어 FE 연결 전에 보완해야 한다. 실제 키·인증서 파일은 읽지 않았다.
- HTTPS App Links로 기존 서버 흐름을 재사용하는 안과 제공자 SDK로 검증 계약을 확장하는 안을 비교했다. 전자는 도메인/실제 서명 검증과 콘솔 호환 확인이 필요하며, 후자는 SDK별 자격증명 계약과 FE 플랫폼 작업이 추가된다. 현재는 권고안·후보 주소만 정리했으며 채택·구현·공유 환경 배포 완료로 취급하지 않는다.
- 사용자 확정: FE 코드는 직접 수정하지 않고 권영민에게 인계할 자료만 준비한다. 테스트 APK는 Android Studio에서 생성한다. [인계 체크리스트](../specs/social-auth.md#권영민-인계-체크리스트)에 FE 복귀/오류/재전송 정책, 실제 APK의 공개 서명 회신, BE/인프라와 공동 검증을 구분했다. 기존 FE Task를 재개·수정하지 않았고 메시지도 전송하지 않았다.
- APK 생성·키스토어 접근·서명 추출·실기기 명령은 실행하지 않았다. 빌드 작업/산출물은 frontend/README.md와 Gradle 설정, 공개 서명/링크 명령은 Android 공식 문서로 대조했다. 앱·콘솔·서버 등록은 대기이며 인계 문서 작성 완료를 실제 연동 완료로 취급하지 않는다.
- 인계 문서 독립 검토에서 App Links 재검증의 비동기 대기를 빠뜨린 점을 보완했다. 나머지 APK 경로·명령·쿠키·재전송 정책은 저장소/공식 문서와 대조했고 git diff --check를 통과했다. 코드 변경이 없어 앱 빌드/서버 검사를 재실행하지 않았다.

## FE 전달 전 BE 마무리

- 사용자 요청: BE에서 가능한 준비를 마친 뒤 FE에 전달한다. FE 코드 수정·메시지 전송은 여전히 범위 밖이다.
- App Links JSON의 설정 기반 서버 제공과 Nginx 정확한 경로 프록시를 테스트 먼저 구현한다. 실제 APK 지문은 미수령이며 미설정404, 지문을 임의로 만들거나 운영에 주입하지 않는다. API와 다른 원시 JSON 배열은 Android 공개 검증 프로토콜에만 한정한다.
- 검증: 실제 로컬 HTTP의 JSON/미설정/잘못된 설정/무인증·잘못된 쿠키, 기존 회원 API 보호, Nginx 경로·Compose 구성, 관련 회귀와 필수 빌드. 제공자 앱/키/콜백 콘솔과 실제 실기기 검증은 계속 미완료다.
- App Links 구현 검사: 최초 공개 조회 기대200/실제404 실패 → 구현 후 실제 Spring HTTP2개 통과. 공개 지문 표기/회전·잘못된 값2개를 포함한 clean build338개 통과(실패·오류·skip0). Nginx1.30.6 구문 검사와 가짜 필수 변수 Compose config 통과. 전용 Docker 네트워크에서 운영 원본 Nginx에 요청해 백엔드 대역 JSON/200/application/json을 확인했고 컨테이너2개·네트워크를 제거했다. 이 프록시 검사는 운영 배포나 실제 APK 인증서 검증이 아니다. SQL/DB 모델은 변경하지 않아 DB 회귀는 앞선 통과 결과를 유지하고 이번에는 다시 실행하지 않았다.
- 사용자 확인/승인: 회사명 이도(Edo), 앱 이름 얼쑤, 대표 도메인 https://k15e102.p.ssafy.io, 카테고리 교육으로 카카오 앱을 생성했다. 콘솔 앱 목록 재조회에서 [얼쑤 앱1628175](https://developers.kakao.com/console/app/1628175)를 확인했다. 이 숫자는 콘솔 앱 ID이며 AUTH_OAUTH_KAKAO_CLIENT_ID에 넣는 REST API 키가 아니다. 기존 SSAFY 앱은 수정하지 않았다. 비밀키를 문서/코드에 복사하거나 서버 환경에 주입하지 않았다. 로그인 활성화·동의항목·허용 콜백과 실제 인증은 별도 확인한다.
- App Links 추가분 독립 점검: 원시 JSON·지문 정규화·미설정404·공개 경로와 회원 인증 분리·환경 전달/Nginx 경로를 검토해 수정 필요 결함 없음. 실제 APK 지문·운영 HTTPS 배포·Android 도메인 검증은 미확인이다. FE 전달은 이 외부 준비까지 마친 뒤 진행하며, 현재 문서만으로 전달 완료 처리하지 않는다.
