## 확정 사항

- 사용자 답변: 미가입 소셜 계정은 401 SOCIAL_ACCOUNT_NOT_REGISTERED, mergeTicket 유효기간10분. 앱 등록·콜백 URI·state FE 합의는 아직 없으며 서버 시작 API 방향으로 설계한다.
- 소셜 신규 가입 없음. 연결된 제공자 ID로만 즉시 로그인, 탈퇴 대기는 로그인 성공 시 취소. 같은 이메일 기존 계정은 자동 연결하지 않고 동의를 받는다.
- 제공자가 확인한 이메일은 동의만, 나머지는 비밀번호 또는 ACCOUNT_MERGE 완료 토큰으로 확인한다. 회원 ID·기록·설정 보존, users를 refresh_tokens보다 먼저 잠근다.
- 제공자 토큰·인가 코드·state·mergeTicket·verificationToken을 로그나 toString에 담지 않는다. 키 누락 시 해당 제공자 거절. 실제 제공자 호출은 로컬 대역으로 검증하며 운영 앱 등록 완료로 보고하지 않는다.

## 미정·의존 사항

- 사용자 확정: state와 mergeTicket의 소비 기록은 MySQL에 해시로 저장한다. 유일키만으로 재사용을 막던143의 안을 대체한다. 임의256비트 토큰+DB 해시 조회이므로 서명 토큰 대신 불투명한 임의 토큰을 쓰며 제공자 ID·이메일을 클라이언트 토큰에 담지 않는다.
- 사용자 확정: POST /api/auth/oauth/{provider}/start(로그인), POST /api/users/me/social-accounts/{provider}/start(연결). state10분·1회 사용·브라우저 쿠키 결속. FE는 authorizationUrl을 열고 기존 완료 API를 호출한다.
- 사용자 확정: 계정 연결 비밀번호 확인은 회원별 독립15분 내5회 실패·15분 잠금. 잠겨도 이메일 인증 경로 허용. 기존 로그인/현재 비밀번호 카운터는 변경하지 않는다.
- 실제 앱 등록·redirect URI는 FE/제공자 설정 회신이 필요하다. 주소가 없는 제공자는 기능 거절로 처리하고 가상 URL을 운영 허용 목록에 넣지 않는다.

## 구현 결과·검증
