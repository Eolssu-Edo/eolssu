# S15P31E102-1120 Android 출시 빌드 코드 축소·난독화 적용과 성능 측정 빌드 추가

- [Task](https://ssafy.atlassian.net/browse/S15P31E102-1120)는 우동균 담당, Epic S15P31E102-1146 소속, Story S15P31E102-1159와 relates로 연결되어 있다. 11-23 활성 스프린트 5에 배정하고 `진행 중`으로 전환했다.
- 시작 기준은 `origin/develop` `70c64b1a3`다.
- 계기는 11-23 Play Console 프로덕션의 "DEX 코드 최적화가 기준점 미만, 난독화 0%" 확인 필요 항목이다(해결 기한 2027년 2월).

## 범위

- release 빌드에 R8 코드 축소·난독화와 리소스 축소를 켠다.
- 출시와 같은 R8 설정에 debug 키로 서명하는 `benchmark` 빌드 유형을 추가해, 업로드 키 없이 기기 확인과 시작 시간 측정에 쓴다.
- Baseline Profile 생성(macrobenchmark 모듈)은 새 Gradle 모듈이라 `frontend/AGENTS.md`의 구조 변경 절차(팀 합의)가 필요해 이번 범위에서 뺐다. 11-23 Task 본문에 같은 내용을 적었다.
- Play 업로드·프로덕션 출시는 하지 않았다. 다음 업로드 versionCode는 12 이상이다(vc11은 1254 검증에 썼다).

## 결과

- 설정·근거·측정값은 [R8 지식 문서](../knowledge/frontend/android-r8-release-build.md)에 적었다. 요약은 아래와 같다.
- 앱 쪽 keep 규칙은 추가하지 않았다. 직렬화·리플렉션·JNI·리소스 이름 조회 지점을 확인했고, 라이브러리가 함께 배포하는 규칙으로 충분했다. `proguard-rules.pro`에는 크래시 줄 번호 유지 설정만 두었다.
- `mapping.txt`는 release AAB의 `BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map`에 자동으로 들어간다. Play가 이 파일로 크래시 스택을 되돌린다.
- 크기: release APK 33.55MB → 20.09MB(-40%), AAB 32.99MB → 25.77MB(매핑 포함), dex 합계 45.4MB → 6.2MB.
- 콜드 스타트(Galaxy S10, Android 12, 같은 ART 컴파일 상태끼리 비교): verify 529~545ms → 392~403ms, 전체 AOT(speed) 415~422ms → 336~338ms.

## 검증 (11-23)

- `./gradlew :androidApp:assembleRelease :androidApp:bundleRelease :androidApp:assembleBenchmark`가 성공했다. `minifyReleaseWithR8`·`minifyBenchmarkWithR8`에 누락 클래스 경고가 없었다.
- Jenkins 출시 잡과 같은 `:shared:testAndroidHostTest :androidApp:lintRelease`가 성공했다. 호스트 테스트는 2,063개 중 실패 0개, 건너뜀 5개였다.
- 실기기 흐름: Galaxy S10(SM-G973N), Android 12, `com.ssafy.eolssu.benchmark` `1.0.0-benchmark`(R8 켬), 수행자 우동균·Claude.
    - 이메일 로그인(사용자가 직접 입력) → 홈 → AI 연주 평가 시작 → 곡 목록 → 개구리소리 곡 정보 → 연주 평가(마이크 권한 허용, 녹음 18초, 실시간 음높이 표시) → 연주 분석 → 결과 화면 → 연습 기록 저장 → 기록 상세(녹음 재생) → 마이페이지 최근 연주까지 크래시 없이 동작했다.
    - 연주하지 않고 녹음해 결과는 0점·놓침 40개였다. 채점 응답의 표시와 저장 흐름을 확인한 것이며, 채점 정확도를 본 것은 아니다.
    - 같은 시간의 logcat에 이 앱의 `FATAL EXCEPTION`, `ClassNotFoundException`, `NoSuchMethodError`, 직렬화 예외가 없었다.
    - 확인용 0점 기록 1개가 사용자 계정에 남아 있다.
- Push 직전 develop에 1257(FCM 푸시)이 병합되어 그 위로 다시 올렸다(`5211fa975`). 다시 실행한 `:shared:testAndroidHostTest :androidApp:lintRelease :androidApp:bundleRelease :androidApp:assembleRelease :androidApp:assembleBenchmark`가 성공했고 호스트 테스트는 2,068개 중 실패 0개였다.
    - 리소스 축소 보고서에서 `firebase.xml`의 `google_app_id`·`gcm_defaultSenderId`·`google_api_key`·`project_id`는 keep 파일로, `ic_notification`은 Manifest 참조로 남았다.
    - 같은 S10에 덮어 설치하자 logcat에 `FirebaseApp initialization successful`이 찍혔고, 로그인 유지·홈·곡 목록까지 크래시 없이 열렸다. 푸시 수신 자체는 확인하지 않았다(benchmark 패키지는 Firebase에 등록된 앱이 아니다).
    - 이 기준의 크기는 release APK 20,535,275 B, AAB 26,486,416 B다.
- 확인하지 않은 것: 간편 로그인(benchmark 패키지는 App Links 지문 미등록), 악보 올리기·편집, 기초 배우기, Play 서명 AAB 자체의 설치 동작, iOS(이번 변경과 무관).
