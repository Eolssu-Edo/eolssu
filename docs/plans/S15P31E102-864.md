# 앱 마이페이지 최근 연주 개선 전후 실기기 속도 비교

[Jira S15P31E102-864](https://ssafy.atlassian.net/browse/S15P31E102-864) · [MR !669](https://lab.ssafy.com/s15-final/S15P31E102/-/merge_requests/669) · [기존 조회 개선과 웹 결과](S15P31E102-823.md)

## 측정 조건

- 2026-11-13, Galaxy S10(SM-G973N), Android 12, 화면 1080×2280. 같은 로그인 계정과 같은 운영 API에서 기존 QA APK #252(`2857c0d9`)와 설치돼 있던 QA APK #308(`75ca986e`)를 사용했다. 웹 비교와 같은 버전 기준이다. 각 APK의 배포 해시와 서명을 검증했다.
- 동일 패키지에서 앱 데이터 보존 설치로 버전을 바꾸고, 기존 계정 식별자의 일치 여부를 확인했다. 각 시도에서 앱 프로세스를 다시 띄워 홈을 펼치고 마이페이지 버튼이 관측된 뒤 750ms를 두고 탭했다. 개선 후 4회 → 개선 전 8회 → 개선 후 4회 순서다. 각 설치 구간의 첫 예열을 제외했다.
- 앱 시작 시 임시 OkHttp 이벤트 리스너를 연결했다. REC-02와 REC-05의 요청 시작, 응답 헤더·상태, 본문 수신 완료를 기록했다. Android 접근성의 홈 안내·최근 연주 제목·화면 범위 내 점수 노드를 같은 기기의 단조 시계로 관측했다. 탭은 터치 누름을 전달한 시점이다. 계정 식별자, 요청 본문과 헤더 값은 결과에 저장하지 않았다.
- 화면 측정값은 점수의 접근성 노드가 처음 관측된 시점이다. 마지막 미표시 관측부터 점수 관측까지의 간격은 개선 전 19.1~25.3ms, 개선 후 24.1~77.6ms였다. 개별 프레임의 픽셀 표시 시점과 계측 오버헤드는 별도로 측정하지 않았다.

## Android 결과

중앙값(최솟값~최댓값)이며 시간 단위는 ms다. 각 버전 8회 모두 같은 최근 연주 카드 내용을 확인했다.

| 구간 | 개선 전 #252 | 개선 후 #308 |
| --- | ---: | ---: |
| 첫 기록 요청 시작 | 탭 후 328.2 (309.9~348.6) | 홈 안내 최초 관측보다 31.1 앞 (5.6~38.7 앞) |
| 각 기록 요청 시작 → 해당 응답 본문 완료 | 64.6 (44.7~104.9), 40건 | 56.8 (46.9~66.4), 8건 |
| 첫 기록 요청 시작 → 마지막 응답 본문 완료 | 864.9 (748.7~914.3) | 56.8 (46.9~66.4) |
| 탭 → 기록 응답 본문 준비까지 대기 | 1194.4 (1071.3~1260.9) | 0 (매회 탭 전에 완료) |
| 탭 → 최근 연주 카드 제목 | 382.4 (329.6~432.7) | 427.0 (362.8~461.7) |
| 탭 → 최근 연주 점수 | 1288.9 (1166.1~1351.3) | 427.0 (362.8~461.7) |
| 기록 요청 수, 홈 / 탭 후 | 0 / 5 (REC-02) | 1 (REC-05) / 0 |

- 개선 전에는 마지막 응답부터 점수 관측까지 94.6ms(90.4~101.1ms)였다. 개선 후에는 탭 1357.2ms 전(1205.2~1514.3ms)에 선조회가 완료됐고 제목과 점수가 같은 관측에서 잡혔다.
- 두 버전의 기록 응답 48건은 모두 HTTP 200이었다. 탭 → 점수 중앙값은 861.9ms, 약 67% 줄었다. 개선 후의 가장 느린 관측도 개선 전의 가장 빠른 관측보다 빨랐다. 개선 전에는 응답 여러 건을 탭 뒤 순서대로 처리했고, 개선 후에는 탭 전에 한 건으로 준비했다. 두 APK에 함께 들어간 다른 변경의 효과는 분리하지 않았다.
- 원래 설치돼 있던 #308로 복원했다. 계정이 유지됐고 임시 계측을 연결하지 않은 정상 실행에서 최근 연주 점수가 표시됐다. 기기와 PC의 임시 계측 파일을 확인하고 정리했다.
