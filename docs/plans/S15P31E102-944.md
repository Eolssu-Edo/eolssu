# S15P31E102-944 edo2 중단 시 edo1 알림

- 운영 모니터링 Story 41, 스프린트 5, 진행 중. [Jira 작업](https://ssafy.atlassian.net/browse/S15P31E102-944) · [운영 안내](../../infra/edo-check/README.md#edo2-중단-알림)
- 문제: edo2의 상태 변화 알림(919)은 edo2 자체가 꺼지면 함께 멈춘다. edo1의 독립 HTTPS 검사(709)가 매분 edo2 중계를 확인하지만 결과는 journal과 상태 파일에만 남는다.
- 범위: edo1 검사의 edo2 중계 결과만 알린다. 약관 API(edo1 자신)는 edo2 감시가 이미 알리므로 제외한다.

## 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 판정·전송 | edo2 감시기(`alert.py`)를 edo1에도 두고 같은 함수를 호출 | 2회 연속 확인, 1회 알림, 미전달 재시도·모호 전송 미재전송, 본문 마스킹 규칙을 하나로 유지한다 |
| webhook | edo1의 기존 Jenkins 실패 알림 webhook 재사용 | 같은 `e102-cicd` 채널이고 이미 root 600으로 있어 새 비밀값을 서버에 더 두지 않는다 |
| 실패 처리 | 알림 오류는 journal에만 남기고 검사·상태 기록은 계속 | 기존 독립 HTTPS 행과 journal 기록이 알림 문제로 사라지지 않게 한다 |

## 검증

- `python3 -B -m unittest discover -s infra/edo-check/tests`: 159건 통과(신규 5건). 연속 2회 장애·복구 각 1건, 1분 실패 무시, webhook 없을 때 기존 동작 유지, 확실한 미전달의 다음 분 재전송, 알림 오류 중에도 상태 파일 기록, unit의 webhook 재사용을 확인한다.
- 2026-11-15 16:38 KST edo1 반영. 직전 파일은 `/var/backups/edo-check/S15P31E102-944-20261115T073839Z`에 보관했다. `alert.py`·`outside.py`·unit의 SHA-256이 저장소와 일치했고 `systemd-analyze verify`를 통과했다. 첫 실행은 성공(종료 0)했고 `alert.json`이 생겨 webhook 전달 경로가 열린 것을 확인했다.

- 실제 알림 검증(사용자 승인): 16:40:10 KST에 edo2 `edo-check`를 중지하자 중계 `/healthz`가 HTTP 502를 반환했다. edo1은 16:40:42에 첫 실패를 기록하고 16:41:43에 두 번째 실패로 `❌ 장애` 1건을 보냈다(중지 후 1분 33초). 16:41:55에 다시 시작해 `/healthz` 200을 확인했고, 16:43:45에 `✅ 복구 · 장애 2분 뒤 복구` 1건이 게시됐다. 두 게시물에 webhook 주소가 없었다. 같은 시간 edo2 감시기는 확인 기준을 넘지 않아 중복 게시가 없었다. 중지 동안 `/edo1`·`/edo2` 명령만 응답하지 않았다.
