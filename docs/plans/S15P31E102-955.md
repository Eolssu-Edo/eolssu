## 선택과 완료 조건

앞선 927은 사용자가 열거나 닫을 때까지 유지하는 설계였다. 이번 사용자 요청으로 자동 닫힘으로 대체한다. 처음 제시한 5초는 구현 전 가정이며, 기존 Material SnackbarHost의 `Short`(기본 약 4초)를 재사용한다. 접근성 권장 시간과 공유 큐의 실제 표시 시점 처리를 보존하며 별도 타이머를 만들지 않기 위한 선택이다. 요청한 잠깐 표시 후 자동 닫힘에 의미 있는 이탈은 없다.

- 음원·악보 모두 짧은 표시 후 소비되어 사라지고 반복 조회·화면 전환으로 재노출되지 않는다.
- 표시 중 열기·수동 닫기와 다음 알림의 자기 표시 시간을 유지한다.
- pause·삭제·계정 전환 취소는 기존 미처리·무효화 규칙을 유지한다.

## 실행 순서

1. 기존 표시 회귀의 무기한 기대를 짧은 표시 기대로 바꿔 현재 코드에서 실패를 확인한다.
2. 두 생성 경로가 공유하는 표시의 duration만 바꾸고 관련 주석을 갱신한다.
3. focused/full Android host 검사, Android/Wasm 빌드와 격리된 로컬 API를 사용한 실제 UI 자동 닫힘을 확인한다. iOS·실서버 생성·실기기 확인 여부는 구분한다.
4. 실제 diff를 자체 점검하고 작업 단위 커밋 및 검증 결과를 기록한다.
