# 조금 빠르게·느리게의 끝 구간 지정과 본래 속도로 제거

- Jira: [S15P31E102-1082](https://ssafy.atlassian.net/browse/S15P31E102-1082). 연결된 Jira 커넥터가 담당자(박찬형)가 아닌 계정이라 스프린트·상태·본문은 이 작업에서 수정하지 않았다.
- 착수 기준: `origin/develop` `008a01dcc`, 별도 worktree. 브랜치 `feat(fe)/S15P31E102-1082-구간-빠르기의-조금-빠르게·느리게에-끝-구간-지정과-본래-속도로-제거`.
- 완료 조건: 구간을 넣은 악보가 저장·음원 생성되고, 끝 위치 뒤에서 원래 빠르기로 돌아온다. 규칙은 [스펙](../specs/jeonggan-tempo-edit.md#조금-빠르게느리게-구간-s15p31e102-1082).

## 결정

- 저장 형식을 바꾸지 않으려고 구간을 `시작 즉시 변경 + 끝 다음 정간의 복귀 즉시 변경` 두 항목으로 저장하고, 읽을 때 합친다. DATA `tempo_repeat`는 항목의 알 수 없는 키를 거절하므로 표시용 필드를 추가하지 않았다.
- 편집 창은 끝 정간을 포함 위치로 받고 내부 끝은 그다음 정간 시작으로 둔다. 점점 변화의 기존 끝(`악보 끝` 허용) 의미는 그대로다.
- `본래 속도로`는 새로 넣는 선택지에서만 뺐다. 인식·기존 기호는 보존한다(삭제하면 원본 기호 정보가 사라지기 때문).
- 예상 음원 길이는 구간을 시작·복귀 즉시 변경으로 펼쳐 계산한다(`playbackTempoChanges`).

## 변경

- `core/model/HanbaeMark.kt`: `span`, `needsEnd`.
- `feature/song/edit/SheetTempoEditing.kt`: 구간 읽기·합치기, 계획 다시 쓰기(`planTempos`), 검증 기준, 재생용 펼치기.
- `feature/song/edit/component/SheetEditSettingsDialog.kt`: 끝 각·정간 입력, 본래 속도로 선택지 숨김, 목록의 끝 표시.
- `SheetSaveDuration.kt`, `sheet_tempo_strings.xml`, 기존 테스트의 조금 빠르게·느리게에 끝 위치 지정.

## 검증

`frontend/`에서 실행했다.

```bash
./gradlew :shared:testAndroidHostTest --tests "com.ssafy.eolssu.feature.song.edit.*" --tests "com.ssafy.eolssu.data.song.*"
```

- 결과: 490개 실행, 실패 0. 새 회귀 5건은 구간 저장·재진입·삭제, 앞 변경 수정 시 복귀 빠르기 재계산, 악보 끝·연속 변경의 복귀 생략, 끝 위치 검증, 복귀 없는 기존 저장본 읽기, 예상 길이(3정간·60에서 첫 정간만 120이면 2.5초)다.
- 미검증: 실제 서버 음원 생성, 앱 화면 조작(에뮬레이터·실기기), Web·iOS 빌드. 저장 항목은 DATA가 이미 받는 기호 없는 즉시 변경과 같은 형식이지만 이번 작업에서 DATA 생성기를 실행하지는 않았다.
