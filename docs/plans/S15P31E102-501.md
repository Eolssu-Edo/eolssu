# S15P31E102-501 분석 응답의 음표별 부분 점수

- Story S15P31E102-35, Epic S15P31E102-20. 소비처는 S15P31E102-502(EVA-04 구간 점수 비교)다.
- 계약: [노션 /v1/analyses](https://app.notion.com/p/408a0252aa4581528abee5ac1bdfd1a7), [PRA-03 분석 계약](../specs/practice-analysis-failure.md#분석-요청과-상태-조회-계약-s15p31e102-186).
- 범위: `scoringVersion`·`scoreWeights`·음표별 부분 점수·`weight` 추가. 허용 범위·판정·감점 곡선은 바꾸지 않는다.

## 결정

- 규칙 C(AI 확정 필요)는 지금 채점을 그대로 옮겨 `note-mean-1`로 정했다. `weight`는 균등 1, 가중치는 1/3, 시김새 음은 음정만 뺀다. AI 담당자 확인은 MR 리뷰에서 받는다.
- 항목 점수 계산을 `np.mean` 대신 `combine()`의 차례 합으로 바꿨다. 백엔드가 같은 부동소수 연산으로 구간 점수를 내야 규칙 A가 소수점 끝까지 성립한다. `sum()`은 3.12부터 보정 합산이라 쓰지 않는다.
- 이 변경으로 값이 정확히 x.5인 경계에서만 점수가 1점 달라질 수 있다. 기존 경계 테스트의 입력은 정확히 77.5이고, 부동소수 오차로 77이던 값이 짝수 쪽 78이 된다. `score_experiment`도 같은 함수를 쓰게 맞췄다.
- 허용 범위·판정은 그대로이므로 `modelVersion`은 올리지 않았다(`pyin-5`).

## 검증

- 2026-11-05, 테스트를 먼저 추가해 실패를 확인한 뒤 구현했다.
- `uv run pytest`(ffmpeg 7.1.1을 PATH에 추가): 412개 통과, 20개 건너뜀. 건너뛴 20개는 모두 OMR 테스트로 `JGB_GENERATOR_DIR`(jeongganbo-generator 클론)이 필요하다.
- 리뷰 후속: 합산이 백엔드와 소수점 끝까지 같은지 고정하려고 공통 벡터를 `test_scoring.py`와 백엔드 `SectionComparisonTests`에 같은 값으로 넣었다. 총점 계산은 벡터로 검사하도록 `total_score()`로 뺐다. `combine`을 `math.fsum`으로, 총점을 올림 반올림으로 바꾼 변형에서 각각 실패를 확인하고 원복했다. 총점 항목 순서를 뒤집은 변형도 벡터가 잡는다. 전체는 413개 통과, 20개 건너뜀(같은 OMR 사유).
