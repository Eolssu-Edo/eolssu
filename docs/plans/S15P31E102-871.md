## 진행

- 실제 PDF: OMR API(DONE, 4쪽, 44.223초)→실제 BE RecognitionResultBuilder→실제 FE ViewModel 추천·적용·되돌리기·최종 저장 요청 재생 통과. 운영의 소금 지원20음 공개 카탈로그를 캐시해 사용했다. 저장소 어댑터는 로컬 기록용이며 운영 계정 저장·DB/R2·배포는 하지 않았다.
- 결과: 501음, 추천+6반음, 자동 옥타브 이동5음, 직접 수정0음. 적용 전 빨간413소박/320정간→적용 후0. 별도 pitch class 계산도 같은 미해결 수다. source·이벤트ID·시간 보존 확인. 새 인식 결과의 검수0건이므로 과거 검수 잔존 증거와 구분한다.
- 작은 회귀의 red: 3건 중2건 실패(음역 검수 자동 해제와 재열기). 현재 수정 후 음역·수동 검수 분리, undo·재열기, 미해결5음, 구조 오류, 카탈로그 실패/대기를 검사한다. 전체 검사 뒤 전역 목록/다른 악기 카탈로그로 자동 해제하는 경계 실패를 추가 확인하고 현재 악기·조율이 일치하는 작성 카탈로그를 요구하도록 보완했다. 전역 음 목록만 있는 기존 수동 검수 테스트는 그대로 유지한다.
- 전체 검사 첫 실행의 추가 저장 회귀는 테스트 카탈로그의 악기 연결 누락으로 초기 미지원 상태를 재현하지 못했다. 실제 악기 조회를 연결한 fixture로 바로잡아 다시 검사한다. 제품 코드를 맞추려고 지원 기준을 낮추지 않았다.
- 지식 기록: [실제 PDF 결과와 한계](../knowledge/frontend/sheet-pitch-adaptation.md#blue-valentine-실제-pdf와-해결된-오류-표시-871).
- 최종 회귀7건을 원래 HEAD 제품 코드에 다시 실행해4건 실패를 확인했다(`baseline-regressions.log`). `finally`에서 수정본 바이트를 복원했고 SHA-256 동일성을 확인했다. 수정본에서는 동일7건과 실제 PDF ViewModel 재생1건이 모두 통과했다(`final-runtime.log`).
