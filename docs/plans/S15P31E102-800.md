# S15P31E102-800 키보드 확인·엔터를 누르면 키보드가 내려가도록 입력칸 수정

- Jira: [S15P31E102-800](https://ssafy.atlassian.net/browse/S15P31E102-800) (Story S15P31E102-109 UI/UX, 에픽 S15P31E102-1)
- 작업 위치: S15P31E102-798 브랜치 작업 중 함께 구현(커밋은 Task별로 나눈다).

## 범위와 완료 조건

- 앱 전체 입력칸에서 휴대폰 키보드의 확인·완료·검색·엔터를 누르면 키보드가 내려간다.
- '다음'은 다음 칸으로 옮기고, 옮길 칸이 없으면 키보드를 내린다.
- 완료 조건: 확인 동작이 붙은 칸(로그인·인증번호 받기·비밀번호 변경 등)도 키보드가 내려감, 공유 테스트·JS 컴파일·Android 설치 빌드 통과, 에뮬레이터 확인.

## 결정

- 원인: 공통 입력칸(`EolssuTextField`)이 확인 키에 할 일([onImeAction], 예: 로그인)이 붙으면 그 일만 하고 기본 동작(키보드 내리기)을 하지 않았다.
- 공통 동작 `rememberHideKeyboard`(`core/ui/component/KeyboardDismiss.kt`)로 화면 키보드를 내린 뒤 할 일을 한다. 공통 입력칸·곡 검색칸·연주 결과 메모칸에 적용했다. 메모칸은 키보드 확인 키 설정이 없어 '완료'로 정했다.
- 입력칸 초점은 풀지 않는다. 에뮬레이터(실물 키보드 모드)에서 초점을 푼 뒤 엔터가 화면 첫 버튼(카카오 로그인)을 눌러 브라우저가 열렸다. 곡 검색칸은 전처럼 초점도 푼다(검색 결과를 바로 보는 칸이라 바로 아래 버튼이 없다).

## 검증 (2026-11-12, Windows 11)

| 항목 | 결과 |
| --- | --- |
| `:shared:testAndroidHostTest :shared:compileKotlinJs :androidApp:installDebug` | 통과. 테스트 1500개, 실패 0, 건너뜀 4 |
| 에뮬레이터(Pixel 7, API 35) 로그인 | 이메일 칸 '다음' → 비밀번호 칸으로 이동하고 키보드 유지. 비밀번호 칸 화면 키보드 ✓ → 키보드 내려가고 로그인 검사(형식 오류) 실행 |
| 에뮬레이터 회원가입 이메일 인증 | 키보드 ✓ → 키보드 내려가고 형식 오류 표시 |

## 남은 확인

- 실기기(삼성 키보드 등 다른 키보드 앱)에서 같은지, 곡 검색·연주 결과 메모칸 직접 확인, iOS·웹.
