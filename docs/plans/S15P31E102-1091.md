# S15P31E102-1091 구간 빠르기 악보의 정간 나누기·합치기와 장단 재시간 보정 허용

- Story: S15P31E102-319, 에픽 S15P31E102-16
- 규칙: [구조 편집 재매핑 스펙](../specs/tempo-plan-structure-edit.md)의 1단계. 2단계(각 추가·삭제, 해시 결합 계약)는 BE 합의 전이라 포함하지 않는다.

## 변경

- 정간 나누기·합치기: 구간 빠르기·반복이 있어도 허용한다. 각 추가·삭제만 계속 막고, 안내 문구도 각 도구 아래로 옮겼다.
- 합치기 기호 보존: 한배 기호가 붙은 음 자리가 합치기로 사라지면, 저장할 때 같은 정간의 첫 음 자리로 옮긴다(`orderedPlacements`). 합쳐서 정간이 비게 되면 기호를 둘 곳이 없으므로 `TempoMarkBeforeMerge`로 막는다.
- 822 장단 재시간 보정:
  - 계획이 있어도 보정 후보를 보이고, 계획을 새 draft에 보존한다.
  - 숫자에는 `ticksPerBeat/ticksPerJeonggan` 비율 변화만 곱한다. 기준 BPM(`tempoReferenceBpm`)은 유지하고, 기본 빠르기는 1054대로 장단 기본값을 따른다.
  - 환산 결과가 40~200을 벗어나면 `TempoOutOfRangeAfterJangdan`으로 막는다.
  - 확인 창에 구간별 바뀌기 전→후 숫자를 보인다.
- 772 시간값 유지 장단 변경은 계획이 있을 때 적힌 기본 빠르기를 지킨다(기존과 같음).
- `본래 속도로` 검사를 같은 빠르기 허용 오차(`sameBpm`)로 바꿨다.
- BE `SheetExpressions.positions()`: 각 index와 칸 id·index만 비교한다. 칸 수나 칸 ID가 바뀌면 지금처럼 `PLAN_POSITIONS_CHANGED`로 거절한다.

## 스펙과 다른 점

- 범위 초과 안내는 어느 구간인지 짚지 않고 한 문장으로만 알린다. 기존 메시지 enum 구조를 그대로 쓰기 위해서다. 확인 창에서는 구간별 숫자를 볼 수 있다.
