# S15P31E102-502 음표별 부분 점수 저장과 구간 점수 비교

- Story S15P31E102-321, Epic S15P31E102-20. [S15P31E102-494](S15P31E102-494.md) 브랜치 위에서 작업했고, 값을 주는 쪽은 S15P31E102-501(AI)이다.
- 계약: [노션 EVA-04](https://app.notion.com/p/401a0252aa45814980a6f98e0f191dfe), [노션 /v1/analyses](https://app.notion.com/p/408a0252aa4581528abee5ac1bdfd1a7), [스펙](../specs/evaluation-detail-apis.md#eva-04-구간-점수).
- 범위: AI 응답 수신·검증, V27 저장, 구간 합산, `scoreComparable` 조건화, `SCORING_VERSION_CHANGED`, `before`·`delta` 점수. FE 연결(S15P31E102-343)은 범위 밖이다.

## 결정

- 부분 점수는 `DOUBLE`로 받은 그대로 저장한다. 자리를 줄이면 곡 전체 합산이 AI 점수와 달라질 수 있다.
- `score_weights`는 노션 계약대로 JSON 한 칸이다. 조회는 `JSON_VALUE ... RETURNING DOUBLE`(운영 MySQL 8.4)로 읽는다.
- AI와 배포 순서가 달라도 되도록 `scoringVersion`이 없는 응답은 NULL로 저장한다. 이때 음표에 부분 점수만 있으면 합칠 규칙이 없으므로 계약 오류다.
- 한쪽이라도 부분 점수가 없으면 `NO_NOTE_SCORES`만 주고 `SCORING_VERSION_CHANGED`는 주지 않는다. 버전이 없는 쪽과는 다르다고 할 수 없다.
- 구간 합산은 음표 순서대로 더하는 AI `combine()`과 같은 연산이다. 저장 뒤 읽은 값이 받은 값과 정확히 같다는 것을 MySQL 테스트로 고정했다.

## 검증

- 2026-11-05, 테스트를 먼저 바꿔 컴파일 실패를 확인한 뒤 구현했다.
- `./gradlew clean build databaseTest --continue --rerun-tasks`(임시 MySQL 8.4, `JANGDAN_SNAPSHOT_DIR` 사용)의 결과는 아래 실행 줄에 있다.
- 구간 합산의 `Math.rint`를 `Math.round`로, `SCORING_VERSION_CHANGED` 조건을 끈 변형에서 각각 `SectionComparisonTests`가 실패하는 것을 확인하고 원복했다.
- 실제 AI 서비스와 연결한 호출, 실제 녹음, 앱 실기기 검증은 하지 않았다. AI 쪽 값은 HTTP 대역과 MySQL 고정 데이터로 검사했다.
