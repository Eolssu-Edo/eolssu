## 확인한 사실 (develop 1dec028b)

- 앱은 첫 실행 때 약관·마이크 안내·로그인을 거쳐야 홈에 들어가고, 로그아웃하면 로그인 화면으로 간다. 학습 화면은 로그인한 회원만 쓴다.
- 앱 `LearnProgressRepository`는 기기 공용 키 `learn_done_<트랙>`에 완료 단계 번호만 남긴다. 계정과 완료 시각이 없다.
- 앱 학습 트랙은 `GuideInstrument`의 `danso`·`sogeum`·`daegeum-jeongak`·`daegeum-sanjo` 네 개다. 정악·산조대금은 황 위치(3/5)와 운지표가 다르다.
- DB `instruments`는 DANSO 한 행뿐이고 앱은 `/api/instruments`의 code로 서버 ID를 찾는다. 활성 악기 행을 더하면 가입·악기 선택 화면에 바로 나타난다.
- `lessons`(kind·content_json 필수)와 `lesson_progress`(score)는 V1 그대로이고 적재 마이그레이션은 없다. 매퍼는 `findById`뿐이다.
- 9단계와 문구는 앱 `LearnCurriculum.kt`에 있다. 판정 방식은 1·2 READ, 3~6 PITCH, 7·8 BEAT, 9 LISTEN(선택)이다. 근거 문서([관악기 기초 단계](../knowledge/domain/wind-beginner-curriculum.md))는 팀 확정 전 제안이다.
- 카드 그림은 앱에 든 `learn_stage_1~9.webp`를 단계 번호로 고르며 네 트랙이 같다.

## 결정 (사용자 확정 2026-11-02, coco-clarify)

- 범위: LRN-01 목록·진도, LRN-02 단계 상세, LRN-03 완료 표시·해제를 모두 1차로 구현한다. Notion 우선순위 칸의 '1차'와 같고, LRN-01 규칙 4의 '회의에서 결정'을 대체한다.
- 진도 기준: 학습 트랙 코드 `DANSO`·`SOGEUM`·`DAEGEUM_JEONGAK`·`DAEGEUM_SANJO`마다 9단계, `lessons` 36행을 둔다. `instruments`와 묶지 않아 악기 행 추가(카탈로그 담당) 없이 네 트랙을 저장한다.
- 완료 판정: 사용자가 누른 표시만 저장한다. 통과 기준(±25센트·70점 등)은 안내 문구이며 서버 자동 판정은 하지 않는다.
- 완료 저장 규칙: 같은 요청을 다시 보내도 결과가 같고 처음 완료 시각을 유지한다. 해제하면 완료 시각을 지운다. `completedCount`는 필수 8단계만 세고 `nextLessonId`는 완료하지 않은 가장 앞 필수 단계다.
- 계약 변경: LRN-01은 `GET /api/lessons?track=DANSO`로 묻고, LRN-01·02 응답의 `instrumentId`를 `track`으로 바꾼다. `thumbnailUrl`은 뺀다(서버가 줄 그림이 없고, 칸을 나중에 더하는 것은 기존 앱과 호환된다). 8단계 곡은 `songIds` 대신 후보 `{title, meta}`를 주고 곡 연결은 앱이 제목으로 찾는다. LRN-03 경로·본문은 그대로다.
- 문구: 서버가 유일한 출처다. `LearnCurriculum.kt`의 문구를 (트랙, 단계)마다 공통·악기 문구를 합친 완성본으로 옮기고, 이후 수정은 새 Flyway 마이그레이션으로 MR 검토를 거친다. 그림·운지표는 앱에 남긴다.
- 스키마: `lessons`에 track·judge_type·optional을 더하고 kind·instrument_id를 뺀다. content_json은 단계 상세 문구로 쓰고 (track, seq)를 유일 키로 둔다. `lesson_progress.score`는 빼고 (user_id, lesson_id) 유일 키는 유지한다. 두 테이블이 비어 있는지 먼저 확인한 뒤 바꾼다.
- 조회 성능: 목록은 (track, seq) 인덱스로 정렬 없이 9행을 읽고 (user_id, lesson_id)로 회원 표시를 붙인다. 목록은 content_json을 읽지 않는다. DB 통합 검사에서 실행 계획(EXPLAIN)으로 인덱스 사용을 확인한다.
- 기기에만 있는 기존 완료 표시: 올릴지 버릴지는 앱 동작이라 S15P31E102-370에서 정한다. 344는 단계별 완료 API만 두고 일괄 동기화 API는 만들지 않는다.

### 검증 기록

- 환경: Homebrew `mysqld` 8.4.9를 scratchpad 임시 datadir·포트 34344·`--max-connections=400`·`--disable-log-bin`으로 띄우고 최소 권한 테스트 계정(`eolssu_test` 전체 + `performance_schema.data_lock*` 조회)을 만들었다. 바이너리 로그를 켠 첫 기준선에서는 트리거를 만드는 기존 검사 3개가 오류 1419(SUPER 권한 없음)로 실패했고, 끈 뒤 같은 클래스가 통과해 환경 문제로 확인했다.
- 기준선(develop cfad44c3): `databaseTest` 158개, 위 환경 문제 3개 외 통과.
- T1: 적재 검사를 먼저 추가해 `track` 칸이 없어 실패하는 것을 확인했다. V13 적용 뒤 `DatabaseIntegrationTests` 24개·`WithdrawalPurgeDatabaseTests` 통과, 전체 `databaseTest` 159개 통과. 생성기가 `LearnCurriculum.kt` 리터럴과 대조해 만든 36행이 DB의 36행과 칸·JSON까지 같았다. 별도 폐기 DB에서 V13 사전 확인이 빈 테이블은 통과하고 `lesson_progress`에 행이 있으면 `chk_v13_preconditions` 3819로 DDL 전에 멈추는 것을 재현했다.
- T2: 진도 요약 단위 테스트와 컨트롤러 테스트를 먼저 써서 타입·클래스가 없어 실패하는 것을 확인했다. 구현 뒤 `test`의 lesson 단위·MockMvc·content_json 해석 11개, `databaseTest`의 `LessonApiDatabaseTests` 4개(트랙별 목록·본인 표시만·상세 표본·초안/없음 404·400·401·EXPLAIN 두 유일 인덱스와 filesort 없음)·`DatabaseIntegrationTests` 24개·`OpenApiDatabaseTests` 3개 통과. Jackson 3의 `JsonNode.map`은 노드 자체에 함수를 적용해 목록 변환에는 `values()`를 쓴다.
- T3: 완료 표시 컨트롤러 테스트를 먼저 써서 `MarkLessonCompletion`이 없어 실패하는 것을 확인했다. 구현 뒤 lesson 단위·MockMvc·content_json 해석 14개와 `LessonApiDatabaseTests` 7개(표시·재표시에 처음 시각 유지, 해제 때 행 삭제, 다른 회원 행 불변, 동시 표시 한 행, 초안·없는 단계 404, 잘못된 본문 400, JSON 아닌 본문 415, 비로그인 401 추가) 통과. 매퍼에 결함 3개(다른 회원 표시 노출, 처음 시각 덮어쓰기, 초안 노출)를 넣자 lesson DB 검사 7개 중 5개가 실패했고 원본으로 되돌렸다. 탈퇴 일괄 삭제는 기존 `WithdrawalPurgeDatabaseTests`가 V13 고정 데이터의 진도 행까지 지우는 것을 확인한다.
