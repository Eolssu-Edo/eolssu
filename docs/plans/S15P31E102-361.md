## 배경

Jenkins는 backend만 다시 배포하고 `ai`는 edo1에서 직접 빌드한 `eolssu-ai:runtime`을 쓴다. 2026-10-28 빌드(develop `88a1b05`, `modelVersion` `pyin-2`) 뒤로 `ai/`에 커밋 32개가 쌓였다. 채점 동작이 바뀐 것은 [S15P31E102-251](../knowledge/ai/short-octave-error.md)(pyin-3, 짧은 옥타브 위 음)과 [S15P31E102-158](../knowledge/ai/beginner-normal-performance.md)(pyin-4, 박자 판정)이다.

## 실행 (2026-11-02, 사용자가 PowerShell 5.1에서 실행)

1. 되돌리기 이름표: `eolssu-ai:runtime-88a1b05`(`a86ee1f296dc`).
2. develop `c701c32`의 `ai/`를 `git archive -o ai.tar`로 묶어 `scp`로 서버 임시 폴더에 보내고 풂(0.8MB). PowerShell 파이프는 바이너리를 깨뜨려 파일로 보냈다.
3. `docker build --label org.opencontainers.image.revision=c701c32c4d9591fe47576712eea81450501535a6 --tag eolssu-ai:runtime`, 임시 폴더 삭제.
4. `docker compose … up -d --no-deps --pull never ai`. 로컬 `ai.tar` 삭제.

- 앱에서 실제로 한 번 채점해 결과 `modelVersion`이 `pyin-4`인지 확인한다(완료 조건).
