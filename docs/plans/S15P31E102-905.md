## 원인과 구현 계획

`SheetEditViewModel.watch`가 화면 scope에서 SHT-13을 조회하므로 화면 이탈 시 조회와 완료 안내가 끝난다. native 연습도 같은 SheetAudioRepository를 사용한다. 기존 API를 관찰하는 singleton 저장소에서 계정 세대별 진행 작업과 완료 알림을 관리하고, NavHost의 활성 lifecycle에서 조회·공통 스낵바를 연결한다. 공통 navigation/di 변경은 이 기능 연결에 필요한 범위이며 다른 Task의 시간·빠르기 계약은 건드리지 않는다.

1. 고정 상태 응답으로 화면 이탈 후 성공 알림·중복·실패·삭제·계정 전환·재시도 회귀를 먼저 작성하고 실패를 확인한다.
2. 기존 API wrapper의 직렬화된 요청/조회로 상태 전이를 감지한다. 편집 화면의 별도 성공 안내를 공통 알림으로 옮긴다.
3. 앱 공통 스낵바의 열기 버튼은 웹에서 해당 악보 편집기, 기기 저장 지원 앱에서는 해당 내 악보 연습으로 이동한다. 이동 직전 계정 세대를 확인한다. 기존 웹 열람 경로도 편집기로 연결되므로 새 경로는 만들지 않는다. 현행 웹 편집기에는 음원 생성·재생 controls가 없으므로 웹 이동은 해당 악보 확인까지이며, 실제 음원 생성·다운로드 사용자 경로는 native 내 악보 연습이다.
4. focused/full Android host 검사와 필요한 빌드, 가능한 실제 앱 흐름을 검증하고 한계를 기록한다.
