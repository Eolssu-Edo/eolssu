## 계획과 판단

1. 완료된 847의 표시 매핑과 편집 목록을 대조한다. 혀치기·반음올림표·꺾는음·원문점 네 항목이 map 밖 분기로만 표시되어 입력 목록에서 누락됐다.
2. 네 항목의 선택·원본 변형 문자열·소박·JSON 저장/복원을 회귀 검사로 재현한다.
3. 공통 registry로 누락을 해소하고 반음올림표를 첨부 원본의 두 가로획과 오른쪽 연결획으로 교체한다.
4. 집중 검사·전체 Android host 회귀와 Android/JS/Wasm 컴파일, 가능한 실제 화면 확인 후 변경을 자체 검토하고 작업 단위로 커밋한다.

원래 요청은 #를 원본 모양으로 재현하는 것이었고, 후속 요청으로 편집기 선택과 다른 누락 항목 점검을 추가했다. 표시 가능한 기호와 입력 목록을 일치시키며 음향 의미는 새로 정의하지 않는다.

## 전체 리뷰와 MR 준비

사용자가 전체 리뷰 후 문제가 없으면 coco-push로 Push·MR 생성을 요청했다. 이전 구현 단계의 Push·MR 제외 범위를 이 요청으로 확장한다.

- 정식 coco-review는 독립 에이전트가 `aa8b2294c67d1093ad938e89928999adcb1a84b7..c5a92599750a3719fcb0cea2ce4d6ce632d8f34a`의 9개 파일과 호출·저장 경로를 읽어 수행했다. 작업트리는 리뷰 시작 시 깨끗했고 범위 스냅샷 SHA-256은 `d0769cd210dccbbe3e9e09289472f1754b457a064cd44ee99be41555b352d437`다.
- 명세·수용 기준, 저장소 규칙, 품질·위험의 세 축에서 수정이 필요한 결함은 발견하지 못했다. 원본과 편집 화면 캡처를 대조했고, registry→입력 목록→선택·삭제→소박별 JSON→초안 저장·서버 문자열 배열 검사 경로 및 검증 XML을 교차 확인했다. 원문점의 의미 미확정 상태와 꺾는음의 이름을 보존한다.
- 최신 `origin/develop`의 `57666c0389f067a4ba084a2fd88088491f2273ee`를 통합했다. `docs/README.md`의 신규 링크 삽입 위치만 충돌하여 920과 develop의 916·917·926 링크를 모두 보존했다. 제품 코드·리소스·회귀 검사는 리뷰한 구현 커밋과 동일하다.
- 통합 상태에서 `:shared:testAndroidHostTest :androidApp:assembleDebug :shared:compileKotlinJs :shared:compileKotlinWasmJs --console=plain --max-workers=2` 성공. 입력이 같은 78개 작업은 up-to-date로 재사용했고 3개 작업을 실행했다. Android host 결과는 1,750개 중 1,745 통과·기존 조건부 5 생략·실패/오류 0이다. 로그는 Git 제외 `frontend/build/sigimsae-920/publication-validation.log`다. 충돌 마커·미해결 인덱스·공백 오류도 해소했다.
- 브랜치명과 Jira 제목은 실제 결과를 설명하므로 유지한다. 첫 Push 직전 Jira 본문에 결과·커밋·검증·남은 범위를 한 번 기록하고 원격 커밋 일치와 Draft MR·담당자·리뷰어·라벨을 재조회한다. Jira 완료 전환과 병합은 수행하지 않는다.

원본 기호 재현과 네 항목 편집 지원이라는 기대·실제 선택 간 기능상 이탈은 없다. iOS 빌드·실기기와 운영 저장/재조회, 복합 시김새 전체 음원 생성은 기존 미검증 범위를 유지한다.
