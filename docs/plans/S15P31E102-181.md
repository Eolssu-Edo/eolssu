## 결정(2026-10-28)

| 항목 | 선택 | 이유·영향 |
| --- | --- | --- |
| API 명세 초안과의 차이 | 스펙 기준. 파일 파트 이름 `audio`, 202 본문은 명세 초안 형식. `endedAt`·`Idempotency-Key`는 받지 않음 | 기기 시계 대신 서버 시각으로 `started_at`과 맞춘다. 재전송 재생은 키·본문 해시 칸(새 마이그레이션)과 20MiB 해시 비교가 필요한데 얻는 것은 409 대신 202뿐이다. 409를 받은 앱은 상태 조회로 확인한다. Notion API 명세를 스펙에 맞춰 고친다(빨간 글씨) |
| S3 클라이언트 | AWS SDK for Java v2 `s3` 2.56.0(BOM), 비동기 Netty 제외 | SigV4 서명 URL과 S3 호환 업체 교체를 표준 구현으로 처리 |
| 체크섬·주소 | `WHEN_REQUIRED`, 경로 방식 | SDK 기본 CRC 체크섬은 S3 호환 업체마다 지원이 다르다. 경로 방식은 R2와 다른 업체가 모두 받는다 |
| 연결값이 없을 때 | 기동하고 업로드만 503 | 이메일 발송(`AUTH_MAIL_MODE=unavailable`)과 같은 방식. 로컬·테스트 서버가 R2 없이 뜬다 |
| 분석 시작 연결 | 조건부 갱신과 같은 트랜잭션에서 `RecordingUploaded(sessionId)` 이벤트 발행 | 처음에는 업로드 쪽 콜백 인터페이스로 두었으나, PRA-03 분석 Task가 먼저 develop에 넣은 계약(트랜잭션 안 발행, `AnalysisOnUpload`가 커밋 뒤 백그라운드 실행)에 맞췄다(2026-10-28 develop 동기화 때). 롤백된 업로드는 분석하지 않는다 |
| 분석 시도 시작 시각 | 업로드 조건부 갱신에서 `analysis_attempt` + 1, `analysis_started_at` = `ended_at`과 같은 서버 `Clock` 값 | 마감 판정이 같은 시계를 쓴다(DB `NOW()` 아님) |

## 남은 일

- 테스트 전용 R2 버킷에서 실제 쓰기, 서명 URL 읽기, 15분 뒤 거부, 삭제 확인(버킷·토큰 준비 뒤). 공개 접근 차단·수명 주기 규칙 설정 확인.
- 운영 `ops` 프로필은 업무 API(이 업로드 포함)를 켜지 않는다. 운영에서 켜는 방법은 Infra와 정한다.
- 운영 서버 `.env`에 `RECORDING_STORAGE_*` 값 등록과 운영 Nginx 설정 반영(배포 작업).
- 업로드 뒤 분석은 `PracticeScoreNotes`(공통 악보 데이터) 구현과 `ANALYSIS_AI_BASE_URL`이 생겨야 실제로 돈다. 그 전에는 업로드된 세션이 상태 조회의 제한 시간 판정으로 `TIMEOUT`이 된다.
- 500(DB 갱신 실패)은 단위·컨트롤러 검사로만 확인했다.
