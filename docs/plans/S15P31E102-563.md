## 현재 상태 (2026-11-08 운영 API 확인)

iOS 중계 주소 `https://k15e102.p.ssafy.io/api/auth/ios/oauth/<제공자>/callback`로 `POST /api/auth/oauth/<제공자>/start`를 보냈다.

| 제공자 | 결과 | 원인 |
| --- | --- | --- |
| kakao·google·naver | 401 `OAUTH_VERIFICATION_FAILED` | 운영 `AUTH_OAUTH_*_REDIRECT_URIS`에 iOS 주소 없음 |
| apple | 503 `SERVICE_UNAVAILABLE` | Apple 설정 값 없음. 운영 Compose도 Apple 변수 5개를 컨테이너에 넘기지 않음 |

같은 요청을 Android 복귀 주소로 보내면 kakao 200. `GET /api/auth/ios/oauth/kakao/callback`은 302로 중계 코드는 배포돼 있다.

## 저장소 변경

- `infra/runtime/compose.yml`: 백엔드에 `AUTH_OAUTH_APPLE_{CLIENT_ID,TEAM_ID,KEY_ID,PRIVATE_KEY,REDIRECT_URIS}` 전달 추가.
- `infra/runtime/.env.example`: 같은 변수와 설명, Apple 복귀 주소 기본값 추가.
- 검증: `MYSQL_PASSWORD=x MYSQL_ROOT_PASSWORD=x docker compose -f infra/runtime/compose.yml --env-file infra/runtime/.env.example config`에서 다섯 값이 backend 환경에 나타남을 확인.

## 운영 적용 순서 (권한 보유자, 별도 승인)

1. 카카오·구글·네이버 개발자 콘솔에 iOS 중계 주소 세 개를 복귀 주소로 등록한다.
2. Apple Developer(팀 `WDA26H33JA`): App ID `com.ssafy.eolssu`는 2026-11-08 자동 서명으로 등록됐고 Sign in with Apple이 켜져 있다(개발 프로파일 권한으로 확인). Sign in with Apple 키는 2026-11-08 오은서가 발급했다(Key 이름 `eolssu`, Key ID `NKM5WQQDJ8`). `.p8` 파일은 발급자가 보관하며 저장소·채팅에 넣지 않는다.
3. edo1 `/opt/eolssu/.env`(root 0600)를 백업한 뒤 각 `AUTH_OAUTH_*_REDIRECT_URIS`에 iOS 주소를 쉼표로 덧붙이고, Apple 변수 5개(`CLIENT_ID=com.ssafy.eolssu`, `TEAM_ID=WDA26H33JA`, `KEY_ID=NKM5WQQDJ8`, `PRIVATE_KEY`, `REDIRECT_URIS`)를 넣는다.
4. 이 브랜치의 Compose를 반영해 백엔드를 다시 띄우고, 운영 DB Flyway 이력에 V22(`sign_in_with_apple`)가 있는지 확인한다.
5. 네 제공자의 iOS start가 200인지 확인하고 iPhone에서 로그인·신규 가입을 확인한다.

## 운영 적용 결과 (2026-11-08, 오은서 직접 실행)

- 콘솔: 네이버에 `/api` 없는 iOS 주소(`/auth/ios/oauth/naver/callback`, 웹 HTML 200)가 잘못 등록돼 있어 `/api/auth/ios/oauth/naver/callback`으로 고쳤다. 카카오·구글도 `/api` iOS 주소로 맞췄다. Android 주소는 유지.
- Compose: 서버 원본이 저장소와 Apple 외에도 달랐다(서버에만 444 QA IPA 볼륨 `/opt/eolssu/ipas`, 저장소에만 `SHEET_CONVERSION_OMR_BASE_URL`·`SHEET_IMPORT_READ_BASE_URL`). 저장소 파일을 그대로 쓰지 않고 서버 원본에 Apple 다섯 줄만 넣은 후보를 만들어 diff(5줄 추가만)를 확인한 뒤 `install-runtime-compose`로 설치했다. 원래 파일 백업: `/opt/eolssu/config/compose.yml.backup-xdmxr7o7`(두 번 실행해 `backup-_lyutuzb`는 첫 설치 결과).
- `.env`: 백업 후 세 리다이렉트 변수에 `/api` iOS 주소를 덧붙이고 Apple 네 값을 넣었다. 개인키는 서버 임시 파일에서 한 줄로 바꿔 붙이고 임시 파일을 지웠다(값 미출력).
- backend만 재생성: 컨테이너 안 `AUTH_OAUTH_APPLE_*` 5개, readiness `{"status":"UP"}`.
- 운영 API: iOS 주소로 `start` kakao·google·naver·apple 모두 200(인증 주소 호스트 kauth.kakao.com·accounts.google.com·nid.naver.com·appleid.apple.com). Android 카카오 200 유지.

- iPhone 실기기(2026-11-08, iPhone 16 Pro / iOS 26.6.2, 출시 번들 ID `com.ssafy.eolssu` Debug 빌드, 오은서 확인): Apple·카카오·구글·네이버 로그인 모두 성공. 개발용 번들(`…eunseo`) 앱은 서버 `CLIENT_ID`와 달라 Apple 확인에 쓰지 않았다.
