## 요청과 완료 조건

- 정간보 쉽게 읽기의 `장단·기호 자료` 버튼을 제거한다.
- 2 음의 길이: 초보자가 박을 들으며 글자 뒤의 초록 빛과 활성 글자를 따라갈 수 있게 한다.
- 3 음의 높낮이: 탁황·황·청황 계단 아래 같은 높이에 스피커 버튼을 배치한다.
- 소리 준비·실패·중지·재시작과 쪽 이동·뒤로 가기·백그라운드 전환에서 강조와 재생을 함께 정리한다.
- 기존 시김새와 기초부터 배우기의 정적 길이 예시를 보존한다.

## 구현 결정

- 기존 `SoundPlayer`와 플랫폼별 리소스 재생기를 그대로 사용한다. 공통 네비게이션·테마·DI·플랫폼·의존성 파일은 수정하지 않는다.
- 읽기 Route에서 `ReadingCatalogViewModel`을 더 이상 만들지 않아 제거한 자료 창의 장단·기호 요청도 발생하지 않는다. 다른 용도의 카탈로그·API·기존 컴포넌트는 삭제하지 않는다.
- 짧은 비교용 합성 WAV 7개를 앱에 포함한다(24 kHz, mono PCM16, 총 600,308 bytes). 실제 악기 녹음·서버 데이터·마이크 권한 없이 동작한다.
- 길이는 이 예시에서 한 칸 = 한 박, 한 박 = 1초(60 BPM)로 정한다. 각 예시는 두 박이고 박 시작에 짧은 클릭을 섞는다. 반 칸은 0.5초, `ㅡ`는 소리를 끊지 않고 두 박, `△`는 박 클릭만 들리는 쉼이다.
- 음높이는 동일한 음색으로 E♭3 / E♭4 / E♭5 (MIDI 51 / 63 / 75, 약 155.56 / 311.13 / 622.25 Hz)를 비교한다. 악기별 조율·운지·채점 기준으로 사용하지 않는다. 길이 예시의 林·南·太는 같은 교육용 황=E♭4 기준으로 MIDI 70·72·65를 사용한다.
- 생성기는 `frontend/tools/reading-sound/build_reading_sounds.py`다. `ReadingAudio.kt`의 예시 칸·분할·기간에서 음원을 만들어 별도 악보를 중복 관리하지 않는다. `--check`는 파일을 쓰지 않고 재현성을 확인한다.
- 준비 중에는 강조하지 않고, 기존 재생기의 실제 시작 응답 뒤 단조 시계로 강조를 시작한다. 16ms 주기로 현재 글자를 계산하며 실제 기기 출력 지연의 정밀 측정값은 아니다.
- 재생 선택은 하나만 유지한다. 같은 버튼은 중지, 다시 누르면 처음부터, 다른 버튼은 이전 소리와 타이머를 취소한다. 실패 시 가짜 강조 없이 재시도 안내를 보여 준다.
- 휴대폰 쪽 이동/드래그, 반응형 배치 전환, 뒤로 가기, Route 해제, Lifecycle `ON_STOP`에서 중지한다. 태블릿에서 시김새 창을 열 때도 기존 소리와 강조를 먼저 중지한다.
- [Compose Lifecycle 공식 문서](https://kotlinlang.org/docs/multiplatform/compose-lifecycle.html)의 웹 `visibilitychange` → `ON_STOP` 매핑을 확인했다. 실제 브라우저/기기 동작은 아래 검증에서 별도로 구분한다.
- 스피커 터치 영역은 48dp다. 읽기 버튼별 접근성 이름과 준비 중/재생 중 상태를 제공한다. 녹색뿐 아니라 버튼 상태와 ‘하나·둘’ 글자로도 현재 박을 표시한다.
