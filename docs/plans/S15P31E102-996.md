# S15P31E102-996 로그인·메모 등 입력칸 글자 수 제한과 메모 입력 오류 수정

- Jira: S15P31E102-996 · 완료(MR !864 병합) · 스프린트 5 · Story S15P31E102-22·23 · 담당 박찬형. 브랜치 `fix(fe)/S15P31E102-996-로그인·메모-등-입력칸-글자-수-제한과-메모-입력-오류-수정`, 기준 `origin/develop` `4831d142`.
- 계기: QA 피드백 중 입력칸 관련 항목들이다. 로그인·회원가입 등 모든 입력창에 글자 수 제한이 없었다. 메모는 500자를 넘기면 400자대로 되돌아갔고, 엔터를 여러 번 누르면 칸이 끝없이 늘어나며 스크롤이 없었다.
- 계획 문서는 작업 당시 만들지 않아 병합 후 이 문서로 남긴다. 상세 결정과 검증은 [지식 문서](../knowledge/frontend/input-length-limits.md)에 있다.

## 결정 (모두 2026-11-16 사용자 요청·확인)

- 상한은 `core/model/InputLimit` 한곳에 둔다. 글자 수는 서버처럼 코드 포인트로 센다.
  - 이메일 100자: 서버 320자는 비현실적이라는 사용자 지적으로 줄였다.
  - 비밀번호는 모든 칸 64자: 처음에는 새 비밀번호만 64자로 하고 로그인 칸은 128자로 두었으나, 사용자 요청으로 통일했다. 서버를 맞추는 일은 S15P31E102-1014에서 한다.
  - 악보 제목 50자, 메모 500자, 검색어 50자.
  - 악보 숫자 칸: 빠르기 3자리. 각·정간 번호는 편집 중인 악보의 각·정간 수에서 자릿수를 정하고, 창을 열 때 한 번 계산한다(서버 요청 없음).
- 상한을 넘겨 치려다 막히면 "N자까지 입력할 수 있어요"를 보인다. 막힌 줄 모르겠다는 사용자 지적으로 넣었고, 딱 맞게 채운 값(빠르기 120 등)에는 띄우지 않는다. 모든 비밀번호 칸에 보기/숨기기 버튼을 둔다.
- 메모는 공용 `EolssuMemoField`(TextFieldState + 입력 변환)로 바꾼다. 값을 거절하던 방식은 한글 조합 중 칸과 키보드 내용이 어긋날 수 있다. 칸은 최대 높이까지만 커지고 안에서 스크롤하며 스크롤 막대를 보인다. 연주 결과 저장 시트에도 같은 칸을 쓴다.
- 입력·제출 흐름 점검(하위 에이전트 감사) 결과를 반영했다.
  - 가입 프로필·비밀번호 변경의 서버 오류를 칸 밖 화면 오류로 분리했다.
  - 요청 중 버튼에 진행 표시를 넣었다.
  - 계정 연결 예외 시 진행 상태를 해제한다.
  - 같은 닉네임이면 요청을 생략한다.
  - 악보 제목·빠르기 오류는 고친 뒤에만 보인다.
  - 파일명으로 채우는 제목은 공백을 자르고 이모지를 반으로 자르지 않는다.

## 기록

- 자동: `:shared:testAndroidHostTest :androidApp:assembleDebug` 통과(각 단계마다). 새 `InputLimitTest`. 화면 오류 분리에 맞춰 `AuthFormViewModelTest`·`OAuthViewModelTest` 기대값을 `formError`로 바꿨다.
- 로컬 MySQL 8.4 + `db` 프로필 백엔드(:18080)에 에뮬레이터(Medium_Phone, `adb reverse`)를 연결해 확인했다.
  - 이메일 130자 → 100자, 검색 70자 → 50자, 비밀번호 140자 → 64자와 안내 문구, 눈 버튼으로 보이기.
  - 메모 446자 읽기 상자의 스크롤 막대. 편집에서 줄바꿈 30번 후에도 칸 높이 유지, 500/500 이후 입력 거부, 저장 후 DB 500자.
  - 회원가입 1~3단계 진입: 로컬 DB에 확인용 약관 2개를 넣고, 인증번호는 고정 HMAC 키로 역산했다.
  - 구간 빠르기 각(1자리)·정간(2자리), 기본 반주 첫 강박 정간(1~48 → 2자리).
- 미검증: 한글 키보드로 500자 경계 조합(adb로 한글 입력 불가), 실기기, 태블릿, iOS.

## 남은 일
