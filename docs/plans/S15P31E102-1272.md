# S15P31E102-1272 녹음 업로드 WAV 허용과 서버 AAC 변환 저장

- [Task](https://ssafy.atlassian.net/browse/S15P31E102-1272)는 우동균 담당, Epic S15P31E102-20, Story S15P31E102-33(연주 녹음·업로드)과 relates로 연결했다(2026-11-23 생성). 활성 스프린트가 없어 스프린트 미배정·`해야 할 일` 상태다.
- 웹 녹음 Task(S15P31E102-1262)에서 백엔드 부분만 떼어 냈다(2026-11-23 사용자 결정: 백엔드만 별도 Task·MR). 웹 클라이언트 구현은 1262가 맡는다.
- 브랜치 `feat(be)/S15P31E102-1272-녹음-업로드-WAV-허용과-서버-AAC-변환-저장`, 기준 `origin/develop` `b72d56156`.
- 업로드 계약(415 조건)이 바뀌므로 BE 담당(오은서)의 MR 리뷰 합의 전에는 병합하지 않는다.

## 결정

- 웹 녹음 형식: 브라우저가 WAV(PCM16)를 올리고 서버가 AAC m4a로 바꿔 저장한다(2026-11-23 우동균, 1262의 (c)안 유지). 근거는 아래와 같다.
    - 음높이 실시간 표시 때문에 웹 녹음기는 어차피 AudioWorklet으로 PCM을 받는다. 그 PCM을 WAV로 감싸는 것이 가장 단순하고, 인코더가 필요 없어 Chrome·Edge·Firefox·Safari에서 모두 동작한다.
    - 브라우저 AAC 인코딩(WebCodecs)은 Firefox·Linux Chrome·구형 Safari에서 안 되고, MediaRecorder(Opus)는 Safari와 형식이 섞이며 Chrome WebM은 길이를 못 읽어 서버 변환이 어차피 필요하다.
    - 저장·재생 서명 URL(`audio/mp4`)·저장 키(`.m4a`)·AI 입력을 m4a 하나로 유지하려고 WAV를 그대로 저장하지 않는다.
- 변환 명령: `ffmpeg -nostdin -v error -xerror -protocol_whitelist file -f wav -i file:<원본> -map 0:a:0 -ac 1 -c:a aac -b:a 64k -movflags +faststart -f mp4 file:<변환본>`.
    - 모노로 바꾼다. AI가 어차피 모노로 디코딩하고 웹 녹음은 모노다. 샘플레이트는 AAC가 지원하면 그대로 두고, 지원하지 않는 값(예: 12345Hz)은 ffmpeg가 가까운 표준 값(12000Hz)으로 바꾼다.
    - `-xerror`로 손상·잘린 WAV는 일부만 바꾸지 않고 실패(415)로 끝낸다.
    - 기본 AAC 코더(twoloop)를 쓴다. `-aac_coder fast`는 약 2배 빠르지만 실제 비트레이트가 절반 아래로 떨어져(10분 2.2MB) 분석 입력 품질을 낮추지 않으려고 쓰지 않았다.
- 메타데이터 칼럼(`recording_bytes` 등)은 저장한 변환본의 값이다. 업로드한 WAV는 저장하지 않는다.
- 변환 상한 30초. 도구 실행 실패·시간 초과는 규격 위반이 아니라 500(`RecordingTranscodeException`)이다. ffprobe 실패(`AudioProbeException`)와 같은 처리다.
- 업로드 요청 시간: 모든 상한(ffprobe 10초 ×2, 변환 30초, 저장소 40초)이 겹치면 Nginx `proxy_read_timeout` 60초를 넘을 수 있다. 정상 경로는 10분 녹음에 수 초라 이 한도를 받아들였고, 504가 나도 서버는 처리를 이어 가 재전송이 409 → 상태 조회로 이어진다. 리뷰에서 다시 정할 수 있다.

## 변경

- `RecordingFileValidator`: MP4+AAC에 더해 WAV+`pcm_s16le`을 받고, `RecordingCheck.Accepted`에 형식(`AAC_MP4`·`PCM_WAV`)을 담는다. 크기·길이는 업로드한 파일에 그대로 적용한다.
- `RecordingTranscoder`(도메인 포트)·`FfmpegRecordingTranscoder`(ffmpeg 구현)를 추가했다.
- `UploadRecording`: WAV면 임시 m4a로 바꾸고 변환본을 다시 검사한 뒤 변환본과 그 메타데이터로 저장한다. 변환 실패는 415, 변환본 검사 실패는 그 결과(413·415·422)다. 변환본 임시 파일은 `finally`에서 지운다. 저장 키·조건부 갱신·동시 업로드 처리는 그대로다.
- `RecordingUploadConfig`: 변환기 빈을 만들어 `UploadRecording`에 넘긴다.
- 문서: [녹음 파일 규격](../specs/recording-file.md)의 업로드 표(7번 변환 추가, 저장소·DB 실패는 8·9번), 메타데이터, 범위, 완료 판정, 검증 방법. [backend README](../../backend/README.md)의 녹음 검사·시간 한도, [runtime README](../../infra/runtime/README.md)의 ffmpeg 용도.
- 실행 이미지는 이미 같은 패키지(`ffmpeg=7:8.0.1-3ubuntu2`)로 `ffmpeg`를 갖고 있어 바꾸지 않았다. 서버 사본과 같게 유지하는 `backend/Dockerfile`·`infra/runtime/backend-runtime.Dockerfile`의 주석도 바꾸지 않았다.
