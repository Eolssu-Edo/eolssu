# S15P31E102-604 백엔드 블루그린 무중단 배포 구현

- [Jira 작업](https://ssafy.atlassian.net/browse/S15P31E102-604) · Story S15P31E102-40 · Epic S15P31E102-21
- [스펙](../specs/backend-blue-green.md) · 시작 시 활성 스프린트 59321에서 진행 중 확인
- 기준 origin/develop `86c463dffe0c27fe7e28d773a894c07038795256` · 단일 Task 구현 및 검증

## 작업 순서

1. 운영 슬롯을 구분하고 악보 인식 큐와 내부 원본 읽기를 소유 슬롯에 묶는다. 기존 단일 인스턴스 경로와 구·신 슬롯 겹침을 검사한다.
2. Compose 후보·Nginx 리로드·전환 기록·롤백을 연결한다. 운영 점검·백업이 활성 버전을 찾는 경로와 최초 설치 절차를 대조한다.
3. Jenkins Python 검사와 백엔드 관련 회귀 검사를 실행한다. 격리 Docker 환경에서 실제 Nginx HTTPS 전환 중 요청, 업로드, 후보 실패 및 이전 연결 처리를 검사한다.

## 구현 메모

- `TemporarySheetSourceStorage`의 원본과 티켓은 프로세스 로컬이며 `ConversionQueue.recover`는 기존 단일 프로세스의 대기·진행 행을 정리한다. 두 슬롯에서는 소유권을 분리해야 한다.
- `Deployer.promote`는 현재 단일 백엔드를 재생성한다. 운영 Compose·웹 배포·Prometheus·점검 도구가 같은 컨테이너 또는 DNS 이름을 참조한다.

## 검증 결과

- 백엔드 호환 변경 커밋 `f06dcf8b`. 구·신 슬롯은 접수 원본과 읽기 티켓을 각각 소유한다. 삭제와 만료는 공유 디렉터리에서 처리한다. 음원 복구는 다른 슬롯이 실행 중이면 건너뛴다.
- `./gradlew test bootJar mediaTest`에서 실행 JAR을 만들었다. 단위 검사 686건 통과·1건 건너뜀, 실제 ffmpeg 녹음 검사 5건 통과. macOS에서는 심볼릭 링크가 없는 임시 경로를 `java.io.tmpdir`로 사용했다.
- 임시 MySQL 8.4.9에서 변환 큐·음원·악보 업로드 관련 `databaseTest` 51건 통과·2건 건너뜀. 두 실제 `ops` JVM을 같은 DB에 붙여 양쪽 준비 상태와 `/api/terms` 응답 일치를 확인했다. 종료와 파일 사용 해제를 확인한 뒤 전용 도구로 DB를 정리했다.
- 전체 DB 검사 301건 중 297건 통과·3건 건너뜀·1건 실패. 변경하지 않은 `BuiltinFingeringApiDatabaseTests`의 파서가 현재 프론트 악기 정의에 없는 `source` 필드를 찾다가 실패했다.
- Python 3.11에서 Jenkins 63건, 백업 15건, 운영 점검 53건, 카탈로그 76건(12건 건너뜀), 약관 4건 통과. 두 Compose 슬롯의 `config --quiet` 통과.
- 격리 Docker에서 `RUN_NGINX_TESTS=1 python3.11 -B -m unittest discover -s infra/scripts/tests` 22건 통과. 실제 Nginx와 합성 백엔드로 전환·원복 중 연속 HTTPS 104건의 실패가 0건이었고, 전환 전에 접수된 업로드의 SHA-256이 일치했다. TLS 가상 호스트에서 새 슬롯을 확인하고 외부 응답에서 점검 헤더를 숨기는 동작도 확인했다.

이 증거는 격리 환경 기준이다. edo1 최초 설치, 운영 부하에서의 자원 여유 및 실사용 녹음·OMR 경로 검사는 [최초 설치·복구 절차](../../infra/runtime/README.md#블루그린-최초-설치와-복구)를 따른다.
