## 2026-11-05 Android 검증

- 수정 전에는 단소 연습곡 1 두 번과 강원도아리랑 한 번에서 카운트다운 직후 `JeongganboView.kt`의 로컬 컴포저블 `DrawStrip` 호출이 `ClassCastException`으로 종료됐다.
- 각 그리기를 컴포저블 람다로 바꾸고 `./gradlew.bat :shared:testAndroidHostTest :androidApp:assembleDebug --offline --console=plain --max-workers=2`를 실행했다. 빌드 성공, Android 호스트 검사 860건 중 실패 0건·스킵 4건.
- 수정 APK에서 단소 연습곡 1 전체 녹음이 카운트다운을 지나 끝까지 진행됐다. 소리 없는 테스트 입력을 서버가 분석해 0점과 틀린 정간 18개를 표시했다.
- 오류 위치 → 추천 1–2각 → 1각 1–2정간 선택 → 72 BPM 반복 → 약 3초 재평가 녹음 → 분석 → 구간 재평가 결과를 확인했다. 구간은 틀린 음 4개를 표시했고, 기준 90 BPM과 속도가 달라 오류 수 비교가 불가하다고 안내했다.
- 전체 연주 두 건(오전 11:11·11:16, 각각 16초·90 BPM)을 저장했다. 최신 기록 상세의 ‘지난 연주와 비교’에서 11:11 기록을 이전, 11:16 기록을 이번으로 표시했다. 첫 기록에는 최근 2주에 비교할 이전 기록이 없다는 안내를 표시했다.
- 비교 화면의 점수 차이가 0점일 때 ‘올랐어요’로 표시되는 오류를 발견했다. 기존 ‘이전과 같아요’ 문구를 같은 점수에 연결하고 양수에만 + 기호를 붙인다.
- 검증 범위는 Android 에뮬레이터의 무음 테스트 입력이다. 실제 단소의 채점 정확도와 분석 실패의 실환경 재현은 검증 범위 밖이다.
- 문구 수정 APK를 다시 설치해 같은 두 기록에서 0점과 이전과 같아요 안내를 확인했다. Android 호스트 검사와 APK 빌드도 다시 성공했다.

## 최신 develop 통합 검증

- 343 기능 커밋 `bd870811`에 `origin/develop`의 `85a9f6d0`을 충돌 없이 통합했다. 작업 트리의 로컬 Web 프록시 설정은 커밋 범위에서 제외했다.
- 같은 분에 시작한 직전 연주를 목록에서 누락하는 회귀 테스트의 실패를 확인했다. 시작 시각을 밀리초로 보존해 기록 상세·비교 기본값·달력의 순서에 반영했다.
- 통합 APK에서 이전·이번 전체 기록과 동일 점수 표시를 확인했다. 짧은 무음 재평가에서는 소리 없음 오류와 같은 구간 복귀가 동작했다. 추천 1–2각에서 다시 평가해 결과 및 속도 차이 안내를 확인했다.
- Android 호스트 검사·디버그 APK, Web Wasm·JS 브라우저 검사를 통과했다. 배포 빌드는 최적화 단계까지 실행했다.
