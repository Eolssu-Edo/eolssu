## 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 첫 실행 흐름 | 약관 동의 → 마이크 안내 → 로그인 → (소셜 첫 가입 · 이메일 가입) → 프로필 설정 → 홈. 홈에 도착하면 첫 실행을 마친 것으로 기기에 남기고, 이후에는 홈에서 시작한다 | 권영민 결정(2026-10-27) |
| 첫 실행 저장 | 새 라이브러리 없이 `core/storage/KeyValueStore`(문자열 읽기·쓰기) + 플랫폼 구현: Android `SharedPreferences`, iOS `NSUserDefaults`, Web `localStorage`(`webMain`에서 JS·Wasm 공용). `data/user/FirstRunRepository`가 이 값을 다룬다 | 권영민 결정. 읽기가 즉시 끝나 첫 화면 전에 시작 화면을 정할 수 있다(홈이 잠깐 보이지 않음) |
| 플랫폼 구현 등록 | 소스 세트마다 `platform/PlatformModule.kt`에 Koin 모듈을 두고, 진입점이 공통 `App(platformModule)`에 넘긴다. Android `App(context)`, Web `App(onNavHostReady)`, iOS `MainViewController()` | Koin 타입을 `shared` 밖에 드러내지 않고, Android Context를 전역 변수·추가 라이브러리 없이 넘긴다. [아키텍처 8절](../../frontend/docs/architecture.md)에 기록 |
| 마이크 안내 | 실제 권한 요청은 하지 않는다(녹음 기능을 붙일 때 연습 화면에서 요청). 와이어프레임의 OS 권한 창 예시는 흉내 내지 않고, 같은 선택을 화면 하단 버튼('허용' · '허용 안 함')으로 둔다. 허용 안 함이면 로그인 화면에서 '연습을 시작할 때 마이크 권한을 다시 안내해요.'를 띄운다. 선택은 저장하지 않는다 | 권영민 결정. OS 창을 흉내 내면 실제 권한 창으로 오해할 수 있다 |
| 로그인·가입 | 서버가 없어 입력 검사만 통과하면 성공으로 본다. 로그인: 이메일 형식이 맞고 비밀번호가 있으면 성공, 아니면 비밀번호 칸 아래에 와이어프레임 실패 문구('이메일 또는 비밀번호가 맞지 않아요.'). 가입 1/2: 이메일 비어 있음·형식 오류, 비밀번호 비어 있음, 확인 불일치. 프로필: 닉네임 비어 있음. 오류는 버튼을 누른 뒤 보이고 그 칸을 고치면 사라진다 | 서버 응답(이메일 중복 등)과 비밀번호·닉네임 규칙은 아직 '[규칙 안내]' 자리라 비어 있는지만 본다. 와이어프레임의 '이미 가입된 이메일이에요.'는 서버가 붙을 때 더한다 |
| 소셜·비밀번호 찾기 | 소셜 버튼은 AUTH-05 자리 화면으로 간다. '처음 가입이에요'는 프로필 설정(단계 표시 대신 'OO 계정으로 가입'), '이미 가입한 계정이에요'는 홈. 비밀번호 찾기는 와이어프레임 안내 문구를 띄운다 | 와이어프레임 동작과 같다 |
| 악기 | 프로필 악기는 대금·소금·단소(피리 제외), 기본 대금. 고른 악기는 아직 홈에 넘기지 않는다 | 홈의 `Instrument`가 `feature/home`에 있어 다른 기능이 참조할 수 없다. 공유 모델로 옮겨지면 연결한다 |
| 공통 부품 | 입력칸·체크 상자·단계 막대는 `feature/auth/component`에 둔다. 화면에 들어올 때 이전 화면의 안내를 한 번 띄우는 `StartMessageEffect`만 `core/ui/component`에 둔다(로그인·홈이 사용) | [협업 문서](../../frontend/docs/collaboration.md) 3절: 두 번째 사용처가 생길 때 옮긴다 |
