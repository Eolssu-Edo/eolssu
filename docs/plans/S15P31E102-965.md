# S15P31E102-965 악보 편집 화면 태블릿 가로 배치

- Jira: S15P31E102-965 · Story S15P31E102-109 · 조사 근거: S15P31E102-960 조사 순위 1 `악보 편집`.
- 범위: 창 너비 Expanded(840dp 이상) 배치만 바꾼다. 편집 상태·자동 저장·저장·대화상자와 휴대폰·태블릿 세로 배치는 그대로다.

## 변경

- `SheetEditScreen`은 `widthClass`가 Expanded이면 본문·상단 바를 `WindowBreakpoints.ContentMaxWidth`(1120dp)로 넓히고 [`layout/SheetEditExpandedLayout.kt`](../../frontend/shared/src/commonMain/kotlin/com/ssafy/eolssu/feature/song/edit/layout/SheetEditExpandedLayout.kt)로 그린다.
  - 왼쪽: 빠르기 줄과 남은 높이를 모두 쓰는 악보.
  - 오른쪽: 400dp 칸에 입력판. 입력판이 창보다 길면 이 칸만 세로로 민다.
- `EditInputPanel(docked = true)`: 네 모서리를 둥글게 하고 12율 자판을 6개씩 두 줄로 놓아 가로 스크롤 없이 모두 보인다(안쪽 372dp ≥ 52dp×6 + 간격 30dp).
- `EditorTopBar`에 `maxWidth`를 받아 본문과 같은 너비로 맞춘다. 기본값은 기존 휴대폰 너비(560dp)다.

## 검증 (2026-11-16, macOS · zulu21)

- `:shared:testAndroidHostTest`: 1,822개 실행, 실패 3·제외 5. 실패 3개는 모두 `SheetAdaptationPersistenceTest`의 `hwangHz` 부동소수 끝자리 비교로, 이번 변경 없이 develop에서도 실패한다(963 세션 확인). 이 변경과 무관하다.
- `:androidApp:assembleDebug`·`:webApp:wasmJsBrowserDistribution` 성공.
- 화면: 로컬 웹에 `SheetEditScreen`을 고정 상태(아리랑 내 편곡)로 그리는 임시 하네스(커밋 안 함)로 확인했다.
  - 1280×800·1000×700·840×600: 악보 왼쪽, 입력판 오른쪽. 12율 자판 6개씩 두 줄로 모두 보이고 가로 스크롤이 없다. 시김새·정간·장단 탭도 오른쪽 칸 안에 들어간다.
  - 700×900(Medium): 기존처럼 악보 아래 입력판, 자판 가로 스크롤.
- 미확인: 실제 태블릿·Android 앱, 로그인한 운영 화면, 음역·이조 탭(하네스에 이조 내용 없음). iOS는 빌드하지 않았다.
