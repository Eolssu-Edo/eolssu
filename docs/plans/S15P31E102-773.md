## 범위와 완료 조건

DATA 내부 HTTP estimate/render, 단위별 실제 BPM·최종 MIDI/PCM 해상도·600초 사전검사, 구간 빠르기/반복/길이표를 공유하는 선율·장구 수행 시계만 소유한다. 최종 점진 변화의 역적분·균형 길이표를 위한 선택적 수행표 `tempoRatio`, `accompanimentStartTick/EndTick`와 생성기가 맡는 오류 사유를 유지한다. 정확한 양수 범위·15MiB/생성시간 제한은 기존 검증 근거에 따른다.

공통 악보 v1·기존 게시 악보/음원은 재작성하지 않는다. 앱 화면/상태·BE API/DB/migration은 이번 증분에 포함하지 않는다. 실제 CAT golden 생성 스크립트는DATA, 생성된 FE fixture와 소비자 회귀는791의 소유다. 새 수행표 필드를 읽는 FE와 생성기 배포 순서를 맞춘다. 실제 생성 성공은 실물 악기·기기 청취 검수와 구분한다.

## 결과

선행787 `ee904af6`와789 기능 snapshot `ca977b3a`를 통합한 뒤 DATA만 추출했다. DATA 전체는 최종 통합본 `9b7cda3b`와 동일하며 FE/BE/AI 신규 증분은 없다. 생성된 FE JSON6개는791에 남기고 생성 스크립트만 포함했다. 구현·검증 완료, 게시와 정식 리뷰는 루트 담당자가 진행한다.

- 격리 Python과 실제 FFmpeg/FFprobe에서 `python -m unittest discover -s data/src/playback/tests -p 'test_*.py' -q`265개 통과. `data.tests.test_jangdan_audio`, `test_reference_data`, `test_playback_import`41개도 통과했다. 처음 `-t .`를 붙인 명령은 tests 디렉터리의 package 구조와 맞지 않아 수집 실패했으며 README 명령으로 실행했다.
- 새 분할 소스의 `PlaybackService`/HTTP handler를 loopback에 띄우고 실제 renderer subprocess를 호출했다. 단소·공식 장구·FFmpeg로 step/repeat/ramp/dotted/weighted/weighted-ramp6종 모두 HTTP200. M4A SHA256·수행표 segments·MIDI 장구 타점이9b7의6개 고정 자료와 정확히 일치했다. 출력 길이는6550/12550/3323/6550/4550/3323ms다. 음원과 수행표의 원본/음원 SHA를 함께 검사했다.
