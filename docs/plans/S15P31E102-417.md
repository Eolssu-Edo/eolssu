## 진행 기록

### 2026-11-03 구현 (Windows)

- 1번 BE 중계: `IosOAuthRelayTests` 3건이 구현 전 401로 실패(경로 없음·비공개)한 뒤 통과. 공개 GET 목록에 경로를 추가했다.
- 2번 공통: `OAuthRoute`(redirectUri·복귀 주소 판정)를 두고 기존 `OAuthRedirect`(Android)·새 `IosOAuthRelay`가 구현한다. `OAuthAttempts`·`ApiAuthRepository`·`ApiUserRepository`는 플랫폼 모듈이 등록한 경로를 받고, 없으면 Android 주소를 쓴다. `IosOAuthRelayTest` 4건이 구현 전 컴파일 실패 후 통과.
- 3번 iOS: `IosExternalBrowser`(ASWebAuthenticationSession, 스킴 `com.ssafy.eolssu`)와 `IncomingLinks`·`OAuthRoute` 등록을 추가했다. **Windows에서는 iOS를 컴파일할 수 없어 미검증이다.**
- 이 PC에 Android SDK가 없어 `:shared:testAndroidHostTest`는 실행하지 못했다. 공통 테스트는 `:shared:jsTest`로 643건(실패 0)을 확인했다.
- 노션 `/auth/oauth/{provider}/start` 동작 규칙에 iOS 콜백 행을 추가했다.

### 2026-11-03 리뷰 반영

새 맥락 리뷰(중간 2·낮음 5)를 모두 반영했다.
- M1: 다시 열기에서 닫은 이전 인증 창의 늦은 완료가 새 창 참조를 지우지 않게 자기 세션일 때만 비운다(iOS, 미컴파일).
- M2: 연결·탈퇴 재인증 start와 DI 주입을 테스트로 고정했다(`IosOAuthRelayTest.everyStartSendsTheRelayRedirect`, `OAuthRouteWiringTest`). 처음부터 통과해 임시 변형(연결 start를 Android 주소로, DI 인자 제거, 포트·사용자 정보 검사 제거)으로 세 테스트가 각각 실패함을 확인하고 원복했다.
- L1: 포트·사용자 정보가 붙은 복귀 주소 거절을 테스트에 추가했다.
- L2: 중계는 같은 이름의 매개변수를 첫 값만 옮긴다. 테스트가 구현 전 실패한 뒤 통과.
- L3: 중계 테스트를 `feature/auth/api`로 옮기고 `error_code` 전달을 확인한다.
- L4: 인증 창 앵커를 연결된 장면의 키 창(없으면 첫 창)으로 바꿨다(iOS, 미컴파일).
- L5: 앱 전용 스킴 상수를 `core/browser.APP_CALLBACK_SCHEME`으로 옮겨 iOS 인증 창이 data 계층을 참조하지 않는다. 경로 등록(`OAuthRoute`)은 플랫폼 모듈의 DI 연결이라 data 참조가 남는다.
