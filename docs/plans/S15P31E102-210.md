## 독립 선행 보완

- 재설정 메일 주소·코드 HMAC·인증 행을 DB의 등록 이메일에 묶는다. `users.email` collation이 같은 변형을 기존 회원으로 판정해도 입력 변형 주소로 발송하지 않는다. 회원이 없는 요청은 기존처럼 입력값 기반 가상 행과 같은 202 정책을 유지한다.
- 단위 검사: `mémber@example.com`을 DB가 `member@example.com` 회원으로 찾는 대역에서 수신 주소/인증 행을 확인했다. 기존 코드에서 입력 주소로 발송해 실패한 뒤 수정 후 집중 15개 통과.
- ACCOUNT_MERGE 발송의 동일 문제는 211에서 새 등록 주소 조회를 재사용해 적용해야 한다. 이번 선행 변경은 PASSWORD_RESET만 대상이다.
- 재설정 소비 구현 시에는 사전 토큰 조회로 회원을 식별하되 잠금은 users → 인증 행 → refresh_tokens 순서로 잡아, 209의 users → 인증 행 삭제와 순서가 뒤집히지 않게 한다. 오래된 입력 변형 주소로 발급된 토큰은 DB 저장 이메일과 정확히 일치하는지도 확인해야 한다.

## 재설정 본체 구현(2026-10-29)

- 기존 HTTP 경로에 테스트를 먼저 추가해 미구현 실패를 확인한 뒤 서비스·MyBatis·컨트롤러를 붙였다. 등록 이메일 증명 → 회원 잠금 → 증명 잠금/재검증 → 해시 저장/증명 소비/refresh 폐기를 한 트랜잭션으로 처리한다. Argon2id 계산은 잠금 밖이며 자동 로그인하지 않는다.
- 합의한 세 정책을 그대로 반영했다. 만료/무효 토큰 401 EMAIL_NOT_VERIFIED, 동일 비밀번호 400 INVALID_REQUEST, 기존 잠금 카운터 유지. 필수 필드 누락·잘못된 JSON은 공통 400이다. 저장 중 비밀번호가 다른 요청으로 바뀌면 덮어쓰지 않고 401로 다시 인증하게 한다.
- 단위 경계: 계산 중 만료·소비·무효화·해시 변경, users → 인증 행 → refresh 순서, 잠금 안에서 Argon2 계산 안 함. 인증 행 잠금 대기 중 만료는 추가 실패 테스트로 재현한 뒤 시각을 잠금 획득 후 읽도록 고쳤다.
- HTTP/MySQL 경계: 재사용/목적/만료/무효화/대상 없음/과거 변형 주소, 동일·잘못된 비밀번호 후 재시도, 탈퇴 대기 유지, 동시 소비 204 한 건/401 한 건, 로그인 잠금·현재 비밀번호 카운터 유지, refresh 폐기 실패 주입 시 해시/증명 롤백, 발송→확인→재설정 연계(만료 access 쿠키 무시). SMTP는 수신 대역이다.
- 검사 fixture는 운영 매퍼와 동일한 UTC LocalDateTime·마이크로초를 쓰고 테스트 간 로그인 카운터를 격리했다. 운영 제한/정책을 완화한 것이 아니다.
- Notion은 이 API의 기존 Request/Response/Exceptions 구조에서 확정한 계약만 바꾸고 Status In progress로 표시했다. 비고는 1차를 유지하고 개발 기록은 추가하지 않았다.

## 리뷰 P2: 회원 보조 인덱스/PK 교착 수정

- 검토 범위 `f891dfa..32d4d2e`(20개 파일). 별도 리뷰어의 정적 검토와 MySQL 8.4 잠금 재현을 대조했다. 재설정의 이메일 FOR UPDATE는 email 인덱스를 먼저 잡고 PK를 기다리지만, 일괄 삭제는 PK를 잡고 email=NULL 변경 시 email 인덱스를 기다려 교착했다. 삭제는 다음 날로 미뤄지거나 재설정은 500이 될 수 있다.
- 수정 전 HTTP/운영 저장소 회귀 테스트에서 삭제의 PK 잠금을 먼저 잡고 실제 `performance_schema.data_lock_waits`의 PK 대기를 관측한 뒤 209의 purge를 진행했다. 재설정 401 기대에 실제 500·DeadlockLoserDataAccessException이 발생했다. 고정 sleep 없이 두 트랜잭션의 실행 순서를 제어한다.
- 수정: 사전 조회한 회원 ID로 `users.id` PK FOR UPDATE를 수행한다. 잠금 뒤 ACTIVE/WITHDRAWAL_PENDING 상태·ID·등록 이메일·비밀번호 해시를 재검증하고, 그 뒤 인증 행/refresh를 처리한다. 응답·비밀번호·기존 잠금 카운터 정책은 변경하지 않는다.
- 수정 후 집중 검사: 단위 5개·HTTP/DB 9개 통과. 새 동시 실행 검사는 삭제 성공·회원 DELETED/email NULL·인증 행 삭제·재설정 401을 확인한다. 최종 전체 회귀와 커밋 결과는 아래에 기록한다.
