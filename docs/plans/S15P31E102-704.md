- Jira: [S15P31E102-704](https://ssafy.atlassian.net/browse/S15P31E102-704), 담당 박찬형.
- Story S15P31E102-26 `Relates`, 활성 스프린트 59321(`S15P31E1 1 스프린트 5`), 진행 중. 시작 절차는 주 에이전트가 MCP로 변경·재확인했다.
- 사용자 요청: 기존 파일로 채점 가능한 곡은 별도 Jira로 분리해서 변경한다.

## 실행 순서

1. 36곡의 신원·악보 해시를 고정한 계획 및 채점 값만 바꾸는 도구를 준비한다.
2. 작은 실패 사례와 실제 격리 MySQL에서 보존·충돌·재실행을 검사한다.
3. 주 에이전트가 실행 범위와 증거를 검토하고 운영 lock·백업 후 적용한다.
4. 공개 API·AI 연결·원본 보존을 확인하고 결과를 남긴다.

## 현재 기록

- 36곡의 기존 이벤트 전체·음악 설정·원본 해시는 699에서 확인했다. `/score`도 전부 200이었다.
- 직접 계산한 기본 BPM의 채점 음표 구간은 14.55–95.25초, 쉼까지 포함한 곡 끝은 최대 97초다. 현재 AI의 4GiB DTW 예상 메모리 제한은 전체 길이와 같은 녹음을 가정하면 전곡 통과한다. 최대 예상치는 67번의 2,217,420,000byte다. 실제 추론 통과를 뜻하지 않는다.
- 실제 AI 소스의 Pydantic 입력 모델에 36곡 1,838개 음표를 넣어 통과했다. [검증 방법·한계](../knowledge/data/existing-score-enablement.md)를 남겼다.
- 채점 UPDATE가 없는 초기 구현에서는 MySQL 활성화·충돌 검사 3개가 실패했다. 트랜잭션 구현 후 로컬 Docker MySQL 8.4에서 10개 검사가 모두 통과했다(사전 조건 4, 실제 DB 6). 전체 적용·재실행 0·부분 완료 시각 보존·뒤 곡 충돌 롤백·음원 추가/삭제·동시 채점 값 변경을 포함한다.
- `git diff --check` 통과. 운영 명령과 격리 DB 재현 절차는 [catalog README](../../infra/catalog/README.md#기존-악보를-유지한-36곡-채점-켜기)에 있다.
- 운영 쓰기는 주 에이전트가 수행한다. 이 worktree에서 운영 데이터는 변경하지 않는다.
