# S15P31E102-513 QA 이름 입장 전환

- 담당 우동균, Epic21, Story328 관련, 활성 스프린트59245(4), 진행 중을 MCP로 확인했다. 완료된498은 재개하지 않고 별도 접근 정책 변경으로 분리했다.
- [스펙](../specs/qa-name-entry.md). 기준은 새로 fetch한 origin/develop이며 현재 checkout은 `feat(infra)/S15P31E102-513-QA-접속을-이름-입력으로-전환`이다. 기존 작업 트리는 깨끗했고 사용자 변경은 없었다.
- 순서: 이름-only HTTP 실패 검사 → 서버/UI/실행 설정의 키 요구 제거 → 기존 세션/제어/설치 회귀 → 공개 중계별 재시작 → 두 페이지 실제 입장 → 운영 문서와 결과/정리.
- 사용자 요청에 따라 주소 보유자가 이름만으로 입장할 수 있음을 시작 안내와 스펙에 명시했다. 제어권·세션 격리·기기 ID 고정은 유지한다. 제품 로그인/API 명세가 아니라 별도 QA 도구의 입장 계약 변경이며 이 스펙에 기록한다.
- 이번 요청은 구현·검증·운영 반영이다. 새 작업의 커밋/Push/MR/병합은 요청 범위에 포함하지 않는다.
- 후속 사용자 결정: 조작자·참여자 모두 10분간 활동이 없으면 1분 확인을 띄우고, 응답 없으면 해당 연결만 종료한다.
- 검증: Node 테스트 78개 통과. 테스트 시계로 10분/1분 경계와 응답 후 연결 유지, 미응답 조작자·참여자의 만료와 영상/제어권 해제, 8시간 상한을 확인했다. JavaScript 구문, PowerShell 8개 스크립트 구문, 키 없는 시작 설정과 기존 설정 호환을 확인했다.
- 운영: Windows의 두 감독을 한 대씩 정상 재시작했다. 2026-11-05 공개 HTTPS 휴대폰(Galaxy S10)·태블릿(Galaxy Tab S9 FE) 페이지를 새로고침해 이름 입력만 남은 것을 확인했고, 각각 같은 테스트 이름으로 입장해 실제 기기 화면 표시까지 확인했다. 테스트 세션과 재시작용 중지 표시는 정리했다. 10분/1분 검증은 위 가상 시계로 수행했다. [운영 안내](../../infra/qa-phone/OPERATIONS.md).
- 2026-11-06 운영 복구: 이전 QA 작업 폴더를 사용하던 두 중계를 현재 작업 폴더로 전환했다. 공개 브라우저에서 이름 입장, 디버깅 포트 라벨·입력칸·버튼의 세로 중앙 일치, 헤더 제어 버튼과 기기별 연결 대기 문구, 한국시간 APK 이력과 최신 업데이트 버튼을 확인했다. 실기기 영상은 두 기기의 무선 디버깅 주소가 연결을 거부해 이번 확인에서 보류했다. Node 테스트 78개가 통과했다.
- 운영 설정에서 이전 접속 키 경로를 제거하고 기본 위치의 기존 키 파일을 복구 가능한 이름으로 바꿨다. 이전 감독의 설정 검사가 현재 두 운영 설정을 거부하고, 공개 페이지에는 이름 입력만 표시됨을 확인했다. 다른 작업이 소유한 이전 Git 작업 폴더는 보관 처리가 차단되어 유지했다. [현재 PowerShell 실행 명령](../../infra/qa-phone/OPERATIONS.md).
- 2026-11-06 실기기 재검증: 사용자가 확인한 휴대폰 40801과 태블릿 38329를 기존 QA 포트 변경 절차로 적용했다. 등록된 기기 ID 확인, 두 중계의 재시작, 공개 브라우저에서 이름 입장과 실시간 영상 표시를 확인했다. 각 화면의 빈 곳에 터치 1회를 전송해 중계 응답 200과 입력 순번을 확인했다. 휴대폰은 영상을 열어 둔 상태에서 터치했다. 검증용 세션과 포트 변경 요청 파일은 정리했다.

- 2026-11-12 갤럭시 S10 후속: 페어링 성공을 무선 감시기에 전달하고, 진행 중인 포트 탐색을 재개한다. mDNS 응답이 없는 경우와 잘못된 기기 ID를 검사한 뒤 공개 QA 탭을 열어 둔 상태에서 포트 변경과 화면 복구를 확인한다.
- 자동 복구 검증: 포트 검색 재개 회귀가 수정 전 실패하고 수정 후 통과했다. 전체 QA Node 테스트 81개가 통과했다. 운영 S10에서 무선 포트 `42207` → `39609` 변경, 연결 대기 중 페어링 `200`, 등록된 기기 자동 확인, 기존 공개 QA 문서에서 실시간 영상 복구를 확인했다. USB는 기기의 무선 디버깅 전환과 페어링 팝업 조작에 사용했다. Windows의 기존 S10 예약 작업에서 이 변경을 실행한다.
- 2026-11-13 후속: S10의 USB를 통해 TLS 포트만 알아내고 등록 기기 확인 뒤 무선 중계를 복구한다. 명령 실패와 케이블 분리 시 기존 탐색으로 돌아가는지 확인하고, 운영에서 포트 변경부터 기존 탭의 첫 영상까지 실측한다.
- 운영 검증: 포트 `41821` → `35823`에서 USB 경유 탐색 로그와 TLS 중계 등록 5.58초를 확인했다. 같은 브라우저 문서에서 약 19초 이후, 27.3초 이내에 실시간 영상이 돌아왔다. 초기 검증에서는 ADB 조회 및 캡처가 지연됐으며, 최종 코드에서 USB가 읽히면 리스너 시작을 짧게 기다린 후 예비 탐색을 재개하도록 보완했다. [운영 기록](../../infra/qa-phone/OPERATIONS.md).
- 2026-11-13 케이블 없는 복구: USB 우선 확인을 유지하고 S10이 운영 PC의 인증된 유니캐스트 요청에 TLS 포트 후보만 응답하게 한다. USB 없이 무선 디버깅을 껐다 켜서 변경된 포트와 기존 브라우저 탭의 영상 복구까지 실측한다.
- 운영 실측: USB 기기와 mDNS 검색 결과가 없는 상태에서 `35823` → `36813`으로 변경했다. 인증된 포트 응답부터 TLS 연결과 기기 ID 확인까지 2.92초, 동일한 공개 QA 문서의 새 영상 프레임 관측까지 20.21초가 걸렸다. S10 전용 예약 작업에 반영했고 전체 Node QA 테스트 85개가 통과했다. 빌드 임시 디렉터리는 정리했다. [복구 절차](../../infra/qa-phone/OPERATIONS.md).
- 태블릿 연결 장애 조사: QA 중계와 공개 웹은 정상 응답했고 저장 주소 `192.168.30.89:38329`는 연결을 거부했다. 사용자가 알려준 새 주소 `192.168.30.89:45369`는 ADB `STLS`를 반환했으나 Windows ADB 로그에서 `SSLV3_ALERT_CERTIFICATE_UNKNOWN`으로 연결이 종료됐다. 포트 도달 이후 태블릿이 운영 PC의 인증서를 거부하는 상태이며 재페어링을 요청했다. 실제 영상 복구는 대기 중이다. 빠른 유니캐스트 포트 조회와 USB 우선 조회는 현재 S10 전용이고 태블릿은 기존 자동 검색을 사용한다. 탐색 중 생성한 실패한 ADB 연결은 개별 정리했다.
- 태블릿 복구 확인: 사용자가 `36505`에서 운영 PC와 태블릿을 재페어링한 뒤, 같은 연결 주소 `192.168.30.89:45369`의 TLS 연결과 등록 ID `R54X3035L8J` 확인이 성공했다. 기존 포트 적용 절차로 중계가 해당 주소를 채택해 `connected`로 저장됐다. 열려 있던 Chrome 태블릿 QA 탭에서 새로고침을 실행하지 않고 `태블릿 연결됨`, 새 포트, 화면 캔버스의 실시간 영상 프레임 표시를 확인했다. 포트 자동 탐색으로 복구한 결과와 구분한다. 탐색 중 남은 실패 연결과 포트 적용 요청 파일은 정리됐다.
