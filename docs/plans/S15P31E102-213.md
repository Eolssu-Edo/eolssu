## 검증

2026-10-28, 개발 노트북(Apple Silicon, linux/arm64 이미지), Docker 29.5.2.

- `docker build -t eolssu-ai:check .` 성공, 이미지 약 1.65GB. 이미지 안 `ffmpeg 8.0.1-3ubuntu2`, `ffprobe 8.0.1-3ubuntu2`, `dpkg ffmpeg 7:8.0.1-3ubuntu2`, `Python 3.12.16`, `id -u` 10001.
- 이미지 안 테스트(README 명령): 63 passed. `tests/unit/test_audio.py`의 헤더·중간 손상, 끝 잘림 → `DECODE_ERROR`를 포함한다.
- 기동 확인: 외부로 나가지 않는 `docker network create --internal` 네트워크에 저장소 대역(같은 이미지의 `python -m http.server`)과 기본 명령의 API 컨테이너를 띄웠다. -20센트 합성음 m4a 요청 1건에 200 `DONE`(요청 idx 3~6, 조율 보정 -15.0센트), 로그 `result=DONE ms=3282`. 컨테이너 사용자 10001, 호스트 포트 없음, 로그에 서명 토큰 0회.
- 저장소 대역이 없을 때 같은 요청은 502 `DOWNLOAD_FAILED`, 로그에 토큰 0회.
- 대역 요청은 이미지가 뜨고 경로가 이어지는지 확인한 것이며 채점 품질 검증이 아니다. amd64 운영 서버용 빌드는 하지 않았다.

## 발견

- 처음 이미지로 띄운 API가 채점 첫 호출에서 500(`ERROR:RuntimeError`)을 냈다. numba가 `@jit(cache=True)` 함수의 캐시를 `/app/.venv/.../librosa` 옆이나 `$HOME/.cache`에 쓰려는데, 사용자 10001은 둘 다 쓸 수 없다. root로 돌린 이미지 안 테스트는 통과해서 드러나지 않았다. `NUMBA_CACHE_DIR`을 비우면 같은 오류가 다시 나고, 넣으면 통과하는 것을 확인했다.
- 다시 빌드한 직후 첫 실행에서 한 번 같은 오류가 났지만, 같은 이미지로 여러 번 다시 실행해도 재현되지 않았다. 원인은 확인하지 못했다.
- Docker Desktop은 `/private/tmp` 아래 경로를 bind mount하지 못한다. 대역 파일은 `docker cp`로 넣었다.
