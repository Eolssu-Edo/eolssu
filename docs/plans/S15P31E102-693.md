# S15P31E102-693 내 악보 편집에서 정간보와 오선보 전환 연결

- Story S15P31E102-319, Sprint 5 진행 중. 기준 `origin/develop` `ca1fc45c`, 별도 작업공간에서 시작.
- 개인 악보와 제공 곡 복사본의 편집기를 정간보로 연다. 오선보 탭을 선택하면 현재 공통 악보에서 생성한 실음 표기를 표시한다. 원본 PDF의 조표나 마디 배치는 공통 악보에 없다.
- 오선보의 단선율 음표를 선택하고 음높이를 위아래로 바꿀 수 있다. 정간보와 같은 초안에서 실행 취소와 저장을 사용한다. 음높이만 바꿨을 때 정간의 row/col, 이벤트 ID·tick·길이, 이음, 가사와 시김새를 유지한다.
- 12평균율 황종 기준과 4분·점4분음표 BPM 단위의 음가를 지원한다. 미완성 초안이나 지원 범위 밖의 악보에는 이유를 표시하고 정간보에서 계속 편집할 수 있게 한다.

## 작업 계획

1. 336의 생성 오선보 변환을 참고해 시간과 음표 선택을 공통 악보에 대응시킨다.
2. 오선보 탭과 음높이 편집을 실제 편집 초안에 연결하고, 음높이 치환 시 기존 소박을 유지한다.
3. 다열 소박·이음·옥타브·셋잇단음표·미지원 입력을 검사하고 Android 호스트와 Wasm 컴파일을 확인한다.

## 구현과 검증

- 실제 편집기에 공통 악보의 tick과 음높이로 생성한 오선보를 연결했다. 336의 음가 분할과 벡터 표기를 참고했고, 가로 목록에서 붙임줄 조각을 눌러도 같은 시작 소박이 선택된다. 12평균율에 맞는 황종을 사용하며 1센트를 넘는 조율 차이나 한도를 넘는 음표 수는 안내한다. 음가 지원 범위는 64분음표, 겹점, 3:2 셋잇단음표와 붙임줄이다.
- 음높이만 고친 초안은 원본 이벤트 시간과 배치를 그대로 사용한다. 다열 소박의 두 번째 음을 바꾸고 나머지 음·이음·가사·숨표·시김새와 ID·tick을 비교했다. 높은·낮은 음역, 다른 황종, 셋잇단음표와 쉼, 미완성·미지원 악보도 검사했다.
- 처음 실행한 집중 검사는 공용 Kotlin 데몬의 Android 컴파일이 정체되어 중단했다. 컴파일러를 Gradle 프로세스 안에서 실행하고 작업자 수를 1로 제한한 뒤 전체 Android 호스트 검사 1,228개 중 1,224개가 통과했다. 기존 4개를 건너뛰었고 실패·오류는 없었다. 새 오선보 검사 3개 모두 통과했다.
- 제목·빠르기 편집(689)과 별개로 병합할 수 있도록 실제 악보 보기 탭을 도구줄 왼쪽에 배치했다. 두 브랜치의 병합을 사전 검사해 충돌이 없음을 확인했다.
- 최종 변경에서 `gradlew.bat :shared:testAndroidHostTest :webApp:compileKotlinWasmJs --max-workers=1 '-Pkotlin.compiler.execution.strategy=in-process' '-Dorg.gradle.jvmargs=-Xmx5g -Dfile.encoding=UTF-8' --console=plain` 성공. `git diff --cached --check` 통과. 기기·브라우저 화면 조작, iOS 실행, 독립 리뷰는 확인 대기다.
