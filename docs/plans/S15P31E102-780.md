- 범위: 기존 Android 호스트 테스트의 대역을 상세 화면이 쓰는 미리보기 조회에 맞춘다. 앱과 Jenkins 설정은 변경 대상에서 제외한다.
- 완료 조건: 상세 요청 실패 후 목록 메모를 유지하고, 다시 시도하면 서버 메모를 반영한 뒤 해당 판본의 악보를 조회한다. 동일 케이스의 수정 전후 결과, 관련 기록 테스트, 전체 Android 호스트 테스트 및 디버그 APK 빌드를 확인한다.

## 원인과 결정

Android QA #256(`cd8eec72`)은 성공했고, #257~#260은 모두 같은 `HistoricalRecordTest` 단언에서 실패했다. 첫 실패인 #257(`8f270078`, MR !617)부터 화면은 `records` 대신 `detailPreview`를 호출한다. 테스트의 `by sample`은 이 호출을 원본 샘플에 넘겨 테스트 대역이 준비한 ‘목록 캐시’가 아닌 빈 메모를 읽었다.

실제 목록 화면은 선택한 행을 상세 진입 전에 넘긴다. HTTP 저장소는 현재 로그인 세션과 기록 ID가 맞을 때만 이 미리보기를 반환하고 세션 변경 시 목록과 미리보기를 지운다. 기존 HTTP 테스트가 이 경계를 확인한다. 따라서 실패한 ViewModel 테스트의 대역에서 목록 행을 미리보기로 직접 제공하고, 메모와 재시도 흐름을 관찰한다.
