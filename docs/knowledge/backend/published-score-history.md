# 공개곡 판본을 바꾼 뒤 기존 연주 결과 보존

2026-11-11 · S15P31E102-745. [계약](../../specs/published-score-history.md) · [게시 절차](../../../infra/catalog/airplane-revision.md)

## 원인과 선택

연주 세션에는 `score_version`이 남지만 기존 공개곡 조회는 `songs`의 현재 JSON만 읽었다. 앱 결과·기록 상세는 현재 판본과 저장 결과 판본이 다르면 실패했고, 진행 중 분석·취약 구간·구간 비교도 저장 당시 악보를 구할 수 없었다. 정악대금 56의 4→6 tick/박 교정은 같은 v1을 덮어쓰면 이전 세션의 시간 해석을 바꾸므로 새 판본이 필요했다.

음원 행에는 해시와 객체 키가 있지만 과거 악보 본문·상세 메타데이터를 복원하는 계약은 없다. 현재 악보 JSON만 보관해도 제목·악기·기본 빠르기·음표 수와 상세 응답이 어긋날 수 있다. 따라서 V38 `song_score_versions`에 공개곡의 판본과 당시 공개 메타데이터를 함께 불변 보관한다. 변경 게시기가 기존 행 복사와 현재 판본·새 음원 변경을 한 트랜잭션으로 처리한다. 사용자 녹음·평가 결과는 복제하거나 고쳐 쓰지 않는다.

## 읽기와 새 연습 경계

- 공개 상세·악보의 선택적 `scoreVersion`은 정확한 판본을 읽는다. 현재 곡과 보관 행 모두 공개·미삭제일 때만 과거 판본을 공개한다. 미지정은 기존 현재 조회다. 없는 판본을 현재로 대체하지 않는다.
- 진행 중 분석과 사용자 결과의 음표·정간 조회는 인증·소유권을 확인한 기존 흐름에서 세션 판본을 명시한다. 기존 내부 읽기의 상태 정책을 변경하지 않는다.
- PRA-03 세션 상세와 연주 기록 응답의 `scoreVersion`은 저장된 DB 값이다. PRA-03의 `songTitle`은 보관 판본 제목이며, 보관 행이 없으면 연결된 현재 곡 제목을 쓴다. 곡이 비공개가 되어도 본인 기록의 제목·점수·메모·녹음 조회를 막지 않는다. 앱 결과·기록·비교는 그 판본으로 곡을 읽고, 같은 곡 다른 판본의 화면 상태를 재사용하지 않는다.
- 453의 범위: 새 전체 연습은 현재 판본이다. 구판 기록에서 새 구간을 녹음할 때 앱은 현재 판본을 다시 확인하고, 서버는 부모 세션 판본이 다르면 기존 409 상태 충돌로 거부한다. 같은 idempotency key의 기존 세션 재전송을 먼저 처리하는 순서는 유지한다.
- 453의 범위: 전체 연습 화면을 열어 둔 사이 판본이 바뀌는 경우도 막는다. 녹음 시작 시 판본을 고정하고 화면 복원·재시도에 유지한 뒤 PRA-01의 선택적 `expectedScoreVersion`으로 제출한다. 현재와 다른 판본은 삽입·업로드 전에 409로 거부한다. 값을 생략한 기존 요청의 해시는 바꾸지 않는다.

## 검증과 적용 상태

이번 분리의 실제 명령과 결과는 [745 계획](../../plans/S15P31E102-745.md)에 기록한다. 원본 MR !576의 서버·DB·R2 검증은 당시 증적이며 이번 브랜치의 통과 수로 재사용하지 않는다.

병합 순서는 745 → 453 → 454 → 707이다. 745의 V38은 표만 만들며 데이터를 바꾸지 않는다. 운영 v2 공개 전에 453의 구앱 판본 미지정 거부와 454의 정확한 판본 조회를 배포하고, 구 설치본 사용자의 업데이트·전환 방안을 확인해야 한다. 활성 세션 0건이나 새 앱 업로드 성공만으로 앱 안의 미제출 녹음을 보호하지는 못한다.
