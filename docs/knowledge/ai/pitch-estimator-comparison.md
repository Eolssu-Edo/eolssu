# 음높이 추정 방법 비교: 합성 입력

- 작업: [S15P31E102-62](https://ssafy.atlassian.net/browse/S15P31E102-62)
- 상태: 합성 입력 비교 완료, 실제 대금 녹음 비교 전. **채택한 방법 없음.**
- 재현: `ai/`에서 `uv sync --group eval` 후 `uv run --group eval python -m evaluation.run_evaluation`
- 코드: [채점](../../../ai/src/ai_service/pipelines/scoring.py), [합성 입력](../../../ai/evaluation/synthetic.py), [비교 실행](../../../ai/evaluation/run_evaluation.py)

## 결론

| 방법 | 판정 일치 | 전부 맞은 입력 | 5.5초 입력 추정 시간 |
| --- | --- | --- | --- |
| pYIN | 299/300 | 29/30 | 0.27초 |
| torchcrepe full | 310/310 | 30/30 | 7.89초 |
| torchcrepe tiny | 310/310 | 30/30 | 0.34초 |

- 합성 입력으로는 세 방법의 판정 정확도가 거의 같다. 유일한 차이는 **신호와 같은 크기의 잡음(0dB)에서 pYIN이 소리를 전혀 찾지 못해 `NO_SOUND` 실패**를 낸 것이다.
- torchcrepe full은 CPU에서 녹음 길이보다 오래 걸려 서버 채점에 부담이 크다. tiny는 pYIN과 비슷한 속도다.
- pYIN은 기본 설정에서 음높이를 10센트 단위로 잰다. 표의 pYIN 음정 오차 0.0은 더 정확하다는 뜻이 아니라 이 단위 때문이다. torchcrepe의 1~5센트가 실제 측정 오차에 가깝다.
- 합성음에는 실제 대금의 숨소리 섞인 음색, 불규칙한 떨림, 배음 변화가 없다. **방법 선택은 실제 녹음 비교 후에 한다.**

## 입력

정악대금 음계를 흉내 낸 합성음이다. 기준음 311.13Hz에서 0·2·5·7·9·12·9·7·5·2·0 반음을 120BPM 한 박씩 분다. 소리는 기본음과 2·3배음(크기 1, 0.5, 0.25)이고, 16kHz다. 정답 판정은 입력을 만들 때 정한 값이다.

## 환경

- 2026-10-22, 커밋 `ce4a2b3` 이후 작업 트리
- Windows 11, Intel 20스레드 CPU, GPU 미사용
- Python 3.12.10, librosa 1.0.0, numpy 2.5.4, torch 2.14.1+cpu, torchcrepe 0.0.24
- pYIN: fmin 100Hz, fmax 2500Hz, frame 1024, hop 10ms
- torchcrepe: fmin 100Hz, fmax 2000Hz, hop 10ms, 주기성 0.21 미만 프레임은 무음, 주기성 3프레임 중앙값 필터
- 채점 허용 범위: 음정 ±50센트, 시작 박의 1/8(62.5ms), 길이 ±25%, 조율 보정 ±100센트. 녹음으로 검증하기 전의 제안 값이다.
- 추정 시간은 방법별 첫 호출(JIT 컴파일·모델 로딩)을 뺀 값이다.

## 비교 중 고친 채점 문제

**같은 음 반복의 늦은 시작을 못 잡음.** 앞 음과 높이가 같으면 높이로는 경계를 알 수 없어, 반복된 음이 150ms 늦어도 세 방법 모두 `CORRECT`로 판정했다. 처음에는 무음 프레임으로 경계를 찾으려 했지만 pYIN은 40ms 끊김을 무음으로 잡지 않았다. 그래서 채점에 프레임 음량(`frame_rms`)을 선택 입력으로 넣고, 앞 음과 높이가 같은 음은 음량이 크게 줄었다가 다시 올라온 첫 프레임을 시작으로 본다. 끊지 않고 이어 분 같은 음은 여전히 구분하지 못한다.

**요성 음의 시작이 늦게 잡힘.** 요성처럼 크게 떠는 음은 음의 중앙값 근처에 늦게 들어와 시작이 늦게 잡혔고 `TIMING`으로 잘못 판정됐다. 음 시작을 "앞 음보다 이 음의 높이에 더 가까워진 첫 프레임"으로 바꿨고, `ai/tests/unit/test_scoring.py`에 같은 경우의 검사를 추가했다. 이 변경으로 정상 입력의 시작 오차가 약 18ms에서 5ms로 줄었고, 보정 범위 밖(-120센트) 입력의 총점은 67점에서 49~54점으로 바뀌었다.

## 새 방법을 비교하는 법

1. `(audio, sr) -> f0` 함수를 만든다. f0는 10ms 간격의 Hz 배열이고 소리가 없는 프레임은 NaN이다. 음량은 방법과 상관없이 `frame_rms`로 따로 구하므로 만들지 않아도 된다.
2. `ai/evaluation/run_evaluation.py`의 `METHODS`에 이름과 함께 추가한다.
3. 필요한 패키지는 `ai/pyproject.toml`의 `eval` 그룹에 넣는다.
4. 비교를 다시 실행하고 이 문서의 결론과 전체 결과를 갱신한다.

새 입력을 추가할 때는 `CASES`에 이름, 확인하려는 것, 합성 인자, 정답 판정을 적고 이 문서의 입력 표에도 한 줄을 더한다.
