# 정간보 스캔 모델 실행과 독립 롤백 (458)

S15P31E102-458은 Story S15P31E102-318, 활성 스프린트 59321의 기존 정간보 전용 Task다. 사용자 2026-11-12 요청에 따라 오선보 MR !649와 별도 브랜치에서 구현했다. 최초 기준 develop f44ef9f4에서 독립 구현한 뒤 최신 develop 58ffdba7까지 통합했다. 오선보 !649는 그 사이 별도로 병합됐으며 이 MR 차이에는 정간보 변경만 포함한다. 원래 요구한 스캔→초안 변환과 독립 MR 범위를 유지했다.

## 동작과 경계

글자 층 없는 PDF와 PNG/JPEG를 기존 DATA 리더로 읽고 같은 JGB→공통 악보 변환기에 연결했다. 검출 격자 열은 율명을 못 읽어도 유지하고 옆 열의 칸 위치로 누락을 보완한다. 인식 원문·신뢰도·원본 쪽/상자를 정간 ID에 연결한다. 지원하지 않는 독립 시김새만 제외해 UNREADABLE로 알리고 읽힌 율명은 남긴다. 애매한 칸을 높은 신뢰도로 읽을 수도 있으므로 결과는 inferred 초안이다.

추론은 Audiveris 잠금을 함께 사용해 동시 1건이다. CPU 배치는 16개, 스레드는 2개다. 텍스트 검사 시간을 포함해 기존 쪽당 60초, CPU 2개, 메모리 2GiB를 유지했다. 원본 모델 폴더는 읽기 전용이고 LayerNorm 이름을 변환한 체크포인트는 요청별 임시 경로에만 만든다. 요청 종료 시 자식 프로세스·쪽 그림·변환 체크포인트를 정리한다.

인쇄 열 하나에 여러 장단이 들어간 경우 음악적 각 경계까지 확정하지 못한다. 검출한 최빈 정간 수를 사용하고 JANGDAN_MISMATCH를 남긴다. 아리랑의 율명 일치는 리듬·장단·시김새 정확도의 증거가 아니다. 실제 촬영 사진의 기울기·원근·다른 글꼴과 전곡 음표별 정확도는 미검증이다. 기울기·원근·그늘 보정은 1059에서 추가했고 합성 사진으로만 검증했다([보정 기록](jeongganbo-scan-rectify.md)). 동동 PNG/JPEG의 모델 결과도 완전히 같지는 않았다.

### 리더 안에서의 동작

- `--yul`은 `reader.omr.model.inference`를 바꿔 끼운다. 격자 리더 본 읽기·`--fill-grid` 보충 읽기·`--grid-boxes` 읽기가 모두 같은 모델 객체를 거치므로 마지막 크기 재시도에도 제한이 적용된다.
- `--batch-size`의 `BoundedBatches`는 `tokenizer`·`model`을 원래 Inferencer에서 그대로 넘겨 주고, 배치를 나눠 같은 Inferencer를 부른다. 따라서 바꿔 끼운 해독 함수가 모든 배치에 쓰인다.
- 모델 어휘(142개)에 중청 계열은 중청황뿐이다. `danso`의 중청태와 `sogeum`의 중청태·중청고는 안내만 출력하고 모델이 내지 못한다. 이 율명은 그 뒤 `recover_water_register`가 청 율명 글자의 두 물수변을 확인했을 때만 나온다. 복원은 `--yul` 목록으로 거르지 않으므로 글자에 근거가 있으면 목록 밖 중청 율명(예: 단소의 중청중)도 남는다.
- 신뢰도는 제한 전 모델 분포에서 고른 토큰의 확률로 바꿨다. 이전 리더는 남은 후보끼리 다시 나눠 확률을 높였다. 그러면 모델이 목록 밖 율명을 가장 높게 본 칸도 확인 기준(0.8)을 넘을 수 있었다. MALerLab `TransformerOMR.inference`는 단계마다 제한 없는 softmax의 최댓값을 곱하므로, 고른 토큰이 제한 전에도 1순위인 칸은 원래 값과 같다.
- 원래 `inference`처럼 제한 해독도 `torch.inference_mode()` 안에서 돈다. 이전 리더는 이 감싸기가 없어 해독 중 기울기 그래프를 만들었다.

## 칸 합쳐짐·누락이 뒤 각으로 번지지 않게 (1060)

S15P31E102-1060, Story S15P31E102-318. 스캔 r8. 전체 쪽 실측과 검증 보강은 후속 S15P31E102-1067에서 한다.

### 원인

- 리더는 각을 `칸 순번 // 한 각의 정간 수`로 나눈다. 가는 가로선을 놓쳐 두 정간이 한 상자가 되거나, 워터마크 때문에 정간 하나가 빠지면 그 뒤 칸이 모두 한 칸씩 당겨진다.
- 이전 `--fill-grid`는 "옆 열에서 그 줄에서 시작하는 상자가 있는가"로만 빈 자리를 찾았다. 아리랑 단소교실 150dpi는 네 열 모두 같은 줄(2각 1·2정간)이 합쳐져 그 아래 줄 위치가 어느 열에도 없었다. 그래서 합쳐진 상자를 그대로 두고 열마다 한 칸씩 밀렸다.

### 동작

- `data/src/scores/jeongganbo_grid.py`의 `fit_columns`가 칸을 격자 자리에 맞춘다. 모델 없이 상자 좌표와 쪽 흑백 그림만 쓴다.
- 자리 높이는 상자 높이의 중앙값이다. 줄 위치는 보통 상자의 위쪽 y와, 1.5배 이상 높은 상자 안을 자리 수로 나눈 위치를 모아 묶는다. 모든 열에서 같은 줄이 합쳐져도 상자 안에서 줄을 얻는다.
- 줄 2개 이상을 덮는 상자는 줄 위치에서 나눠 다시 읽고 `split`을 붙인다. 빈 줄은 먹이 있으면 채우고(이전 동작), 먹이 없으면 같은 열의 위·아래 칸 사이이면서 양쪽 세로선이 이어질 때만 채운다(`filled`). 열 아래쪽 끝의 먹 없는 자리는 채우지 않는다.
- 리더는 맞춘 칸 순서로 `gak`·`jeonggan`을 `cells.json`에 쓴다. 스캔 엔진은 이 번호로 `cellId`와 줄을 만들고, 번호가 없거나 순서가 맞지 않으면 이전처럼 순번으로 나눈다. 나눈 칸에는 `LOW_CONFIDENCE`(`GRID_SPLIT`)를 남긴다. BE·FE는 `detail.reason` 값으로 분기하지 않는다.
- `--grid-boxes`(2/3 크기 재시도)는 단마다 열이 따로라 열의 첫 칸과 끝 칸 사이만 채운다. 한 각의 정간 수는 맞춘 뒤의 열 길이 최빈값이다.
- 칸 오류가 없으면(모든 상자가 줄 하나씩, 빈 줄 없음) 아무것도 바꾸지 않는다.

### 계약 영향

- issue 종류는 바꾸지 않았다. 기존 `LOW_CONFIDENCE`에 `detail.reason` 값 `REST_ONLY`만 더했다. BE `RecognitionResultBuilder`는 kind·detail을 그대로 넘기고 cellId 기준으로 확인 필요 칸 수를 세므로 코드 변경이 없다.
- FE 검수 대화상자는 `GAP_IN_VOICE`만 따로 보이고, 나머지 `LOW_CONFIDENCE`는 공통 문구('확신이 낮음')와 율명 고치기 버튼을 보인다. `REST_ONLY` 칸도 공통 문구로 보인다. 칸 지우기 안내 같은 전용 문구는 FE 후속 판단이다.
- 새 변환만 영향을 받는다. 이미 저장된 결과의 확인 필요 칸 수는 다시 계산하지 않는다.
- Notion API 명세(SHT-08 `/users/me/sheets/{sheetId}/score`, `/v1/recognitions`)는 `issues[].detail`을 인식 서비스 값 그대로로 적고 reason 목록을 두지 않아 고치지 않았다.
