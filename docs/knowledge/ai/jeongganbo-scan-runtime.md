# 정간보 스캔 모델 실행과 독립 롤백 (458)

S15P31E102-458은 Story S15P31E102-318, 활성 스프린트 59321의 기존 정간보 전용 Task다. 사용자 2026-11-12 요청에 따라 오선보 MR !649와 별도 브랜치에서 구현했다. 기준은 develop f44ef9f4이며 오선보 구현 커밋 985663d9를 가져오지 않았다. 원래 요구한 스캔→초안 변환과 독립 MR 범위를 유지했다.

## 동작과 경계

글자 층 없는 PDF와 PNG/JPEG를 기존 DATA 리더로 읽고 같은 JGB→공통 악보 변환기에 연결했다. 검출 격자 열은 율명을 못 읽어도 유지하고 옆 열의 칸 위치로 누락을 보완한다. 인식 원문·신뢰도·원본 쪽/상자를 정간 ID에 연결한다. 지원하지 않는 독립 시김새만 제외해 UNREADABLE로 알리고 읽힌 율명은 남긴다. 애매한 칸을 높은 신뢰도로 읽을 수도 있으므로 결과는 inferred 초안이다.

추론은 Audiveris 잠금을 함께 사용해 동시 1건이다. CPU 배치는 16개, 스레드는 2개다. 텍스트 검사 시간을 포함해 기존 쪽당 60초, CPU 2개, 메모리 2GiB를 유지했다. 원본 모델 폴더는 읽기 전용이고 LayerNorm 이름을 변환한 체크포인트는 요청별 임시 경로에만 만든다. 요청 종료 시 자식 프로세스·쪽 그림·변환 체크포인트를 정리한다.

인쇄 열 하나에 여러 장단이 들어간 경우 음악적 각 경계까지 확정하지 못한다. 검출한 최빈 정간 수를 사용하고 JANGDAN_MISMATCH를 남긴다. 아리랑의 율명 일치는 리듬·장단·시김새 정확도의 증거가 아니다. 실제 촬영 사진의 기울기·원근·다른 글꼴과 전곡 음표별 정확도는 미검증이다. 동동 PNG/JPEG의 모델 결과도 완전히 같지는 않았다.

- 가중치: [v1.0.0 공개 릴리스](https://github.com/MALerLab/jeongganbo-omr/releases/tag/v1.0.0)의 checkpoints.tar.gz, 67,802,998바이트, SHA-256 f0e0d44a7ad54b7389b02f871e825d3ae439c5dda1a8f189916c727795a251bb.
- 모델 저장소 README는 프로젝트를 MIT라고 명시하지만 별도 LICENSE 파일과 가중치 개별 조건은 제공하지 않는다. 학습 데이터셋의 이용 조건과도 구분해야 한다. 확인된 문구를 배포용 법률 승인으로 해석하지 않으며 코드·원본·모델의 조건은 각각 검토한다. 원본과 모델은 Git에 넣지 않았다.
- torch 2.15.0+cpu, torchvision 0.29.2+cpu, x-transformers 1.30.20 등은 스캔 전용 requirements에 URL·해시로 고정했다. 채점용 uv.lock은 바꾸지 않았다. Python 3.12/Linux x86_64용이며 PyTorch 공식 CPU 휠을 직접 지정해 보조 인덱스 간 버전 혼동을 피한다.
- upstream의 패키지 초기화가 학습 도구까지 import하므로 이미지 빌드에서 __init__.py 두 개의 공개 export만 추론에 필요한 것으로 줄였다. 인식 모델과 리더 계산 코드는 그대로다. gamma→weight, 0인 beta 제거는 기존 DATA 리더의 호환 변환을 재사용한다.

기본 omr.Dockerfile은 마지막 scanner 단계까지 빌드한다. 기본 runtime을 독립 단계로 유지하고 확장만 뒤에 붙여 458을 되돌려도 오선보 변경을 보존한다. 기존 검증 이미지 70b2e1dbee82…를 OMR_SCANNER_BASE로 지정한 실제 확장 이미지 빌드를 통과했다. 기본 인자 runtime과 최종 scanner 대상은 docker build --call=outline으로 확인했다. Ubuntu/Audiveris 기본 단계 전체의 신규 설치 빌드는 실행하지 않았다.

## 로컬 검증

기존 OMR 런타임을 확장한 실제 이미지의 기본 CMD로 실행했다. 소스 바인드 마운트 없이 비관리자 10001, 읽기 전용 파일시스템과 /tmp tmpfs, CPU 2개·메모리 2GiB 조건이다. 로컬 MySQL 8.4.13과 실제 Spring HTTP·worker·OMR HTTP를 사용했다. 관측 memory.peak는 1,647,558,656바이트(약 1.53GiB)였으며 oom/oom_kill은 0이었다. 모델 설치 중 캐시는 이 수치에 포함하지 않았다.

세 곡 모두 초안 저장 HTTP 200, 재조회 동등성, 원본 음고 snapshot 보존, 임시 업로드 원본 삭제를 검증했다. 프론트 호스트 테스트는 실제 초안의 무편집 왕복, 음 하나 변경, 나머지 모든 event와 시간/provenance 보존, JSON 재열기를 확인했다. 입력은 국립국악원 대금 정악보 2021 수정본의 로컬 발췌이며 원본·가공본을 저장소에 배포하지 않는다.

동동 PNG·JPEG도 DONE이었다. 아리랑의 기존 참조 PDF는 Downloads 단소.zip에서 동일 SHA-256 289041922719a180d4a0db63fc1576ba74f48ab4a7c044865914b1e1c79e979a로 재확보했다. 150dpi 그림을 입력해 48칸을 보존했고, [114 수기 기준](../data/jeongganbo-omr.md)의 정간별 율명 순서 48/48이 일치했다. 기존 39개 깨끗한 칸만의 대조와 평가 범위가 다르므로 일반 정확도 상승률로 보고하지 않는다. 빈칸/쉼표 종류·시김새·정확한 시점은 이 지표에서 제외했다.

두 배 크기 아리랑 그림은 첫 해상도에서 격자를 못 찾고 1/2 크기 재시도로 DONE이었다. 응답 상자 너비 190/192px가 원본 크기로 복구됨을 확인했다. 빈 그림은 FAILED/NO_GRID_FOUND였다. 관련 단위·회귀 176개를 통과했다. 전체 AI 채점/오디오 테스트는 이번 스캔 검사 범위가 아니다.

원본·실제 응답·모델·명령·JUnit·로그는 Git 제외 경로 data/processed/score-test-assets-801/runtime/scan458에 보존한다. 생성 이미지·체크포인트가 들어간 임시 실험 컨테이너는 검사 후 제거한다. 공식 독립 리뷰와 운영 배포는 수행하지 않았다.

## 롤백

DB·공유 응답 스키마 변경이 없다. 458 MR의 단일 구현 커밋을 revert하면 스캔 분기·전용 의존성·모델 빌드 단계가 함께 제거되고 기존 텍스트/오선보 경로가 남는다. 806과의 결합·개별 revert 검사는 별도 임시 worktree에서 수행하고 결과를 MR에 기록한다. 저장된 사용자 초안은 일반 공통 악보라 코드 롤백 뒤에도 보존된다.
