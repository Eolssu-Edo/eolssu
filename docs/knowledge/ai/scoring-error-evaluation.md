# 단소 채점 오류 검출 평가: 실행과 결과 해석

- 작업: [S15P31E102-242](https://ssafy.atlassian.net/browse/S15P31E102-242)
- 대상: 채점 담당자. 같은 녹음에서 허용값이나 채점 코드를 바꾼 결과를 비교한다.
- 기준: `pyin-2`, 커밋 `168a5b6`의 [기준 결과](../../../ai/evaluation/baselines/arirang-synthetic-pyin-2.json). 실제 사람 연주의 정확도와 확정 허용값을 뜻하지 않는다.
- 코드: [평가 실행](../../../ai/evaluation/error_detection.py), [합성 묶음](../../../ai/evaluation/synthetic_set.py), [정답 기록 검사](../../../ai/evaluation/labels.py).

## 실행

Python과 ffmpeg가 필요하다. 아래 명령은 저장소 루트의 PowerShell에서 실행한다. 의존성은 `ai/uv.lock`을 사용한다. `eval` 그룹의 torchcrepe는 이 pYIN 평가에 필요하지 않다.

```powershell
Set-Location ai
uv sync --locked
uv run python -m evaluation.synthetic_set
$labels = @(Get-ChildItem ../data/processed/recordings/danso/arirang-synthetic/*.label.json | ForEach-Object { $_.FullName })
uv run python -m evaluation.error_detection @labels --out ../data/processed/recordings/danso/arirang-synthetic/result.json
```

생성기는 정상 1개와 오류 종류별 3개, 총 13개 WAV와 정답 기록을 만든다. 오류 녹음마다 서로 이웃하지 않는 5개 음에 오류를 넣는다. 아리랑 공통 악보 샘플 61음, 점4분음표 96 BPM, 음 사이 40ms 끊김, 난수 시드 0을 사용한다. 실제 기기 입력 m4a 검증은 별도다.

결과 전후 비교는 같은 정답 기록과 녹음으로 실행한다.

```powershell
uv run python -m evaluation.error_detection @labels --compare ../data/processed/recordings/danso/arirang-synthetic/result.json --vary scoring --out ../data/processed/recordings/danso/arirang-synthetic/after.json
```

`--vary scoring`은 채점·평가 코드나 설정을 바꿨다는 선언이다. 실행 환경을 바꿨으면 `--vary environment`, 둘 다 바꿨으면 `--vary scoring environment`를 쓴다. 선언하지 않은 묶음이 달라지면 비교를 거절한다. 데이터·합성 조건·실제 녹음 조건은 다른 녹음 비교가 되므로 변경 선언 자체를 허용하지 않는다. 저장된 기준 결과와 다른 환경이면 그 차이를 먼저 확인한다.

## 정답 기록과 통제하는 조건

[기록 형식](../../../data/src/recordings/recording_label.schema.json)은 녹음·악보 SHA-256, 연습 구간, BPM과 단위, 의도한 오류의 음 번호·종류·크기, 녹음 조건을 담는다. 번호는 쉼을 빼고 곡 처음부터 0으로 센 NOTE 순번이다. 실제 녹음에는 연주자 익명 ID, 숙련도, 악기, 기기·앱, 장소·잡음 등 조건도 남긴다. 형식 검사는 사람이 의도한 오류를 실제로 냈는지 보증하지 않는다.

| 묶음 | 남기는 정보 | 비교할 때의 의미 |
| --- | --- | --- |
| data | 정답 기록 해시와 묶음 해시 | 같은 입력인지 확인 |
| scoring | 모델 버전, 코드 내용 해시, 허용값, pYIN 설정, 프레임 간격, 기준음 | 채점 조건의 차이 확인 |
| environment | Python·패키지·ffmpeg 버전, 잠금 파일 해시, 운영체제 | 실행 환경의 차이 확인 |
| synthetic | 생성 방법, 시드, 잡음과 음 사이 끊김 | 합성 조건 고정 |
| performed | 실제 연주·녹음 조건 | 사람·악기·기기 차이 확인 |

코드 해시는 줄바꿈 차이를 제외한 Python 파일 경로와 내용을 사용한다. 문서만 바뀐 커밋은 채점 조건 변경으로 보지 않는다. 결과 JSON의 커밋 번호는 출처 정보로 따로 남는다.

## 지표 읽기

| 이름 | 계산 | 뜻 |
| --- | --- | --- |
| TP | 의도한 오류의 종류까지 맞힌 음 수 | 옥타브 오류는 PITCH와 옥타브 의심 표시가 모두 필요 |
| WRONG_KIND | 오류로 판정했지만 종류가 다른 음 수 | 검출 성공과 별도로 보고 |
| FN | 의도한 오류를 CORRECT로 본 음 수 | 오류를 놓침 |
| FP·TN | 오류를 넣지 않은 음의 잘못된 오류 판정·CORRECT 수 | 정상 녹음뿐 아니라 오류 녹음의 정상 음도 포함 |
| 검출률·오탐률 | TP / (TP + WRONG_KIND + FN), FP / (FP + TN) | 오류를 찾는 정도와 정상 음을 잘못 지적하는 정도 |

정상 점수는 오류를 넣지 않은 녹음의 총점 평균이다. 도구는 음정 30·40·50·60센트, 시작 0.125·0.2박, 길이 20·25%의 16개 조합을 비교한다. `★`는 오탐률 5% 이하 중 검출률 최대, `◆`는 검출률에서 오탐률을 뺀 값이 최대인 조합이다. 동률이면 코드상 먼저 나온 조합을 표시한다. 이 표시는 비교 후보이며 서비스 기준의 자동 확정이 아니다. 길이 허용값은 점수에 영향을 주지만 별도 길이 오류 판정은 없다.

### 비율의 불확실성: 윌슨 95% 구간

성공 수 x, 시행 수 n, p̂ = x/n, z = 1.96일 때 다음을 계산한다.

```text
중심 = (p̂ + z²/(2n)) / (1 + z²/n)
반폭 = z/(1 + z²/n) × √(p̂(1−p̂)/n + z²/(4n²))
구간 = 중심 ± 반폭
```

9/10의 구간은 약 59.6~98.2%, 10/10은 약 72.2~100%다. 10개를 모두 잡았어도 실제 검출률을 100%라고 확정할 수 없다는 뜻이다. 종류별 오류 15개는 작은 시험 묶음의 시작점이다. 15/15를 잡아도 하한은 약 79.6%다. 같은 녹음 안 음들은 서로 영향을 받으므로 독립 시행 가정도 약하다. 이 구간을 사람 전체에 대한 신뢰구간으로 해석하지 않는다.

### 같은 음의 전후 비교: 맥니마 검정

정답과 비교해 전에는 맞았고 후에는 틀린 음 수를 b, 반대는 c로 센다. 양쪽 모두 맞거나 모두 틀린 음은 이 검정에 넣지 않는다.

```text
b+c < 25: X ~ Binomial(b+c, 0.5), p = min(1, 2 × P(X ≤ min(b,c)))
b+c ≥ 25: χ² = (b−c)²/(b+c), 자유도 1의 상측 확률
b+c = 0: p = 1
```

b=0, c=6이면 p=0.03125다. 어느 방향으로 얼마나 바뀌었는지 b·c와 함께 읽는다. 작은 p가 개선 폭이나 실제 연주 품질을 보증하지는 않는다. 도구는 16개 조합의 p를 각각 내며 여러 번 검정한 데 대한 보정은 하지 않는다. 같은 녹음의 음 사이 의존성도 남는다. 탐색 결과로 사용하고 별도 사람·녹음 묶음에서 다시 검증한다.

## 아리랑 합성 기준 결과

기준 결과 JSON에 기록된 환경은 Windows AMD64, Python 3.12.10, NumPy 2.5.4, librosa 1.0.0, jsonschema 4.26.0, ffmpeg 9.0.2다. 생성 시각과 명령, 입력 해시·코드 해시는 JSON에 보존돼 있다. 아래 값은 저장된 결과를 읽은 값이며 이 문서 작업에서 음원을 재생성해 다시 측정한 값은 아니다.

기본 허용값은 음정 50센트, 시작 0.125박, 길이 25%다. 아리랑 96 BPM에서 시작 허용값은 약 78ms다.

| 지표 | 값 | 해석 |
| --- | --- | --- |
| 정상 녹음 | 1개, 100점 | 이 합성 정상 입력에 한정 |
| 종류까지 맞힌 오류 | 49/60, 81.7%, 윌슨 구간 70.1~89.4% | 종류 틀림 3개, 놓침 8개 |
| 정상 음의 오탐 | 10/733, 1.36%, 구간 0.74~2.49% | 오류 녹음의 정상 음도 포함 |
| 종류별 검출 | 음 바꿈 15/15, 옥타브 6/15, 박자 14/15, 누락 14/15 | 옥타브는 종류 틀림 2개와 놓침 7개 |

단음의 조율 결과는 [김 세기·취법별 측정](danso-tuning-variation.md)을 따른다. 한 연주자·악기의 관찰이며 보정 상한을 확정하는 근거로 쓰지 않는다.

## 적용과 남은 확인

- 평가 도구는 채점 오류를 드러내고 비교하는 데 쓴다. 합성 결과가 모든 오류의 검출 성공을 뜻하지 않는다. 짧은 옥타브 오류 수정은 별도 작업이다.
- 아리랑 한 곡, 합성 정상 1개와 오류 60개이므로 다른 곡·실제 입문자에게 일반화하지 않는다. 사람 녹음의 정확도와 허용값은 별도 녹음 검증에서 정한다.
- 실제 녹음은 사람별로 조정용과 최종 평가용을 나눠 같은 사람의 녹음이 양쪽에 섞이지 않게 한다. 같은 데이터에서 허용값을 고르고 그 결과만 보고하면 성능을 과하게 평가할 수 있다.
- 재현 검사는 동일 명령의 음별 판정과 지표를 비교한다. 실행 시각·명령·출처 커밋은 달라질 수 있어 결과 파일 전체 바이트가 같아야 하는 것은 아니다.
