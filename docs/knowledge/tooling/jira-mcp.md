# Jira MCP 사용 안내

- 작업: `S15P31E102-47`
- Jira 작업 규칙의 기준: [AGENTS.md](../../../AGENTS.md)의 `작업 시작과 Jira 연결`, `Jira·Git·MR`.

## 처음 연결하기

1. 사용하는 AI 도구에서 Jira를 지원하는 Atlassian MCP를 연결하고 본인 Atlassian 계정으로 인증한다. 연결은 팀원별로 필요하다.
2. `https://ssafy.atlassian.net` 사이트와 `S15P31E102` 프로젝트를 사용할 수 있는지 AI에게 조회를 요청한다. 계정에 해당 Jira 작업 권한이 있어야 한다.
3. 연결이 확인되면 저장소를 열어둔 AI에게 업무를 요청한다.

## 업무 흐름: 백로그 → 해야 할 일 → 진행 중

| 단계 | 의미 | 요청 예시 | 처리 |
| --- | --- | --- | --- |
| 백로그 | 나중에 할 업무를 모아둠 | “일단 등록만 해줘.” | 스프린트에 배정하지 않고 보관 |
| 해야 할 일 | 이번 스프린트에서 할 업무로 정했지만 아직 미착수 | “이번 스프린트에 할 일로 넣어둬.” | 활성 스프린트 배정, `해야 할 일` 상태 |
| 진행 중 | 실제 작업에 착수 | “시작하자 / 구현해줘 / 조사해줘.” | 활성 스프린트 배정 확인, `진행 중` 전환 후 작업 |

이 문서의 세 단계는 업무 처리 흐름이다. Jira 내부에서는 스프린트 배정과 상태 변경이 별도이므로, 백로그 단계의 새 Task도 상태 필드에는 `해야 할 일`로 저장된다.

신규 Task를 등록만 해달라는 요청은 백로그 단계에서 끝낸다. “이번 스프린트에 넣어둬”는 해야 할 일까지, “바로 시작하자”는 진행 중까지 처리한다. 처음부터 시작을 요청하면 백로그에 등록한 채 끝내지 않는다.

기존 Task가 이미 목표 단계에 있으면 유지한다. 단순 등록 요청으로 재사용한 기존 Task의 스프린트·상태를 변경하지 않는다. 스프린트 배정 요청만으로 진행 중인 업무를 해야 할 일로 되돌리지 않는다. 작업을 미루거나 이전 단계로 돌리라는 명시적 요청은 그 범위에 맞게 처리한다. 완료된 Task의 재개와 다른 담당자 업무에 편입하는 경우는 [AGENTS.md](../../../AGENTS.md)의 사전 확인 규칙을 따른다.

## MCP 처리와 결과 확인

1. 업무 목적·범위·담당자와 기존 Task·Story를 확인한다. 필요할 때만 Task를 생성하고 기존 Story에 `다음과 관련됨`으로 연결한다. 포인트는 입력하지 않는다.
2. 요청한 업무 단계를 정하고 현재 스프린트·상태를 확인한다. 이미 목표와 같은 변경은 생략한다.
3. 해야 할 일·진행 중 단계로 처리할 때는 해당 프로젝트·보드의 실제 활성 스프린트를 조회해 배정한다. 대상이 없거나 여러 개여서 특정할 수 없으면 필요한 사항만 확인한다. 스프린트를 임의로 만들거나 시작하지 않는다.
4. 상태 전환이 필요하면 `listJiraIssueTransitions`에서 요청한 도착 상태를 찾아 그 전환 ID로 `transitionJiraIssue`를 실행한다.
5. 변경 후 Task를 재조회해서 Story 연결, 스프린트, 상태를 확인한다. 시작 요청은 활성 스프린트 배정과 진행 중 전환을 모두 확인해야 처리 완료로 보고한다.

결과에는 실제 Key·Story 연결 여부·업무 단계·스프린트를 알린다. 스프린트 미배정인데 상태만 진행 중이면 “상태는 진행 중, 활성 스프린트 배정은 미완료”라고 알려 남은 일을 드러낸다.

MCP가 연결되지 않았거나 인증·권한 오류가 있으면 Jira 쓰기를 중단하고 필요한 조치를 알린다. 생성 응답이 유실되거나 연결·배정·전환 중 일부만 실패하면 기존 이슈·링크·스프린트·상태를 재조회한다. 기존 Key와 성공한 변경을 보존하고 실패 단계만 이어서 처리한다.
