# 웹 마이페이지 최근 연주 카드가 처음 표시될 때의 지연

[Jira S15P31E102-863](https://ssafy.atlassian.net/browse/S15P31E102-863) · [기존 운영 계정 측정](../../plans/S15P31E102-823.md#운영-웹-구간별-재측정) · [MR !669](https://lab.ssafy.com/s15-final/S15P31E102/-/merge_requests/669)

## 관측한 원인

- 운영에서 기록한 432ms는 주소가 마이페이지로 바뀌고 REC-05 응답이 이미 준비된 뒤, 점수의 접근성 노드가 브라우저에 처음 나타날 때까지의 중앙값이다. 2026-11-13 후속 조사에서 운영 릴리스가 측정 당시와 같은 `75ca986e7a752edb35080dca5f10595a111a66b4`임을 확인했다.
- 최초 진입의 큰 비용은 화면을 처음 배치하면서 Skia가 글꼴 바이트로 타입페이스를 만들고 문단을 배치하는 작업이다. Compose의 레이아웃 호출 아래 `SkiaFontLoader.loadBlocking → FontCache.load → makeFromBytes` 스택을 확인했다. 구간 내 CPU 프로파일 3회에서 해당 스택 표본 시간은 112.5~162.1ms였다. 같은 탭에서 재진입할 때는 3회 모두 이 스택이 잡히지 않았다. 프로파일의 시간은 호출 위치와 비용을 가리키는 근거이며 아래 실측 시간과 합산하지 않는다.
- 화면 픽셀과 접근성 DOM은 다른 시점에 갱신된다. Compose 1.12.1의 `ComposeWebSemanticsListener`는 변경이 잠잠해진 뒤 100ms에 웹 접근성 트리를 동기화한다. 실제 첫 진입 3회의 캡처에서 제목과 점수 단위가 보인 뒤 접근성 점수 관측까지 97.3~117.4ms 더 걸렸다. 이 실험의 차이를 기존 운영 432ms에 그대로 적용할 수 없다. [Compose Web 접근성 소스](https://repo.maven.apache.org/maven2/org/jetbrains/compose/ui/ui-wasm-js/1.12.1/ui-wasm-js-1.12.1-sources.jar)
- [마이페이지 진입](../../../frontend/shared/src/commonMain/kotlin/com/ssafy/eolssu/feature/profile/MyPageRoute.kt)은 캐시된 최근 연주 값을 초기 상태로 읽고, 프로필과 학습 진도는 별도 효과에서 갱신한다. 로컬 회원 정보 응답에 1,200ms를 추가한 3회에도 카드가 그 응답보다 먼저 그려졌다. 폰트 HTTP 요청도 클릭 이후 관측되지 않았다. [화면 스크롤 구성](../../../frontend/shared/src/commonMain/kotlin/com/ssafy/eolssu/feature/profile/component/ProfileFrame.kt)은 프로필부터 하단 링크까지 같은 Column에 두므로 첫 레이아웃에는 카드 외 화면 요소의 작업도 포함된다.

## 렌더링 시점 분해

운영 보관본의 정적 파일을 그대로 제공하고, 회원·악기·학습 진도·최근 연주는 고정 응답을 준 격리 루프백 서버에서 실행했다. Windows Chrome 157.0.8103.51, 1280×900, DPR 1, 헤드리스 모드였다. 운영 계정과 네트워크는 기존 운영 432ms 측정에만 사용했다. 아래는 마이페이지 버튼의 `pointerdown`부터 잰 중앙값(최솟값~최댓값)이다.

| 관측 지점 | 탭에서 첫 진입 3회(ms) | 같은 탭에서 재진입 3회(ms) |
| --- | ---: | ---: |
| 최근 연주 숫자가 보이는 캡처 | 164.2 (161.0~216.1) | 30.6 (28.3~33.0) |
| 점수와 ‘점’이 모두 보이는 캡처 | 251.1 (235.6~294.5) | 30.6 (28.3~33.0) |
| 점수의 접근성 DOM 노드 관측 | 364.3 (352.9~391.7) | 142.6 (141.1~144.1) |

- 첫 캡처 시점은 프레임 표본의 상한이다. 첫 진입 3회에서 완성 점수 직전 캡처와의 간격은 15.3~16.9ms였다. 캡처의 점수 영역을 최종 화면과 대조하고, 제목·숫자·단위가 순차 표시되는 표본을 육안으로도 확인했다.
- 첫 진입에서 완성 점수 이전 메인 스레드의 가장 긴 작업은 142.0~188.1ms였다. 같은 구간에 V8의 Wasm 지연 컴파일이 617~618회 있었으며 합계 16.2~17.7ms였다. 재진입 표본에서는 긴 작업과 지연 컴파일이 관측되지 않았다. 별도 비추적 6쌍에서도 접근성 점수 관측은 첫 진입 580.0ms, 재진입 162.7ms였다. 실험 간 절대시간 차이가 있어 비교는 각각의 실행 안에서 했다. [V8의 Wasm 컴파일](https://v8.dev/docs/wasm-compilation-pipeline)
- 심볼은 Jenkins 보관본에서 복원했다. 배포 Wasm의 SHA-256은 `60b5e69bd18e7ea499e90047f24331caa32b19269abf1fe1e73dc5f6244d94f9`로 Jenkins 최적화 결과와 일치했다. 같은 Binaryen 132와 Kotlin Gradle 플러그인의 기본 옵션, 저장소의 추가 최적화 옵션으로 디버그 이름을 생성했다. 심볼을 붙인 바이너리와 배포 바이너리의 함수 섹션 및 함수 본문을 대조했다. 전체 28,694개 중 본문이 일치한 28,634개만 이름을 연결했고, 위에 인용한 폰트와 레이아웃 함수도 그 집합에 속했다. Chrome은 해시가 일치하는 운영 보관본으로 실행했다.

## 글꼴 비용을 분리한 실험

[화면 테마](../../../frontend/shared/src/commonMain/kotlin/com/ssafy/eolssu/core/theme/EolssuTypography.kt)는 본문과 제목에 IBM Plex Sans KR의 세 굵기를 쓴다. 원본 세 파일 합계 8,527,428바이트를 격리 서버에서만 2,398,828바이트의 시험용 파일로 바꿨다. ASCII·한글 자모·KS X 1001 한글과 시험에 필요한 기호를 남겼고, 유지 글자의 폭을 검사했다. 첫 진입 순서를 원본→시험본과 시험본→원본으로 번갈아 6쌍 실행했다.

| 클릭 이후 관측 | 원본 중앙값(ms) | 시험본 중앙값(ms) |
| --- | ---: | ---: |
| 점수와 단위가 보이는 첫 캡처 | 577.0 | 428.3 |
| 점수 이전 메인 스레드의 가장 긴 작업 | 332.9 | 178.5 |

- 6쌍 모두 완성 점수가 빨랐다. 같은 쌍의 차이는 중앙값 151.7ms, 범위 85.6~221.6ms였다. 각 쌍의 최종 1280×900 캡처는 전체 픽셀이 일치했고, REC-05는 모든 표본에서 클릭 전에 HTTP 200으로 완료됐으며 클릭 후에는 0건이었다. 글꼴 데이터 크기가 첫 화면의 표시 시간을 바꾼다는 근거다.
- 시험본은 고정 화면의 글자를 기준으로 만든 진단용이다. 사용자 닉네임·곡 제목에서 사용할 수 있는 전체 한글의 가독성, 다른 기기와 브라우저, 운영 환경의 실제 픽셀 시점은 미검증이다. 제품 코드는 조사 대상으로만 사용했다. [한글 글꼴 제약](web-korean-fonts.md)

## 재현 절차

1. 운영 보관본 `75ca986e`을 MIME이 맞는 루프백 정적 서버에서 제공한다. 외부 요청을 차단하고 회원·악기·학습 진도 API를 고정한다. REC-05에 제목 ‘아리랑’, 점수 92, 주간 횟수 4가 있는 기록을 넣는다. 브라우저 초기화 시 루프백에만 `first_run_completed=true`, `auth.member_id=669`, `learn_recent_member_3_669=Danso:1,2`를 설정한다.
2. 새 브라우저 컨텍스트에서 `#home`을 열고 아래로 스크롤한다. 마이페이지 버튼이 보인 뒤 750ms를 두고 클릭한다. Chrome DevTools Protocol로 네트워크 완료, 사용자 타이밍 마크, 스크린샷 트레이스와 접근성 점수 노드를 모은다. 캐시 재사용과 고정 기록 표시를 확인한다. 같은 탭에서 홈으로 돌아와 30초 캐시 만료 전에 다시 진입한다.
3. 첫 화면 전용 작업은 별도 CPU 샘플링에서 확인한다. 해당 시점의 이벤트와 검증된 Wasm 심볼을 대조한다. 글꼴 비교는 fonttools 4.62.1로 위 글자 범위만 남긴 파일을 루프백에서 제공하고, 원본과 실행 순서를 번갈아 잰다. 같은 점수·화면과 요청 수를 확인한다.
