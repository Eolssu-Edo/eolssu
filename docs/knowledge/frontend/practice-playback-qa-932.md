## 빠르기 변화 악보의 재생 전 길이 후속 수정

공식379(`6ebd0b8f`)의 내악보50 `QA931-BlueVal-1729`는118마디472Q, 기준160BPM이며26→30각과58→62각에서 각각16Q 동안80→160으로 가속한다. 편집·저장 표시와 수행 시간표는3:02인데, 연습 화면은 생성 전·생성 중·다운로드 후·캐시 재진입에서2:57로 표시하다 첫 재생에3:02로 바뀌었다. 원본 검증 채팅의 `app-flow-20261115/126`, `131`~`132`, `136`~`140`, `147`~`148`이 근거다.

고정 BPM 계산은177초이고 선형 BPM의 역수를 적분하면 `440×60/160 + 2×16×60×ln(2)/80 = 181.635532초`다. 실제 검증된 수행 시간표는181.635521초이며 샘플 반올림 차이만 있다. 전체 시간 문구만 바꾸면 첫50% 탐색은 원래 기보 중간2832tick에서92.683359초로 재생되어 수행 시간의50%인90.817760초와 어긋난다.

생성 전에는 편집기와 같은 적분 함수를 공유해 모범 예상 길이를 사용한다. 로컬 음원이 있으면 기존 계정·악보 버전·해시 검증 경로에서 수행 시간표를 읽어 재생 전에 연결한다. 파일을 디코딩하거나 소리를 내지 않고 첫 탐색도 수행 시간에 맞춘다. 화면 재진입, 느린 속도, 반복 구간의 두 번째 occurrence, 장단에서 옮긴 새 기보 위치를 첫 재생까지 유지하도록 회귀로 확인한다. ±5초는 표시 시간 기준으로 원본 음원 위치에 한 번 환산한다.

`Song.durationMs`와 장단·녹음·평가 시계는 유지한다. 생성 전 탐색 제한과 일반 악보 칸 선택 후 처음부터 재생하는 동작도 유지한다. 반복·길이 기호 또는 잘못된 계획은 예상 길이를 만들지 않으며, 검증된 수행 시간표가 없는 기존 음원은 기존 기보 시간으로 돌아간다. 새 서버 API나 wire 형식은 추가하지 않는다.

자동 회귀는 생성 전·생성 대기·다운로드 중 예상 길이, 다운로드 후/캐시 진입 첫 길이와 탐색, 화면 재진입, 빠르기 변경·상대 탐색, 모드 전환을 검증한다. 새 APK의 실제 폰 확인은 원본 검증 채팅에 인계하며, 앞 절의15e91837 APK 실기기 통과를 이 후속 코드의 통과로 취급하지 않는다.

## 한계

S10 프로필 에뮬레이터는 저장 공간 부족으로 부팅되지 않았으며 결과로 사용하지 않았다. 사용자 후속 지시에 따라 실제 폰을 순차 인계받았다. iOS·Web 실행, 마이크/평가·기록 상세 자체의 기능, 음향 출력 품질·타격 정밀도는 이번 검증 범위에서 확인하지 않았다. 구간의 직접 재선택·구간 로드 실패 복구, 내악보 자체가0개인 계정, 다양한 악기/곡 전체 조합은 실행하지 않았다. 이 보고서의 통과 범위를 앱 전체·모든 플랫폼의 통과로 확대하지 않는다.
