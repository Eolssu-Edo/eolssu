# 서버 악보 편집 연결 시 보존할 정보

- 작업: S15P31E102-532. 기준: SHT-08·11·04와 `CommonScoreData` v1.
- 근거: [내 악보 계약](../../specs/user-sheets.md), `backend/.../sheet/api/UserSheetController.kt`, `frontend/.../data/song/CommonScoreData.kt`.

## 표기와 시간

서버 각의 정간 수는 가변이다. 장단 패턴의 길이로 악보를 다시 나누면 위치 ID가 바뀐다. 각 길이와 원래 정간 ID를 편집 상태에 보존하고, 각 삽입·삭제 때는 표시 위치와 이벤트 참조를 함께 바꾼다.

정간 안의 `row/col`은 단순 음 목록과 다르다. 수정하지 않은 칸은 원래 분할을 그대로 쓰고, 수정한 칸만 새 배치로 만든다. 가사와 기존 이벤트의 부가 표기도 명시적 변경이 없으면 보존한다.

빈 문자열 표기는 기존 이벤트의 이음일 수 있다. 연결된 원본 빈 표기와 새로 입력 중인 빈 자리를 구별한다. 완전히 빈 정간 수와 확정 저장 전에 채울 미입력 자리 수는 같은 지표가 아니다.

3분할을 새로 넣는데 기존 정간 tick 수가 3으로 나누어지지 않으면, 표시를 반올림하지 않고 공통 배수로 tick 단위를 늘린다. `ticksPerBeat`도 같은 비율로 늘려 기존 연주 시간을 보존한다. 원본을 수정하지 않았으면 시간 단위도 그대로 돌려준다.

## 저장 순서와 계정

조회 문서의 `scoreVersion`은 문자열, 초안의 `draftRevision`은 정수다. 초안과 확정 저장을 하나의 순서로 직렬 처리하고 응답으로 확인된 값만 갱신한다. 409가 오면 최신 값을 추측해 덮어쓰지 않고 현재 편집을 보존한다.

입력 뒤 자동 저장 대기 중 바로 닫으면 ViewModel 취소로 변경이 사라질 수 있다. 닫기·뒤로 가기는 마지막 초안을 먼저 저장하고 성공한 뒤 이동한다. 실패하면 계속 편집할지 미저장 변경을 버릴지 사용자에게 묻는다. 로그인 세대가 바뀌면 이전 작업·문서·음원 상태를 폐기한다.

## 적용 범위와 검증 한계

서버 악보의 오선보 확장은 사용자 결정으로 후속 분리했다. 이번 편집 연결은 정간보만 제공한다. 확인 필요 이슈의 원본 이미지 검수·해결 UI는 업로드 연결 범위에 남겨두며 임의로 `resolvedIssueIds`를 채우지 않는다.

`SheetDocumentRepositoryTest`, `SheetDocumentEditingTest`, `SheetDocumentViewModelTest`로 HTTP 응답·원본 보존·초안 순번·충돌·계정 전환·종료 저장을 확인한다. MockEngine/가짜 저장소 검증을 실제 서버 회원 자료의 저장 성공으로 보고하지 않는다.
