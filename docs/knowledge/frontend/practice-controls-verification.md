# 연습 조작과 설정 화면 검증

- Task: S15P31E102-518
- 기준: origin/develop 69541563에서 시작한 작업 브랜치, [스펙](../../specs/practice-controls.md), [검증 기록](../../plans/S15P31E102-518.md).
- 환경: Windows, Android API 37 Medium Phone 에뮬레이터, Kotlin/Compose 버전은 저장소 버전 카탈로그 기준.

## 확인한 동작

모드 선택과 재생은 분리해야 한다. 선택 시 진행 이벤트와 이벤트 내부 비율을 보존하고, 모범 음원 재생 시 원본 tick을 음원의 앞 여백·연주 시간에 맞춰 변환한다. 장단 연습과 평가는 같은 악보 시계를 사용한다.

장단 설정 변경은 녹음 속도 변경과 분리한다. 평가 중에는 속도만 고정하고, 장단은 녹음 시계에 맞춰 켜고 끈다. 공통 테스트의 녹음·샘플 플레이어 대역으로 녹음 진행 유지와 소리 시작/정지를 확인했다. 실제 Android 오디오 포커스·마이크 품질을 증명한 것은 아니다.

에뮬레이터에서 기존 시트의 배경 누르기 후 닫힘을 확인하지 못했다. 연습 화면의 모달 배경에 전체 닫기 동작을 명시하고, 하위 뒤로가기와 분리한 뒤 닫힘을 관찰했다. 라이브러리 자체 결함으로 단정하지 않는다. 다른 화면의 공통 시트는 그대로 둔다.

## 남은 수동 확인

1. 실제 기기에서 평가 시작 → 설정 → 장단 → 소리 켬/끔을 반복하면서 녹음·진행이 유지되는지 확인한다.
2. 일반 연습 진입 경로에서 모범/장단 재생의 악보 이동, 운지 악보의 한 각 표시를 확인한다.
3. 태블릿·iOS와 글꼴 확대에서 모달 배경 닫기·한 각 표시·필요 시 스크롤 접근을 확인한다.

기록된 자동 검사: Android 907개, Wasm 885개 통과, Android 디버그 APK 빌드 성공. 실기기 검증은 미완료다.

## 두 음 미리보기 복원

S15P31E102-500의 기존 `nextFingerCells`를 한 각 배치에 다시 연결했다. 현재 표시 각의 마지막 이벤트 뒤 실제 발음 두 개를 별도 운지·율명·가사 행으로 표시한다. 에뮬레이터의 구아리랑 준비 화면에서 두 행이 나타나는 것을 확인했고, 관련 기존 테스트 14개와 Android APK 빌드가 통과했다. 재생 중 갱신과 다른 화면 크기는 이 후속 확인에 포함하지 않았다.

## 로딩에 따른 배치 변화 방지

동적 안내 문구만 고정해도 악보 준비 안내나 운지 이동 줄이 사라지면 남은 높이를 사용하는 악보가 커질 수 있다. 플레이어 안내 칸은 항상 56dp를 확보하고, 일반 악보 준비 안내는 투명하게 숨기되 자리를 유지한다. 운지 이동 줄과 다음 두 음 표의 높이도 유지한다. 움짤은 원본 30프레임·2초 간격을 PNG atlas와 공통 Canvas로 재생하며 로딩이 끝나면 애니메이션 코루틴도 종료된다.

Android 911개·Wasm 889개 검사와 APK 빌드가 통과했다. 에뮬레이터의 일반 악보에서 재생 전후 및 실제 움짤 로딩 표시 유무에 따라 플레이어와 하단 버튼 위치가 유지되는 것을 확인했다. 운지 마지막 각·확대 글꼴·태블릿·iOS의 화면 안정성은 추가 수동 확인 대상이다.

## 타임라인 이동과 종료 후 재생

표시용 트랙을 Slider로 연결하고 드래그 중 임시 위치와 실제 음원 이동을 분리했다. 손을 놓을 때 한 번만 이동해 매 입력마다 음원을 다시 불러오는 것을 피한다. 음원 위치는 앞 여백과 실제 연주 길이를 기준으로 계산하고, 재생 중/일시정지 상태를 보존한다. 종료된 모범 연주에서 현재 tick을 다시 넘기면 곡 끝이 재생 시작점이 되는 문제가 있어, 끝에서 재생할 때는 기존 재시작 경로로 들어간다.

후속 자동 검사 Android 916개·Wasm 894개와 APK 빌드가 통과했다. API 37 에뮬레이터 구아리랑에서 탭으로 0:15, 드래그로 0:23 이동 및 종료 후 0:00 재시작을 관찰했다. 조작 버튼은 균등 배치, 기존 로딩 표시는 아래 40dp 고정 칸으로 이전했으며 문자열은 추가하지 않았다. 실기기 오디오·iOS·태블릿은 미확인이다.

2026-11-06 배치 수정에서는 하단 로딩 전용 칸을 제거하고 시간 표시 사이의 40dp 고정 칸을 사용한다. 로딩 영역을 기존 시간 행과 공유해 표시 유무에 따른 높이를 고정하면서 플레이어의 빈 공간을 줄였다. Android 빌드·Wasm 컴파일과 에뮬레이터 준비 화면의 배치는 확인했으나 실제 로딩 전환 관찰은 사용자 입력으로 검증 페이지가 바뀌어 미완료다.

## 평가 중 악보 따라가기 복귀 (S15P31E102-558)

조작하지 않으면 평가 중 악보는 휴대폰 일반 악보·운지법 함께 보기·다시 연주하기 모두 연주 위치를 따라 넘어갔다. 원인은 악보를 끄는 동작이었다. 터치 슬롭을 넘는 짧은 끌기(60px)만으로 `follow`가 꺼지고, 그 뒤로는 작은 '현재 위치로' 버튼을 눌러야만 다시 따라갔다. 악기를 든 채로는 이 버튼을 누르기 어렵다. 구아리랑에서는 연주가 10각을 지나도 화면이 1~7각에 멈춰 있었다.

평가(녹음) 중에 끌면 그때의 각을 `followHeldGak`에 기억한다. 현재 위치가 다른 각으로 넘어가면 다시 따라간다. 모범 연주·장단 연습은 그대로 '현재 위치로'를 누를 때까지 멈춰 둔다. API 37 에뮬레이터 구아리랑에서 2각에서 끈 뒤 3각에서 버튼이 사라지고 11각까지 따라가는 것을 확인했다. 실기기와 태블릿 두 단 배치는 확인하지 않았다.

에뮬레이터에서는 호스트 마이크를 켜도(`adb emu avd hostmicon`) 녹음 시작 직후 입력 초과 검사에 걸려 '연주가 중단되었어요'가 떴다. 이 확인에서는 그 검사를 로컬에서만 끄고 진행했다. 원인과 수정은 S15P31E102-559에서 따로 다룬다.
