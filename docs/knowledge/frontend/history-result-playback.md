# 이전 연주 결과와 녹음 재생의 상태 경계

기준: S15P31E102-553 미병합 구현, 2026-11-07 검증. 사용자의 인수인계 설계를 구현했다.

## 데이터·화면 책임

- 기록 목록은 항목 점수·오류의 완전한 데이터가 아니다. `RecordDetailUiState.detailLoaded`가 참일 때만 `PracticeRecord`를 `EvaluationResult`로 변환해 공용 필터·항목 점수에 넘긴다.
- `HttpPracticeRecordRepository.detail`이 PRA-03 상세와 EVA-01 평가를 합친다. 화면에서 평가를 중복 요청하지 않는다. `eventErrors`도 보존해야 나뉜 정간의 틀린 소박만 칠할 수 있다.
- 변환의 `id`는 선택한 기록 ID, `total`은 기록 점수, `sample`은 false다. 목록만 남은 조회 실패는 평가·연습 가능으로 표시하지 않는다.
- `history`가 조회·필터·재생·삭제 상태를 소유하고 `result`는 평가 직후 오류 위치만 맡는다. 공용 필터·점수 카드·북 그림은 `core`에 두어 기능 간 참조를 추가하지 않았다.

근거: `RecordDetailViewModel.kt`, `HttpPracticeRecordRepository.kt`, `core/ui/score/ScoreErrorFilter.kt`와 해당 상태·저장소 테스트.

## 재생·삭제 경계

- 슬라이더·±5초의 `seek`는 일시정지 중 위치만 옮기고, 재생 중에는 그 위치에서 이어 듣는다. 정간 터치의 `playAt`은 일시정지 중에도 그 음부터 시작한다. 마지막 음을 눌러도 처음으로 되돌리지 않는다.
- 녹음이 없는 기록은 재생·위치 이동을 받지 않으며 악보의 터치 동작과 현재 위치 강조도 숨긴다.
- Route 해제와 ON_STOP에서 일시정지한다. 기록 전환·삭제 성공·계정 전환에서는 재생을 중단한다.
- 삭제 응답은 요청 당시의 기록 ID와 선택 세대가 모두 맞을 때만 현재 화면에 적용한다. 다른 기록을 열었다 돌아온 경우에도 이전 삭제 응답이 새 상태를 덮지 않는다.

## 관찰한 UI

- 웹 격리 미리보기 360×800: 필터 네 개가 한 줄에 있고, 재생·±5초·취약 구간 연습이 하단 한 줄에 있다.
- 800×1100: 각을 여러 줄로 접는다. 1280×800: 목록과 합친 상세를 두 칸으로 표시한다.
- 360×480: 본문 전체를 스크롤해 요약 아래 악보에 접근할 수 있다.
- 음정 오류가 있는 현재 정간: 갈색 바탕·음표 아이콘과 연두 위치 테두리가 함께 보였다. 음정 필터를 누르면 박자·음 길이 표시가 사라졌다. 재생 위치의 글자는 빨강으로 바뀌지 않았다.
- 녹음 없는 미리보기: 안내가 바뀌고 따라가기 스위치·악보 터치를 숨기며 손잡이·재생 조작이 흐려졌다. 재생 버튼을 눌러도 재생 상태로 바뀌지 않았다. 다만 웹의 생성된 접근성 DOM에는 `aria-disabled`가 없었으므로 스크린리더의 비활성 안내는 검증하지 못했다.
- 북 카운트다운의 숫자 3은 옅은 삼태극 위에서 읽혔다. 실제 시간 경과에 따른 3→2→1 전 과정은 실기기에서 확인하지 않았다.

웹 미리보기는 실제 Screen에 고정 데이터를 넣은 시각 검증이다. 인증·서버 호출·오디오 재생 E2E 증거가 아니다. 임시 진입점과 미리보기 소스는 원복·제거했다.

## 실기기와 남은 범위

- Galaxy S25+ SM-S936N, Android 16, 앱 1.0.0(2) debug, 1440×3120 / density 600에서 확인했다. 검증 수행자는 Codex 에이전트이며, 실행일은 2026-11-07이다.
- 실제 기록의 점수·메모·악기명·종류별 오류·비교·취약 구간 선택 진입을 확인했다. 정간을 누른 뒤 `0:01 · 1각 2정간`과 일시정지 버튼을 관찰했고 Android MediaPlayer 상태는 started였다.
- 홈 버튼 및 시스템 뒤로 가기 뒤 MediaPlayer 상태가 paused가 됐다. 기기 미디어 볼륨은 음소거 상태여서 소리의 청취 품질은 판정하지 않았다.
- 삭제 확인 창을 열고 취소해 기록이 남는 것을 확인했다. 실제 서버 기록 삭제는 수행하지 않고, 성공·Busy·Failed·중복 확인·늦은 응답·계정 변경은 자동 테스트로 검사했다.
- 취약 구간 선택의 기존 북 속도 슬라이더에서 `약간 느리게`→`보통` 단계 선택을 확인하고 원래 단계로 돌렸다.
- 비교 화면의 빨강 오류 테두리는 실제 화면에서 확인했다. 점수 상승의 빨강은 `CompareScreen.kt`의 `delta > 0`·인장 색 코드에 남아 있으며 해당 기록 쌍에서는 점수 비교 불가라 상승 표시는 실화면 검증하지 않았다. 둘 다 이번 변경 범위에서 제외했다.
- Android 태블릿 실기기와 iOS는 미검증이다. 태블릿 배치는 위 웹 미리보기에서만 확인했다.

재현 명령·자동 검사 결과와 작업 상태는 [553 실행 기록](../../plans/S15P31E102-553.md)에 둔다.

## 후속 발견: 기록의 가로 따라가기와 북 주변 틈

같은 날 사용자 피드백으로 가로 따라가기 누락을 발견했다. 초기 점검은 현재 정간 표시·재생 이탈을 확인했으나 기록 재생이 먼 각으로 넘어갈 때의 스크롤을 검증하지 못했다.

- 수정 전 S25+에서 재생 위치는 `0:14 · 7각 1정간`이지만 보이는 악보는 1~4각이었다. `JeongganboView`의 `FollowPlayhead` 공급 함수가 live cursor가 있을 때만 값을 내고, 기록 재생의 `currentIndex`를 무시했다.
- 기록처럼 live playback이 없는 경우 `currentIndex`로 스크롤 좌표를 구하도록 고쳤다. 빨강 live 글자·진행 칠하기를 켜지 않고 기존 연두 정간 표시를 유지한다.
- 수정 후 같은 위치에서 7각이 보이고, 실제 녹음이 `0:35 · 16각 1정간`으로 진행되면 13~16각이 보이는 것을 확인했다. 스크롤은 기존 각 단위·300ms 이동 방식을 사용한다.
- 북 주변 흰 틈은 북 Canvas의 사각 배경이 아니라 Material3 `SliderDefaults.Track`의 기본 `thumbTrackGapSize`였다. 재생 슬라이더에서 이 값만 `0.dp`로 지정하면 선이 북 아래까지 이어진다. 북 그림과 기존 연습 속도 슬라이더는 바꾸지 않았다.
- 수정된 코드에서 Android host 1,020 통과·기존 외부 서버 4 건너뜀, debug APK·Wasm 배포 빌드를 다시 통과했다. 실기기 전후 증거와 로그는 실행 기록에 연결했다.

## 후속 관찰: 구간 재평가의 분할 정간

- 구간 반복·재평가 악보는 `SectionLoopScreen` 한 곳에서 그린다. 결과 요약 화면에는 악보가 없다. 이 화면은 기존 고정 정간 높이를 그대로 쓰므로 세 줄 소박의 간격이 오류 위치·기록 화면보다 좁았다.
- 해당 화면의 율명을 두 소박 16sp·셋 이상 15sp, 세로 소박 한 줄은 최소 26dp로 조정했다. `JeongganboMetrics.splitScaleMany`와 `errorScoreCellHeights`의 선택 인자로 해당 화면에서만 조정하고, 다른 화면의 기본 크기는 보존한다.
- 악보의 `unitRow` 수로 높이를 구한다. 가로로 나뉜 음의 개수를 세로 줄 수로 계산하지 않는다. 원본 음표 순서·정간 좌표·시간 정보는 그대로 둔다.
- S25+에서 아리랑·소금 1각의 세 줄 소박을 전후 비교했다. 글자가 커졌고 행 사이 공간이 확보됐다. 구간 반복 화면에서 공용 배치를 확인했으며, 실제 녹음·서버 구간 재평가를 다시 수행한 증거는 아니다.
- 새 일반/긴 각 검사 2건을 포함해 Android host 1,022 통과·기존 외부 서버 4 건너뜀, debug APK·Wasm 배포 빌드를 통과했다. 세부 증거는 실행 기록의 ‘구간 재평가 소박 가독성’에 둔다.

## 구간 반복 완료 버튼 문구·높이

- 사용자 최종 선택에 따라 완료 상태의 `처음부터 다시`는 `다시 연습`, `이 구간 재평가`는 `구간 재평가`로 바꿨다.
- 두 버튼을 감싸는 Row의 높이를 내용에 맞춰 정하고 각각 그 높이를 채우도록 해서, 문구 줄바꿈이 생겨도 버튼 높이를 맞춘다. 재시작·멈춤·재평가 동작은 바꾸지 않았다.
- 최종 코드의 Android host·APK·Wasm 배포 빌드를 통과했고 S25+에 설치했다. 최종 실화면 확인은 사용자가 직접 하기로 했으므로 두 버튼의 실기기 높이를 확인 완료로 기록하지 않는다.

## 녹음 시간과 악보 위치의 분리

- 오디오의 밀리초 위치를 음표 번호로만 보관하면 긴 음 안의 진행이 사라진다. `playbackPositionMs`는 녹음의 연속 시간, `position`은 해당 시간의 악보 음표 인덱스로 각각 보관한다.
- 슬라이더·±5초·이어듣기에는 실제 시간을 사용하고, 정간 터치는 해당 음표의 시작 시간으로 이동한다. 전체 길이는 미디어가 보고한 길이, 서버 재생 응답 길이, 기록의 초 단위 길이 순으로 사용한다.
- 마지막 음 안에서 재개하는 것과 파일 끝에서 재시작하는 것을 음표 번호로 구분하면 안 된다. 실제 시간이 전체 길이에 도달했는지로 판단한다. 파일 끝으로 이동하면 멈추고, 다음 재생은 처음부터 시작한다.
- 플랫폼 오디오 보고 사이의 북 이동만 짧게 보간한다. 별도 시계로 재생 시간을 추정하지 않는다. 드래그 중에는 입력을 바로 표시하고 놓을 때 한 번 적용해 미디어를 반복 로드하지 않는다.
