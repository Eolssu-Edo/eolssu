# 기록 메모의 유니코드 문자 수

- 작업: [S15P31E102-933](https://ssafy.atlassian.net/browse/S15P31E102-933), 2026-11-15.
- 기준: [REC-01 메모 규칙](../../specs/practice-records.md), backend `MemoChange.of`의 `codePointCount`와 `MemoChangeTests`.

## 확인한 차이

서버는 앞뒤 공백을 자른 메모를 최대 500개 유니코드 코드 포인트까지 받는다. `😀`는 코드 포인트 1개이며 Kotlin `String.length`로는 UTF-16 단위 2개다. 기록 상세의 입력 제한·카운터·저장 검사가 `String.length`를 사용하여 서버가 허용하는 메모를 거부했다.

`edf90cc3`의 실제 `RecordDetailViewModel`에 격리 저장소를 연결하고 `openMemo → editMemo → saveMemo`로 검사했다. `😀` 500개는 저장소에 전달돼야 하지만 전달된 요청은 0개였다. 추가한 회귀 1건이 실패했고 기존 6건은 통과했다. `😀` 500개에 `가` 하나를 더한 501자는 거부됐다. 증거는 `C:/higher/qa-evidence/S15P31E102-933/memo-red.log`와 `memo-red.xml`이다. 이 검사는 서버 통합이나 실제 앱 UI 재현을 대신하지 않는다.

## 적용

기록 상세에서만 쓰는 `recordMemoLength`로 입력 제한·카운터·저장 전 검사를 맞춘다. 유효한 서로게이트 쌍만 1개로 세고 홀로 남은 서로게이트는 1개로 센다. 커서의 `TextRange`는 Compose의 UTF-16 인덱스를 계속 사용한다. 앞뒤 공백 제거·500자 상한·실패 시 초안 유지 등 기존 계약은 유지한다.

코드 포인트는 화면의 글자 모양 묶음과 다르다. 결합 문자인 `e + U+0301`은 2개, `👩‍🔬`은 3개로 세어 현재 서버 기준과 맞춘다. 새 grapheme cluster 규칙을 도입하지 않는다.

수정 후 메모·기록 상세·목록 대상 Android host test 41건이 통과했다(실패/오류/제외 0). 메모 경계 8건에는 정상/실패/취소/기록 전환에 따른 늦은 결과 격리, 한글 500/501자, 이모지 500/501자, 결합 문자·줄바꿈·홀로 남은 서로게이트가 포함된다. 후속 전체 Android host test는 1,774건 통과·5건 제외·실패/오류 0이며 APK 빌드도 성공했다. 실행 명령·제외 이유·증거 위치는 작업 계획에 기록했다.

## 실제 Android UI 재검증

Galaxy S24+의 로그인된 QA 앱에서 배포본 #372는 😀 1개를 `2/500`으로 표시하고 250개 이후 추가 입력을 거부했다. 수정본 `qa933-local-fea297e4-qa309`는 같은 입력을 `1/500`으로 표시하고 500개를 받는다. 501번째 추가 붙여넣기를 시도한 뒤에도 최종 필드와 카운터는 500개·`500/500`이었다. 증거 `40`·`41`·`64`·`65` XML/화면은 위 로컬 증거 폴더에 보존한다.

모바일 데이터를 끄고 기본 네트워크 없음 확인 후 저장을 시도하자 실패 안내와 500개 초안이 유지됐다(`66`). 취소 후 읽기 메모는 기존 값과 동일했다(`67`, `38`·`43`과 대조). 오프라인 앱 재실행의 연결 오류에서 네트워크 복구·재시도를 거쳐 로그인된 홈으로 돌아왔다(`68`~`70`). 기존 사용자 메모에 변경값을 저장하지 않았으므로 이 결과를 실제 서버의 긴 메모 저장 성공으로 해석하지 않는다.

후속으로 ROOT가 최종 통합 APK `qa933-integrated-7eb7b7d2-qa309`(1794724936, SHA-256 `d349770dd7273092c06b3424847c7ac76d81bb51880c810dcea2f9e17142a7fd`)를 설치했다. 별도 증거 경로 `C:/higher/qa-evidence/app-flow-20261115/`의 `67`~`69-933*`에서 1개 `1/500`, 500개 허용, 501번째 실제 붙여넣기 뒤에도 500 코드 포인트·UTF-16 1000단위 유지가 확인됐다. `65`와 `70-933*`의 메모를 내용 노출 없이 대조해 취소 후 원래 값과 동일함도 확인했다. 테스트 메모를 서버에 저장하지 않았으며, QA 클립보드는 검증 후 빈 값 쓰기 성공·임시 도구 제거로 정리됐다.
