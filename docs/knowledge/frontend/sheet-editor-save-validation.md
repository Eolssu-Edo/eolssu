# 내 악보 저장 검증과 숫자 입력

S15P31E102-725 · 2026-11-11. [사용자 동작](../../specs/user-sheets.md#내-악보-편집-진입과-저장)과 [작업·검증 기록](../../plans/S15P31E102-725.md)을 함께 본다.

## 저장 여부는 현재 악보로 판단한다

변환 당시의 안내와 현재 오류는 수명이 다르다. 전조·추정 장단·페이지 인식 안내만으로 저장을 계속 막지 않는다. 빈 정간, 미확인 정간, 등록되지 않았거나 악기 음역을 벗어난 음, 잘못된 이음·길이, 장단 불일치는 현재 편집 상태로 다시 검사한다.

확인 버튼만으로 잘못된 음을 통과시키지 않는다. 음을 수정한 뒤에 확인할 수 있으며, 실행 취소로 잘못된 음이 돌아오면 다시 저장을 막는다. 음역 자료가 로딩 중이거나 실패한 상태도 완료를 허용하지 않고 재시도 동작을 제공한다.

확정 저장은 UI뿐 아니라 ViewModel의 요청 진입과 저장 잠금 안에서도 검사한다. 앞선 초안 저장을 기다리는 동안 내용이 바뀔 수 있기 때문이다. 확정 요청 중에는 편집을 잠가 응답이 다른 내용의 확인 항목을 지우지 않게 한다. 자동·임시 저장은 유지한다.

장단 선택에서는 BPM 단위뿐 아니라 정간당 tick 비율과 각 길이를 검사한다. 장단 해제는 메타데이터만 바꾸며 음표·이벤트·tick·배치를 보존한다.

## 빠르기와 예상 음원 길이

공통 입력 컴포넌트 `EolssuTextField`의 일반 숫자 유형이 `KeyboardType.NumberPassword`를 사용하고 있었다. 빠르기 저장 시 삼성 패스가 로그인 정보 저장을 제안한다는 사용자 제보에 따라 `KeyboardType.Number`로 수정했다. 실제 비밀번호 입력 유형은 별도로 유지한다. OS의 저장 제안 여부와 입력 유형 수정 여부는 검증 결과를 구분한다.

예상 길이는 현재 정간 수 × 60 / BPM × 원본 `ticksPerJeonggan / ticksPerBeat`로 계산한다. 점4분음표 BPM도 이 비율에 포함되므로 추가로 3을 곱하거나 나누지 않는다. 장단 이름으로 시간을 추정하지 않고, 장단 사용을 해제해도 원본 시간 비율을 보존한다.

저장 전 미완성 악보를 `toSong()`으로 바꾸면 표시용 대체 악보에 시간 정보가 없을 수 있어 예상 길이는 원본 시간 정보에서 직접 계산한다. 잘못된 BPM에는 예상 값을 표시하지 않는다. 반복·빠르기 변화 등이 실제 음원 길이에 영향을 줄 수 있어 문구는 ‘예상 음원 길이’로 쓴다.

## 검증 범위

MR 준비 시 최신 develop 통합 후 Android 호스트 테스트는 1,316개 중 1,312개 통과, 4개 건너뜀, 실패·오류 0개다. 현재 악보 검증, 저장 대기·응답 경합, 제목·빠르기 변경 직후 최종 저장, 저장 실패 후 재시도, 예상 길이의 원본 시간 비율을 포함한다. Android 앱 빌드도 통과했다.

Android 17/API 37 에뮬레이터에서 별도 앱 ID `com.ssafy.eolssu.preview725`, 메모리 저장소와 고정 악보로 직접 저장·오류 차단·예상 길이 갱신을 확인했다. 두 차례 빠르기 입력의 EditorInfo는 `inputType=0x2`, UI 계층의 `password=false`였다. 운영 서버나 사용자 악보는 변경하지 않았다. 상세 증거는 작업 기록에 남겼으며 삼성 실기기·iOS·운영 배포 결과로 대체해 보고하지 않는다.

## 초기 오류 표시와 실제 정간으로 이동 (736)

저장 창의 후속 안내 개선은 아래 [반복 참고 안내](#반복-참고-안내와-실제-미확인-검수의-구분-928)와 구분한다.

725 배포 앱 사용 후의 후속 요청은 미리듣기 페이지와 상시 검토 패널 제거다. 빨간 배경·테두리 및 `!` 표시는 모든 수정 대상 정간에 적용하고, 선택한 소박의 연두 표시가 오류 표시를 덮지 않게 한다. 화면 읽기 프로그램에는 율명 설명과 함께 수정 필요·선택 상태를 전달한다. 확인·수정 동작은 저장 시 요청한 창으로 옮긴다.

각 번호만으로 스크롤 거리를 계산하면 긴 각이 여러 줄로 나뉠 때 실제 위치와 어긋난다. 같은 정간이 선택된 채 사용자가 다른 곳으로 스크롤하면 선택 번호가 바뀌지 않아 기존 효과도 재실행되지 않는다. 실제 렌더링한 정간에 `BringIntoViewRequester`를 붙이고, 저장·수정 이동마다 요청 번호를 증가시켜 가로·세로 스크롤을 처리한다. 기존 호출자는 새 선택·이동 인자를 생략할 수 있다.

빠르기·장단 설정은 대화상자 안에서 임시 선택하고 적용 시 하나의 실행 취소 단위로 반영한다. 적용·취소 이후 장단 조회 결과가 도착해 선택 창이 다시 열리지 않게 조회 작업도 종료해야 한다. 오류 위치는 앞선 이벤트의 잘못된 길이를 뒤의 정상 이벤트에 누적해 전파하지 않고, 각 이벤트가 참조하는 표시 구간과 비교해 찾는다. 검증 결과와 미확인 범위는 [736 작업 기록](../../plans/S15P31E102-736.md)을 따른다.

## 반복 참고 안내와 실제 미확인 검수의 구분 (928)

2026-11-15 Galaxy S24+ QA364 제보의 같은 문구4줄은 현재 미확인 검수4건이 아니었다. 제목·생성일로 한정한 읽기 전용 변환 annotation 조회에서 PDF 빠르기 보완(`TEMPO_PDF_TEXT`)3건·성부 선택(`VOICE_GUESSED`)1건이 확인됐다. 조회 시에는 실제 issue0건·미확인0건·확정 버전2·`EVALUABLE`이었다. 상태 수명과 재현 조건은 [928 작업 기록](../../plans/S15P31E102-928.md)을 따른다. 사용자 악보·초안·원본은 수정하지 않았다.

`SheetConversionNotes`의 일반 fallback이 서로 다른 사유를 같은 원본 비교 문구로 표시한 것이 원인이다. 빠르기 보완의 `count=1,2,2`는5곳의 숫자 표시를 보완했다는 뜻이며, `staff_pdf_tempo.supplement`의 변경/삽입 수에서 온다. `VOICE_GUESSED`는 여러 성부뿐 아니라 화음에서 단일 선율을 고른 경우도 포함한다. 음악적으로 올바른 인식을 보장하는 안내가 아니므로 원본 대조는 여전히 필요하다.

FE 표시 adapter는 원본 annotation을 바꾸지 않고 같은 사유·위치·detail의 참고 안내만 묶는다. 빠르기 보완 수만 합산하며 쪽·마디·좌표·기타 detail이 다르면 분리한다. 원본 응답에 쪽·좌표가 없으면 특정 정간으로 안내하지 않는다. 안내는 변환 당시의 참고 정보이고, 저장 제한은 기존 현재 악보 검증·미확인 issue와 명시적 확인으로 판단한다. [표시 계약](../../specs/sheet-review-guidance.md)을 함께 본다.

최종 호스트1753건(실패·오류0, 기존 제외5), APK·Wasm 실행용 빌드와 격리 App 경로에서 요약·저장·미확인 차단·선택 위치·원본 쪽/마디 분리를 확인했다. 데스크톱 브라우저 결과이며 실기기·iOS·접근성 인수를 대체하지 않는다. 상세 명령과 fixture 제약은928 작업 기록을 따른다.
