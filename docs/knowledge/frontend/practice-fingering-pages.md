# 연습 악보 운지 연결과 표시 위치

- 작업: S15P31E102-500.
- 코드 기준: `origin/develop 6b29fbc7`에서 분기한 로컬 작업. 운영 반영·실기기 검수와 구분한다.

## 확인한 원인과 적용

공통 악보의 `ScoreNote.SourcePitch`는 기본 12율과 -2~2옥타브를 보존한다. 연습 운지 목록은 이 값을 일부 음만 있는 `Yul` enum으로 줄였고, 변환 실패를 실제 쉼과 같은 null로 취급했다. 내장 소금 표에는 청고 `㴌`와 운지 `100000`이 있지만 enum에 청고가 없어 ‘쉼’으로 표시됐다. 같은 문제가 청남·청응·중청음 등에서도 생긴다.

내장표의 한자는 원본 악보와 다른 이체자도 포함한다. 예를 들어 표의 중청태 `㶃`는 원본 악보의 중청태 `㳲`와 글자가 다르므로 문자열만 비교하면 연결되지 않는다. 기존 `baseYulOf`·`octaveOf`의 내장표 의미를 사용해 원본 기본율·옥타브와 대응하고 구멍 상태를 그대로 사용한다. 원본 음이나 옥타브를 낮춰서 대체하지 않는다. 자료가 없는 음은 그림 없이 ‘운지 자료 없음’, 실제 쉼만 ‘쉼’이다. 내장표 자체의 음악적 정확성·전문가 검수는 이번 소프트웨어 연결 검사로 증명하지 않는다.

## 페이지와 가사 근거

`data/tests/fixtures/scores/school-textbook-sogeum-p16.score.json`은 도라지타령 20각·68이벤트, 1각 3정간, `ticksPerBeat=3`, `ticksPerJeonggan=3`이다. NOTE의 7음은 청고·남·청남·임·청임·청태·청황이다. 세마치 패턴의 9소박과 3정간을 같은 단위로 보지 않는다.

가사 원본 `data/annotations/scores/school-textbook-sogeum-p16/도라지타령_소금.jgb.json`에는 `도 | - - 라 | 지`와 `지 - 화`처럼 정간 안 위치를 뜻하는 장음 토큰이 있다. 기호를 먼저 삭제하고 남은 글자를 가운데 모으면 ‘라’·‘화’의 발음 위치가 바뀐다. 늴리리야의 `{세로표} 노`와 아리랑의 `{세로표} - 리`에서는 메타 표식도 빈 슬롯으로 보존해야 한다. 먼저 원본 토큰 자리와 표시 줄을 대응하고 각 토큰 안의 기호·메타 문자열만 지운다. 원본 데이터는 보존하고 표시 변환만 적용한다.

대강 하나가 1.5정간인 판본도 두 대강 합은 3정간이다. 각 길이가 정수라는 이유로 대강도 정수 정간이라고 보지 않는다. 페이지 끝이 원본 표시 자리 중간에 있으면 표시용 조각만 나누고 원본 이벤트를 공유한다. 다음 페이지의 계속음은 장음으로 표시해 운지와 가사를 반복하지 않는다.

실행 명령·결과·기기별 미확인 범위는 [작업 계획](../../plans/S15P31E102-500.md)에 기록한다.

Android 화면 후속 확인에서는 두 대강에 장음이 포함되면 실제 율명이 3개만 표시됐다. 사용자의 후속 요청에 따라 고정 대강 수 대신 실제 발음 6개 이상을 담을 때까지 대강을 묶는다. 장음·쉼·빈 자리는 개수에서 제외한다. 미리보기 두 음은 현재 음 바로 다음이 아니라 현재 페이지 밖의 다음 발음으로 분리한다. 장음·빈 자리 높이는 음 줄의 절반으로 줄여 슬롯 대응을 유지하며 표시 밀도를 높인다.

다음 두 음을 세로 표로 표시할 때는 새 음절 문자열을 다시 분해하지 않고, 전체 `FingerCell`의 원본 슬롯에서 음·운지·가사를 함께 한 행으로 추출한다. 같은 정간의 장음 뒤 음절과 같은 높이의 반복 발음도 구분한다. 현재 악보의 표 머리·행 컴포넌트를 미리보기에도 재사용해 열 너비와 읽기 순서를 유지한다.
