# 악보 편집에서 음원을 만들 수 없는 입력과 잘못 남는 표시 (1080)

- 작업: [S15P31E102-1080](https://ssafy.atlassian.net/browse/S15P31E102-1080) · 확인 2026-11-17 · 배포 QA APK #474(`6ec216ab`)와 develop `97aa1cdda` 디버그 빌드, API 37 에뮬레이터(Medium_Phone), 운영 API.

## 저장이 실패하는 구조

- 확정 저장(`PUT /api/users/me/sheets/{id}/score`)은 서버가 저장 전에 음원 생성기의 사전 검사(`playback.estimate` → `render_request.estimate` → `authoring_tempo.preflight`)를 거친다. 생성기가 `ValueError`를 내면 `{"errorCode":"INVALID_REQUEST"}`만 돌려주고 어느 음·기호인지는 버린다.
- 앱은 확정 저장의 400 `INVALID_REQUEST`를 따로 다루지 않아 "저장하지 못했어요. 편집은 그대로니 다시 시도해 주세요."만 띄운다. 다시 시도해도 같은 결과다.
- 즉 "음원을 만들 수 없는 악보는 저장하지 않는다"는 서버에서 이미 지켜지고 있고, 빠진 것은 이유와 바로 고치는 방법이다.

## 시김새 조합 실측

입력은 편집기 목록의 시김새 52개(요성표·퇴성·추성·전성 + 공통 렌더러 등록 이름)다. `data/src/playback/tests/_helpers.common_notes`로 네 음 악보를 만들고 둘째 음에 붙여 `preflight`를 직접 호출했다.

| 조건 | 결과 |
| --- | --- |
| 한 개, 단소·소금·정악대금·산조대금 | `전성`만 거절, 나머지 51개 통과. 첫 음·마지막 음·쉼표 앞 음도 같다 |
| 두 개 조합 1,275쌍 | 382쌍 거절. 네 악기의 거절 쌍이 같다 |
| 앱 실측(시트 68) | 전성 하나 → 400 `INVALID_REQUEST`, 요성표 하나 → 200 |

거절 쌍은 대부분 생성기의 범주로 설명된다. 꾸밈음(grace·surround·attached·independent)은 한 음에 하나, 음높이 곡선(퇴성·추성·흘림·미는표·풀어내림·꺾는음·겹흘림)은 하나, 요성류(요성표·겹요성표·농음·풀어내림)는 하나, 길이표는 하나만 받는다. 꾸밈음과 끊는표·혀치기·반음올림표도 함께 받지 않는다. 예외(같은음표·노·니·로·리 같은 단순 꾸밈과 반음올림표+니레 허용)가 있어서, 앱에는 범주 규칙 대신 실측 쌍 목록을 그대로 둔다(`SigimsaePlaybackRules.kt`).

점검 당시 `전성`은 앱(`SheetDraft.Sigimsae.Jeonseong`)에만 있고 DATA·BE·AI 코드 어디에도 해석이 없었다. 이후 [1084](https://ssafy.atlassian.net/browse/S15P31E102-1084)에서 앞꾸밈음(grace)으로 해석이 들어갔고, 1087에서 기호 그림과 저장 거절 위치 안내가 들어갔다.

## 기준음이 다른 악보의 표시

- `supportedInputPitches`는 악보의 `hwangHz`가 악기 조율과 다르면 빈 집합을 돌려준다. 그래서 모든 음이 갈색 ↕(낼 수 없는 음)로 표시된다.
- 높이 맞추기 패널은 MIDI 기준으로 계산해 "낼 수 없는 음 0개"를 보이고, 상단 안내(`importGuide`)도 그 수를 써서 사라진다. 사용자는 표시가 왜 남는지, 무엇을 눌러야 하는지 알 수 없었다.
- 패널의 '적용'을 한 번 누르면 기준음이 악기 값으로 바뀌고 표시가 모두 없어진다(시트 149, 산조대금, 52칸 → 0칸).

## 구간 빠르기와 정간 잠금

`hasTempoPlan`이 `performancePlan` 키의 존재만 봤다. 구간 빠르기를 넣었다 지우면 빈 `tempos`가 남아 정간 나누기·합치기·각 추가·삭제와 장단 선택이 계속 막혔다. 지금은 `tempos` 또는 `repeats`에 항목이 있을 때만 막는다. 반복 구간도 각 번호에 묶이므로 잠금에 넣는다.

## 앱에서 바꾼 것

- 함께 해석되지 않는 시김새를 고르면 기존 것을 새로 고른 것으로 바꾸고 알린다(실행 취소 가능). 저장 단계의 거절 위치 안내(1087)보다 앞에서 막는다. 처음에는 전성도 목록에서 뺐지만 1084 병합 뒤 되돌렸다.
- 기준음이 다르면 상단 안내에 "원래 높이로 맞추기"(1085에서 "기준음 맞추기"를 바꾼 문구)를 보여 한 번에 맞춘다.
- 흐리게 보이는 율명(지원 목록 밖)은 비활성 버튼이라 눌러도 반응이 없었다. 흐린 모양은 두고 누를 수 있게 바꿔, 누르면 악보는 그대로 두고 이유를 알린다.
- 구간 빠르기 삭제 버튼을 수정 버튼과 같은 테두리 모양으로 맞추고 글자만 빨갛게 했다.
- 장단 선택 창의 제목·안내가 0 높이로 접히던 중복 세로 스크롤을 뺐다.

## 남은 일

- 사전 검사 오류에 음 위치·기호를 담아 보내면 앱이 그 칸으로 이동하고 바로 고치는 버튼을 줄 수 있다(DATA·BE·FE 계약 추가).
- 세 개 이상 조합은 실측하지 않았다. 서버가 같은 생성기로 확정 저장을 다시 검사하므로 남는 경우는 저장 실패 안내로 드러난다.
- 편집 닫기는 홈의 '악보 추가·편집하기'에서 들어왔으면 홈으로 간다. `closeEditor`에 적힌 의도된 흐름이라 바꾸지 않았다.
