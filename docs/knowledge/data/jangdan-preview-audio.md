# 등록 장단 10종의 미리듣기 음원

S15P31E102-160 · 2026-11-04

[국립국악원 국악기 디지털 음원 단음 다운로드](https://www.gugak.go.kr/digitaleum/front/monotone/list.do)에서 장구(19847)의 원본 WAV를 받았다. 장구 목록의 공공누리 유형은 1이다. 가공한 음원의 출처는 국립국악원이며, 원본과 파생 음원의 SHA-256 및 타격 배치는 [생성 목록](jangdan-preview-audio-manifest.json)에 있다.

이 미리듣기는 [등록 패턴](../../../data/reference/jangdans.json)을 서비스 기본 BPM에서 한 주기 재생한 것이다. 각 타격의 앞 무음을 잘라 모노로 섞고 AAC-LC M4A 44.1 kHz / 64 kbps로 인코딩했다. 덕기는 3:1, 덕덕은 1:1로 배치한다. 기덕·기닥의 앞꾸밈과 더러러러의 굴림은 녹음 타격을 재배치한 교육용 편집이다. 기닥·다는 약한 채편 샘플을 사용하고 따는 단일 채편 타격으로 표현했다. 타령과 계면가락도드리는 현재 등록 패턴과 BPM이 같아 같은 소리가 나오며 ID별로 각각 제공한다.

## 다시 생성하기

저장소 루트에서 실행한다. `--samples`에는 생성 목록과 SHA-256이 같은 WAV 6개를 둔다. `--output`에는 아직 생성되지 않은 경로를 지정한다.

```powershell
python -m data.src.audio.jangdan_audio --reference data/reference/jangdans.json --samples data/raw/jangdan-160 --output data/processed/jangdan-160
python -m unittest data.tests.test_jangdan_audio
```

FFmpeg가 PATH에 없으면 `--ffmpeg`에 실행 파일을 지정한다. 이 결과는 FFmpeg 7.1의 AAC 인코더으로 생성했다.

같은 원본으로 두 번 생성해 M4A 10개 SHA-256이 모두 일치했다. 생성 명세의 `objectKey`를 사용해 기존 모범 음원과 같은 비공개 R2 버킷에 조건부 PUT했다. 10개 모두 전체 GET의 SHA-256·크기가 원본과 일치했고, 서명 GET의 처음 64바이트를 `206 audio/mp4`로 받았다. PCM 디코딩 결과는 계획한 길이보다 최대 888프레임(약 20ms) 길었고 16비트 범위에서 클리핑이 없었다. 장구 연주자 청음 검수는 남아 있다.

재게시할 때는 [R2 업로드 도구](../../../infra/r2/README.md)에 M4A 파일과 생성 명세의 객체 키를 한 쌍으로 넘긴다. 서버의 `catalog/jangdan-preview-sha256.properties`에는 검증된 ID와 SHA-256을 기록한다. 내용이 바뀌면 새 해시의 객체를 먼저 검증한 뒤 매핑을 바꾼다.

### 자산·연결 제안과 남은 검수

1. 기본 타격은 기존 덩·쿵·덕 등의 짧은 샘플을 재사용하고 타격 시점을 곡 시간표에 맞춘다. 기덕의 앞꾸밈 간격은 일반 박 간격과 별도로 다룬다.
2. 현재5단계 속도를 유지한다면 굿거리5구간·세령산5구간, 최대10개의 짧은 굴림 클립을 초기 납품 목표로 둔다. 우선순위는18개 악보가 있는 굿거리다. 세령산5구간은 굴림 주법·길이 검수 후 확정한다. 이것은 전체 곡이나 장단 한 주기를 속도별로 복제하는 안이 아니다.
3. 가까운 길이의 실연 원본을 선택해 편집하고, 특히0.5초 부근과2.4초 부근에서 굴림 밀도·강세·타격감·연결음을 청음한다. 한 원본을 최대4.7배 범위 전체로 늘려도 자연스러울 것이라고 가정하지 않는다. 원본 녹음 수와10개 최종 클립 수는 같을 필요가 없다. 청음으로 동일 샘플을 재사용할 수 있으면 자산을 줄인다.
4. 곡별로 장단 ID, 시작 tick, 패턴 한 주기에 대응하는 score tick 길이를 검수한다. 같은 장단명의 다른 음가 스케일과 여러 장단을 담는 열을 처리한다. 장단 이름이 없는45개에 임의의 기본 장단을 붙이지 않는다.
5. 모범 재생에서는 실제 재생 위치와 수행 시간표를, 장단만 사용하는 연습에서는 악보 시간표와 선택 BPM을 공통 기준으로 사용하도록 연결한다. 정지·탐색·반복·속도 변경 시 함께 재설정해야 한다. 현재 연습 장단 실제 소리 연결은 미완료다.

검증 완료 범위는 운영 공개 메타데이터 전수 조회와 수치 환산이다. 실제 굴림 원본 확보·클립 제작·청음·장단 연결 수정·모범 연주의 속도 정책 변경은 수행하지 않았다. 모범 연주1배속만 제공할지는 앞선 대화의 제안이며 확정된 설정으로 취급하지 않는다.

## 연습용 PCM 생성

2026-11-04 사용자 승인 후속 구현. 공식 단음 목록의 `instrCd=19847` 응답에서 `Janggu_4_2.wav`(mntnSeq2292)가 **더러러러/중**임을 확인했다. 4_1·4_3은 같은 주법의 강·약 녹음이며 길이 구분이 아니다. 기존 생성기의6_2는 **더/중**으로, 네 번 배치한 이전 근사와 실제 굴림 원본을 구분한다. 2_2는 **기덕/중**이며 연습 자산 `gi.wav`는 앞꾸밈만 추출한 편집이다.

[국립국악원 공식 페이지](https://www.gugak.go.kr/digitaleum/front/monotone/list.do)가 표시하는 공공누리 제1유형에 따라 원문·가공본 재배포가 가능하며 출처와 가공 사실을 표시한다. 다운로드는 공식 `/digitaleum/cmmn/file/monotone/download.do`를 사용했고, 추가4_1·4_3 다운로드에는 비상업용 앱 개발·검증 목적을 제출했다. 새로 생성하는5개는4_2 하나를 사용한다. 제품에는 원본 전체를 포함하지 않는다.

```powershell
python -m data.src.audio.jangdan_practice_audio --samples data/raw/jangdan-160 --output data/processed/jangdan-practice-160 --ffmpeg <ffmpeg.exe>
python -m unittest data.tests.test_jangdan_practice_audio data.tests.test_jangdan_audio
```

출력 경로는 새 경로여야 한다. FFmpeg7.1로 PCM16·44.1kHz·모노 WAV11개를 생성한다. 6개 단타는 기존 검증 원본에서 앞 무음과 잔향을 다듬고, 굴림5개는 실제 굴림 녹음의0.204~2.650초를 음높이 유지 `atempo`로 시간 압축한다. 각 필터 배수는2이하로 나누며 마지막에 실제 앱의 정수 BPM에 맞춘 프레임 수로 보정한다. [FFmpeg 공식 변경 기록](https://ffmpeg.org/pipermail/ffmpeg-cvslog/2018-June/114136.html)은2를 넘는 단일 배수에서 샘플 생략을 피하려면 필터 체인을 사용하도록 설명한다.

전체 압축비는 약2.41~4.85배다. 타격 개수·밀도·음색이 원본과 완전히 같다고 보장하지 않는다. 출력 전후 길이 보정량을 [연습 자산 생성 명세](../../../frontend/shared/src/commonMain/composeResources/files/jangdan/manifest.json)에 기록했다. 최대 무음 보충은635프레임(14.4ms), 최대 잘림은189프레임(4.3ms)이고 잘린 구간의 절대 피크는PCM16의9이하였다. 양끝 짧은 페이드로 클릭을 완화한다.

두 번 생성한11개 WAV의 SHA-256이 모두 같았다. 5개 굴림은44847·33494·26727·24275·22235프레임으로 요청 구간에 가장 가까운 정수 프레임이다. 모노/샘플레이트·앞50ms의 발음·무음/클리핑 없음도 확인했다. 생성 명세에는 원본과 결과 해시, crop, 도구 버전, 필터 배수, 보정량과 피크가 있다.
