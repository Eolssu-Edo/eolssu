# 소금 정간보 우물사이 문서의 검토 화면과 대조 결과

관련 Task: `S15P31E102-130`. 2026-10-26에 소금 정간보 PDF 13개를 OMR로 바꿔 둔 우물사이 문서(`.jgb.json`) 14개를 원본과 대조했다. 문서는 곡 15개다. 북천이맑다커늘에는 소금1·소금2 두 성부가 있다. 검토 화면은 단소 때 만든 것([단소 정간보 변환](danso-scores-umulsai.md))을 다시 썼다.

## 결론

- **15곡 772정간을 사람이 모두 확인했다.** 고친 정간은 3곡 25개(3.2%)다. 나머지 11곡은 고칠 곳이 없었다.
- **틀린 곳은 판형에 몰려 있다.** 소금교실10은 나란히 적힌 두 음을 위아래 두 줄로 읽었다. 북천이맑다커늘은 한 정간에 율명이 둘인 칸에서 한 음을 빠뜨렸다.
- **정간 상자는 그림의 선만으로 모두 찾았다.** 기존 두 도구는 이 판형에서 칸을 찾지 못했다. 그래서 [grid_boxes.py](../../../data/src/scores/grid_boxes.py)를 새로 만들었다. 14개 문서 모두 찾은 칸 수가 문서의 정간 수와 같았다.

## 자료

받은 폴더는 `Downloads/sogeum_dataset`이다. PDF 13개와 `.jgb.json` 14개가 들어 있다. 기초연습곡1·2 PDF 한 장에서 연습곡 두 개가 나왔다.

| 묶음 | 곡 |
| --- | --- |
| 교과서 표준악보집 (PDF187~202) | 새야새야, 개구리소리, 구아리랑, 도라지타령, 밀양아리랑, 아리랑, 닐리리야, 몽금포타령, 북천이맑다커늘 |
| 학교 교과서 (PDF14~16) | 소금연습곡 1·2, 아리랑, 도라지타령 |
| e-국악아카데미 소금교실 10차시 | 아리랑 |

- `.jgb.json`을 만든 OMR 도구·설정은 기록이 없다. 확인하지 않았다.
- PDF는 원본 목록(`data/catalog`)에 등록하지 않았다. 출처·이용 조건도 확인하지 않았다.

## 정간 상자 찾기

검토 화면이 원본 칸을 확대해 보여 주려면 정간마다 그림 속 위치가 필요하다. 기존 두 도구는 이 판형에서 칸을 거의 찾지 못했다.

| 방법 | 결과 |
| --- | --- |
| 글자 층 읽기(`standard_score_text.py`) | PDF 13개 중 1개만 읽음. 가사·설명 글의 한자 때문에 칸 안 글자 수 검사에서 멈춘다 |
| 글자 층 읽기에서 글자 검사만 건너뜀 | 3개만 칸 수가 맞음. 다른 곡은 단이 여럿이거나 선이 옅어서 칸이 더 잡히거나 덜 잡힌다 |
| OMR 리더 칸 찾기(dpi 100~300) | 1개만 일부 찾음 |
| `grid_boxes.py` | 14개 모두 칸 수가 맞음 |

`grid_boxes.py`는 150dpi 흑백 그림에서 밝기 215보다 어두운 화소를 선으로 본다. 표준악보집의 옅은 회색 선은 160 기준에서 빠졌다.

1. 60px 이상의 세로선으로 열을 나누고, 세로선 길이가 같은 묶음을 단으로 본다.
2. 열 안의 가로선을 찾는다. 실선은 열 폭의 85% 이상을 덮는다. 점선은 15% 이상을 덮고, 조각이 4개 이상이며, 양끝에 닿는다.
3. 가로선이 있는 열 바로 오른쪽에 가로선 없는 가사 열이 붙어 있으면 율명 열로 본다.
4. 학교 교과서처럼 가사 열에도 가로선이 있으면 율명 열과 가사 열이 번갈아 있다. 이때는 먹이 많은 쪽을 율명 열로 본다.
5. 칸 크기가 중간값에서 크게 벗어나는 열은 뺀다. 장단 열, 단 사이 빈 줄, 머리 그림 무늬가 여기에 걸린다.

한 페이지에 칸 수가 같은 악보가 나란한 경우도 있다(소금보·단소보, 연습곡 1·2). 이때는 오른쪽 제목 칸에 `소금`이나 문서 이름 끝의 곡 이름이 든 악보를 고른다. 상자 위에 문서 선율을 겹쳐 그린 결과, 6곡은 순서·위치가 원본과 맞았다(구아리랑, 북천이맑다커늘, 닐리리야, 도라지타령 2곡, 소금연습곡2). 나머지 8곡은 상자 수와 칸 배치만 확인했다.

## 대조 결과

검토 기록은 `Downloads/<제목>.review.json` 14개이고, 모든 정간에 확인 표시가 있다. 고친 3곡의 `.jgb.json`은 받은 폴더의 원래 문서를 덮어썼다. 처음 문서는 검토 화면 HTML 안에 남아 있다.

| 곡 | 정간 | 고친 정간 | 내용 |
| --- | ---: | ---: | --- |
| 북천이맑다커늘 | 112 | 11 | 빠진 율명 9개, 이음 줄 수 2개. 소금1·소금2 모두 6~8각 |
| 아리랑(소금교실10) | 48 | 13 | 나란히 쓴 두 음을 두 줄로 읽음(`- 남` → `-남`, `청황 청태` → `청황청태`) |
| 아리랑(학교 교과서) | 48 | 1 | 이음 줄 수(`- - 청태` → `- 청태`) |
| 나머지 11곡 | 564 | 0 | |

- 고친 문서 3개는 내려받은 파일과 받은 폴더의 파일이 같다.
- 구아리랑은 고친 정간 없이 `.jgb.json`을 한 번 저장했다. 처음 문서와 비교하면 빈 짧은 각 설정(`gakBeats: ""`)만 붙어 있고 선율은 같아, 받은 폴더에 옮기지 않았다.
- 정간을 넣거나 지운 곡은 없다. 그래서 가사 위치도 바뀌지 않았다.

## 남은 일

- 대조한 문서를 `data/raw`·`data/annotations` 어디에 둘지 정하지 않았다. 원본 등록(출처·이용 조건·SHA-256)과 함께 팀이 정한다.
- 14개 문서의 선율에 시김새가 하나도 없다. 악보에 있는 시김새를 빠뜨렸는지는 따로 세지 않았다.

## 취타 검수 화면 위치 오류 확인

2026-11-03 S15P31E102-403에서 취타 초급·중급·고급의 기존 검수 화면이 첫 12칸에 장단 열을 배치하고 실제 세 번째 악보 열을 빠뜨리는 것을 발견했다. 각 입력 JGB는 36칸이지만 PDF의 마지막 각은 4칸뿐이며, 나머지 8칸은 원본에서 정간으로 확인되지 않는다. 세 PDF 모두 칸 상자를 원본 그림 위에 겹쳐 확인했다. 기존 생성기의 칸 찾기 로직은 아직 수정하지 않았으며 기존 화면은 검수에 쓰지 않는다. 이번 검수용 화면은 처음 28칸의 위치만 바로잡고 나머지 8칸의 위치를 미확인으로 남겼다. 이 화면은 임시 결과이며 원본 악보나 기존 검수 파일을 덮어쓰지 않았다.
