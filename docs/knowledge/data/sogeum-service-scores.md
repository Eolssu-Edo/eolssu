# 소금 서비스 4곡 채점 정답 검수와 채점 켜기

관련 Task: `S15P31E102-387`. 2026-11-02~03에 소금 학습 과정 "악보와 곡" 단계에서 쓸 소금 곡을 채점 가능하게 했다. 곡은 단소와 같은 아리랑·도라지타령·밀양아리랑·늴리리야다.

## 결론

- **판본은 학교 교과서가 먼저, 없으면 국립국악원 2022 표준악보집이다.** 2026-11-03 사용자가 팀 순서로 확인했다(저장소 문서에는 이전 기록이 없다). 그래서 아리랑·도라지타령은 교과서(`school-textbook-sogeum-p15`·`p16`), 밀양아리랑·늴리리야는 표준악보집(`ngc-standard-2022-p193`·`p196`)이다. 실제 소금 녹음 4개도 모두 교과서 판본에 더 맞는다(아래 표).
- **정답은 사람이 원본과 대조했다.** 교과서 2곡은 2026-10-26 검토 화면에서 대조하고 2026-11-02 사지한이 확인(158), 표준악보집 4곡은 2026-11-02에 확인했고 고친 음은 없다. 표준 판본은 숨표만 넣었다(아리랑 4, 도라지타령 11, 밀양아리랑 7, 늴리리야 0). 표준악보집 아리랑·도라지타령(p194·p192)은 검수까지 마쳤지만 채점에는 쓰지 않는다.
- **서비스 곡 행은 새로 넣지 않았다.** [S15P31E102-339](https://ssafy.atlassian.net/browse/S15P31E102-339)가 2026-11-02 운영 DB에 소금 23곡을 DRAFT·비채점으로 넣었고, 두 판본이 모두 있다. 채점할 곡은 아리랑 96, 도라지타령 93, 밀양아리랑 95, 늴리리야 91이고, 운영 악보와 정답은 음·시작·길이·이벤트 id가 같다. 그 곡을 갱신하는 도구([enable_scoring.py](../../../infra/catalog/enable_scoring.py))를 만들었다.
- **소금 음역은 林~㵜(중청남려)다.** [국립국악원 국악사전 「소금」](https://www.gugak.go.kr/ency/topic/view/109) 기준이다. 사전은 㵜를 C6로 적었지만 저장소 규칙(황 0 = E♭4)으로 C7이고, 소금 기본음계 녹음의 중청임이 약 1940Hz라 C7 쪽이 맞다(`data/tests/test_reference_data.py`의 소금 녹음 옥타브 검사). 소금 율명 행은 V13(S15P31E102-364)과 339 적재로 DB에 있어 기준 데이터(`data/reference`)에는 넣지 않았다.

## 실제 녹음 채점

S15P31E102-158의 소금 정상 연주(갤럭시 S24+, 사람이 들어 문제 없음)를 pyin-5로 두 판본에 채점했다. BPM은 판본마다 녹음의 소리 구간 길이에 맞춰 따로 추정했다.

| 녹음 | 교과서 | 표준악보집 |
| --- | --- | --- |
| 아리랑_소금_2 | **85**(맞음 57/60) | 82(맞음 57/61) |
| 아리랑_소금_연습 | **85**(맞음 56/60) | 83(맞음 56/61) |
| 도라지타령_소금_2 | **86**(맞음 62/66) | 62(놓침 24) |
| 도라지타령_소금_연습 | **82**(맞음 56/66) | 64(놓침 15) |

- 아리랑 두 판본은 6곳만 짧게 다르다(60·61음). 도라지타령 표준 판본은 26음 더 길어, 녹음 길이에 맞추면 BPM이 92~102로 비현실적이다. 녹음은 교과서 판본을 분 것이다.
- 옥타브 규칙은 맞다. 조율 보정은 ±35센트 안이다.
- 밀양아리랑·늴리리야는 소금 녹음이 없어 실제 녹음으로 채점하지 않았다.

재현: `ai/`에서 `evaluation.local_score`의 `load_notes`를 소금 정답도 읽게 바꾼 스크립트로 채점했다(저장소 밖). 로컬 채점 화면은 단소 4곡만 고를 수 있고 소금은 더하지 않았다.

## 채점 켜기 검증

- 운영 DB 읽기(SELECT만, 2026-11-03): 4곡의 id·출처·`score_version`·현재 악보 해시가 도구 계획과 같고 모두 DRAFT다. 339 V15 적용 뒤에도 악보는 그대로다.
- 폐기용 MySQL 8.4.13(2026-11-03, 운영에서 읽은 4곡 악보와 `updated_at` 자동 갱신 열): 읽기 검사 4곡 대상, `--apply` 뒤 다시 읽기에서 숨표 0·0·7·0, reviewed, 채점 켜짐. 재실행은 쓰지 않았다. 실행 사이에 한 곡(95)이 바뀌면 CHECK 오류로 멈추고 앞서 바꾼 96·93도 되돌려졌다.
- 실행 순서와 명령은 [infra/catalog README](../../../infra/catalog/README.md#소금-4곡-채점-켜기)에 있다. 339 게시 뒤 사람이 실행한다.

## 403 소금 정답 검수 중간 기록

2026-11-03에 개구리소리, 구아리랑, 몽금포타령, 새야새야, 소금 연습곡 1·2, 북천이 맑다커늘 소금 2의 원본과 정답을 기록했다. 사용자가 검수한 숨표를 반영한 후에도 공개 운영 악보의 음, 시작, 길이와 이벤트 ID가 같음을 확인했다. 정간당 박은 운영 악보에서 읽은 값이며 원본의 박 해석을 별도로 검증한 결과는 아니다. 새야새야, 연습곡 1·2, 북천이 소금 2의 운영 악보에는 장단이 없어 빈 값과 4분음표 박 단위를 그대로 사용한다.

북천이 맑다커늘 소금 1은 사용자가 원본을 보고 음도 수정했다. 운영의 이벤트 79개와 달리 수정한 정답은 이벤트 80개다. 검수 정답은 저장소에 보존하고 채점 활성화에서는 보류한다. 나머지 곡의 정답 등록과 운영 확인은 완료되지 않았다.

2026-11-03 후속 확인에서 숨표가 율명 열 오른쪽에 속한다는 해석을 적용해 개구리소리·구아리랑·몽금포타령의 숨표 위치를 바꾸고 새야새야의 2개를 추가했다. AI가 고친 칸은 처음에 inferred로 보류했다. 변경 전 사용자의 저장 파일은 작업 폴더 completed에 보존했다. 변환 전후 음높이·시작·길이·이벤트 ID는 같았다. 북천이는 사용자가 오선보를 근거로 두 성부 모두 적용하도록 정해, 두 성부의 10각 끝에 숨표를 반영했다. 처음에는 두 정답도 inferred로 보류했다.

2026-11-03 박 단위 재확인: 339 적재곡은 QUARTER 기준이다. 403 정답 중 개구리소리·구아리랑은 운영 악보의 정간당 박을 사용했으나 `score_data.py`가 장단 기준표에서 DOTTED_QUARTER를 읽어 결과의 박 단위가 운영과 다르다. 숫자로 비교한 음·시작·길이와 박 단위 일치는 별도 검증이다. 403 채점 켜기 도구는 운영 악보의 숨표·review만 바꾸므로 이 변환 결과의 박 단위를 운영에 복사하지 않는다. 다섯 추가 곡은 사람 검수 파일을 보존했으나 박 단위·장단 처리를 정하기 전 정답 등록을 보류한다.

후속 수정: 개구리소리와 구아리랑의 검토 기록에 운영 악보의 QUARTER를 명시하고 변환기가 이를 우선 사용하도록 했다. 다른 정답 16개의 변환 결과는 변경 전과 같음을 확인했다. 원본 악보 자체의 박 단위 해석은 별도 검토 대상이다.

2026-11-03 후속 등록: 사용자가 원본 PDF와 숨표를 확인한 어깨동무·옹헤야·태평가·해주아리랑·오나라의 정답을 저장했다. 다섯 곡 모두 운영 악보와 음·쉼의 종류, 시작·길이, 이벤트 ID와 박 단위가 일치한다. Notion에 올린 팀원이 나누어 원본을 대조했으나 개인별 담당과 당시 정간별 기록은 확인되지 않았다. 내려받은 원본 JGB의 해시는 운영의 원본 JGB 해시와 다르므로 바이트 일치를 주장하지 않는다.

2026-11-03 취타 초급·중급: 사용자가 원본에 표시된 28정간과 숨표를 확인했다. 입력 JGB에는 마지막 각 뒤에 빈 정간 8개가 더 있었으나 PDF에는 없어 정답에서 제외하고 원래 검수 파일의 해시와 제외한 정간 기록은 보존했다. 변환한 음·쉼의 종류, 시작·길이, 이벤트 ID와 QUARTER 박 단위는 운영 악보와 같다. 입력 JGB 원본 해시는 운영의 입력 해시와 다르다.

취타 고급도 사용자가 원본 28정간을 검수한 문서를 보존했다. 운영 악보와 비교하면 이벤트 49개와 59개로 다르다. 차이는 시김새가 있는 7정간 `c0-j3`, `c0-j6`, `c0-j11`, `c1-j3`, `c1-j6`, `c1-j10`, `c1-j11`에 모인다. 검수본의 시김새 자리가 운영에는 별도 음으로 표현되어 있다. 이는 두 데이터의 표현 차이를 확인한 것이며 운영 변환의 원인이나 채점 정답으로서 동등함을 입증하지 않는다.

기존 재생 가져오기 도구를 검수본에 실행하면 2각 11정간의 `느니르`에서 중단한다. 도구는 소금 교재의 설명과 예시의 기준음이 다르다고 알려 준다. 채점에서 사용할 표현을 결정하기 전까지 이 곡은 403의 운영 채점 계획에 넣지 않는다. 검토 기록의 `serviceComparison.approvedForScoring=false`는 보류 의사를 기록한 값이며, 기존 채점 켜기 도구가 자동으로 이를 검사하는 기능은 아니다.

2026-11-03 사용자가 각 번호를 표시한 원본 그림 5개를 확인하고 네 곡과 북천이 두 성부의 수정 숨표 위치가 모두 맞다고 응답했다. 수정된 칸의 확인 표시와 여섯 정답의 `reviewed`를 복구하고 사용자 확인자를 남겼다. 북천이 소금 1은 숨표 검수와 별개로 운영 악보와 음이 달라 채점 반영 보류다.
