# 단소 339 적재곡 채점 정답 검수와 채점 켜기 계획

관련 Task: `S15P31E102-404`. 계획·진행 기록은 [404 계획](../../plans/S15P31E102-404.md)이다. 2026-11-04에 S15P31E102-339가 운영에 적재한 단소 46곡(id 5~50)의 정답을 원본과 대조하고, 30곡의 채점 켜기 계획을 만들었다. 운영 적용은 같은 날 S15P31E102-433에서 했다(아래 "운영 적용").

## 결론

- **30곡을 채점 계획에 넣었다.** 각 곡의 정답이 운영 악보와 음·쉼 종류, 율명·옥타브, 시작·길이, 이벤트 ID, 시김새 유무, 박 단위(QUARTER)까지 같다. 계획은 [scoring-plans/danso.json](../../../infra/catalog/scoring-plans/danso.json)이다.
- **채점은 운영 악보의 음표로 한다.** 채점 켜기 도구 `enable_scoring.py`는 숨표와 검수 상태만 바꾸고 음표는 바꾸지 않는다. 그래서 운영 음표가 원본과 다른 곡은 켜지 않고 별도 Task로 넘겼다.
- **운영 악보에 원본 숨표가 많이 빠져 있었다.** 계획 30곡의 숨표 66개 중 43개는 원본에는 있고 운영에는 없던 것이다. 모두 각 끝, 율명 열 오른쪽에 있다(소금 403과 같은 규칙).
- **원본의 옥타브 표기는 `氵` 점 수로 구분한다.** 점 하나는 `청`, 둘은 `중청`이다. 원본 JGB 31곡의 율명은 모두 이 표기와 맞았다.

## 정답 파일

- 정답 31개(계획 30곡과 25번)는 `data/annotations/scores/<원본 ID>/`에 있다. 원본 ID는 표준악보집 `ngc-standard-2022-p<쪽>`, 국립국악원 실기교재 자료 번호 `ngc-silgi-2016-<번호>`, 교과서 연습곡 `school-textbook-danso-p14-exercise-<번호>`다. 새 원본 PDF 20개를 [원본 목록](../../../data/catalog/collected-scores/sources.json)에 넣었다.
- 검토 기록의 `serviceSong`이 운영 곡 id를 가리킨다. 이중주는 운영 30이 어이 얼어자리 단소2(`p183-part-2`), 31이 단소1(`p183-part-1`)이다.
- 입력 JGB는 노션 jgb 모음의 단소 사본이다. 운영의 `provenance.jgbSha256`과 같은 파일은 하나도 없어서, 바이트가 아닌 내용으로 대조했다. CRLF였던 5개는 저장소 규칙에 따라 LF로 바꾸고 `storedSha256`을 따로 적었다.
- 정간당 박은 운영 악보의 `ticksPerJeonggan / ticksPerBeat`를 그대로 썼다. 원본 악보의 박 해석은 따로 확인하지 않았다.

## 변환기 규칙

운영 재생 변환기(`data/src/playback/jgb.py`)와 맞추려고 정답 변환기 `score_data.py`에 두 규칙을 넣었다.

- `{빈지속}`·`{이음표}`·`{-}`를 따로 쓰면 `-`처럼 앞 소리를 잇는다. 다른 글자에 붙여 쓰면(`임{빈지속}`) 운영은 따로 한 자리로 떼지만 정답 변환기는 아직 그 규칙이 없어 멈춘다.
- `gakBeats`(`각:정간 수`)로 각마다 정간 수를 따로 정한다.
- 각 첫머리의 이음·빈 정간은 다른 각의 음을 잇지 못해 쉼이 된다. 원래 있던 규칙이며 운영도 같다.

## 검수 방법

- 개구리소리·구아리랑은 사용자가 검수 화면에서 전 정간을 대조했다. 고친 정간은 없다.
- 나머지 29곡은 사용자 지시로 AI가 먼저 검수했다. Sonnet 에이전트 7개가 원본 PDF 그림과 정간마다 대조했고, 주 세션이 지적한 곳을 그림으로 다시 확인했다. 사용자는 판단이 갈린 2건만 확인했다. 하나는 25의 음, 다른 하나는 26 북천이 단소2에도 10각 끝 숨표를 넣을지였다. 이 방식은 계획의 D-13이다.
- 검토 기록에 방법을 남겼다. `answerApproval.note`에 누가 어떻게 봤는지 적었다. AI가 넣은 숨표는 `breathCorrection.by: AI`이고, 사람이 정한 것만 `humanConfirmation`이 있다.
- 시김새 이름 가운데 그림만으로 확정하지 못한 것이 있다. 강원도아리랑·경복궁타령·고사리 끊자의 니레·노니로·노네·흘림표다. 이 이름들은 운영과 같고, 채점은 시김새가 있는지만 보므로 영향이 없다. 고사리 끊자·쾌지나칭칭나네는 원본 기호가 길게 내려오는 물결선이라 정답의 `풀어내림표`가 맞다. 운영의 `농음표`와는 이름만 다르다.

## 확인과 재현

- 운영 대조: 공개 곡 상세 `GET https://k15e102.p.ssafy.io/api/songs/{id}`의 `result.score`와 `convert_answer(<원본 ID>)` 결과를 이벤트마다 비교했다(대조 코드는 저장소 밖).
- 계획 검사: `python -m unittest discover -s infra/catalog -p "test_enable_scoring.py" -v`가 곡과 정답의 짝, 숨표, reviewed를 확인한다. 현재 해시는 운영 실행 때 맞지 않으면 쓰기 전에 멈춘다.
- 폐기용 MySQL 8.4.13: 공개 API로 읽은 30곡 악보를 넣고 실행했다. 결과는 읽기 검사 30곡 대기, `--apply` 30곡 적용, 다시 읽기에서 숨표 66·reviewed 30·채점 켜짐 30이었다. 재실행은 쓰지 않았고, 실행 사이에 바뀐 곡이 있으면 쓰기 전에 멈췄다. 읽기 검사 뒤 쓰기 직전에 한 곡(48)이 바뀌면 트랜잭션이 멈추고 앞선 29곡도 되돌아갔다(채점 켜짐 0).
- 독립 검토자가 공개 API로 해시·숨표·이벤트·제외 곡을 다시 맞춰 보았다(U6).
