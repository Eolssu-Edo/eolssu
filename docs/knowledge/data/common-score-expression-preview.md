## 원본과 수행의 구분

공통 v1의 이벤트는 이음 칸을 합치면서 `sigimsae`도 합친다. `청중{농음표}|-`와 `청중|-{농음표}`의 결과가 같으므로 원본 위치를 복원할 수 없다. v1 필드를 추가하면 strict JSON Schema와 FE decoder가 거부한다. BE/AI의 NOTE idx·음높이·기보 시각과 “시김새가 있는 음은 음정 채점 제외” 의미도 보존해야 한다.

따라서 원본 바이트와 v1은 그대로 두고 선택적인 표현 입력, 수행 시간표를 별도로 둔다. 표현 입력은 원본 SHA256으로 묶고 기호를 특정 표시 자리에 배치한다. 원본 기호와 다른 개수·누락·미지 필드·잘못된 위치는 오류다. 입력이 없으면 각 이벤트 첫 자리에 배치하고 `event-origin-inferred`로 기록한다. 이는 원본 위치 판독 완료를 뜻하지 않는다.

표시 자리는 정수 이벤트 틱보다 세밀할 수 있다. `청중 - -`는 하나의 1tick 이벤트지만 세 자리의 시작은 0,1/3,2/3tick이다. 수행 시간표는 분수 표시 위치와 실제 밀리초를 분리한다. 꾸밈음이 늘어나도 원본 eventId·noteIdx는 유지하고 실행 순서의 occurrenceId만 새로 만든다. 늘임과 반복 후에도 같은 원본 칸을 찾을 수 있다.

## 정책

`educational-preview/v1`을 선택한 경우에만 기본값을 채운다. 기존 JGB source 모드는 기존 미확정 거부를 유지한다. 이미 확정된 악기별 규칙은 새 기본값보다 우선한다. 단소의 니느라니는 [1,0,1,0], 정악대금·소금은 [1,0,-1,0]처럼 서로 다르다. 숫자는 반음이 아니라 선택 음계의 상대 단계다.

명시한 조/상대 음계가 없으면 교육용 황종계면 [0,3,5,7,10]을 쓴다. 원본 `hwangHz`로 조율하며 자동 악기 이조·옥타브 접기는 하지 않는다. 알려진 기호·별칭만 지원하며 오타와 서로 충돌하는 효과는 생략하지 않고 오류로 알린다.

| 미확정 기본값 | 교육용 선택 |
| --- | --- |
| 느니라 | 앞 꾸밈 [1,0,-1] |
| 노라느니 | 본음 자리 음열 [-1,-2,1,2] |
| 느네느 | 앞 꾸밈 [0,2], 기존 악기 규칙이 있으면 우선 |
| 나니르노니르 | 앞 꾸밈 [-1,1,-2,1], 기존 소금 규칙 우선 |
| 느나르나니/느니르나니 | [1,2,1,0,-1], 기존 단소·소금 규칙 우선 |
| 깊은/얕은 요성 | 4Hz, ±100/20cent |
| 하성/내림표 | 음 시작부터 길이 1/4 동안 200cent 하강 후 유지 |

다른 기존 기호에 대한 fallback과 실제 적용 숫자는 `source-map.json`의 `notation_policy`에 기호·악기·근거·음열·수치로 남긴다. 격음 전용 음색이나 국악기별 새 샘플을 확보한 것은 아니다. 깊은 요성 등 지속 효과는 이음 자리부터 지연 적용한다. 이음 자리의 새 음열·강세는 원본 본음 높이를 기준으로 새로 발음하고 그 근사를 기록한다. 강세·끊는표·겹친 곡선처럼 모순되는 조합은 자동으로 덮어쓰지 않는다.

빠르기 기호는 기존 정간 단위 계획을 사용한다. 정간 중간 표시 자리에 있어도 빠르기는 그 정간 시작부터 바뀌며, `placement_assumptions`에 원래 `written_position`과 실제 `effective_position`을 따로 기록한다. 예를 들어 한 정간의 두 번째 1/3 자리에 조금느리게가 붙으면 그 정간 전체가 기본의1.25배 길이가 된다. 이는 교육용 계획의 명시적 선택이며 시김새 곡선·음열의 시작 위치 처리와 구분한다.

## 입출력

실행 명령은 [재생 도구 README](../../../data/src/playback/README.md)를 따른다. 표현 파일의 최소 예는 다음과 같다. `sourceSha256`에는 원본 파일의 실제 바이트 SHA256이 필요하다.

```json
{
  "schema": "common-score-expressions/v1",
  "sourceSha256": "<원본 파일의 64자리 SHA256>",
  "placements": [
    {"eventId": "c0-j0-r0-u0", "cellId": "c0-j1", "row": 0, "col": 0, "symbols": ["깊은요성"]}
  ]
}
```

같은 이벤트의 기호 전체를 위치별로 한 번씩 배치한다. 원문 `니레@50,0,0`처럼 숫자 배치값을 가진 토큰은 원본 그대로 보존하고 기호명만 해석한다. 선택 필드 `jo`, `relativeScale`, `expressionPolicy`, `expressionProfile`은 기존 재생기의 명시 정책을 덮어쓴다. `performancePlan`은 기존 `<악기>-performance/v1` 형식이며 `input_sha256`에 같은 공통 원본 해시를 사용하고 BPM은 정간/분이다. 명시 계획을 주면 자동 반복·빠르기 계획을 대체한다.

출력 `performance.common.json`은 `common-score-performance/v1`이다. 원본 SHA256·scoreVersion·sourceId·instrument·BPM/단위와 실제 출력 음원 SHA256에 결합한다. `segments`는 모든 표시 자리의 occurrenceId/eventId/cellId/row/col, startTick/endTick, startMs/endMs, sigimsae다. 재생 시간 구간은 연속하며 기보 틱은 반복 시 뒤로 돌아간다. `durationMs`는 악보 종료이며 MIDI의 후행 약550ms는 포함하지 않는다. `source-map.json.events`의 target_hz/시각은 원래 본음·기보 기준이며 시김새가 펼쳐진 소리의 목록은 `expression_source_map`이다.

FE는 이 파일을 원본·음원에 맞춰 검증한 뒤 Model 모드에만 연결한다. 기존 녹음·채점 시간이나 Song의 기보 길이는 바꾸지 않는다. 서버 API/DB 게시 경로는 이번 범위에 포함하지 않는다.

검증 실행/결과·미실시 범위는 [Task338 계획](../../plans/S15P31E102-338.md)에 기록한다. 음열·길이·쉼·곡선의 수치 일치와 정석 연주 청감 평가는 구분한다.

### 2026-11-02 실행 결과

Python3.10.21, NumPy2.2.6, SoundFile0.14.0, FFmpeg/ffprobe9.0.2, 로컬 CAT 자산으로 WAV/AAC-LC를 생성했다. playback201개·data88개 자동 검사 통과. 독립 관측기는 재생 IR/MIDI/시간표를 기대값으로 읽지 않고 저장소의 수동 기대 fixture를 사용한다. 잘못된 반음·옥타브·쉼·음 분할·재발음·곡선·요성·강세를 거부하는 관측기 자체 검사10개도 통과했다.

| 실제 파형 | 결과 |
| --- | --- |
| 소금·정악대금·산조대금 WAV/AAC 6파일 | 각각40/40 검사 통과 |
| 단소 BPM60 WAV/AAC 2파일 | 각각39/40. 느니라 첫62.5ms 꾸밈의 초기25ms F0 관측창 실패 유지 |

단소 실패창에서 자기상관은 약474Hz, 최대 스펙트럼은 약943Hz이며 다음 창에서는 약934Hz로 일치했다(목표 약932Hz). 짧은 CAT attack의 복합 성분에서 관측 방법이 엇갈린다. 스펙트럼은 진단 정보로만 추가했으며 F0 임계값을 완화하거나 통과로 덮지 않았다. BPM60 해당 창의 주기적 F0 검증은 미해결 한계다. 강세는 일정한 음량 증가로 검사하지 않고 명시 velocity/CC11의 attack·중간·끝 세 구간 비율로 검사한다. 현재 정악/산조 CAT 자산이 같아 이 고정곡의 두 WAV도 동일하며 별도 음색 확보를 뜻하지 않는다.

Android17/API37 에뮬레이터에서 실제 공통 정간보·ModelAudioSession·AndroidAudioPlayer를 실행했다. 4악기 모두28개 수행 표시 자리를 관찰했고 늘임17초→기보16.5tick, 반복25초→기보20tick 복귀, 파일29.55초 종료→수행29초/100%를 확인했다. 녹음·채점 표시는 원래24초를 유지했다. 기존47개 glyph를 재사용하고 미보유 glyph는 이름으로 표시한다. 실제 기기 청취·전문가 연주 품질·운영 API/DI 게시·iOS 실기기 검증은 수행하지 않았다.

이 진단에서는 음원·정책을 임의로 수정하지 않았다. 실제 곡의 기보된 시김새를 사용한 대조, 동일 구간의 본음과 시김새 적용음을 분리한 청취 확인이 남아 있다. 아리랑 수치 검사 통과나 느린 BPM의 추가 검사는 이 파일에 대한 사용자 지적을 해소하지 않는다.
