## 조사표와 범위

[전체 근거표 CSV](score-tempo-audit.csv)와 [구조화 JSON](score-tempo-audit.json)은 **기존 정간보 장단 → 기존 정간보 빠르기 → 외부 정보 장단 → 외부 정보 빠르기** 순서다. 이후 열에 적용값·단위·정간/분·수정 또는 유지 이유·출처·PDF 해시·검토 범위를 기록했다.

기존 카탈로그 107판본 중 비행기 56번을 제외한 106판본을 조사했다. 다른 채팅에서 처리하는 신규 비행기 132·133·134번도 수정 대상에서 제외한다. 18판본을 교정하고 88판본은 유지한다. 교정 대상은 공개 17판본과 기존 숨김 1판본이다. 숨김 소금 아리랑 107번은 공개하지 않는다.

원본 JGB 107개와 변환 provenance의 해시를 대조했고, 107판본에 대응하는 PDF는 중복을 제외하면 101개다. 이번 직접 시각 검토는 25개 PDF·28행이다. 나머지 79행은 기존 조사 기록·원본 식별 정보·현재 악보와 대조했으며 모든 PDF를 이번에 다시 시각 검토한 것은 아니다. 원보 인쇄 빠르기와 `tempoBpm=60` 등의 JGB 편집값을 구분한다. 원보 수치를 확인하지 못한 곳에 편집값을 원전 지정 빠르기로 옮기지 않는다.

## 장단·박자·속도의 관계

장단을 정할 때 박 수와 소박 구조를 고려하되, 그것만으로 장단을 확정할 수는 없다. 굿거리와 자진모리처럼 같은 3소박 4박 구조를 쓰는 장단은 원보 명칭·구음/리듬형·한배·선율과 가사의 구절까지 비교한다. 각 정간이 큰박인지 소박인지도 판본별로 확인한다.

운영 `defaultBpm`의 단위는 4분음표다. 따라서 `정간/분 = BPM × ticksPerBeat ÷ ticksPerJeonggan`, `장단 길이(ms) = cycleTicks × 60000 ÷ BPM ÷ ticksPerBeat`로 환산한다. 예를 들어 굿거리의 점4분음표 66/분은 저장 BPM 99다. 12소박 정간판이면 198정간/분이고, 4큰박 정간판이면 66정간/분이다. 같은 BPM 숫자만 맞추거나 정간 수를 곧 박자로 취급하면 실제 재생 속도가 달라진다.

이번 변경은 실제 속도 변경 10판본, 실제 속도를 유지한 박 단위 표기 정정 7판본, 속도를 유지한 장단명 보완 1판본이다. 표기 정정 27·30·31·80·104·105·106번은 `이전 BPM × 이전 ticksPerBeat = 새 BPM × 새 ticksPerBeat`를 만족한다. 104·109번에 이미 적용된 699의 음표 교정 등 현재 악보의 선율·가사·시김새·이벤트 ID와 채점 가능 상태는 보존한다.

## 주요 판단과 출처

- 경복궁타령은 원보의 자진타령 명칭을 유지한다. [변미혜의 동일 악곡 장단 비교 연구](https://www.earticle.net/Article/A312037)의 자진타령·자진모리 한배 비교와 [국립국악원 자진모리 교육 범위](https://academy.gugak.go.kr/dp/pds/HTML5-1-7-3/HTML5-1-7-3-4/index.htm)를 참고해 점4분음표 108/분을 연습값으로 선택했다. 논문이나 원보가 이 곡의 숫자 108을 지정했다는 뜻은 아니다.
- 싸름은 [국립국악원 가창 악보](https://academy.gugak.go.kr/dp/pds/HTML5-2-3-4/HTML5-2-3-4-2/HTML5-2-3-4-2-4/44.jpg)의 선율·가사·음가와 [굿거리형 설명](https://encykorea.aks.ac.kr/Article/E0072817)을 대조한 비교 판본 추정이다. 다른 전승의 중모리·세마치를 같은 격자에 옮기지 않았다.
- 대금 뱃노래 기본·장식음판은 [대금교실](https://academy.gugak.go.kr/course/active/detail.do?courseActiveSeq=914)의 느린 호흡 연습 맥락을 가진다. [굿거리 교육 범위](https://academy.gugak.go.kr/dp/pds/HTML5-1-7-3/HTML5-1-7-3-2/index.htm)의 느린 쪽인 점4분음표 66/분으로 연습 기준을 보완했다. 기존 느린 속도가 원전과 달라 틀렸다고 단정하지 않는다.
- 대금 오나라는 [표준악보집](https://www.gugak.go.kr/userfiles/files/textbook_final.pdf)의 같은 곡 소금판 본문과 구절을 대조한 굿거리 추정이다. 목차와 본문의 장단명이 상충하므로 해당 악곡 본문을 우선했다. 각 경계 지속 문제는 기존 699 범위이며 이번에 음표를 수정하지 않았다.
- 한오백년은 [공식 공연 해설](https://www.gugak.go.kr/site/program/performance/detail?menuid=001001001001&performance_id=30008163)의 느린 중모리 근거로 장단명만 보완하고 60정간/분을 유지했다.
- 취타 세 판본은 원보의 12박 취타장단을 우선한다. [국악사전](https://www.gugak.go.kr/ency/topic/view/258)의 피리 정악보 55~72정간/분 범위에서 64를 소금 연습값으로 선택했다. 해당 소금 원보의 인쇄 BPM은 아니다.
- 정선아리랑은 현재 원보에서 장단명·숫자 빠르기·도중 변속 지시를 확인하지 못했다. 장단 미확인과 기존 60정간/분을 유지하며 다른 연주의 변박·변속 설명을 이 판본에 적용하지 않았다.

기존 승인표의 다른 속도는 유지했다. 새 카탈로그 미리듣기 기본값을 기존 악보에 일괄 덮어쓰지 않았다. 33판본은 최종 전통 장단명이 비어 있으며, 이 중에는 서양식 박자 편곡·기초 연습곡도 있다. 이 수치를 모두 조사 실패 또는 해결 완료로 해석하지 않는다. 온라인 근거 주소가 확인되지 않은 10·11·19·32·102·103번은 URL을 만들어 넣지 않았다.

## 운영 적용 결과

독립 검토에서 표현 companion을 바꾸고 렌더 없이 묶음을 만들 때 이전 렌더 결과를 포장할 수 있는 재실행 결함을 발견했다. 준비 도구가 companion 파일 SHA와 renderer manifest의 `configuration_sha256`를 비교하도록 수정했다. 실제 게시한 18개는 이미 모두 일치했다. 수정 도구로 18개를 다시 포장한 release가 게시본과 바이트 단위로 같으며, 변조/누락 companion은 거부되는 것을 확인했다.

2026-11-11 09:49 KST, 공개 17판본·숨김 1판본을 단일 트랜잭션으로 적용했다. 실제 게시한 `release-v2/release.json` SHA-256은 `942355081cbe9182fffea9270d1bd9c1a1a14058907bba97ffa23351b5d2e276`이다. 104·109번은 v2→v3, 나머지 16개는 v1→v2다. 악보·음원·수행 시간표 54개와 release 1개의 업로드 전체 GET 해시·MIME·만료 설정을 확인했다.

첫 적용은 운영 DB의 `chk_model_audio_object_key`가 숫자 폴더 경로를 거부해 전체 롤백됐다. 재조회에서 18개 모두 수정 전 상태를 확인했다. 기존 `cases/<악기>-<번호>-p<쪽>/` 경로 규칙에 맞춰 묶음을 다시 만들었고, 54개 파일의 바이트·해시는 그대로였다. DB 제약을 수정하거나 완화하지 않았다. 게시 도구에 해당 경로의 사전 검증을 추가했고 실제 V15 CHECK를 격리 MySQL 테스트에 적용해 실패·전체 롤백을 재현했다. 첫 묶음과 receipt는 진단 증거로 남겨두되 DB에서 사용하지 않는다.

최종 검증은 다음과 같다.

- 수정된 18개 DB 행이 목표 악보·BPM·판본·음원과 정확히 일치하고 재실행 대기 0개다. 비행기를 제외한 비대상 88개 곡 행과 이전의 모든 비행기 외 음원 행이 그대로다. 비행기에는 쓰기를 하지 않았다.
- 공개 17개 곡 목록·악보·음원 메타데이터·수행 파일의 판본/BPM/해시를 대조했다. 실제 서비스 음원 전체 GET 해시가 같고, Range `bytes=0-1023`가 206 및 같은 바이트를 반환했다. 모든 음표의 종류·율명/옥타브 식별자·정간 위치·tick을 이전 API와 대조했다.
- 숨김 107번은 목록에 없고 악보·음원·수행·재생 URL 모두 404다. 채점 가능 상태는 모든 대상에서 유지됐다.
- 반주 API 주기는 자진타령·자진모리 약 2.222초, 굿거리 약 3.636초, 한오백년 중모리 12초로 저장 BPM/격자와 일치했다. 취타는 기존 API의 자동 반주 지원 장단에 포함되지 않아 명칭·악보·모범 음원만 반영되며 새 장구 패턴을 만들지 않았다.
- 연습 요청 임시 차단·기존 요청 drain·활성 POST 0을 확인하고 적용했다. 완료 후 gate 파일을 제거하고 readiness 200, 인증 없는 연습 요청의 정상 401, 기존 backend route 해시 보존을 확인했다.
