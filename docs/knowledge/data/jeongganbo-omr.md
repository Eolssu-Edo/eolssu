# 정간보 OMR로 악보 PDF를 JSON으로 바꾸는 시험

관련 Task: `S15P31E102-114`. 2026-10-26에 공개 정간보 OMR 모델로 팀이 모은 e-국악아카데미 교실 악보 2쪽을 읽고, 우물사이 문서(`.jgb.json`)로 바꿨다.

## 결론

- **변환 경로는 동작한다.** PDF 쪽 → OMR → JG-like 텍스트 → 우물사이 `.jgb.json`까지 한 번에 이어진다. 1쪽 처리는 CPU에서 약 14초다.
- **단소 아리랑(굵은 명조 한자 악보)은 쓸 만하다.** 정간 48칸 중 39칸을 깨끗하게 잘랐고, 그 39칸의 율명·위치는 모두 맞았다.
- **잘못 자른 칸 때문에 각이 밀린다.** 두 칸이 한 상자로 합쳐지거나 한 칸이 빠지면 그 뒤 정간이 모두 앞으로 당겨져 각 구분이 틀어진다. 결과를 그대로 쓰지 못하고 사람이 잘린 칸을 확인해야 한다.
- **글꼴·선 굵기가 다르면 크게 떨어진다.** 대금 교실 3차시(가는 고딕풍 한자, 연한 회색 선)는 28칸 중 12칸만 깨끗하게 잘랐고, 그중 음이 있는 7칸에서 2칸만 맞았다.
- **판단: 일부만 쓴다.** 국악원 정악보와 모양이 같은 악보는 OMR로 초안을 만들고 잘린 칸만 사람이 고친다. 모양이 다른 악보는 우물사이에 손으로 입력한다. 모델 재학습은 하지 않는다.

## 도구와 버전

| 도구 | 버전 | 쓴 부분 |
| --- | --- | --- |
| [MALerLab/jeongganbo-omr](https://github.com/MALerLab/jeongganbo-omr) | `e95045f`, 체크포인트 릴리스 v1.0.0(`checkpoints.tar.gz` 67.8MB) | 정간 자르기(`JeongganboReader`)와 정간 인식 모델. MIT |
| [jeongganbo-generator](https://github.com/danbinaerinHan/jeongganbo-generator) | `9d4a24e` | `tools/import-ngc-omr.mjs`로 JG-like 텍스트 → `.jgb.json`. MIT |
| Python | 3.12, torch 2.14.1 CPU, x-transformers 1.30.20, opencv-contrib 5.0.0, pdfplumber | 원래 요구는 Python 3.8·torch 2.0.1이지만 3.12에서 동작했다 |
| Node | 24.18.0 | 변환 스크립트 |

OMR 원래 코드에서 바꿔야 했던 것:

- **체크포인트 이름**: 공개 체크포인트는 옛 x-transformers의 LayerNorm 이름(`gamma`·`beta`)으로 저장돼 있어 Pipfile에 고정된 1.30.20에서도 그대로 읽히지 않는다. `beta`가 모두 0이라 `gamma`를 `weight`로 바꾸고 `beta`를 버렸다. 계산은 같다.
- **해상도**: 리더의 정간 크기 기준(너비 85~110px, 높이 66~320px)이 국악원 악보집 300dpi에 맞춰져 있다. 교실 악보를 300dpi로 그리면 정간이 너무 커서 하나도 못 찾는다. 150dpi로 그려 정간 너비를 약 95px로 맞췄다.
- **읽는 순서와 각**: 교실 악보는 한 열에 각 네 개가 간격 없이 이어져 리더가 각을 나누지 못한다. 상자를 열(오른쪽부터)·행(위부터) 순서로 다시 세우고, 각은 장단의 정간 수(세마치 3)로 나눴다.
- **정간 전체 음**: 모델은 가운데 음 하나를 위치 `5`로 내지만 데이터셋 표기는 정간 전체 `0`이다. 이 경우만 `0`으로 바꿨다.

## 결과

### 단소 아리랑 (`ngc-easy-danso-06`, 1쪽)

경기도 민요, 세마치 3정간. 4열 × 각 4개 = 16각 48정간이다. 사람이 PDF를 보고 맞춘 정답(오른쪽 열부터, 각은 `/`로 구분):

```text
1열: 중 | -임 | 중임 / 무 | -청황 | 무청황 / 청태 | 청황청태 | 무임 / 중 | -임 | 중임
2열: 무 | -청황 | 무청황 / 청태청황 | 무임 | 중임 / 무 | -청황 | 무 / 무 | (빈칸) | 쉼표
3열: 청중 | (빈칸) | 청중 / 청중 | 청태 | 청황 / 청태 | 청황청태 | 무임 / 중 | -임 | 중임
4열: 무 | -청황 | 무청황 / 청태청황 | 무임 | 중임 / 무 | -청황 | 무 / 무 | (빈칸) | 쉼표
```

| 항목 | 값 |
| --- | --- |
| 찾은 상자 | 43개 |
| 깨끗하게 자른 정간 | 39 / 48 (81%) |
| 두 칸이 한 상자로 합쳐짐 | 4곳(8칸). 모두 둘째 각의 1·2정간 사이 가로선이 다른 선보다 가늘다 |
| 못 찾은 정간 | 1칸(3열 둘째 각 3정간). 국립국악원 워터마크가 정간 선 위에 겹친다 |
| 깨끗한 칸의 율명·위치 | 39 / 39 맞음. 음이 있는 36칸과 빈칸 3칸 모두 |
| 변환 검증 | `import-ngc-omr.mjs --verify` 정간 칸 나눔 43/43 일치. 경고 "한 행에 통째+반칸" 2곳은 합쳐진 상자 |

합쳐진 상자는 두 정간의 음을 한 정간 안의 위치로 읽는다(예: `무 / -청황` → `:2 무 :4 - :5 - :6 - :8 청황`). 상자가 48개가 아니라 43개라서 첫 합쳐진 곳 뒤로 각 구분이 모두 밀렸다.

### 대금 교실 3차시 (`ngc-easy-daegeum-03`, 1쪽)

같은 e-국악아카데미 시리즈지만 글꼴이 가는 고딕풍 한자이고 정간 선이 연한 회색이다. 7열 × 4정간 = 28정간.

| 항목 | 값 |
| --- | --- |
| 깨끗하게 자른 정간 | 12 / 28 (43%). 찾은 열마다 가운데 두 칸이 합쳐지고, 오른쪽에서 다섯째 열은 통째로 못 찾았다 |
| 깨끗한 칸 중 음이 있는 칸 | 2 / 7 맞음. `㳞`(청중)을 청남·청황으로, `潢`(청황)을 퇴성으로, `汰`(청태)를 응으로 읽었다 |
| 깨끗한 빈칸 | 5 / 5 맞음 |

## 판단 근거

- 아리랑 쪽은 국악원 정악보처럼 굵은 명조 한자와 진한 선을 써서 모델이 학습한 모양과 가깝다. 대금 3차시는 글꼴과 선이 달라 인식과 자르기가 함께 무너졌다. 같은 출처라도 차시마다 판형이 다르므로 악보마다 1쪽을 먼저 돌려 본다.
- 칸 자르기 실패는 모두 가는 선·워터마크에서 생겼다. 상자 그림(`boxes.png`)을 보면 사람이 1분 안에 찾을 수 있다. 칸 수가 장단 × 각 수와 다르면 자르기 실패로 본다.
- 정답 대조는 1쪽씩이라 정확도 숫자는 작은 표본이다. 전체 단소 악보를 돌리기 전에 판형이 다른 악보를 몇 쪽 더 시험한다.

## 이용 조건과 미확인 사항

- 두 PDF 모두 바닥글에 "개인 학습용으로만 활용", "무단 복제·전재 및 배포는 삼가"라고 적혀 있다. OMR로 만든 텍스트·JSON도 이 악보의 내용을 옮긴 것이므로 서비스 데이터로 쓸지는 팀이 정한다.
- OMR 모델·변환 코드는 MIT다. 국악원 정악보를 OMR로 읽은 공개 데이터셋(`jeongganbo-dataset`)은 CC BY-NC-SA 4.0으로 별개 조건이다.
- 시김새는 이 두 쪽에 거의 없어 시김새 인식은 확인하지 못했다.
- 교과서 악보(`textbook-final` 등)의 단소 쪽은 시험하지 않았다.
