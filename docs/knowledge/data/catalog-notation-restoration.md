# 카탈로그 공통 악보와 JGB 대조

2026-11-04 공개 곡 목록·상세 API의 107곡(단소 46, 소금 23, 정악대금 28, 산조대금 10)과 V6 초기 시드 4곡을 확인했다. 공개곡은 `provenance.jgbSha256`으로 로컬 재생용 JGB를 찾았다. 시드는 저장소에 있는 정답 JGB와 맞췄다. 전체 111곡이 원본 해시, 성부 및 각별 정간 수 검사에 통과했다. 공개 API 범위 밖의 운영 행은 이 결과에 포함하지 않는다. 1~4번은 시드 스냅샷 기준이다.

정간 가사는 67곡(공개 63곡과 초기 시드 4곡)에서 2,931정간을 복원했다. 원보 비교에서 부제, 각 이름, 겹줄, 대강 묶음, 장단 구음의 차이도 확인했다. 이번 복원 범위는 정간 가사다.

공개 105곡은 기존 재생 가져오기 도구로 다시 읽었다. 각·정간·표시 단위, 조율·시간축과 시김새 이벤트는 운영 응답과 같았다. 83곡은 이벤트 전체가 일치했다. 22곡에는 재생용 JGB에 없고 운영에만 있는 숨표 85개가 있었다. 반대 방향 차이는 없었다. [운영 단소 검수](danso-loaded-scores.md)와 [소금 정답 검수](sogeum-scores-review.md)에 따라 운영 숨표를 보존했다.

감사 도중 S15P31E102-476이 단소 5곡의 운영판을 변경해 상세 API를 다시 읽었다. 버전 2가 된 25·44번은 검수 JGB와 정답 변환기로 다시 대조했다. 각·정간·이벤트가 일치했고 황종 표기만 311.13Hz와 311.1269837220809Hz로 달랐다. 운영의 값을 보존했다. 44번의 시김새 9곳을 검수 JGB의 위치대로 표현 JSON에 연결했다. 공개 107곡을 다시 읽어 복원 기준본과 같음을 확인했다.

일부 JGB의 독립 시김새는 재생 가져오기에서 구체 음으로 펼친다. 붙임줄, 조 정보와 각 경계 지속처럼 공통 본문과 별도로 쓰는 연주 표현은 공통 파일 해시에 연결한 표현 JSON에 보존했다. 공개 107곡 모두 원본 JGB를 읽지 않는 공통 재생 변환으로 복원 전후 같은 음 이벤트와 빠르기를 냈다. 글꼴, 종이 크기, 편집기 패널 상태는 원본 자료에 보관한다.

## 복원본과 검증

로컬의 `data/processed/scores/catalog-477/`에 곡 ID별 복원 전 `baseline/`, 복원본 `common/`, 공통 표현 `expressions/`, 기본 BPM과 SHA-256을 담은 `manifest.json`을 보관했다. 원본 또는 가사의 공개 이용 조건을 확인하기 전까지 이 파일들은 로컬에서 검증에 사용한다.

```powershell
python data/src/scores/restore_catalog_lyrics.py <현재-공통-악보.json> <해시가-일치하는.jgb.json> --out <복원본.json>
```

복원기는 해시, 성부, 정간 위치와 기존 선택 필드의 충돌을 검사한다. 결과는 새 파일에 쓴다. 111곡 모두 JSON Schema 검사 및 같은 원본으로 재실행했을 때의 결과 일치 검사를 통과했고, 이벤트·음표 순서·타이밍·악보 버전을 보존했다. Android 호스트 테스트에서 복원 전후 111곡을 실제 공통 악보 파서로 읽고 앱 타임라인 일치를 확인했다. 데이터 테스트 170개와 재생 테스트 223개가 통과했고 재생 테스트 2개가 건너뛰어졌다. 복원 CLI에서 다른 원본 해시를 거부하고 기존 출력 파일을 보존하는 것도 확인했다.

운영 적용 전 곡별 가사 이용 조건을 확인한다. 구버전 앱은 모르는 필드가 들어오면 악보를 읽지 못하므로 새 응답의 호환 조건을 먼저 갖춘다. 적용할 때는 최신 DB에서 곡 ID·판본·기존 JSON이 기준본과 같은 행만 골라 변경하고, 적용 후 공개 상세 API와 앱에서 가사·기존 타임라인을 확인한다.
