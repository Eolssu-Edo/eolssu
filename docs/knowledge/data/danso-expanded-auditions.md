## 확인한 원보 차이와 전사

고사리·싸름·쾌지나·한오백년·청어·정선의 `{풀어내림표}`21개는 연결 PDF에서 농음 글리프였다. 실제 풀어내림을 농음으로 일반 치환한 것이 아니라, 각 칸의 원본 해시·전후 문자열·PDF를 확인한 교정이다. 청어4각1정간의 청협→청태, 한오백년6각3정간의 중청황청중→청임청중도 원보와 대조했다. 한오백년의 prefix 노니로4곳은 첫 본음에 연결했다.

싸름의 긴 농음선2개는 정간의3분박 전체에 걸쳐 있어 같은 범위의 본음에 효과를 전개했다. 천안삼거리의 너녜2곳은 다음 청황에 연결하고, 한 쪽 PDF의24정간 뒤에 JSON에만 추가된 마지막1정간을 파생본에서 제거했다. 원본의 추가칸과 `gakBeats=7:1`은 교정 기록에 남겼다.

진도아리랑은 연결된 단소 PDF의16각48정간을 직접 전사했다. 황종63과 기존105의 조율 기준에서 MIDI77~85이며 자동 이조하지 않았다. 청성곡은 PDF에 수록된 **단소 오선보2줄**만 전사했다. 하단 대금보는 포함하지 않았고8va를 한 번 반영해 MIDI68~85를 사용했다. 전곡이라는 주장을 하지 않는다. 전사 위치·음가·붙임줄·꾸밈은 별도 `transcription-map.json`에 있다.

단소 대분류에 속한 `instrument=all`은 파생본에서 단소로 명시했다. 상대음이 필요한 `joPreset=all` 입력 중 원음에 다섯 음급 `[0,2,5,7,10]`이 모두 나타난10파일만 이 음급 집합을 계산에 사용했다. 이는 원보의 조를 확정하는 판정이 아니다. 입력 악기가 다르거나 음계 근거가 부족하면 자동 이조·생략하지 않는다.

## 검증과 재현

실행은 [CLI 안내](../../../data/src/playback/README.md#근거를-기록한-단소-일괄-변환)를 따른다. 41항목47파일을 실제 CAT 단소 샘플로 생성했다. 기존4800 PPQN으로 표현할 수 없던 정선의1/18 quarter를 정확히 기록하도록14400 PPQN을 사용한다. 예전 그리드도 모두 표현할 수 있으며 BPM과 정간 길이는 유지한다.

Python3.12의 격리 검사54개가 통과했다. 숨의 실제 WAV 무음, 다음 시작시각, CC72 복구, 지속 위 농음 시작, 농음·흘림의 음높이/시간 보존, 길이 기호의 합, nested triplet, 원본 교정의 정확 일치와 출력 경로 충돌을 포함한다. 실제47음원의3057음, 숨69곳·농음37음·흘림32음을 생성하고 원본·파생·MIDI·WAV 해시, 대응표, PCM 유한값·무클리핑을 검증했다. 결과는 출력의 `verification.json`에 있다.

기존17음원과 비교해1004음의 음높이열·velocity·BPM·시작 위치와 WAV 샘플 수가 일치했다.28곳의 종료 차이는 PPQN 양자화로 최대0.0331ms다.6곳은 새 숨 정책에 따라 공백을 줄였다(개구리4/12, 구아리랑10/3, 도라지3/3·11/3·19/3·23/3). 다음 음 시작·전체길이는 유지했다. 합성 성공·전사 대조를 국악 전문가의 연주 품질 승인으로 확대하지 않는다.

2026-10-28 추가 점검에서는 파일 읽기·UTF-8 디코딩·JSON 파싱을 항목별 오류 처리에 포함했다. 잘린 JSON, 잘못된 인코딩, 객체가 아닌 JSON, 없는 파일은 해당 항목만 보류하고 다음 곡을 처리한다. 읽을 수 있었던 원본 바이트는 오류가 있어도 보존한다. 네 실패 사례 뒤의 정상 곡 처리·최종manifest/index 생성·원본 불변을 확인하는 회귀 검사를 추가해 총55개 검사가 통과했다. 카탈로그 자체와 입력/출력 경로 충돌은 개별 곡 처리 전에 검증한다.

## 강원도아리랑 원보·JSON·WAV·실연 대조

2026-10-28, 같은 Task166의 후속 조사다. 대상은 국립국악원 단소 PDF `강원도아리랑_정간보_단소_국악원-18705.pdf`, 원본 `강원도아리랑.jgb.json`, 파생 `prepared/001.jgb.json`, 생성 `tracks/001-p1/danso.wav`, [느루의 단소 강원도아리랑](https://www.youtube.com/watch?v=XwskMGMBZFo)이다. 원보·생성물은 기존 `data/processed/playback/166-listen/` 아래에 있으며 상세 측정 자료는 같은 경로의 `comparisons/gangwon/`에 보존한다. 조사 때문에 원본이나 재생 정책을 변경하지 않았다.

### 원보와 생성물

- PDF의 8각×10정간을 독립적으로 전사해 원본·파생 JSON과 대조했다. 율명75개, 빈 지속11정간, 쉼2정간, 한 칸 두 음8곳이 일치했다. 니레는1각9·3각4, 노니로는2각5·6각5에 모두 보존돼 있으며, 꾸밈6음을 더하면 MIDI 발음은81개다. 숨표·농음·흘림은 원보에도 없다.
- PDF에는 숫자 BPM과 서양식 절대 조율 지시가 없다. 190정간/분은 엇모리의 공식 빠르기 범위에서 선택한 생성값이며, 해당 영상의 연주 속도를 측정해 정했던 값이 아니다.
- MIDI81음의 음높이·시작·끝은 생성 이벤트와100μs 이내로 일치했다. WAV의 안정된 구간에서도 MIDI77·80·82·85·87·89에 해당하는 기본주파수를 확인했다. 반음·옥타브 변환 오류는 관측하지 못했다.
- 악보 시간은 `80×60/190=25.263초`이고 WAV는25.813초다. 마지막0.55초는 종료 여유다. 이 곡에는 숨표가 없어 가변 숨 정책이 차이를 만들지 않는다.

### 영상과의 차이

영상 설명은 Gb→Cb→Db의 세 버전을 명시한다. 공개 영상 음성의 기본주파수를 자동 추정하고 주요 차이는 별도 FFT로 확인했다. 아래 시각은 반주·잔향을 포함한 측정의 근사값이다.

| 영상 구간 | 첫음의 명목 음높이 | 우리 WAV와의 관계 |
| --- | --- | --- |
| 약10.75~30.75초, Gb | B♭4, MIDI70 | 우리 첫음이7반음 높음 |
| 약35.75~55.75초, Cb | E♭5, MIDI75 | 우리 첫음이2반음 높음 |
| 약60.75~80.75초, Db | F5, MIDI77 | 우리 첫음과 같은 명목 음높이 |

서양 조 이름과 황종 기준음은 서로 다른 개념이므로 `Db`와 `hwangPitch=63(E♭4)`를 단순 비교해 이조량을 계산하지 않는다. 영상은 약240정간/분으로 정렬되며80정간이 약20초다. 우리190정간/분보다 약26% 빠르다. 239.9라는 정렬 최적값은 정확한 메트로놈 설정을 증명하지 않는다.

같은 높이의 세 번째 버전에서도 음형·음가 차이가 있다.

- 원보2각7~9정간은 F5를 지속하지만, 영상 약65.03~65.28초에 Ab5가 나타난 뒤 F5로 돌아온다. 원보6각의 반복 자리에서도 약75.02~75.27초에 같은 차이가 나타난다. 약1정간 길이의 차이이며 독립 FFT에서도 약837Hz를 확인했다.
- 원보3각6~8정간은 E♭6–D♭6–E♭6–D♭6이지만, 영상 약66.98~67.42초에는 E♭6이 길게 유지된다. 원보7각의 반복 자리에서도 약76.97~77.43초에 같은 양상이 나타난다.

이는 원보와 다른 연주 음형·음가가 관측됐다는 뜻이다. 연주자가 우리가 확보한 PDF를 보고 표현을 추가했는지, 다른 판본을 사용했는지는 확인되지 않았다. 특정 시김새 이름이나 오연주·오전사라고 단정하지 않는다. 같은 음을 여러 번 부는 타격 횟수는 기본주파수만으로 확정하지 못하며, 전체 음표 일치율을 정확도 점수로 제시하지 않는다.

### 현 재생 정책의 한계

본음의 정간 시간은 올바르지만, 꾸밈은 고정 `1/16 quarter`라서 `staffUnit=auto→dotted`, 내부quarter BPM285에서 각각13.16ms가 된다. 카탈로그의8분음표 기준으로 내부 단위를 통일하면39.47ms가 되지만, 어느 값도 이 실연의 꾸밈 길이로 검증된 값은 아니다. 일반적인16분음표(`1/4 quarter`)와 코드의 `1/16 quarter`를 혼동하지 않는다. 내부 단위에 따라 꾸밈의 실제 시간이 달라지는 점은 개선 검토 대상이다.

[우물사이 고정 커밋의 원본 재생 코드](https://github.com/danbinaerinHan/jeongganbo-generator/blob/9d4a24e54bf36093d4d264d0271d214500d36db7/js/app.js#L6314-L6318)는 `min(90ms, 자리 길이×30%/꾸밈 수)`를 쓴다. 우리105·166의 재생 관례와 다르며, 원본 앱의 수치도 공인 연주 표준이라는 뜻은 아니다. 현재13ms 꾸밈은20ms 연결 envelope보다 짧고 첫 샘플 attack의 진폭도 작아서 약하게 들리거나 섞일 가능성이 있다.

긴 음4개에는 악보의 농음 표시 없이도 기존105의 자동 ±25cent 떨림이 들어가며, WAV에서 실제 적용을 확인했다. 고정 음량·샘플 연결·음색 역시 실연의 호흡·강약·발음을 그대로 재현하는 모델이 아니다. 따라서 원보→JSON→MIDI→WAV의 데이터 일치와 특정 실연의 재현 품질은 별도로 검증해야 한다.

원보 SHA256 `63b40692a485409b162c596151a437440c574cf3cb336ac5ec9536bdd0ec5926`, 원본 JSON `0bc7f6200282ebb04317d62da7d862b351de2f1aa5a8c78b9781eb3dbe02d99d`, 파생 JSON `94431afe76841a2c025c7dd63d60845d7e2c854544b43d437ede573ab29d4245`, WAV `962d41469567733fdbd6ed6de150f62986050a5491eff2076a087f4fc0365662`로 입력을 식별한다. 측정법·수치·음표 위치는 `comparisons/gangwon/`의 PDF 대조표·WAV 측정 보고서·영상 비교 요약에 기록했다. 영상 원본 음성은 분석용 임시 파일로만 사용하고 결과물에 재배포하지 않는다.

### 두 곡 시간 그래프

사용자 요청으로 강원도아리랑(`001-p1`,25.813초)과 개구리소리(`002-p1`,18.732초)의 생성WAV만 시각화했다. `comparisons/time-graphs/`에 PNG·SVG 두 쌍, 입력 해시가 있는 `graphs.json`, 측정 `plot-data.json`·CSV, `extract_pitch.py`·`render.py`를 보존한다. 소리 크기는20ms 창의 최대·최소 진폭과 RMS, 음높이는80ms Hann FFT·자기상관의 기본주파수 추정이며10ms 간격으로 표시한다. 실제 MIDI의 기준음높이를 겹쳤다. MIDI음높이로 탐색 대역을 제한하거나 맞지 않는 음높이를 지우지 않았다. MIDI음 경계는 쉼·전환부 제외에만 사용했다. 강한2배음은 스펙트럼·자기상관으로 보정했고, 무음·짧은 꾸밈·낮은 신뢰도는 선을 잇지 않았다. 전체 파형 그래프에서 빠진 음높이 점이 발음 누락을 의미하지는 않는다.

그래프 두 장의 글자·축·범례·공백을 렌더 후 확인했다. 입력WAV는 변경하지 않았다. 각 파일의 디지털 정규화가 독립적이므로 세로축의 크기를 실제 연주자의 음압·강약으로 해석하지 않는다. Python3.12와 NumPy로 추출하고 분석용 임시 폴더에 설치한 Matplotlib3.11.2로 렌더했다. 렌더는 해당 폴더의 `plot-data.json`을 읽으며 프로젝트의 런타임 의존성은 변경하지 않았다.
