# QA APK의 MR 정보 자동 반영과 기기별 최신 설치

2026-11-05 · S15P31E102-498 · 운영 적용 완료. 2026-11-05 독립 명세·규칙 리뷰에서 기기 ID 고정과 logout 쿠키를 보완한 뒤 해당 범위를 재검토했다.

## 선택과 근거

EDO1의 원본 `/opt/eolssu/apks/index.json`에 있는 MR 번호에 한해서 실제 GitLab MR 작성자와 제목을 조회한다. 같은 index의 `mergeRequestDetails`를 두 Windows 미러가 가져가 공통 UI에서 표시한다. Jenkins 게시 흐름을 더 묶지 않고 별도1분 타이머를 선택해 API 장애가 APK 빌드를 실패시키지 않도록 했다. 원래 공통 소스/기기별 중계 구조는 유지했다.

GitLab 프로젝트 전용 토큰은 Reporter/read_api만 부여했다. [GitLab 프로젝트 토큰](https://docs.gitlab.com/user/project/settings/project_access_tokens/)의 역할·scope 조합에 따라 접근 범위를 제한한다. 실제 생성본 만료일은2027-07-31이며 기존 checkout 자격은 수정하지 않았다. root 전용0600 원본을 [systemd LoadCredential](https://systemd.io/CREDENTIALS/)로 서비스에 전달한다. 토큰을 환경변수/명령 인수/로그/원본 저장소에 넣지 않는다.

## 실제 결과와 범위

기존 수동 상세 정보78개에서 새2개를 포함한80개를 자동 조회했고, 두 페이지에서 MR !333/송가연/실제 MR 제목을 확인했다. 두 페이지의 버튼으로 Android 빌드#96을 설치했다. 태블릿12:25:52 KST, 휴대폰12:26:11 KST; versionCode1793847399, `qa-20261105.025639-85a9f6d0`. 태블릿 설치 중 휴대폰 홈 조작이 유지됐다. 제품 앱 녹음·AI 평가는 범위에 포함하지 않았다.

첫 영상 그림 없이 heartbeat만 수신하는 대기는6초 후 기존 이미지 복구를 허용하고 이미 그려진 정지 화면은 유지한다. 이 분기는 가짜 시계의 감시 동작으로 실패/통과를 확인했다. 실제 설치 후 새로고침의 두 기기 영상 표시도 확인했다. 기기 인코더/GOP가 관측한 대기의 원인이라고 단정하지 않는다.

최신 버튼은 성공하여 **보관된 APK 중 최신**을 설치한다. 아직 빌드되지 않은 develop SHA를 즉시 빌드하는 버튼이 아니다. MR 수집 약1분, Windows 동기화 약1분과 웹 조회 약5초·다운로드 시간이 필요하다. API 실패·토큰 만료 시 기존 정보는 보존되고 새 상세 정보는 확인 중으로 남으므로 운영자가 타이머 상태와 자격을 점검한다.
