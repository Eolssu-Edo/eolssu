# edo1 서비스 준비 상태 검사

[S15P31E102-665](https://ssafy.atlassian.net/browse/S15P31E102-665) · [기존 점검 메시지 기준](mattermost-inspection-messages.md)

| 대상 | 수집 근거 | 성공한 검사의 범위 |
| --- | --- | --- |
| 블로그 편집기 두 종 | 허용 Origin으로 내부 `GET /config`의 HTTP 200, CORS, OAuth 설정 확인. 쓰기 편집기는 `canBatch: true`도 확인 | 로그인·일괄 반영 설정 응답. 실제 OAuth 로그인·DB 접근·글 반영은 별도 |
| phpMyAdmin | loopback `GET /`의 HTTP 200과 phpMyAdmin 로그인 양식 확인 | 로그인 화면 응답. MySQL 인증·쿼리는 별도 |
| 리뷰 봇 터널 | 내부 Cloudflared `GET /ready`의 상태와 활성 엣지 연결 수 확인 | 터널 연결. 웹훅·원본 서비스 트래픽은 별도 |
| 연주 분석 AI | 내부 `POST /v1/analyses`에 필수 필드가 없는 빈 JSON을 보내 HTTP 422와 검증 오류 확인 | HTTP 통신. 기대 응답을 받으면 통신 정상으로 표시하며 음원 처리·추론·채점은 검사 범위 밖이다 |
| MySQL 복제 프록시 | Docker 포트 매핑 및 호스트에서 `ss`로 loopback 수신 소켓 확인 | 로컬 수신 정상으로 표시. 복제 통신은 연결 출발지의 `/edo2-health`에서 판정 |

Docker 중지·일시정지·비정상 검사는 기존 판정을 우선한다. 실행 상태와 검사 경로를 확인한 뒤 고정 로컬 대상으로만 검사한다. 검사 경로나 로컬 수집 수단을 확인할 수 없으면 확인 불가, 확인된 경로에서 기대 응답이 없거나 실패 응답이 오면 실패로 판정한다. 응답 본문·쿠키·자격 증명은 보고에 담지 않는다.

컨테이너 사실의 선택 필드 `readiness`는 기존 edo2 대기 웹과 동일한 `[판정, 근거, 소요]` 배열이다. 판정은 `정상`, `실패`, `확인 불가`, `미검증` 중 하나다. `null`이면 별도 검사 결과가 없다. `/edo1-health`는 이 세 값을 서비스 검사 행에도 사용한다. AI HTTP 검사 결과에는 선택 필드 `readiness_kind: "http_communication"`을 함께 제공한다. 이 유형의 `정상`만 통신 정상으로 표시한다. 복제 프록시의 로컬 소켓 검사는 `readiness_kind: "tcp_listener"`로 구분한다.

edo1 상태 표에서 준비 검사 성공은 `검증 완료`, AI HTTP 통신 성공은 `통신 정상`, 복제 프록시의 소켓 수신 확인은 `로컬 수신 정상`으로 표시한다. 각 행에 검사 방식과 근거를 함께 표시한다. 요약·집계는 기존 내부 판정을 사용한다. 실패·미측정·미검증은 상세 행에 그대로 표시한다. 이 검사는 관측된 컨테이너에 적용하며, edo1의 복제 프록시 컨테이너가 누락되면 실패로 표시한다. Cloudflared 기본 포트의 응답을 확보하지 못하면 확인 불가이며, 받은 HTTP 503은 실패다.

## edo2 복제 통신 판정

`/edo2-health`의 복제 감시 행은 실행 중인 기존 `eolssu-replication-watch.timer`와 최근 `eolssu-replication-watch.service` 완료 결과를 읽는다. 감시는 20초 주기, 1초 타이머 정확도, 최대 실행 8초이며 복제 원본·수신·적용과 적용 지연 10초 이하를 확인한다. 종료 이후 45초 이내의 성공만 `복제 통신 정상`으로 표시한다. 결과 시각은 같은 호스트의 단조 시계로 비교한다.

감시 실행·예약 실패는 장애, 유효 시간이 지난 성공은 주의, 완료 이력 없음·실행 중은 미검증, systemd 조회 실패·불완전한 결과는 미측정으로 표시한다. edo1 프록시에서 확인한 소켓 수신의 성공·실패는 해당 호스트의 로컬 검사로 집계한다.
