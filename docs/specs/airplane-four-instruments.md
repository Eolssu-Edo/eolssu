# 비행기 네 악기 악보·CAT 음원·단모리 연결

- 작업: [S15P31E102-707](https://ssafy.atlassian.net/browse/S15P31E102-707), Story S15P31E102-26.
- 2026-11-11 사용자의 Jira·코드·MR 분리 요청에 따라 기존 MR !576에서 데이터와 단모리 연결만 분리한다.

## 동작과 범위

단소 132·소금 133·산조대금 134는 기존 v1의 음표·식별자·시간축과 CAT77 연결을 유지한다. 정악대금 56의 검토 입력은 기존 25음·이벤트 ID·tick·정간·숨표를 보존하고 정간당 1박을 나타내는 v2(`ticksPerBeat=6`)다. 정악대금은 새 곡 ID로 중복 등록하지 않는다.

네 악기 모두 기존 악보 → MIDI → CAT 경로를 사용한다. 장단은 기존 카탈로그 단모리 7의 8소박·4분음표 4박을 77 BPM 연습 반주로 연결한다. 원보에 전통 장단이나 수치 빠르기가 인쇄됐다는 뜻은 아니다. 새 장단이나 단음 녹음을 조합하는 별도 생성 경로를 추가하지 않는다.

보충 장단은 검토한 sourceId·악기·JGB 해시·판본이 모두 맞을 때만 연결한다. 단소·소금·산조대금 v1은 4tick을 8소박으로 나누고, 정악대금 v2는 24tick을 8소박으로 나눈다. 기존 앱의 Double 시간 예약에 맞춰 서버의 정수 나눗셈 제한을 제거한다. 정악대금 v1에 v2용 반주를 붙이지 않는다.

## 완료 조건과 검증

① 네 JSON이 공통 악보 스키마와 시간축·음표 연결 불변식을 만족한다.
② 허용한 네 판본에서 단모리와 원래 악보·판본을 함께 반환하고 다른 판본·악기·해시에는 보충 장단을 붙이지 않는다.
③ 서버 단위·HTTP 검사와 앱의 반 tick 시간 예약 검사로 77 BPM의 주기와 타격 위치를 확인한다.
④ 실제 데이터 공개 후 네 악보·채점 가능 상태·음원·수행 시간표 및 기존 기록의 보존을 확인한다. 이 단계는 아래 선행 작업과 앱 전환 검증 뒤에 수행한다.

## 공개 선행 조건

이 MR의 JSON은 자동 적재하지 않는다. 운영 56의 판본·BPM·음원은 이 코드 병합만으로 바뀌지 않는다. 정악대금 v2 공개에는 [745 판본 보관·조회·게시](https://ssafy.atlassian.net/browse/S15P31E102-745), [453 녹음 판본 보호](https://ssafy.atlassian.net/browse/S15P31E102-453), [454 기록 상세](https://ssafy.atlassian.net/browse/S15P31E102-454)의 검증이 먼저 필요하다. 구 앱의 미제출 녹음과 과거 결과 조회까지 전환 조건을 확인한 뒤 데이터를 게시한다.

745의 이력 테이블·판본 API·운영 게시기, 453의 녹음·세션 변경, 454의 기록·결과 화면 변경은 이 분리본에 포함하지 않는다. 생성·운영 이력은 [악보 근거](../knowledge/data/airplane-beginner-score.md), 이번 분리본의 검사는 [작업 계획](../plans/S15P31E102-707.md)에 기록한다.
