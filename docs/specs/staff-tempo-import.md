# 오선보 숫자 빠르기 가져오기

S15P31E102-882. 사용자 요청: 숫자 빠르기를 읽고 기존 구간 빠르기와 재생 연결을 확인한다. 기존 사용자 악보·불변 원본·운영 데이터는 변경하지 않는다.

## 동작과 범위

- MusicXML의 숫자 metronome/sound를 단위와 위치를 보존해 읽는다. 첫 빠르기는 장단 기본값과 구분한다. BPM 미인식 시 기존 기본값을 유지한다.
- 기존 `common-score-expressions/v1`의 `performancePlan`을 사용한다. 공통 악보 v1·JGB에 임의 필드를 넣지 않는다. 정간 경계로 정확히 대응되는 숫자 변화만 계획에 넣고 불명확한 위치는 검토 알림으로 남긴다.
- 못갖춘마디 앞 쉼·쪽 결합·기존 반복 펼침을 숫자 위치에도 똑같이 적용한다. 음고·음표 ID·기보 시간은 빠르기 인식 때문에 바꾸지 않는다.
- 서버는 인식된 첫 BPM과 companion을 저장·초안·편집에 전달하고 서버 식별자/provenance 변경 뒤 SHA를 재결합한다. 요청에 BPM이 있으면 기존 계약처럼 우선하며 숫자 계획도 같은 비율로 조정한다.
- 2026-11-13 사용자 선택: `MOLTO ACCEL`/`accelerando`는 같은 마디의 앞 숫자 표시부터 다음 숫자 표시까지 가속한다. 목표는 다음 숫자이며 기보 위치에 대한 선형 BPM과 역수 적분을 사용한다. `molto`의 별도 배율·연주 관행을 추정하지 않는다.
- 같은 위치에서 160→80으로 내린 직후 80→160 가속을 표현하려고 기존 tempo 항목에 선택적 `start_bpm`을 추가하는 것도 사용자가 승인했다. 생략 시 앞 BPM을 이어받는 기존 동작은 유지한다. 시작/목표는 기본 BPM 변경 시 함께 비례 조정한다.
- PDF 글자층의 `q = 숫자`/`♩ = 숫자`와 Audiveris 마디/첫 타점이 유일하게 대응되면 누락 숫자를 보완하고 잘못 연결된 위치를 첫 타점으로 옮긴다. 중간 타점·마디 수 불일치·모호한 위치는 추정하지 않는다. `TEMPO_PDF_TEXT` 검토 알림을 남긴다.
  - 조표·박자표 때문에 첫zero-time 타점이 오른쪽으로 밀린 마디도, 같은 마디의 시작선부터 그 타점 앞까지의 여백에 놓인 숫자는 유일한 후보일 때 시작값으로 연결한다. 오선·마디 범위와 zero-time·최근접 첫 타점 및 상충 숫자 검사는 유지한다([11월14일 재현](../plans/S15P31E102-882.md)).

## PDF 숫자 빠르기 보완 (S15P31E102-935)

- 사용자 제공 AuClair PDF의 Leipzig Type3 폰트는 `ToUnicode`에서 U+ECA5를 내보낸다. SMuFL의 명시적 4분음표 메트로놈 문자 U+ECA5/ECA6와 점 U+ECB7만 추가로 읽는다. 임의 PUA·다른 음표 단위·글꼴의 시각 모양은 추정하지 않는다.
- 숫자 전체가 하나의 값이어야 한다. 범위·분수·쉼표 숫자·별도 줄의 숫자, 단어 안 ASCII q는 빠르기로 보충하지 않는다. 같은 마디 시작에 서로 다른 PDF 숫자가 있으면 입력 순서와 관계없이 보충하지 않는다.
- 원래 MusicXML의 명시적 빠르기, 마디/첫 타점의 유일한 대응, 음표 보존과 `TEMPO_PDF_TEXT` 검토 알림을 유지한다. 글꼴 이름만으로 PUA를 해석하지 않는다. 글자층의 Unicode 매핑 자체가 잘못된 PDF는 지원을 보증하지 않는다.
- 완료 검사는 실제 PDFium을 쓰는 자체 PDF, 로컬 원본 opt-in, 실제 변환기·HTTP 응답까지로 나눈다. 고정 Audiveris 출력으로 실행한 HTTP 검사는 실제 OCR 품질이나 배포 후 휴대폰 동작을 증명하지 않는다.

## 한계

숫자 변화의 시작·끝은 현재 계획이 표현하는 정간 경계여야 한다. 경계 안쪽 숫자는 `TEMPO_OFF_GRID`, 가속의 시작 숫자·다음 목표/위치가 없거나 목표가 높지 않으면 `TEMPO_RAMP_UNRESOLVED`로 알린다. 같은 위치의 상충 숫자는 `TEMPO_CONFLICT`로 알리고 적용하지 않는다. 해석 불가 숫자를 건너뛰어 더 먼 숫자를 가속 끝으로 사용하지 않는다.

첫 BPM이 앱의 단위에서 양의 INT로 표현되면 인식 메타데이터로 전달한다. 분수/범위 초과면 기존 장단 기본값을 기본 BPM으로 유지하고 `TEMPO_BASE_NOT_INTEGER`를 알리되 정확히 대응되는 숫자 수행 계획은 보존한다. 숫자가 없는 입력의 기존 기본값과 명시 요청 BPM 우선은 유지한다. 이미지·글자층 없는 PDF의 누락된 OCR 숫자를 별도 OCR로 복원하는 기능, 임의 곡선·ritardando 자동 해석, 구간 생성 UI·숫자 표기의 악보 위 표시를 새로 구현하지 않는다.

인식 BPM은 요청 BPM보다 우선하지 않는다. 요청이 있으면 인식된 기준 대비 구간 시작/목표를 한 번 비례 조정한다. 요청이 없으면 인식값을 장단 기본값보다 우선한다. 최초 미해결 음 초안은 불변 원본 score의 해시를 기준으로 companion을 유지하여 음고 수정·반복 자동 저장 뒤 확정 저장에서도 재결합한다.

## 완료 조건

작은 고정 입력에서 단위·위치·반복·쪽 결합과 기본값 회귀, OMR HTTP 응답→서버 저장/초안의 companion 보존을 검증한다. 대표 PDF는 격리된 파일로 실행하여 숫자별 인식 여부와 위치/가속 한계를 기록한다. 운영 배포·기존 악보 복구·새 MR/Push는 포함하지 않는다.
