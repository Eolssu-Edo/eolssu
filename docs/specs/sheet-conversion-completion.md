# PDF·사진 악보 변환 완료 알림 (927)

사용자가 요청한 동작: PDF·사진 업로드 뒤 앱의 다른 화면에 있어도 악보 인식 완료를 알고 해당 결과를 연다. 905의 음원 생성 알림과 별개이며 기존 음원 알림을 유지한다.

- 업로드 접수(SHT-07)된 악보는 즉시 앱 공통 수명에서 추적한다. 목록의 SHT-10 조회에서 진행 중인 악보를 발견해도 이어서 추적한다.
- 앱 활성 중 기존 SHT-10을 서버의 `pollAfterMs` 간격(기본 3초, 0.5~30초 범위)으로 조회한다. 화면 이동은 추적을 중단하지 않는다.
- 추적하던 악보가 DONE이면 검토 필요 여부와 무관하게 `악보 변환이 완료됐어요.`와 `열기`를 한 번 표시한다. 열기는 그 악보의 편집기로 이동한다.
- 과거 DONE의 최초 조회·반복 조회·같은 업로드 접수 재응답으로 다시 알리지 않는다. 실패·404 삭제는 성공으로 알리지 않는다. 명시적 재시도는 새 시도로 추적한다.
- 로그인 세대가 바뀌면 진행·대기 알림을 비운다. 이전 계정 응답·열기 동작은 새 계정에 영향을 주지 않는다.
- 앞선 사용자 요청(2026-11-15, 927): 기존 작은 하단 스낵바를 **상단 별도 완료 알림바**로 대체하고 직접 누를 때까지 유지했다. 이후 같은 날 사용자 요청(955)으로 유지 시간을 아래처럼 대체한다. 큰 제목·메시지, `열기`·`닫기`, 상태 표시줄 안전 영역과 기존 오류 안내는 유지한다.
- 음원·악보 생성 완료 알림은 Material `SnackbarDuration.Short`로 잠깐 표시한 뒤 자동으로 닫는다(기본 약 4초, 플랫폼 접근성 권장 시간이 있으면 연장). 별도 타이머를 추가하지 않고 기존 `SnackbarHost`가 실제 표시 시점부터 시간을 관리한다.
- 악보와 음원 완료는 전용 표시 큐를 공유한다. 열기·닫기·자동 닫힘으로 처리한 알림은 소비하며 다시 표시하지 않는다. 대기 중인 다음 알림에는 자기 표시 시간이 주어진다. 표시 중이거나 대기 중인 알림은 pause로 취소되면 미처리 상태로 복귀 후 다시 표시한다. 삭제된 결과는 표시 대기 중에도 취소한다.
- OS 푸시·앱 종료 중 알림은 범위 밖이다. 추적은 메모리이며 재실행 뒤에는 목록에서 진행 상태를 다시 발견해야 한다. 일시 조회 실패는 다음 간격에 재조회하며 5회 연속 실패하면 조회를 멈추고 화면 재진입으로 재발견한다(기존 음원 관찰 정책과 동일).

수용 검증: 업로드→다른 화면→완료 알림→열기를 자동 회귀 및 Galaxy S24+의 실제 PDF·사진으로 확인한다. 과거 완료·중복·실패·삭제·재시도·계정 세대·pause와 기존 음원 알림을 회귀한다. Android host 검사와 Android/Wasm 빌드를 확인하며 iOS 미검증을 구분한다.
