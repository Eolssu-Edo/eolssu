# 기초 배우기 수동 완료 연결

- 작업: [S15P31E102-934](../plans/S15P31E102-934.md)
- 상태: 기존 수동 완료 동작의 연결 복구. Android 17 실기기에서 완료 창·저장·재진입 확인.

## 기대 동작

5·6단계는 할 일 박스 안에서 음높이를 판정한다. 음높이 기준이 없거나 마이크를 쓸 수 없어 화면이 `해 봤어요`를 제공하면, 마지막 박스를 확인했을 때 기존 `완료했어요!` 창으로 이어져야 한다. 창의 다음 단계 동작은 기존 완료 저장 경로를 사용한다.

마이크 권한을 영구 거부하면 판정 계획은 남아 있으나 듣기는 불가능하다. 이 경우도 화면이 이미 제공하는 수동 완료와 같은 정책을 적용한다. 권한 정책·통과 음높이/시간·서버 완료 계약을 변경하지 않는다.

## 검증과 범위

- 실제 `LearnPracticeViewModel.prepare → startListening`에서 영구 거부 상태와 보존된 판정 계획을 만든다.
- 화면에서 사용하는 완료 콜백을 실행해 중간 박스는 박스 완료만, 마지막 수동 박스는 박스 완료 뒤 축하를 한 번 요청하는지 검사한다.
- 판정 가능한 마지막 박스는 기존 자동 통과 효과가 축하를 담당한다. 콜백이 중복 축하하지 않아야 한다.
- 휴대폰에서 5·6단계 권한 거부 → 수동 박스 완료 → 완료 창 → 저장 → 재진입을 확인한다. 기존 사용자의 진도 초기화는 금지한다.
- 작은 호스트 검사로 실제 버튼 표시·탭·저장 완료를 검증했다고 보고하지 않는다. 새로운 UI 테스트 프레임워크·의존성은 추가하지 않는다.

원래 기대는 화면에 제공한 수동 확인이 단계 완료로 이어지는 것이다. 실제 구현 선택은 기존 완료 콜백의 판정 불가 조건을 일치시키는 것이며 제품 정책 변경은 없다.

실행 결과: 인계받은 QA933에서 5·6단계의 마지막 수동 확인 후 완료 창 누락을 재현했다. 수정 QA `3d9a7725`에서 완료 창과 다음 단계 이동, 목록 반영 및 앱 재실행 후 저장 유지를 확인했다. 마이크 자동 판정은 실행하지 않았다. [조건과 증거](../knowledge/frontend/android-guide-flow-verification.md)를 함께 본다.
