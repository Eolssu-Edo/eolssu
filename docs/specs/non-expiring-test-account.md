# 운영 테스트 계정의 인증 만료 예외

- Task: S15P31E102-260 / Story: S15P31E102-22 / Epic: S15P31E102-14
- 요청: edo1의 `test1@test.com` 한 계정, 지정한 비밀번호로 로그인하며 토큰·세션의 시간 만료를 없앤다. 비밀번호 원문은 문서·코드에 남기지 않는다.
- 대상 회원은 운영 DB의 ID `1`이다. 운영자가 `AUTH_NON_EXPIRING_USER_IDS=1`을 지정한 경우에만 예외를 켠다. 기본 허용 목록은 비어 있다.
- 예외 access token은 `exp` 없이 서명하고, 임의 리프레시 토큰의 SHA-256을 `session_hash`로 넣는다. JWT 서명, 허용 회원 ID, DB의 같은 회원·같은 해시·만료 없음·미폐기 세션, ACTIVE 회원 상태를 매 요청 검증한다.
- refresh token의 `expires_at=NULL`은 시간 만료 없음이다. 지정 회원만 발급·재발급할 수 있고 기존 회전·재사용 탐지·로그아웃·비밀번호 변경·탈퇴의 폐기 처리를 유지한다. 허용 목록에서 제거하면 예외 access·refresh 모두 거부한다.
- 일반 회원의 access 30분, refresh 14일 정책은 유지한다. 계정·자격 증명을 애플리케이션 마이그레이션으로 자동 생성하지 않는다.
- AUTH-04 재발급 응답의 `accessTokenExpiresAt`은 예외 계정에만 null이다. 프론트는 이 필드를 읽지 않고 쿠키로 인증한다.
- 브라우저 쿠키는 400일로 설정한다. 브라우저 보관 제한·사용자 쿠키 삭제·서명 키 교체까지 없애는 기능은 아니다. [Chrome의 쿠키 수명 제한](https://developer.chrome.com/blog/cookie-max-age-expires)을 따른다.

완료 검증: 일반/예외 발급, 서명·회원·활성 세션 검증, 예외 해제·회전·로그아웃·비밀번호 변경·탈퇴 후 거부, NULL 만료의 MyBatis 저장·조회 및 운영 로그인 확인. 운영 무기한 적용은 사람이 MR을 병합한 뒤 정상 배포와 허용 목록 설정까지 확인해야 완료다.
