# Blue Valentine 소금 제공 곡과 4박 기본 반주

## 후속 확정: 기본 운지에 맞춘 4판

사용자는 3판의 운지 누락 확인 후 곡 전체를 반음 낮춰 다시 게시하도록 요청했다. 3판의 490개 본음을 각각 1반음 낮춰 4판으로 만든다. 음역은 임(B♭4)부터 청남(C6)이며 모든 본음이 현재 소금 운지 카탈로그에 대응해야 한다. 이는 운지 자료 대응 검증이며 실물 악기·전문 연주 검수를 뜻하지 않는다.

- 곡135·제목·소금2·장단12와 118각490음·이벤트 ID·쉼·붙임줄·변속 수행 시간은 유지한다. 조성 변경에 맞춰 악보와 CAT 선율을 함께 다시 만든다.
- 공통 악보의 입력 JGB 출처 해시는 보존하고, 공통 악보 변환기의 반음 이조 및 이전3판의 해시를 생성 이력에 기록한다. 표시용 율명과 이벤트 음고를 함께 변경하며 hwangHz 기준을 중복 이동하지 않는다.
- 3판과 기존 음원을 보존한 뒤 불변 R2 객체와 DB 메타데이터를 4판에 연결한다. 다른 곡·기준음·운지표는 변경하지 않는다.
- 사용자 추가 지시에 따라 첫 이벤트가 쉼이라는 이유로 반주를 억제하는 조건과 곡별 첫 쉼 예외를 제거한다. 현재 악보 그리드의 시작 위치0tick·완전한 장단 주기를 기준으로 반주를 맞춘다. 선율이1.5박 뒤에 시작해도 장단은0박부터 시작한다. 장단명이 없거나 그리드 시작·주기가 불명확한 입력은 기존 검증을 유지한다. 임의의 장단 오프셋을 새 공유 필드로 도입하는 작업은 포함하지 않는다.
- 완료 검증: 490음의 일괄 −1반음·운지 누락0·배치/타이밍 보존, 실제 MIDI/AAC 음고·길이·쉼, 공개 현재/이전 악보·음원/수행 시간표의 판본/해시와 첫박0·주기16tick 반주, 변경 전 백업과 다른 카탈로그 행 보존.

아래는 3판 등록 당시 범위이며 음고 보존 조건은 위 4판 이조 요청으로 대체한다.

## 확정 범위

사용자 제공 악보를 현재 CAT 경로로 합성하고 앱 제공 곡으로 등록한다. 3판 당시 사용자 지시는 소금 지원음으로 편곡한 Blue Valentine에 `덩 | 덕 | 궁 | 덕`을 연결하고, 등록 결과와 필요한 소스 변경을 MR로 제출하는 것이었다. 기존 Task S15P31E102-746과 Story26을 유지한다.

- 곡135, 제목 Blue Valentine, 소금2,118각490음을 유지한다.2판의196음 옥타브 편곡·붙임줄·변속 수행 시간표를 보존한다. 음역 밖 음을 새 기준음이나 한글 대체 표시로 통과시키지 않는다.
- 장단12 **4박 기본 반주**는4분음표1박마다 덩·덕·궁·덕, 한 주기4박이다. 기본160 BPM은 원본 시작값이다. 전통 장단의 공인 기본형으로 명명한 항목이 아니다.
- 새 연결 판본에서 장단 FK·공통 악보의 장단명·음원 및 수행 시간표의 판본과 해시를 일치시킨다. 이전 게시 판본은 현재 저장소의 이력 보존 규칙에 따라 보존한다.
- 곡은 첫마디의1.5박 쉼 뒤 선율이 시작되지만118개 마디가 모두4박인 원본이다. 검수한 이 곡의 식별자·JGB 해시·판본에만 첫마디 첫박부터 장단 재생을 허용한다. 다른 곡의 못갖춘마디 억제 정책은 유지한다.
- 앱은 CAT 선율 음원과 장구 반주를 별도로 동기 재생한다. 선율 음원에 장구를 중복 혼합하지 않는다. 단독 장단 미리듣기도 실제 샘플과4박 시간표로 등록한다.
- 음원 파일은 불변 R2 객체에, DB에는 악보 JSON과 객체 키·해시·판본 등 메타데이터를 저장한다. 기존 곡·기준음·단모리·사용자 데이터는 보존한다.

## 완료 조건

1. 공개 곡 상세와 악보 API에서 소금·490음·장단12 및16tick(4박) 반복 계획이 일치한다. 첫박이 쉼인 등록 곡에 계획이 제공되고 미검수 곡에는 확대 적용되지 않는다.
2. R2 선율·수행 시간표·단독 미리듣기 객체의 전체 해시·판본·길이를 실제 API로 확인한다. 기존 음표 ID·음고·시점·기존 판본과 다른 행 보존을 대조한다.
3. 앱 공통 장단 계획기와 서버 반주 생성의 네 타점 및 반복을 확인한다. 실기기 검증과 API·공통 코드 검증을 구분한다.
4. 관련 회귀 검사·빌드를 통과한 변경을 최신 origin/develop과 통합하고 Push 후 Draft MR의 제목·본문·head·대상 develop·담당자·리뷰어·기존 라벨을 재조회한다. 병합은 사람이 한다.
