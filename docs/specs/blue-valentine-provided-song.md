# Blue Valentine 소금 제공 곡과 4박 기본 반주

## 확정 범위

사용자 제공 악보를 현재 CAT 경로로 합성하고 앱 제공 곡으로 등록한다. 최종 사용자 지시는 소금 지원음으로 편곡한 Blue Valentine에 `덩 | 덕 | 궁 | 덕`을 연결하고, 등록 결과와 필요한 소스 변경을 MR로 제출하는 것이다. 기존 Task S15P31E102-746과 Story26을 유지한다.

- 곡135, 제목 Blue Valentine, 소금2,118각490음을 유지한다.2판의196음 옥타브 편곡·붙임줄·변속 수행 시간표를 보존한다. 음역 밖 음을 새 기준음이나 한글 대체 표시로 통과시키지 않는다.
- 장단12 **4박 기본 반주**는4분음표1박마다 덩·덕·궁·덕, 한 주기4박이다. 기본160 BPM은 원본 시작값이다. 전통 장단의 공인 기본형으로 명명한 항목이 아니다.
- 새 연결 판본에서 장단 FK·공통 악보의 장단명·음원 및 수행 시간표의 판본과 해시를 일치시킨다. 이전 게시 판본은 현재 저장소의 이력 보존 규칙에 따라 보존한다.
- 곡은 첫마디의1.5박 쉼 뒤 선율이 시작되지만118개 마디가 모두4박인 원본이다. 검수한 이 곡의 식별자·JGB 해시·판본에만 첫마디 첫박부터 장단 재생을 허용한다. 다른 곡의 못갖춘마디 억제 정책은 유지한다.
- 앱은 CAT 선율 음원과 장구 반주를 별도로 동기 재생한다. 선율 음원에 장구를 중복 혼합하지 않는다. 단독 장단 미리듣기도 실제 샘플과4박 시간표로 등록한다.
- 음원 파일은 불변 R2 객체에, DB에는 악보 JSON과 객체 키·해시·판본 등 메타데이터를 저장한다. 기존 곡·기준음·단모리·사용자 데이터는 보존한다.

## 완료 조건

1. 공개 곡 상세와 악보 API에서 소금·490음·장단12 및16tick(4박) 반복 계획이 일치한다. 첫박이 쉼인 등록 곡에 계획이 제공되고 미검수 곡에는 확대 적용되지 않는다.
2. R2 선율·수행 시간표·단독 미리듣기 객체의 전체 해시·판본·길이를 실제 API로 확인한다. 기존 음표 ID·음고·시점·기존 판본과 다른 행 보존을 대조한다.
3. 앱 공통 장단 계획기와 서버 반주 생성의 네 타점 및 반복을 확인한다. 실기기 검증과 API·공통 코드 검증을 구분한다.
4. 관련 회귀 검사·빌드를 통과한 변경을 최신 origin/develop과 통합하고 Push 후 Draft MR의 제목·본문·head·대상 develop·담당자·리뷰어·기존 라벨을 재조회한다. 병합은 사람이 한다.
