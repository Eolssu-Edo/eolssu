# 인식 정간보의 장단 정정

2026-11-12 사용자 요청·후속 답변, S15P31E102-822 / Story319.

- 원본 각별 정간 수, 칸 안 배치, 음표 ID·음고·기호를 보존한다.
- 정간보 인식기가 요청 장단으로 추정한 박 길이는 변경 후보의 제약으로 쓰지 않는다. 보존된 인식 원본의 격자와 카탈로그 패턴 음가로 후보를 판단한다. 장단을 자동 확정했다는 뜻은 아니다.
- 사용자는 원본에 박 길이가 없는 경우 새 장단에 맞춰 한 칸의 박 길이를 보정하고 적용 전에 알리는 방식을 선택했다. 현재 인식기의 한 각=한 주기, 한 정간=1·1/2·1/3박(세령산 3/2박 예외) 범위를 재사용한다. 미등록 패턴의 음가는 추측하지 않는다.
- 원본이 동일하면 최초 요청 장단·BPM 단위·tick 배율과 무관하게 같은 후보가 활성화된다. 원본 격자와 다른 불완전 각은 허용하지 않는다.
- 오선보 등 독립된 시간 정보가 있는 악보는 기존 시간값·완전한 주기 판정을 유지한다. 숫자 구간 빠르기 계획이 있으면 시간 보정은 제공하지 않는다.
- 보정은 현재 편집 내용에 적용하며 실행 취소/다시 실행, 임시·확정 저장/재조회에서도 유지한다. 불변 authoring.source는 바꾸지 않는다. 시간 안내와 저장·재생은 보정한 공통 악보를 쓴다.
- 이전772의 모든 장단 변경에서 tick을 유지하던 정책을 위 인식 정간보의 명시적 정정에 한해 대체한다. 서버 API·공통 악보 스키마와 기존 게시 악보는 변경하지 않는다.

검증: 서로 다른 최초 장단의 같은4정간 격자, 박 길이 정정/취소/왕복, 원본·현재 편집 보존, 오선보·구간 계획 경계, ViewModel 저장·재조회, 전체 Android host 검사·APK·공통 웹 컴파일. Windows의 iOS·실기기 청취는 별도 미검증으로 남긴다.
