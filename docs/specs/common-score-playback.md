# 공통 악보 v1 기반 음원 생성

- 작업: [S15P31E102-338](https://ssafy.atlassian.net/browse/S15P31E102-338), Story S15P31E102-30.
- 기준: 지한의 [공통 악보 v1](../../data/src/scores/score_data.schema.json), [156의 승인 결정](../plans/S15P31E102-156.md).
- 2026-11-02 사용자 정정: 공통 악보를 기준으로 음원을 생성하고 FE는 별도로 둔다. 이 문서는 앞서 사용한 공통→JGB 왕복 설계와 MR 내 FE 구현 범위를 대체한다.

## 구조와 책임

`공통 악보 events·columns/cells/units → 구조화된 수행 음표 → 기존 MIDI → CAT PCM → WAV/M4A`를 사용한다. 음원 생성 중 JGB 문서·선율 문자열을 만들거나 JGB parser/convert_jgb를 호출하지 않는다. 악기별 음열·꾸밈 길이·효과 계산은 입력 형식과 무관한 음악 규칙으로 공유한다.

생성 명령은 서비스 공통 v1만 받는다. JGB나 기존 내부 재생 IR 파일을 직접 입력하면 공통 악보 가져오기 안내와 함께 거부한다. 내부 IR은 MIDI·합성기에 전달하는 구현 자료로만 유지한다. 기존 JGB 자료는 별도 `data.src.scores.playback_import`에서 공통 악보로 가져온다. 가져오기 경계의 JGB 판독은 유지하되 공통 악보 생성 경로는 이에 의존하지 않는다.

이 MR은 DATA 생성기·입력 검증·회귀 검사만 포함한다. 앞서 추가한 FE 코드·테스트·리소스는 별도 [S15P31E102-380](https://ssafy.atlassian.net/browse/S15P31E102-380)과 FE 브랜치에 보존한다. FE 화면 구현, 운영 API 연결, 서버 곡 적재·음원 업로드는 별도 업무다.

## 입력과 보존 조건

- 서비스 v1 스키마·검수된 채점 변환기·기존 악보 파일은 변경하지 않는다. eventId/cellId·scoreVersion·원문 바이트·NOTE 순번과 기보 tick을 보존한다.
- `--common-bpm`은 music.bpmUnit의 분당 박 수로 명시한다. tick/ticksPerBeat×60/bpm 초와 music.hwangHz 조율을 보존한다. 악기 변경·옥타브 접기를 자동으로 수행하지 않는다.
- 병합된 event.sigimsae만으로 장식의 원래 위치를 복원할 수 없는 경우, 공통 파일 SHA256과 eventId/cellId/row/col에 결합한 선택적 common-score-expressions/v1을 사용한다. 원본 JGB를 생성 시점에 다시 읽지 않는다. 위치 미지정은 첫 표시 자리 적용이라는 추정으로 기록한다.
- 표현 파일의 해시·기호 수/순서·위치·원문 슬롯 묶음·slur·각 경계 지속을 검사한다. 누락·상충·잘못된 입력을 조용히 생략하지 않는다. sourceSlots는 가져오기에서 생성한 inferred 자료의 호환 입력이며 공통 좌표/음높이로 검증해 사용한다.

## 시김새와 수행 시간

- 명시한 educational-preview/v1에서 단소·소금·정악대금·산조대금의 확정 음열을 우선 사용한다. 미확정 기호의 기본값은 근거와 정책 버전을 가진 교육용 근사값이며 전문가 검수로 간주하지 않는다.
- 꾸밈·독립 음열·요성·곡선·강약·숨표·늘임·길이표·빠르기·반복을 공통 표시 자리에서 처리한다. 원문 슬롯의 균형 길이표는 꾸밈 전, 수행 길이표는 꾸밈 후에 적용한다. 기보 시간과 실제 수행 시간은 분리한다.
- 시김새 내부 연결과 가져온 독립 음열의 slur를 보존한다. 쉼·숨표·명시 끊는표 경계를 넘지 않으며 새로 적힌 동음은 다시 발음한다. 각 경계 지속은 근거가 명시된 경우에만 허용한다.
- 짧은 대금 연결음의 crossfade는 기존 수정값 min(20ms, 다음 음 길이/5)를 유지한다. 기존 기대 음높이·시점과50cent 허용치를 바꾸지 않는다. 숨표 목표 무음120ms와 음 길이 절반 상한을 유지한다.

## 숫자 가속의 명시 시작값 (882)

2026-11-13 사용자가 기존 `<악기>-performance/v1`의 tempo 항목에 선택적 `start_bpm` 추가를 승인했다. `bpm`은 목표 정간/분이고 `start_bpm`은 해당 위치에서 즉시 적용할 시작 정간/분이다. 양의 유한수이며 `end_gak`·`end_cell`이 있는 점진 구간에만 허용한다. 생략하면 앞 빠르기를 이어받는다. 예를 들어 `{gak:26, cell:1, start_bpm:80, bpm:160, end_gak:30, end_cell:1}`은 앞 구간160을 바꾸지 않고26각에서80으로 내린 뒤30각까지 가속한다. 중복 위치·구간 겹침 금지는 유지한다.

기본 BPM 변경은 시작/목표를 같은 비율로 조정한다. 선율·장구·수행표는 기존 `PerformanceClock`을 사용한다. 새 입력을 보내기 전에 이를 읽는 생성기를 배포해야 하며 구버전 생성기는 알 수 없는 필드로 거절한다. 필드 없는 기존 입력은 같은 동작을 유지한다. [인식 연결과 범위](staff-tempo-import.md).

## 출력

원본 공통 JSON, 내부 수행 음표, MIDI, WAV 또는 AAC-LC M4A, manifest와 원본 이벤트/표시 자리 대응표를 생성한다. 교육용 표현을 선택하면 원본·음원 SHA256에 결합한 common-score-performance/v1도 생성한다. 이는 데이터 산출물이며 FE 구현을 포함하지 않는다. 약550ms 후행 여백은 수행 악보 길이와 구분한다. 기존 출력 보호·원본 비변경·실패 시 게시 방지를 유지한다.

내부 IR 음표 ID는 공통 cell/row/unit에 기반한다. `expression_source_map`은 `common-expression-map/v1`로 바꾸고 생성하지 않는 JGB 문서의 문자 offset·version 필드는 제거한다. 이 내부 진단 정보 변경과 서비스 v1 원본 ID·NOTE idx·tick 및 `common-score-performance/v1`의 보존은 구분한다.

### 작성 악보의 로컬 반주 시계 (773)

새 `common-score-performance/v1` segment는 선택적 양수 `tempoRatio`(구간 끝 BPM/시작 BPM)를 전달한다. 한 표시 구간 안에 빠르기 경계가 없어야 하며 생성기가 확인한다. 빠르기가 기보 위치에 선형으로 변하는 구간에서 시간 비율 t에 대한 기보 비율은 `expm1(log(r)·t)/(r−1)`이다. 탐색은 역함수를 사용한다. 필드가 없거나 r=1이면 기존 선형 보간을 유지한다.

가져온 `sourceSlots`의 균형 길이표는 같은 정간의 표시 칸과 반주 박 위치를 다르게 만들 수 있다. 해당 segment는 선택적 숫자 쌍 `accompanimentStartTick`/`accompanimentEndTick`으로 실제 반주 축을 전달한다. 원본 `startTick`/`endTick`은 표시·탐색에 그대로 사용하고 로컬 장구와 현재 박 표시만 반주 축을 사용한다. 구간 BPM 적용 후 나눈 표시 chunk의 시간 비율을 원래 slot의 역적분 역함수로 투영한다. 단순히 원본 slot 전체의 비율을 각 chunk에 복사하지 않는다. 쌍이 없으면 원본 tick 축을 쓴다. 두 값은 유한수이고 `0 ≤ start < end ≤ 악보 전체 tick`이어야 한다.

BE는 수행 JSON을 보존한다. 기존 원본·음원·판본·sidecar는 재작성하지 않는다. 새 필드가 있는 산출물에는 이를 읽는 FE가 필요하므로 생성기와 FE를 함께 배포한다. 구버전의 엄격한 JSON decoder까지 호환된다고 가정하지 않는다. 기존 필드가 없는 수행표의 구간 내부 선형 보간은 유지한다.

## 완료 조건

- JGB 해석 모듈을 차단한 상태에서도 공통 악보의 기본음·시김새 음원 생성이 성공한다. JGB 문서/문자열 조립 및 공통 생성 경로의 JGB import가 없어야 한다.
- 기존 공통 악보107성부와 수기 시김새 기대값의 음높이·시작·길이·연결·효과를 이전 검증본과 대조한다. 과거 JGB 비교기는 구버전 증거로만 보존한다.
- 실제4악기 CAT WAV/AAC 각각40개 검사와 단소 BPM30의9개 검사를 기존 창·허용치로 통과한다. 합성 신호·해시·오류 입력 대조를 유지한다.
- 전체 DATA/playback 회귀와 독립 검토를 완료한다. 생성 CLI의 JGB/내부IR 거부와 canonical 입력·출력 보호를 실제 실행한다.
- MR의 frontend 변경은0건이다. 기존곡 생성 가능과 서버 등록 완료를 구분하여 보고한다.
