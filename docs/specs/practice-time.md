- Jira: [S15P31E102-169](https://ssafy.atlassian.net/browse/S15P31E102-169), Story S15P31E102-23, Epic S15P31E102-14
- 상태: 사용자 합의(2026-10-27, 회의 안건 E1과 성장 화면 통계 기준). FE·BE·Data 담당자 검토 전이다. BE-1 검증·저장 계층만 구현 중이다.
- 구현 계획: [S15P31E102-169 계획](../plans/S15P31E102-169.md)
- 기준 코드: `origin/develop` `d60d8e0`. 저장 구조는 V2의 `score_views`([DB 스키마](../contracts/db-schema.md))를 그대로 쓴다.

## 목적

사용자가 실제로 악보를 보며 연습한 시간을 연습 시간으로 센다. 백그라운드와 자리 비움 시간은 빼고, 오프라인이나 갑작스러운 종료에도 기록이 거의 빠지지 않게 한다. 기록의 정본은 서버의 `score_views`이고, 성장 화면(GRO-01·02)은 이 값을 합산해 보여 준다.

## 범위

포함:

- 앱이 연습 시간을 재는 규칙(멈춤, 자리 비움, 알림)
- 구간 기록을 기기에 저장하고 서버로 보내는 방식
- 체류 기록 API(GRO-04)의 검증·중복 처리
- 사용자 화면 합산과 관리용 마트 집계 기준

유지하는 동작:

- `practice_sessions`·`evaluations`의 녹음·채점 흐름과 기존 마트 칸(`session_count` 등)의 의미
- V2 `score_views`의 칸·제약(`(user_id, idempotency_key)` 유일, `0 ≤ counted_seconds ≤ visible_seconds`, `ended_at ≥ started_at`)
- 탈퇴 일괄 삭제에서 `score_views`를 회원 단위로 지우는 규칙

제외:

| 항목 | 이유 |
| --- | --- |
| 다른 화면의 체류 분석, 분석 도구(GA·Firebase) 도입 | 이번 범위가 아니다. 필요하면 따로 붙인다. |
| 주기적 서버 전송(heartbeat) | 실시간이 필요 없고, 부하만 늘리며 오프라인 누락은 막지 못한다. |
| 마이크로 소리를 감지해 자리 비움 판정 | 권한·배터리·개인정보 부담 |
| 구간당·하루 최대 인정 시간 | 자리 비움 규칙으로 충분하고 불필요하게 복잡하다. |
| 여러 기기에서 겹친 시간 제거 | 두 번 세지는 시간은 많아야 10분 정도이고, 병합 비용이 크다. |
| 자정을 넘긴 구간을 날짜별로 나누기 | 일 단위 지표에서 차이가 작다. |

## 용어

| 용어 | 뜻 |
| --- | --- |
| 악보 화면 | 곡의 정간보를 보며 재생·녹음·메트로놈을 쓰는 연습 화면. 연습 시간은 이 화면에서만 잰다. |
| 구간 | 악보 화면이 앞에 보이기 시작한 때부터 화면을 떠나거나 앱이 가려질 때까지. `score_views` 한 행이 구간 하나다. |
| 보인 시간 (`visible_seconds`) | 구간에서 화면이 실제로 앞에 보인 초 |
| 인정 시간 (`counted_seconds`) | 보인 시간에서 자리 비움으로 판정된 시간을 뺀 초. 연습 시간으로 세는 값이다. |
| 활동 | 터치·스크롤·키 입력, 그리고 재생·녹음·메트로놈이 돌아가는 상태 |

V2 SQL 주석은 `counted_seconds`를 "최대 인정 시간을 적용한 값"으로 적었지만, 이 스펙의 정의가 그 주석을 대신한다. V2 파일은 Flyway checksum 때문에 고치지 않는다.

## 측정 규칙 (앱)

1. **구간 시작:** 악보 화면이 앞에 보이면 새 구간을 연다. 시작할 때 구간 키(UUID)와 시작 시각을 정한다.
2. **구간 끝:** 화면을 떠날 때, 앱이 백그라운드로 갈 때, 화면이 잠길 때, 웹 탭이 가려질 때 구간을 닫는다. 돌아오면 새 구간을 연다.
3. **활동 중:** 재생·녹음·메트로놈이 돌아가는 동안은 입력이 없어도 인정 시간을 계속 센다.
4. **자리 비움:** 그 밖에는 마지막 활동 뒤 10분까지 인정한다. 그 뒤로는 화면이 보여도 인정 시간을 늘리지 않는다. 다음 활동이 생기면 다시 센다.
5. **알림:** 마지막 활동 뒤 9분 30초에 "계속 연습 중인가요?" 알림을 한 번 띄운다. 누르면 활동으로 보고 10분을 다시 센다. 응답하지 않으면 10분에서 멈춘다.
6. **짧은 구간:** 인정 시간이 10초 미만인 구간은 보내지 않고 버린다.
7. **상한 없음:** 구간 길이와 인정 시간에 최대값을 두지 않는다.

시간은 앱의 단조 시계로 재고, `started_at`·`ended_at`만 기기 시각(UTC)으로 기록한다. 측정 로직은 앱 공통 코드(`frontend/shared`)에 하나만 두고, 서버로는 악보 화면 구간만 보낸다.

## 기기 저장과 전송

1. 열린 구간의 상태(구간 키, 회원, 곡, 시작 시각, 보인 시간, 인정 시간, 저장 시각)를 **30초마다 기기 저장소에 덮어쓴다.** 이때는 네트워크를 쓰지 않는다.
2. 구간이 닫히면 `ended_at`을 정해 **전송 대기열**로 옮기고 바로 보낸다. 닫힌 구간은 다시 바뀌지 않는다.
3. 앱이 시작되거나 앞으로 돌아오면, 대기열을 보낸다. 앱이 갑자기 종료돼 닫히지 않은 구간이 남아 있으면 마지막 저장 시각을 `ended_at`으로 정하고, 저장된 값으로 닫아서 대기열에 넣는다.
4. 같은 구간은 항상 같은 키와 같은 본문으로 다시 보낸다. 처음 합의한 "보기 ID로 덮어쓰기" 대신 닫힌 구간을 한 번만 저장하는 방식을 골랐다(2026-10-27). 기존 V2 제약과 409 규칙을 그대로 쓰기 위해서이며, 사용자에게 보이는 결과는 같다.
5. 응답에 따른 처리:

| 응답 | 앱 처리 |
| --- | --- |
| 201, 200 | 대기열에서 지운다. |
| 409, 400, 404 | 다시 보내도 결과가 같으므로 지우고 오류 로그를 남긴다. |
| 401 | 토큰을 갱신한 뒤 다시 보낸다. 갱신에 실패하면 대기열에 남겨 둔다. |
| 네트워크 오류, 5xx | 대기열에 남겨 두고 다음 전송 시점(구간 닫힘·앱 시작·앞으로 돌아옴)에 다시 보낸다. |

6. 기록은 측정한 회원의 것으로만 보낸다. 다른 회원으로 로그인한 상태에서는 그 기록을 보내지 않는다. 로그아웃할 때 남은 기록을 한 번 보내 보고, 실패한 기록은 지운다.

받아들인 누락: 보내기 전에 앱 데이터를 지우거나 앱을 삭제한 경우, 마지막 기기 저장 뒤 최대 30초, 로그아웃 때 보내지 못한 기록.

## 체류 기록 API (GRO-04)

경로와 오류 응답 형식은 Notion API 명세서의 GRO-04와 공통 오류 형식을 따른다. 이 스펙은 의미만 정한다.

요청:

| 항목 | 위치 | 뜻 |
| --- | --- | --- |
| `Idempotency-Key` | 헤더 | 구간 키. 회원별로 유일하다. |
| `songId` | 본문 | 곡 |
| `startedAt`, `endedAt` | 본문 | 구간 시작·끝(UTC) |
| `visibleSeconds`, `countedSeconds` | 본문 | 보인 시간, 인정 시간(초, 정수) |

서버 처리:

| 조건 | 응답 |
| --- | --- |
| 새 키 | 저장하고 201 |
| 같은 키, 같은 본문 | 저장하지 않고 기존 기록으로 200 |
| 같은 키, 다른 본문 | 409. 저장한 칸과 비교한다(V2 주석). |
| `endedAt < startedAt`, `countedSeconds > visibleSeconds`, 음수 | 400 |
| `visibleSeconds > (endedAt − startedAt) + 1초` | 400. 반올림 오차로 1초를 허용한다. |
| `visibleSeconds > (서버 수신 시각 − startedAt) + 1초` | 400. 앱 버그나 틀린 기기 시계로 부풀린 값을 막는다(R3). 구간을 닫자마자 보내면 반올림한 보인 시간이 1초 미만 길 수 있어 1초를 허용한다. |
| 없는 곡(`songs` 행 없음) | 404. 숨김·삭제 표시된 곡의 기록은 받는다(오프라인 연습 뒤 곡이 숨겨진 경우). |

서버는 10초 미만 구간을 따로 거절하지 않는다. 버리는 일은 앱이 맡는다.

## 조회와 집계

- **날짜:** 구간은 `started_at`의 KST 날짜에 속한다.
- **사용자 화면(GRO-01·02):** 운영 DB `score_views`에서 회원·기간으로 `counted_seconds`를 바로 합산한다. 인덱스 `idx_score_views_user_started`를 쓴다. 그래서 방금 끝난 연습도 바로 반영된다.
- **여러 기기:** 기기별 구간을 그대로 더한다.
- **관리용 마트:** `mart_daily_practice`에 `total_practice_seconds`를 더한다. `(stat_date, instrument_id)`별로, 그날(KST) 시작한 구간 중 그 악기 곡의 `counted_seconds` 합이다. 일 배치가 채운다.

## 성장 화면 통계 (GRO-01·02)

2026-10-27 사용자 합의, 2026-10-28 Notion API 명세에 맞춰 고침. 대상은 앱의 연습 기록지 화면(`GROWTH-01`, `frontend/.../feature/history/GrowthUiState.kt`)이다. 서버는 앱이 정한 날짜 범위를 집계하고, 주·월 탭의 기간·막대·변화 표시는 앱이 정한다.

API(모두 회원 인증 필요, 경로 앞에 `/api`):

| 요구사항 | 요청 | 응답 `result` |
| --- | --- | --- |
| GRO-01 요약 | `GET /users/me/growth/summary?from=YYYY-MM-DD&to=YYYY-MM-DD` | `from`, `to`, `practiceCount`, `practiceSeconds`, `practiceDays`, `currentStreakDays`, `averageTotalScore`, `previousPeriod{practiceSeconds, practiceCount, averageTotalScore}`, `completedMissionCount`, `totalMissionCount` |
| GRO-02 날짜별 | `GET /users/me/growth/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD` | `items[]{date, practiceSeconds, practiceCount}`. `from`~`to`의 모든 날짜를 기록 없는 날도 0으로 채워 날짜 순서로 준다 |

- **기간:** `from`·`to`는 KST 날짜이고 양 끝을 포함한다. 둘 다 필요하고 `from` ≤ `to`, 최대 366일이다. 연도는 1001~9998년이다(DB 시각 범위). 어기면 400 `INVALID_REQUEST`.
- **날짜 소속:** 구간과 연주 세션은 시작 시각의 KST 날짜에 속한다.
- **지난 기간(`previousPeriod`):** `from` 바로 앞의 같은 일수 구간. 주 보기면 지난주다. 월 보기에서는 지난달과 날짜 수가 다를 수 있다(예: 10월 31일치의 지난 기간은 8/31~9/30).
- **미션 수:** 미션이 구현되기 전에는 `null`이다(Notion 규칙 5).
- **곡별 최고점(`bestBySong`)·항목별 성장(`metricGrowth`):** 비교 집단 규칙이 정해지지 않아 별도 Task에서 구현한다. 그 전에는 응답에 없다.

값:

| 칸 | 값 |
| --- | --- |
| `practiceSeconds` | 기간 안에 시작한 구간의 `counted_seconds` 합(초). 앱이 분으로 내림해 보여 준다 |
| `practiceCount` | 기간 안에 시작해 분석이 끝난(`DONE`) 연주 세션 수. `FAILED`와 녹음 중 그만둔 연주는 빼고, 연습 기록 저장 여부(`saved_at`)는 따지지 않는다 |
| `averageTotalScore` | 같은 `DONE` 세션 중 평가가 있는 세션의 총점 평균(소수점 반올림 정수). 없으면 `null` |
| `practiceDays` | 기간 안의 연습한 날 수 |
| `currentStreakDays` | 오늘(KST)부터 거꾸로 이어진 연습한 날 수. 오늘 아직 연습하지 않았으면 어제부터 센다. 어제도 하지 않았으면 0이다. `from`·`to`와 관계없다 |

- **연습한 날:** 그날(KST) 시작한 구간의 인정 시간 합이 1분 이상인 날. 녹음 여부는 따로 보지 않는다(녹음도 악보 화면에서 하므로 시간에 들어 있다). Notion 원안의 'DONE 세션이 있는 날'은 녹음 없이 연습한 날을 빼고 연습 시간과 기준이 달라 고르지 않았다(2026-10-28 사용자 결정).
- **앱의 주·월 탭:** 주는 KST 월요일~일요일이고 막대는 요일별 7개다. 월은 달력 월이고 막대는 그 달의 날짜를 월~일 단위로 묶은 주차별 4~6개다(1일이 든 주가 1주차, 앞뒤 달 날짜는 뺀다). 앱은 요약을 `summary`로, 막대를 `calendar`의 날짜별 값을 더해 그린다. 변화 표시(지난 기간과의 차이)는 앱이 `previousPeriod`로 계산한다. 평균 변화는 두 쪽 평균이 모두 있을 때만 보여 준다.
- **분 표시:** 요약 칸은 합계를 내림하고 막대는 각각 내림하므로, 요약 칸과 막대 합이 1~2분 다를 수 있다. 막대를 먼저 내림해 더하면 합계가 실제보다 작아져서 고르지 않았다.
- 고르지 않은 것: 서버가 주·월 기간과 막대를 정하는 `GET /me/stats`(2026-10-27 초안. Notion 명세의 `from`·`to` 방식에 맞췄다), "지난주 같은 요일까지"와 비교, 10초 이상 체류를 연습한 날로 보기(잠깐 열어 본 날이 연속 기록에 들어간다).
