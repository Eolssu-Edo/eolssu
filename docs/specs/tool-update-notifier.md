## 동작

Windows 트레이와 macOS 메뉴 막대의 같은 앱으로 제공한다. 앱은 Graphify 발행본을 조회하거나 다운로드하지 않는다. 기존 앱이 사용하던 프로젝트의 Graphify 폴더가 있으면 **Graphify 정리**를 표시한다. 한 번 누르면 Git에 추적되지 않는 앱 관리 폴더를 OS 휴지통으로 옮긴다. 완료 즉시 카드를 숨기고 앱 재실행 후에도 정리된 폴더에 대해서는 숨긴다. 정리에 실패하면 이유와 재시도 버튼을 표시한다. 여러 체크아웃은 기존 프로젝트 선택에서 하나씩 정리한다. 일반 코드 탐색으로 돌아간다.

COCO는 공식 npm의 @thisis-joe/coco-skills 전체 배포 목록을 조회한다. 프리릴리스도 포함하고 latest 태그 이동만으로 새 배포를 만들지 않는다. 최초 실행에는 최신 기존 배포 하나를 안내하고 이후 새로 생긴 모든 버전을 한 알림으로 묶어 안내한다. 재시작 후에도 이력을 보존한다. SSH 실패와 npm 실패는 독립적으로 처리한다.

COCO 수동 설치·업데이트는 제목 오른쪽 한 줄에서 배포 버전·설치 대상·현재 프로젝트/전역 위치를 선택해 실행한다. 새 배포가 목록의 맨 위로 오면 닫힌 선택 칸도 즉시 새 버전을 선택한다. 최신 배포가 같으면 직접 고른 버전을 유지한다. 새 설정의 설치 대상은 Codex/Claude이며 저장된 선택은 유지한다. 자동 반영을 켜면 저장한 설치 범위에 프리릴리스를 포함해 버전 우선순위가 가장 높은 COCO를 적용한다. 같은 대상에 이미 적용한 버전은 반복 설치하지 않으며 실패 후 5분 간격으로 재시도한다. 이전 Graphify 전용 자동 다운로드 선택을 COCO 설치 동의로 승계하지 않는다. 공식 npm CLI의 install 명령에 정확한 버전과 명시적 범위를 전달한다. 설치 위치 선택을 생략해 전역으로 빠지거나 --remove-global로 기존 전역 설치를 자동 삭제하지 않는다. 공식 설치 도구가 개인 변경·다른 스킬 충돌을 거부하면 그 실패를 보존한다. 개인 스킬을 실제 바꾸는 검증은 하지 않고 격리된 --dest로 공식 설치 동작을 확인한다.

앱은 네이티브 알림 버튼·설정 창·지금 확인·종료를 제공한다. 화면에는 헤더·홍보 문구·로고를 두지 않는다. 업데이트·연결은 동작을 가로로 배치한 620×440 창을 사용한다. 웹 탭에서는 현재 화면에 맞춰 최대 1100×760으로 넓히고 각 페이지를 처음 열 때 80% 배율을 적용한다. 설정·알림 이력은 OS 사용자 데이터 폴더에 저장하고 SSH 키·비밀번호는 앱 설정에 저장하지 않는다. 다운로드용 공개 포트나 서버 push 서비스를 추가하지 않는다. 설치 실행 파일·node_modules은 Git 제외한다.

## 완료 조건

1. Windows/macOS 빌드 파일을 만들고 실제 실행한 플랫폼·미검증 플랫폼을 구분한다.
2. 기존 앱이 받은 그래프를 한 번 눌러 휴지통에 옮긴다. 추적 파일·심볼릭 링크·다른 파일이 섞인 폴더는 보존한다. 성공 후 카드를 숨기고 실패 후에는 다시 누를 수 있다.
3. npm의 프리릴리스·정식 배포를 모두 감지하고 재시작·태그 변경·오프라인 후 중복 없이 처리한다. 최신 배포가 바뀌면 접힌 선택 칸을 갱신한다.
4. 선택한 COCO 버전·런타임·범위를 공식 CLI에 전달하고 실패/부분 성공을 명확히 표시한다.
5. macOS 실제 설정·알림·정리 버튼·로그인 실행 설정을 확인한다. Windows 실제 표시 검증은 Windows 실행 환경이 있어야 한다.
6. 생성 결과는 Git에서 제외하고 사용·설치·복구 방법을 문서로 제공한다.

## 추가 확정 범위

폰 APK·태블릿 APK는 사용자 확인대로 같은 최신 공용 QA APK를 받는다. 아이폰 IPA는 별도 최신 게시 파일을 받는다. 서버 index의 배열 순서를 믿지 않고 builtAt을 정렬한다. 크기·SHA-256을 확인한 임시 파일만 목적지로 이동한다.

업데이트·연결, QA, 블로그, Grafana, Prometheus, Jenkins, DB, n8n, PlayStore출시 탭을 제공한다. QA와 블로그는 각각 https://15.165.144.7/qa, https://team-edo.github.io/ 를 앱 안에서 연다. 운영 도구는 각자의 localhost 포트(13000, 13001, 18080, 18081, 15688)를 연다. DB는 localhost:18081에서 edo1 루프백의 8081로 포워딩한다. 로딩 중이거나 응답이 없거나 빈 페이지인 경우 중앙에 SSH edo1 연결을 표시한다. 연결 카드와 운영 탭의 SSH 버튼은 같은 edo1 터미널 연결을 사용한다. 운영 도구의 루프백 포트를 함께 열고, 운영 탭에서 연결했다면 해당 포트를 확인한 뒤 페이지를 자동으로 다시 시도한다.

각 웹 화면은 별도 세션과 WebContentsView에서 해당 출처의 페이지 이동만 허용한다. 외부 페이지에 preload·Node·로컬 IPC를 주지 않고 HTTPS 인증서 검증을 유지한다. 선택된 탭의 view만 표시하고 연결 실패 시 다시 연결하거나 기본 브라우저로 열 수 있다. PlayStore출시는 사용자가 지정한 Doply 페이지를 OS 기본 브라우저에서 연다. 승인된 팀 전용 설치 파일에 키가 포함된 링크 자원을 넣으며 Git·로그에서는 제외한다. 링크가 없는 빌드의 기기별 등록은 OS 암호화 저장소를 사용한다.

APK·IPA 다운로드 카드를 왼쪽, edo1·edo2 터미널 연결 카드를 바로 오른쪽에 배치한다. 프로젝트 폴더 선택은 그 아래 설정 카드에 둔다. 모든 업데이트 자동 반영과 로그인 시 실행은 맨 아래 카드 밖에 나란히 두고, 선택 즉시 저장한다. 기존 사용자 SSH 별칭을 사용하고 다운로드 호스트 입력란은 두지 않는다. 헤더·화면 로고·홍보 문구와 정식/프리릴리스 안내 문구는 사용자의 UI 피드백에 따라 제거한다. 배포 감지 범위는 모든 버전으로 유지한다.
