# 저장한 기록의 녹음 보관과 미저장 녹음 30일 정리

- Jira: S15P31E102-375(Epic S15P31E102-14). 결정·진행: [375 계획](../plans/S15P31E102-375.md). 앞선 결정: [342 계획](../plans/S15P31E102-342.md) 결정 3·13.
- 상태: 사용자 승인 계약(2026-11-02). clarify 결정 1~12와 새 판 문구를 확정했고, 새 판은 사전 고지 없이 배포 즉시 시행한다(결정 8·9 변경).
- 바꾸는 계약: [녹음 파일 규격](recording-file.md) '보관', [약관 공개](terms-release.md), [연습 기록 API](practice-records.md) '녹음 보관 정책과의 관계', [녹음 저장소 운영](../../infra/storage/README.md), [backend README](../../backend/README.md) R2 설정.

## 목적

회원이 '연습 기록 저장'한 연주의 녹음은 나중에도 다시 들을 수 있게 남긴다. 저장하지 않은 녹음은 지금처럼 업로드 30일 뒤 지운다. 보유기간이 늘어나므로 처리방침 새 판을 시행한 뒤에만 저장한 녹음을 30일 넘게 남긴다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 저장한 녹음 | `saved_at`이 있고 `record_deleted_at`이 없는 세션의 `recording_url`([연습 기록 API](practice-records.md)의 '기록') |
| 미저장 녹음 | `saved_at`이 없는 세션의 `recording_url` |
| 30일 경과 | 서버 UTC 기준 `ended_at` + 30일 < 지금. 정확히 30일인 순간은 아직 경과가 아니다. `ended_at`은 업로드 성공 시각이다 |
| 시행일 | 처리방침 새 판을 운영에 배포해 `current`로 공개한 날(KST). 새 판 버전 이름도 이 날짜(`YYYY-MM-DD`)다. 사전 고지 없이 즉시 시행한다(아래 '회원 고지') |

## 동작

### 미저장 녹음 정리 작업

1. 매일 04:30(Asia/Seoul)에 돈다. 탈퇴 일괄 삭제(04:00)·백업(매시 10분)과 겹치지 않게 하고, 세션 단위의 짧은 트랜잭션으로 처리한다.
2. 대상은 미저장 녹음 중 30일 경과한 세션이다. 분석 상태(`PENDING`·`DONE`·`FAILED`)는 따지지 않는다.
3. 세션마다 먼저 조건부 갱신으로 `recording_url`을 비운다. 조건은 `id`, 읽은 `recording_url`과 같음, `saved_at IS NULL`, 30일 경과다. 갱신이 0행이면 그사이 저장됐거나 바뀐 것이므로 건너뛴다.
4. 갱신에 성공한 세션만 저장소에서 그 키를 지운다. 없는 키는 성공이다(저장소 계약).
5. 파일 삭제가 실패하면 `recording_url`이 아직 비어 있을 때만 원래 키로 되돌린다. 다음 실행에서 다시 대상이 된다. 되돌리기 전에 저장됐다면 녹음이 남아 저장한 녹음으로 보관된다.
6. 저장소 키·서명 URL은 로그에 남기지 않는다. 실행 결과는 지움·건너뜀·되돌림·DB 오류 수와 걸린 시간만 남긴다.
7. 이 작업은 저장소 종류와 관계없이 돈다. 시행일을 보지 않는다.

| 상황 | 결과 |
| --- | --- |
| 미저장, 30일 경과 | `recording_url` NULL, 파일 삭제 |
| 미저장, 정확히 30일 또는 그 전 | 변화 없음 |
| 저장한 기록(경과 여부 무관) | 변화 없음 |
| 작업이 비운 직후 저장(API로만 가능) | 저장은 성공하고 `recordingAvailable`은 false. 앱 결과 화면은 연습 직후에만 열려 생기지 않는다 |
| 작업이 읽은 뒤 비우기 전에 저장 | 조건부 갱신 0행, 녹음 보관 |
| 파일 삭제 실패 | 키를 되돌리고 다음 날 재시도 |
| 비운 뒤 삭제 전에 프로세스 중단 | 객체가 남는다(아래 '알려진 제약') |

### 시행일 전과 후

- 새 판 배포 전: R2 `recordings/` 30일 수명 주기 규칙과 `eolssu-r2-purge` cron이 저장 여부와 관계없이 30일 뒤 지운다(현행 처리방침). 정리 작업도 미저장 녹음을 같은 기준으로 지운다.
- 새 판 배포 뒤 운영 전환(아래 '운영 절차')을 마치면 저장한 녹음은 회원이 기록을 지우거나(REC-04) 탈퇴 일괄 삭제가 끝날 때까지 남는다.
- 로컬 저장소 모드는 바꾸지 않는다. 모든 녹음을 30일 뒤 읽기 거절·정리하며, 이때 공개되는 `2026-10-30` 처리방침도 30일 보관이다.

### 처리방침 새 판

- `backend/src/main/resources/legal/<시행일>/`에 다섯 문서를 둔다. `service`·`privacy`·`collection`은 아래 문구로 바꾸고 시행일을 고친다. `age`·`permissions`는 시행일만 고친다.
- R2(S3) 저장소에서는 배포하는 순간부터 `/api/terms/documents/current/{문서}`가 새 판이다. `2026-11-02`는 이전 버전 이력으로 계속 열린다. 시각으로 바꾸는 장치는 두지 않는다. 로컬 모드에서는 새 판을 공개하지 않는다(현행 규칙과 같음).
- 버전 이름은 실제 운영 배포일과 같아야 한다. 병합·배포가 이름의 날짜보다 늦어지면 병합 전에 폴더·상수 이름을 배포일로 고친다([333 계획](../plans/S15P31E102-333.md)의 시행일 이동과 같은 이유).
- 가입 동의 목록(`terms` 행)은 운영자가 배포 직후 새 판 4개 코드(`AGE_OVER_14`·`SERVICE_TERMS`·`PRIVACY_COLLECTION`·`MICROPHONE_NOTICE`)를 `effective_at` = 넣는 시각으로 넣는다. 기존 조회가 `effective_at <= 지금`으로 고르므로 그때부터 새 판 동의를 받는다. 기존 회원 재동의 흐름은 없다([333 계획](../plans/S15P31E102-333.md)과 같음).

바꿀 문구(2026-11-02 사용자 확정). 보관 기간을 적은 네 문장만 바꾸고 나머지 문장은 그대로 둔다.

| 문서·위치 | 지금(`2026-11-02`) | 새 판 |
| --- | --- | --- |
| privacy 1항 연주 분석·채점 | 원본은 업로드 후 30일이 지나면 삭제합니다. | 원본은 업로드 후 30일이 지나면 삭제합니다. 다만 '연습 기록 저장'한 연주의 녹음은 그 기록을 삭제하거나 탈퇴 삭제가 끝날 때까지 보관합니다. |
| privacy 4항 국외 이전 '보유·이용 기간' | 업로드 후 30일(저장소 정리 주기에 따라 최대 약 1일 지연). 그 전에 개별 삭제 처리 또는 탈퇴 삭제가 완료되면 먼저 삭제 | 업로드 후 30일(저장소 정리 주기에 따라 최대 약 1일 지연). 저장한 연습 기록의 녹음은 그 기록을 삭제하거나 탈퇴 삭제가 끝날 때까지. 그 전에 개별 삭제 처리 또는 탈퇴 삭제가 완료되면 먼저 삭제 |
| collection 연주 녹음 문단 | …업로드 후 30일이 지나면 삭제합니다(저장소 정리 주기에 따라 최대 약 1일 지연). | 이 문장 뒤에 "저장한 연습 기록의 녹음은 그 기록을 삭제하거나 탈퇴 일괄 삭제 시까지 보관합니다."를 붙인다 |
| service 6항 마지막 문장 | 녹음 원본의 업로드 후 30일 보관 정책은 별도이며 탈퇴 취소로 연장되거나 복원되지 않습니다. | 저장하지 않은 녹음 원본은 업로드 후 30일이 지나면 삭제되고 탈퇴 취소로 복원되지 않습니다. 저장한 연습 기록의 녹음은 기록을 삭제하거나 탈퇴 삭제가 끝날 때까지 보관됩니다. |

그대로 두는 것: privacy 3항(저장 위치·서명 주소·임시파일·이용 제한·복원 불가), 4항의 '기존 녹음'(이전 시기와 방법) 문장·이전받는 자·국가·항목·목적·거부 방법·위탁 목록, 5항 탈퇴·파기(일괄 삭제 때 저장한 녹음도 지운다). Play 데이터 보안 설문은 수집 항목·공유 여부가 바뀌지 않아 고치지 않는다.

### 회원 고지

- 이번 변경은 사전 고지와 회원 메일 없이 즉시 시행한다(2026-11-02 사용자 결정). 앞서 정한 30일 전 게시·메일 세 번 계획을 대체한다.
- 근거: 운영 회원은 3명(모두 ACTIVE, 2026-10-29~11-02 가입)으로 개발 중 계정이며 실사용자가 없다([333 계획](../plans/S15P31E102-333.md)의 판단과 같음). 서비스 약관 8항의 사전 고지(일반 7일·중요 30일)는 실사용자가 생긴 뒤의 변경부터 지킨다.
- 실사용자가 생긴 뒤 다시 바꾸게 되면 이 예외를 쓰지 않는다.

### 앱 문구

저장 확인 시트의 보관 안내는 "저장한 기록의 녹음은 직접 지울 때까지 보관돼요"로 한다. 화면은 359·369가 만든다. 새 판이 먼저 배포되므로 문구 분기는 없다.

## 운영 절차

각 단계는 사용자 승인 뒤, 배포 잠금 `/run/lock/eolssu-backend-deploy.lock` 아래에서 변경 전 백업을 받고 한다. 결과는 375 계획 문서에 남긴다.

1. **배포 확인:** 새 판과 정리 작업이 배포됐는지, `current/privacy`가 새 판이고 `2026-11-02` 주소도 200인지 확인한다. `terms` 새 판 4행을 넣는다.
2. **전환:** ① Cloudflare 대시보드에서 `eolssu-recordings`의 `recordings/` 수명 주기 규칙을 지운다(계정 소유자). ② `/etc/cron.d/eolssu-r2-purge`를 지운다. ③ R2 규칙으로 이미 파일이 지워진 저장한 녹음 수를 조회한다(`saved_at` 있음, `ended_at`이 30일 전 이전). 저장 기능이 2026-11-02에 배포됐으므로 2026-12-02 전에 전환하면 0건이다. 0건이 아니면 객체가 실제로 없는지 확인한 뒤 `recording_url` 정리를 따로 승인받는다.
3. **확인:** 다음 날 정리 작업 실행 로그를 확인한다. 30일 경과한 저장 녹음이 생기면 R2에 남아 있는지 확인한다(그 전에는 해당 없음).

## 범위

- 포함: 정리 작업, 처리방침 새 판(즉시 시행), 문서 정정, 운영 절차와 결과 기록, 노션 REC-01~04 문안.
- 하지 않음: R2 객체 이동, 고아 객체 정리, 시행일 설정값·시각 전환, 사전 고지·회원 메일, 앱 공지 기능, 로컬 저장소 변경, REC-01~04·PRA-03 응답 변경, 앱 화면(369), 마이그레이션.

## 유지하는 동작

- REC-01~04 계약과 재생 가능 판단(녹음 경로 있음·기록 삭제 안 함, 30일 판단 없음).
- REC-04의 즉시 삭제, 탈퇴 일괄 삭제의 녹음 삭제, 업로드 만료(40분) 배치, 업로드 실패 때 자기 객체 삭제.
- `2026-10-30`·`2026-11-02` 문서 본문과 그 공개 규칙(새 판 시행 뒤 `2026-11-02`는 이전 버전 이력).

## 알려진 제약

- 수명 주기 규칙을 지운 뒤에는 DB가 가리키지 않는 객체를 지우는 것이 없다. 업로드 저장 뒤 DB 갱신과 자기 객체 삭제가 둘 다 실패하거나, 정리 작업이 비운 뒤 파일을 지우기 전에 멈추거나, 파일 삭제가 실패한 사이에 탈퇴 삭제·기록 삭제로 되돌릴 행이 없어질 때만 생긴다. 마지막 경우는 세션 ID 경고 로그를 남기고 `failed`로 센다.
- 로컬 저장소 모드에서 저장소 키 형식이 아닌 오래된 값(예: `https://…`)은 삭제가 거절돼 매일 비웠다 되돌린다(`restored`가 줄지 않는다). R2에서는 없는 키 삭제가 성공이라 해당하지 않는다.
- 로컬 저장소 모드로 되돌리면 저장한 녹음도 30일 뒤 정리되고 `recording_url`은 남는다(그때 공개 처리방침과 같다).
