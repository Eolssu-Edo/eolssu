# 약관 공개와 국내 녹음 저장

- Task: S15P31E102-300. 사용자 결정: 2026-10-30 국내 운영 서버의 비공개 디스크로 녹음 저장 전환 승인.
- 운영 주체: 이도(Edo). 연락처는 Notion 지정 네 토글과 약관 제공 준비 문서를 따른다.
- 탈퇴 요청 후 30일 유예·로그인 취소를 유지한다.
- 추가 승인: Naver SMTP를 출시 기본으로 준비하고 Gmail SMTP는 확장으로 유지한다. 문의 처리 완료 후 90일, 일반 로그 14일, 개인정보 관리자 접근기록 1년, DB 백업 최대 30일로 정한다. 정책 확정과 운영 적용 완료를 구분한다.

## 구현 계약

1. 로컬 저장은 명시적으로 `RECORDING_STORAGE_TYPE=local`일 때 선택한다. 기존 S3 구현은 이관 검증 전 보존한다.
2. 녹음 키와 DB 참조는 유지한다. 저장 루트는 웹 공개 경로와 분리하고 backend 전용 계정만 접근한다.
3. 읽기는 기존 15분 만료 URL 계약을 유지하는 HMAC 서명 GET으로 제공한다. 변조·만료·삭제·업로드 30일 경과 파일은 반환하지 않는다. 경로 이탈·심볼릭 링크를 거절한다.
4. 원본은 업로드 후 30일이 되면 읽기를 막고 정기 정리한다. 탈퇴 배치는 같은 저장소의 삭제 구현을 사용한다.
5. 앱 외 삭제 안내는 로그인·DB 없이 공개한다. 이메일로 계정·개별 자료 삭제를 접수하고, 등록 이메일 소유를 확인한다. 비밀번호·인증번호를 이메일로 요구하지 않는다.
6. 공개 문서 및 서명 읽기 경로만 GET 공개 목록에 추가한다. 회원 API 인증은 유지한다. 서명 읽기 쿼리는 프록시 접근 로그에 남기지 않는다.

## 검증 및 운영 전환

격리 임시 디렉터리에서 저장·읽기·삭제·경로 이탈·서명 변조·만료·30일 경계를 검사한다. 실제 HTTP로 익명·잘못된 쿠키의 공개 문서 접근과 보호 API의 401을 검사한다.

운영 전환 전 R2 객체와 DB 키를 대조하고 업로드 시각·크기·해시를 보존해 국내 디스크로 복사한다. 업로드를 일시 중지하고 누락·중복·만료를 재대조한 뒤 설정을 전환한다. R2 원본 삭제는 국내 사본과 실제 분석·삭제 검증 후 별도 확정한다. 전환을 검증하기 전 ‘국내 저장 전환 완료’로 게시하지 않는다.

메일 전송·문의, 소셜 제공자와 백업은 녹음 저장 전환만으로 국내 처리로 바뀌지 않는다. 해당 처리 경로의 고지는 별도로 실제 계약·처리 조건에 맞춘다.

## 2026-10-30 변경: R2 복귀와 국외 이전 고지 (S15P31E102-333)

위 국내 디스크 저장 결정을 대체한다. 원래 결정과 근거는 위에 그대로 둔다.

- 사용자 결정(2026-10-30): 운영 서버 디스크 단독 저장은 DB·앱과 같은 장애 범위에 묶여 위험하다. AWS S3는 계정 권한이 없어 쓸 수 없으므로 Cloudflare R2로 되돌리고 처리방침에 국외 이전을 고지한다. 실사용자·스토어 심사 이력이 없어 사전 공지 기간 없이 시행한다.
- 새 약관 버전 `2026-10-31`(시행일 2026-10-31 KST). 처리방침 1항의 녹음 보관 문장(삭제 지연 약 1일, 읽기 중지 문구 제거)과 3·4항, 수집 동의의 녹음 보관 문장만 바꾸고 나머지 본문은 시행일 외에 같다. 이전 국가는 사용자 선택에 따라 "미국 및 Cloudflare 아시아·태평양 지역 데이터센터 소재 국가"로 적는다. R2 버킷은 APAC 위치 힌트만 있어 국가를 특정할 수 없다. 근거는 개인정보 보호법 제28조의8제1항제3호(계약 이행 보관 위탁, 처리방침 공개)이며 법률 검토는 운영 담당자가 확인한다.
- 공개 조건: local 저장소에서는 `2026-10-30`만, R2(s3) 저장소에서는 `2026-10-31`을 현행으로 공개하고 `2026-10-30`은 이전 버전 이력으로 남긴다. 저장소가 없거나 R2 값이 빠지면 모두 503이다. 국외 이전 고지가 디스크 운영 중에 먼저 보이거나, R2 운영 중에 국내 저장 고지만 보이는 상태를 만들지 않는다.
- 앱 마이페이지와 Play Console은 `/api/terms/documents/current/{문서}`를 연결한다. 실제 저장소에 맞는 현행 버전을 보여 주므로 병합·배포 시점과 저장소 전환 시점이 달라도 링크가 끊기지 않는다. 동의 기록의 본문 주소는 버전 고정 주소를 유지한다.
- 순서: 처리방침 공개·시행(2026-10-31 00:00 KST 이후, 저장소 전환과 동시) 뒤에만 기존 녹음을 R2로 복사한다. 새 업로드도 전환 뒤에만 R2로 간다.
- 30일 보관: 백엔드가 새로 올린 녹음은 R2 수명 주기 규칙(업로드 후 30일)으로 지운다. 디스크에서 옮긴 녹음은 R2 업로드 시각이 새로 찍히므로 원래 업로드 시각을 객체 메타데이터 `original-uploaded-at`에 남기고, 이관 도구의 `--purge-expired --delete`를 매시 실행해 그 시각 기준 30일에 지운다. 30일이 지난 디스크 파일은 옮기지 않는다.
- 복사와 디스크 정리는 DB의 현재 녹음 참조(`recording_url` 있고 `record_deleted_at` 없음)를 기준으로 한다. DB에서 삭제된 녹음은 R2로 복사하지 않고 디스크에서만 지운다. DB가 참조하는 미만료 녹음은 복사 기록에 있고 R2에서 크기·SHA-256으로 확인돼야 디스크에서 지운다. R2에 없다는 사실만으로는 삭제를 판단하지 않으며, 하나라도 어긋나면 아무것도 지우지 않는다. 디스크 정리는 R2 객체를 지우지 않는다.
- 처리방침의 이전 시기에는 시행일의 기존 녹음 일괄 이전과 원래 업로드 시점 기준 30일 삭제를 함께 적는다.
- 운영 순서와 명령은 [녹음 저장소 운영 문서](../../infra/storage/README.md#r2-복귀-s15p31e102-333)를 따른다.
