# 곡 목록 악기 필터 (S15P31E102-408)

상태: 2026-11-03 사용자 요청과 Jira 408의 구현 범위. Story S15P31E102-24, 선행 407의 네 악기 공개와 별도 작업이다.

- `GET /api/songs?instrumentId=...`는 선택한 활성 악기의 PUBLISHED·미삭제 곡만 ID 오름차순으로 반환한다. 생략하면 기존 전체 목록을 유지한다.
- ID는 선행 0 없는 양의 Long 십진 문자열이다. 빈 값·0·음수·공백·비숫자·범위 초과는 400 `INVALID_REQUEST`, 없는/비활성 악기는 404 `RESOURCE_NOT_FOUND`, 활성 악기의 곡이 없으면 200 빈 목록이다.
- 응답의 문자열 ID, 정수 scoreVersion, 원본 score, 기존 songId 기반 악보·모범 음원 경로를 보존한다. 저장 데이터·게시 상태·인증 정책을 바꾸지 않는다.
- FE의 AI 평가 곡 목록과 연습용 제공 곡 목록은 `/api/instruments`에서 받은 이름·ID로 전체 및 악기 선택을 제공한다. DB ID를 enum 순서나 상수로 만들지 않으므로 정악/산조대금을 구별한다. 네 악기 노출은 407의 활성 카탈로그에 의존한다.
- 기본은 전체다. 악기 변경은 서버에 필터를 전달하고 이전 곡·선택을 즉시 비운다. 진행 중 요청을 취소하고 늦은 응답이 새 선택을 덮어쓰지 못하게 한다. 실패와 빈 목록을 구분하며 재시도는 현재 악기를 유지한다. 악기 변경 때 검색어·난이도는 유지하고, 검색 조건 초기화는 악기까지 전체로 되돌린다. AI 목록의 평가 가능 조건과 연습 목록의 전체 제공 곡 조건은 유지한다.
- 검증: 컨트롤러 ID/상태 검사, 실제 MySQL+HTTP의 악기별/생략/숨김·삭제/원본 악보·모범 음원 연결, FE HTTP 파라미터와 선택·경합·재시도, BE clean build/databaseTest, FE Android host 및 Web 검사. 후속 사용자 요청에 따라 407이 병합된 develop 통합·Push·MR 생성까지 포함한다. 운영 배포·운영 DB 적용은 제외한다.

기존 응답 계약은 [카탈로그 API](catalog-read-apis.md)를 따른다.
