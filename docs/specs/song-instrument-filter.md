# 곡 목록 악기 필터 (S15P31E102-408)

상태: 2026-11-03 사용자 요청과 Jira 408의 구현 범위. Story S15P31E102-24, 선행 407의 네 악기 공개와 별도 작업이다.

- `GET /api/songs?instrumentId=...`는 선택한 활성 악기의 PUBLISHED·미삭제 곡만 ID 오름차순으로 반환한다. 생략하면 기존 전체 목록을 유지한다.
- ID는 선행 0 없는 양의 Long 십진 문자열이다. 빈 값·0·음수·공백·비숫자·범위 초과는 400 `INVALID_REQUEST`, 없는/비활성 악기는 404 `RESOURCE_NOT_FOUND`, 활성 악기의 곡이 없으면 200 빈 목록이다.
- 응답의 문자열 ID, 정수 scoreVersion, 기존 songId 기반 악보·모범 음원 경로를 보존한다. 목록 항목의 원본 score는 S15P31E102-419에서 제외했고 상세·CAT-04가 반환한다. 저장 데이터·게시 상태·인증 정책을 바꾸지 않는다.
- 2026-11-03 실기기 확인 후 사용자 결정: 악기는 가입·마이페이지에서 정한다. FE의 AI 평가 곡 목록과 연습용 제공 곡 목록은 그 악기의 곡만 자동 조회하며 별도의 악기 선택 버튼을 표시하지 않는다. `/api/instruments`의 code로 실제 ID를 찾으며 DB ID를 enum 순서나 상수로 만들지 않는다. 정악/산조대금을 구별한다.
- 마이페이지의 악기 변경은 서버 저장 성공 후 공유 악기 상태에 반영한다. 저장 중 중복 요청을 막고 실패를 표시하며 기존 선택을 보존한다.
- 앱 재시작에서도 같은 설정을 사용하도록 첫 실행을 마친 계정의 정보를 공통 진입점에서 한 번 복구한다. 복구 중에는 대기 화면, 일시 실패에는 재시도를 제공하며 401이면 로그인 화면으로 안내한다. 마이페이지 조회·저장의 401도 로그인 복귀로 처리한다. 서버 인증·쿠키 정책은 바꾸지 않는다.
- 후속 실기기 인증 장애: Android OAuth URL은 Custom Tabs 서비스를 지원하고 해당 HTTPS 주소를 열 수 있는 외부 브라우저에 전달한다. 지원되는 기본 브라우저를 우선하고, 기본 링크 처리 앱이 해당 기능을 제공하지 않으면 설치된 지원 브라우저를 선택한다. 지원 브라우저가 없으면 기존 브라우저 없음 안내를 사용한다. 앱 내부 WebView·무조건 기본 링크 처리 앱으로의 fallback을 사용하지 않으며 서버의 state·PKCE·콜백 검증은 유지한다.
- 악기가 바뀌면 이전 곡·선택을 비우고 다시 조회한다. 진행 중 요청을 취소하고 늦은 응답이 새 선택을 덮어쓰지 못하게 한다. 악기를 확인할 수 없으면 전체 곡으로 대체하지 않는다. 실패와 빈 목록을 구분하며 재시도는 현재 악기를 유지한다. 검색어·난이도는 악기 변경 때 유지하고, 검색 조건 초기화는 검색어·난이도만 되돌린다. AI 목록의 평가 가능 조건과 연습 목록의 평가 가능 여부와 무관한 제공 곡 조건은 유지한다.
- 검증: 컨트롤러 ID/상태 검사, 실제 MySQL+HTTP의 악기별/생략/숨김·삭제/원본 악보·모범 음원 연결, FE HTTP 파라미터와 선택·경합·재시도, BE clean build/databaseTest, FE Android host 및 Web 검사. 후속 사용자 요청에 따라 407이 병합된 develop 통합·Push·MR 생성까지 포함한다. 운영 배포·운영 DB 적용은 제외한다.

기존 응답 계약은 [카탈로그 API](catalog-read-apis.md)를 따른다.
