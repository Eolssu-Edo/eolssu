# 곡별 장단 반주와 굿거리 굴림

S15P31E102-160·340. 2026-11-04 사용자 승인 범위. 기존 카탈로그·율명 업무는 유지한다.

## 동작과 경계

- 160은 등록10종의 미리듣기 M4A, 공통 타격6개, 굿거리의 현행5단계(기준4분음표99, 적용59/79/99/109/119)에 맞는 약1017/759/606/550/504ms 굴림5개와 107개 곡의 검수 자료를 전달한다. 원본·가공·잔향·청음 상태를 구분한다.
- BE491은 검수된 음원과 곡별 반주 정보를 API로 제공하고 판본·의미 해시·카탈로그 패턴을 보호한다.
- FE340은 검수된 곡별 장단을 선택한 연습 속도에 맞춰 실제 소리로 재생한다. 등록10종의 미리듣기와 기존 모범 연주 배속을 유지한다.
- 곡별 검수 결과에는 악보 판본/원본 식별자, 장단 ID, 시작tick, 패턴1주기에 대응하는score tick 길이, 근거 또는 미연결 사유가 필요하다. 제목·장단명만으로 자동 매칭하거나 악보·음원BPM을 덮어쓰지 않는다.
- 이름 없는45개와 음악적 주법이 미검수인 세령산은 근거 없이 소리를 붙이지 않는다. 검수 가능한 곡부터 연결하고 나머지는 사유를 명시한다.
- 모범 연주에서는 실제 미디어 위치/수행 시간표를 기준으로, 연습에서는 현재 악보 위치/선택BPM을 기준으로 소리를 예약한다. 일시정지·탐색·구간반복·배속·화면이탈·백그라운드·계정변경에서 이전 예약과 소리를 정리한다.
- 평가 녹음의 기존 마이크 유입 방지 정책을 보존한다. 실제 악기 연주 속도 자동 추종은 범위 밖이다.
- API 확장이 필요하면 기존 필드 의미를 보존하는 선택적 반주 메타데이터로 제공하고, 검수되지 않은 악보와 구버전 응답에서는 반주를 사용하지 않는다.

### 160 전달물과 BE491·FE340 소비 계약

160의 [곡별 검수 결과](../knowledge/data/jangdan-song-review.md)는 `backend/src/main/resources/catalog/jangdan-playback.json`에 둔다. 107개 판본 중 구조 검수60개와 장단명 미상45개·세령산 굴림 미검수2개의 사유를 명시한다. 미리듣기 M4A는 비공개 R2의 `jangdan-preview/v1/{id}/{sha256}.m4a`에 게시하고 서버 리소스에는 ID별 SHA-256을 둔다. 연습용 AAC-LC M4A 11개는 비공개 R2 `jangdan-practice/v1/{sample}/{sha256}.m4a`에 게시한다. 서버에는 샘플명·해시 목록을, 앱에는 `files/jangdan/manifest.json`과 이용 조건을 제공한다. 앱은 연습 시작 전에 필요한 샘플만 내려받아 길이·해시 검증 후 캐시하고 SoundPool에 로딩한다. 캐시가 유효하면 서버 요청을 생략한다. 160은 원본 PCM과 곡별 검수를 담당했고, 492는 M4A 변환·생성 명세·R2 게시를 담당한다. 서버 API는 491, Android 캐시는 340에서 연결한다.

악보 의미 해시의 공통 형식은 `typed-tree-sha256-v1`이다. null=`n`, boolean=`t/f`, 숫자=`d`+뒤0/지수 제거한10진수+`;`, 문자열=`s`+UTF-8바이트길이+`:`+문자열, 배열=`[`+요소+`]`, 객체=`{`+UTF-16키순으로 정렬한 문자열키·값+`}`를 UTF-8로 인코딩해 SHA-256한다. 문자열 내용·배열순서·숫자/문자열 타입을 보존하고 객체 키 순서·공백·동등한 수 표기 차이만 제거한다. 일반 파일 SHA-256이나 CAT-05 sourceCommonSha256과 혼용하지 않는다. BE491은 이 형식으로 검수 manifest와 현재 악보를 대조한다.

BE491의 구현은 CAT04에 선택적 `jangdanPlayback {jangdanId,name,startTick,cycleTicks,pattern:{beats,group}}`을 제공한다. 기존 `jangdan_id`·BPM 필드의 의미와 저장값을 보존한다. sourceId·scoreVersion·악보 의미 해시·기본BPM·카탈로그 패턴이 검수 목록과 일치할 때만 반주 정보를 반환한다. 곡마다 첫 정간에 검수 기본형 첫 박을 맞춘 교육용 반주이며 원본 연주자의 변주를 복원했다고 주장하지 않는다.

FE340은 앱에 녹음하지 않고 시간표대로 연습하는 `장단으로 연습` 시작/정지 경로를 추가한다. 장단 패널 미리듣기와 모범 연주 반주도 같은 세션에서 관리한다. Android는 PCM을 미리 읽은 SoundPool을 원음 속도1로 재생하고, 현재score tick으로 기한을 판단한다. 지나간 타격을 한꺼번에 밀어 재생하지 않는다. 지원하지 않는 플랫폼과 미검수 곡에서는 소리를 낼 수 없는 이유를 표시한다.

다섯 굴림 클립은 공식 실제 굴림을 오프라인 시간 압축한 파생물이다. 두 클립(기본99/빠른119)의 사용자 청음 의견은 수용됐으나 전체 클립의 전문 연주자 검수는 별도다.

## 검증과 완료 조건

1. 굴림5개는 출처·허용 조건·해시·실제 길이·피크·가공 과정이 기록되고 다른속도에맞는클립을 선택한다. 음악적 청음 미확인은 기술검사와 구분한다.
2. 운영107개 조사목록의 연결/보류 사유를 모두 남기고, 기준악보와 다른판본에는 잘못 연결되지 않는다.
3. 다른BPM/음가스케일로 같은속도를표현한곡, 굿거리 소박/큰박 정간형,5속도 선택, 정지/탐색/반복/백그라운드의 행동검사가 통과한다.
4. Android 실행과 실제 오디오 출력의 기술증거를 남긴다. 실기기/연주자청음/미지원플랫폼 상태는 별도 보고한다.
5. DATA160의 자산·검수 자료, BE491의 API·판본 보호, FE340의 앱 재생을 별도 커밋·MR로 검토하고 160 → 491 → 340 순서로 반영한다. 운영 반영은 별도 단계이며 자산 준비만으로 앱 재생 검증을 완료 처리하지 않는다.

## 기준과 역할

운영조사 snapshot은 최초160 worktree의 Git 제외 `data/processed/jangdan-tempo-survey-160/`에 보관했다. 재사용할 곡메타데이터는 [빠르기 목록](../knowledge/data/jangdan-tempo-inventory.csv), 해석 근거는 [음원 조사·생성 기록](../knowledge/data/jangdan-preview-audio.md)과 [곡별 검수 결과](../knowledge/data/jangdan-song-review.md)다. 분리 기준은 `origin/develop=a680a0ae`이며 160과 340은 이 공통 조상에서 각각 별도 브랜치·worktree로 구성한다.

- DATA160: 음원 생성·출처·21개 자산, 107개 곡의 검수 데이터와 공통 전달 계약.
- BE491(S15P31E102-491): 검수 결과 소비·판본 보호·음원과 곡별 반주 API 제공 및 서버 검증.
- FE340(S15P31E102-340): API 응답과 음원 자산을 사용하는 앱 재생·화면 연결 및 검증. DATA160의 자료 준비, BE491의 서버 제공, FE340의 실제 재생 완료 여부를 구분한다.
