# 4악기 학습 카탈로그 정렬

S15P31E102-407. 2026-11-03 사용자 요청으로 CAT-03·06을 단소·소금·정악대금·산조대금 모두에 제공한다.

## 동작과 보존

- 공개 code는 DANSO, SOGEUM, JEONGAK_DAEGEUM, SANJO_DAEGEUM이다. 기존 행이 있으면 ID·이름·허용 오차를 유지하고 활성화한다. 없는 행은 같은 코드로 등록한다. 다른 악기의 상태는 바꾸지 않는다.
- pitches는 전역 명목상 율명/옥타브 기준이다. 기존 ID·반음·한자를 보존하며 FE 운지 원본에서 사용하는 누락 (yul,octave)만 새 마이그레이션으로 추가한다. 한자 이체자는 FE에서 (yul,octave)로 대응한다.
- 음역은 기존 범위를 축소하지 않고 FE 운지표와 기존 기본음 라벨을 포함하도록 확장한다. 최소 범위는 단소 [3,29], 소금 [7,33], 정악·산조대금 [-5,29] 반음이다. 출처는 FE FingeringTables.kt·Fingering.kt 및 기존 reference-audio 명목상 매핑이다. 이 범위는 카탈로그 탐색 범위이며 실측 조율·채점 승인·전문가 운지 검수의 승격이 아니다.
- 기존 양의 문자열 ID와 공개 GET·오류·정렬·nullable 필드 계약을 유지한다. 임의 비활성 악기의404는 유지한다.
- FE는 두 대금도 각각 명시적인 서버 code로 조회한다. 레거시 DAEGEUM이나 배열 순서에서 ID를 추정하지 않는다. 내장 운지 표시는 그대로 유지한다.
- 사용자 후속 선택에 따라 회원가입·마이페이지·홈의 악기 모델도 4종으로 통일한다. 공통 enum에 명시적 serverCode를 두고 서로 다른 실제 ID를 왕복한다. 기존 로컬 Daegeum만으로 종류를 결정하지 않으며 운영에서는 서버 ID 확인 전 미확인 상태를 유지한다. 학습 완료 집계도 정악·산조를 독립적으로 계산한다.
- 모범 음원 적재는 새 악기를 기본 비활성으로 만드는 기존 정책을 유지하되 이미 공개·확장된 악기를 충돌로 취급하거나 비활성으로 되돌리지 않는다. 코드·이름·허용 오차 및 기존 자료를 포함하는 음역을 확인한다.

2. 기존 pitches 1~11 및 기존 악기·곡·음원 참조를 보존한다. 실제 DB HTTP와 FE host 검사로 확인한다.
3. BE clean build·databaseTest, 관련 Python 도구 검사와 FE host 검사를 수행한다. 운영 DB/배포는 이 구현 범위 밖이다.
