# QA 웹의 실기기 관측과 격리 검증

S15P31E102-936. 기존 휴대폰·태블릿 QA 페이지에 실기기 화면과 격리 환경의 실행·관측을 통합한다.

## 최신 표시 조정 · 2026-11-15

- 헤더 포트 입력의 보이는 라벨을 제거하고 접근성 이름은 유지한다. 영상 상태와 해상도는 기기명·연결 상태 아래에 두 줄로 배치한다.
- 참여자 이름은 헤더의 실제 가용 폭만큼 오른쪽에서 왼쪽으로 펼치고, 공간이 부족할 때만 `외 N명`으로 줄인다. 전체 명단은 펼쳐서 확인할 수 있다.
- 로그 수집 상태와 종료 버튼은 앱 처리 기록 카드 안에 둔다. 상태는 `로그 수집 전 / 로그 수집 중`, 버튼은 `로그 수집 종료`이며 실제 관측 중에만 표시한다.
- 별도 안내서는 발표자가 QA 담당자에게 기능·조작·실제 근거를 설명하는 시연 대본이다. 기본 화면에는 장문 설명을 추가하지 않는다.
- 최대 6대 통합 배치는 우선 예시 HTML로 검토한다. 기존 QA 구성과 중앙·우측 내용을 유지하고 선택한 기기가 늘 때 좌측 화면을 축소한다. 실제 다기기 서비스 계약의 변경이나 6대 지원 완료를 뜻하지 않는다.

### 자동 배치 시안으로 조정

- 사용자가 수동 기기 선택/대수 버튼 대신 연결 상태를 따라 자동으로 모두 표시하도록 요청했다. 위의 ‘선택한 기기’는 표시 여부를 수동 선택한다는 의미로 더 이상 사용하지 않는다. 카드 클릭은 제어·로그·APK의 현재 대상만 바꾼다.
- 연결된 기기 0~6대를 표시하고 연결 수 변화에 맞춰 좌측 격자만 재배치한다. 중앙·우측 QA 항목과 메뉴는 보존한다. 연결 기기가 없으면 빈 상태와 비활성 조작을 표시한다.
- 모델/유형/방향과 무관하게 세로형 카드 틀을 유지한다. 앱 영상은 원래 비율을 유지해 카드 안에 맞추고, 가로 영상도 세로 카드 내부에 배치한다.
- 헤더의 기기명·연결/영상 상태·해상도 묶음은 각 기기 카드 안으로 옮긴다. 포트 입력/적용도 헤더에서 제거하고 각 카드의 연결 설정에서 해당 기기의 값만 수정한다.
- 예시 HTML의 연결·끊김·방향 변경은 기본 QA 조작과 구분된 접힌 시연 설정에서만 모의한다. 이를 실제 ADB 자동 검색/동시 연결 지원으로 설명하지 않는다.

### 앱 조작 중심의 2열 시안 · 2026-11-16

- 사용자 요청으로 가운데 조작 열을 없애 좌측 앱 영역을 넓힌다. 번호 메뉴와 선택한 기능 패널은 앱 화면 위, 앱 처리 기록은 우측 서버 자동 검사 위에 둔다. 기존 기능·로그·관리 메뉴는 보존한다.
- 번호는 `1 앱 실행 / 2 로그인 / 3 기초 콘텐츠 / 4 연습 기록 보기 / 5 연습·평가 / 6 악보 추가·편집 / 7 부하 테스트`다. 제어권 번호·안내 패널은 제거하되 헤더의 제어권 요청·승인·반납 동작은 유지한다.
- 1번의 최신 APK 적용과 QA 앱 실행 버튼은 후속 사용자 요청에 따라 좌우로 나란히 둔다. 연결된 기기 중 최신 빌드가 없는 기기에만 적용하고, 대상이 없거나 연결0대이면 비활성화한다. QA 앱 실행은 클릭 시 연결된 모든 기기에 적용한다. 시안에서는 예시 버전·앱·로그만 바꾼다.
- 동시 제출 도구는7번을 선택할 때만 해당 선택 패널에 표시한다. 제출 수·시작/중단·성공/실패/5초·개별 결과·로그를 유지한다. 기존 우측 하단에는 상시 표시하지 않는다.
- 서버 검사 버튼 왼쪽에는 기기마다 전체 높이의 세로 색띠를 하나씩 왼쪽→오른쪽으로 나란히 쌓는다. 위아래로 나누지 않는다. 오른쪽에는 같은 기기색을 사용한 번호·통과 배지를 표시해 여러 기기의 결과를 구분한다. 선택 기기 전환으로 이전 통과 색이 사라지지 않는다. 이 색은 예시 검사 문맥이며 실제 기기 E2E 통과의 증거가 아니다.
- 우측 앱 처리 기록의 로그 보기·실행 정보는 첨부 화면처럼 기본 접힘으로 두어 서버 검사도 발견할 수 있게 한다. 필요할 때 펼치는 기능은 유지한다.
- 번호 아래 선택 패널의 반복 제목은 모두 제거하고 조작/확인 내용만 둔다. 앱 화면 바깥 카드와 번호 메뉴·선택 패널의 좌우 경계를 동일하게 맞춘다.
- 두 열 사이의 여분 공백을 없애고 좁은 세로 구분선으로 너비를 조절한다. 포인터 드래그·키보드 조절·기본 비율 복원을 제공하고 최소 너비를 지킨다. 좁은 화면은1열로 바꾸고 구분선을 숨긴다. 저장하는 값은 로컬의 숫자 비율뿐이다.
- 로그 출처는 드롭다운 대신 가로 한 줄 버튼으로 표시하고 선택 상태를 구분한다. 좁을 때는 버튼 그룹 안에서만 가로로 스크롤한다. 로그 접기와 실행/기기 범위 필터는 유지한다.
- 확인 항목은 사용자의 최종 정정에 따라 가로 배치를 유지한다. 항목별 위아래 여백과 기준선을 통일하고 공간이 부족할 때만 항목 단위로 줄바꿈한다.
- 부하의 별도 완료 배지는 제거한다. 시작 버튼이 시작→로딩→제출 완료로 바뀌고 실패/중단은 완료로 표시하지 않는다. 현재 부하는 미실행으로 시작하며 과거 예시는 이력으로만 남긴다.

- 기기 화면과 터치·뒤로·텍스트 입력, 이름 입장·제어권·무활동 종료, 무선 복구를 보존한다. 오래된 프레임과 연결 대기는 조작 가능한 현재 화면으로 표시하지 않는다.
- 기기·OS·앱 버전, 격리 API, 연결 상태와 마지막 프레임·이벤트 시각을 표시한다. 계정 버튼은 선택된 앱 입력칸에 서버가 보관하는 폐기용 계정 값을 전달한다. 비밀번호는 브라우저 응답·관측 로그에 포함하지 않는다.
- 실제 HTTP 시도별 UUID를 앱과 backend의 요청·응답 증거로 연결한다. 401 재전송도 새 UUID다. 앱 로컬 숫자는 appRun·flow·visit 또는 appRun·flow·evaluationSubmission으로 구분한다.
- 녹음 제출의 202, AI 완료, DB DONE·평가·음표 저장, 앱 DONE 확인, 첫 점수 그리기를 각각 표시한다. 평가 타이밍 ID·sessionId·attempt·evaluationId로 연결하며 시간 근접성으로 연결하지 않는다. 실제 backend 수신과 proxy 수신을 구분하고 없는 증거는 대기한다.
- 최근 동작 선택과 따라가기를 지원한다. 자동 검사는 feedback/retry/duplicate/ownership으로 제한한다. 부하 규모는 6/150/300/500/750/1000을 제공하고 작은 규모부터 실행한다. 채점 60초 마감, 실패 포함 분모와 5초 측정 구간을 표시한다. 같은 격리 환경의 관측·자동 검사·부하는 상호 배제한다.
- 실행 API는 운영자가 설정한 loopback 격리 서비스만 호출하며 임의 URL·명령·파일·DB 접근을 받지 않는다. 기존 세션·기기 소유권·epoch를 검사한다. 두 기기의 관측·입력은 선택된 기기에만 적용한다.
- 실제 마이크가 기본이다. 합성 PCM은 명시적으로 선택한 QA 빌드에서만 공급하고 준비 이벤트와 실제 입력 사용, 인코딩·채점 성공을 구분한다. 운영 빌드에는 활성화하지 않는다.
- 검증은 실제 기기에서 곡/악보/녹음/실제 AI/본인 결과와 단계 증거, 네 자동 검사, 소규모 부하·중단·이력, 권한·비밀값 제외·환경 상호 배제를 확인한다. Mac의 기존 실행 결과는 참고 근거다.

## 대시보드 시각 구성

2026-11-15 사용자 요청으로 좁은 우측 카드·접힌 탭 구성은 전체 대시보드로 대체한다. Mac 인계본 `qa-demo/index.html`의 밝은 종이색 배경, 흰 패널, 올리브·라임 강조, 파랑/황토/적색 상태 토큰과 조밀한 관측 구성을 따른다. Windows의 다중 기기·제어권·APK·한글 입력은 유지하므로 픽셀 단위 복제는 목표로 삼지 않는다.

- 데스크톱은 기기 화면·동작 관측·검사/동시 제출 도구를 병렬 배치한다. 주요 기능 제목과 실행 버튼은 탭을 열지 않아도 보인다. 불필요한 화면 배경 여백과 중첩 스크롤을 줄인다.
- OS·앱·격리 API·프레임/이벤트 시각은 상단에, 실제 HTTP·AI·DB·앱 표시 단계와 최근 동작 목록은 관측 영역에 둔다. 관측 전에는 확인 가능한 단계 종류와 대기 상태를 보여 주며 통과 데이터를 만들지 않는다.
- 자동 검사 네 가지는 설명·최근 판정이 있는 버튼으로, 동시 제출은 규모·실행/중단·성공/실패/5초 기준·슬롯별 상태와 소요 시간으로 표시한다. 이전 결과는 같은 페이지에서 펼친다.
- 한글 입력·APK 최신 적용/이력·페어링·연결해제·제어권 승인/거절은 보존한다. 표시 순서가 바뀌어도 API·세션·기기 선택·권한 조건은 바꾸지 않는다.
- 1280×720 및 넓은 데스크톱에서 기능 발견성과 가독성을 확인하고, 320px에서는 한 열로 전환해 가로 넘침을 막는다. 정상 본문 명암비 4.5:1, 키보드 포커스와 상태 문구를 확인한다.

## QA 담당자의 진행 화면 · 2026-11-15

사용자가 설명 없이도 순서대로 조작할 화면과 별도 설명서를 요청했다. 위의 설명형 버튼·바로가기·상세 정보 상시 노출은 다음 구성으로 대체한다.

- 기본 화면은 `실기기 QA`와 `서버 자동 검사` 두 영역으로 구분한다. 실기기는 제어권, 앱 실행, 로그인, 기기에서 녹음·평가 순서를 단계명과 버튼 활성 상태로 표시한다. 완료 증거 없이 로그인·평가를 통과로 표시하지 않는다.
- 페이지에는 단계명·버튼·실행 상태·결과만 표시한다. 클릭/스와이프 설명, 바로가기 줄, 환경 설명, 빈 기록 안내, 성능 측정 정의 등 문장은 제거한다. 사용법·측정 구간·입력 방식·일반 APK와 관측 APK의 차이는 별도 QA 담당자 설명서에 둔다.
- 현재 실행과 이전 실행 결과를 구분한다. 서버 검사는 실제 기기 UI를 조작하지 않는 API 검사이며 별도 결과 영역을 사용한다. 두 영역의 실행 상호 배제·권한·기기 선택은 기존 계약을 유지한다.
- 요청 UUID·API 주소·HTTP 목록·음표 비교표·실행 이력·로그는 펼쳐 보는 상세로 제공한다. 실제 수집한 로그와 DB 조회 근거만 표시하고 미수집 상태는 `기록 없음`으로 둔다. 원문 전체를 공개하지 않고 허용된 식별자·상태·시간·수치만 제공한다. 앱 로그, 서버 로그, AI 로그, DB 조회 기록의 출처를 구분하며 다른 기기·요청·재시도의 기록을 현재 판정 근거로 섞지 않는다.
- 로그 열람은 현재 이름 세션의 읽기 권한을 사용한다. 임의 파일 경로/원격 주소 조회를 추가하지 않는다. 펼친 선택 동작의 근거만 추가로 내려받고 접힌 상태에서는 로그 본문을 주기적으로 전송하지 않는다.
- 검증은 진행 전/실행 중/완료/실패/서비스 미연결 상태, 로그의 요청 연결·비밀값 제거·누락 근거, 작은 폭·키보드 이동·기존 제어/APK/페어링 회귀를 확인한다. 실제 마이크 전체 흐름은 기존 미검증 항목을 유지한다.

## 기능별 확인 항목 선택

- 사용자가 녹음 평가 외의 기능도 보여줄 수 있도록 번호 선택을 요청했다. 1제어권, 2앱 실행, 3로그인, 4기초 콘텐츠(기초부터 배우기·운지법 보기·정간보 읽기), 5연습 기록 보기, 6연습·녹음·평가, 7악보 추가·편집으로 구성한다.
- 각 번호는 탭이며 누르면 바로 아래의 관련 버튼·확인 항목이 바뀐다. 상태 갱신이 사용자의 선택을 덮어쓰지 않는다. 키보드로 번호 이동·선택이 가능하다.
- 번호 선택은 앱 자동 조작이나 검증 완료를 뜻하지 않는다. 콘텐츠/기록/악보 기능을 녹음 평가 완료 증거로 통과 처리하지 않는다. 실제 로그와 녹음 처리 판정은 별도로 유지한다.
- 화면은 짧은 항목명만 표시하고 선택의 의미·실행 방법은 별도 사용 설명서에 둔다. 실제 마이크 검증은 새6번에서 계속한다.

## 표시 밀도와 검사 선택

- 디버깅 포트는 기기 정보와 제어권/연결해제 버튼 사이 헤더 중앙에 둔다. 좁은 화면에서는 별도 행으로 내려 겹침을 막고 입력/적용 동작은 유지한다.
- 보이는 `실기기 QA`·`기기 화면` 제목과 밝기 상태 문구는 사용자 요청으로 제거한다. 화면·접근성 영역 이름·밝기 유지 기능은 보존한다.
- 서버 검사는 평가 결과 비교·평가 재시도·중복 제출 방지·계정 접근 차단으로 표시하며 버튼 안의 이름과 상태를 좌우 한 줄로 배치한다. 폭이 부족하면 버튼 열 수를 줄인다.
- 선택한 검사의 결과와 로그는 해당 검사명 아래 묶는다. 요청 중에는 이전 검사 결과를 새 검사 결과처럼 보여주지 않는다. 과거 판정에는 `이전`을 붙이고 현재 판정과 구분한다. 자세한 동작 설명은 별도 설명서에 둔다.

## 실제 통합 QA 적용 · 2026-11-16

- 사용자가 시안의 실제 적용과 최신 자동 빌드 APK 사용을 확정했다. 앱 확인의 기준은 EDO1이 develop에서 빌드해 보관한 최신 APK다. 로그 수집을 위해 임시 관측 APK로 교체하지 않는다. 관측용 APK 호환 경로는 유지하되 실제 설치된 APK에서 없는 로그·서버/AI/DB·그리기 근거를 만들지 않는다.
- 단일 /qa/ 화면에서 운영자가 등록한1~6개 중계의 연결 기기를 자동 표시한다. 기존 /qa/tablet/도 같은 화면이다. 유형별 탭·수동 표시 선택을 두지 않는다. 모든 카드는 세로 틀이고 내부 영상은 기기 비율을 유지한다. 연결 이름·파랑/빨강 상태 점·영상 정보·연결 설정은 각 카드에 둔다.
- 좌측 메뉴/선택 내용/앱 바깥 카드의 너비를 맞추고 우측에는 앱 처리 기록→서버 자동 검사→실행 이력을 둔다. 두 열 사이는8px 구분선으로 드래그·키보드·기본 비율 복원·숫자 비율 저장을 지원한다. 좁은 폭은 한 열이다.
- 번호는1앱 실행/2로그인/3기초 콘텐츠/4연습 기록/5연습·평가/6악보 추가·편집/7부하 테스트다. 반복 소제목 없이 내용을 표시한다. 최신 APK 적용과 QA 앱 실행은 좌우 배치다. 실행은 연결 기기를 대상으로 하며, 갱신은 설치 패키지·버전이 다른 대상만 적용한다. 미확인 버전은 최신으로 판정하지 않는다.
- 제어권·epoch·입력 순번·영상·쿠키·업데이트 결과는 기기별 독립이다. 클릭/탐색/한글 입력은 선택한 기기로만 전달한다. 일괄 작업은 시작 당시 대상을 고정하며 다른 조작자 소유이면 승인 대기로 남긴다. 이름 입장·10분 무활동+1분 확인·연결해제·승인/거절·페어링·밝기를 보존한다.
- 기기별 전체 높이 색띠를 좌→우로 누적하고 같은 색의 번호/통과 배지를 사용한다. 실제 해당 기기 문맥의 서버 검사 결과만 사용하며 다른 기기 결과·늦은 응답·직전 실행을 새 판정으로 바꾸지 않는다. 이는 기기 앱 E2E 통과가 아니다.
- 로그 출처는 한 줄 버튼이며 현재 동작/선택 기기/연결 기기 범위를 구분한다. 요청·timing·시도·기기·runId 범위를 유지하고 수집되지 않은 로그는 기록 없음이다. 일반 앱 실행은 중앙 예약으로 서버검사/부하와 배타 처리하고 고정 QA 컴포넌트만 연다. 앱 실행 완료를 앱 기능/채점 완료로 표시하지 않는다.
- 동시 제출은7번에서만 표시한다. 우상단 완료 배지 없이 실행 버튼이 시작→로딩→제출 완료로 바뀌고 실패/중단은 완료가 아니다. 요청 중에는 직전 결과를 지우고 실제 수신 결과만 표시한다.
