# QA 이름 입장

S15P31E102-513 · 2026-11-05 사용자 요청: 비밀번호 없이 이름만 입력해 들어온다. 휴대폰과 태블릿 공통 적용.

- 공개 `/qa/`, `/qa/tablet/`에서 표시 이름만 입력한다. 서버 `POST /api/login` 요청은 `{name:string}`이고 접속 키를 요구하지 않는다. 기존 token 필드가 와도 권한 판단에 쓰지 않는다.
- 이름은 trim 후 비어 있지 않고 원문32자 이내, 제어 문자 없는 문자열이어야 한다. 위반400, 잘못된 JSON400/본문4KiB 초과413, 다른 Origin403, IP당1분10회 초과429를 유지한다.
- 입장하면 임의 세션 쿠키를 발급한다. Secure/HttpOnly/SameSite=Strict 및 기기별 쿠키 이름/Path,8시간 수명을 유지한다. 입장 전 화면/상태/입력/설치 API는401이다. 같은 이름으로 입장해도 다른 세션의 제어권을 얻지 않는다.
- 제어권 요청/승인/거절/반납과 기존30초 무응답 양도, owner/epoch/maintenance 검사, 기기 ID 고정은 유지한다. APK 설치·포트 변경도 기존 운영 권한을 따른다.
- 제어권과 관계없이 입장 뒤 클릭·터치·키 입력·스크롤이 10분간 없으면 “접속 중이신가요?”를 띄운다. 1분 안에 **계속 연결**을 누르면 타이머를 다시 시작한다. 응답이 없으면 해당 세션의 영상과 제어권(보유·대기)을 종료한다. 다른 세션과 기기는 유지하며 진행 중인 APK 설치는 끝까지 처리한다.
- 상태 조회·영상·화면 캡처·자동 새로고침은 활동이 아니다. 세션의 같은 Origin에서 보내는 `POST /api/activity {}`만 활동으로 세고, 확인이 표시된 뒤에는 `{confirm:true}`가 필요하다. `GET /api/state`의 `idlePromptMs`는 평소 null, 확인 중 남은 밀리초다. 만료 후 활동과 상태 조회는 401이며 다시 이름을 입력해야 한다. 8시간 상한은 그대로다.
- 접속 키 입력 UI·서버 검사·실행 도구의 키 파일/환경변수/숨김 입력 의존을 제거한다. 기존 운영 키 파일은 사용하지 않으며 삭제하지 않는다. GitLab MR 조회용 읽기 토큰은 별개이고 이번 변경 대상이 아니다.
- 공개 주소를 아는 누구나 이름만으로 입장해 기기 화면을 보고 제어권을 요청할 수 있다. 이름은 인증된 실명이 아니며, 중복 이름과 이름 사칭을 막지 않는다. 사용자 요청에 따른 접근 정책 변경이다. 새 접근 제한/계정 인증을 임의로 추가하지 않는다.
- 검증: 이름만 입장, 잘못된 이름/Origin/미입장/비소유자 거부, 같은 이름의 세션 분리, 쿠키 교차 거부/정확한 logout, 무활동 알림·확인·만료 및 다른 세션 유지, 두 공개 페이지의 실제 이름 입력 입장과 화면 표시.

## 갤럭시 S10 페어링 후 복구

- 휴대폰 QA에서 페어링이 성공하면 중계가 현재 무선 연결 포트의 검색을 앞당긴다. 자동 검색 목록이 비어 있어도 등록된 휴대폰의 마지막 IP에서 연결 포트를 확인하고, 기기 ID가 일치하는 주소에만 연결한다.
- 새 포트에 연결하면 이미 입장한 QA 탭에서 포트 입력과 페이지 새로고침 없이 화면을 복구한다. 중계가 교체되면 열려 있는 탭의 기존 자동 재입장 경로를 사용한다.
- S10의 승인된 USB 연결이 있으면 그 기기에서 현재 TLS 리스너의 포트를 읽어 우선 연결한다. 케이블이 없거나 USB에서 포트를 확인할 수 없으면 S10에서 실행 중인 도구에 Wi-Fi 유니캐스트로 현재 포트를 묻는다. 도구가 응답하지 않으면 기존 무선 탐색을 사용한다.
- Wi-Fi 유니캐스트 조회는 운영 PC와 S10 사이의 공유 키로 검증한다. USB와 유니캐스트에서 찾은 포트는 ADB TLS 리스너 응답과 등록된 기기 ID를 확인한 뒤 기존 페어링으로 연결한다. S10의 TLS 무선 디버깅을 껐다 켜서 포트를 바꾸고, 케이블·mDNS·새로고침 없이 화면이 돌아오는 시간을 확인한다.
