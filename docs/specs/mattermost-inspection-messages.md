# Mattermost 점검 메시지 구성

[S15P31E102-616](https://ssafy.atlassian.net/browse/S15P31E102-616). edo1·edo2의 상태·서버·컨테이너 점검 여섯 명령에 적용한다.

- 공통 순서는 종합 판정과 수집 시각, 핵심 요약, 우선 조치, 상세 근거다. 장애·주의·미검증·미측정은 계속 구분한다. 우선 조치는 장애와 주의부터 최대 다섯 건을 보여준다. 나머지는 상세에서 확인할 수 있다.
- edo1 상태는 Nginx 라우팅 설정이 가리키는 슬롯과 해당 컨테이너의 검사 결과를 함께 표시한다. 설정을 읽을 수 없으면 슬롯은 미측정이다. 외부 웹·API 준비 응답과 Prometheus 수집, 인증서는 각각 판정한다.
- edo2 상태는 중계 HTTPS·IP 인증서와 DB 백업 최신성·복구 검증 결과를 구분한다. 백업 파일 최신성과 실제 복구 결과는 별도 검사다. 복제본과 대기 API가 수집되면 Docker 검사로 표시한다. 복제 지연과 장애 조치 가능 여부는 별도의 검사 범위다.
- 서버 점검은 CPU 표본·RAM·루트 디스크·Docker 상태를 먼저 표시한다. 컨테이너 점검은 수집·실행 수와 측정된 CPU·RAM 상위 대상을 먼저 표시한다. 수집된 값이 없을 때 사용량이나 실행 수를 0으로 가정하지 않는다. 정상적인 빈 목록은 컨테이너 없음으로 표시한다.
- 상세 수치, 기존 검사·임계값·명령·권한, 원래 컨테이너 이름을 보존한다. 출력 제한에 걸리면 생략을 표시한다. 중계는 이전 수집기 응답도 읽을 수 있다.

## edo1 블로그 편집기 롤백 보관본

`/edo1-health`에서 `eolssu-blog-editor-writable-(before|rollback|pre)-<8자리 소문자 16진수>` 형식의 보관본은 Docker inspect가 정상 종료를 확인한 경우 서비스 검사에서 제외한다. 종료 상태는 `exited`이고 실행·OOM·Docker 오류가 없어야 하며 종료 코드는 0이어야 한다. 조회 실패·비정상 종료는 기존 판정을 따른다. 운영 이름 `eolssu-blog-editor-writable`과 edo2는 이 조건에 해당하지 않는다. `/edo1-containers`에서는 보관본도 인벤토리에 포함된다.
