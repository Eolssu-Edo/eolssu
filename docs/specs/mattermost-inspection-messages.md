# Mattermost 점검 메시지 구성

Mattermost CI/CD 채널에서 `/edo1` 또는 `/edo2`를 실행하면 해당 호스트의 상태·서버·컨테이너 점검을 한 번에 받는다. [통합 작업](../plans/S15P31E102-701.md)

- 첫 게시물에는 짧은 호스트 제목, 수집 완료 시각·소요 시간·요청 ID, 영역별 장애·주의·미검증·미측정 건수를 표시한다. 후속 게시물이 있으면 제목으로 주제를 구분하고 같은 요청 ID를 붙인다. 게시물마다 최대 14,000자, 요청당 최대 다섯 건이다. 표가 다음 게시물로 이어지면 열 머리글을 다시 표시한다. 한도를 넘겨 생략한 내용은 마지막 게시물에 표시한다.
- 상세는 주제별 표에서 읽는다. 상태는 서비스·호스트·백업, 서버는 자원·저장공간으로 나눈다. 컨테이너는 상태, 자원, 데이터 저장공간, 실행·포트, 통신량·이미지를 따로 표시한다. 우선 확인 항목은 장애와 주의부터 최대 다섯 건을 표시한다. 한 종류의 수집이 실패하면 해당 영역에 미측정과 이유를 표시하고 다른 영역의 결과를 함께 제공한다.
- edo1 상태는 Nginx 라우팅 설정이 가리키는 슬롯과 해당 컨테이너의 검사 결과를 함께 표시한다. 설정을 읽을 수 없으면 슬롯은 미측정이다. 외부 웹·API 준비 응답과 Prometheus 수집, 인증서는 각각 판정한다.
- edo2 상태는 중계 HTTPS·IP 인증서와 DB 백업 최신성·복구 검증 결과를 구분한다. 백업 파일 최신성과 실제 복구 결과는 별도 검사다. 복제본과 대기 API가 수집되면 Docker 검사로 표시한다. 복제 지연과 장애 조치 가능 여부는 별도의 검사 범위다.
- 서버 점검의 CPU 표본·RAM·루트 디스크·Docker 상태는 표에서 확인한다. 컨테이너 점검은 수집·실행 수와 측정된 CPU·RAM 상위 대상을 한 줄로 표시한다. 수집된 값이 없을 때 사용량이나 실행 수를 0으로 가정하지 않는다. 정상적인 빈 목록은 컨테이너 없음으로 표시한다.
- 기존 상세 수치·검사 근거·임계값·수집 권한과 원래 컨테이너 이름을 보존한다. 중계는 기존 수집기의 세 가지 결과 형식을 사용한다.

## edo1 블로그 편집기 롤백 보관본

`/edo1`의 서비스 상태 표에서 `eolssu-blog-editor-writable-(before|rollback|pre)-<8자리 소문자 16진수>` 형식의 보관본은 Docker inspect가 정상 종료를 확인한 경우 제외한다. 종료 상태는 `exited`이고 실행·OOM·Docker 오류가 없어야 하며 종료 코드는 0이어야 한다. 조회 실패·비정상 종료는 기존 판정을 따른다. 운영 이름 `eolssu-blog-editor-writable`과 edo2는 이 조건에 해당하지 않는다. 컨테이너 표는 보관본도 인벤토리에 포함한다. 정상 종료가 확인된 보관본의 상태는 `롤백 보관 · 중지`, 실행 통계는 `해당 없음`으로 표시한다. 저장공간은 계속 수집한다.
