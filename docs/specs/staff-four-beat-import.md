# 오선보 4박 장단 선택과 기존 초안 복구

2026-11-13, S15P31E102-880. 사용자 요청: 원인 확인에 이어 가져오기 오류와 이미 추가한 `VB`를 수정한다. [원인](../knowledge/frontend/sheet-jangdan-correction.md#오선보-44-가져오기의-장단-후보-누락-880), [작업 기록](../plans/S15P31E102-880.md).

## 수정 범위

- 요청 장단이 없는 오선보에서 단순4박·한 박이4분음표인 박 구성을 읽으면 기존 카탈로그의 `4박 기본 반주`를 제안한다. 전통 장단명으로 단정하지 않으며 `JANGDAN_GUESSED`를 유지한다.
- 정간 하나는4분음표1박, 한 각은4박으로 공통 악보에 저장한다. 카탈로그 기본 빠르기를 쓰는 기존 서버 계약을 유지하므로 이 반주의 시작 기본값은160 QUARTER BPM이다.
- 명시 요청 장단의 우선순위,9/8 세마치·12/8 굿거리, 박자 미인식 시의 기존 리듬 추정과 그 밖 박 구성의 검수 안내를 보존한다. 새 장단·API 필드·스키마는 추가하지 않는다.
- 원본 숫자 템포·가속 구간의 자동 추출은 이번 수정에 추가하지 않는다. 단순4박 반주의 기본160과 원본 템포 인식은 구분한다.

## 기존 악보 복구

해당 사용자의 오선보32 최신 자동 저장 초안만 복구한다. 확정본·다른 악보·인식 원본·기존 음원을 보존한다. 현재503음의 이조·음표 위치·이음·분할·기호·adaptation을 유지한다.

복구는 예상 박 단위 DOTTED_QUARTER, 박/정간18/12 tick, 모든 각4칸, 잘못 들어간 기본66 BPM, 구간 빠르기 계획 없음과 원본 출처를 확인한 경우에만 진행한다. `draft.score.music`의 단위를QUARTER·박tick12로 바꾸고, 장단명·ID를 기존4박 기본 반주12로 연결한다. 초안 BPM은 이 반주의 시작160으로 복구한다. 이벤트와 정간tick은 변경하지 않는다. 이는 전체 곡의 구간 빠르기 복원이 아니다.

쓰기 전 최신 스냅샷을 별도 보관하고 현재 score_version·draft_revision·초안 해시가 일치할 때만 한 트랜잭션으로 반영한다. draft_revision을1 올려 현재 열린 편집기의 오래된 저장이 덮어쓰지 못하게 한다. 확인 조건이 달라지면 적용을 중단하고 실제 최신 편집을 보존한다. 확정 저장·완료 상태 전환은 사용자의 검수를 대신하지 않는다.

## 완료 조건과 검증

1. 수정 전4/4 변환·인식 회귀가 굿거리와 점4분박 때문에 실패하는 것을 확인하고, 수정 후4박 기본 반주·QUARTER·정간당1박·불일치 알림 없음으로 통과한다.
2. 명시 요청 장단,9/8·12/8과 기존 오선보 음표·인식 회귀가 통과한다. 실제 변환과 가짜 Audiveris의 HTTP 경계를 구분해 기록한다.
3. 초안 복구의 작은 고정 데이터 검사에서 편집 음고·이벤트·불변 원본 보존, 예상과 다른 초안·구간 계획 거부, 재적용·오래된 revision 거부를 확인한다.
4. 운영 대상 초안을 재조회하여4박 후보·단위·BPM과 편곡·원본 해시 보존을 확인한다. 현재 열린 화면은 다시 열어 최신 revision을 받도록 알린다.

최초 수정 요청은 구현·검증·작업 단위 커밋과 해당 사용자 초안의 제한된 복구를 포함한다. 후속 `MR` 요청에 따라 최신 develop 동기화·검증·Jira 결과 기록·Push·Draft MR 생성을 진행한다. 사람의 병합과 서비스 코드의 정식 배포는 별도다.
