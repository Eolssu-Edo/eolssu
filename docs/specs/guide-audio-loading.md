## 문제와 범위

악기 선택 이름은 CAT-01 응답을 그대로 사용한다. 운영 응답에는 단소·소금·정악대금·산조대금이 있으며, 이전 검증 캡처의 “서버” 접두어는 테스트 응답 이름이었다. 문자열을 임의로 제거하는 제품 코드는 추가하지 않는다.

음원 목록은 악기 dataset 전체를 조회하지만, 현재 Route의 취법·학습 단계 resetKey가 바뀔 때마다 같은 목록을 지우고 다시 조회한다. 이미 성공한 목록의 반복 조회를 없애고, 초기 로딩의 대상이 운지 그림이나 악기 목록이 아닌 음원 목록임을 문구로 구분한다. 운영 API 자체의 지연 개선은 이 작업에서 주장하지 않는다.

## 동작

- 한 ReferenceAudioViewModel이 살아 있는 동안 성공한 악기별 목록을 재사용한다. 빈 목록도 성공 결과다. 실패 결과는 캐시하지 않는다.
- 같은 악기의 취법·학습 단계 전환은 재생을 멈추고 녹음 선택을 지우되, 진행 중인 목록 요청을 취소하거나 성공 목록을 다시 조회하지 않는다.
- 다른 악기로 바꾼 뒤 돌아올 때 성공 목록이 있으면 즉시 재사용한다. 선택·재생은 이전 악기에서 이어지지 않는다.
- 명시적인 재시도는 서버를 다시 조회하며, 요청 중 중복 재시도는 같은 요청을 유지한다. 실패 후 재시도는 정상적으로 동작한다.
- 화면을 떠나 dismiss하면 진행 중 요청·선택·목록 캐시를 비운다. 재진입은 새로 조회한다.
- 목록 로딩·실패 메시지는 “음원 목록”이라고 표시한다. 실제 음원 다운로드·재생의 로딩 문구와 기존 빈 자료 문구를 유지한다.
- 운지표·음표 대응·출처·서버 API/DB·플레이어 구현과 재생 계약은 변경하지 않는다.

## 검증

같은 악기 재열기, 로딩 중 재열기, 악기 왕복, 빈 결과, 실패 재시도, 명시 갱신, dismiss와 오래된 요청 취소를 작은 고정 응답으로 검증한다. 변경 전 취법 전환의 중복 HTTP 요청을 실제 Wasm UI에서 재현하고, 변경 후 같은 전환의 요청 수·로딩 상태를 비교한다. 전체 Android host 테스트와 Wasm 빌드를 수행한다. Windows의 검사는 iOS·실기기 검증을 대신하지 않는다.
