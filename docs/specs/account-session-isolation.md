## 동작

로그인·가입·소셜 가입·병합·로그아웃·탈퇴로 인증 주체가 정해질 때 회원 ID와 로그인 세대를 함께 갱신한다. 같은 회원의 재로그인도 별도 세대로 구별한다. 토큰 갱신은 동일 세션으로 유지한다.

개인 작업을 시작할 때 회원·세대를 캡처하고 요청 발송 전 기존 인증 Mutex 안에서 확인한다. 변경된 작업은 전송하지 않는다. 응답·캐시·낙관 상태·성공 처리를 반영하기 전에도 같은 세대인지 확인한다. 진행 중 여러 페이지 조회는 개별 요청 단위로 보호한다.

계정이 바뀌면 기록·평가·성장·진도·내 악보·재생 URL 및 진행 상태를 비운다. 공개 카탈로그는 개인 데이터와 분리한다. 회원 없는 기존 학습 진도는 legacy로 보관하며 새 계정에 자동 귀속하지 않는다. 녹음 pending 파일은 기존 소유권·복구 정책을 따른다.

화면의 작업 시작부터 요청까지 계정 정보가 유지되어야 한다. 데이터 계층의 검사만으로 오래된 화면의 저장 버튼이 새 계정으로 실행되는 것을 허용하지 않는다.

## 수용 기준

- A→B, A→B→A 전환 후 이전 작업의 요청 발송 0건, 응답 반영 0건, 개인 캐시 잔존 0건.
- 같은 로그인 세션의 정상 요청·저장·재시도는 유지한다.
- 정상 로그인·가입·소셜 로그인·계정 연결 뒤 프로필 캐시 초기화는 인증 회원/세대를 지우지 않는다. 실제 로그아웃·탈퇴·세션 만료만 인증을 무효화한다.
- 로그인 변경과 HTTP 쿠키·토큰 갱신의 기존 Mutex 보호를 유지한다.
- 회원 없는 legacy 진도와 다른 회원의 pending 녹음을 자동 이관하지 않는다.
- 공개 카탈로그 조회와 기존 로그인·가입·로그아웃 테스트를 통과한다.

## 전후 비교

새 회귀 검사를 기존 코드에 실행해 실패를 재현한 뒤 구현한다. 동일 고정 데이터·요청 순서·횟수로 잘못 발송된 HTTP 요청, 늦게 반영된 응답, 캐시에 남은 개인 데이터의 전후 건수를 기록한다. 측정의 단위·분모·기준 커밋·실행 명령과 로그 위치를 남긴다. 성능 수치는 실제 측정한 경우만 보고한다.

코드·스키마 및 HTTP 계약의 추가 변경이 필요하면 기존 선택과 영향을 작업 계획에 기록한다. API 연결 확대와 판본 보존은 별도 기능 작업이다.
