# 녹음 파일 규격 (PRA-02)

- Jira: [S15P31E102-168](https://ssafy.atlassian.net/browse/S15P31E102-168), Story S15P31E102-33, Epic S15P31E102-20
- 상태: 사용자 합의(2026-10-27, `coco-clarify`). 크기·길이 숫자는 실측 전 시작값이다. 메타데이터 칼럼 4개, 변환 위치(AI 서비스), GCS 저장·세부, 비동기 분석 요청, 오류 형식은 사용자가 확정했다.
- 관련 계약: [DB 스키마](../contracts/db-schema.md)의 `practice_sessions`. 원본 저장소는 GCS(Google Cloud Storage)이며 이 작업 범위에서 연결한다([GCS 저장](#gcs-저장)).
- 클라이언트 범위: Android·iOS 앱. 웹 녹음은 이번 구현 범위가 아니다.

## 목표

사용자가 연습 구간을 연주해 녹음하면 앱이 m4a(AAC) 파일 하나를 서버에 올린다. 서버는 규격에 맞지 않는 파일을 업로드 시점에 바로 거부하고, 맞는 파일은 원본 그대로 저장한 뒤 분석 전에 AI가 읽는 형식으로 바꾼다.

## 동작

### 클라이언트 녹음

- 형식은 MP4 컨테이너의 AAC(`.m4a`) 하나다. 플랫폼이 허용하면 모노·AAC·128kbps·44.1kHz 또는 48kHz로 요청한다. 서버는 비트레이트·샘플레이트·채널 수로 거부하지 않는다.
- 녹음은 10:00에 자동으로 멈춘다. 업로드 전에 파일이 20MiB를 넘으면 앱이 먼저 알린다.
- 녹음은 Android·iOS 앱에서만 한다. 웹 녹음과 webm·ogg(Opus) 형식은 받지 않는다.

### 업로드

연습 세션 하나에 녹음 파일 하나를 multipart로 올린다. 서버는 아래 순서로 검사하고, 먼저 걸리는 결과를 반환한다. 거부한 파일은 저장하지 않으며, 세션 상태도 바꾸지 않는다.

| 순서 | 조건 | 응답 | 세션 |
| --- | --- | --- | --- |
| 1 | 세션이 없거나 요청 사용자의 세션이 아님 | 404 | 변화 없음 |
| 2 | `status`가 `RECORDING`이 아님(이미 저장됨, 분석 중·완료·실패) | 409 | 변화 없음 |
| 3 | `started_at` + 40분이 지남 | 410 | 변화 없음. 만료 정리는 아래 배치가 한다 |
| 4 | 파일 크기 > 20MiB(20,971,520바이트) | 413 | 변화 없음 |
| 5 | MP4 계열 컨테이너가 아니거나 AAC 오디오 스트림이 없음(확장자·MIME가 아니라 ffprobe 결과로 판정) | 415 | 변화 없음 |
| 6 | 길이 ≤ 0초 또는 ≥ 601.0초(ffprobe 길이) | 422 | 변화 없음 |
| 7 | 저장소 쓰기 실패 | 503 | 변화 없음, 같은 세션으로 재시도 가능 |
| - | 모두 통과 | 202 | 원본 저장, `recording_url`과 메타데이터 칼럼 기록, `ended_at` = 업로드 성공 시각(서버 UTC), `status`를 `PENDING`으로 변경. 분석 결과를 기다리지 않고 바로 응답한다 |

- 길이 상한은 600초이며 AAC 앞뒤 패딩으로 1초 미만 길어지는 것은 허용한다. 연습 구간(BPM·시작~끝 음표)으로 계산한 길이와는 비교하지 않는다. 구간보다 짧은 녹음은 AI 채점의 `TOO_SHORT`가 처리한다.
- 4~7에서 거부되면 같은 세션에 다시 올릴 수 있다. 저장에 성공한 세션은 2에 걸려 409를 받으며, 다시 불려면 새 세션을 만든다.
- 저장 키는 서버가 만든 `recordings/{practice_sessions.id}.m4a`이다. 사용자가 보낸 파일명은 쓰지 않는다. `practice_sessions.id`는 만료되지 않는 행 ID라 키가 바뀌지 않는다.

### 오류 응답

거부 응답 본문은 Spring의 ProblemDetail(RFC 9457, `application/problem+json`)이며, 앱이 안내를 고를 `code` 문자열을 추가한다. 이 형식은 백엔드 공통 오류 형식으로 `common/error`에 둔다.

| 상태 | `code` |
| --- | --- |
| 404 | `SESSION_NOT_FOUND` |
| 409 | `SESSION_NOT_RECORDING` |
| 410 | `SESSION_EXPIRED` |
| 413 | `RECORDING_TOO_LARGE` |
| 415 | `RECORDING_UNSUPPORTED_FORMAT` |
| 422 | `RECORDING_INVALID_DURATION` |
| 503 | `RECORDING_STORAGE_UNAVAILABLE` |

```json
{"type": "about:blank", "title": "Payload Too Large", "status": 413, "detail": "녹음 파일이 20MiB를 넘습니다.", "code": "RECORDING_TOO_LARGE"}
```

### 원본 메타데이터 (DB 칼럼)

저장 성공 시 업로드 검사에서 얻은 값을 `practice_sessions`에 함께 기록한다. 한도 실측과 실패 원인 추적에 쓰는 값만 둔다. 새 Flyway 버전으로 추가하며, 기존 행과 업로드 전 행은 NULL이다.

| 칼럼 | 값 |
| --- | --- |
| `recording_bytes` | 원본 파일 바이트 수 |
| `recording_duration_ms` | ffprobe 길이(ms, 반올림) |
| `recording_sample_rate` | 원본 샘플레이트(Hz) |
| `recording_channels` | 원본 채널 수 |

코덱은 검사를 통과하면 항상 AAC라 칼럼으로 두지 않는다. SHA-256은 무결성·중복 확인 요구가 생기면 다시 정한다. 칼럼 타입은 구현에서 기존 SQL 규칙에 맞춘다.

### 세션 만료

- `RECORDING` 상태로 `started_at` + 40분(최대 녹음 10분 + 업로드·재시도 여유 30분)이 지난 세션은 만료다.
- 업로드 요청은 위 3번 검사로 바로 410을 받는다. 배치 주기와 관계없이 같은 기준을 쓴다.
- 주기 배치가 만료 세션을 `FAILED`, `fail_reason = 'UPLOAD_TIMEOUT'`으로 바꾼다. 배치 주기는 구현에서 정한다.

### 분석 요청과 결과 조회

- 저장 성공을 커밋한 뒤 백엔드가 백그라운드에서 AI 서비스에 HTTP로 분석을 요청한다. 요청에는 세션 ID, 곡·연습 구간·BPM, 원본을 15분 동안 읽을 수 있는 GCS 서명 URL이 들어간다.
- AI가 결과를 돌려주면 백엔드가 평가 결과를 저장하고 `DONE`으로, 실패 사유(`DECODE_ERROR`·`NO_SOUND`·`TOO_SHORT`)를 돌려주면 `FAILED`로 바꾼다. 시간 초과(`TIMEOUT`)·연결 실패(`SERVER_ERROR`)를 포함한 실패 코드 전체, 늦은 결과 무시, 분석 다시 시도는 PRA-03 [연주 분석 실패 사유와 화면 안내](https://ssafy.atlassian.net/browse/S15P31E102-167)를 따른다.
- 앱은 업로드 202를 받으면 분석 대기 화면에서 세션 상태를 2초 간격으로 조회하고 `DONE`·`FAILED`가 되면 멈춘다.
- 큐·별도 작업 서비스는 두지 않는다. AI 요청·응답 본문은 분석 연동 작업([S15P31E102-186](https://ssafy.atlassian.net/browse/S15P31E102-186))에서, 시간 초과 값과 `PENDING`에 남은 세션 처리는 PRA-03에서 정한다.

### 분석용 변환

- **AI 서비스**가 서명 URL로 원본 m4a를 받아 분석 직전에 **16kHz·모노·PCM16** 오디오로 디코딩한다. 스테레오는 두 채널 평균으로 모노화한다. 백엔드는 원본 위치만 넘기며 ffprobe 검사 외의 디코딩은 하지 않는다.
- 변환 결과는 메모리 배열 또는 임시 WAV 파일로만 쓰고 분석 뒤 버린다. 저장소에 두지 않으며, 재분석 때는 원본에서 다시 만든다.
- 변환·디코딩이 실패하면 세션을 `FAILED`, `fail_reason = 'DECODE_ERROR'`로 바꾼다.

### GCS 저장

| 항목 | 결정 |
| --- | --- |
| 지역 | 서울(`asia-northeast3`), Standard. GCP 신규 계정 무료 크레딧으로 운영하며 예산 알림을 설정한다. 크레딧 기간·금액은 GCP 공식 안내로 확인하고, 종료 후 유료 전환 여부는 팀이 정한다 |
| 접근 | 공개 접근 차단, 균일한 버킷 수준 접근 |
| 인증 | 백엔드 전용 서비스 계정에 이 버킷의 객체 쓰기·읽기·삭제 권한만 준다. JSON 키는 서버의 비밀 파일로 두고 컨테이너에 읽기 전용으로 마운트해 `GOOGLE_APPLICATION_CREDENTIALS`로 지정한다. 저장소에는 커밋하지 않는다 |
| AI 읽기 | 백엔드가 분석 요청마다 15분 유효한 읽기 전용 V4 서명 URL을 만든다. AI 서비스에는 GCP 자격 증명을 두지 않는다 |
| `recording_url` | 버킷 안 객체 키(`recordings/{id}.m4a`)를 저장한다. 접근 가능한 URL은 필요할 때 서명해 만든다 |

### 보관

원본은 버킷 수명 주기 규칙으로 `recordings/` 객체 생성 30일 뒤 GCS가 자동 삭제한다. 기준은 DB `created_at`이 아니라 업로드 시각이라 최대 40분 늦게 지워진다. 이 규칙으로 기존 스키마 주석의 "삭제 배치"는 파일 삭제를 하지 않는다. 삭제 후 `recording_url`이 가리키는 파일이 없는 문제는 이 스펙에서 다루지 않는다(별도 Task).

## 유지할 동작

- `practice_sessions`의 기존 칼럼 의미와 상태 값(`RECORDING`·`PENDING`·`DONE`·`FAILED`), `recording_url` 30일 보관 규칙.
- AI 채점 입력(오디오 배열 + 샘플레이트)과 `NO_SOUND`·`TOO_SHORT` 판정.

## 한도 실측

1. Android·iOS에서 각각 기본 설정으로 10분 녹음을 하나씩 만든다.
2. 비트레이트·샘플레이트·채널·크기·ffprobe 길이·디코딩한 프레임 수를 기록한다.
3. 크기 한도 = 최대 실측 크기 × 1.5를 MiB 단위로 올림한다. 길이 한도는 서비스 곡의 최대 연습 길이를 확인해 다시 정한다.
4. 결과와 바꾼 숫자는 `docs/knowledge/backend/`에 기록하고 이 스펙의 숫자를 고친다. 동작은 바꾸지 않는다.

## 완료 판정

- [ ] 44.1kHz 스테레오와 48kHz 모노 AAC m4a가 202를 받고 저장되며, `recording_url`과 메타데이터 칼럼 4개·`ended_at`이 채워지고, 상태가 `PENDING`이 된다.
- [ ] 20,971,521바이트 파일은 413, MP3를 `.m4a`로 이름만 바꾼 파일은 415, 0초 파일과 601초 이상 파일은 422를 받고 저장되지 않는다.
- [ ] 모든 거부 응답이 `application/problem+json`이며 위 표의 `code`를 담는다.
- [ ] 600.5초 AAC 파일은 통과한다.
- [ ] 저장된 세션에 다시 올리면 409, 다른 사용자의 세션이면 404를 받는다.
- [ ] `started_at` + 40분이 지난 `RECORDING` 세션은 업로드 410을 받고, 배치 뒤 `FAILED`·`UPLOAD_TIMEOUT`이 된다.
- [ ] 저장소 쓰기 실패를 흉내 내면 503을 받고 세션은 `RECORDING`으로 남아 재업로드가 성공한다.
- [ ] 변환 결과는 16kHz·1채널·PCM16 WAV이며 길이가 원본과 1초 미만 차이다. 깨진 원본은 `FAILED`·`DECODE_ERROR`가 된다.
- [ ] Android·iOS 앱이 10:00에 녹음을 멈추고, 만든 파일이 AAC m4a다.
- [ ] 저장에 성공한 원본이 서울 GCS 버킷의 `recordings/{id}.m4a`에 있고, 백엔드가 만든 서명 URL로 자격 증명 없이 15분 안에 읽히며 만료 후에는 거부된다.
- [ ] 버킷이 공개 접근 차단 상태이고 `recordings/` 30일 삭제 수명 주기 규칙이 설정돼 있다.
- [ ] 한도 실측 결과가 기록되고 스펙의 숫자가 갱신된다.

## 검증 방법

- **픽스처:** ffmpeg로 몇 초짜리 사인파 AAC(44.1kHz 스테레오·48kHz 모노), 이름만 바꾼 MP3, 0초 파일, 저비트레이트 무음 AAC(600.5초·601초 이상), 손상 파일을 만들어 테스트 자원으로 둔다. 큰 파일은 커밋하지 않고 테스트 중에 생성한다.
- **백엔드:** 검사 순서·오류 코드·저장 키·상태 변경을 저장소 대역으로 단위 테스트한다. 메타데이터 칼럼과 상태 변경은 DB 통합 테스트로 확인한다. ffprobe가 없는 환경에서는 해당 테스트가 실패해야 하며 건너뛰지 않는다.
- **변환:** AI 쪽 테스트에서 픽스처의 변환 결과(16kHz·1채널·PCM16)와 길이를 검사한다. AI 대역을 사용한 테스트를 실제 채점 검증으로 보고하지 않는다.
- **ffmpeg 버전:** 로컬·CI·운영의 ffprobe 판정이 같도록 백엔드 이미지의 패키지 버전을 고정하고, 검사기 구현 Task(S15P31E102-180)에서 실제 버전을 확인해 이 문서에 기록한다.
- **GCS:** 단위 테스트는 저장소 대역을 쓰고, GCS 연결은 테스트 전용 버킷에 실제로 올리고 읽어 확인한다. 인증 정보는 저장소에 커밋하지 않는다.
- **앱:** 자동 정지는 Android·iOS에서 직접 실행해 확인한다. 단위 테스트만으로 완료로 보고하지 않는다.
