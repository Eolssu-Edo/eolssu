# 카카오 계정 상태 변경 웹훅

S15P31E102-296. 사용자 승인: 서명형 User Unlinked만 처리하며 카카오 연결만 지운다. 회원·기록·이메일 로그인·기존 세션은 보존한다.

## 수신 계약

- `POST /api/webhooks/kakao/events`, `Content-Type: application/secevent+jwt`, 본문은 최대16KiB의 SET 문자열이다. 사용자 쿠키는 사용하지 않는다.
- RS256, `typ=secevent+jwt`, kid, 고정 issuer `https://kauth.kakao.com`, aud(대표 REST API 키), app_id, sub와 이벤트 subject 일치를 검증한다. 공개키는 고정 `https://kauth.kakao.com/.well-known/jwks.json`만 조회한다. 토큰의 URL은 사용하지 않는다.
- User Unlinked 이벤트 URI는 `https://schemas.openid.net/secevent/oauth/event-type/user-unlinked`다. 다른 이벤트는 현재 수신 계약에 포함하지 않는다.
- jti·txm·iat·toe를 요구한다. 미래 시각 허용 오차60초, 발생/발급 후24시간까지만 받는다. 이는 공식 재전송 종료 약130분보다 넉넉한 로컬 재생 방지 경계다.
- DB 처리 성공 후 빈202, 입력/서명 검증 실패는400 `{"err":"invalid_request|invalid_key|invalid_issuer|invalid_audience","description":"..."}`. 일시적인 키 조회·DB 장애나 설정 누락은503으로 재전송을 유도한다. 이 경로는 공통 API envelope의 승인된 예외다.

## 순서·재연결 보호

- jti·txm의 SHA-256 영수증과 제공자 subject의 SHA-256 해제 워터마크를 같은 트랜잭션으로 저장한다. 원문 토큰·키·이메일·subject는 새 테이블이나 로그에 보관하지 않는다.
- 워터마크와 영수증은48시간 뒤 매분 최대500개씩 삭제한다.24시간 수신 한도와10분 OAuth 흐름보다 길게 보존한다.
- 회원 행 → subject 워터마크 행 순서로 잠근다. 연결 소유자가 잠금 중 바뀌면 트랜잭션을 롤백하고503으로 재전송받는다. 회원이 없으면 subject만 잠근다.
- OAuth 시작 시각을 mergeTicket과 소셜 연결에 이어 저장한다. 해제 시각 이전에 시작한 미완료 연결은 워터마크로 거절하고, 늦은 통지가 이후 시작한 새 연결을 지우지 않게 한다. 기존 연결은 created_at으로 대체한다.
- 배포 전에 발급된 V9 mergeTicket은 STATE10분+MERGE10분의 가장 이른 시작 시각으로 보수적으로 처리한다. 해제와 겹친 기존 티켓은 재시작이 필요할 수 있다. 이미 연결된 기존 행의 정확한 OAuth 시작 시각은 복원할 수 없으므로 created_at 기준이며, V10 이후 완료한 흐름부터 시작 시각 경계를 보장한다.
- 카카오 toe는 초 단위다. 사용자 확정(2026-10-30): 같은 초 안의 순서를 확인할 수 없으면 보안 우선으로 연결을 해제하고 새 흐름으로 재시도한다. 새 흐름은 toe 다음 초부터 허용하며 이후 흐름은 이전 통지로 삭제하지 않는다.
- 중복·미연결·새 연결보다 오래된 이벤트도 검증과 영수증 저장이 끝나면202다. 다른 제공자·refresh token·회원 상태는 변경하지 않는다.

## 운영 경계와 검증

공개키는5분 캐시, 새 키 조회는10초 구간으로 제한하며 연결500ms·읽기750ms·응답32KiB 한도를 둔다. 리다이렉트·토큰 내 jku/x5u 주소를 따라가지 않는다. 알려진 키 검증은 조회 제한 중에도 계속한다. 새 키 조회 장애/제한은503으로 재전송받는다.

본문을 받은 뒤 검증·DB 대기 상한은2.5초다. 동시에 네 작업까지만 처리하며 대기열을 두지 않는다. DB 트랜잭션은1초 제한이다. 시간 초과 때 취소를 요청하고503으로 응답한다. JDBC가 취소 직전에 커밋했다면503이어도 처리가 끝났을 수 있으며, 재전송은 같은 영수증으로202가 된다. 외부 프록시·본문 전송·네트워크 시간을 포함한 카카오3초 제한 준수는 배포 후 실제 이벤트로 별도 확인한다.

`AUTH_OAUTH_KAKAO_CLIENT_ID`와 `AUTH_KAKAO_WEBHOOK_APP_ID`가 필요하다. 누락 시 기동은 가능하나 수신은503이다. 콘솔은 배포 후 User Unlinked만 구독하도록 별도로 활성화한다. 실제 카카오 송신 검증은 로컬 서명·DB·HTTP 테스트와 구분한다.
