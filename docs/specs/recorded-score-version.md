# 녹음 판본과 신규 연습 세션 보호

- 관련 작업: S15P31E102-453. 사용자가 승인한 707 분리 범위이며 담당자는 박찬형이다.
- 목적: 녹음 당시의 악보 판본을 새 판본의 시간축으로 채점하지 않는다.

## 요청과 판정

PRA-01의 선택 필드 `expectedScoreVersion`은 양의 정수다. 같은 사용자·멱등 키의 저장된 요청을 먼저 재생한다. 신규 요청의 명시 판본이 현재 게시 판본과 다르면 409이고, 부모 세션도 같은 현재 판본이어야 한다. 잘못된 0 이하 값은 400이다.

필드를 생략하거나 null로 보낸 구 앱은 과거 판본이 보관되지 않은 곡에서 종전처럼 동작한다. `song_score_versions`에 현재와 다른 판본이 있는 곡은 실제 녹음 판본을 확인할 수 없으므로 신규 요청을 409로 거절한다. 롤백으로 현재 판본이 낮아져도 다른 보관 판본이 있으면 같은 규칙을 적용한다. 단순히 현재 판본이 2 이상인 모든 곡을 막지는 않는다. SQL 삽입도 현재 게시 판본이 조회 때와 일치할 때만 수행해 판본 교체와의 경합을 막는다.

클라이언트는 녹음을 시작한 화면의 판본을 `RecordedTake`에 보존하고 PRA-01에 전달한다. 분석 제출 직전 조회한 현재 판본과 녹음 판본이 다르면 새 제출을 중단한다. 기록 기반 취약 구간에서도 현재 판본 여부를 확인하고 구판의 새 연습 진입을 막는다.

## 의존성과 제외 범위

745의 `song_score_versions` 마이그레이션이 먼저 배포되어야 한다. 과거 판본 조회와 기존 기록의 분석 재현은 745, 기록 상세의 독립화와 과거 결과 소비는 454, 비행기 v2 데이터는 707에서 다룬다. 기존 세션의 분석을 최신 판본만 허용하는 정책으로 바꾸지 않는다.

## 완료 조건

- 보관 곡의 생략/null 신규 요청, 명시 불일치, 구판 부모, 조회-삽입 간 판본 교체는 세션을 만들지 않는다.
- 현재 판본 명시 요청과 기존 키 재전송은 성공한다.
- 클라이언트 녹음 판본 전달·구판 새 연습 차단을 단위 검사한다.
- backend 일반 빌드, 745 스키마를 포함한 DB 검사, frontend Android host 검사를 기록한다. 실제 기기 녹음과 iOS 검증은 별도로 명시한다.

## PRA-01 추가 필드와 오류 계약

`POST /api/practice-sessions` 요청 JSON의 `expectedScoreVersion`은 선택 필드이며 `null`을 허용한다. 숫자는 JSON 정수 `1..2147483647`이어야 하고 문자열·소수·범위 초과·0 이하는 `400 INVALID_REQUEST`다. 기본값은 null이고 생략과 명시 null은 멱등 비교에서도 같다.

- 신규 키의 명시 판본 불일치, 다른 판본이 보관된 곡의 생략/null, 부모 세션의 판본 불일치, 조회와 삽입 사이의 판본 변경: `409 STATE_CONFLICT`, 삽입 없음.
- 같은 키와 다른 본문(명시 판본 추가·변경 포함): `409 IDEMPOTENCY_CONFLICT`.
- 같은 키와 같은 본문: 곡의 공개·판본 상태가 바뀌어도 원래 세션을 `201`로 반환한다. 새 행은 만들지 않는다.
- 유효한 신규 요청: 현재 판본으로 한 행을 저장하고 기존 `201` 응답 형태를 반환한다. 이 작업은 응답 필드를 추가하지 않는다.

로그인 쿠키·멱등 키 헤더·곡/부모 소유권과 범위 조건은 기존 계약을 따른다. 잘못된 JSON·인증은 Controller 이전에도 거절되므로 멱등 재전송이 이 경계를 우회하지 않는다. PRA-03 결과 메타데이터는 745의 별도 계약이다.
