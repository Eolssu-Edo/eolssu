# 공개곡 판본 보관과 정확한 조회

S15P31E102-745. MR !576의 판본 보존 변경을 비행기 데이터 작업(707), 녹음 판본 보호(453), 기록 상세 소비(454)와 분리한다.

## 동작

공개곡 교체 전 악보 JSON과 당시 공개 메타데이터를 `(song_id, score_version)`으로 보관한다. 보관과 현재 판본 교체는 같은 트랜잭션에서 실행한다. 사용자 세션·녹음·평가 결과는 바꾸지 않는다. 마이그레이션은 보관 표만 만들며 운영 곡을 자동 교체하지 않는다.

`GET /api/songs/{id}`와 `/score`의 선택적 `scoreVersion`은 양의 정수의 정확한 판본을 조회한다. 생략하면 현재 판본이다. 잘못된 형식은 400, 없는 판본은 404다. 현재 곡이 숨김·삭제되었거나 보관 판본이 공개되지 않았다면 공개 조회하지 않는다. 개인 악보에는 적용하지 않는다.

진행 중 분석과 취약 구간·구간 비교는 세션의 판본을 읽는다. 보관되지 않은 판본을 현재 악보로 대신 채점하지 않는다. 기존 인증·소유권 정책을 유지한다.

PRA-03은 `scoreVersion: Int`, `songTitle: String`을 항상 포함한다. 제목은 보관 판본이 있으면 당시 제목을, 없으면 연결된 곡의 제목을 사용한다. 제목 조회는 공개 상태로 기록 접근을 제한하지 않는다. REC 목록·저장 응답도 세션의 판본을 포함한다.

## 게시와 소비자

기존 비행기 release의 `task=S15P31E102-707`과 해시·객체 키 계약은 유지한다. 게시기는 검증된 변경 전 상태에서만 56 v1 보관·v2 음원 등록·현재 행 교체를 수행한다. 다른 세 곡과 기존 음원·기록을 보존하며 충돌 시 전체 rollback한다.

녹음 판본·새 세션 보호는 453, 앱의 결과·기록·취약 구간 표시와 악보 실패 상태는 454의 범위다. 서버의 활성 세션 0건만으로 구 앱의 미제출 녹음까지 안전하다고 판단하지 않는다. 707의 실제 v2 공개는 세 Task 검증과 앱 전환 확인 후 수행한다.

## 검증

고정 v1 세션을 만든 뒤 현재 곡을 v2로 교체해 실제 MySQL HTTP의 현재/과거 조회·실패·메타데이터·분석·취약 구간을 대조한다. 게시기는 작은 고정 묶음으로 원자성·충돌·재실행·gate 복구를 검사한다. 사용자 실제 녹음·CAT 품질·운영 반영은 이 검사로 대체하지 않는다.
