# Mattermost 점검 수집과 판정

[S15P31E102-664](https://ssafy.atlassian.net/browse/S15P31E102-664) · [메시지 구성](mattermost-inspection-messages.md)

- 서버 점검은 Docker 저장공간 API를 한 번 조회한다. 저장공간 조회가 실패해도 이미 수집한 엔진 상태와 RAM 사용량을 표시한다. 점유량과 회수 가능량은 엔진이 제공하는 근거로 표시한다.
- 컨테이너 점검은 고정 태그의 로컬 syslog 저장 크기를 파일 메타데이터로 읽는다. API 슬롯은 같은 로그를 공유한다. node-exporter의 읽기 전용 호스트 루트는 관측용으로 표시하고 용량 순회를 생략한다. Jenkins 등 실제 데이터 경로의 접근 오류·경로 시간 초과·전체 측정 예산 소진을 구분한다.
- NET과 블록 I/O는 개별 판정한다. Docker 블록 I/O 필드가 없거나 null이면 검증된 cgroup v2의 카운터를 읽는다. 읽을 수 있는 빈 통계는 기록 없음이고, 조회 실패는 미측정이다.
- edo2 대기 웹의 Docker 준비 검사가 미설정이면 등록된 loopback 포트에 직접 연결해 인증서와 `/index.html` HTTP 200을 확인한다. Docker의 중지·비정상 상태와 중계 자체 HTTPS는 별도로 판정한다. 대기 웹 컨테이너를 교체하지 않는다.

두 서버의 기존 명령과 권한 경계를 유지한다. 회귀 테스트와 운영 수집·중계 렌더링으로 확인한다.

## edo1 컨테이너 준비 상태

- 컨테이너 점검은 상태 점검과 같은 준비 검사 결과를 컨테이너 이름으로 연결하고 판정과 근거를 함께 보여 준다. Docker 상세 조회 실패·중지·비정상 상태는 준비 검사 결과보다 우선한다.
- 준비 검사 성공은 실행 중인 서비스에 `검증 완료`와 근거를 표시한다. 명시적 실패는 장애, 오래된 관측은 주의, 검사 경로나 필요한 근거를 확보하지 못한 경우는 확인 불가, 근거가 없는 경우는 미검증으로 구분한다. Docker 검사만 통과했다면 그 검사 범위로 표시한다.
- 공통 결과가 없거나 지원하지 않는 서비스는 기존 Docker 근거를 사용한다. edo2 대기 웹의 HTTPS 판정은 기존 표시를 유지한다.
- 연주 분석 AI의 준비 검사 범위는 HTTP 통신이다. 공통 수집기가 기대한 입력 검증 응답을 `정상`과 `readiness_kind: http_communication`으로 전달하면 `통신 정상`과 `POST /v1/analyses · HTTP 422 (입력 검증 응답)`을 표시한다. Docker 검사와 HTTP 실패는 기존 우선순위를 따른다.
- MySQL 복제 프록시는 인벤토리에 남긴다. 공통 수집기가 로컬 수신 성공을 `정상`과 `readiness_kind: tcp_listener`로 전달하면 `실행 · 로컬 수신 확인`과 수신 근거, `복제 통신은 /edo2-health에서 확인`을 표시한다. 로컬 수신 성공은 복제 통신 미검증으로 집계하지 않는다. Docker 중지, 로컬 수신 실패와 확인 불가는 각각 표시하며 복제 통신 판정은 출발지인 edo2 상태 점검에서 확인한다.
