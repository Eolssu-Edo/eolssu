# 설치된 APK의 실제 앱 로그 연결

- 대상: S15P31E102-994. 현재 설치된 QA APK의 성능 이벤트를 그대로 읽는다. 앱 빌드·설치·실행 상태와 API 주소를 바꾸지 않는다.
- 최종 경로는 `exec-out run-as com.ssafy.eolssu.qa --user 0 cat no_backup/qa-performance.db`로 고정된 성능 DB만 읽는다. 앱 브로드캐스트·ACK·원본 파일 쓰기·삭제가 없다. 초기 begin/read 경로는 순차 재조회 지연으로 대체했다.
- 변경된 DB는 연속 두 사본이 같은 경우만 PC 임시 파일에 복제해 SQLite readOnly로 열고 quick_check·상태·연속 순번을 검사한다. 일관성이 맞지 않으면 다음 주기에 재시도한다. PC 원문 임시 사본은 매번 즉시 삭제한다. WAL 등 확인하지 않은 형식은 조용히 과거 데이터로 처리하지 않고 수집 대기로 표시한다.
- 기기 수집 간격은400ms, 선택한 QA 화면 조회는500ms다. 순번 뒤 새 항목만 투영하며 현재 APK가 DB에 보존한 해당 버전의 모든 기록을 1600건씩 이어 읽는다. 원본에서 이미 ACK된 기록은 복구하지 않는다. 화면은150건씩 표시하고 이전 기록/최신 기록으로 전체를 탐색한다. 이는 설정값이고 실제 반영 지연은 기기 연결 후 따로 측정한다.
- 등록된 기기의 ADB 전송과 고정 identity를 확인한다. 기기당 한 조회만 수행하며 private 앱 로그 조회와 설치 유지보수의 기존 배타 경계를 공유한다. 중복 브라우저 조회는 같은 수집 캐시를 사용한다.
- `GET ./api/live/status`의 기존 이름 세션·기기 경계를 유지한다. 일반 APK는 수집 캐시에 있는 실제 앱 이벤트를 operations/evidence로 투영하고 격리 서버 검사/부하/실행 이력과 자동 로그인·합성 입력은 사용자 결정으로 현행 UI에서 종료한다. 과거 근거 파일은 보존한다. 기본 상세 로그는 연결된 모든 기기로 열고 출처/기기/동작 필터를 유지한다. 격리 서비스 연결은 제거하며 원본 로그를 기존 중계에서 함께 수집한다. 운영 서버에 고의 실패/부하를 자동 이전하지 않는다.
- 앱 원문은 허용한 enum·수치·난수 ID·버전만 사용한다. 로그 출처는 앱으로 고정하고 원문의 source는 dataSource로 구분해 보존하며 서버 증거로 신뢰하지 않는다. run_started/log_gap과 누락 수, run/버전, 원본 단조 시각도 유지한다. 비밀번호·쿠키·토큰·URL·본문은 전달하지 않는다.
- stream/순번으로 중복을 막고 앱 run·flow·visit을 분리한다. 설치 버전과 다른 과거 이벤트를 현재 동작으로 표시하지 않는다. 재시작/부분 조회/기기 연결 끊김을 명시하고 실제 이벤트·원본 시간·수신 시각을 구분한다.
- 앱의 HTTP 시도·데이터 로드·화면 그리기 근거만 표시한다. 없는 요청 UUID·서버 수신·AI 완료·DB 저장·완료 상태를 만들지 않는다. 일반 APK의 API 주소를 격리 루프백으로 표시하지 않는다.
- 완료 확인: 현재 APK의 실제 로그가 QA 웹에서 새로고침 없이 보이고, 기기별 격리·설치 버전·정규화·영상 동작과 종료된 검사 명령의 차단을 확인한다. 사용자의 앱을 조작해 새 로그를 발생시키지 않는다.


## 연결과 화면 변경

- 사용자가 PC 페어링 키 입력 제거를 승인했다. 이름 세션 참가자는 등록된 기기의 Android 팝업 포트·6자리 일회 코드를 입력해 페어링한다. HTTPS/동일 출처·세션·현재 조작자·설치 배타·단일 실행/2초 재시도 제한은 유지한다. IP/명령/기기 ID를 브라우저에서 받지 않는다. 물리 기기의 코드를 가진 참가자에게 허용 범위가 넓어지는 변경이며 별도 PC 비밀은 생성/전달하지 않는다.
- APK 버전 관리 카드와 이력 선택만 제거한다. 상단 최신 APK 적용과 빌드 보관/기존 자료는 보존한다. 검증 중 설치 버튼을 누르지 않는다.
- USB로 시작해도 일치하는 등록 ID의 저장된 TLS 주소를 읽어 감시기를 켠다. 무선 검색 중에도 USB 연결을 매 주기 확인하고 USB가 있으면 우선한다. USB가 없으면 감시기는 종료하지 않고 포트 힌트→mDNS/기존 연결→등록된 IP의 포트 검색을 반복한다. 폰/태블릿 모두1초 주기로 확인하며 포트 전체 검색 후5초 쉬고 반복한다. 한 검색 묶음과 ADB 응답 시간은 추가되므로1초 복구 보장은 아니다.
- Android TLS 무선 디버깅·기존 페어링은 유지한다. 무선 디버깅이 꺼져 있거나 IP/네트워크가 바뀌어 등록 주소에 닿지 않으면 접속할 수 없으며, IP 변경은 운영 설정 갱신이 필요하다.

- 2026-11-16 확정: 격리 QA backend/AI/DB를 종료하고 앱의 현재 서버 설정을 유지한다. 로그 수집을 별도 서비스로 분리하지 않는다. 추가 비동기 서버 상태 캐시도 도입하지 않는다. 기존 live/control은410으로 종료하고 신규 격리 실행·패키징을 차단한다.
