## 동작과 경계

WAV 원본의 해시·샘플레이트·채널·라벨 ID·출처·추정 상태를 유지하고 배포용 AAC-LC M4A를 생성한다. 원본 음높이·구간을 다시 조율하거나 라벨을 확정 정답으로 승격하지 않는다. 각 출력은 전체 디코드와 길이 대조를 통과해야 한다. 출력 폴더는 새 경로만 허용하고 실패 시 완성된 manifest를 남기지 않는다.

DB에는 `reference_audio_assets`를 추가한다. 기존 `pitches`는 악기별 녹음 ID가 아니므로 변경하지 않는다. 기존 단음의 임의 대표 파일 선택을 피하고 `datasetId + labelId`를 자산 식별 기준으로 사용한다. 430개 모두 선택 가능한 새 조회 API를 제공한다. 기존 CAT-06/08, FE 재생 동작과 사용자 녹음 저장 정책은 보존한다.

## 변환·적재 계약

- 출력 manifest schemaVersion=1, `assets` 배열. `assetId`는 UTF-8 `datasetId + "\n" + labelId`의 SHA-256 소문자 64자리다.
- 공통 필드: assetId, datasetId, labelId, category, technique, register, yulmyeong, displayLabel, file, objectKey, contentType, sha256, bytes, durationMs, sampleRateHz, channels, review, eligibleForNoteScoring, metadata.
- datasetId: danso, sogeum, jeongak-daegeum, sanjo-daegeum. 원래 catalog datasetId와 일치해야 한다.
- objectKey: `reference-audio/v1/{datasetId}/{assetId}/{sha256}.m4a`. 사용자 녹음의 `recordings/` 및 그 30일 삭제 규칙을 사용하지 않는다.
- contentType=`audio/mp4`; AAC-LC 목표 192kbps, 원본 샘플레이트·채널 유지. metadata는 원본 label/source와 WAV SHA·크기·프레임 정보를 포함한다.
- 적재는 별도 CLI가 검증한 manifest에서 재실행 가능한 SQL을 만든다. 기본 DRAFT. 동일 ID의 다른 파일/메타데이터를 무조건 덮어쓰지 않는다. 실제 저장소 게시 검증 뒤 PUBLISHED로 전환한다.

## 조회·재생

- `GET /api/reference-audios`: datasetId(필수), category/technique/register/yulmyeong 선택 필터. PUBLISHED만 안정된 순서로 반환.
- `GET /api/reference-audios/{assetId}`: 게시된 자산 상세와 출처·검수 상태.
- `GET /api/reference-audios/{assetId}/play`: 게시된 키에 대해서만 만료형 서명 GET URL로 이동. DB에는 만료 URL을 저장하지 않는다. 응답은 캐시하지 않는다.
- 상세/목록의 soundUrl은 위 재생 경로로 연결한다. 상대 경로임을 계약에 명시한다. 저장소 미설정 시 재생은 공통 형식 503, 없거나 DRAFT인 ID는 404, 잘못된 입력은 400.
- 기존 공개 카탈로그처럼 읽기만 공개한다. 임의 object key나 URL 입력으로 서명하는 API와 공개 쓰기 API는 만들지 않는다.
- 별도 REFERENCE_AUDIO_STORAGE_* 설정으로 읽기용 서명기를 구성한다. 사용자 녹음의 local/s3 선택·비밀값·삭제 동작과 독립적이다. 운영 버킷 공개 정책은 변경하지 않는다.

## 2026-11-02 후속 확정: 기본음과 기준 음의 명시적 관계

사용자의 관계 보완 요청으로 앞 절의 관계 보류 결정을 다음 범위에서 대체한다. `reference_audio_assets.pitch_id`는 nullable FK로 `pitches.id`를 참조한다. 기준 음 하나에 여러 주법·세기의 기본음 녹음이 연결된다. 이 연결은 라벨이 뜻하는 명목상 음의 식별이며, 실측 주파수 검수나 채점 정답 승격이 아니다. 시김새와 근거가 없는 음원은 null이다.

V13은 유지하고 V14에서 FK와 `pitch_mapping_basis`를 추가한다. 둘은 함께 null이거나 유효한 값이어야 하며 기본음만 연결한다. 명시적 매핑 CLI는 검증된 manifest의 자산·파일 해시와 연결 근거를 확인하고 `(yul, octave)`로 대상 pitch를 찾는다. 없는 대상·충돌은 전체 배치를 거부하고 동일 매핑 재실행과 기존 import는 상태를 보존한다. 최초 단소 기본음 30개 매핑에 아래 라벨 재대조 결과를 추가한다.

목록과 상세의 자산에 `pitchId: string | null`을 추가한다. 목록은 선택 `pitchId` 필터를 제공하며 1부터 9223372036854775807까지의 선행 0 없는 십진 문자열만 받는다(그 외 공통 400). 미연결은 JSON null, 없는 양수 ID는 빈 목록이다. 근거는 DB/매핑 파일에 보관하고 공개 응답 필드는 늘리지 않는다. 기존 경로·응답 봉투·soundUrl·재생 동작을 보존한다.

위 141개 단계에서 확인한 미등록 기준 음을 추가한다. 사용자는 **현재 API 방식 유지: 단소 범위 내15음을 모두 표시**를 선택했다. V15는 기존11행의 ID·율명·반음과 단소 악기의 범위 경계를 보존하고 필요한 기준 음11행을 추가한다. 전역 목록은22개, 기존 semitone 범위 필터의 단소 목록은15개가 된다. 악기별 별도 허용 목록 테이블이나 API 의미 변경은 추가하지 않는다.

새 기준은 임/남/무 octave−1, 황/태/고 octave0, 남 octave0, 고/남 octave1, 고/임 octave2다. ID는 DB에서 할당하며 기존 `data/reference/pitches.json`은 단소 전사 기준이므로 확대하지 않는다. 한자는 기존 `data/src/scores/review_page.html`의 HANJA 표를 따른다.

완료 기준을 **기본음219개 연결(단소30·정악54·소금90·산조45), 미연결211개(시김새207·명시적 대안4)**로 대체한다. 기존 단소 매핑/근거와 모두의 inferred/채점 제외/파일을 보존한다. 스키마/기준 데이터가 바뀌므로 clean build와 databaseTest를 다시 실행하고 실제430개 적재·매핑·재실행, 전역22/단소15 조회를 검증한다.

## 후속 확정: 시김새207개의 역할별 음 관계

사용자의 시김새 연결 요청에 따라 기존 라벨 근거를 재사용한다. 기본음 전용 scalar FK를 모든 음형의 대표음으로 확장하는 대신 V16 `reference_audio_pitch_relations`에 자산·역할·관측 순서·기준 음 FK·근거 경로·매핑 근거를 저장한다. 원래 `pitchId`/필터는 기본음 전용으로 유지한다.

- 207자산 모두 `LABEL`(행의 명목상 율명) 1개를 가진다. 단소26·소금12자산에는 `SEQUENCE` 88개, 산조 다루치기10자산에는 `LOWER_ANCHOR`/`DESTINATION` 20개를 추가한다. 총315관계이며 추가 기준 음은 없다.
- `SEQUENCE`만 원래 orderedAnchors 배열의 0부터 시작하는 순서를 가진다. 다른 역할은 순서가 없고 DB 키용 index=0이다. 목록 정렬은 LABEL, SEQUENCE(index), LOWER_ANCHOR, DESTINATION이며 시간순이라는 뜻이 아니다.
- 원음 기준 F0 분석창은 음표의 시작/끝이 아니다. 다루치기 반복 횟수로 관측하지 않은 이벤트를 만들지 않는다. labelAnchorIndex, 대안, 검토 근거는 metadata에 보존한다. 연결은 inferred 라벨의 명목상 대응이며 채점 정답 승격이 아니다.
- 목록/상세 자산은 `pitchRelations: [{role, sequenceIndex: number|null, pitchId: string, evidencePath: string}]`를 추가한다. 기본음은 빈 배열이다. evidencePath는 상세 metadata를 기준으로 한 JSON Pointer다.
- 새 선택 필터 `relatedPitchId`는 기본음 scalar 또는 역할별 관계의 일치를 찾는다. 기존 필터들과 AND이며 동일 음이 반복돼도 자산은 한 번만 나온다. ID 형식/400은 기존 pitchId와 같다. 목록 관계는 배치 조회하고 재생에는 추가 조회가 없다.
- 명시적 매핑 CLI는 manifest 파일·자산 식별과 원본 metadata를 검사한다. SQL은 자산/기준 음을 잠그고 전체 관계 집합을 비교한다. 기존 집합이 완전히 같으면 no-op, 부분/추가/충돌·누락 대상·근거 변경이면 전체 배치를 거부한다. 기존 import 역시 metadata 충돌을 거부하므로 관계가 낡은 근거 위에 남지 않는다.
- 완료 검증: V16 제약, 순서/역할/근거 대응, atomic conflict/replay, 기존 scalar 필터 보존, 새 필터 중복 방지, 실제430개 중426연결·4미연결 및 모든 상태/파일/metadata 보존, clean build/databaseTest/Python/HTTP.

## 현재 배포 단위: 최종 V13

운영 Flyway가 V12까지이고 신규카탈로그 테이블이 없다는2026-11-02 확인에 따라 미적용 개발파일 V13~V16을 최종V13 하나로 묶는다. 자산테이블의 기본음 FK/근거, 누락11개 기준음, 역할별 관계테이블을 함께 정의한다. 위 기능·검수/채점·API·426/315 완료조건은 그대로다. 명시적 매핑의 파생SQL참조는 최종V13으로 정렬하고 이전개발이력은 Git에 보존한다. 이미 과거개발판을 적용한 테스트DB는 새 폐기DB로 대체하며 운영checksum repair나 DDL 원자적롤백을 가정하지 않는다.

## 명시적 매핑 JSON 간소화

사용자의 큰 JSON 구조 개선 요청에 따라 내부 매핑8파일을 schemaVersion2로 바꾼다. 파일 공통 datasetId·basis와 원본 manifest 파일의 SHA-256을 한 번 기록한다. 기본음 행은 labelId/yul/octave, 시김새 행은 labelId와 label/sequence/lowerAnchor/destination의 명시적 yul/octave 객체만 보유한다. sequence와 두 gesture 역할은 원본에 있을 때만 기록한다. 자산 한 행은 한 줄로 표시하고 이름을 축약하거나 위치 배열·암시적 범위로 바꾸지 않는다.

manifest는 같은 바이트를 한 번 읽어 SHA-256 검증 후 JSON으로 해석하고 기존 파일/출처 검사를 수행한다. 자산 ID·파일해시·원본분류·역할·순서·근거경로는 검증된 manifest에서 복원한다. 목표음은 계속 명시적 입력이며 측정 F0로 추정하지 않는다. 잘못된 버전/필드·중복JSON키/labelId·해시·dataset/category·목표·누락/추가 역할·선택음 불일치는 SQL 생성 전에 거부한다. schema1은 내부 호출부를 함께 이전하고 제거한다.

SQL DB guard와 basis는 그대로다. 변경 전 실제430개에서 확보한8개 확장 매핑/SQL과 변경 후 결과가 완전히 같아야 한다. 기준은 기본음219/시김새207/315관계/미연결4개, SQL8파일 바이트 동일, 기존 SQL 적용 후 새 SQL 재실행의 전체 DB행 보존이다. 공개API·V13·원본 annotations/M4A/manifest는 변경하지 않는다.

## 후속 UI 확정: 카드 안 선택·재생·탐색

사용자 추가 요청으로 재생 모달과 읽기 전용 진행 막대를 대체한다. 운지법과 기초 학습의 운지 카드에서 옵션 버튼을 누를 때마다 정확한 악기·취법·율명의 다음 녹음으로 순환하며 현재/전체 개수를 표시한다. 기본음·시김새 옵션의 주법과 길이를 보존하고 선택만으로 재생하지 않는다. 옆 버튼은 재생·일시정지·이어 듣기를 전환한다.

현재/전체 시간과 Slider를 카드 안에 두고 터치·드래그로 위치를 조절한다. 재생 중 이동은 재생을 유지하고 일시정지 중 이동은 정지를 유지한다. 완료 후 이동은 Paused로 준비한다. 로딩·실패·미선택에는 탐색을 비활성화한다. 한 화면의 player 하나를 공유하며 선택/악기/취법/단계 변경과 화면 이탈 시 해제한다. 출처·가공은 작은 링크를 누르면 같은 카드 안에서 펼치며 별도 모달은 띄우지 않는다. 원본 출처 웹 링크는 유지한다.

2026-11-02 추가 요청으로 운지법 화면 하단의 `등록된 율명·운지 자료` 버튼을 제거한다. 기존 악기·취법 선택과 카드 내부 녹음 컨트롤은 유지한다. 운지표와 녹음의 수록 범위 차이는 [대조 기록](../knowledge/frontend/reference-audio-playback.md)에 남기며, 없는 자료의 운지·음원을 임의로 채우지는 않는다.
