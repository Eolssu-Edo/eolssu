# 공통 악보·모범 음원 적재와 재생 연결

작업: S15P31E102-339, Story30. 2026-11-02 사용자 요청: 생성한 악보 전체와 음원을 추가한다. 기존 공개4곡은 덮어쓰지 않는다. FE380은 별도 Draft MR !222다.

## 후속 결정: 우선 사용하고 곡별 수정

사용자는 청음으로 직접 품질을 판단하기 어렵고, 우선 넣어 사용하다 문제가 있으면 삭제·교체하는 방식을 선택했다. 이에 따라 전문가 청음을 게시 선행 조건에서 제외한다. 아래 DRAFT 적재 기록은 이전 단계의 결과이며, 다음 목표는 기술적으로 조회·재생 가능한107개를 공개 연습곡으로 제공하는 것이다. 자동 생성·inferred·임시 난이도와 원자료의 사용 승인 미확인 기록을 확정 검수/승인으로 바꾸지는 않는다. 새 곡의 비채점 상태와 기존4곡은 유지한다.

현재 FE는 장단 NULL103건을 목록 전체의 오류로 처리하므로 상태만 PUBLISHED로 바꾸지 않는다. BE339의 객체 키 기반 읽기 경로와 FE380의 nullable 장단·실제 수행 시간표 소비를 먼저 연결한다. 배포는 기존 develop 이력 검증을 따르고 MR은 사람이 병합한다. 코드가 준비된 것과 운영에서 신규곡을 볼 수 있는 상태를 구분한다.

사용자가 기본음의 저장 방식과 일관성을 확인한 데 따라 모범 음원도 DB에 URL 대신 `object_key`를 저장한다. `performance_object_key`, `source_common_sha256`으로 같은 판본의 수행 시간표를 연결하고, 기존 description의 내부 근거 JSON은 `song_model_audios.generation_metadata`로 옮긴다. 사용자용 description에는 이 내부 JSON을 표시하지 않는다. 기존107개의 악보 원문·버전·음원 바이트·해시·길이는 보존하며 새로 합성하지 않는다. 모르는 기존 URL은 추정 변환하지 않고 마이그레이션을 중단한다.

CAT-05의 앱 응답은 `audioUrl`을 유지하되 서버 기준 `/api/songs/{songId}/model-audio/play`를 제공한다. 매 요청 게시 상태를 확인한 뒤 짧은 읽기 전용 서명 URL로 이동한다. 선택적 `performanceUrl`과 `sourceCommonSha256`은 공통 악보와 수행 시간표를 결합하는 데 사용한다. 수행 JSON은 같은 서버에서 크기·시간 제한 아래 제공해 Web의 외부 저장소 CORS 설정 변경을 요구하지 않는다. 버킷 공개·사용자 녹음 키 노출·만료 URL의 DB 저장은 하지 않는다.

문제 곡은 정확한 sourceId·버전·파일 해시를 확인해 개별 HIDDEN으로 내린다. 원본 객체와 기존 연결은 보존한다. 교체 시 새 파일·해시·버전으로 검증한 결과를 연결하며 무조건 삭제하거나 동일 키의 바이트를 덮어쓰지 않는다. 공개·숨김 도구는 기본 조회, 명시적 적용, 이전/이후 receipt, 재실행과 충돌 거부를 갖춘다.

## 최초 적재 범위와 당시 결정

- 공통 v1 기반으로 생성·디코딩 검증한107개 묶음(단소46·소금23·정악대금28·산조대금10)을 적재한다. sourceId·악기·판본·파트를 식별자로 사용하고 제목으로 병합하지 않는다.
- 원본 공통 JSON·표현·수행 시간표·M4A와 생성 근거 파일을 SHA256 manifest로 묶는다. 원본 바이트와 기존 서비스4곡의 ID·악보·게시 상태는 보존한다.
- 현 출처의 inferred·serviceDatasetApproved=false/사용권 미확인 상태를 유지하며 새 자료는 DRAFT다. PUBLISHED 전환·새 검수 승인·운영 앱 동기화 완료를 포함하지 않는다.
- 기존 운영 R2의 비공개 객체 저장을 사용하되 `recordings/`와 분리된 `model-audio/drafts/<manifest-sha256>/`에 해시가 일치하는 새 객체만 쓴다. 버킷 공개·수명주기·사용자 녹음 정책은 변경하지 않는다. 원래 버킷 설정은 서버에서 읽으며 자격값·서명 URL은 출력하지 않는다.
- 업로드 전 모든 파일·경로·해시·크기를 검증한다. 같은 키가 있으면 실제 바이트 해시를 대조해 같은 객체만 재사용하고 다른 내용은 중단한다. 업로드 후 다시 읽어 SHA256을 확인한다. 삭제·덮어쓰기·음원 공개는 하지 않는다.

## 서비스 DB 연결과 사용자 결정

107개는 모두 QUARTER 기준이며 곡 난이도는 원본에 없다. 새3악기의 채점 허용치와 일부 음역·장단 pattern도 확정돼 있지 않다. 변경 전 songs의 instrument_id/jangdan_id/difficulty는 NOT NULL이며 이름만 같은 장단을 연결하면 기존 DOTTED_QUARTER와 충돌한다.

사용자는 악기는 연결하고, 장단은 없을 수 있으므로 비워두며, 난이도는 기준을 정해 판정하도록 지시했다. 따라서 instrument_id/difficulty는 필수로 유지하고 jangdan_id만 nullable로 바꾼다. 연결 장단이 없을 때 BPM 단위는 원본 score.music.bpmUnit을 사용한다. 기존 장단을 연결했을 때의 일치 검증은 유지하며 가짜 장단/pattern을 추가하지 않는다.

현재 FE는1=입문,2=초급,3=중급이다. 사용자가 이 분류도 확정본이 아니라고 설명했으므로 자동 난이도는 이3단계의 임시 기준으로 저장하고 policyVersion·측정값·축별 점수·근거를 함께 기록한다. 기존 DB의4/5를 새로 사용하거나 프론트 분류를 고치지 않는다.

기존 단소 설정은 보존한다. 새 악기는 canonical instrument code로 연결하되 공개 활성화·채점 승인을 하지 않는다. 새 악기 행은 비활성으로 두고, 등록 데이터의 실제 율명 범위를 근거로 기록한다. 채점 허용치 등 미정 운영 기본값은 승인된 악기별 음악 기준으로 주장하지 않으며 새 곡의 is_scorable=false를 유지한다. 공개 전 검수 항목으로 기록한다.

107개 중 기존 중모리·QUARTER와 맞는4개는 해당 장단을 연결한다. 나머지103개는 장단 FK를 비우고 원본 이름을 악보에 보존한다. 세마치·굿거리는 이름이 같아도 기존 DB의 DOTTED_QUARTER와 단위가 다르므로 연결하지 않는다.

## 임시 난이도 산정

정본 NOTE만 사용해 아래5축을 각각0~2점으로 계산한다. 총0~2점은 입문,3~5점은 초급,6~10점은 중급이다. 정책 버전은 `score-difficulty/provisional-fe3/v1`이며 곡마다 원본 해시·측정값·축별 점수·판정 근거를 보관한다. 쉼표로 연주 밀도가 희석되지 않도록 실제 NOTE 길이 합계를 사용한다. 시김새 기호는 악보 읽기 부담으로만 세며 악기별 실제 연주 난이도가 검증됐다는 뜻은 아니다.

| 축 | 1점 | 2점 |
| --- | --- | --- |
| 초당 NOTE 수 | 1.5 초과 | 3 초과 |
| 가장 짧은 NOTE | 0.5초 미만 | 0.25초 미만 |
| 음역 또는 7반음 이상 도약 비율 | 12반음 초과 또는10% 이상 | 24반음 초과 또는25% 이상 |
| 반 정간보다 짧은 NOTE 비율 | 10% 이상 | 30% 이상 |
| 시김새 기호가 붙은 NOTE 비율 | 10% 이상 | 30% 이상 |

이 기준으로107개는 입문39·초급41·중급27이다. 사용자 안내대로 FE 단계 자체도 확정본이 아니며, 전문 검수 후 정책 버전과 함께 재산정할 수 있다.

## 검증·복구

파일 업로드는 private prefix 내의 내용 검증만 수행하며 서비스 공개4곡 API 결과가 유지되는지 확인한다. 결과 receipt에는 manifest SHA·객체 키·SHA·크기·새 생성/재사용 여부를 기록한다. 사용자 결정에 따라 배포 lock·변경 전 백업 아래 nullable 장단 DDL과 조건부 데이터 적재를 수행한다. DDL의 implicit commit과 데이터 transaction rollback은 구분하고, 기존 행 불변·중복 재실행·DB readback을 확인한다. 공개 전환은 음원 사용권·미정 메타데이터·performance 소비 및 FE의 nullable 장단 대응을 확인한 뒤 별도로 진행한다.
