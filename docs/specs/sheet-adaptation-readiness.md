# 분석 완료 후 음역 맞추기 준비

S15P31E102-879 · Story S15P31E102-319. 사용자는 분석이 끝난 악보에서 추천·이조를 바로 조절하고 같은 악보로 검증한 뒤 MR을 게시하도록 요청했다.

## 동작과 범위

- 기존에는 편집 문서를 받은 뒤 저장 검증·음역 맞추기·음원 악기 목록을 별도로 조회하고 탭을 열 때마다 로딩 상태를 새로 만든다. OMR 재분석이 아니라 카탈로그 중복 조회다.
- 악보 작성에 필요한 활성 악기·전체 등록 음·악기별 지원 음역·장단을 업로드 및 분석 중 준비하고 편집 화면에서 함께 재사용한다. 일반 카탈로그 API·다른 기능의 캐시 정책은 바꾸지 않는다.
- 준비된 분석 결과를 열 때 음역 맞추기 추천과 이조 조절을 즉시 제공한다. 같은 악보에서 탭을 다시 열거나 준비된 악기를 다시 선택하면 카탈로그를 재요청하거나 추천 영역을 로딩으로 초기화하지 않는다. 사용자의 선택을 유지한다.
- 악보가 바뀌면 현재 원본 연결과 편집본을 기준으로 추천을 다시 계산한다. 추천 기준·음표 ID·시각·원본 음고·되돌리기·저장 검증은 유지한다.
- 회원 ID와 세션 세대를 경계로 준비 자료와 실행 작업을 격리한다. 계정 전환 후 늦은 응답은 재사용하지 않는다. 준비 실패를 성공으로 표시하지 않으며 필요한 악기의 재시도를 허용한다. 앱을 새로 연 경우의 최초 문서·필수 자료 조회까지 없애지는 않는다.

## 완료 조건

1. 실제 ViewModel 경계의 회귀로 초기 준비·동시 중복 방지·같은 악보 재진입·악기 변경·추천 선택 유지·악보 편집 후 재계산·실패 복구·계정 전환을 확인한다.
2. 같은 `nmixx-blue-valentine_easy_pdf.pdf`를 사용한 실제 로컬 앱에서 분석 완료→편집→음역 맞추기·이조·적용·되돌리기·재진입을 확인하고 요청 횟수와 화면 근거를 보관한다. 추천 +6반음·옥타브 이동 5개·수정 필요 0개는 기존 동일 인식 결과의 기준이며 전곡 인식 정확도 인증은 아니다.
3. 관련 Android host 회귀와 공유 Web 빌드를 실행한다. Windows에서 확인하지 못한 iOS·실기기는 별도로 밝힌다.
4. 최신 develop과 통합해 Draft MR을 게시한다. 운영 데이터·배포는 변경하지 않는다.
