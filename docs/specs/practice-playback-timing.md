# 연습 화면의 장단 타이밍과 긴 악보 표시

- 작업: S15P31E102-791의 재생 누락·화면 지연 후속 수정
- 상태: 2026-11-12 사용자 요청으로 구현 승인
- 기존 구간 빠르기·편집 API 업무와 그 선행 Task는 유지한다. 이 문서는 해당 계약에 의존하지 않는 연습 재생 수정 범위다.

## 기대 동작

장단 샘플은 재생 전에 준비한다. Android에서 UI 작업이 지연되어도 장단 시계와 타격 처리는 계속 진행한다. 소리는 모범 음원 또는 연습 시계를 따르며, 늦은 타격을 한꺼번에 몰아치지 않는다.

후속 실측에서 타격 요청은 약 385–395ms로 일정했지만 SoundPool 출력은 341–448ms로 흔들렸다. 동일 캡처 경로의 고정 PCM 기준 음원은 389.604–389.625ms였다. Android에서는 타격을 단일 PCM 스트림의 짧은 버퍼에 혼합하여 개별 스트림 시작 지연을 없앤다. 기존 모범/연습 시계와 즉시 출력 인터페이스는 유지한다. 정지·탐색·해제 시 이미 혼합된 native 버퍼와 타격 잔향도 제거한다.

반주는 화면용 보정 속도를 사용하지 않는다. Android 음원 위치에는 실제 측정 시각을 함께 전달하여 UI 전달 지연이 타격 시간에 더해지지 않도록 한다. 연속 재생 중 음원 위치의 작은 후행 보고로 같은 타격이 다시 나지 않으며, 명시적 탐색은 새 시계를 사용한다. 출력 중 쓰기 실패는 즉시 실패 상태로 종료하고, native 출력이 굶으면 이미 지난 PCM 구간을 다시 밀어 넣어 이후 타격까지 계속 늦추지 않는다.

Android의 재생 시작 알림과 실제 디코더 시계 진행을 구분한다. 최초 재생·탐색·재개 직후에는 위치가 실제로 움직일 때까지 장단 타격을 기다린다. 대기 중에는 타격 커서를 진행시키지 않아 탐색 시작점과 재개 중복 방지 기준을 보존한다.

native 출력 버퍼를 임의로 두 hardware burst까지 줄이지 않는다. Galaxy S24+에서 이 설정은 연속적인 버퍼 부족과 소리 잘림을 일으켰다. 플랫폼의 기본 버퍼를 유지하고 타격 파형과 간격을 함께 확인한다. 디코더 준비 신호를 제공하지 않는 플랫폼의 0 위치 반주 시계와 기존 첫 타격 동작은 보존한다.

처음 재생할 때 플레이어가 아직 0 위치를 보고하는 동안 회색 진행 표시가 먼저 나갔다가 뒤로 돌아오지 않는다. 재생 시작 이후의 진행 보정과 명시적인 탐색·재시작·반복을 구분한다.

긴 악보에서 화면 밖 UI 구성과 불필요한 갱신을 줄인다. 화면의 모양, 오른쪽부터 읽는 순서, 원본 음표·정간·tick 연결, 표시 위치·클릭·현재 위치 따라가기·확대·글꼴 배율을 보존한다. 같은 기기·곡·빌드 조건에서 성능 개선이 확인되는 변경만 유지한다.

## 수명주기와 범위

샘플 준비·오디오 포커스·UI 상태 전환은 화면 소유자가 유지하고, 타격 반복만 분리한다. 정지·일시 정지·탐색·변속·모드 변경·화면 이탈·백그라운드·포커스 손실 뒤에는 이전 재생의 타격이 이어지지 않는다. 자원을 해제한 뒤 다시 시작할 수 있다.

외부 API·악보 데이터·장단 패턴·BPM 정책은 바꾸지 않는다. 사용자 데이터 삭제, 운영 배포·Push·MR 생성은 이 요청의 범위에 포함하지 않는다. iOS는 Windows에서 검증할 수 없으므로 별도로 표시한다.

## 검증

1. UI 실행 문맥을 진행시키지 않는 동안에도 장단의 지정된 타격 시각이 유지되는 실패 전·성공 후 회귀.
2. 취소된 재생의 지연 준비·정지·재시작·출력 실패·탐색·변속·화면 이탈 회귀.
3. 최초 0 위치의 반복 보고와 이후 실제 진행, 명시적 탐색의 진행 표시 회귀.
4. 긴 악보의 처음·중간·끝과 가변 높이·분할 각·스크롤 범위를 확인하는 검사 및 실기기 UI 검증.
5. Android host 테스트와 APK 빌드. 같은 Galaxy S24+에서 공개 소금137·154 BPM·장단 켜짐 조건의 타격 간격과 프레임 통계를 전후 비교한다. 사용자 개인 악보 원본은 확보 여부를 구분한다.

기존 재현과 제한은 [진단 기록](../knowledge/frontend/android-jangdan-timing.md)을 따른다.
