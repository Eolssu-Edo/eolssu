# 정간보 한배 기호 인식과 구간 빠르기 편집

상태: Draft MR !736의 후속 수정·독립 재검토·현재 환경 검증을 완료했다. 후속 충돌 해결 요청의 develop 동기화·공유 검증은 [현재 계획](../plans/S15P31E102-882.md), 과거 상태는 [중단 시점 인수인계](../knowledge/ai/jeonggan-tempo-handoff.md)를 확인한다. Draft 해제·MR 병합은 수행하지 않았다.

S15P31E102-882의 빠르기 지원 후속 범위. 2026-11-13 사용자는 정간보에도 지원하도록 요청했고, 숫자가 없는 기호는 위치와 뜻을 보존한 뒤 기존 빠르기 편집에서 목표값을 지정하는 방식을 선택했다.

## 동작

- `ㅈㄴ`(좀/조금 느리게), `ㅈㅅ`(조금 속하게/빠르게), `ㅈㅈㄴ`(점점 느리게), `ㅈㅈㅅ`(점점 속하게/빠르게), `ㅂㅅ`(본래 속도로)의 뜻과 기보 위치를 보존한다. 낱자 사이 점과 세로 배열을 허용한다. 이 기호는 음높이를 만드는 시김새가 아니다.
- 숫자가 없는 새 인식 기호에는 0.8/1.2 같은 재생 배율을 자동 적용하지 않는다. 목표와, 점진 변화라면 끝 위치를 사용자가 지정하기 전에는 기호를 표시하고 목표 미지정 상태를 알리며 기존 빠르기를 유지한다. 본래 속도로의 목표는 이미 알려진 곡의 기본값이다.
- 새 입력 탭이나 정간을 추가하지 않는다. 기존 빠르기 창 안에 전체 빠르기와 구간 변경을 함께 둔다. 시작 정간, 바로/점점, 목표 빠르기를 편집하고 점점일 때 끝 정간을 정한다. 인식된 기호와 직접 추가한 기호를 같은 목록에서 수정·삭제할 수 있다.
- 악보에서 한배 기호와 적용 위치를 읽을 수 있어야 한다. 기존 음표·정간 ID와 기보 tick을 보존하며, 구간 편집도 되돌리기·다시하기 및 저장 후 재진입에서 유지한다.
- 전체 빠르기 변경 시 기존 확정 숫자 구간의 시작/목표를 같은 비율로 한 번 조정한다. 한배 기호 때문에 음고·음가를 바꾸지 않는다. 기존 구간 계획의 구조 편집 보호를 유지한다.
- 악기 맞춤·이조·개별 음 교정은 음고만 바꾸므로 인식·편집된 구간 빠르기와 기준 BPM을 보존한다. 전체 BPM이 기준과 달라도 시작/목표를 중복 조정하지 않으며, 적용·실행 취소/다시 실행·초안 저장/재진입 뒤 구간 목록과 예상 길이가 유지되어야 한다. companion의 반복·기호·원본 연결과 서버의 SHA 재결합 계약은 바꾸지 않는다.

## 기존 계약 재사용

공통 악보 v1과 `common-score-expressions/v1`의 기존 기호 배치·숫자 `performancePlan`을 사용한다. 새 파일 형식·DB 컬럼·재생 엔진을 만들지 않는다. 같은 정간의 한배 기호는 정간 시작부터 적용한다. 점진 변화는 기존 기보 위치에 대한 선형 BPM과 그 역수 적분을 사용한다. 목표가 없는 기호가 교육용 자동 근사로 재생되지 않도록 명시적 계획을 전달하고, 다른 기호·반복의 기존 의미를 보존한다.

정간보 인식은 글자층의 확인 가능한 낱자와 스캔의 판독 가능한 인쇄 기호를 읽어 위치와 함께 검토 가능하게 전달한다. 기존 분류 모델 가중치·음표 어휘를 임의로 바꾸지 않는다. 모호한 글자·위치나 검증하지 못한 사진은 확정 인식으로 보고하지 않는다. 실제 원본에 있는 `ㅈㄴ`/`ㅈㅅ`를 우선 대조하며, `ㅈㅈㄴ`/`ㅈㅈㅅ`/`ㅂㅅ`는 검증용 고정 입력의 지원과 실제 곡 인식 품질을 구분한다.

## 예상 음원 길이 (S15P31E102-903)

- 편집 화면과 저장 창은 구간 계획 유무만으로 예상 길이를 숨기지 않는다. 미입력 정간을 포함한 전체 기보 길이에 원본 `ticksPerJeonggan/ticksPerBeat` 비율을 적용한다.
- 즉시 변경은 해당 정간 시작부터 다음 변경까지 목표 BPM을 적용한다. 점진 변경은 시작부터 끝 위치까지 선형 BPM의 역수를 적분하며, 끝 이후에는 목표 BPM을 유지한다. 명시 시작 BPM이 있으면 이를 사용한다. 목표 미지정 기호는 기존 속도를 유지한다.
- 전체 BPM 입력 중에는 구간 BPM을 같은 비율로 계산하며 적용·저장·재진입 때 비율을 중복 적용하지 않는다. 구간 수정·삭제와 undo/redo에도 현재 초안으로 다시 계산한다.
- 3정간/60 BPM에서 두 번째 정간부터 120 BPM이면 2초, 첫 정간부터 악보 끝까지 60→120 선형 변화이면 `3 × ln(2)`초다. 점4분음표 등 원본 단위 비율도 보존한다.
- 반복·덧길이·반길이처럼 이 계산기가 아직 지원하지 않는 시간 변화나 잘못된 시간값에는 기존의 예상 길이 표시 제한을 유지한다. 실제 합성 음원의 릴리스 꼬리·인코딩 길이까지 정확히 일치한다는 의미는 아니다.
- 회귀·앱 화면 증거와 미검증 조건은 [903 작업 기록](../plans/S15P31E102-903.md)에 남긴다.

## 저장된 숫자 가속의 표시 (S15P31E102-956)

2026-11-15 사용자의 최신 지시인 **“기호만 넣고 숫자 표시는 그냥 편집 들어가면 보이게 해”**를 따른다. 이전의 악보 위 숫자 안내 선택은 이 지시로 대체됐다. 기존 `placements=[]`인 저장 악보도 재업로드 없이 기호를 읽고 기존 편집의 빠르기 설정에서 숫자를 확인할 수 있어야 한다.

- 유효한 숫자 상승 구간의 시작 정간에 `ㅈㅈㅅ`, 하강 구간에는 `ㅈㅈㄴ`를 표시한다. 같은 정간에 명시 한배가 있으면 이를 우선하고 파생 기호를 중복 추가하지 않는다. 2026-11-15 감속 자동 표시 후속 요청을 반영한다.
- 편집·휴대폰·태블릿의 악보 영역에는 가속 숫자/위치 안내 카드를 추가하지 않는다. 기존 세로 기호 영역에 한배만 표시하고 원래 악보 배치를 유지한다.
- 숫자는 기존 편집 빠르기 설정의 구간 목록에 표시한다. 명시 시작 속도가 있는 구간은 시작→목표와 시작·끝 각/정간을 읽을 수 있어야 한다. 기존 목표·끝 위치 편집을 보존하며 새 시작 속도 입력 기능은 추가하지 않는다.
- 가속 판정은 `start_bpm`이 있으면 앞 구간 목표보다 우선한다. 없으면 앞 확정 숫자 또는 곡 기본 BPM을 사용한다. 편집 숫자는 기존 정간/분→악보 BPM 단위 변환과 전체 BPM 배율을 그대로 사용한다.
- 즉시 변경·동속·잘못된/겹치는 구간에는 자동 점진 기호를 표시하지 않는다. 원문의 `molto` 정도를 추측하거나 복원하지 않는다.
- 파생 표시는 UI 모델에만 둔다. `sigimsae`, `placements`, `sourceSlots`, `performancePlan`, 원본 SHA, 음표/정간 ID·tick·음높이·저장 payload와 재생은 그대로 보존한다. 기존 5종 명시 한배의 편집·저장 의미를 바꾸지 않는다.
- 고정 입력의 기호/재진입/배율/불변성 회귀와 실제 편집·휴대폰·태블릿 악보의 숫자 카드 부재, 편집 빠르기 창의 실제 BlueVal 두 80→160 구간을 확인한다. 이전 숫자 카드 캡처는 최신 UI 증거로 사용하지 않는다. 물리 휴대폰·공유 서버 조작, 병합·배포는 제외한다. 격리 에뮬레이터는 명시 serial로만 사용하고 실기기 검증과 구분한다.

## 기존 한배 지원 완료 조건

1. 기호가 있는/없는 작은 입력에서 음표·정간 보존, 기호/위치 전달, 숫자 미지정 시 속도 유지와 명시 숫자 구간 적용을 검사한다.
2. 기존 빠르기 창에서 추가·수정·삭제·목표 미지정·점진 범위 오류, 실행 취소·저장·재진입을 검증한다.
3. 정간보 원본 두 곳(국립국악원 대금 정악보 48쪽 별곡 돌장 `ㅈㄴ`, 134쪽 수제천 4장 `ㅈㅅ`)과 대조한 결과·미지원 범위를 남긴다. 원본 스캔을 Git에 넣지 않는다.
4. 관련 AI·DATA·BE·FE 회귀와 실제 편집 UI를 확인한다. iOS·실기기 청취를 확인하지 않았다면 따로 미검증으로 남긴다. Push·MR·운영 배포와 기존 사용자 악보 수정은 포함하지 않는다.
