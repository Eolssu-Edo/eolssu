# 블로그 글 수정·삭제 일괄 반영

- Jira: S15P31E102-660
- 기준: `origin/blog`의 `f52d17bd`
- 작업 단계: 구현·로컬 검증 완료, MR 검토 및 운영 반영 대기

## 동작

- GitHub로 본인 계정을 확인한 작성자가 자기 공개 글의 제목과 Markdown 본문을 임시 저장하거나 글을 삭제 대기에 넣는다. 같은 글은 대기 목록에서 한 건으로 표시한다. 삭제 대기를 취소하면 앞서 임시 저장한 수정본을 복원한다.
- 대기 항목은 서버의 영속 저장소에서 작성자별로 관리한다. 같은 브라우저 탭에서 글 목록·상세·편집 화면을 오가거나 새로고침해도 편집 로그인은 최대 15분간 유지된다. 로그아웃 후 대기 목록은 재로그인하면 다시 볼 수 있다.
- 블로그 화면의 오른쪽 하단에 대기 건수를 표시한다. 편집 로그인이 없거나 대기가 0건이면 버튼을 숨긴다. 검토 화면에서 수정·삭제를 구분하고 개별 취소와 일괄 반영을 제공한다.
- 적용 요청은 검토한 목록과 현재 대기가 일치해야 한다. 서버는 각 글의 작성자와 버전을 재확인하고 GitHub에 단일 커밋을 만든다(2026-11-26 GitLab에서 전환). 성공 확인 전에는 대기 항목을 보존한다. 타임아웃 후 재시도는 같은 요청이 이미 커밋되었는지 확인한다.
- SQLite를 켠 배포에서는 기존 즉시 저장·삭제를 차단한다. 새 화면은 배치 API를 사용할 수 없으면 업데이트 안내를 표시한다.

## 구현·검증 순서

1. 기존 작성자 인증과 `/post` 프록시에서 배치 API를 제공한다. 독립된 SQLite를 기존 영속 마운트에 추가하고 원본 권한, 버전, 다른 탭의 변경, 재시도를 API 테스트로 확인한다.
2. Hugo 공통 템플릿에 버튼과 확인창을 연결한다. 편집 화면에서 로그인과 대기 상태를 복원하고, 데스크톱과 모바일에서 실제 UI를 확인한다.
3. Flask 회귀 테스트와 Hugo 빌드를 실행한다. `blog` 병합 후 Pages 배포와 편집 서버 갱신을 확인한다. 운영 글의 수정·삭제 확인에는 별도로 승인된 테스트 글을 사용한다.


## 로컬 검증 결과

- Python 3.12에서 편집·조회수 API 28건과 블로그 배포·TIL 회귀 테스트 33건을 통과했습니다. 동시 일괄 요청, 응답 유실 복구, 다른 작성자 차단, 충돌 후 목록 보존을 포함합니다.
- Jenkins와 같은 Hugo 0.145.0으로 사이트를 빌드했습니다. Chrome 1060px·320px에서 테스트 OAuth 콜백, 로그인·대기 유무에 따른 버튼 표시, 목록·상세 이동, Escape와 초점 복원, 개별 취소, 혼합 일괄 요청을 확인했습니다. 테스트 GitLab은 수정·삭제 한 커밋을 받았고 브라우저 오류는 없었습니다.
