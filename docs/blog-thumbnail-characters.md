# 썸네일 캐릭터 선택과 제작

작업: S15P31E102-538. coco-blog는 이 가이드와 README의 이미지 규칙을 읽어 프로젝트 캐릭터를 확인합니다.

## 첫 질문

원고 방향이 정해지면 “이번 글 썸네일에 코코 또는 팀 캐릭터 ‘절쑤’를 사용할까요?”라고 묻습니다.
선택지: **코코 / 절쑤 / 둘 다 / 사용하지 않음 / 추천받기**.
이미 답한 선택은 다시 묻지 않습니다. 캐릭터를 거절해도 썸네일 제작은 계속합니다. 추천을 요청하면 글과의 관련성을 설명하고 선택을 받은 뒤 제작합니다.

## 승인된 참고 자료

| 캐릭터 | 의미와 외형 기준 | 공개 참고 자료 |
| --- | --- | --- |
| 코코 | 팀원의 반려견이며 COCO 스킬 이름의 유래입니다. 갈색 곱슬털·늘어진 귀·청록색 목걸이 등 승인된 외형을 유지합니다. | [승인된 첫 글 썸네일](https://team-edo.github.io/blog-images/2026-10-hello-coco.webp) |
| 절쑤 | 확정된 팀 캐릭터입니다. 갓·한복을 입은 백호의 무늬·의상·비율을 유지합니다. | [기존 팀 캐릭터](https://team-edo.github.io/images/tiger-hello.webp), 원본 경로는 `data/brand.yaml`의 `mascot` 기준 |

두 공개 이미지는 외형 확인용입니다. 없는 방향·의상·표정을 확정된 설정처럼 추정하지 않습니다. 상세 참조가 필요하면 작성자에게 승인된 자료를 요청합니다. 새로운 참고 자료의 사용·공개 범위는 확인하고, 개인 사진의 사람·집 내부 등 배경을 옮기지 않습니다. 개인 사진 모음이나 대화 원문은 Git에 올리지 않습니다.

## 대화와 제작

1. 선택한 캐릭터가 글에서 할 행동, 구도, 배경, 최소 소품을 2~3안으로 제안하고 방향을 정합니다.
2. 캐릭터가 어울리지 않는다면 이유를 짧게 설명하고 기술 개념·도구·문제 해결 과정을 표현하는 대안을 제안합니다. 최종 선택은 작성자가 합니다.
3. 실제 시안을 보여주고 구도·표정·소품·배경 피드백을 받아 수정합니다. 선택하지 않은 캐릭터를 임의로 추가하지 않습니다.
4. 목록·추천·글 상세와 모바일에서 잘림과 작은 크기의 가독성을 확인한 뒤 최종 선택을 받습니다. 생성·미리보기 도구를 쓸 수 없으면 그 단계를 미확인으로 명시합니다.

## 이미지와 게시 기준

- [README의 이미지 규칙](../README.md#이미지)이 형식·용량·업로드 위치의 기준입니다. 현재 썸네일은 1200×630 WebP, 300KB 이하, `YYYY-MM-slug.webp` 형식입니다.
- 기존 썸네일과 어울리는 밝은 연두색 계열 배경(`#F3F6E9`)을 기본으로 하되 작성자의 선택을 따릅니다. 불필요한 장식·문구·소품을 최소화합니다. 사이트 배경은 흰색을 유지합니다.
- 최종 이미지 선택은 공개 업로드나 글 게시 승인이 아닙니다. 이미지 저장소가 글 공개 전에 공개된다는 점을 알리고 승인된 범위에서 업로드합니다.
- 공개 주소의 실제 이미지를 확인한 뒤 글의 `thumbnail`에 연결합니다. 별도 이미지 없는 글은 목록·상세에서 분야별 기본 썸네일을 사용합니다.
