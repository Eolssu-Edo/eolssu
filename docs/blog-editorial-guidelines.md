# Team Edo 블로그 글감과 게시 기준

팀이 직접 한 선택과 그 결과를 설명할 수 있는 작업을 기록합니다. 후보는 넓게 모으고, 실제 글을 함께 검토하며 이 기준을 보완합니다.

## 후보로 남길 기준

다음 중 하나에 해당하면 공개 후보로 남깁니다.

- 나중에 다시 참고하고 싶은 경험
- 잘 만들었거나 잘 선택했다고 생각하는 작업
- 다른 팀원이나 개발자에게 설명하고 싶은 내용

완성한 기능, 설계 결정, 문제 예방, 팀의 반복 작업을 줄인 자동화, 트러블슈팅, 실험·성능 개선 모두 글감입니다. 개선 폭이나 글의 분량으로 후보를 걸러내지 않습니다. 효과가 없었던 시도도 조건과 판단 근거를 남길 가치가 있습니다.

기본 흐름은 coco-blog 실행 후 로컬 TIL 목록에서 글감을 선택하는 방식입니다. 기존 Git 가져오기에서 TIL의 `blog.candidate: true`는 **후보 표시**입니다. 공개가 확정됐다는 의미가 아닙니다.

## 게시 전에 확인할 세 가지

1. **우리가 직접 한 일을 구체적으로 설명했는가?** 배경·대상·변경한 내용이 드러나야 합니다.
2. **왜 그렇게 했는지 판단의 이유가 있는가?** 제약, 검토한 대안, 선택이나 포기의 근거를 설명합니다.
3. **결과를 보여주는 근거가 하나 이상 있는가?** 측정값, 설계도, 전후 화면, 테스트 결과, 실제 사용 경험이나 피드백 등을 제시합니다.

수치는 여러 근거 중 하나입니다. 큰 성능 개선이나 장애 경험이 없어도, 잘한 설계와 완성한 기능을 구체적인 근거로 설명하면 게시할 수 있습니다. 처음 만드는 기능은 완성된 사용 흐름과 검증 결과를 근거로 삼을 수 있습니다.

측정값을 쓰는 글은 비교 조건·측정 방법·표본 수·반복 횟수와 한계를 함께 남깁니다. 측정하지 않은 값은 미측정으로, 확인하지 못한 내용은 미확인으로 표시하며 초안을 작성하면서 수치를 만들어 채우지 않습니다.

## 글을 구성하는 기본 흐름

성과·설계·기능 구현을 소개하는 글은 다음 흐름을 기본으로 삼습니다.

1. 필요했던 이유와 해결하려던 상황
2. 우리가 한 선택과 그 이유
3. 완성된 모습이나 실제 동작
4. 확인한 효과와 근거
5. 남은 과제와 적용 범위

트러블슈팅은 재현 조건·가설과 확인 과정·원인·수정 후 검증을, 실험·비교는 가설·비교 조건·결과·해석을 중심으로 구성할 수 있습니다. 모든 글에 같은 목차를 강제하지 않습니다.

## 요약문

글 목록과 글 상세에 표시되는 요약문(`description`)은 완결된 존댓말 문장으로 씁니다. ‘~입니다’, ‘~합니다’, ‘~했습니다’처럼 문맥에 맞는 어미를 사용합니다.

## 분야와 태그

- 분야는 DATA·AI·INFRA·FE·BE·보안 등을 기준으로 글의 중심을 정하고, 연관 분야와 여러 태그를 함께 사용할 수 있습니다.
- AIFlow는 팀이 AI를 활용해 계획·구현·검증하는 방식과 하네스·스킬 경험을 기록하는 분야입니다.
- 보안은 접근 권한, 요청 위조 방지, 민감한 값 보호, 외부 노출 제한이 글의 핵심인 경우에 사용합니다.
- 도구에서 사용할 수 있는 값은 `data`, `ai`, `ai-native`, `infra`, `frontend`, `backend`, `security`, `회고`입니다.
- 같은 분야에서도 성과 소개·문제 해결·실험·설계·회고 등 서로 다른 방향의 글을 작성합니다.

## TIL 가져오기와의 관계

1. 작성자가 coco-blog를 실행하고 로컬 TIL 목록에서 하나 또는 여러 글감을 선택합니다.
2. coco-blog와 분야·글의 방향·근거·공개 범위를 대화로 정합니다.
3. 별도 공개 원고를 검토하고 `prepare-local --reviewed`로 `draft: true` 초안을 준비합니다. 원본 TIL은 커밋하지 않습니다.
4. 위 세 가지 기준과 본문·이미지·출처·공개 정보를 사람이 검토합니다.
5. 검토한 뒤 `draft: false`로 바꾸고 기존 빌드·MR·배포 절차를 따릅니다.

도구의 패턴 검사 통과가 편집 검토 완료를 의미하지 않습니다. 근거의 의미나 작업의 가치를 점수로 자동 판정하지 않습니다. MR은 사용자가 직접 생성하며, 에이전트는 요청받은 경우 정해진 양식의 본문을 준비합니다.
