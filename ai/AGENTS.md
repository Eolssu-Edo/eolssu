# AI 작업 지침

- 연주 요청별 전처리·음높이 추정·DTW 정렬·음표별 채점을 구현한다. 데이터셋 구축은 `data/`와 연계하고 공통 변환을 중복 구현하지 않는다.
- 실시간 온디바이스 음높이 안내와 연주 후 서버 분석을 구분한다. 서버 실험 결과를 모바일 정확도·지연의 증거로 사용하지 않는다.
- 국악 조율 기준, 음높이 단위·옥타브 처리, 시간축·무음 처리, DTW 설정과 채점 허용치를 명시한다. 미검증 기본값을 팀의 확정 기준으로 취급하지 않는다.
- 악보·음표 식별자를 분석 결과까지 유지한다. 정상·오류 연주, 무음·짧은 입력·분석 실패에서 결과 형식과 실패 처리 방식을 확인한다.
- 음높이·정렬·채점 방식을 비교할 때 같은 평가 데이터와 조건을 사용한다. 정확도·오류 유형·소요 시간을 함께 확인하고 관측 범위 밖으로 일반화하지 않는다.
- 실험에는 입력·데이터/모델 버전·파라미터·실행 명령·환경·평가 기준·결과·한계를 남긴다. 튜닝 데이터와 평가 데이터의 중복은 Data와 확인한다.
- 빠른 로직 검사에는 작은 고정 배열·오디오를 사용한다. 실제 모델 추론·전체 데이터 평가의 실행 조건을 따로 정하고 모델·전처리·채점 변경에는 필요한 품질 검증을 수행한다. 모의 추론 통과를 품질 통과로 보고하지 않는다.
- 모델 가중치·대용량 입력은 Git에 넣지 않는다. `ai/models/`, `ai/data/`는 제외 경로이므로 모델 정의 코드와 검증용 샘플은 추적 가능한 경로에 둔다.
- 논문·라이브러리·도메인 조사와 PoC 결과는 `docs/knowledge/ai/`에 기록한다. 제안과 채택된 결정을 구분하고 채택한 기준은 구현·데이터 계약에 연결한다.
- 실행 구성을 만들면 이 폴더의 README에 설치·실행·빠른 검사·실제 모델 검증 명령과 필요한 모델의 획득 방법을 기록한다.
